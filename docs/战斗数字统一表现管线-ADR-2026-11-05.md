# 战斗数字统一表现管线 ADR

**文档角色**：治疗与伤害共用显示策略、世界行预算及语义边界的决策记录；当前实现归 `launcher/src/Guardian/HitNumbers/`，验收入口归 [视觉工具](../tools/hit-number-visual-harness/README.md)。

**最后核对代码基线**：commit `43880364e014c4e27008074dc4bfa09ea6d6a097`（2026-11-05），本轮实现位于其上的工作树。

**状态**：维护者于 2026-11-05 授权实现，同日明确回复“验收通过”，授权与上层 HUD 修复共用一批正式发布列车。源码和自动验证已完成；发布证明和正式入口复验另行记证，不由离屏图或构建代签。

## 1. 决策与边界

统一字体、字号规则、描边、动画、布局策略与世界行上限。治疗是 `CombatNumberKind.HealHp` 表现事件，不进入伤害账本、总伤 reducer、命中次数、伤害随机序号或 AS2 伤害结算。

本轮不改 AS2 HP 写入、`HealApplier`、`hn` 11 字段、`Hh1/Hh0`、特殊复活的治疗显示 epoch 或能力协商。保留 150ms 固定数值窗口、小数跨窗口结转、有界整数、移动锚点、断连/reset/off 清理。满血重置、法力恢复和旧吸血标签的语义沿用现合同。

## 2. 生产路径

`HealNumberAccumulator` 只做聚合和独立周期管理，输出 `CombatNumberVisualEvent`；不生成 `PaintItem`，不决定脚边偏移。`HitNumberRuntime` 把两类候选交给 `HitNumberLayoutEngine.BuildCombatFrame`。

布局器通过类型化适配器复用现有 `BuildFrame` / `BuildTotalFrame`。适配后的 `HitNumberSegment` / `HitNumberTotalEntry` 是本次布局的临时数据，不回流 `_segments`、`_totals` 或 `LedgerStore`。治疗每个 150ms 窗口才新增表现事件，逐帧治疗输入不创建伤害 Segment。

| 模式 | 治疗表现 |
|---|---|
| balanced | 每目标连续周期复用当前窗口的可见值；用共用摘要栈、字号、冲击和渐变恢复，不每 150ms 重播入场 |
| total | 同一连续治疗周期独立累计恢复值，用共用 Total 布局及脉冲；不出现伤害 hit 计数，周期结束后重新累计 |
| detail | 每个已发布的 150ms 窗口成为一条逐发候选，复用固定栈、逐发字号和边界测量 |
| classic | 每个已发布窗口复用经典散开及 14 帧缩放/模糊表，使用独立表现序号，不改变伤害随机结果 |

固有语义差异为绿色、正号、治疗聚合窗口与独立生命周期。治疗和伤害共享一次行数选择，`hitNumberWorldRowLimit=24` 不再允许额外追加 24 条治疗；`0` 仍解除产品行数限制。

## 3. 身份、几何与有界状态

`LifecycleKey` 保留协议原始实例/epoch。只对明确的 `.heal.<非负整数>` 后缀提取 `PresentationTargetKey`，用于同一实例的表现分组；不同 epoch 的候选绝不合并数值。

旧伤害的 MovieClip 名和治疗的实例 ID 没有可靠别名关系。本轮不根据坐标或名字猜测同一业务目标。统一布局结束前，由同一几何预留步骤核对实际字形包络；保留原伤害固定栈，新语义行从策略原位选择最近可用位置，避免跨通道遮挡。几何避让不赋予任何业务身份。

有限预算下，完整语义行无法放入舞台时按世界行省略计数退出，不截断数字；显式无限制保留所有候选。治疗 pending / 当前可见目标各最多 512，逐窗口历史最多 4096，均按自然寿命清理。锚点按周期共享引用，逐帧移动不扫描全部历史窗口。

## 4. 验证与合并发布

`HealNumberRuntimeTests` 保留解析、小数、失效、整数、移动及真实像素重叠回归。`CombatNumberUnifiedLayoutTests` 追加四模式共用策略/预算、独立累计、窗口粒度、身份隔离、状态上限与跨 wire 键几何预留。HUD 边界由 `HudBoundaryRegressionTests` 与扩充后的 `HudAnchorCompositeTests` 验证。

视觉工具输出 P27–P34 四模式治疗/混流样本，V03–V06 四模式持续治疗动效及数值序列；同轮压力输入为每秒 1200 伤害段加 1200 治疗事件，检查共享行数、耗时、分配、有界账本与 GDI/USER/句柄稳定。性能数值只作本机对照，不能称真实战斗帧率。

维护者确认统一候选的观感后，与 [上层 HUD 修复](上层HUD风格锚定与分区仲裁-ADR-2026-11-05.md) 共用冻结源码、双构建共识、promotion 与标准入口检查，不拆成两次 runtime 发布。正式发布遵循 [runtime 发布协议](runtime-build-reproducibility.md#release-protocol)。
