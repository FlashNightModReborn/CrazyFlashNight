## 1. 文档边界

本文只解决两个实际问题：拿到外部 One-shot 产出后，如何判断它是不是可继续施工的产品；通过后，如何把源码改写接入现役 Launcher Web、Host 与 AS2，而不重做前端。玩法、经济、信息权限和验收阈值只以玩法规格为准，本文不复制第二套规则。

One-shot 输入包、返回 ZIP、临时解压目录、重复 `dist/`、原始截图和夹具素材都是运输或验收中间物，不是仓库长期真源。仓库长期只保留：

- 玩法规格；
- 本交接文档；
- 验收后以普通源码文件导入的产品实现；
- 因真实协议、入口和测试变化而同步更新的 canonical docs。

这条流程消除的是“部署站点能玩，但没有可接入源码、接口映射或真实证据”的不确定性。它不增加逐步人工确认：只有视觉盲评和真实游戏体验需要维护者判断，其余检查默认由施工 Agent 连续完成。

## 3. 回收时必须拿到什么

仅有部署 URL、截图或编译后的 `dist/` 不足以接入。返回产品至少必须包含：

- 完整源码、`package.json`、锁文件和实际使用的构建配置；
- 可复现的安装、typecheck、单测、构建、浏览器 E2E、资产闭包与截图命令；
- 作为比对样本的静态 `dist/`，但它不是后续源码真源；
- `BlackMarketPort`、Fixture Host、公开投影与持久化结构的实际实现；
- 18 张运行截图、测试摘要、资产闭包、实现报告、验收矩阵与视觉自评；
- 已知问题、未执行项、外部依赖和环境前置；
- 最终运输 ZIP 的字节数与 SHA-256。

返回 ZIP 只用于传输。验收通过后把需要的源文件正常导入仓库；不得把整个返回 ZIP 当作游戏运行依赖或长期归档。

## 4. 导入前审计

在隔离临时目录解压，不直接覆盖仓库。依次完成：

1. 冻结返回 ZIP、解压文件清单和锁文件摘要，记录生成模型、日期与输入 ZIP 摘要。
2. 检查依赖、构建脚本、绝对路径、远程 URL、CDN、遥测、动态下载、秘密信息和许可证风险。
3. 从干净依赖状态真实执行项目声明的 typecheck、单测、构建、E2E、资产闭包和截图命令。
4. 以真实运行页面核对三组二选一、全局待结算门、TP/K 支付、提取/回售、刷新恢复、幂等对账与最后总结。
5. 核对 1024×576、1366×768、1920×1080 的 18 张截图；完成玩法规格 `BM-DEMO-03` 要求的独立盲评。模型自评不能替代该项。
6. 确认购买前 DOM、ARIA、日志和公开资源路径不泄露身份；公开货物文件名保持不透明。
7. 形成 `ACCEPT / REVISE / REJECT` 结论。未通过时在临时产出上修订，不把半成品导入现役模块。

静态站点可用于产品体验验收，但不能证明 AS2 余额、库存、存档、掉落、Launcher 生命周期或 WebView2 真实链路。

## 6. 真实接入顺序

1. 将验收后的 UI、样式、状态投影和测试以普通源码导入目标 minigame 模块。
2. 建立真实 AS2 领域：资格真源、page draft/page object、交易点、补货信用、待结算、receipt、flush 与对账。
3. 建立 Launcher Host adapter：只传不透明句柄和脱敏 `PublicSnapshot`，执行超时、缓存与生命周期管理。
4. 用现役 manifest 重绑真实装备、材料和消耗品资产；确认不从文件名、DOM 或请求泄露身份。
5. 正式登记 panel contract、面板入口和单实例语义；实际发生入口/协议/测试变化时，同轮更新 `launcher/README.md`、`agentsDoc/testing-guide.md`，并按需更新 `agentsDoc/as2-web-panel-migration.md`。
6. 接入堕落城商业街黑市摊位 NPC 与可见失败路径。
7. 执行玩法规格第 17.7 节真实纵切和第 19.3 节上线阶段；涉及 `.as` 时取得新鲜 Flash trace/Output 证据。

## 7. 允许改什么，不能借机改什么

接入允许修改：

- Fixture Host → 真实 Host/AS2 adapter；
- 构建入口、模块路径、项目 shell 和共享生命周期接线；
- fixture/localStorage/调试入口清理；
- 资产 manifest 映射、无障碍挂起项补齐和真实错误文案；
- 为真实权威、失败恢复和 WebView2 生命周期增加必要测试。

接入不得擅自修改：

- 六件货、三组二选一、同组同价与每组最多买一件；
- 买后提取/回售、全局待结算门、50:1 单向兑换；
- 0–10 级信息权限、购买前身份边界和 UTC 纪元权威；
- 三舱视觉语法、物品主体尺度、状态反馈和独立成品感；
- “上线时重做整面前端”的路线。

若实际产品无法在上述边界内接入，结论应回到 `REVISE`，而不是在游戏仓库内静默重写后宣称 One-shot 成立。
