# 双药剂组与八槽共享冷却 ADR（2026-08-27）

> 当前状态：`HUMAN_ACCEPTANCE_PASSED / NOT_RELEASED`
> 适用范围：AS2 药剂输入与存档、玩家信息 HUD XFL、Character Build、Settings、Launcher Host/Web。
> 本文冻结产品语义和跨层契约；自动化通过不代表真实游戏观感、手感或发布验收。

## 1. 决策

- 药剂背包固定为 `2 组 × 4 通道 = 8 个物理槽`，不把可同时使用的冷却通道从 4 扩为 8。
- `6` 为“药剂组切换”默认键，`7 / 8 / 9 / 0` 继续对应 4 个冷却通道。
- 上下两组的同列槽共享同一条 `drug:0..3` 冷却；切换使用独立 `drug:switch` 冷却。
- 首个候选的切换冷却为 `3000 ms`，由独立根参数提供，不与 `_root.吃药冷却时间` 共用存储。真人手感验收可以只调整该参数，不改变协议。
- 战斗 HUD 顺序固定为 `6 | 7 | 8 | 9 | 0`。Character Build 显示两排四列药剂槽，不创建第九个“切换槽”。
- 活动药剂组是进程内会话状态：死亡、场景转换不重置；成功读档、新建角色和删档清理重置为第 I 组；不写入存档。

## 2. AS2 权威模型

`DrugInputService` 必须显式分离三个维度，不再用一个含混的 `SLOT_COUNT` 同时表示输入、冷却和容器容量：

```actionscript
BANK_COUNT = 2
LANE_COUNT = 4
PHYSICAL_SLOT_COUNT = 8
```

物理槽与通道映射：

```text
physicalSlot = bank * 4 + lane
bank         = floor(physicalSlot / 4)
lane         = physicalSlot % 4
cooldownKey  = "drug:" + lane
```

切换状态机：

1. 每帧先读取“药剂组切换键”，再处理 4 个药剂通道。
2. 切换只在物理键的上升沿尝试一次。即使当时 `drug:switch` 仍在冷却，该次按下也必须被消耗；持键等到冷却结束不得自动切换。
3. 切换成功时翻转活动组，启动 `drug:switch`，并把 4 个药剂通道全部置为“必须先松键”。
4. 切换成功的同一帧不使用药剂；切换键因冷却被拒绝时，不额外封锁正常药剂输入。
5. 切换不调用任何 `drug:0..3` 冷却的 reset/start，因此上下位冷却永远连续。
6. HUD MovieClip 只是投影。MovieClip 缺失、重绑或可见帧切换失败都不得成为输入或冷却权威。

`ManualCooldownService` 新增独立 switch key 与按 key 重置能力。按 key 重置只用于成功读档、新建角色或删档清理的会话边界，不在暂停、死亡、场景转换或切换药剂组时调用。

## 3. 存档与旧档迁移

不提升 `mydata.version = "3.0"`。药剂布局只使用自己的幂等标记：

```text
mydata.ext.drugLoadout.version = 2
```

读档规则：

- 无标记的历史存档只保留药剂键 `0..3`。构造 8 槽容器前必须丢弃所有越界键，尤其是旧 `ArrayInventory` 曾读入但因容量过滤而隐藏的 `4..7`，防止扩容后“幽灵物品”复活。
- 完成清理后写入 `ext.drugLoadout.version=2`，保存待落盘迁移状态，直到权威全量存盘真正成功。
- 已标记 v2 的存档保留 `0..7`，重复读取不得再改变内容。
- 新角色直接建立 8 槽空容器和 v2 标记。
- 旧槽 `0..3` 继续是第 I 组；不做物品平移、复制或索引换位。

`packGameState` / SOL / Launcher snapshot / JSON shadow / `loadFromMydata` / 新建角色必须共用同一布局规则，不允许只修本地 SOL 分支。

## 4. 键位迁移

Settings 注册新逻辑 ID `药剂组切换键`，默认键码 `54`（数字 `6`）。键表从 35 行升为 36 行，AS2、C# Host、Web runtime 与 harness 必须使用同一 ID 顺序。

历史玩家可能已把其他动作改到 `6`。迁移必须：

1. 保留每个历史逻辑 ID 的有效自定义键码，不抢走旧绑定。
2. 只对缺失的“药剂组切换键”选键：若 `54` 空闲则用 `54`；否则按冻结的人体工学候选 `T(84) → Y(89) → V(86) → X(88) → Z(90)` 选择首个空闲键，再按默认表键码顺序和 KeyManager 合法键码升序兜底。所有阶段都排除 `Esc` 和 `F1..F12`。
3. 结果必须是可在 Settings 中直接应用与保存的无冲突表。
4. 快照应给 Web 一条有界的迁移提示，说明保留了旧 `6` 绑定，并显示新动作被分配到的实际键。成功存盘后清除 pending 提示。
5. “恢复默认”始终把新动作设为 `6`；正常改键仍由现有冲突校验裁决。

Settings 顶层 domain envelope 继续使用 v1，以避免把本次键表增量扩散到刚完成的复活/返回基地等无关命令；携带键表的 snapshot/apply 必须精确增加 `keySchemaVersion:2`。Host/Web/AS2 对该子协议 fail closed，不通过 `keys.length` 暗猜版本。

## 5. Character Build 严格投影

现有顶层 Character Build v1 request/response envelope 不改名；药剂布局新增严格 `drugLayout.v=2` 子协议，不通过数组长度暗猜布局版本。

```text
drugLayout = {
  v: 2,
  bankCount: 2,
  laneCount: 4,
  physicalSlotCount: 8,
  activeBank: 0 | 1,
  switchKeyLabel: string,
  switchCooldown: {
    ready, totalSteps, currentStep,
    progressPercent, animationFrame, remainingMs
  }
}
```

`drugs` 固定 8 行，每行在旧药剂投影字段上显式增加：

```text
slot: 0..7
bank: floor(slot / 4)
lane: slot % 4
active: bank == drugLayout.activeBank
```

- `keyLabel` 从 lane 的 `7/8/9/0` 绑定获取，上下同列一致。
- 同列两行投影同一 `drug:lane` 冷却，并在该冷却激活时共享 equip/unequip mutation lock。
- C# 必须验证 `bank/lane/active`、数组长度和 cooldown 同列一致性；Web 不重算权威映射。
- Web 使用两个明确的组容器呈现两排四列，标记第 I / II 组与当前组；候选、tooltip、拖放、键盘漫游、equip/unequip 必须覆盖全部 8 个物理槽。

## 6. HUD / XFL

`玩家信息界面.xfl` 的五个背景格与整体宽度保持不变：

- 第一列复用 `控制器4 + 进度条4`，绑定“药剂组切换键”和 `drug:switch`。
- 原 `位置示意0..位置示意3`、`进度条0..进度条3`、`控制器0..控制器3` 整体向右平移一列，实例名与逻辑 lane 不变。
- 删除休眠 `位置示意4`，在同一图标层直接放置专用 `药剂组切换图标` MovieClip。它不设 linkage，不使用 `attachMovie`。
- 首候选的同色 `I / II` 在小分辨率真人验收中辨识不足，已废弃。修订候选以大轮廓 `○ / ×` 为第一视觉锚点、以同位置的高对比 `1 / 2` 为语义兜底；圆叉使用同一中性色，不照搬手柄品牌配色，也不让颜色单独承载状态。每帧 `stop()`；冷却条在图标上方，按键文字在冷却条上方。
- 四个可见 `DrugIcon` 在切换后通过现有 `CollectionIcon.reset(collection, physicalSlot)` 重绑到目标组，不销毁容器、不重建冷却、不修改任何物品。

PlayerInfo 必须使用独立 XFL 目标发布；AS2 service/UI include 变更另外发布 `asLoader`。本功能不需要发布 main XFL。

## 8. 发布边界

人类验收通过后才进入：

```text
source commit/tag
  -> immutable Git-tree request
  -> registered local X509 builder
  -> GitHub Hosted OIDC/Sigstore builder
  -> same identity + payload closure
  -> production policy + strict v2 consensus
  -> atomic promotion
  -> formal entry identity/lifecycle smoke
  -> push and post-promotion audit
```

发布结论严格使用 `compiled → candidate_built → candidate_executed → e2e_verified → promoted → standard_entry_verified`。正式入口只检查 identity/lifecycle 不能冒充药剂业务旅程；若未在正式入口重跑八槽、切换和读回，必须明确保留该边界。
