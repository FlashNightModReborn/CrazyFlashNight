<technical_baseline>
默认使用：Vite + TypeScript strict + React + SVG + Vitest。使用 npm 并提交 lockfile。可以使用小型测试辅助库和 Playwright 做浏览器验收；不要用 Canvas 取代需要可检查、可访问的 SVG/DOM 界面。

保持下列分层，并允许在不改变边界的前提下细化：

- `src/core/`：纯状态、命令校验、战略阶段与结算、序列化；
- `src/battle/`：可替换 `BattleResolver` 接口、`VirtualBattleResolverV1`、不可变战斗事件日志；
- `src/ai/`：只提交玩家同款合法命令的确定性启发式 AI；
- `src/data/`：附件快照的逐字副本、地图和集中化参数；
- `src/replay/`：命令/事件录像、导入导出、确定性重放；
- `src/simulation/`：无浏览器批量对局与统计；
- `src/ui/`：React、SVG地图、战略界面、战斗播放、结算层；
- `src/dev/`：测试抽屉、预设与诊断适配；
- `tests/`：规则、镜像、确定性、模拟与浏览器验收。

UI 不得直接写 `GameState`；所有变化都通过验证命令进入纯状态机。战斗解析器不得访问 DOM。动画只能播放解析器已生成的不可变事件，不能反向驱动规则。立即结算和正常播放必须使用同一次解析结果，不能存在第二套快战公式。

把两份输入原样复制到成品的 `docs/reference/`；把 JSON 快照再作为运行时内置数据放入 `src/data/`。运行时不得依赖附件路径存在。序列化和录像包含 `schemaVersion`、`rulesVersion`、`configDigest`。
</technical_baseline>

<implementation_requirements>
完整实现规格书，而不是只挑核心战斗。特别防止以下常见偏航：

- 只有金币，不创建 K 点、mana、energy 或第二货币字段；
- 卡牌是无限生产蓝图/科技树，不是会耗尽的手牌；不限制同卡部署数量；
- 普通重装兵是带 `elite` 的 T2 越级产物；精锐重装兵是带 `boss` 的 T3 终局产物；
- 战略回合与节点战斗回合严格分离；节点战斗在 `MOVE_OR_ATTACK` 中即时写回，经验只进待结算账本，其余恢复/占领/科技/生产按规格统一延迟；
- 单棋子没有额外行动次数上限，但每移动一条边或参战按人头消耗公共 AP；
- 敌军占据己方节点立即令它失去稳定、补给线路径和生产锚点资格；
- 恢复早于占领；新夺节点按非己方节点口径只恢复损失差值的三分之一，本轮不产出；
- 战斗行为、目标选择、 simultaneous sniper volley、弹药装填、压制生命周期、命中/伤害/上限、持久 HP、失败重入锁全部按规格逐项实现；
- `auditOnlyStats` 全量保留但绝不进入 v0.1 战斗计算；
- 阵亡经验按单位经验价值分别记击杀方 1 倍、损失方 3 倍；总经验相同不意味着卡牌升级效率相同；
- 升阶严格遵循每张卡快照允许的序列，不凭空授予被省略阶段；每卡每个战略结算最多升一阶；
- 野战团灭不等于失败；仅当部队、待部署单位、有效订单和生产能力按规格同时消失才彻底消灭；
- AI 难度只改变一次汇总后向下取整的金币，不改变属性、经验、AP、地图规则或 AI 决策算法；
- 红蓝双方必须共用同一数据、规则与 AI 代码路径，阵营交换不产生硬编码偏置。

先完成并锁定纯内核，再接 UI。不得以 TODO、占位按钮、永远返回常量的假实现、仅显示日志但不能操作的界面，冒充规格中的必需能力。
</implementation_requirements>

<ui_and_playability>

- 战斗支持正常、4倍速、暂停/继续、立即结算、逐回合日志；能辨认狙击先制、弹药装填、未命中、特攻和压制；

- 最低 1024×576，并验证 1366×768、1920×1080；关键操作支持键盘；状态不能只靠颜色；尊重 `prefers-reduced-motion`。

视觉风格采用克制的军事沙盘/战术终端语言：深色底、清晰节点连线、红蓝阵营高对比、金币与补给信息优先、少量警示色。可玩性和信息层级高于装饰。
