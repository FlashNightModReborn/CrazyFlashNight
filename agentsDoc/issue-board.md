## 0. 净收益声明（治理要求）

本流程消除的决策不确定性：「哪些工作做了一半」「每条线推进到哪」「下一步该干什么」——此前只能靠重读 docs/ 考古回答（一次全量普查约消耗一次主配额额度）。为何不能自动化：Epic 边界裁决、验收凭证判定、授权批示都是人类判断。净收益：状态索引常数时间可查；维护动作被硬性压缩（见 §5 成本控制）。若一个月后维护负担超过收益，按 §5 自我拆除条款降级为单文档台账。

## 1. 权威边界

- 业务与施工状态以仓内 `docs/`、`agentsDoc/` 为准；运行身份与发布闭包以源码、manifest、consensus 等机器真源为准。GitHub 侧只做调度指针，不复制正文。
- 授权先于计划：卡片不授予权限，只引用既有授权；已获授权的流程按原授权执行，不要求卡内重复批示。
- 卡按目标状态由对应证据移动：机器门输出可把机器门卡移到完成、把含人验的卡移到待验收；人类验收回执才能把卡移到完成；决策批示才能解除 Blocker=decision。证据类型之间不互相代签。

## 2. 结构

- **label**（4 自建 + 复用 `bug`）：`epic`（长期契约/常驻邮箱）、`sub-epic`（例外才建）、`perf`、`runtime-release`（完成条件含正式 runtime 发布；仅触及 C# 源码不触发，native source-ahead 合法）。
- **Status**：Inbox / Ready / 施工中 / Blocked / 待验收 / 完成。
- **自定义字段**：`Domain`（工程/玩法系统/数值标定/关卡任务/剧情文案/美术资产/音频；跨界按验收难点归一个值，不为分类拆卡）；`Blocker`（quota/hardware/field/art/decision/timing）；`验收方式`（机器门/需人类验收/机器门+人验/决策裁决）。
- **视图**：调度台（按 Status 分组）、按域（按 Domain 分组）、虫（label:bug）、性能（label:perf）、现场复验（Blocker=field）、列车队列（label:runtime-release）。
- **关闭路径**：验收完成 = 满足全部完成条件；退出（取消/重复/被替代/不再计划）= close as not planned 归档，不计入交付；Projects 自动化配置须区分关闭原因。

## 4. 卡片模板

**模板 A·机器施工卡（默认）**：目标（含验收口径）/ 权威文档（仓内路径）/ 授权依据（引用既有授权，不新授）/ 本次范围 / 验证门（链接 testing-guide 适用章节 + 本卡新增条件，不照抄计数，关闭时附本轮结果）/ 禁区（不删编译锁与 scratch 备份；`.as` 保持 UTF-8 BOM；未知写不盲重放、不用 UI 投影/关窗/换会话解除未知写锁；marker 不当作编译成功证据；只用真实 Flash CS6 GUI 编译不手工改 SWF；不混入 AS3/JavaScript 假定；涉持久写先读对应权威与恢复合同）/ 关闭凭证。

**模板 B·列车卡**（= A + 发布段；仅当完成条件含正式 runtime 发布时打 `runtime-release`）：发布段按 `docs/runtime-build-reproducibility.md#release-protocol` 现行协议执行（冻结 immutable source commit/tag/request → 双 faultDomain 对同一冻结树独立生产并达成同一 build identity/payload closure 共识 → strict v2 production policy receipt 全项通过 → 唯一 promotion writer → CI 事后 Audit）；授权状态以既有授权记录为准。

**模板 C·人工验收卡**：验收对象／环境／身份（候选运行/正式 runtime/素材评审）/ 验收旅程 / 判定标准 / 回执格式（验收人+日期+机器+结果+证据）/ 前置依赖。回执只证明所验范围；批量窗口回执逐项标明通过/失败/未测与卡号，一条总体好评不得关闭整批。验收方式=决策裁决的卡不用模板 C，完工证据 = 裁决文档 + 批示评论。

## 5. 运营规则

1. 提交说明中文 + 回归提示；普通提交用 `Refs #N` 引用，仅全部完成条件满足的提交才用 `Closes #N`。
2. Ready 是候选队列（≈5 张），不代表并发能力；实际并发受共享文件闭包、CS6 机器、发布资源分别约束。
3. Blocked：等仓内某卡用 blocked-by，其他原因填 Blocker；全部解除才回 Ready。
4. Epic checklist 只放卡链接，不复制内容；仓内文档状态更新是完工动作的一部分。
5. 散卡：不成批的 bug/体验增强带 label/Domain 直接落板；某主题 ≥3 张相关卡才考虑配常驻 Epic，不预建。
6. 目标型 Epic 关闭前补"领土归属"一节再关闭。
7. 仓外项目默认不入板，确需跟踪用散卡 + Blocker=timing。
8. 按需核对：建卡不做全量前置审计，候选落 Inbox；转 Ready 前由派工者点查当时状态（点查不是审计）。验证门对照表：`tmp/adr-scan-20260918/vresult-gates.md`。
9. 退出路径见 §2 关闭路径。

## 6. 成本控制（防自我繁殖）

- 视图两周未用即隐藏（不删除）；核心字段一次定型后不增删，多余则忽略。
- 每月凭体感回顾：维护负担明显超过收益则降级为单文档台账，不硬撑。
- 维护劳动优先派另一份额度的执行端（如 swe2）；主控复核仍有成本——能由脚本判定的状态一律用脚本/gh，不交给模型重新判断。
- 人验攒到固定窗口批量进行：多卡合并为一份验收旅程清单，测试员只对清单回执（一条评论可 Refs 多卡），不逐卡操作 GitHub；维护者按回执批量移卡。
