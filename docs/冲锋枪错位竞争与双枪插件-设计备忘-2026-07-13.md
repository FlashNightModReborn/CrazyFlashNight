# 冲锋枪错位竞争与双枪插件设计备忘

**文档角色**：跨会话 / 抗 compact 的游戏设计与技术施工备忘。  
**状态**：第一、二波均已落盘；Flash smoke 与运行态实战标定结果见各波施工记录，图标与获取途径仍待补。  
**最后核对代码基线**：commit `ab41d758f7`（2026-07-13）。

## 0. Compact 恢复入口

如果后续会话只剩这份文档，先恢复以下结论：

1. 目标不是让冲锋枪与突击步枪获得相同纸面 DPS，而是让两者在操作节奏、目标处理方式和构筑组合上错位竞争。
2. 突击步枪继续担任泛用、高冲击倾向、单枪闭环较完整的武器；冲锋枪以轻量、快速换弹、直接打血和插件联动换取就业空间。
3. 冲锋枪的换弹优势在现实中有一定合理性，但不是普遍物理定律。游戏中应把它当作可读的枪种手感规则，而不是现实模拟结论。
4. 双插件主要服务双枪/双武器协同：一把负责打空韧性槽，另一把负责挂入“破韧后增伤”的前置状态。混合职责构筑应有更高上限；无脑双持同类武器仍可保留高下限，但不应成为全场景最优。
5. 第一波已把两个候选数值写入实验配置：冲锋枪固有 `reloadPenalty=-17`；冲击插件使用 `impact'=max(25, round(1.8×sqrt(impact)))`，且沿用现有 curve 的“只改善、不反向变差”规则。二者仍需运行态标定后才能视为正式平衡结论。
6. 增伤插件采用目标/`stackGroup` 级聚合控制器：一个监听 MetaBuff 持有多个 `(sourceUID, profileId)` 轻量候选，并只通过一个最终 Pod 输出完整候选倍率的 MAX；不按层或来源堆积效果 Buff。
7. 技术施工的三个核心前置是：声明式子弹命中效果、韧性槽破裂事件、领域专用的监听 Buff。真正的难点是命中效果与冲击结算的先后顺序，而不是事件或 Buff 基础设施本身。
8. 第二波采用 `<hitBehavior>`（避免与视觉命中特效混用），实现 `ToughnessBroken`；后续审阅修复加入 `stackGroup/profileId` 隔离与单 Pod 聚合。实验值为基础 180 帧、破韧延长 60 帧、上限 300 帧、3 层、每层 6%、仅同一 shooter 的破韧可叠层。
9. 普通手枪不再靠面板追赶冲锋手枪/大威力手枪，而作为行为型 buff 机补弱：灰蛊裂隙弹使用精确 `weapontype:手枪` 分支，提高到 240 帧维持、360 帧上限、每层 7%（峰值 21%）；冲锋手枪和大威力手枪仍使用基础档。

## 1. 问题与设计目标

### 1.1 当前问题

当前平衡算法会让重量更高的突击步枪换取更多综合预算。即使冲锋枪更倾向于直接削减生命，突击步枪也常能同时获得：

- 不弱的打血能力；
- 更强的冲击力倾向；
- 更稳定的泛用射程和单枪闭环；
- 在相同构筑成本下更高的综合容错。

结果是突击步枪接近冲锋枪的上位替代。单纯把二者的 DPS 拉齐，只会让枪械手感继续同质化，并不能为冲锋枪创造独立的玩法理由。

### 1.2 成功标准

本设计的收益锚点不是“所有枪种平均 DPS 一致”，而是：

- 玩家能通过枪种和插件预判战斗节奏；
- 同一敌人由不同构筑处理时，操作过程和风险窗口明显不同；
- 每类枪在特定场景中有真实就业，而非只在面板上换皮；
- 低心智压力构筑有可接受下限，但需要职责组合的构筑拥有更高上限；
- 不让一个插件同时抹掉霰弹枪、突击步枪和冲锋枪之间的边界。

## 2. 枪种错位定位

| 枪种 | 主定位 | 应保留的优势 | 应保留的缺口 |
|---|---|---|---|
| 突击步枪 | 泛用主武器 | 综合输出、冲击倾向、射程与稳定性、较完整的单枪闭环 | 换弹窗口更长，双武器联动收益不应压过专门枪种 |
| 冲锋枪 | 高频打血与战斗续接 | 轻量、快速换弹、快速切回输出、近中距离持续施压 | 原生打条较弱，单枪解决高韧性目标的效率不如专职武器 |
| 霰弹枪 | 爆发打条/近距离控制 | 典型场景下最高的破韧效率和即时反馈 | 距离、节奏、容错或持续输出受限 |
| 普通手枪 | 双持与灵活搭配 | 低负担、快速换弹、构筑接口丰富 | 单枪上限有限，需要副手或插件补足职责 |
| 大威力手枪 | 慢节奏单发与高风险回报 | 单发威力、特殊目标处理 | 当前换弹负担较高，不能被冲击插件无成本补成全能枪 |

### 2.1 现实合理性边界

现实中的冲锋枪可能因弹匣、枪体尺度、操控距离和训练体系而呈现较快的换弹与再接敌体验，但并不存在“冲锋枪必然比突击步枪换弹快”的通用规律。弹匣布局、释放机构、携行方式和射手训练的影响都很大。

因此游戏规则应表达为：

> 冲锋枪被设计成更容易结束换弹空窗并恢复压制，而不是宣称所有现实冲锋枪机械换弹都更快。

这足以支撑手感差异，又不会让现实原型反过来绑死数值。

## 3. 换弹负担福利

### 3.1 当前数据锚点

`reloadPenalty` 直接加在基础负担 `100` 上；负担越低，换弹动画的可缩放片段越快：

```text
burden = 100 + reloadPenalty
```

当前数据具有以下稳定参照：

| 对象 | 当前 `reloadPenalty` | 含义 |
|---|---:|---|
| 长枪冲锋枪 | `0` | 无固有换弹优势 |
| 手枪冲锋枪 | `0` | 无固有换弹优势 |
| 突击步枪 | `0` | 基准负担 |
| 普通手枪 | `-15` | 固有快速换弹 |
| 大威力手枪 | `17` | 固有慢换弹 |
| 加长弹匣 + NOAH 结构 | `-20` | 条件式换弹优化，同时提供容量收益 |

实际换弹帧数还会受到动画分段取整、固定尾帧、逐发换弹和枪械师“快速换弹”影响，因此 `-17` 不严格等于总换弹时间减少 17%；它表示可缩放换弹片段使用 `83%` 的基础负担。

### 3.2 第一波实验配置

第一波已让全部 16 把长枪冲锋枪和 38 把手枪冲锋枪获得：

```xml
<reloadPenalty>-17</reloadPenalty>
```

选择 `-17` 的理由：

- 明显强于当前 `0`，足以形成肉眼可感的续接差异；
- 略强于普通手枪的 `-15`，强化冲锋枪的射击循环身份；
- 不超过突击步枪通过 NOAH 条件加长弹匣获得的 `-20`，保留改装突击步枪在高投入后的追赶能力；
- 仍留有插件、技能和特殊枪械进一步区分的空间。

### 3.3 边界与验证

- 不能只观察面板百分比，需要按长枪、主手、副手、双枪结束段分别记录实际换弹帧数。
- 特殊动画、逐发换弹、内置副武器和阻止弹匣插件的武器应单独审计。
- 若 `-17` 令换弹窗口失去战术意义，优先回调到 `-15`；若实际帧数因取整差异不明显，再试 `-18~-20`，不要直接给伤害补偿。
- 这是枪种福利，不应重复计入纸面 DPS 预算后又把冲锋枪威力下砍到无法形成体验差异。

## 4. 双插件与双枪玩法

### 4.1 构筑目的

两种插件不是为了让一把弱枪同时补齐所有短板，而是为双枪/双武器职责组合提供语言：

```text
破韧武器：快速打空韧性槽
    ↓ ToughnessBroken
增伤武器：预先挂入监听状态，破韧后获得增伤层数
    ↓
切换/交替射击：利用增伤窗口直接打血
```

预期的构筑层级：

- 同类双持：操作简单、下限高，但打条或增伤效率至少一端受限；
- 不同枪种混搭：需要理解职责和切枪节奏，上限更高；
- 专职霰弹枪：仍是典型近距离破韧标杆；
- 泛用突击步枪：可以独立完成战斗，但不应同时获得最高换弹、最高破韧和最高增伤联动。

### 4.2 反全能约束

施工和调参时保持两个不等式：

```text
冲锋枪固有换弹收益
    ≤ 突击步枪通过高投入条件改装获得的换弹收益

冲锋枪/手枪安装冲击插件后的典型打条能力
    < 典型霰弹枪在有效距离内的打条能力
```

这两个约束不是要求所有样本严格排序。特殊武器可以越界，但必须以稀有度、射程、弹药、插件槽或其他明确成本交换，并留下理由。

## 5. 冲击力插件

### 5.1 字段语义

当前 XML 的 `<impact>` 实际是“击倒率”分母，运行时关系为：

```text
冲击力 = 伤害值 × 50 ÷ impact
```

因此：

- `impact` 越低，实际冲击力越强；
- 插件要强化打条能力，应压低 `impact`；
- 不能把 `<impact>` 数字变大误读为“冲击力变强”。

### 5.2 为什么采用平方根压缩

线性百分比会把原本就有较强冲击力的武器继续等比例放大，也难以挽救 `impact=200~500` 的弱冲击武器。平方根压缩更符合本插件的目标：

- 原生冲击很弱的武器获得质变；
- 原生已经较强的武器收益受控；
- 极端坏值被拉回可用区，而不是被直接改写成霰弹枪级别；
- 沿用装备属性现有 `curve/sqrtScale` 能力，无需发明新运算符。

### 5.3 第一波实验曲线

第一波“黑爪扩张弹”已配置：

```text
candidate = round(1.8 × sqrt(currentImpact))
result    = min(currentImpact, max(25, candidate))
```

对应 XML 形状：

```xml
<curve>
    <impact>
        <type>sqrtScale</type>
        <coefficient>1.8</coefficient>
        <min>25</min>
    </impact>
</curve>
```

现有 curve 实现会在曲线结果比原值更差时保留原值，因此 `impact<25` 的高冲击武器不会被插件削弱。

| 原始 `impact` | 曲线后约值 | 解释 |
|---:|---:|---|
| `10` | `10` | 已强于下限，保持原值 |
| `25` | `25` | 下限锚点 |
| `50` | `25` | 获得明显强化 |
| `80` | `25` | 常见弱冲击冲锋枪进入可用区 |
| `100` | `25` | 获得质变但仍弱于典型低 impact 霰弹枪 |
| `200` | `25` | 极弱冲击被拉回下限附近 |
| `500` | `40` | 极端值获得帮助，但不会直接跳到霰弹枪级 |

### 5.4 待实测风险

- 冲击力依赖实际伤害，不能只比较 `<impact>`；必须按单位时间累计冲击和一次弹匣可造成的韧性削减量比较。
- 霰弹枪还有散射命中率、射程和“冲击连携”被动加成，标杆应取真实战斗结果，而不是只看 XML 单字段。
- curve 在 `percentage/multiplierZone` 之后执行。多个插件叠加、改装顺序和 cap 必须进入测试矩阵。
- 若插件可装在原生 `impact<25` 的武器上，它可能成为无收益陷阱；tooltip 应正确表达或通过适用条件排除。

## 6. 破韧增伤插件

### 6.1 玩法状态机

用户提出的核心模型可保留：

```text
增伤子弹有效命中
  → 创建或刷新“破韧监听 Buff”
  → Buff 存续期间监听韧性槽破裂事件
  → 每次破韧增加一层增伤
  → 刷新或延长监听窗口
  → 到期后退订事件并移除增伤效果
```

它把伤害收益绑定到“先挂标记、再完成破韧”的战斗行为，而不是直接给常驻 DPS，因此符合异质化目标。

### 6.2 目标域聚合结构

#### A. 聚合控制 MetaBuff

- 挂在敌人身上；
- 按 `(sourceUID, profileId)` 保存候选的配置、层数与到期帧；
- 包含一个 `TimeLimitComponent` 作为唯一生命周期门控；
- 包含一个 `EventListenerComponent` 监听破韧事件；
- 同一 `stackGroup` 只创建一个实例，后续命中只刷新对应 profile，不重复订阅；
- 普通帧只推进逻辑时钟，只有当前赢家到期才扫描候选并切换回退值。

#### B. 单一最终 PodBuff

- 由控制 MetaBuff 注入一个修改 `damageTakenMultiplier` 的 PodBuff；
- 每个候选先独立计算 `1 + stackCount × damagePerStack`，最终只取候选结果的 MAX；
- 候选切换时通过 `BuffManager.setPodBuffValue()` 原位更新，不替换 MetaBuff、不重新分配 Pod；
- 满层后的破韧只延长 deadline，倍率未变时不触发属性重算。

示意：

```text
damageTakenMultiplier = 1 + stackCount × damagePerStack
```

`BuffManager.getBuffById()` 用于找回控制 Buff，`TimeLimitComponent.setRemaining()` 维护聚合域的最晚到期；`setPodBuffValue()` 在 update 外立即重算、update 内合并进本轮脏属性重算。

### 6.3 为什么只原位修改固定 Pod

通用 `MetaBuff` 在构造时防御性复制子 Pod 模板，运行期修改模板并不会自动重注入。聚合器因此从创建起固定注入一个值为 1 的 Pod，不改变模板或成员关系。

`BuffManager.setPodBuffValue()` 只允许修改已注册 Pod 的数值，并让对应属性按管理器当前是否处于 update 安全重算；它不开放动态模板、追加 Pod 或重注入能力。这样既保留 MetaBuff 生命周期边界，也消除同 ID 替换效果 Buff 带来的分配、退订/重订和潜在帧间空窗。

### 6.4 配置形状

不要在 XML 中存放任意 AS2 函数名或可执行字符串。推荐使用封闭的声明式类型，由注册表解析：

```xml
<hitBehavior>
    <type>toughnessVulnerabilityPrimer</type>
    <stackGroup>grayGooVulnerability</stackGroup>
    <profileId>base</profileId>
    <duration>180</duration>
    <breakExtend>60</breakExtend>
    <maxDuration>300</maxDuration>
    <maxStacks>3</maxStacks>
    <damagePerStack>0.06</damagePerStack>
    <sameSourceOnly>true</sameSourceOnly>
</hitBehavior>
```

这里的 `180/60/300/3/0.06` 已作为第二波实验参数落盘，但仍不是完成实战标定后的正式平衡结论。

### 6.5 命中与破韧的顺序契约

现有 `BulletQueueProcessor.settleHit()` 的主顺序是：

```text
计算伤害 → 发布 hit → 处理死亡事件
```

现有 `击中时触发函数` 在多个路径中由 caller 提前调用，而且射线、穿透、链式等路径明确只对首个/主命中调用。直接复用它有两个问题：

- 回调可能早于正式伤害结果，难以排除闪避或无效伤害；
- 同一发是否先挂监听再触发破韧，会受具体命中路径影响。

推荐新增统一的声明式命中效果阶段：

```text
计算实际伤害
  → 确认命中有效
  → BulletHitEffectRegistry.apply(...)
  → 发布 hit
  → ImpactStateHandler 处理冲击并按需发布 ToughnessBroken
```

建议默认允许“同一发有效命中先挂监听、随后由这一发造成破韧并获得首层”，因为该语义对双枪交替射击最稳定，也不依赖左右手先后顺序。如果设计上要求“第一发只埋种、不能触发本次破韧”，应显式增加 armed frame/phase，而不是依赖事件订阅顺序。

### 6.6 破韧事件契约

事件应在 `ImpactStateHandler` 的 `remainingImpactForce > 韧性上限` 分支内发布，并放在韧性清零之前或紧邻清零处：

```actionscript
dispatcher.publish(
    "ToughnessBroken",
    hitTarget,
    bullet.shooter,
    bullet,
    damageResult,
    isRigid
);
```

建议语义：

- 一次越过阈值只发布一次；
- 刚体目标只要韧性槽被打空也发布，因为事件表达的是“破韧”而非“倒地”；
- 击杀优先、闪避、浮空/倒地分支的直接清槽不发布；
- 监听器默认可以按 shooter 过滤，决定是否只接受标记施加者造成的破韧；
- 事件名已锁定为 `ToughnessBroken`。

### 6.7 全局易伤与来源限定

`damageTakenMultiplier` 是目标的全局承伤属性。即使破韧监听按 shooter 过滤，PodBuff 生效后仍会放大所有来源对该目标造成的伤害，包括伙伴或其他友方单位。

施工前必须在以下语义中二选一：

1. **全队易伤**：沿用 `damageTakenMultiplier`，实现简单，插件同时具有辅助价值；
2. **仅施加者增伤**：不能只使用全局属性，需要在伤害管线加入来源条件，成本和热路径风险显著更高。

第二波采用方案 1（全队易伤）。同一 `stackGroup` 的不同来源/profile 先由领域控制器取完整候选倍率的 MAX，最终 Pod 仍使用 `MULT_POSITIVE` 与其他易伤系统保守共存，不相乘叠加。

### 6.8 正反馈风险

伤害计算会先应用 `damageTakenMultiplier`，冲击结算又依赖本次伤害，因此易伤会同时提高后续打血和打条效率，形成：

```text
破韧 → 增伤 → 后续冲击更强 → 更容易再次破韧 → 继续增伤/续时
```

这可以成为构筑奖励，但必须通过最大层数、延长上限、每层增伤和破韧来源过滤控制。尤其要防止同一把装有冲击插件的高射速武器独立完成无限续杯，从而反过来淘汰双武器协同。

### 6.9 与磁稳贯穿弹的收益锚定

“灰蛊裂隙弹”的直接竞争品是同属高等 `弹药` tag 的“磁稳贯穿弹”。后者把普通弹替换为 `pierceLimit=3`、无常规穿透伤害衰减的“次级穿刺子弹”，默认射击间隔为：

```text
I磁稳 = (I + 50) × 1.2
射速保留率 q = I / I磁稳
磁稳吞吐倍率 M(I,k) = q × k
```

其中 `k` 是一次射击的实际有效判定数：单体实战为 1–2，列队群体上限为 3。若单体第二判概率为 `p₂`，则单体期望为 `q×(1+p₂)`，不能把“稳定二判”或“三判上限”直接当作常驻收益。完整弹匣循环还应以实测换弹时间 `R` 修正射速保留率：

```text
q循环 = ((C-1)×I + R) / ((C-1)×I磁稳 + R)
```

2026-07-13 数据快照中，54 把冲锋枪的中位间隔为 `I=85`；忽略换弹时 `q≈0.525`，稳定二判约 `+4.9%`，三判群伤上限约 `+57.4%`。普通手枪与大威力手枪中位间隔更长，磁稳贯穿弹的固定 `+50` 惩罚占比更低，因此天然更偏爱慢射武器；灰蛊裂隙弹保持原射速，天然更偏爱高射速冲锋枪。这种宿主偏好差异属于预期异质化，不应通过按枪种动态易伤倍率强行抹平。

灰蛊裂隙弹不按满层时长直接估值，而按伤害加权平均层数估值：

```text
S̄ = 1×w₁ + 2×w₂ + 3×w₃
G灰蛊 = damagePerStack × S̄
```

`w₁/w₂/w₃` 是玩家与队友有多少基准伤害实际打在相应层数期间；首破前伤害属于零层。峰值建议取磁稳单体与群体收益区间的低位：

```text
G峰值 = G磁稳单体 + λ×(G磁稳群体-G磁稳单体)
λ建议 0.20–0.30
```

用冲锋枪中位间隔、稳定二判上限和 `λ=0.25` 代入，峰值约为 `18%`，对应当前 `6%×3层`。预期短战为 `0–4.8%`，精英战约 `7.2–10.8%`，长线首领约 `10.8–14.4%`，只有满层稳定输出达到 18%。由于它是全队易伤且会反向提高后续冲击，当前可接受调参区间为 `6%–8%/层`、峰值 `18%–24%`；未经实测不应超过 `8%/层`。若收益不足，应先检查平均层数、首破时点和持续窗口，而不是直接提高倍率。

### 6.10 灰蛊系列设定与穿刺互斥

正式名称定为“灰蛊裂隙弹”，与既有“灰蛊蚀刻霰弹”组成可识别的纳米弹药产品谱系。弹体外层携带休眠纳米机器构成的牺牲性涂层：命中时涂层剥落并附着目标；同一发射者完成破韧时，结构裂隙为群落提供扩散通道；群落随后广播脆弱区域，使所有友军攻击都能利用该弱点。再次命中表示补充群落和通信链，破韧续时表示获得新的裂隙与材料；到期则解释为自清洁、免疫反应和电子干扰令群落失活。

`sameSourceOnly=true` 表示群落与发射武器的遥测密钥/弹道特征绑定，只有施加者造成的破韧能触发扩散；一旦裂隙网络建立，弱点信息对全队可见，因此效果仍是全队易伤。

穿刺弹需要坚硬、低变形、低摩擦并保持完整的侵彻外被；灰蛊涂层则必须在命中时剥落、转移和沉积，两条材料路线相互矛盾。因此除共同 `弹药` tag 阻止与磁稳贯穿弹等弹药插件叠加外，灰蛊裂隙弹还使用 `<excludeBulletTypes>pierce</excludeBulletTypes>` 排除原生穿刺武器，避免多判、群伤、无射速惩罚与全队易伤被集中到同一上位弹种。

### 6.11 普通手枪的行为型补弱

普通手枪内部长期存在预算塌陷：表现较强的轻型自动武器会被分流到“冲锋枪”，高单发模型会被分流到“大威力手枪”，留下的精确“手枪”子类难以仅靠面板增幅同时获得身份与竞争力。因此本轮不提高普通手枪的 `power/interval`，而把它定位成低面板、低负担、靠行为为后续武器和全队提供增益的标记工具。

> 2026-07-15：本节的旧 3 层/破韧续时实验档已被本文 §15 的 18 格命中模型取代；以 §15 与 `agentsDoc/data-schemas.md` 为当前真相。

灰蛊裂隙弹基础档继续服务冲锋枪和大威力手枪：`duration=180`、`breakExtend=60`、`maxDuration=300`、`maxStacks=3`、`damagePerStack=0.06`。精确普通手枪分支仅提高三项：

```text
duration:       180 → 240 帧（6 → 8 秒）
maxDuration:    300 → 360 帧（10 → 12 秒）
damagePerStack: 6%  → 7%（三层峰值 18% → 21%）
```

这个档位把主要收益放在建立/维持标记的容错与团队易伤上，仍低于每层 8%、峰值 24% 的实测前警戒线；`breakExtend/maxStacks/sameSourceOnly` 不变，避免普通手枪获得无限续杯或独立闭环。设定上解释为普通手枪较低的膛压与弹道载荷减少涂层剪切和热损失，使更多纳米机器人抵达并停留在目标表面。这里表达的是架空弹药与宿主负载的适配性，不主张现实中“手枪一定更温和”的普遍物理结论。

实现上不能写旧式 `name="手枪"`：该值会按兼容规则同时匹配 `use=手枪`，从而误伤冲锋手枪和大威力手枪。新增的向后兼容限定写法 `name="weapontype:手枪"` 只匹配精确子类；旧无前缀分支仍按 `use/weapontype` 联合集合匹配。Tooltip 把内部 token 翻译为“武器子类：手枪”，并对嵌套 `hitBehavior` 展示秒数、层数和每层易伤，不得输出 `[object Object]`。

- 每秒冲击、每弹匣冲击、首次破韧耗时；
- 与典型霰弹枪有效距离内实测对比；
- 原生高冲击武器不会被插件反向削弱；
- tooltip 不把低 `impact` 错写成“冲击力降低”。

### 9.3 增伤插件

- 同一目标/`stackGroup` 的有效命中只创建一个控制 Buff、一个监听和一个最终 Pod；

- 续时不超过上限；
- 刚体、闪避、击杀、浮空、倒地分支；
- 相同 shooter、不同 shooter、伙伴伤害；
- 弱→强与强→弱命中顺序结果一致，弱 profile 不延长强 profile；
- 强 profile 到期后回落到仍存活的弱 profile，多来源/profile 只取 MAX 不相加；
- 穿透、射线、链式和多目标的主/副命中规则；
- Buff 到期、目标死亡、场景销毁后无幽灵 Pod 和遗留订阅；
- 满层续时与赢家切换不替换 Pod，update 内外改值均不发生重入或状态污染。

### 9.4 构筑收益

- 双持相同冲锋枪的低操作构筑；
- 一把破韧、一把增伤的混合职责构筑；

- 突击步枪 + 冲锋枪；

## 15. 18 格命中模型与追猎射击适配（2026-07-15）

旧“破韧才叠层”模型在冲锋枪上被削韧不足卡死，在杂鱼上又常未进入第三次破韧就已击杀。当前模型改为稳定命中计数：内部 18 格，玩家只需识别 6/12/18 三个结算点。冲锋枪每命中 1 格，大威力手枪 2 格，普通手枪 3 格；真实破韧额外追加一次本枪种等价命中，从必要条件降为锦上添花。

每格提供 1% 全队易伤；每跨过 6 格，该发动态获得一次击溃；预测达到 18 格时同时获得斩杀。基础档仅由冲锋枪完整使用，节点击溃为 1%、满层斩杀为 8%，以三个不可转移的节点收益补偿一发一格的慢启动；大威力手枪分支显式锁定为 0.1% 与 5%，避免双枪快速挂满全队易伤后切长枪的循环继续膨胀；普通手枪补弱档为 0.3% 与 8%。达到满层后不再重复结算已触发的击溃节点，但后续灰蛊命中持续拥有本 profile 的满层斩杀判定。

基础衰减参数为停火 90 帧后、每 10 帧退一格；普通手枪为 150/15 帧。节点使用整段回差：6/12/18 节点分别要退到 0/6/12 格才重新武装。这允许 Boss 游击战中通过真实拉开时间重新获得击溃，但阻止在 5↔6 附近微停火刷取。

大威力手枪按双枪追猎射击的典型 12–15 发窗口标定，因此每发 2 格可在一次技能中稳定经过前两个节点，高容量配置才能进入满层区。追猎射击所有六个子弹初始化点均从对应手枪属性透传 `hitBehavior`，不再丢失插件的新行为。

灰蛊仍使用与黑爪一致的 `sqrtScale 1.4/min 20` 冲击压缩，保证冲锋枪长枪构筑至少可用。`ToughnessBroken` 的语义同步收窄：只有非刚体实际进入破韧/击倒状态时才发布；刚体越阈仍会把韧性槽归零，但不发事件。这与玩家可见结果一致，也避免无击倒表现时隐式奖励灰蛊层数。
