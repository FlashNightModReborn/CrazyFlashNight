# 统一输入 R13：长宽比变化与恢复活性

日期：2026-09-24。基线：commit `5c02a103603ca60ccadd62348fe83753838fb0ca` 加 R13 未提交工作树。仅 C1 隔离候选，不是普通游戏或正式 runtime。

## 现场与根因

用户对 R12 反馈：其他验收可行，但连续改变长宽比会拉伸失控，有时恢复、有时最终一直“正在恢复输入”，随后关闭。现场日志为 `logs/c1-input-acceptance/20260924-105729-781-c472b3f8`；closure `e12d8c8c0d911f66d41ff53f1aff1fdfcb6ac7eb99d6c5efb7317144eea8b2e9`，与 R12 冻结候选相符。

1. **确定的比例错误**：保留位图按 `width/stillWidth` 和 `height/stillHeight` 两个不同系数缩放。窄高／宽扁客户区会非等比拉伸。浏览器 Bounds 还先于取消截图更新，可能把浏览器中间帧固化进位图。
2. **确定的页面加载请求丢弃**：北京时间10:59:15.119，Host 在 epoch135／geometry96 发出恢复；10:59:15.190已进入epoch136／geometry97。10:59:15.194，真实整形页的 snapshot 请求仍带135／96，到达后被统一的 inputRound 相等判断丢弃。其后只有 suspended，没有最后页面的 page_ready；临近退出时 Raw 输入仍 Healthy／Neutral／Eligible，无来源丢包。页面加载和物理输入轮次被错误地共用失效边界。
3. **定向测试补出的目标丢失**：v1 中真实快照被声明延迟1200ms后跨几何送达，数据恢复了，但第一次页面打开中途缩放导致协调器回退到 M，Web 无法获得正常准入。中间反例 `tmp/c1-r13/matrix1` 保留；不是一项已通过的输入验收。

旧包的首轮压力试验 `tmp/c1-r13/r12-aspect-negative` 因草稿不等而失败；其中键盘刺激可能涉及当时输入法组合，本轮不据此声称复现了现场卡死或丢失已确认文字。后续长宽比压力测试使用既有草稿，原键盘／组合专项独立执行。

## 修复合同

- 位图改为统一 `min(width/sourceWidth,height/sourceHeight)` 比例并居中留边。正常 Web 页面继续走既有等比布局；窄窗口内容整体变小、出现空白可以接受，横纵拉扁不属于预期。
- 先保留旧 Web viewport 的画面，再更新浏览器 Bounds，避免抓取正被重排的中间尺寸。模态遮挡、真实控制器退休和旧键盘尾包隔离继续保留。
- 只有 `snapshot/query` 可按**当前精确页面实例、generation、session、coverage**接收已过去的正整数输入轮次；拒绝未来轮次。源控制器仍由 WebMessage sender 校验，旧页面实例／代次不因此复活。只读请求不会授予输入；close、写命令、ACK、prepared、grant仍走原严格边界。生产 Host task 与 AS2 服务仍是数据权威，未复制业务规则或重放写命令。
- 协调器新增显式的 `ConsumeIntentForRetainedPreparation`：C1 在消费已经由完整输入产生的一次性打开／关闭请求后，承担保留目标生命周期的义务。几何改变会重新取消、重新准备，但不把已开始构建的页面退回世界。仍需完整取消覆盖、可信 neutral 和新一轮 prepared 才能 grant。构建失败必须 Fail；原 `ConsumeIntentForPreparation` 的回退语义保持，原测试保留。
- 页面准备失败明确进入故障状态并显示“恢复失败，请关闭候选后重启”，不一直伪装成恢复中。没有添加焦点重试、伪造松键或重放用户点击。
