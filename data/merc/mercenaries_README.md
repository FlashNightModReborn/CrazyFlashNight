# 佣兵配置文件说明 (mercenaries.json)

本文档说明如何在 `mercenaries.json` 文件中配置佣兵装备及其插件（MOD配件）。

---

## 📋 基本格式

### 装备配置字符串格式

```
装备名#强化等级#进阶名#配件1,配件2,配件3
```

### 参数说明

| 参数 | 必填 | 说明 | 示例 |
|------|------|------|------|
| **装备名** | ✅ 必填 | 装备的ID名称 | `PPK`、`黑框眼镜` |
| **强化等级** | ❌ 选填 | 装备强化等级（1-13），不填默认为1 | `5` 表示 +5 强化 |
| **进阶名** | ❌ 选填 | 装备进阶/涂装名称，留空则不使用进阶 | `二阶`、`三阶` |
| **配件列表** | ❌ 选填 | 用逗号分隔的配件名称列表，留空则不安装配件 | `弹簧,螺丝套件,小型液晶屏` |

## 📝 配置示例

### 示例 1：配置手枪（带配件）

```json
"secondary1": "PPK#5##弹簧,螺丝套件,小型液晶屏"
```

**解释：**
- 装备：PPK手枪
- 强化：+5
- 进阶：无（留空）
- 配件：
  - 弹簧（射速增强）
  - 螺丝套件（精度增强）
  - 小型液晶屏（瞄准增强）

---

### 示例 2：配置防具（带进阶和配件）

```json
"body": "红黑色功夫装#3#二阶#可塑式钢板,战术背带"
```

**解释：**
- 装备：红黑色功夫装
- 强化：+3
- 进阶：二阶
- 配件：
  - 可塑式钢板（防御增强）
  - 战术背带（扩展配件槽）

---

### 示例 3：配置近战武器（简单配置）

```json
"melee": "pencil#1##护手,石英磨刀石"
```

**解释：**
- 装备：铅笔（近战武器）
- 强化：+1
- 进阶：无
- 配件：
  - 护手（防护）
  - 石英磨刀石（锋利度增强）

## ⚠️ 注意事项

### 1. 配件必须存在
配件必须在 `data/items/equipment_mods/` 目录下的配件列表中定义，否则无法加载。

### 2. 配件类型匹配
配件的 `<use>` 标签必须包含该装备类型：
- 手枪配件只能用于手枪
- 近战配件只能用于近战武器
- 防具配件只能用于对应部位的防具

### 3. 配件槽位限制
配件数量不能超过装备的配件槽位数：
- 默认：3个配件槽
- 可通过特定配件（如"战术背带"）扩展槽位数

### 4. 配件标签冲突
同一 `tag` 的配件不能同时装备。例如：
- ❌ 不能同时装备 "骨芯颅印" 和 "辅助握持板"（它们有相同的冲突 tag）

### 5. 进阶参数占位符
**重要：** 当第三个参数（进阶）留空时，**必须保留两个 `#` 号**：

✅ **正确：**
```json
"secondary1": "PPK#5##弹簧,螺丝套件"
```

❌ **错误：**
```json
"secondary1": "PPK#5#弹簧,螺丝套件"
```

## 🧠 性格配置（personality）

佣兵六维人格默认由「等级 + 名字字符码」的确定性种子生成（`_root.生成随机人格`）。在条目顶层加
`personality` 可按维度覆写，**只影响你写出的维度**，其余仍取随机人格结果。

```json
{
  "level": 30,
  "name": "示例佣兵",
  "id": 900,
  "height": 170,
  "face": 0,
  "hair": 20,
  "gender": "女",
  "personality": { "勇气": 0.9, "技术": 0.2 },
  "equipment": { "head": null }
}
```

- 可配置维度只有六个，键名必须逐字一致（中文）：`勇气`、`技术`、`经验`、`反应`、`智力`、`谋略`。
- 取值区间 `[0, 1]`；越界会被夹回 0 或 1，非数值的那一维会被忽略（六维以外的键一律丢弃，
  写成 `null` 与不写同义——不会被当成 0）。
- 生效范围：战队/雇佣面板的六维雷达、角斗场标准/隐藏对战（对手卡与实际对手同源）、
  出战佣兵战斗 AI 的实际决策（`配置人形怪AI` 会按覆写后的人格重算派生参数）。
  这些消费方读的都是同一份 `merc[19].性格`，不会各算一套。
- 待雇 NPC 也吃这份配置：`createMercEntity` 会把 `merc[19].性格` 合并进木偶的 personality，
  它没配 `dialogues` 时抽哪几句公共台词就由这一维决定。世界内刷出的副本由
  `MercSpawner.copyMercMeta` 独立补拷，不会再被公共深拷贝工具抹平（见文末「已知边界」）。
- 不生效范围：角斗场 roster / 元战队 / 爬升模式的佣兵对手，以及一切兵种怪——它们没有佣兵
  元数据通道，仍取随机人格（与 authored `passive` 的边界一致）。
- 主动技能**不能**在这里配置：技能的唯一权威源是 `已学技能表`，由等级桶 + 装备组合随机生成，
  调研结论见 `docs/人形怪AI定制-调研结论与开发方向-2026-09-07.md` §4 与 §4.1（佣兵侧可行性复查）。
- 注意 `技术` 这一维会被面板的技能预估读到（`buildSkills` 按 `技术` 档位算缓存键与点数倍率），
  而实战单位首次初始化时人格尚未生成，技能表恒按 `t0` 算——这是上面 §4.1 记录的既有偏差，
  覆写 `技术` 只会让它更明显，不会新引入 bug。

## 💬 指定对话（dialogues）

在条目顶层加 `dialogues` 数组，这个佣兵在世界里被雇下之前，点「对话」只念你写的台词，
不再按人格去抽公共台词池。

```json
{
  "level": 30,
  "name": "示例佣兵",
  "id": 900,
  "dialogues": [
    "听说北边又闹僵尸了，你去不去？",
    { "text": "枪我擦了，火药也干了。", "expression": "微笑" }
  ],
  "equipment": { "head": null }
}
```

- 一条台词写成纯字符串（表情按 `普通`），或写成 `{text, expression}`。`expression` 可选值与 NPC
  对白表一致：`普通`、`微笑`、`坏笑`、`大笑`、`呲牙`、`思考`、`严肃`、`无奈`、`茫然`、`鄙视`、
  `难过`、`悲伤`、`悲伤2`、`愤怒`、`比划`。留空即 `普通`；写错不会报错，也不会让对话框空白，
  只是那张脸切不过去。
- **每点一次「对话」播一条**：台词整表洗牌后逐条轮播，播完一轮再洗一次。没配置的佣兵是几条
  随机台词挤在同一轮里、一次点按整段播完，两者语义有意不同。
- 只在**世界内的待雇 NPC** 上有意义：雇下之后是出战单位，没有对话入口；角斗场对手和兵种怪
  读的是怪物台词表，不吃这份配置。
- 杂交出来的佣兵不继承这份台词：它的名字是现场生成的，查不到原记录，继续走随机池。
- 空串、数字、只有 `expression` 没有 `text` 这类条目只丢弃自身；整表都没有有效文本时，
  等同于没配置。
- ⚠ **台词里不能出现半角双引号 `"` 或反斜杠 `\`**。`mercenaries.json` 由 AS2 侧 `LiteJSON`
  解析，它按 `indexOf('"')` 扫字符串、不解码转义，一处引号写歪会让**整份佣兵池**解析失败。
  要引用语气就用全角「」或“”。`scripts/run-merc-loadout-tests.ps1` 的静态门守这条。

## 🧩 其他顶层可选字段

与 `equipment` 同级，全部缺省即不生效：

| 字段 | 作用 |
| --- | --- |
| `personality` | 覆写六维人格，见上一节 |
| `passive` | 佣兵被动技能表（`{技能名:{技能名,等级,启用}}`），出战单位经 `佣兵参数.被动技能` 生效 |
| `pricemultiplier` | 雇佣价格倍率 |
| `enhancement` | 写入 `merc[19].装备强化度`；出战生成处的注入目前是注释状态，填了暂不影响实战装备强度 |
| `hidden` | 标记为隐藏佣兵（`merc[19].隐藏`）。雇佣列表等消费方按该标记过滤，与池内位置无关 |
| `equiplocked` | 填 `true` 后该佣兵装备固定，托管交付/替换/取回全部拒绝，面板整区禁用 |
| `dialogues` | 指定该佣兵在世界里待雇时的台词，见上面「指定对话」一节 |

以上字段都写进 `merc[19]` 元数据并随存档保存，**只对新读入/新雇佣的佣兵生效**，
改动配置不会追溯修改已有存档里已雇佣的佣兵。

## ⚠ 已知边界：世界副本的元数据与池流转

`MercSpawner.createMercData` 用 `_root.深拷贝数组`（`scripts/引擎/引擎_fs_常用工具函数.as`）复制库
记录，而那个工具只按数字下标递归、遇到具名键对象返回空数组，所以副本的 `佣兵数据[19]` 一度是空的。
现在非杂交分支在复制之后显式补一份：`instance[19] = copyMercMeta(库记录[19])`（`MercSpawner.copyMercMeta`
/ `copyPlainData`）——深拷一份只属于本副本的纯数据，并打上 `世界副本: true`。必须是新对象而不是共享
引用：装备托管在运行期写 `merc[19].装备托管`，共享引用会把玩家交付给某个场景单位的物品回染进库记录，
之后同一条记录刷出的每个 NPC、雇下的每个佣兵都带着同一份托管。

补齐之后的字段矩阵：

| 字段 | 面板雇佣 / 角斗场 / 雇后的出战记录 | 直接雇下世界里的待雇 NPC |
| --- | --- | --- |
| `dialogues` | —（不参与） | 生效；木偶阶段仍按名字查 `MercLibrary` 索引，与 `[19].对话` 等价 |
| `personality` | 生效 | 生效（本轮修复） |
| `passive` / `equiplocked` | 生效 | 生效（本轮修复）：出战单位的 `佣兵参数` 现在拿得到 authored 值。`equiplocked` 当前无记录填写 |
| `pricemultiplier` | 生效 | 不生效，**与 `[19]` 无关**：世界内定价 `mercWorldGoldPrice` 只算 `[18]`×口才，从不读倍率 |
| `hidden` | 生效 | 列表侧照旧（列表按池记录过滤，池记录 `[19]` 本来就完整） |
| 池流转（雇下移出池 / 解雇回池） | 照旧 | **照旧不参与**，见下 |

关于最后一行：`[19]` 一补齐，`removeMerc` 里「解雇把记录 push 回可雇池」的条件
`meta.是否杂交 == false` 就会成立，而副本的 `[2]` 已被 `createMercData` 拼上随机后缀，回池等于往池里
塞一份 id 膨胀的重复项，之后同一条库记录可以反复刷出、反复雇。所以 `MercSpawner.removeMerc` 与
`MercPanelService.handleWorldHire` 都先判 `世界副本 !== true`，世界副本一律不做池流转——这与修复前的
可观察行为一致（修复前该分支因 `[19]` 为空、`spliceFromPool` 又按 `[2]` 匹配不上而同样不生效），
不是新语义。真要统一「世界雇下移出池 / 解雇回池」得先让副本能回溯到库记录身份（不改写 `[2]`
或另存库编号），那是独立改动。

其余边界保持原样：

- 杂交分支不在本轮范围：它由 `MercHybridizer.hybridize` 自己构造 `[19]`，不带 `世界副本` 标记。
- 旧存档里 `同伴数据[i][19]` 已是空数组的记录不回填、不迁移，行为与修复前相同。
- `enhancement` 的实战注入仍是注释状态（见上表）。
