# 战队面板 → 双栏工作台翻新设计（2026-08-03）

**文档角色**：一次性施工设计与交接契约。稳定规则回写 [agentsDoc/workbench-ui-system.md](../agentsDoc/workbench-ui-system.md)；跨层协议护栏仍以 [agentsDoc/as2-web-panel-migration.md](../agentsDoc/as2-web-panel-migration.md) 为准。

## 0. 背景与目标

战队面板（`team`：佣兵/伙伴/战宠/机械四 tab）实现于 2026-06，早于双栏工作台体系定型，未消费任何共享基础设施：自绘缩放、双份 Toast、三处 token（两处同值复制 + 一处硬编码）、零键盘可达性、手写确认弹窗、巨型 innerHTML。本轮把它整体迁入 workbench 体系，目标是**体系身份对齐**，不是换皮：

- 布局：`DualPaneShell` + 封闭 profile + `PanelScale`（1024×576 逻辑画布）。
- 交互：键盘可达（Enter/Space 激活、focus-visible 基线、Esc 分层）、共享 modal、HelpAction、CommitBar 权威写。
- 视觉：DLS/θ token + 语义色 + `--wb-motion-*`，战术橙气质收敛为一个 skin 覆盖块。
- 工程：协议零改动（JS 纯展示层定位不变），pet/merc 控制器重写，CSS 三旧件删除归一。

**非目标**：panel=mercs/pets 协议与 AS2 服务、PanelRequestMux 迁移（见 §7 偏差登记）、拖拽、虚拟滚动、arrow-key roving 网格导航（Tab+Enter 已满足等价要求，留后续）。

## 1. 聚合形态（用户已裁决）

- **伙伴/战宠/机械三 tab 统一形态**：同一 controller（`pet-panel.js`）按 rosterType 重开，视图结构完全一致。
- **佣兵 tab 特殊形态**：有纸娃娃/装备/技能/阵亡复活，右栏决策面与培养页形态单独设计（§3.2）。
- tab 切换 = 子 controller 重建 Shell（同 Skills/Crafting 换 view 重建的现役模式）；`_lastTab` 会话记忆保留；busy 守卫阻止切换/关闭保留。

## 2. 壳层（team-panel.js 重写）

- `Panels.register('team', …)` 不变；`createDOM` 返回 `.panel-scale-shell .team-host`，`PanelScale.attach(host, 1024, 576)`；删除自绘 updateFitScale/bindScaleWatcher。
- 两个子容器（merc / pet）保持，tab 切换只切 `hidden` + 调 controller.onOpen；修正 `_views.pet` 命名错位（键名与 tab id 对齐）。
- tab 条改为唯一 `<nav class="team-tabs">`（4 个 `workbench-mode-btn` 风格按钮，`aria-label="战队分类"`，激活态 `team-tab-active` + `aria-current`），作为 **header 第一个 action** 注入当前激活 Shell：controller 的 `onOpen(el, initData)` 接收 `initData.tabNav` 元素，先 `_shell.addHeaderAction(tabNav)` 再加本领域 actions（帮助、关闭）。
- 世界内雇佣/领养候选逻辑不变：`{view:'hire', kind, detail}` initData → 切到 kind 匹配 tab → 候选置顶进 roster 网格首张卡。
- 关闭：`onRequestClose` busy 守卫保留；发 `panel:'team', cmd:'close'` 不变。
- CSS 改为 panels.css 静态闭包加载，删除 `ensureLink` 运行时注入；`css/team_panel.css` 删除（内容并入 `css/workbench/team.css`）。

## 3. 视图地图

### 3.1 伙伴/战宠/机械（统一，profile = `catalog-decision`）

每 tab 打开时 controller 重建一个 `DualPaneShell`（profile 字面量 `'catalog-decision'`，WB128 兼容）：

| 状态 | 左栏（SOURCE=名册/目录） | 右栏（TARGET=决策） |
|------|--------------------------|----------------------|
| roster（默认） | PaneChrome：排序/筛选下拉 + 「＋ 领养宠物」入口；EntityTile 卡片网格（候选卡置顶）；空态四类 | 选中实体详情：头像/名称/等级/chip/体力·经验条/快捷进阶开关；动作：出战·休息切换、恢复体力、「培养 →」进 SecondaryPage |
| store（领养） | 分类 tabs + 可领养目录网格 | 选中候选预览 + **CommitBar**（价格、余额、阻断原因、唯一主 CTA「确认领养」） |
| advance（培养） | — | SecondaryPage 覆盖 body：属性/战斗属性/进阶方案 + 出战/恢复/强化/删除 |

- header：tabNav｜标题「伙伴/战宠/机械」｜status（读取中/就绪/错误）｜metrics（金币、K点、出战 n/n、栏位 n/n）｜HelpAction｜关闭。
- roster 网格挂 `GridDensityController`（panelId `team-pet`，默认 compact、localStorage 持久化）；compact 隐藏的信息由共享 PanelTooltip 等价提供。store 目录不做密度切换（决策目录保持 full，对齐 crafting recipes）。
- 领养/进阶/删除流程见 §4。

### 3.2 佣兵（特殊，profile = `catalog-decision`）

| 状态 | 左栏 | 右栏 |
|------|------|------|
| roster（默认） | PaneChrome：「＋ 雇佣佣兵」入口；佣兵卡网格（纸娃娃头像 + 出战/阵亡徽标；世界内候选置顶） | 选中佣兵决策面：中号纸娃娃、名称/等级/状态、关键属性摘要；动作：出战·休息（阵亡→复活）、「培养 →」；roster 网格挂密度切换（panelId `team-merc`） |
| hire（雇佣市场） | 等级定位 chips + 无缝下滑佣兵池（触底加载、哨兵行） | 选中候选：纸娃娃/技能/特质预览 + **CommitBar**（金币或 K 点价格、余额、阻断原因、唯一主 CTA「确认雇佣」） |
| detail（培养） | — | SecondaryPage：造型预览 Canvas、性格特质、战斗技能、装备调配（2026-08-23 起可写：托管换装交付/替换/取回，手雷槽只读，见《佣兵装备托管-设计-2026-08-23》）、出战/复活、解雇 |

- header metrics 增加「复活币」；「出战 n · 佣兵栏 n/n · 复活币 n」。
- 纸娃娃渲染链（asset-timeline + dressup-doll-renderer、manifest 缓存、cacheKey、alpha 测量）原逻辑保留，只改挂载位置与尺寸。

## 4. 权威写与反馈

- **CommitBar 仅用于交易型写**：领养（adopt/world_adopt）、雇佣（hire/world_hire）。阶段：browse（选候选，零写入）→ preview（右栏预览 + 价格/余额/阻断原因，来自最新 snapshot 展示，不作权威裁决）→ commit（唯一主 CTA，busy 到回包）→ reconcile（回包异常/超时→只读提示 + 重新拉 snapshot，绝不自动重放）。
- **直接动作**（出战/休息、恢复体力、强化、进阶、复活、扩容）保持按钮 + pending 态（beginOp/endOp 语义保留），blocked 时给可读原因（tooltip/status），不允许可点外观 + silent no-op。
- **删除/解雇**：改用 `shell.openModal`（共享 focus trap/Esc/opener restore），删除自绘 confirm overlay。
- Toast 统一为共享 `Toast.add`（本地 `toast()` 包装，同 skills/kshop 模式）；删除 pet 三色队列与 merc 单 toast 两套实现。
- 空态统一 `{kind, statement, nextStep}` 语义，使用 `.workbench-empty-state` + `data-empty-kind`（empty/filtered/error/unavailable）；商店加载保留骨架/loading 态并接入 `WorkbenchState` status 投影。
- status：`setStatus(text, WorkbenchState.*)`；FlowRail 仅在 pending/写中提升亮度（setStatus 已自动处理）。

## 5. 键盘与可达性

- 实体卡统一 `Workbench.EntityTile`（`projectInteraction` → `applySemantics` → `bindActivation`：click + Enter/Space；blocked 卡 inspectable/actionable 分离，激活只解释原因）。
- 全部动作按钮带「名称 + 当前动作」的 aria-label；排序/筛选下拉为共享可键盘操作组件（按钮开/关、菜单项真 button、Esc 关并归还焦点）。
- Esc 分层：modal → SecondaryPage →（面板关闭由 Host panel_esc 承担，前端不重复拦截）；下拉/搜索草稿各自先消费。
- focus ring 全靠 `states.css` named baseline，team.css 不写任何 outline 规则（WB135）。
- 命中区：主 CTA ≥40px、实体卡 ≥44px、图标动作 24×24 透明 hitbox。
- tooltip：每 controller 一个 `PanelTooltip.createScope`，close/rebind 时 dispose；沿用 `bindAsync` 被动说明原型；装备 rich tooltip 协议不变。

## 6. CSS 与 token 策略

- 新增唯一文件 `launcher/web/css/workbench/team.css`，在 `panels.css` 中插到 `character-build-stats.css` 之后、`states.css` 之前。
- 只消费 `--dls-*` / `--theta-*` / `--wb-semantic-*` / `--wb-motion-*` / `--wb-ease-*` 与 core 结构 token；**零硬编码色值、零裸 duration/easing、零 `transition:all`**（触碰行 ratchet 清零要求）；字号遵守 §4.1 下限（中文正文 ≥10px、主标签/按钮 ≥11px）。
- skin 块：`.team-workbench[data-workbench-skin="team"]` 做 token 覆盖（accent 取 `--dls-energetic` 琥珀系承接原战术橙气质），不改布局/命中区/状态结构；语义色不覆盖。
- 动效只变 opacity/transform/color/border-color；reduced-motion 由 shell 根统一关闭，team.css 不新增本地 reduced block、不新增 keyframes（优先复用 `wb-pulse-busy` 等 shared keyframes）。
- 滚动面（名册网格、雇佣池、详情滚动区）使用共享 `--wb-scrollbar-*` 窄轨 token + 移除系统箭头。
- 不覆盖壳级 `grid-template-columns/rows`（WB129）；footer 需求全部走 pane 内部，不新增 root footer。
- 删除 `css/pet_panel.css`、`css/merc_panel.css`、`css/team_panel.css`（债务只降不升）；`harness.html` 同步移除这三个 link。
- `.kshop-workbench` 历史类名不动；team 根类用 `team-workbench` + `data-workbench-skin="team"`。

## 7. 偏差登记（须回写 canonical doc）

1. **panel_resp 直挂 listener 保留**：pet/merc 现有 callId + session 守卫的请求层不变，未迁 `panel-runtime.js` 的唯一 Router/Mux（协议零改动原则；后续独立批次）。
2. **每 tab 重建 Shell**：对齐 Skills/Crafting 现役模式，构造点使用 profile 字面量并登记进 `tools/workbench-ui-ratchet-baseline.json` 的 `profileGate.productionCalls`（pet-panel.js ×1、merc-panel.js ×1）。
3. **arrow-key roving 网格导航未实装**：Tab + Enter/Space 满足等价激活要求，留后续批次。
4. store/hire 目录不做密度切换（决策目录保持 full，同 crafting recipes 先例）。
