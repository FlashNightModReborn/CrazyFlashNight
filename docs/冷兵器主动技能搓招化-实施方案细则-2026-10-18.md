## 0. 一句话结论

可行，且**比上一版计划小很多**：不需要新增按键事件、不需要改 C#、不需要重建 V8 bundle、不需要动任何 XFL。
真正要落地的是 **1 个指令表 XML + 1 个运行时合并点 + 1 个按名释放入口 + 1 个 AS2 派发文件 + 2 处挂载**，
其中「只在冷兵器模式可放」这条**必须写在 AS2**（XML 的 `<Requirements>` 生产链路不消费，写了不生效）。

## 3. 指令表设计

### 3.1 事件词表（现有 18 种，够用，不扩）

方向：`FORWARD / BACK / DOWN / UP / DOWN_FORWARD / DOWN_BACK / UP_FORWARD / UP_BACK`
按键沿：`A_PRESS / B_PRESS / C_PRESS`
复合：`DOUBLE_TAP_FORWARD / DOUBLE_TAP_BACK / SHIFT_HOLD / SHIFT_FORWARD / SHIFT_BACK / SHIFT_DOWN`

> 不新增第 4 个动作键。跨层改 `InputEvent.as` + `input-event.ts` + `input-sampler.ts` + mask 打包 + 重建 bundle，收益只有「多一个终结键」，而 C 在兵器待机时本来就空闲。

### 3.2 推荐指令表（方向 + C，5 条）

| 技能 | 指令 | 写法 | 动作后的自然语义 |
| --- | --- | --- | --- |
| 迅斩 | `↘ + C` | `DOWN_FORWARD, C_PRESS` | 下前压刀 → 快斩 |
| 凶斩 | `↙ + C` | `DOWN_BACK, C_PRESS` | 下后拉刀 → 重斩 |
| 瞬步斩 | `↖ + C` | `UP_BACK, C_PRESS` | 后上撤步 → 连斩 |
| 拔刀术 | `↗ + C` | `UP_FORWARD, C_PRESS` | 前上抢身 → 拔刀 |
| 火舞旋风 | `← + C` | `BACK, C_PRESS` | 后撤旋身 → 旋风 |

四个斜向 + 一个正后，键位互不重叠，也不占用 `→`（前进+C 最容易误触，故不用）。

可选扩展：
| 六连 | `↑ + C` | `UP, C_PRESS`（注意 `UP>A` 已被月光斩占用，C 侧空闲） |
| 空间斩 | `→ + C` | `FORWARD, C_PRESS`（确认能接受误触风险再加） |

### 3.3 为什么用 C 而不是 A / B / 新键

| 键 | 待机时的既有行为 | 结论 |
| --- | --- | --- |
| `A` | 当帧就起普攻（`拳刀状态机:187`），cmdName 下一帧才到 ⇒ **必然先出一刀再被技能打断** | 手感脏，且技能全成「普攻取消」，不适合待机施法 |
| `B` | 当帧起跳（`:201`） | 同 A 的抢帧问题 |
| `C` | **拳刀状态机无任何分支**，兵器待机时按 C 什么都不发生 | 干净、零抢键、零 XFL 改动 ✅ |
| 新第 4 键 | 需改 4 处跨层 + 重建 bundle | 成本高，收益低 |

唯一需要接受的是：C 是枪械模式的换弹键，玩家可能有肌肉记忆；但**只在 `攻击模式=="兵器"` 且方向按住时生效**，且兵器模式本来就没有换弹。

### 3.4 为什么不做「↓↘→C」这类三段式

三层理由，缺一不可：

1. **DFA 每步只有 8 帧**。按住 ↓ 超过 8 帧 DFA 就回 ROOT，后面的 ↘ 从根开始匹配，指令直接丢。
2. **现有招式也全靠帧检查兜底**（`使用剑气释放` 里 `if(!当前搓招名 && 下行 && 动作A)`），说明「按住方向再按终结键」才是玩家真实输入形态。
3. 如果保留帧检查兜底，三段式就**没有约束力**——兜底只认最后的方向 + C，玩家做 `↘C` 一样能放。所以要么接受「方向+C」，要么彻底去掉兜底、接受 267ms 的严苛节奏。推荐前者。

### 3.5 前缀冲突校验（在 lightWeapon / heavyWeapon=cold_arms 两张表上逐条查过）

| 新指令 | 该方向在现有表中的用法 | 结论 |
| --- | --- | --- |
| `DOWN_FORWARD, C` | `DOWN_FORWARD` 只接 `A_PRESS`（剑气释放/双剑气/疾影剑气/飞沙走石） | 同前缀不同分支，**不冲突** |
| `DOWN_BACK, C` | 只接 `A_PRESS`（猎影十字/交叉斩/空坠强袭） | 不冲突 |
| `UP_BACK, C` | 只接 `A_PRESS`（十六夜月华/双龙连斩/迅捷连斩） | 不冲突 |
| `UP_FORWARD, C` | **`UP_FORWARD` 在全仓指令表中从未出现** | 完全空闲 |
| `BACK, C` | `BACK` 作首事件在 XML 表中从未出现（`SHIFT_BACK` 是另一个事件） | 完全空闲 |

- 现有指令最长 2 个事件，新指令也是 2 个 ⇒ **不存在「一个指令是另一个的前缀」**，DFA 的 prefix-free 约束天然满足。
- 与 `barehand` 模组无交集（该模组有 `DOWN>A` 回旋踢、`FORWARD>B` 燃烧指节，但模块不同、且我们不合并进 barehand）。

### 3.6 误触面评估

| 场景 | 是否触发 | 说明 |
| --- | --- | --- |
| 兵器待机，只按 C | 否 | 无方向，方向定义全不满足 |
| 兵器前进（→）时按 C | 否 | 本方案不含 `FORWARD>C` |
| 兵器后退（←）时按 C | **是（火舞旋风）** | 唯一「单方向」指令，若不想要可改成 `↓↙←` 组合或换 `↑C` |
| 空手/长枪/手枪模式按方向+C | 否 | `攻击模式 != "兵器"` 直接返回 0 |
| 普攻连招中按方向+C | 否 | 拳刀状态机不在跑（此时是兵器攻击容器），cmdName 6 帧后自然过期 |
| 技能/战技动画中 | 否 | 同上 |

### 5.3 C3 · `构建搓招模组` 合并（`通信_fs_帧计时器.as`）

```as2
_root.帧计时器.构建搓招模组 = function():Void {
    this.commandModules = {};

    var bareReg:CommandRegistry = new CommandRegistry(64);
    bareReg.loadConfig(CommandConfig.getBarehanded());
    bareReg.compile();
    this.commandModules["barehand"] = { registry: bareReg, dfa: bareReg.getDFA() };

    // 冷兵器主动技能：只并入 light / heavy 两个模组（barehand 不并）
    var 技能表:Object = CommandConfig.getXMLConfig("playerColdSkill");

    var lightReg:CommandRegistry = new CommandRegistry(64);
    lightReg.loadConfig(技能表
        ? CommandConfig.merge([CommandConfig.getLightWeapon(), 技能表])
        : CommandConfig.getLightWeapon());
    lightReg.compile();
    this.commandModules["lightWeapon"] = { registry: lightReg, dfa: lightReg.getDFA() };

    var heavyReg:CommandRegistry = new CommandRegistry(64);
    heavyReg.loadConfig(技能表
        ? CommandConfig.merge([CommandConfig.getHeavyWeapon(), 技能表])
        : CommandConfig.getHeavyWeapon());
    heavyReg.compile();
    this.commandModules["heavyWeapon"] = { registry: heavyReg, dfa: heavyReg.getDFA() };

    this.dfaBuilt = true;
    this.dfaSentToLauncher = false;
    this.发送DFA数据到Launcher();
    _root.服务器.发布服务器消息("[搓招] 模组构建完成 → Launcher 同步" + (this.dfaSentToLauncher ? "OK" : "等待连接"));
};
```

**注意**：`getHeavyWeapon()` 返回的是 `_xmlConfigs["heavyWeapon"]`，也就是 `cold_arms_weapon.xml`（见事实 12）。
所以**不要**把技能指令写进 `heavy_weapon.xml`——它已经被覆盖，永远不参与编译。

### 5.5 C5 · `QuickSkillInputService.releaseBySkillName`

```as2
/**
 * 按技能名释放快捷技能：找到装备槽后复用 releaseSlot，
 * 因此 MP 事务 / 权威冷却 / 按住锁存语义与按数字键完全一致。
 * 返回 null 或 {attempted, released, ...}；released 为 true 才表示真的放出去了。
 */
public static function releaseBySkillName(unit:Object, rawSkillName:String):Object {
    if (!unit) return null;
    var skillName:String = SkillReleaseGuard.normalizeSkillName(rawSkillName);
    if (skillName == null) return null;

    var slots:Array = SkillLoadoutService.findEquippedSlots(skillName);
    for (var i:Number = 0; i < slots.length; i++) {
        var slotIndex:Number = slots[i];
        var descriptor:Object = SkillLoadoutService.getSlotDescriptor(slotIndex);
        if (!descriptor || descriptor.stateHealth != "ok" || descriptor.writeBlocked === true) continue;
        descriptor.__domainDescriptor = true;
        if (!isEquippedSkill(descriptor)) continue;            // 已学习 + 数值合法
        var cooldownKey:String = ManualCooldownService.quickSkillKey(slotIndex);
        if (!ManualCooldownService.isReady(cooldownKey)) continue;   // 关键：releaseSlot 自己不查冷却

        getConsumedSlots(unit)[slotIndex] = true;              // 与数字键共用按住锁存
        return releaseSlot(unit, slotIndex, descriptor, 0);
    }
    return null;                                               // 未装备 / 全部在冷却
}
```

> 用「遍历该技能的所有槽、取第一个冷却就绪的」而不是「固定取第一个槽」：简单难度允许同一技能装多槽，这样不会因为槽 1 在冷却就整招失灵。

_root.技能函数.冷兵器主动技能搓招 = function():Number {
    var 自机:Object = _parent;
    if (!自机 || 自机.攻击模式 != "兵器") return 0;

    // ① DFA 命中（可能比按键晚 1 帧）：只要名字在表里就接

    return this.攻击模式 == "兵器";

## 6. 帧级时序（C 按下的那一帧发生什么）

| 帧 | 动作 | 关键状态 |
| --- | --- | --- |
| n-1 | 玩家按住 `↓` | V8 收到 `DOWN`，DFA 进 state₁（若 8 帧内没有下一步会超时） |
| n-0 | 玩家加按 `→`，采样得 `DOWN_FORWARD` | DFA 进 state₂，`hints` 出现 `迅斩:↘C:1` |
| n | 玩家按 `C`；同一帧 `帧计时器.frameUpdate` 采样 mask，`动作C=true`；`man.onEnterFrame` 跑拳刀状态机 | ② 帧检查命中 → `releaseBySkillName` → `释放技能` → `状态改变("技能")` → **man 被卸载** |
| n | 同帧剩余逻辑 | 派发函数已 `return`，A/B 分支不执行 |
| n+1 | Launcher 回 `K`：cmdName=`迅斩` | `搓招缓冲已消费` 已是 true ⇒ `当前搓招名` 保持空，不会二次触发 |
| n+k | 技能容器播完 | 回到 `兵器站立`，`__冷兵器技能C已消费` 在松 C 后复位 |

> 如果玩家是「先按住 ↘ 超过 8 帧再按 C」，DFA 已经超时回 ROOT，但② 帧检查仍然成立 ⇒ 技能照放。这就是兜底存在的意义。

## 8. 风险与回滚

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| `←C` 误触（后撤时按 C） | 中 | 若实测频繁，把火舞旋风改成 `↓↙←` 或 `↑C`；XML + 表各改一行 |
| 帧检查兜底与 DFA 各触发一次 | 低 | 兜底同帧先跑并置 `搓招缓冲已消费`，DFA 路径自然失效；若发现双放，检查是否漏置该标记 |
| `释放条件` 门槛影响既有玩法 | 中 | 这是刻意的：空手时按数字键也不再能放剑术技能。若你只想约束搓招、保留数字键旧行为，就不要注册 C7（见 §9-2） |
| 合并后模组命令数变多，hints 变吵 | 低 | 只在按住四个斜向/后时出现，最多 1 条；不满意可在 TS `buildHints` 过滤（要重建 bundle） |
| `heavy_weapon.xml` 被误当生效表 | 高 | 已在 §5.3 标注：重武器模组装的是 `cold_arms_weapon.xml` |
| 丢 BOM | 高 | 新 `.as` 用「复制现有文件再改名」的方式创建，不要用编辑器新建空文件 |
| 回滚 | — | 删除 C1/C6 两个新文件，`git checkout` C2-C5/C8/C9 六个文件即可；无存档改动、无资源改动 |

## 9. 需要你拍板的三件事

1. **指令表形态**：接受「方向 + C」（`↘C/↙C/↖C/↗C/←C`，推荐），还是坚持三段式（`↓↘C` 这种，需要接受 267ms 节奏或放弃帧检查兜底）？
2. **门槛作用面**：`攻击模式 != "兵器"` 时禁止释放——这个限制是**同时作用于数字键**（推荐，行为一致），还是**只作用于搓招**（数字键保留旧行为，会出现「空手按键能放、搓招不能放」）？
3. **本轮技能数量**：只做你点名的 5 个；还是把 `六连`、`空间斩` 一起做（`龙斩` 建议单独评估，它是武术&剑术混合且偏空中）？

确认后按 C1 → C9 顺序落地，每完成 C1~C3 先验一次「DFA 能回名字」，再做 AS2 侧，最后统一过 `-Target publish` 编译门。
