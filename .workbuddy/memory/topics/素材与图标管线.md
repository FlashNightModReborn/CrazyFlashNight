## 图标管线（SWF 是唯一真源）

双通道：Flash 内 `attachMovie("图标-" + itemData.icon)` 读 `flashswf/arts/素材库-物品技能图标.swf`；Web/Launcher 读 `launcher/web/icons/manifest.json` + `*.webp`，由 `tools/bake-icons-offline.py` + `tools/ffdec/ffdec-cli.exe` 离线扒出。`Icons.resolve()` 只查 manifest，无 AS2 动态采样回退。

加图标：① SVG → CS6 导入 XFL（勾"为 ActionScript 导出"，linkage `图标-XXX`）② publish 图标库 SWF ③ 重跑 `scan_linkage.py`（冷启 ~3.5 分钟，缓存热 24 秒；不做这步 bake 报 `unresolved=missing_asset`）④ `python tools/bake-icons-offline.py --name XXX,YYY`

- 环境：managed 3.13 没 Pillow，用系统 `C:/Users/Akatosh/AppData/Local/Programs/Python/Python310/python.exe`
- 耗时被 FFDec `-swf2xml` 吃掉（4.8MB → 254MB XML、191 秒，必然超默认 120s）；超时只让 sprite_graph 退化成空 → 静态首帧，无害。9 个图标 ≈ 2 分钟
- 跳过行为（无 `--force-overwrite-existing`）：一致 → `unchanged`；有差异 → `layout_protected`（保留旧图）；只有缺文件才 `created` → 增量加图标天然安全。`--name` 收裸名（不带 `图标-` 前缀），逗号分隔或重复多次都行；`--dry-run` 只跑不写
- ★ 这个"跳过"**不省时间**（2026-09-15 实测，用户会问）：跳过做在**最后写盘那一步**（`write_icon_if_needed` → `unchanged`/`layout_protected`），在此之前对**每个源 SWF 无条件**跑四趟 FFDec：`-export symbolClass` → `-export script` → `-swf2xml` → `-export sprite`。"图标已存在"这条信息在导出阶段完全没用上，已存在的图标一个字节都没少导出。全量 `--scope all` 实测（1661 目标 / 30 源 SWF，13 分钟走到一半）：symbolClass 30 SWF ≈ 28 s；script + swf2xml 30 SWF ≈ 480 s（≈16 s/SWF，累计吐 **1.25 GB** `raw-xml/*/swf.xml`，大头在这）；sprite 9/30 时已 52 MB、≈21 s/SWF ⇒ **全量一轮约 26~30 分钟**。只补图标就老实用 `--name`
- 新增图标前先查 `asset_source_map.xml` 有没有那条 `图标-XXX`：没有就 `--name` 必报 `unresolved=1 swfs=0`（**什么都没烤，但退出码 0，容易看漏**）。重扫走 `tools/linkage_scanner/scan_linkage.py`（约 1 分钟），扫完必须差分核对：正常 = **纯新增、消失 0、改指向 0**（`symbolName` 由空补成实际路径属补全，无害）
- 成功判据 `tmp/icon-bake-offline-report.json`：`created=1 / processed=1`、`unresolvedSummary` 空、`protectExistingLayout: true`；自查符号表用 `grep -l 'linkageExportForAS="true"' <元件>.xml` 或 `ffdec-cli.exe -export symbolClass <out> <swf>`（1.5 秒）
- ⚠ `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]` 有**两个触发点，含义完全相反**（2026-09-15 补）：脚本里 `remove_tree` 只在两处调用 —— **开头**清上次遗留、**结尾**（L4520，summary 打印之前）清本次中间产物。
  - 打在**开头**：脚本**只打这一行就退出，什么都没跑**（2026-09-14 实证）
  - 打在**结尾**：**产物已全部落盘，只有收尾清理 + summary 那行 print 丢了，退出码 1**。日志里只有这一行 JSON、看不到 `[icon-bake-offline] targets=...` 就是这种。判据：`tmp/icon-bake-offline-report.json` 的 mtime + `launcher/web/icons/manifest.json` 是否同步刷新

## 给 CS6 画 SVG 只能用保守子集

CS6 老导入器不支持 `<linearGradient>`+`fill="url(#id)"`、`<clipPath>`、`opacity`（Animate 支持，所以只有 CS6 丢色），也不支持 transform。只用字面 `#RRGGBB`，渐变拆 2~3 段实色，半透明预先混色，最外层描边最后画来盖毛边；一切"淡入淡出"用几何量（宽度/半径/长度收到 0）表达，别用深色冒充。描边重量约 2.3% 画布（64 画布 → 主体 1.5）；中央标签别太大，否则 32px 糊成黑块。参考 `tmp/gen_potion_icons.py` 脚本头。

- 交付给 CS6 的 SVG 放 `素材/svg-待导入/`（或对应 XFL 旁的 `svg-待导入/`）；导入前去掉 `<!DOCTYPE>`、`pt`→`px`、无意义的 `opacity="1.00"`
- 位图自动描出的 SVG（上千条 path、上千种颜色）当 24×24 图标会糊成一团，图标帧应另出简化版

**逐帧动效 SVG（Python 生成）**成套约束，参考 `tmp/天启大封印-特效/gen_shu_effects.py`（头注释）+ `_verify.py`，以及 `tmp/王之财宝-光圈/gen_babylon_halo.py`（后 3 条硬经验来自它；同目录 `_verify.py` / `_render_check.py` / `_make_preview.py` 可直接抄）：

- **环形别挖洞，改叠实心盘**（2026-09-14 王财光圈实测）：`<polygon>` 用「外圈正走 + 内圈倒走」在非零环绕语义下是对的，但在**起始角的径向接缝**处会出一整条楔形漏空 → 改成**由外向内叠实心盘**（内层盖外层，层间露出即成环带）：无接缝、点数减半、任何填充规则下结果一致。同类：扇环（高光弧）做成**两端收尖的梭形**（`w=0.5·(r_out-r_in)·sin(πu)^0.6`），别做带两条径向边的扇段
  - ⚠ **这套"叠盘"只适用于 SVG/光栅渲染器**。同一批图**写进 XFL 时不要照搬叠盘**——XFL 里同帧多个 `DOMShape` 的先后没有验证过的语义，要改写成 Flash 的**区域写法**（每条边界只画一次 + `fillStyle0`/`fillStyle1` 两侧配色），见 `手写XFL-格式与踩坑.md` §12
- **外缘别做「一圈小三角」毛边**：突出量与格距同量级时看着就是一排齿轮齿。改用几层更大更暗、竖直抻长、边缘带细碎谐波起伏（m=11/17）的大盘 → 柔和阶梯式外晕，图元数还从 60 掉到 3
- **摆动幅度必须钳在相邻圈宽的 45% 以内**（等比圈宽 `GROW=q` 时最坏 `0.45×(1/q+1)`，恒不串圈）；>0.5 必串圈自交。另：`abs(cos θ)` 是**水平**方向、`abs(sin θ)` 才是竖直（第一版把「竖直外泄」做成了左右外泄）
- **非零环绕**：同一 `<polygon>` 拼多根小图形会把圆盘填实 → 每根各自成多边形
- **循环无缝**：周期量走整数周期。分段接缝：爆发段相位用 `(i-(N-1))/LOOP_N`（负相位）使末帧与循环首帧逐点相同。**验收判据 = 帧 0 与帧 N 的 SVG 输出文本逐字节相同** —— 别比原始浮点：`2π*N/N` 与 `0` 必然差 1e-13，会把"无缝"误报成几百处不同。另把 24 帧 SVG 内联进 `preview.html` 预览比 `<img src>` 稳（不受 file:// 子资源策略影响，还能用 `mix-blend-mode: plus-lighter` 模拟相加混合）
- **防顿帧**：消散段用 `u=(i-8)/6` 而非 `(i-9)/5`，否则与上一帧参数完全相同
- **消散是"碎开飞散"不是"缩回"**；碎片基准半径用独立常量（如 `ORB_SHARD_R=1.42`），共用底图半径会跟着缩成环；碎片夹画布内（`lim = min(cy,H-cy,cx,W-cx)-40`）
- 画布加高须同步放大毛边频率、采样段数、光丝/浮尘数量，否则纹理变稀、边缘成节状直线
- 一次性段 + 循环段混排：SVG 只出两条序列，循环由用户代码侧控制；半透明出两套配色（不透明色 + CS6 手设不透明度 / 极暗色 + CS6「叠加」混合）
  - ⚠ **配色与混合模式是绑定的，出图时就要说清，别指望"到 CS6 再调"**（2026-09-14 王财光圈返工）：为「相加(add)」设计的调色板整体压暗、最暗近黑（`#0E0C07`），它的前提是"相加 ⇒ 近黑 ≈ 不加色 ≈ 视觉透明"；一旦脱离相加混合（GIF/PNG 预览、或忘了设混合模式），近黑**原样变黑块**。实色调色板最暗取暗橄榄褐（`#2F2B1B`）→ 读作"金子的阴影"。**要透明感只有两条路**：实色 + 实例不透明度（可烘进填充：`<SolidColor color="#66FFFF" alpha="0.701960784313725"/>`，本库 CS6 原生产物见 `特效与子弹/普通麻醉子弹.xml`），或暗色 + 必设的相加混合。**别把"配色选择"当成纯美术问题**——它和运行时的混合模式/不透明度是一个整体，先定后写。
  - ⚠⚠ **"亮度包络"的走向本身就是背景色的函数**（同轮二次返工）。光源向外衰减时，"越外越接近背景"这条假设的实现方向**随背景翻转**：黑底 = 外缘压暗（`ENV` 尾段 0.62→0.12，v 落到 0.09 橄榄黑），白底 = 外缘回升到淡黄（`ENV_WHITE` 尾段 0.53→0.98）+ 外辉三层从"逐层乘 k_v 压暗"改成"逐层往白里混"（`mix_white`）。**只换调色板不换包络 = 没修**：外缘照样是深色，到白底依旧是一圈脏边。落地形态 = 生成器里开一个 `pal="white"` 主题（`PAL_*` / `ENV_*` / `V_GAIN*` / 外辉策略按主题分支），内中段与黑底版**逐点等价**（各自乘 V_GAIN 后 v 相同 → 里圈观感不变），只改外侧尾段与背景化开方式。
  - ⚠⚠⚠ **"淡"要用几何（真空隙）表达，不要用颜色逼近背景色**（同轮三次返工，也是这三轮的总根因）。前两轮都在改调色板/亮度包络，本质是**把"透明度"硬编码成"某个特定背景色"** —— 于是每换一次底就穿帮一次：黑底向在白底上是黑黄边，白底向在白底上直接消失（最外几圈几乎是 `#FFFDF2`），中间还夹一条被涟漪压到 v≈0.29 的橄榄暗金（`#A98939`）。**正解：外圈改成"金/淡黄弧带 + 带间真空隙"**，只在形状上上色，"淡"由背景透出来给 —— 同一份几何在白/中灰/黑三底上都成立（对照图 `_bg_compare.png`）。XFL 里就是"某条边界的某一侧不写 `fillStyle`"（细节见 `topics/手写XFL-格式与踩坑.md` §12.3）；SVG 里用**零宽缝 keyhole polygon**（仍是纯 polygon，不破坏 CS6 导入约束）。判据应固定成两张图：**三背景对照** + **全帧最暗色**。附带一条：真空隙还能顺手替掉"外缘往背景里化开"的实心辉光盘 —— 那几层恰恰就是"和背景色重了"的元凶。
