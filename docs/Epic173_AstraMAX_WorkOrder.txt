## 2. 冻结的最小接口与行为合同

以下为接口契约/AS2 实现骨架，不是已经编译的补丁。保留现有公开 API 的兼容调用；新方法留在 GroundTargetMotion，不新建一组控制器/策略/请求对象类。

### 2.1 身份捕获

建议公开接口：

    captureTarget(action:MovieClip):MovieClip
    captureCandidates(action:MovieClip):Void
    isCandidateCurrent(action:MovieClip, index:Number):Boolean

captureTarget 每次入口先使旧追踪编号、world/actor身份、目标名称失效并清旧敌方目标引用；全部校验成功后才写新身份。失败不能遗留上一段凭据。它只在原有锁定/索敌/换目标帧调用，不执行新的索敌，不改目标选择顺序。校验 action._parent 是当前 world 内的现役单位、动作属于该单位、单位/目标活着、目标非自身、脚点及显示坐标为有限数、地图边界有效、脚点合法。使用 Dictionary.getStaticUID 在锁定时保存 world、actor、动作实例及目标的数值 UID，沿用 action.追踪编号 作为目标 UID。持续位移元件在放置时捕获动作编号，消费时校验该编号。诺艾尔回旋元件横跨多个锁定帧，元件可先于后段锁定脚本放置，放置时须取得动作自己的编号。该操作不提前给目标签发凭据。不得只存 MovieClip 引用。

执行时只比较已捕获的数值 UID、当前 world/actor/action 关系和当前目标；不要在消费阶段 getStaticUID 后给新同名目标补签。原生用例须在旧动作卸载、同路径新动作完成有效锁定后触发持旧编号的回调，核对新动作与单位的位置、方向和碰撞框均未改变；随后由新动作成功移动作阳性对照。失效只拒绝本次位移。不得把“捕获失败”写成 是否追踪=false，让原追踪分支意外落入自由冲刺分支；也不取消后续伤害、收招、MP/CD。

兽王候补专用：captureCandidates 在原完整索敌完成后保存 action 私有的原列表引用及 Number UID 数组。列表是普通 Array，身份比较不受 MovieClip 同路径重绑问题影响。重用该 action 的数组；不改公共记录/全局缓存。候补选择时要求原列表身份、索引 UID 和当前对象存活有效，然后沿原有顺序选择。每次索敌 O(n)，不进入逐帧热路径。

### 2.2 有最低速度的追击/退避

保留 lockRush(action)，保留原速度上限/下限/追踪持续帧；复用 #172 已验收数学式：

    dx = actorX - targetX
    dz = actorZ - targetZ
    s = max(speedMin, min(speedMax, abs(dx) / frames))
    span = max(abs(dx), abs(dz), s)
    vz = span > 0 ? s * (dz / span) : 0

参数与派生值须有限，frames>0、0<=speedMin<=speedMax。失败先清本动作的四向速度及锁定身份，不能留下上一段速度。保持原 X 最低速度，不把 X 夹到目标上。

扩展接口：

    advanceRush(action:MovieClip, xSign:Number, zSign:Number,
                stopAtLockedZ:Boolean):Boolean

旧单参数调用默认 (+1,+1,true)。允许的冻结组合：

- 普通追击：(+1,+1,true)。
- EXUSIAI 后撤射击/后空翻：(-1,+1,true)，X 后退、Z 向锁定行靠近。
- 不明士兵后空翻扔雷：(-1,-1,false)，X/Z 均逃离目标，绝不能应用向锁定 Z 的夹止。

sign 必须为 +1/-1。先按模式生成实际四向请求，再交 checkedFourWay；预检与提交使用同一组符号。负左速度仍取原“左”朝向分支，不得交换左右字段让单位转身。

这不是所有轨迹完全等价：横向主导且不触发保护的区间保留原斜率；近同列/陡斜率被明确修成有界速度。正常距离、攻击时序和非异常轨迹需对照验证。

### 2.3 无最低速度的动作：只消除 0/0，不改成 rush

可实现一个标量函数：

    chaseScale(dx:Number, cap:Number, frames:Number):Number

先检查有限性、cap>=0、frames>0；cap==0时明确返回0。其余有效输入下，abs(dx)>cap*frames时返回cap/abs(dx)，否则返回1/frames；检查派生比例有限。实现可用abs(dx)/frames与cap比较避免cap*frames溢出。必须覆盖dx=0、cap=0、dz非0时两轴速度为0。

诺艾尔回旋：

    rX = (7 + random(5)) / 10
    rZ = (7 + random(5)) / 10
    k  = chaseScale(dx, cap, frames)
    vx = dx * k * rX
    vz = dz * k * rX * rZ

随后原样执行原 vZ 上限、加速度与速度分支。保持 rX 然后 rZ 两次随机调用，不增加抽样，不把曲线替换为直线追击。EXUSIAI 两个无 min 动作使用同式但 rX=rZ=1。dx!=0 时数学等价；dx=0 取连续极限，正常浮点重排误差单列容差。

锁定仍捕获目标身份；执行使用 checkedFourWay，不追加锁定 Z 止步。诺艾尔每帧保留原 if(up){up-=a}else if(down){down-=a}，X 同型；不要改成四个速度同时减量。

### 2.4 两类提交入口

    checkedFourWay(action:MovieClip, up:Number, down:Number,
                   left:Number, right:Number):Boolean
    followAxes(action:MovieClip, keep:Number, minX:Number,
               maxX:Number, maxZ:Number):Boolean

checkedFourWay 仅接本次明确的敌人动作/原体冲刺。四个值必须有限，但允许合法负数。严格模拟原分支：

    dz = up != 0 ? -up : (down != 0 ? down : 0)
    dx = left != 0 ? -left : (right != 0 ? right : 0)

路径为 Z→X 的 L 形。朝向按 left!=0 优先、再 right!=0，按原方向改变规则保留锁定方向语义。不要用 down-up/right-left 代替分支预测。

followAxes 仅接第 4 节六个玩家模板技能，包括使用同模板的 NPC。unit.方向必须严格为“左”或“右”，否则false且不写位置、朝向、碰撞框，不默认非法方向为右。路径统一 X→Z，无需公共任意路径策略参数。完全保留旧参数：

    facing = unit.方向 == "左" ? -1 : +1
    d = facing * (targetX - actorX) - keep
    若显式提供有限 minX，d=max(d,minX)
    若有限 maxX>0，d=min(d,maxX)
    dx=facing*d
    dz=targetZ-actorZ
    若有限 maxZ>0，按原符号截幅 dz

缺省 minX 不是 0，必须保留负距离；缺省 maxX/maxZ 不增加任意业务距离帽。非法显式参数拒绝，不让 NaN 进入比较或步数循环。玩家模板 飞行浮空 时拒绝；不要仅按 控制目标 名称判断模板。

### 2.5 几何与失败原子性

在 GMT 内部用一个私有 tryCommitAxes 完成共同流程：

1. 验证锁定身份、数值、有限高度 actorZ-actorY、当前地图边界、源脚点和目标脚点，以及碰撞层/碰撞器已初始化。
2. 用局部标量计算最终 X/Z/Y 和适用的 起始Y，验证所有将要写入的数值。
3. 按调用者的真实 L 形次序检查两段，不用起终点直线替代。保留 openSegment 的约 2px 采样、单轴最多384步作为初始有界策略；先算预算再循环，超限整次拒绝，绝不粗采样后放行。
4. 每次请求直接读取当前实际 collisionLayer，不缓存跨帧路径，不在移动 helper 内调用 redraw。layer 身份和 CollisionLayerRenderer.revision 仅为辅助守卫；revision 不覆盖 drawObstacle(false) 等所有更新，不能作为唯一正确性依据。
5. 所有可能返回 false 的检查均发生在首个位置写入前。进入成功块后不再调用 Mover/hitTest/resolveCollision、不再返回“保持原位”的失败结果。
6. 在同一同步块提交_x、Z轴坐标、_y=oldY+dz；浮空且dz!=0、需要同步起始Y时，起始Y必须为有限Number，缺失/NaN/Infinity均在首个位置写入前拒绝，通过后同步+=dz。地面或纯X移动不要求该字段存在，也不创建它。
7. 保留原朝向分支副作用；最终位置和朝向确定后 AABB 更新一次。纵移时沿现役 Mover 语义用 DepthManager.instance.updateDepth(unit,newY)，不要顺便统一为 Z 排序。

成功块只适配这些已审查的模板：标准方向改变只改方向/scale，Depth/AABB 不发布战斗状态事件。不宣称兼容未知自定义 unit.移动，不建立通用事务回滚。

不写 temp_y、垂直速度、__air、浮空旗标、技能浮空旗标、状态、生命/伤害、MP/CD；高度积分和来源交接仍归现有系统。保留旧 counterBlink 的终点型穿越语义、旧 followSlash 的既有动作策略；这两项原则上只改资源桥接。

新入口准确提交合法 ±0.5px 纵移，不继承 Mover.move25D 的 dy|dz 亚像素死区；这是一项明确局部差异，必须测试合法浮空高度与起始Y。普通 Mover 不变。

起点已非法时只拒绝并留诊断，不引入盲 clamp、无条件回滚、全图搜安全点或传送出生点。冻结入口负责拒绝并保留现场。已有污染的单位交既有场景安全退出／恢复流程，新增跨动作安全点与通用脱困归场景／移动器维护者独立跟踪。#175 的出口要求证明拒绝未产生部分写入并能定位受影响入口。

2px 采样不是任意亚像素薄墙的连续几何证明。本闭包要测实际生产薄墙与采样相位；若真实薄墙漏过，该项不得标完成。只允许在本安全层按实测收紧步距，并按原合法最大单段距离重算有限步数上限、重测性能；不得静默缩短合法射程或改回终点放行。若该修正超出单层局部调整才能成立，报告具体薄墙反例与性能结果，再升级裁决；不自行建几何引擎。
