# 打击伤害数字生产路径视觉验收 Harness

该工具只提供确定性输入和合成战斗底图；伤害行、数字和属性标识全部直接调用
Launcher 生产实现：`HitNumberLayoutEngine`、`HitNumberRenderPlanner`、
`HitNumberScenePainter` 与 `HitNumberPainter`。截图和视频先绘制生产 tight surface，再按
`PixelBounds` 合成回底图；工具中没有第二套伤害数字布局或战斗账本绘制器，避免验收件与
游戏实际代码分叉，也避免全视口直绘掩盖真实裁剪。

当前覆盖四种正式行为：

- `balanced`（默认）：每次攻击投影为 `总伤害 × 段数 + 结构化属性`，居中锚定目标；
  主数字短暂显示最新段来源色后回落到该次攻击的伤害贡献主体色，属性标签保持来源色或
  固定语义色，并保留吸血/护盾精确值；每个目标最多显示三个最新攻击行，不再额外绘制
  目标箭头；
- `total`：每目标连续累计总伤和段数，恢复旧聚合器的跳数、当前段颜色闪现后回落到
  伤害贡献主体色、效果标签 boost/占比衰减、属性来源色、emoji、吸血和护盾精确值；
  静默 1.25 秒后自然淡出，MISS 不进入世界总伤但仍保留在精确账本；
- `classic`：在 C# 中忠实复现旧 Flash 的逐段随机散开、14 帧缩放/模糊轨迹；它是
  可选兼容行为，不恢复 Flash renderer 或 fallback；
- `detail`：沿用目标固定攻击栈，在世界行中显示每一发子弹的精确伤害；单元宽度和行高
  由生产字形保守边界决定，长数字/属性标签会减少列数而不会互相覆盖；非零全局上限下
  每个目标只保留最新六个攻击行，主要用于调试和低 hit 场景，显式 `0` 仍完整无限制。

除明确复刻旧行为的 `classic` 外，其余模式都不读取邻近目标来改变方向，不使用随机
散开、扇形轨道或动态避碰；`detail/total` 的短距归属标记也只指向本行权威目标，
默认 `balanced` 不绘制该标记。联弹的虚拟子弹共享 `BurstId`，并通过
`ExpectedBurstHitCount` 从首段起预留完整攻击行；新攻击首帧直接占据完整槽位，不挤压
相邻行。

`P01`—`P26` 覆盖单发冲击、20/60 段每秒、六目标、近邻交错归因、混合语义、四种行为、
屏幕边缘与屏外剔除、120 段无限制、五位逐发数字无碰撞，以及总伤当前色→主体色的
双时相样本；新增四模式共用同一 canonical 输入的 11 色板和语义全集，避免把不同夹具
误判成 renderer 色差。`manifest.json` 记录每张图的输入段数、剔除数、
世界行数、省略数、实际提交像素范围及 surface 外沿的非透明像素数；中心样本外沿非零即提示
tight bounds 可能裁剪，越过物理屏幕的不可见 overscan 另按边缘样本解释。

治疗验收 `P27`—`P34` 通过真实 `HitNumberRuntime` 解析与绘制，分别覆盖四种模式的纯治疗和伤害/治疗混流。
绿字使用每目标固定150 ms数值窗口和最多一个可见值。窗口与动画寿命分离：持续回复更新原可见项、不反复重播入场；每次输入及时更新目标锚点，入场缩放/抬升与伤害共用生产曲线，停止后按1.08秒寿命淡出。
伤害、治疗、吸血/护盾标签的显示统一钳制成有界整数。治疗先精确聚合，足1才显示；不足1的尾数在同一连续周期跨窗口结转，周期结束丢弃显示尾数，不写回真实HP或改变治疗结算。
绿字固定在目标右侧低位，不参与伤害行、Total、Ledger、命中段数或伤害随机序号。
关闭显示、换场景和连接代际切换会清除治疗状态；特殊复活只推进治疗显示 epoch，不改战报生命或击杀事实。

协议沿用 `hn` 的 11 字段。新版 Damage 在生产端分别掩码 flags/size/color，保证保留位不被字号溢出占用；接收端仍把非空 Burst 的旧高位记录按 Damage 解析。
HealHp 只接受 `packed=4194304`、空 Burst、空效果字段、零吸血/护盾、非空目标和 count=1 的严格形式。
`Hh1/Hh0` 是独立的治疗能力门，未协商时默认关闭；沿用旧 `汲:N` 的吸血不会重复发送绿字。

HP 写入统一通过 `HealApplier`，只对写后实际增加量显示。普通治疗保留 capped 与 exponential overflow 两条结算；护士枪和眷属的 capped 改为单调增量，旧扭转补满 1.5 倍上限，菲尼克斯最后一跳封顶，女仆保留向上取整上限。
拼命之王的无固定上限治疗作为命名例外。满血/阶段重置不伪装成治疗，法力恢复不显示 HP 绿字。
资源调用点归 `tools/heal-numbers/asset-contract.json`；运行 `python tools/heal-numbers/verify_assets.py --base HEAD` 检查清单、复活显示重置及本轮新增直接正向 HP 写入。
FLA 容器修改遵循[美术装配约束](../../agentsDoc/art-asset-assembly.md#5-独立素材库与确定性装配)。此检查不是任意等价写法的全程序证明。实际 AS2 写后 setter、协议与复活契约用 `scripts/run-heal-number-tests.ps1 -TimeoutSeconds 900` 在 CS6 中验证。

默认还生成三条生产路径视频：`V01` 验证持续高 hit 下默认模式的冲击节奏和目标锚定；
`V02` 验证近邻目标交叉攻击时固定、可追溯的来源归属。视频画面中的战斗背景和底部
状态条属于 harness，伤害数字本体属于生产实现。
`V03` 逐帧驱动真实Runtime，覆盖30Hz持续治疗、目标移动、整数窗口更新、停止后的淡出，并与伤害同时显示；另存数值/位置/缩放/透明度序列，静态截图不能代替此项。未安装ffmpeg时保留原始PNG帧，不将未编码MP4称为成功。

每次运行还会执行生产管线压力探针：先用 600 帧按 60 FPS、每帧 20 段模拟
1200 段/秒，贯穿真实 span parser、1.08 秒寿命 reducer、默认 24 行选择和 GDI+ 绘制；
随后继续灌入 900 帧，把精确对账环推过 32768 段容量并验证明确的覆盖计数，再在暂停态
按需物化 24 发攻击的第一页 JSON。清单记录世界热路径耗时、托管分配、Gen0 次数、
活动/后备段峰值、GDI/USER/进程句柄，以及满环日志物化耗时和分配。耗时只作本机比较；
世界历史越界、账本未保持固定容量或 GUI 资源净增长会使 harness 失败。

同轮另跑相同伤害输入加 1200 次治疗/秒的压力探针（20 个持续治疗目标），单独写入 `healing-performance.json`，可以直接比较解析/布局和绘制的额外耗时。
这是本机合成极端流量的微基准；不代替真实战斗帧率或游戏内性能验收。

运行：

```powershell
.\tools\hit-number-visual-harness\run.ps1
```

可用 `-OutputRoot <目录>` 指定一个不存在或为空的输出目录；用 `-NoVideo` 只生成 PNG。
默认输出到被 `.gitignore` 排除的 `tmp/hit-number-visual/review-<时间>`。视频需要
`ffmpeg`；也可向工具传 `--gif`，使用本机已有 Python/Pillow 编码GIF（包装入口 `run.ps1 -Gif`），不安装依赖。
成功的普通伤害视频清理其临时帧；治疗动效保留逐帧PNG和数值序列供边界复核。

精确对账日志位于暂停态 Web 设置页，使用 `hit_number_ledger` 从 Host 的固定容量场景环
读取；它不占用战斗键，也不由本 harness 复制一套 UI 绘制器。该界面另由 Settings Web
harness 与真实候选截图验收。

这些产物证明生产绘制和布局代码对确定性样本的表达，不是 Flash/WGC 真实游戏 E2E，
也不代表 `candidate_executed`、`e2e_verified`、`promoted` 或
`standard_entry_verified`。真实热键、分层窗口提交、Overlay 生命周期和游戏内手感仍需
在 Launcher 候选进程中单独验收。
