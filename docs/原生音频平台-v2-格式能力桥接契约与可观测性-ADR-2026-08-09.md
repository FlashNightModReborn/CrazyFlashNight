## 1. 问题、目标与非目标

### 1.1 问题

当前系统把“消息已发送”“文件已被目录发现”“native load 成功”“播放图在推进”和“玩家真实听到”折叠成近似同一成功面。已确认的问题包括：

- catalog 宣称 OGG，但 native 未注册 Vorbis decoder；
- 11 个 AAC/MP4 文件使用 `.wav` 扩展名，另有注册 BGM 缺文件；
- 默认 backend 可落入始终成功的 Null；
- BGM/SFX start、readiness 和错误没有端到端确认；
- 只有 BGM 内部 peak，无法证明 SFX 或 endpoint；
- 当前没有可进入发布门的音频 qualification corpus 和真实 endpoint runner。

### 1.2 目标

- 让播放器能力成为 native 可查询事实，而不是 C#/文档猜测。
- 让每个 BGM 请求可追踪到 accepted/deferred/started/failed/superseded。
- 让 SFX 预载、未知 ID、节流、丢弃和启动失败可计量。
- 让“全零内容”“增益静音”“Null backend”“设备丢失”“endpoint 静音”可区分。
- 支持当前玩家/资源需要的常见格式，并保留稳定扩展点。
- 让一次最终 promotion 覆盖能力、测试、notice、资产合同与正式入口。

### 1.3 非目标

- 不建设通用媒体播放器、视频 demux、网络流或 DRM。
- 不支持任意安装在 Windows 上的第三方 codec；只公开本 ADR allowlist。
- 不在本轮增加 HRTF、空间音频、卷积混响、MIDI、tracker、ReplayGain 或自动响度改写。
- 不用 limiter/normalizer 掩盖资源或混音错误；可增加 clip counter，改变声音需另行听感决策。
- 不把 AS2 改造成 native API 镜像；AS2 只消费产品级音频语义。
- 不批量重命名全部历史 SFX；文件名当前还是 linkageId 合同的一部分。

## 2. 当前地面真相

### 2.1 现役实现

- `miniaudio.h` 为 `0.11.25`，当前 `miniaudio_bridge.c` 通过 `MINIAUDIO_IMPLEMENTATION` 单 translation unit 编译。
- `ma_bridge_init()` 以 `ma_engine_config_init()` 生成的全默认 config 调用 `ma_engine_init()`，没有显式 context/device/resource manager/backend policy。
- BGM 用两个 stream slot crossfade；SFX 每资源四 voice、30 ms 同 ID throttle。
- `AudioTask` 是 fire-and-forget；SFX preload 在后台线程进行，ready 前请求被当作未知 ID 丢弃。
- `MusicCatalog` 硬编码 `.mp3/.wav/.ogg/.flac`。
- producer 只 materialize/编译 `miniaudio_bridge.c + miniaudio.h`，链接 `ole32.lib`。

### 2.2 资源事实

资源数量、magic、11 个 MP4/AAC 伪装文件、缺失 BGM 与 latent `apwersound.wav` 见调研备忘 §5。本文不复制全清单，避免两份真源漂移。

### 2.3 外部能力

- miniaudio 内建 WAV/MP3/FLAC，并通过 `ma_decoding_backend_vtable` 和 self-managed resource manager 扩展 decoder；官方 example 包含 libvorbis/libopus。
- 上游已建议从 `MINIAUDIO_IMPLEMENTATION` 迁移到 `miniaudio.c + miniaudio.h`，为 0.12 split 做准备。
- Windows Media Foundation 原生公开 AAC/ADTS、MP4/M4A 和 WMA 等格式；Source Reader 能输出 uncompressed audio、读取至 EOF、seek 和 drain。

这些事实只决定候选路线；exact 版本、源码、SDK 链接和行为仍须 A1/A3 fresh qualification。

## 3. 目标拓扑与权威

```text
AS2 product intent
  ├─ BGM requestId + latest-wins intent
  └─ SFX frame batch + audioReadyGeneration
          ↓
C# AudioTask / AudioCoordinator
  ├─ wire revision / ack / counters / lifecycle
  ├─ capability-driven MusicCatalog
  └─ structured diagnostics
          ↓ versioned C ABI
Native Audio Runtime
  ├─ real-backend-only context/device fallback policy
  ├─ resource manager + decoder registry
  ├─ BGM/SFX buses + meters
  ├─ device generation/recovery
  ├─ bounded runtime compatibility probe
  └─ offline EOF qualification probe
          ↓
WASAPI → DirectSound → WinMM → explicit failure
```

| 层 | 权威 | 不拥有 |
|---|---|---|
| AS2 | 场景/BGM/SFX 产品意图、优先级和当前业务语义 | codec、设备、native load 成功判定 |
| C# | 协议、请求关联、catalog、readiness、错误翻译和 UI/日志投影 | decoder 内部和物理设备实现 |
| native | decoder、PCM、播放图、设备、meter、底层错误 | 场景优先级和玩家业务状态 |
| qualification | 语料、故障注入、endpoint 证据 | 生产业务权威 |
| 人类 | H1 范围和 H2 听感/promotion 授权 | 伪造机器证据或跳级状态 |

## 4. 设备与生命周期合同

### 4.1 Production backend

production 必须同时：

1. production compile policy 固定 `MA_ENABLE_ONLY_SPECIFIC_BACKENDS + MA_ENABLE_WASAPI + MA_ENABLE_DSOUND + MA_ENABLE_WINMM + MA_NO_NULL`，或经构建断言证明完全等价；
2. fallback 在 **context 与 playback device 都成功** 后才停止，不能把“第一个 backend 的 context 初始化成功”误当成“该 backend 可播放”；
3. 可由仅编入上述三种 backend 的 `ma_device_init_ex()` 在 device-init 层枚举，或显式逐 backend 完成 context+device；两种实现都必须保留相同结果语义；
4. 导出实际选中的 backend、device name/id、sample rate、channels、format 和 generation；
5. 若从 WASAPI 降级到 DirectSound/WinMM，记录结构化 warning；
6. 三个真实 backend 均失败时进入 `audioStatus=failed_no_output`、不发布 audio ready、目录与播放控制显示不可用及原因。

Null 只允许 test-only/offline qualification build。该构建必须带不可混淆的 capability/identity，且 production policy 明确拒绝。

音频 fail-closed 不等于 Launcher 必须退出；本 ADR 推荐并在 H1 决策块中冻结“明确无音频降级、游戏可继续”。若人类要求音频失败即终止 Launcher，必须改写冻结块后再签 H1。无论进程是否继续，都不得把 Launcher `Ready`、socket 存活或目录可见外推为 audio ready。

### 4.2 Device change

- 默认设备或路由变化推进 `deviceGeneration`。
- 恢复期间暂停接收新 native 播放，C# 进入 `recovering`。
- BGM 保存 current intent、loop、gain 和可用 cursor，在新设备成功后有界恢复。
- SFX 不回放 recovery 期间的历史事件；只统计 drop，ready 后接收新事件。
- 重试必须有界、可中断、可观测；耗尽后进入已定义的 `failed_no_output`，不无限后台循环。
- exact 次数/退避在 A2 由故障注入锁定，不在没有数据时随意拍值。

### 4.3 Thread ownership

- 所有会改变 engine、sound、resource manager、device 或 decoder 状态的 native API 只由一个 owner queue/thread 串行执行；socket、UI polling、preload worker 和 recovery job 不得直接并发 mutation。
- meter、cursor、capability 和 device state 通过不可变/原子 snapshot 暴露；snapshot 读取不得与 sound/device uninit 直接竞态。
- preload、probe、MF 与 recovery job 必须可取消、可等待；job 不能在 generation 失效或 shutdown 后回写 handle。
- A2 故障注入必须包含“首选 backend context 成功但 device 失败”，并证明会尝试下一个真实 backend，而不是静默失败或落入 Null。

### 4.4 Shutdown

停止 admission → 等待/取消 decoder jobs → 停声源与 device → uninit engine/resource manager/context → 平衡 MF/COM 生命周期。重复 shutdown 必须幂等；不得让异步 preload 在释放后回写 handle。

## 5. 格式与 decoder 合同

### 5.1 H1 推荐矩阵

| Container / codec | Backend | H1 推荐 | 公开扩展名 |
|---|---|---|---|
| RIFF/WAVE PCM/float | miniaudio built-in | include | `.wav` |
| MPEG audio Layer III | miniaudio built-in | include | `.mp3` |
| FLAC | miniaudio built-in | include | `.flac` |
| Ogg Vorbis | official miniaudio libvorbis adapter + pinned libogg/libvorbis/libvorbisfile | include | `.ogg`, content=Vorbis |
| AAC-LC/HE-AAC in MPEG-4 | Media Foundation source/decoder exposed as miniaudio-compatible data source/backend | include | `.m4a`, `.mp4` |
| AAC in ADTS | Media Foundation | include | `.aac`, `.adts` |
| Ogg Opus | official miniaudio libopus adapter + pinned libopus/libopusfile | recommended option | `.opus`; `.ogg` only after content probe |
| WMA/ASF | Media Foundation | defer public promise | none until qualified |
| other | none | reject | none |

扩展名只是发现 hint；container/codec 才决定 decoder。`.ogg` 不能等同于 Vorbis，必须区分 Ogg Vorbis 和 Ogg Opus。

Vorbis 路线在 H1 前已完成显式取舍：vendored miniaudio `0.11.25` 确有可接入外部 `stb_vorbis.c` 的 optional wrapper，cursor 会正常维护；评审所称“push mode cursor 恒为 0”不成立。真正限制是 resource-manager/VFS streaming 会走 push mode，其 length 成功返回 `0`，后向 seek 需要重建 decoder 并向前暴力解码，而且 codec 本体当前未 vendored。它适合极简 decode 场景，但不满足本轮 BGM 的完整 duration/seek/EOF 资格合同。因此 R2 明确选择官方 miniaudio libvorbis adapter + pinned libogg/libvorbis/libvorbisfile；`stb_vorbis` 作为已评估未选方案，不再留给 A3 自行决定。

### 5.2 Media Foundation 边界

- 只接受 allowlist 中明确的 container/codec；第三方系统 codec 偶然能解码不自动扩大 capability。
- 必须支持 wide path、duration、seek、EOF/drain、format change 和 deterministic cleanup。
- COM/MF 初始化、worker thread、取消和 shutdown 必须有专项故障注入。
- 长 BGM 不允许以“全文件预解码进内存/临时 WAV”作为默认生产实现。
- A3 可在 `ma_decoding_backend_vtable` 与 `ma_data_source` adapter 中做 bounded spike；对外 ABI、capability 和结果语义不得随内部方案分叉。

### 5.3 依赖政策

- 优先采用 miniaudio 官方 adapter 与 codec 官方源码，不复制来源不明的单头文件 fork。
- exact tag/commit、SHA-256、build flags、license 与上游 URL 进入 tracked lock/notice。
- Vorbis 和 Opus 均为 BSD-family，但仍须分发 notice；不能以“宽松许可证”跳过审计。
- 所有 bundled decoder 静态链接进 `miniaudio.dll`，不增加 loose codec sidecar。

## 6. Native ABI 与 capability

### 6.1 ABI 原则

- 新 ABI 有独立 major/minor；breaking change 增 major，不静默复用现役签名。
- 所有 struct 以 `structSize + abiMajor + abiMinor` 开头。
- caller 分配输出结构和 UTF-8/UTF-16 buffer；native 不把需要跨边界释放的裸指针交给 C#。
- bool、enum、整数宽度固定；不把 C 编译器布局、`ma_result` enum size 或 miniaudio struct 直接暴露给 P/Invoke。
- C# 音频子系统先校验 ABI/capability，再发布 audio catalog/ready；不匹配只令音频 fail-closed，并按 `noOutputPolicy` 进入明确降级，不伪装成 ready。
- path 使用 wide/caller-owned buffer，完成规范化与允许根目录 containment 校验；超长路径显式失败，禁止固定 1024 字符截断。
- gain、fade、seek、loop 等数值先校验 finite 与冻结范围；负 fade、NaN、Inf 或溢出不得进入 native。

### 6.2 Capability 最小集合

```text
abiVersion
bridgeBuildId
miniaudioVersion
decoderBackends[]
containers[] / codecs[] / extensions[]
compiledBackendMask
selectedBackend / selectedDevice
supportsProbe / supportsSeek / supportsLoop / supportsDeviceRecovery
supportsBgmMeter / supportsSfxMeter
testOnlyNullEnabled
```

capability 分成 build capability 与 runtime device state；“编译支持 AAC”不能冒充“当前设备已启动”。

runtime snapshot 另含 `audioStatus=initializing|ready|recovering|failed_no_output|shutdown`、`audioSessionId`、`audioReadyGeneration`、`deviceGeneration` 和最近一次结构化失败；build capability 不得缓存覆盖这些动态状态。

### 6.3 结构化结果

每个可能失败的操作至少保留：

```text
requestId | operation | stage | category | nativeCode | hresult |
decoderBackend | audioSessionId | audioReadyGeneration | deviceGeneration |
retryable | messageKey
```

稳定 category：

```text
ok | missing | unsupported_container | unsupported_codec | malformed |
truncated | io_error | abi_mismatch | not_ready | stale_generation | unknown_id |
throttled | start_failed | seek_failed | device_unavailable |
device_lost | superseded | internal_error
```

不得再把所有 load failure 压成 `-2`，也不得丢弃原始 `ma_result`/HRESULT。

## 7. AS2/C# 桥接合同

### 7.1 Generation 域与状态机

禁止使用裸 `generation`。四个域不可互换：

- `connectionGeneration` 是现役 XMLSocket transport 世代，只防旧连接回调污染，不进入音频 wire 的 ready 判定。
- `audioSessionId` 是 process-scoped UUID；进程启动或 AudioCoordinator/native 完整所有权重建时生成且永不复用。
- `deviceGeneration` 是 native 真实设备生命周期世代，`uint64` 以十进制字符串过 wire；初值 `0`，每次真实设备初始化/恢复 attempt sequence 开始前推进。
- `audioReadyGeneration` 是 C# admission snapshot 世代，`uint64` 以十进制字符串过 wire；初值 `0`，每次初始化、恢复、capability 或 preload snapshot 重建开始前推进，重建结束后以同一世代发布 `audio_ready` 或 `audio_unavailable`。只有 ABI/capability、真实设备和完整 catalog 属于同一一致快照时才 ready。

请求的 `audioSessionId` 或 `audioReadyGeneration` 与当前值不等时返回 `stale_generation`、附 current tuple、零副作用。SFX 只计 `staleGenerationDrops`，不回放；BGM 只有携当前世代时才可 `accepted_deferred`。异步 job 必须捕获 session/ready 及相关 device 世代，完成时再次比对，stale completion 不得发布 handle/snapshot。计数器溢出时建立新 session 并重置；若 wire 无法可靠发布 reset，则音频 fail-closed。响应和诊断携完整音频 tuple，不能用 socket connection 世代代替。

### 7.2 BGM

- 每个 play/stop/seek/loop 请求携 `wireRevision=2`、`requestId`、`audioSessionId` 和当前 `audioReadyGeneration`。
- 结果至少区分 `accepted_deferred`、`started`、`stopped`、`superseded`、`failed`。
- bootstrap gate 只保留最新 BGM intent；被替代请求返回 `superseded`。
- `started` 必须在 decoder/source 初始化与 `ma_sound_start()` 成功后产生，不在 socket send 时产生。
- AS2 业务优先级仍由 `SoundEffectManager` 持有，C# 不重新实现 stage/jukebox/scene 决策。

### 7.3 SFX

- native/C# 完成 preload 后发布 `audio_ready {audioSessionId, audioReadyGeneration, deviceGeneration, loaded, failed, overrides, capabilityDigest}`。
- ABI、decoder registry 或真实 device 失败时改发 `audio_unavailable {audioSessionId, audioReadyGeneration, deviceGeneration, category, messageKey}`；不得同时发布 `audio_ready`。
- ready 前和 recovery 中的 SFX 不排队重放；分别计入 `preReadyDrops` / `recoveryDrops`。
- 每帧 fast-lane 保持批量低开销，不对每一枪做请求/响应往返。
- 汇总暴露 `unknownIdCount`、`throttledCount`、`startFailureCount`、`playedCount`，对首个/采样错误写结构化日志。
- `ma_sound_seek_to_pcm_frame()` 与 `ma_sound_start()` 均检查返回值；只有成功才计 `playedCount`。

### 7.4 Wire migration

- 新 wire 使用显式 revision；schema、AS2、C#、fixture 和文档同轮升级。
- implementation candidate 可短暂接受旧 wire 做差分诊断，但最终 release Gate 必须删除永久 v1 fallback 或证明它仅属于明确的 bounded migration window。
- 触及 `AudioBridge.as` 时先复核实际 source/include 归属；默认优先 `asLoader`，不能未经证据选择 `main`。
- AS2 编译结论必须有 fresh trace/Output；`publish_done.marker` 不单独算成功。

## 8. Catalog 与资产合同

### 8.1 Discovery 与 runtime compatibility probe

`MusicCatalog` 不再拥有硬编码“支持格式”真值。新流程：

```text
filesystem candidate
  → header/container sniff
  → native capability match
  → bounded runtime compatibility probe
  → available | probing | unavailable(reason)
  → catalog projection
```

手工注册但 missing/unsupported 的曲目保留可诊断记录，UI 显示禁用和 reason，不表现为可点击成功项。

玩家热投放文件在 size/mtime 连续稳定后才 probe；复制中的半文件保持 `probing`/`unstable_input`，不得被永久缓存为 malformed。

R2 runtime probe 只回答“当前 capability 是否可初始化并在上限内产出解码帧”，不签完整内容质量：两次 `size+mtime` 观测间隔 1000 ms；文件上限 512 MiB；单次最多 2000 ms、8 MiB 输入、96000 decoded frames；可取消。它不查询完整 duration、不要求 EOF。超时为 `inconclusive_timeout` 而不是 unsupported；有界窗口全零为 `compatible_signal_unknown`，不能写 `ok_silent`。缓存键含 normalized path、size、mtime、首 64 KiB SHA-256、capability digest 和 probe contract revision。

### 8.2 Extension mismatch

- shipped BGM 出现 extension/container mismatch 时，qualification 默认失败；A5 经 consumer/分发审计后决定 canonical rename 或显式 legacy exception。
- 玩家热投放文件可按内容解码，但必须标记 `extension_mismatch`；不得自动改写用户文件。
- 539 个历史 `.wav`/MP3 多数属于 SFX/linkageId，禁止批量改名；先用 content-based decoder 和 manifest 证明兼容。
- 11 个 MP4/AAC 伪装 BGM、缺失 Zenitsu URL 和 latent `apwersound.wav` 分别处理，不能用一个占位静音文件掩盖三种问题。

### 8.3 Offline qualification 与 silent content

只有 offline qualification probe 必须 stream decode 到 EOF，并输出 full SHA-256、frames、duration、peak、RMS、leading/trailing silence 和 non-finite count；单文件上限 120 秒，超时是 qualification failure，不冒充 unsupported。`ok_silent` 是合法检测结果但默认不进入可播放目录；若设计上确需静音资源，必须在 asset manifest 显式 allow。该 probe 不得在 catalog/UI hot path 执行。

## 9. 可观测性与“有声”词典

### 9.1 Runtime diagnostics

至少提供：

- BGM/SFX pre-master peak/RMS 与 clip counter；
- source/group/master gain；
- cursor/length/playing/start result；
- selected decoder/container/codec；
- backend/device/state/generation/underrun；
- preload/recovery/drop/error counters。

生产 runtime 不常驻抓取系统 loopback；endpoint capture 仅在显式 qualification/diagnostic 模式启用。

### 9.2 结论词典

| 词 | 最低证据 | 不能推出 |
|---|---|---|
| `referenced` | 配置/AS2 引用存在 | 文件存在 |
| `identified` | container/codec 识别 | 可完整解码 |
| `decoded` | EOF、frame/duration 合法 | PCM 非零 |
| `content_nonzero` | peak/RMS 超过冻结阈值 | 播放图已启动 |
| `graph_signal` | start 成功、cursor 与 bus meter | 真实设备或 endpoint 有声 |
| `device_active` | real backend/device started | 系统 mixer/硬件可听 |
| `endpoint_nonzero` | loopback/端点捕获非零 | 听感质量可接受 |
| `human_audible` | 人工听见 | 无爆音、延迟或平衡问题 |
| `human_accepted` | 完成人工矩阵并签 H2 | promotion 或正式入口验证已完成 |

master/BGM/SFX gain 为 0 时是 `muted_by_gain`，不是 decoder failure。全零 packet 也不能单独代表 stop。

### 10.1 Build closure

实施后必须同步：

- `miniaudio.c + miniaudio.h` 和 decoder source 的 canonical LF materialization；

### 10.2 State machine

| 状态 | Audio v2 最低证据 |
|---|---|
| `compiled` | 锁定工具链成功；新增 native/C#/AS2 tests 与受影响现役门通过 |
| `candidate_built` | immutable candidate、manifest、identity、closure 自洽；仍 `NOT_DEPLOYED` |

## 13. 人类验收合同

### 13.1 H1_IMPLEMENTATION_ACCEPTANCE

H1 不绑定整份 ADR raw hash：§15 台账与证据会持续更新，绑定整份文件会自我撤销。H1 的唯一规范目标是 canonical [`h1-decision-manifest.v2.json`](contracts/audio-v2/h1-decision-manifest.v2.json)，当前 scope revision 为 `AUDIO-V2-H1-SWEET-SPOT-R2`，当前 SHA-256 为 `518D1B5EA83960300B79D5C6DFB3CCDDAD3FFF1094C5950537E5C4FA9918469E`。

manifest 固定为 UTF-8 无 BOM、LF、对象键递归排序、2-space indent、末尾一个 LF；SHA-256 覆盖整个文件字节。它完整承载 backend/no-output、decoder 具体实现、ABI、wire/generation、双 probe、线程/恢复、资源、observability、资格、H1/H2/release 与非目标。本文只解释；任何规范语义改变都必须升 revision、生成新 proposal 并重签。

```text
P = commit(ADR + manifest + schemas + validator/tests + research evidence; temporary reviews absent)
  → human binds P commit/tree + manifest SHA and accepts H1
  → H = descendant evidence-only commit(H1 receipt + atomic recovery/status updates)
  → A1 may begin
```

P 必须是单 parent A0-only commit；相对 parent 的 diff 必须等于 validator 冻结的 A0 exact allowlist（`.gitattributes`、`AGENTS.md`、两份音频文档、本轮列明的 contracts、validator/test 与 research evidence），不能靠整个目录前缀夹带额外脚本，且 P tree 中不存在临时审查。P 必须是 HEAD/H 的 ancestor；`git ls-tree P <path>` 必须能恢复 manifest、全部 schemas、ADR、validator 和 test 的 exact blob。未提交工作树、unreachable blob 或 `commit=null` 一律不能被接受。P 形成后运行：

```powershell

```

该命令生成唯一可接受的精确文本，形状如下；所有占位符必须由命令输出替换，人类不能只回复“看过/推进”：

1. 规范化 CRLF 与最多一个末尾换行后，人类原文必须与 `--print-h1` formatter 输出全文完全相等；禁止额外、重复、冲突字段或把拒绝文本后附模板。Agent 不得代签。
2. validator 从 P 读取并验证 exact bytes、canonical encoding、完整决策、schema surfaces、A0-only diff、Git provenance 与 P ancestry；`.gitattributes` 强制 audio-v2 contract/evidence JSON 与 validator/test JS 在所有 host checkout 为 LF，避免 Windows `core.autocrlf` 改写 raw digest；同时要求当前 attributes、manifest、全部 schemas、validator/test bytes 与 P 完全相等，不能用 HEAD 的弱化工具验证旧绑定。
3. H 必须是 P 的 direct single-parent child，且 diff 恰好只有 ADR、备忘、`h1-implementation-acceptance.json`。receipt 与同一 H commit 原子更新顶层状态、§0.2、§0.4 状态、§0.6、§13.3、§15.3、§16.3 及备忘恢复入口。
4. H 的稳定恢复面必须把唯一顶层状态行精确改为 `ACCEPTED / IMPLEMENTATION_AUTHORIZED_A1_A6 / PROMOTION_BLOCKED / NOT_DEPLOYED`，唯一机器标记行精确改为 `H1_STATE=accepted；H2_STATE=not_applicable_before_A6`，并出现 H1 `accepted`、A0 `completed_H1`、A1 `authorized_pending` 与“当前 H1 已有效”；备忘的两条唯一顶层行同步改为 `READ_ONLY_RESEARCH_COMPLETE / IMPLEMENTATION_AUTHORIZED_A1_A6 / NOT_DEPLOYED` 和 `H1_STATE=accepted`。validator 解析这两条唯一权威行并拒绝重复/互斥状态，禁止说明模板中的同名字样冒充当前状态。
5. 施工中的 ADR 台账/证据追加不失效；frozen manifest/schema/validator/test 任一变化必须升 revision、新 P、新 H1。manifest 任一语义叶变化会由 digest/mutation tests 使旧 H1 失效。
6. 完成 H commit 与 `node tools/audio-v2/validate-contract.js --proposal-commit <P>` 复核后才可开始 A1。

H1 只解锁 A1–A6，不解锁 source tag、正式 builder/signing、request 或 A7 promotion。当前用户“解决审查并推进”发生在 R2/P 尚不存在前，足以授权完成 A0 与形成 P，但不能替代绑定未来 exact P 的 H1。

### 13.2 H2_PROMOTION_ACCEPTANCE

H2 只在 A6 已形成以下不可变链后生效：

```text
S = frozen release source commit/tree
  → exact candidate from S reaches e2e_verified
  → E1 = evidence-only descendant containing canonical A6 evidence manifest
  → human binds S + candidate identity/closure + E1 evidence and accepts H2
  → E2 = evidence-only descendant containing H2 receipt/status
  → runtime source tag/request still points exactly to S
  → E3 = evidence-only h2-request-link after request creation
```

E1 必须是 S 的 direct single-parent evidence-only child；diff 只允许本文与 `docs/evidence/audio-v2/**`。本文唯一顶层状态行必须精确为 `ACCEPTED / E2E_VERIFIED / HUMAN_PROMOTION_ACCEPTANCE_REQUIRED / NOT_DEPLOYED`，唯一机器标记行精确为 `H1_STATE=accepted；H2_STATE=pending_exact_human_acceptance；E1_STATE=evidence_ready`，台账另写 `E1_EVIDENCE_READY`；任何同文并存的 accepted/promotion-authorized 顶层状态都 fail-closed。其 A6 evidence manifest 严格符合 [`a6-evidence-manifest.schema.v1.json`](contracts/audio-v2/a6-evidence-manifest.schema.v1.json)，至少绑定：

- S commit/tree、candidate manifest/Core/miniaudio bytes+SHA、build identity 与 payload closure；首次生成 H2 文本时必须另传 absolute canonical live candidate root。validator 按现役 v2 规则枚举根 EXE 与 `runtime/` 完整 payload，拒绝 link/reparse、缺项和多项，逐 file row 重算 bytes/SHA 与 payload closure，并从 S 的 `config/build/runtime-inputs.v2.json` 重新计算 artifact-source/producer-recipe/toolchain-lock 三个 domain hash 与 build identity，不能只核 Core/miniaudio 或相信 manifest 自报 hash；
- 同一个 E1 还必须 tracked 保存 candidate-verification attestation 与原始 runtime manifest snapshot；attestation 绑定 seal-time observed root/time、完整 payload file count、source-domain config blob/SHA、candidate fields、snapshot blob/bytes/SHA 及 S 中 frozen validator blob。live root 只是一轮 sealing 前置，不是永久 locator；E2、compact 或跨机审计从 E1 attestation/snapshot、S 与候选哈希恢复，不能因旧临时目录清理而使已签 evidence 不可验证；正式 builder 后续仍必须复现同一 identity/closure；
- 真实 backend、device-id digest/name、sample rate/channels/format 与 `audioDeviceQualified=true`；
- 九个固定 reportId（资产 EOF、native ABI/decoder/lifecycle、真实 backend 故障注入、C# bridge/catalog、AS2 wire/publish、Launcher regression、BGM endpoint、SFX endpoint、device recovery endpoint）各一个符合 [`automated-report-envelope.schema.v1.json`](contracts/audio-v2/automated-report-envelope.schema.v1.json) 的 canonical tracked JSON blob；R2 manifest 对每个 report 冻结 required case matrix、report-specific source-input role matrix 和每个 case 的 required check IDs；普通 case 只接受 typed measurement，不接受自由 `observed`/`passed`；
- envelope 绑定 S、identity/closure、all-pass summary、case-results closure、S 内实际可恢复的 producer path/blob/SHA，以及 E1 tracked configuration JSON 和 input-manifest JSON。input manifest 必须排序列出三项 candidate artifact 和该 report 的全部不同 S input roles；validator 逐项恢复/recompute blob/bytes/SHA、role coverage 和整个 input closure，不能只写一个任意 64-hex，九组 configuration/input path 不得复用；
- 44 个 case 每项必须指向不同 path/blob/SHA 的 tracked structured JSON：普通 case 符合 [`automated-case-evidence.schema.v1.json`](contracts/audio-v2/automated-case-evidence.schema.v1.json)，回绑 producer/config/input closure/S/candidate，并对冻结 check IDs 输出有类型、可判定的 measurement；`shipped_corpus_all_files` 使用更严格的 [`asset-eof-results.schema.v1.json`](contracts/audio-v2/asset-eof-results.schema.v1.json)，validator 从 S 的 Git tree 重新枚举 `sounds/` + `music/` 下 `.flac/.m4a/.mp3/.mp4/.ogg/.opus/.wav/.waz` 完整集合，逐文件核对 path/blob/bytes/SHA 与 magic-sniff；PCM s16le 的 frames、peak 与 nonzero ratio 由 validator 直接从 S bytes 重算，压缩格式的 decode-to-EOF/frames/signal 由冻结 runner 在 seal-time 重跑；静音或非音频只能引用 S 固定路径、符合 [`asset-qualification-waivers.schema.v1.json`](contracts/audio-v2/asset-qualification-waivers.schema.v1.json) 的 exact path/exceptionId/owner/reason/signalClass，任意字符串例外无效；
- 每份报告另绑定符合 [`producer-verification.schema.v1.json`](contracts/audio-v2/producer-verification.schema.v1.json) 的不同 tracked verification blob。首次 `--print-h2` 时 validator 从 S 核对 `tools/audio-v2/qualification-runner.js` 与 [`qualification-runner-dependencies.schema.v1.json`](contracts/audio-v2/qualification-runner-dependencies.schema.v1.json) closure 的 exact bytes，把 S dependencies、E1 configuration/input/case/capture bytes materialize 到隔离目录，再以 live candidate 重放全部九份报告；runner canonical stdout 必须逐字节等于 E1 verification blob，单份上限 30 分钟。该机制能防止工作树/输入替换，却**不能机械判定恶意、空实现或只回显摘要的 runner 语义**；S runner 及其依赖是显式 H2 信任根，人类必须在 H2 前审查源码，并在 exact runner SHA 中接受。E2/compact 复验仍使用 E1 seal，无需旧 candidate 临时目录；
- endpoint capture 必须恰有四个 distinct tracked WAV，分别且只绑定 `bgm_playback`、`sfx_playback`、`bgm_sfx_mix`、`device_recovery` 一个 case，每个 case 恰出现一次，四份 path/blob/SHA 也必须彼此不同；每个 WAV 是 E1 内至少 1 秒的 `audio/wav-pcm-s16le`，单文件 ≤1 MiB、合计 ≤4 MiB，并绑定符合 [`endpoint-capture-configuration.schema.v1.json`](contracts/audio-v2/endpoint-capture-configuration.schema.v1.json) 的不同 E1 config 与 S 中固定 `tools/audio-v2/capture-endpoint.ps1` blob/SHA。config 精确回绑 candidate identity/closure、真实 device/backend、capture bytes/SHA、case、格式/rate/channels/duration、runId/time；validator 从 data chunk 重算并要求 peak absolute PCM16 ≥64、non-zero sample ratio ≥0.001，不能复制一份录音冒充四类 case，也不能用全零或单点噪声占位。采集工具同样是显式 H2 信任根：机器验证来源与闭包，人类必须审查工具语义并试听绑定录音；
- endpoint closure 是按 `captureId` 排序的 canonical JSON 数组 SHA-256，数组逐项包含 capture artifact、configuration artifact、tool artifact、case 与全部 media metadata，validator 必须重算；44 项 case evidence 对 endpoint cases 另有固定 `captureIds` 映射，不能用自由文字宣称已关联；
- 符合 [`human-listening-matrix.schema.v1.json`](contracts/audio-v2/human-listening-matrix.schema.v1.json) 的十项不重复、逐 case `passed` 的 canonical tracked JSON及完整 SHA；每项使用冻结的结构化 `captureIds` 映射，不接受自由 `evidence` 字符串替代录音绑定。

H2 Gate 不接受外部 locator：所有结构化报告、十项听感矩阵及上述四类短 endpoint capture 都必须由 E1 Git bytes 永久恢复。更长/高码率录音可作为非 Gate 诊断留在外部，但不能代替这些 bounded captures。孤立 `reportSha256`、总括 `humanListeningResult=accepted` 或不可定位口头听感均无效。

E1 后首次运行 `node tools/audio-v2/validate-contract.js --proposal-commit <P> --evidence-commit <E1> --evidence-manifest <path> --candidate-root <exact-live-root> --print-h2`；没有 fresh live full-payload rehash 与九份隔离 runner replay 就不输出 H2 文本。validator 同时从 S 读取 frozen P contract bytes、runner/dependencies、capture tool、waiver registry 与 report-specific inputs，从 E1 读取 candidate attestation/snapshot、九份 report、十八份 configuration/input provenance、44 份 structured case evidence、九份 producer-verification、四份 capture config/WAV 与 listening matrix，复核 Git blob/bytes/SHA、role/case/check/capture matrix、完整 shipped corpus、可直接解析 PCM 的 frames/signal、runner canonical stdout exact match、四 case 一一覆盖、closure、H→S→E1 ancestry/evidence-only diff。人类在接受前必须 source-review S runner/dependencies 与 capture tool；H2 原文必须与 formatter 输出全文完全相等，精确绑定 S commit/tree、build identity、payload closure、E1 commit/tree、evidence manifest path/SHA、candidate-verification SHA、endpoint capture tool SHA、endpoint closure SHA、listening matrix SHA、qualification runner SHA、`audioDeviceQualified=true`、`promotionAuthorized=true` 与 `decision=accepted`。E2/compact 复验可不传已经清理的 live root，但仍须从 E1 bytes 完整通过 attestation/snapshot 与 provenance/seal 校验。

Agent 随后在 E2 写 `docs/evidence/audio-v2/h2-promotion-acceptance.json`，严格符合 [`h2-promotion-acceptance.schema.v2.json`](contracts/audio-v2/h2-promotion-acceptance.schema.v2.json) 并保存完整原文。E2 必须是 E1 的 direct child，diff 恰好只有 ADR 与 receipt；ADR 的唯一顶层状态行精确改为 `ACCEPTED / E2E_VERIFIED / PROMOTION_AUTHORIZED / NOT_DEPLOYED`，唯一机器标记行精确改为 `H1_STATE=accepted；H2_STATE=accepted；E1_STATE=evidence_ready`，并原子写 H2 `accepted` 与“当前 H2 已有效”。随后用同一命令追加 `--h2-receipt <path>` 复核 E2。

E1/E2/E3 都是 **evidence-only 后继**：只能改变本文状态/台账及 `docs/evidence/audio-v2/**`，绝不是 release source。S 中每个 frozen contract blob 必须与 P 完全相等，即使当前工作树被还原也不能掩盖 S 漂移；H1 receipt 必须在 H/S/E1/HEAD 同字节，H2 receipt 必须在 E2/HEAD 同字节，commit-aware 恢复状态从 HEAD 的 ADR/备忘读取并要求工作树一致。现役 `cf7-runtime-build-request.v2` exact allowlist 保持不变；不得把 H1/H2 字段塞入 request、requestId、build identity 或 payload closure。source tag/request 必须精确指 S；request 创建后 E3 `h2-request-link.json` 旁路绑定 requestId、source tag、S、E1 manifest 与 E2 receipt。

任一 S、artifact source/input、candidate bytes、identity、closure、backend/device、automated report、endpoint closure 或 listening matrix 变化都会使 H2 失效，必须回 A6 形成新 S/E1 并重签。没有有效 E2 receipt 时不得创建 source tag/request、调用正式 builder、生成 production proof/quorum/receipt 或 promotion。

## 14. 风险与 stop-loss

| 风险 | 控制 | Stop-loss |
|---|---|---|
| MF seek/thread 生命周期复杂 | bounded A3 spike + fault injection | 无法稳定 seek/cancel 时只保留资产规范化，不硬接生产 |
| 新 codec 扩大 CVE/许可面 | 官方源码、pin/hash/notice、窄 allowlist | 依赖无法可复现或许可不清则拒绝该 codec |
| 设备恢复引入重复播放 | BGM latest intent，SFX no replay，generation | 出现 stale SFX/双播即停止 A2/A4 |
| content probe 拖慢 hot reload | background bounded runtime probe + explicit state | 不允许阻塞 UI/Flash ready；超时标 `inconclusive_timeout`，不误判 unsupported |
| 批量改名破坏 linkageId | shipped BGM 与 SFX 分开治理 | 未闭合全部 consumer 前禁止 SFX rename |
| meter 被误解为可听 | 结论词典 + endpoint/H2 | 任何 Gate 以 peak 单签即失败 |
| 一次性范围膨胀 | AUDIO-V2-013 非目标 | 出现 FFmpeg/网络流/DSP 要求时另开 ADR |
