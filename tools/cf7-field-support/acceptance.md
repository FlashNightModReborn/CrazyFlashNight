# 双开发机候选验收

这是待执行清单，勾选前记录真实结果。A 为维护者/Agent，B 为模拟测试员。使用实际 ZIP、普通用户入口、专用测试目录/克隆槽，不依赖 B 的 SDK、预置密钥或私下辅助脚本。

记录：验收人、日期、工具 buildId/ZIP SHA-256、A/B Windows 版本、游戏目录、源与运行身份、各项通过/失败/未测及证据位置。

2026-09-21 安排：已完成回执保存于仓内 `docs/evidence/field-support-*acceptance-2026-09-21.json`。维护者决定先提交推送当前工具成果，将 #105 设为待验收后归档并保持开放；下列尚未覆盖项随真实的 A 开发、B 测试继续，不要求本轮集中做完，也不把归档视为通过。各次施工记录当次身份和实际覆盖项，沿用本清单，不新建一套每日回执。

1. **初始连接**：B 解压启动→明确开启→复制网络申请→A 批准→B 导出票据→A 导入→双方核对指纹→B 允许。记录真实人工步骤和失败提示。A 批准的是新临时节点，不是把长期密钥放进工具包。
2. **跨网路线**：B 使用手机热点等不同网络。记录状态中的直连/中继信息与实际拓扑；必要时在 A 用现有 Tailscale 诊断查看目标路线。局域网通过不代签公网/NAT；本轮两地距离不代表跨洲体验。
3. **探针与传输**：A 生成带唯一 marker 的探针，上传 B 执行；结果绑定账户、路径、PID、文件哈希。下载证据并复核哈希。尝试不完整上传与篡改内容，确认不能发布为可用文件。
4. **问答**：A 发一个选项/文字问题，B 回答；再验拒绝、取消、到期与迟到回复。长命令期间问答和停止仍可响应。
5. **文件替换**：仅专用测试文件，验原件备份、替换与恢复；替换后主动改成第三种内容，恢复必须报告冲突且保留第三种内容。
6. **游戏候选**：A 用真实 producer 候选打包上传；B 导入规范目录、验证身份，正常退出旧游戏后从候选入口运行。核对真实 `isolated_candidate` 日志、PID、Core SHA-256 与 identity/closure。损坏 manifest、额外 runtime 文件与不匹配启动脚本必须拒绝。使用专用/克隆存档，不能拿真实槽试写。
7. **Agent 接班**：前一 CLI 退出，下一 Agent 先 status 再查询原操作，连接仍在原本有效期内。两个修改流程争用时其中一个明确 busy；状态与结束可用。
8. **撤销**：长命令运行期间 B 点“立即结束”，A 新命令被拒绝、受控子进程结束、原本运行的其他程序保留。旧票据与旧接班记录不能恢复权限。
9. **真实异常**：物理断网，最多 90 秒后本机撤权；重连不能恢复旧会话。另验助手异常退出、代理异常退出与机器重启。记录文件残留/恢复状态，未知写先核对，禁止盲重放。
10. **收尾**：正常退出实验游戏后结束诊断；检查任务、临时网络组件和文件变更。恢复冲突保持可见；不把“关闭窗口”当所有字节都恢复。真实测试员现场与 #106 的根因验证另行进行。

第一包允许发现并修正缺陷；完成以上本轮适用项后才报告双机验收通过。候选导入尚未实际运行就标未测，不能凭本机格式校验代签。工具验收通过后再以同一已验收包进入测试员现场。

- 提醒应明确指向尚待回答的问题；核对重复刷新、问题取消/到期、拒绝后的行为，避免旧问题继续提醒或把没有答复当作同意。

- 同轮记录真实不同网络拓扑、直连/中继路线、延迟与传输表现；局域网通过不代签该轮结果。
