# 地图工作台操作指南

这份指南写给第一次接触地图内容制作的人。先完成一个可撤销的小练习，再尝试新地点和人物迁移；不需要先理解 JSON、AS2 或 C#。

## 入门练习

### 先挪一个现有图块，不写入项目

目标：看懂“选中 → 修改 → 预览 → 撤销”。这次练习不用新增场景，也不用改玩家进度。

1. 左上方“地图页面”选择 **A兵团**，也就是基地页。
2. 在左侧对象树展开 **场景图块**，选择 **基地屋顶**。不是“人物身份”，也不是“物理地点”。如果分类收起来了，先点分类前的小三角。
3. 保持右侧 **创作视图**，点击 **聚焦所选**。确认 **编辑边框** 已勾选，**对比保存前** 未勾选。
4. 在左侧属性找到 **横坐标**，记下原数值，增加 10，然后按 Tab 离开输入框。等待底部完成预览；屋顶图块会向右移动。
5. 勾选 **对比保存前** 看原位置，再取消勾选看草稿。它只切换观察内容，不保存，也不撤销。
6. 点击 **撤销草稿末步**。图块和数值应回到刚才的位置。

做到这里就已经掌握最基本的编辑方式。整个过程不点击“检查并应用”，项目文件不会被这个练习改动。

> 改坐标后画面没有变化？先按 Tab 提交输入，再看底部是否“处理中”或有错误。切到“创作视图”，确认没有勾选“对比保存前”，然后试“聚焦所选”。不需要先把模拟进度改到后期。

### 创作视图与玩家预览

- **创作视图**是每次打开时的默认状态。可以选择所有页面和分层；当前方案隐藏的图块、地点与头像仍可编辑，并用“隐藏”文字和虚线标出。直接单击边框只选中，拖动才改坐标；也可从左侧选择对象后填写数值。
- **玩家预览**按当前 A／B 方案的真实条件显示，画布只读。若整页不可见，会明确写出当前页面名称和原因，点击“切回创作视图”即可继续制作；不会偷偷跳回 A兵团。若只是当前分层隐藏，也会明确提示，右侧其他可见分层仍可选择。

这两个按钮只切换看法，不改草稿、模拟方案或游戏条件。创作视图中显示出来，不代表玩家已经能看见或进入；检查剧情效果时请切到玩家预览，并结合左侧原因树。

隐藏对象优先使用当前方案能确定的外观；不能确定时显示基础图片或占位。室友性别未知时只显示占位，不替你猜男生或女生。

### 界面从哪里看

- **左侧上部**：页面选择、对象分类和新建／复制等操作。
- **左侧中部**：当前对象的属性，以及“怎样编辑这类对象？”的对应帮助。
- **左侧下部**：“对照原因与当前值”、应用历史和草稿操作。
- **右侧上部**：创作／玩家视图、方案 A／B、模拟编辑、显示方案和画布工具。
- **左侧底部**：草稿操作数量、检查并应用、当前结果或错误。遇到问题先看这里。

可随时点“← 返回编辑”继续操作。帮助页不会替你执行教程，也不会自动修改数据。

## 认识这些对象

同一个人物、同一个真实地点，可以在地图上出现多次。下面这些对象负责的事情不同。

| 对象 | 可以理解成 | 什么时候编辑它 |
| --- | --- | --- |
| 地图页 | 地图的一张纸／一个页签 | 新建一页、改页签名、调整页面尺寸 |
| 物理地点 | 游戏真正能前往的地方 | 登记真实场景、设置这个地点能否进入 |
| 地点表现 | 某张地图上的可点区域 | 把一个已有地点放到另一页，或关联图块 |
| 场景图块 | 地图上的建筑／地形图片 | 挪屋顶、换图片、调整大小和层级 |
| 分层 | 地图右侧的筛选按钮 | 让玩家只看屋顶、一楼或某片区域 |
| 人物身份 | “这个人是谁”的档案 | 维护显示名、现场任务检索名、驻点数量策略 |
| 人物驻点 | “这个人在哪、何时在场” | 安排人物出现、离开或迁到另一地点 |
| 人物头像 | 地图上表示驻点的小图片 | 调整头像位置，按剧情换头像 |
| 剧情条件 | 可重复引用的一组要求 | 多处共用一组任务／基建条件 |
| 任务端点 | 已有任务找谁接、找谁交 | 选择固定驻点，或跟随人物当前驻点 |

### 最容易混淆的三件事

- **有图片不等于能进入**：图块只是表现；可点区域要关联物理地点，地点还要绑定真实场景。
- **有头像不等于能对话**：头像只是标记；真实 NPC 必须先存在于已发布场景，再由人物驻点显式绑定。
- **地点可进入不等于所有关卡已解锁**：具体关卡仍有自己的条件，地图条件不会替它解锁。

“稳定标识”用于内部关联，不需要手动改。改显示名称不会自动把人物变成另一个人。

复制整页会新建页内表现、图块、头像和分层的标识，但复用原物理地点、人物身份与驻点。若想复制的是“另一座真正的新场景”，需要另外制作并登记场景。

## 创建地图和地点

### 先决定：复用旧地点，还是接入新场景

第一次建页，建议先复用一个已有地点。这样可以先学会页面布局，不必同时处理 Flash 场景制作。

1. 点击对象树的 **地图页** 分类标题，再点左上 **新建**，输入名称并确认。空分类也可以这样新建。
2. 点击 **地点表现** 分类标题 → **新建**，从 **复用的物理地点** 中选择已有地点。
3. 点击右侧 **素材库 / 导入** 准备图片；已有图片可以直接选，暂时不要点击应用。
4. 点击 **场景图块** 分类标题 → **新建**，选择图片和刚创建的地点表现。
5. 在属性中调整横坐标、纵坐标、宽度和高度。也可勾选“编辑边框”后直接拖动图块。
6. 需要右侧分层按钮时，选择 **分层** → **新建**，勾选它包含的地点表现；再选图块，勾选 **图块出现在哪些分层**。
7. 切换页面和分层检查布局，再按“剧情条件与双方案”一章检查不同进度。

新建按钮针对的是你最近选中的对象类别。想建图块却弹出人物窗口时，取消，重新点“场景图块”分类标题即可。

### 确实要新增物理地点

先在既有场景制作流程中做好并发布真实场景，完成游戏侧接入；然后在工作台点 **重读 / 核对结果**，更新制作目录。

选择 **物理地点** → **新建**，只能挑选“已接入且尚未登记”的真实场景。登记后，再为它添加地点表现和场景图块。

没有可选场景时，不是让你手填一个英文标识。已有场景请复用原物理地点；真正的新场景需要先补齐制作与发布。可从已有物理地点的 **打开场景制作源** 查看入口。

### 修改边界与顺序

- 已关联图块的地点表现，其边界会随图块的整体范围更新；要挪建筑，优先改场景图块。
- 图块“上移／下移”改变绘制顺序；分层“上移／下移”改变按钮顺序。复制目前支持整页和图块，不复制人物身份或驻点。
- 要在另一页显示同一地点，创建新的地点表现，不要重复登记真实场景。

## 剧情条件与双方案

### 条件写在什么地方

- 页、图块、头像的 **显示条件**：是否画出来。
- 物理地点的 **显示条件／可进入条件**：是否显示这个地点、是否允许普通导航。
- 人物驻点的 **人物在场条件**：此人此时是否在这处驻点。
- 图块／头像的 **编辑剧情外观变化**：条件成立时换成哪张图片。

条件编辑器中的“全部满足”表示每条都要成立；“任一满足”表示至少一条成立。可以嵌套组合，但不要用大量重复条件堆出难以理解的逻辑。

### 例子：主线达到 30，或者大学达到 7

1. 选择要控制的物理地点，点击 **可进入条件**。
2. 将条件类型改为 **任一满足**，添加两个子条件。
3. 第一个选任务链“主线”，最小进度填 30；第二个选任务链“大学”，最小进度填 7。最大进度不需要时留空。
4. 保存条件，等待预览。先不应用到项目。
5. 在右侧选好两个不同的模拟方案，分别点 **编辑 A**、**编辑 B**。给 A 设置主线 29／大学 6；给 B 设置主线 30／大学 6，然后保存模拟方案。
6. 切到 **玩家预览**，用 **显示方案** 切换 A／B；左侧展开 **对照原因与当前值**，检查 A 为什么不满足、B 命中了哪条分支。
7. 再把 B 改为主线 29／大学 7，检查另一条开放路径。

在玩家预览中，如果对象还受页面或其他显示条件约束，只改“可进入条件”不一定能让它出现；先看原因树，不要把所有条件一概改为永远满足。继续调整布局时切回创作视图。

### 这些进度不是一回事

| 模拟事实 | 含义 | 不会自动代表什么 |
| --- | --- | --- |
| 任务链已完成的最大链序号 | 这条链推进到了哪个完成节点 | 不代表此前每个任务都完成 |
| 历史任务完成 | 某个具体任务曾完成 | 不代表它现在可以交付 |
| 进行中 | 当前接着这个任务 | 不代表目标已经达成 |
| 可交付 | 当前任务满足交付条件 | 不能仅凭主线数值推断 |
| 基建等级 | 是否拥有、建到了几级 | 空白不是 0，也不是已建成 |

数字留空表示未知。遇到未知时，工作台不会替你假定条件成立。

“读取游戏事实”只读当前游戏状态；没有连接游戏时不可用。实时事实不能直接编辑，先用 **复制 A 为模拟** 建立独立副本。编辑模拟方案不会改玩家存档，也不会变成地图草稿操作。

A／B 如果选择同一个方案，编辑它时两边都会跟着变；要做对照，请选不同方案或先复制一份。

外观变化按顺序采用第一个满足项。早晚头像同时满足时，上面的项优先；有未知条件挡在前面时，先补事实，不要仅靠调整顺序掩盖问题。

## 人物身份与驻点

### 在地图上放一个真实 NPC

1. 先确认这个 NPC 已在真实场景中制作并发布。工作台不会凭空生成 Flash 人物、对白或商店。
2. 在 **人物身份** 中复用已有的人；只有确实新的人物才新建。显示名可以改，**现场任务检索名** 必须对应真实 NPC，不能拿显示名猜。
3. 新建 **人物驻点**，选择人物身份和驻点位置。
4. 在 **真实场景中的 NPC 实例** 下拉框中选择匹配实例。没有选项时，先检查人物检索名、物理地点和来源是否已就绪。
5. 设置 **人物在场条件**。对已显式接管的实例，它是这处 NPC 的出现规则。
6. 确认本页已有该物理地点的 **地点表现**；再新建 **人物头像**，选择人物驻点、附着的地点表现及图片。
7. 在 A／B 中检查头像和驻点原因。应用并完整重启后，再到真实场景检查对话与任务行为。

> 绑定真实实例时，不会自动把源脚本里的“任务需求／任务需求支线”翻译成工作台条件。若要保留旧门槛，请把主线要求与历史任务完成要求明确写入“人物在场条件”，再应用。未显式接管的原 NPC 继续按原脚本初始化。

“只配置地图展示，暂不接入真实实例”只承诺地图表现。它不能作为新任务目标已可到达的证明。

### 例子：同一个人从甲地迁到乙地

- 只用一个 **人物身份**，驻点数量策略选 **同时只在一处**。
- 建立甲、乙两个驻点，各自绑定对应场景中的真实实例。
- 甲驻点条件为主线最大进度 29；乙驻点条件为主线最小进度 30。
- 两处头像分别关联自己的驻点和地点表现。后期换头像时可编辑剧情外观变化。
- 用主线 29 与 30 的方案对照，确认任何一个方案都恰好只有一处在场。

不要新建两个同名人物来冒充迁移；任务需要跟随的是同一个身份。确实允许同时多处的人物，应选择对应驻点策略，并谨慎使用跟随端点。

来源发生变化时先点“重读 / 核对结果”，核对后使用 **更新该实例的来源绑定**；不能仅因为名称相同就假定仍是同一个可用实例。

## 任务端点

选择对象树 **任务端点** 中的已有任务，点 **编辑接取 / 交付端点**。接取与交付分别设置，可以找不同的人。

| 方式 | 适合的剧情 | 目标不在时会怎样 |
| --- | --- | --- |
| 固定驻点 | 必须到某地找此人 | 解释不可达，不自动转去别处 |
| 跟随当前驻点 | 此人搬家后任务仍跟着他 | 必须唯一找到一个在场且已接入的驻点 |

跟随解析出零处、两处或未知时都不会随便取第一个。先到“人物驻点”检查在场条件与真实实例绑定。

### 建议的验证顺序

1. 先让人物的两个驻点在 A／B 中正确互斥。
2. 给一项任务设置固定驻点，给另一项设置跟随当前驻点。
3. 在两套方案中查看任务端点说明：固定端点不应偷偷搬家，跟随端点应随着唯一在场驻点变化。
4. 应用重启后，检查任务列表的前往、地图红点、HUD 提示，以及实际接取／交付。

这里只编辑“找谁、去哪里”。任务的前置、目标、对白、奖励、任务增删和远程交付开关仍在任务制作源。按钮 **打开任务制作源** 可以定位原文件。

历史任务可能只填写一个 NPC 名，没有固定地点。这原本可能表示任意同名现场都可匹配；改为新端点前先确认剧情意图，不要仅因为地图上暂时只有一个头像就强行固定。

## 素材与清晰度

### 导入或替换图片

选中图块／头像后，可点属性中的 **选择 / 导入图片**；也可从右侧 **素材库 / 导入** 浏览全库。

1. 导入 PNG、WebP 或 JPEG，先看透明背景、像素尺寸和来源信息。
2. 需要裁切时设置像素矩形并生成新候选，再检查边缘。裁切不会改坏原图。
3. 明确选择候选并关联到目标图块／头像。仅导入图片不等于已经替换了地图内容。
4. 在实际地图显示尺寸下看清晰度；“看起来大”不等于原图像素足够。
5. 确认后再检查并应用。正式新增图片会随地图批次写入，不需要手工复制文件。

透明边缘会经过真实解码与像素校验；不要只给文件换扩展名。单图上限为 16 MiB、单边 4096 像素、总计 1600 万像素。

### 从已有 SWF 提取

从发现的发布素材中选择来源元件、帧和倍率，再提取为候选。不是让你猜数字 SpriteId。

依赖外部素材或尚未能独立导出的元件会说明不可用；需要回到 Flash 素材制作流程，不要随便选另一个编号代替。提取不会修改 SWF。

换图片后仍要检查尺寸、关联地点表现与分层。已有共享图片不会因为删除一个图块就被一并清理。

## 应用、重启与撤回

### 三层内容要分清

| 你看到的东西 | 在哪里 | 何时改变 |
| --- | --- | --- |
| 未应用草稿 | 工作台中的修改 | 编辑、撤销末步、放弃草稿 |
| 项目已保存内容 | 地图、任务源和图片文件 | 确认“检查并应用”或精确撤回 |
| 当前游戏加载内容 | 已运行的启动器进程 | 完整退出启动器后重新启动 |

**对比保存前** 切换的是同一方案下的“磁盘基线／草稿”；**显示方案 A／B** 切换的是进度。它们是两个独立的比较方向。

### 正常应用

1. 检查 A／B 效果与左侧原因，确认没有错误。
2. 点击 **检查并应用**，逐项确认将修改哪些地图文件、原任务文件和新图片。
3. 确认应用，等待底部明确显示完成。不要在处理中连续点击。
4. 退出整个启动器，再从 **地图工作台测试启动.cmd** 打开同一候选。只返回游戏标题页不够；第二阶段验收期间不要改用旧正式入口。
5. 从实际游戏入口检查刚才的效果。预览不会真的导航或替你完成任务。

### 想反悔时选哪个按钮

- **撤销草稿末步**：只退回最后一次未应用操作。
- **放弃草稿重读**：丢弃全部未应用修改，重新读磁盘内容；不撤回已应用内容。
- **应用历史 / 精确撤回**：选择已应用批次，点击“撤回所选批次”；当前有草稿时先导出或处理草稿。
- **导出草稿**：保存当前编辑意图，便于备份；它不是整份项目备份，也不能绕过原内容摘要检查。

关闭工作台会保留草稿，不等于应用。撤回后也要完整退出并重开，游戏才会使用恢复的内容。

### 超时、冲突和恢复

结果未知时点 **重读 / 核对结果**，查询这次操作究竟是否完成；不要复制一份操作重新提交。

保存后立即关闭或退出时，文件可能已经写好，但界面还没收到确认。重新打开工作台会先自动核对原保存：已完成就显示已保存内容并清除对应的待确认草稿，不会重复应用；尚未完成或确实发生外部冲突时，才保留草稿并给出下一步。不要因为再次看到草稿提示就重做或重新应用同一批修改。

如果提示文件被其他人修改，先保留／导出草稿，再核对新的磁盘内容。精确撤回不会覆盖后来独立编辑的字节，也不会删除仍被别处引用的共享图片。

拉取上游后，没有未应用修改的空草稿会自动使用新内容；真正的未应用草稿会保留。若地图或任务资料已经变化，画布会显示 **旧草稿与当前项目不一致**，明确提示预览已暂停；这不是还在加载，继续等待不会自动恢复。此时编辑、导入与应用暂不可用，右侧直接提供两种处理入口：

- **导出保留的草稿**：保存旧基线和全部未应用修改；导出后仍保留当前草稿。之后需对照新内容迁回，不能直接覆盖新版本。
- **放弃试用草稿并加载当前项目**：明确丢弃未应用修改并恢复当前项目预览。只影响浏览器草稿，不撤回已保存内容，也不修改玩家存档；与左侧“放弃草稿重读”是同一操作。

如果还有写入尚未确认完成，右侧改为 **核对写入结果**，不能直接丢弃。先查询原操作，再按结果处理；不要重复提交。关闭／重开工作台或目录暂时读取失败，都不会抹掉保留的草稿。结果未知的写入也不会当作空草稿丢弃。

“恢复未完成批次”用于当前已知的中断操作，不是清理旧数据的按钮。无待恢复批次时不用点击。

## 常见问题排查

| 现象 | 先检查什么 | 下一步 |
| --- | --- | --- |
| 不知道新建会创建什么 | 对象树最近选中的分类 | 先点目标分类标题，再点新建 |
| 画布看不见新图块 | 当前页、分层、关联地点表现和显示条件 | 切到全部分层，选对象并聚焦；看原因树 |
| 图块能看见但不能拖 | 编辑边框、对比保存前、处理中状态 | 开启边框，关闭保存前对比，等预览完成 |
| 改数字后没有反应 | 输入框是否还在编辑 | 按 Tab 或点空白提交输入，再看底部错误 |
| 地点可见却不能进入 | 可进入条件与导航生命周期 | 看具体原因；战斗／结算中的普通导航仍受限制 |
| 整个页面不见了 | 页面自身的显示条件和当前方案 | 补齐事实，或修正页面条件；不要直接删除页面 |
| 方案显示“未知” | 对应任务、链或基建是否留空 | 填入明确模拟值，或读取真实游戏事实 |
| 改 B 时 A 也变了 | 两侧是否选择同一个方案 | 选不同方案，或先复制一份 |
| 头像存在但场景里没人 | 驻点是否显式绑定真实实例 | 核对来源、人物在场条件，并完整重启 |
| NPC 实例下拉框没有选项 | 人物检索名、驻点物理地点和发布状态 | 打开制作源补齐；重新读取目录 |
| 跟随任务找不到人 | 是否恰好一个驻点在场且就绪 | 修正互斥条件，不用同名人物临时顶替 |
| 删除被拒绝 | “查看引用”列出的任务、驻点、表现 | 先重绑／解绑引用，再删除目标 |
| 应用按钮不可用 | 没有草稿、校验失败、忙或结果未知 | 看底部原因；只编辑模拟方案不会产生内容草稿 |
| 应用后游戏还是旧内容 | 是否只返回了标题，或开了旧正式入口 | 完整退出，用同一测试 CMD 重开 |
| 上游更新后旧草稿冲突、预览暂停 | 项目／任务源已经变化，不是仍在加载 | 使用画布中的导出／放弃入口；有未确认写入时先核对结果 |

仍不能定位时，向维护者描述“选了哪类对象、改了哪个字段、期望怎样、实际怎样”，附底部错误和 A／B 原因截图。不要只报一个内部标识，也不必提供玩家存档。

## 画布与键盘

- 滚轮或 **−／+**：缩放观察，不修改图块尺寸。
- 鼠标中键拖动，或按住空格再左键拖动：平移画布，不移动对象。
- **聚焦所选**：把所选图块／头像移到适合观察的位置。
- **玩家取景**：恢复当前页面／分层的标准取景。
- **专注画布**：暂时收起属性区；按 Esc 或“显示属性”返回。
- 画布取得焦点后，方向键可平移，Home 恢复取景。
- 对象树用上／下、Home／End 移动焦点；Tab 进入下一控件，Enter／空格激活按钮。
- 帮助中可搜索主题，点“阅读当前主题”把焦点移到正文；正文可用方向键和 PageDown 滚动。
- 帮助的 **← 返回编辑** 或 Esc 返回原编辑状态；右上 **关闭工作台** 则关闭整个工作台，不会偷偷应用草稿。

坐标输入、选择列表和按钮都是拖拽的替代路径。不方便拖动时，直接填写属性即可。
