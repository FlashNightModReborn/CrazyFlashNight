# 武器散射度数值口径

本文档记录 `data/items/武器_*.xml` 中 `<diffusion>` 的设计口径，避免后续按单把武器直觉反复漂移。

## 字段含义

- `diffusion` 是子弹角度随机偏移的半径，实际弹道约在 `[-diffusion, +diffusion]` 整数角度内随机。
- 角色移动射击会在武器基础散射上追加惩罚，基础值不需要单独覆盖移动惩罚。
- `accuracy` 是命中加成，不等同于弹道散射。

## 玩家枪械的点射扩散控制

普通枪弹及纵向枪式联弹在成功开火提交时使用 500 ms 游戏时间窗口；暂停期间窗口不增长。
`n` 包含本次成功开火，`Δ` 使用本次技能/配件生效后、按调度器向上取整的正常间隔。
基础扩散倍率为 `0.5 + 0.5 * min(1, n / max(1, 500 / Δ))`；有效间隔至少 500 ms 时每发保留原扩散。
实际武器的历史由角色运行态保存，双枪不同物件独立；动画重建、切回原武器或同物件换手不清空历史。
记录不写物品或存档；空仓、提交拒绝、暂停及无效弹道不增加密度。

只缩放基础枪械散布，移动额外惩罚及移动射击技能保持原口径。随机角度仍按原整数半径抽样，
再缩放结果；原 `diffusion` / `子弹散射度` 字段不连乘，也不承接本次倍率。
纵向联弹按一组计一次，整组冻结倍率，首颗与补弹一致；补弹节奏、间距随机和衰减不变。
横向霰弹、拖尾、导弹、弓箭、喷火/技能以及非玩家控制单位继续使用原行为。
具体适用枪弹在 `WeaponSpreadRuntime` 中定义。真实 CS6 回归入口：`scripts/run-weapon-spread-tests.ps1`。

小数散射角不能进入 MovieClip 实例名称；子弹实例使用独立序号，避免 Flash 目标路径中的点号
使 `area.getRect` 产生无效碰撞框，导致子弹无法进入运动与清理队列。下挂副武器的枪口只用于
出生坐标转换，飞行弹不以静止枪口区域作为旋转碰撞区域。穿刺弹进入退场帧后保留地图检测，
但不重复因射程超限重启同一退场动画。

素材与飞行回归分别使用 `scripts/run-weapon-spread-lifecycle-tests.ps1`（普通弹首发、连续射击、
真实命中与穿刺退场）和 `scripts/run-weapon-projectile-flight-tests.ps1`（纵向对象/素材回退、
副武器导弹近远距离、左右及移动深度）。两者加载现役子弹素材，经过真实工厂、运动、碰撞队列和
清理；敌人缓存、伤害公式与表现使用隔离夹具，不代替候选构建、发布或人类实机体验验收。

## 分来源装填与幽灵散射

留膛、幽灵装填和技能奖励按独立字段共存，普通弹容 `C` 先按原插件与取整规则计算。提前换弹只把已有普通弹转为留膛来源，弹药总量不变；补满普通仓后才能得到 `C+留膛`。折开式、转轮及其他未获结构标注的武器不能由这条路径凭空增加弹容。双管白火铳和非栓式机构沿用既有取整、威力及配件叠加。

原生幽灵资格加冲击连携才允许幽灵装填；枪械内构强化套件以 merge 将上限提高到 2。没有原生资格的武器只得到内构原有收益。TTI Benelli M4 的普通弹容调整为 7，留膛 1、原生幽灵 1；装内构并启用技能可到 7+1+2。GM6 的奖励超装上限独立为 `C`，可与留膛共存；奖励优先补普通仓缺额，再填奖励配额，不由内构获得幽灵资格。结束出击使未装备、背包中的旧奖励同样过期，付费弹药与拆包余额保留。

每发按提交前实际剩余幽灵数 `G` 冻结散射倍率 `1+min(2,2G/C)`，消费顺序为幽灵、奖励、留膛、普通。倍率只加宽实际弹道角度，不改原始 diffusion 或旧衰竭参照，不把移动惩罚再乘一次；已发射联弹不会随下一发的来源数改变。幽灵弹打完即回到原散射。该风险针对中远距离单体火力，近距离与群体收益仍需真人平衡验收。

换弹在实际动画门禁逐次提交；射击取消、松开持续装填或受击只结束剩余动作，保留已提交的装填和已支付余额。具备资格时，轻点换弹会自动补足幽灵配额，不要求持续按住。完全打空后轻点换弹先走原整匣路径，再以独立逐发动画补幽灵弹；按住换弹在动画门禁选择逐发装填，松开仅取消这种长按模式。取消后仍走原射速、半自动与射击许可检查；空枪持续按射击不会阻止装填推进。

每次拆包只增加 `C` 发预算；额外容量不会提高每包产出。未用预算随武器保存、跨场景保留，即使无新弹匣也能使用最后余量。免费初始弹、补给和技能造弹不变成付费余额。真实弹种改变时卸下旧装填，已付费部分只退回原弹种余额；普通盒式换匣仍遵守既有弃弹和枪械师回收规则。

装备注释只在普通弹容数字后以青色、黄色、紫色 `+N` 标出留膛、幽灵与奖励的条件上限；不再逐件附加装填机制正文。颜色图例、触发条件、打断和拆包规则集中在游戏帮助「基本操作」的装填章节，幽灵的技能要求与散布代价同时由「冲击连携」说明。

HUD 主数字显示实际总弹数，沿用原有单枪/双枪数字格式与宽度，只改变现有弹药文字颜色：幽灵为黄色、奖励为紫色、留膛为青色，三者并存时依此取优先级。拆包余量和全部来源发数、超额数及本发散射倍率放在对应枪位的悬停说明中。新 Host 通过 `ammoDetails` 协商详情，旧 Host 仍接收原字段集合；合法来源由 AS2 判定。

机器验证入口：`scripts/run-weapon-ammo-tests.ps1`、`scripts/run-weapon-ammo-data-tests.ps1`、既有射击/双持/联弹/HUD/钛金套装专项。原生持久化通过唯一 disposable SOL 的真实 flush，再由 `tools/inspect-weapon-ammo-sol.mts` 读取原始字节的不可变副本；测试不写玩家槽位。最终候选从根 `本地开发启动.cmd` 进入，换弹节奏、散射风险、HUD 可读性与 TTI 平衡保留人工验收。前期开发停在人力验收；2026-10-20 已追加完整发布列车授权，按冻结源码、本地与云端独立共识、政策门及原子部署推进。正式状态以 runtime manifest 与签名 consensus 为准，部署不代签手感和平衡验收。

## 建议带

| 类型 | 常规建议 | 说明 |
|------|----------|------|
| 狙击步枪 / 精确反器材 | `1-2` | 高射速、科幻半自动或粗糙旧枪可到 `3-4` |
| 战斗步枪 / DMR | `2-3` | 全威力自动射击平台可到 `4-5` |
| 突击步枪 | `3-6` | 短管、老旧、高后坐或粗放仿制可到 `7-8` |
| 冲锋枪 / PDW | `3-6` | MAC10、全自动手枪、粗糙短枪可到 `8+` |
| 手枪 | `3-5` | 竞赛枪、长管精密枪可到 `1-3`，土制/短管/粗糙枪可到 `7+` |
| 机枪 / 压制机枪 | `5-8` | 稳定架构或科幻补偿可到 `3-4` |
| 霰弹枪 | `8-20` | 锯短、超短枪可到 `25+`；独头弹、能量弹按实际弹种另判 |
| 发射器 | `2-6` | 火箭/导弹多为 `2-4`，榴弹多为 `4-6`，DIY 或弹幕武器可到 `8+` |

## 例外原则

- 可以因为现实原型、来源游戏手感、科幻设定、技能联动或平衡需求越出建议带，但需要在描述、注释或提交说明里留下理由。
- `GM6_LYNX` 的较大散射来自 CQB 反器材平台设定，允许保留。
- `NEGEV` 的极低散射是致敬 CS:GO 激光枪弹道，允许保留。
- `夜莺` 是能量霰弹武器，弹丸为能量束而非实体弹丸，不遵循常规霰弹枪扩散规律，允许保留极低散射。
- `T181` / `T181C` 为早期反器材原型枪，以粗犷结构和低精度换取大口径破坏力，允许保留偏大散射。
- `单管步枪` 是 1 级民用狩猎武器（老旧的单发猎枪），并非军用狙击平台，允许保留较大散射。
- 能量步枪、磁轨武器、G11 类超高速点射可使用极低散射，但应确认不是漏填默认值。
