## 操作与信息

- 药剂和技能共用右上角 × 卸下操作。图标本体查看详情，快捷键使用；没有额外编辑模式。药剂操作携带真实 A/B 组 slot，按下和抬起必须命中同一目标，换组、换角色、断线或 revision 变化取消旧手势。
- 冷却和资源不足各有含义：冷却占据中心倒计时；可用次数临界时显示静态琥珀色角标及“1次”；不可用时显示原因。倒计时仅最后三秒显示小数，不提前宣布可用。
- 药剂组用 A/B 标识。双持弹药只用固定上下两排区分，移除“主／副”文字与双刻线；详情保留“主手（上排）／副手（下排）”。弹药与弹匣保留各自图标，移除重复的“发／匣”后缀；搓招保留自己的来源顺序，不随快捷技能装卸跳位。
- 药剂数量独占图标左上角的固定区域，与右上角 × 留有间隔。普通数量保留原值，大数量按实际字体宽度缩写，最后以固定边界裁切兜底；不会挤占相邻槽或卸载按钮。药剂图标像装备/技能图标一样直接在下方标出当前快捷键，整格（含左上角数量、中心图标、底部快捷键与右上角 ×）共用同一条物品/技能默认详情提示并在其中展示完整数量与所属快捷栏格位（如 `快捷栏：A组4号格（快捷键：0）`），不再在左上角数量或右上角 × 处弹出第二套独立深色小框，避免多重显示；数字区域点击不卸载，右上角 × 点击仍执行卸下。
- 盾量主读数和青色环始终取最新权威值。失效或扣除后的旧量只作细灰色辅助残影，不伪装成仍可承伤的护盾。盾量与护盾强度分别标识。
- 资源详情统一使用技能栏右侧既有斜纹中的说明入口，移除资源旁新增入口；完整名字保留在详情中。姓名静止截断，经验和技能点降低视觉权重，常驻技能等级角标让位给使用状态。HUD 本地说明框（资源、弹药、Buff、关卡聚焦目标）与物品/技能等远端 tooltip 统一使用 `NativeTooltipWidget` 默认半透明灰渐变样式与默认正文字号，保持全界面注释风格一致；战技槽采用更高对比度的金属灰蓝渐变底衬与剪影内填充（`alpha=96`），并与主动技能、药剂统一使用纵向冷却遮罩 + 琥珀色分界线（`horizon`）+ 中心倒计时，移除战技槽底部冗余的横向进度细条（横向进度细条仅保留在武器切换槽）。
- 关卡聚焦目标血条（`PlayerHudFocusTargetWidget`）支持同屏最多 **4 个目标**纵向堆叠（单行高 `30px`、行距 `3px`），按 **`protect`（保护目标）> `boss`（关卡首领）> `combat`（当前交战目标）** 排序并自动去重（已作为保护目标或 Boss 显示的单位不重复占交战槽位）。`combat` 目标由玩家直接命中（`shooter._name === _root.控制目标`，15 帧 `0.5s` 粘性窗口内 AOE 多目标取 `hp满血值` 更高者）优先驱动，无直接命中时回退至 `hero.攻击目标`（索敌战技/受击仇恨），脱离交战 150 帧（5 秒）或目标死亡（`hp <= 0`）自动隐藏，使未预设关卡聚焦目标的普通关卡同样具备实时目标血条反馈。同时，玩家直接命中敌方目标时统计全局输出连击数（`hits`，散射武器按 `actualScatterUsed - scatterMissCount` 累加有效命中段数，窗口内切换目标或目标去重到 `boss` 行不断连，连续 `COMBO_TTL_FRAMES = 75` 帧 / `2.5s` 无命中清零），并在受击目标行角色徽章右侧紧邻渲染同款机械切角连击徽章 `[N HIT]`（`1..9` / `10..29` / `30+` 三档递进暖金-炽橙-绯金配色，命中递增触发 `150ms` 缩放高光脉冲，名称锚点保持稳定不抖动）。视觉与动效全面对齐左下角玩家资源层：（1）外框、左侧 `22×24` 头像框（复用 `LootIconCatalog` 的 `enemy-portraits` 矢量头像与 `doll-portraits` 换装烘焙管线）、角色徽章与连击徽章采用玩家护盾铭牌同款机械切角多边形；（2）`boss` 与 `combat` 统一采用玩家 HP 血球同源的三段深绯红光泽与暖橙红受击残影（以 `Boss` 暗金绯红徽章/加强金属边与 `交战` 冷灰钢徽章区分首领与普通怪），`protect` 对齐玩家护盾荧光青（`#00FFFF`）与深青黑金属底；（3）血条采用平行四边形斜切轮廓、内部暗网纹肌理、斜向亮刃前沿与 `25%/50%/75%` 斜向微刻槽，超额生命（`>100%`）复用玩家 `HpOverflow` 珊瑚暖金与 `MpOverflow` 斜纹；（4）右上角读数改用玩家资源区同款 Aero 矢量数字（`PlayerHudTextCache`），并将聚焦目标血条的量级缩写阈值提高至 `1,000,000`（读数预算宽度 `92px`），使 1~6 位数（`<1,000,000`，即数万至几十万血量的 Boss，如 `158420/200000`）完整显示精确整数，仅 `>=1,000,000` 时缩写为 `万/亿`；（5）接入 `Tick(deltaMs)` 时钟驱动受击残影 `90ms` 保持 + `230ms` 平滑收缩、`360ms` 翠绿回血预览前沿、`150ms` 连击脉冲及 `1300ms` 周期低血危急正弦微呼吸（过渡结束自动归于零开销空闲）。无活跃 Buff 时血条紧凑贴顶至 `y=4`，有 Buff 时按实际卡片行数下移至 `y=36`、`68` 等；支持逐行只读悬停展示完整名称、角色说明、精确 `HP / MaxHP (百分比)`、超额量、当前连击数与危急状态。

## 动效策略

危险提示优先于操作回执，操作回执优先于冷却完成提示及装饰。低生命以 25% 进入、超过 30% 退出，避免临界反复闪动；满状态停止无用循环。冷却完成反馈缩短为 180 ms，多槽同时结束时分摊亮度；暂停、隐藏、死亡、换组或装配变化不补播旧事件。

`hudMotionMode` 是独立的 Host 持久化偏好：`full` 完整，`reduced` 精简，`static` 静态反馈。未知或旧配置回退到完整；保存失败回退原值且不发应用通知。降低动效不会降低权威数据更新频率或隐藏禁用原因。

## Buff 显示合同

`MetaBuff.hudInfo` 为可选显示 DTO：`name`、`description`、`polarity`、`stacks`。投影在注册时复制为不可变数据，沿用原主计时器；不从 ID、命名正负或时长猜增减益。药剂、兴奋剂、铁布衫、霸体减伤及本轮涉及的剑圣/蛛网来源显式提供名称与语义；其他 MetaBuff 可由子 Buff 的真实属性名提供中性概述，缺少信息时显示“状态”。尚未声称全效果目录的专用图标与文案已经完备。

来源文字有长度上限，并有独立元数据总预算，避免拥挤的 Buff 列表挤爆既有 128 KiB 传输上限。超预算只省略可选说明，不删除 Buff 或计时。旧消息没有 `info` 仍可解析。

Host 对 Buff 栏执行紧凑重排：常驻/无主计时 Buff（`!Timed`，含腕刃等装备常驻 Buff 及其事件爆发态）优先，限时 Buff（`Timed`）随后；同类内部按获取顺序排列。卡片在刘海左侧安全列内每行10张、行距32逻辑像素自动换行，临时 Buff 消失后紧凑补齐；聚焦目标血条使用同一布局高度随行数下移。单页最多8行，超过80张才出现本地翻页，现有256行传输上限内的卡片全部可访问，最多四条目标血条仍留在底部玩家HUD上方。翻页只改变本地显示，不发送游戏命令；换角色、连接代次、列表收缩及隐藏期间取消旧点击。

若原悬停槽位对应的 Buff 已消失或变为其他 Buff 则立即关闭过时提示。卡片采用深色金属底和银灰边框，名称保持中性色，明确的增减益色收敛到计时条或底部短线；非计时状态不再显示无意义圆点。悬停显示全名、已提供的效果说明、增减益类别、层数和真实剩余时间。计时使用现有 AS2 步长，未提供主计时器时不制造倒计时。Buff 实现 `INativeHudPointerSnapshot`，共享合成的输入路由才能验证目标并送达悬停；排队事件跨 Buff 替换、角色或视口变化失效。悬停为本地只读，Buff tooltip 留在上部 surface，避免把上下 HUD 合并成覆盖整个游戏的输入区域。

### 可选 `buffDetails` 基础设施（2026-10-24）

Host 在现有 `playerHudSync` 中显式请求 `buffDetails=true`，断连后能力退休；未请求的旧 Host 继续接收原精确字段集。`MetaBuff.hudPresentation` 是独立可选显示描述，不参与数值、叠层或生命周期。声明方必须显式提供 `groupId/primary`、事件组件与是否读取实际注入 Pod，不能按名称、数值正负或组件形状自动归组。

协商后每行可增加 `incarnation`、可选 `group/activation/mods`。`incarnation` 来自 `getId()`，仅作显示实例版本；外部 ID 继续负责稳定槽位，不能用于删除 Buff。`activation` 只读显式事件组件的 `isActive/getRemaining/getDuration`，与 Meta 存活状态和主寿命计时分离。`mods` 读取 `getInjectedPodIds(meta.getId())` 对应的实际 Pod，保留 `property/calc/value`，Host 不把子效果合计成最终角色属性。

每条最多 8 个修正、每快照最多 64 个；超预算省略对应可选 `mods`，不保留容易被误读为完整列表的半份数据。字段缺省表示未提供详情，`mods=[]` 才表示已确认当前没有注入修正。普通 Buff 不执行新增 Pod 查询或逐行 DTO 分配，旧快照及行继续不可变。

Host 从同一份 adopted raw rows 生成共享卡片视图。一个显式组必须恰有一个 primary、至多一个激活源，否则全组退回独立卡；组卡沿用 primary 的外部 ID。绘制、命中和 tooltip 消费同一卡片，不因同 ID 换实例而误关提示。tooltip 只比较阶段、逐项修正和量化后的显示秒数，避免其他 Buff 或每帧计时变化触发无谓文档重建。

腕刃控制器和常态/爆发效果显式共享组 ID，控制器提供激活状态及真实事件计时，效果提供实际注入修正。玩家看到一张卡，常态显示基础空手攻击力修正，爆发展示完整空手修正及刀锋利度抵扣；重复触发沿用原事件刷新，到期恢复原效果。没有新增 UI 计时器，也没有改变原事件、替换 ID、装备数值或卸载链。

统合61式后续采用两个真正持有属性Pod的MetaBuff，分别显示「全装助力」「缓冲护盾」。轻盾的激活信息只读该套自身状态，破盾后及时撤掉抗性Pod并更新详情，HUD查询不推进护盾或整备时钟。冷绑定与新增事件都只投影MetaBuff，避免独立Pod在热添加时偶发显示为匿名状态、冷绑定后又消失。规则和专项证据见[统合61式设计与实现](统合61式装甲套装-设计与实现-2026-10-25.md)。

本轮不补全其他 Buff 的图标、名称、描述或特殊机制，也不建立自动中文条件解释器；这些工作留给后续内容专项。普通缺详情 Buff 继续使用上述中性回退。
