# CF6 老头与老头机器人装配

本目录维护人形 R7、机器人 R7 和角色局部变形的确定性 XFL 装配。用户指定人形为阶段 8／档次系数 9，机器人为阶段 8／档次系数 20；默认先人形、再生成机器人，目标是对方舟兽王及 EXUSIAI 指挥官造成明显威胁但最终落败。工作区改动暂缓提交，等待用户验收。

## 真源与入口

- 唯一编辑工程：`flashswf/arts/new/Codex老头素材/Codex老头素材.xfl`，由本目录生成器装配并交给真实 CS6 发布。
- 原稿：`flashswf/arts/new/Codex素材源稿/CF6老头人形-R7`、`CF6老头机器人-R7`、`CF6老头变形-R2`。每份 `archive-origin.json` 绑定收到的原始 ZIP 和保留文件；包内 Python 只作历史来源，不执行。
- 人形注册：兵种 471，`敌人-CF6老头人形`，默认 50 级、身高 180。
- 机器人注册：兵种 472，`敌人-CF6老头机器人`，默认 50 级、身高 190。
- 两者从同一 `Codex老头素材` 共享锚点经 `things-new.fla` 第 4 帧装载；锚点显式包含两种形态。Include 的 itemID 必须等于对应 DOMSymbolItem 的实际 itemID。

## 动作与适配

| 形态 | 原动作 | 帧数 | 伤害触发帧 | CF7 行为 |
|---|---|---:|---|---|
| 人形 | 970 连射 | 53 | 13、21、29、37 | 四发普通子弹，每发空手攻击力 ×1 |
| 人形 | 972 刺击 | 34 | 7 | 物理近战 ×1，随后有界推进 |
| 机器人 | 994 光束 | 64 | 29 | 波属性魔法 ×1，沿实际光束区域 |
| 机器人 | 997 连踢 | 40 | 9、26 | 两次物理近战 ×1，保留两次推进段 |
| 机器人 | 1007 砸击 | 62 | 37 | 物理近战 ×1，较大的接触区域 |

人形使用原 12／13 帧受击分支和 89 帧倒地恢复；独立人形死亡在原停止帧 31 注销。机器人使用 12／13 帧受击分支、不浮空；按当前大于 9 帧的观测规则属于长受击，结合韧性 40，霸体系数为 3.2。111 帧死亡演出由身体内部时钟完成。暂停、硬直和旧动作 token 不允许新增攻击。近战区域子弹、普通子弹、冲击和伤害结算均走现有 CF7 入口，没有直接扣目标 HP。

机器人在各招式接触前暂时持有刚体，光束另在蓄能到第 29 帧持有抗击退；两项分别保存和恢复原值，不减少伤害。光束前 22 帧可转向同一实例并每帧至多移动 3 像素对齐纵深，第 23–29 帧锁定；硬直、暂停、目标替换或旧身体不允许继续跟踪。踢击与砸击不获得光束的抗击退。光束第 30 帧释放这两项状态；各招式收招、中断或死亡也会释放仍持有的状态。

身体使用收到的最新版矢量稿。共用刺刀 484 在原包仍为位图，本目录的 `bayonet.svg` 保留其原轮廓与配准，明确改为原生矢量；金色仍由原时间轴颜色变换产生。原位图枪口与机器人爆炸改用已装载的 CF7 枪火／火花／小烟雾，不把参考位图带入运行库。

两种形态各自持有独立地面阴影。身体、阶段过渡与阴影都跟随世界 Z；变形开始时清零真实被击移动所用的 `speed`，避免人形在过渡中继续滑行。机器人落地约束与阴影不会写入其他单位的同名公共阴影槽。

## 连续两阶段

人形默认 `老头变身=true`；显式 `false`、`0`、`"false"`、`"0"` 使用独立人形。非法值明确诊断并关闭变身。关卡人数留给机器人阶段结算，人形不重复掉钱；经验沿用标准死亡检测。

变形采用原 2008 的前 93 帧角色部分，换入当前两份 R7 分件，保留身体替换顺序和过渡碎片。原 94–283 帧全屏放大、主角立绘、场景跳转和音乐控制保存在原稿中，不执行为战斗单位脚本。这里不是完整剧情过场的接入声明。

第 93 帧只尝试生成一次机器人。继承位置、方向、等级、阵营和产生源；不继承旧 HP、MP、面板或 Buff。普通对象 token 绑定世界、父实例、身体和新实例，初始化版本及上下文一致后才显示后继、退出前阶段。返回为空、名称碰撞、身份丢失、上下文不一致或初始化超时均进入明确错误状态，不自动重放生成。

## 原生验证与历史失败

当前 R12 发布资源为 **356,928 字节、53 个 Shape、28 个 Sprite、0 位图**，XFL 共 82 个元件。真实 CS6 发布和专项测试都要求当轮 Compiler 0/0。R12 行为测试为 **680 passed / 0 failed**，包含 34 组实际时间轴动作、13 组阶段场景，以及共用被击移动、变形接地、追踪与状态恢复。

R12 把机器人连踢起手距离从 150 调到 190 像素；两段推进、两次接触区域与伤害倍率未改。真实发布资源的测试验证了左右朝向从 190 像素起手后均能在原第 9／26 帧接触目标，推进不越过 90 像素停止距离。

完整原生绘制在 R6 覆盖 715 个原动作／过渡帧和 3 个镜像关键帧，共 **718 点、1439 passed / 0 failed**，另导出并逐张检查了 19 张原生画面。R7 只更新行为脚本；85 个原生 XML 去除 ActionScript 后逐项相同，并重新通过 6 点绘制探针（16 passed / 0 failed）。R12 的 85 个 XML 再次与 R7 去除脚本后相同，并通过新一轮 6 点绘制探针（16 passed / 0 failed）。这些证据明确分层，不把旧图像写成新版本重新截图。R6 固定比例 `BitmapData.draw` 夹具的重复绘制中位数 14 ms、P95 20 ms、最大 25 ms，仅作素材夹具记录，不代表全游戏帧耗或弱机资格。

旧 R2 虽通过 445 项行为断言，随后完整绘制暴露机器人身体未进入 SWF；该版和没有进入有效战斗的 `bridge_lost` 尝试均保留。后续还有完整绘制／截图恢复、旧数值下的超时、低威胁试跑，以及两次测试自身时序／括号错误；最终证据包保留对应失败源码、编译信息、原始 trace、产物与恢复记录，不只保留成功结果。

每个形态结束时的 `CF6_ELDER_COMBAT_END` 仅记录出招和发出接触判定的次数，不能当成实际命中或累计伤害。后继的 `CF6_ELDER_PHASE_READY` 则记录真实初始化的等级、血量和攻防，用于核对两阶段没有继承旧面板。

## 数值校准口径

当前候选为 R13：行为与发布 SWF 沿用 R12，配表为 R13。阶段／档次保持用户指定的 **人形 8／9、机器人 8／20**；攻速、伤害倍率、段数、霸体系数来自上述动作和受击观测，未用面板反推替换观测。完整公式输入与输出见 [balance-inputs.json](balance-inputs.json)，由 [balance.py](balance.py) 生成。

自由分配采用人形成长 1、高攻低血防 2、高防低血 4；机器人成长 1.0、高攻低血防 2、高防低血 28。机器人成长 1.0 用于补足高等级压力，30 级面板几乎不变；高防低血分配用于延长物理交战并减少可被兽王吸血回补的生命总量。高防低血 28 超出公式工具的参考区间 0.1–10，是本候选明确保留给人工复核的分配选择；没有修改公式、参考区间、对手或伤害结算。
