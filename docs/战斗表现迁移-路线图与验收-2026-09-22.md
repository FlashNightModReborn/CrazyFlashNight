**文档角色**：战斗表现原生迁移的唯一批次、issue 指针与阶段结果汇总；长期规则归[迁移契约](../agentsDoc/combat-presentation-migration.md)。<br>
**最后核对代码基线**：commit `e50e818d81`（2026-09-24；天气代码为本地候选）。<br>
**当前状态**：规划与看板建账完成；BP8 天气本地候选正在验证，其他原生战斗表现尚未接管。常驻 [Epic #109](https://github.com/FlashNightModReborn/CrazyFlashNight/issues/109)；待办卡保持开放、可见。<br>
**授权边界**：原始建账授权仅含文档提交推送与 Epic/issue；2026-09-24 用户另授权 BP8 天气源码施工和开发候选验证，并接受起床后继续视觉迭代。该授权不包含自动提交推送、真实存档试写或正式 runtime 发布。

## 1. 已对齐的方向

- 优先原生接管联弹、常用简单子弹与适合的战斗效果；C# 负责管理，原生合成器承接绘制。第二 Flash/OCX 进程不作为默认前置；只有出现有实测价值的兼容性阻塞才另行评估。
- 保留 Flash 编辑真源，按素材导出中间形式；AS2 保留战斗权威，普通子弹对象化不继承联弹伤害语义。
- 小型子弹允许提到人物上方。大型爆炸/浓烟、需要人物前后关系的视觉首批保留 AS2；不等待天空/地图拆层或播放器透明输出。
- 使用具体素材/行为/层级白名单，混合架构可以长期存在；不一次性搬全部素材，也不要求先实现完整时间轴解释器。
- 射线、几何残影、简单打击与天气粒子共用空间/时间/缓存/批量绘制能力，各自保留适配器和预算。人物主体与游戏模拟不纳入本阶段。
- 收益是待测假设；以减少主 Flash 峰值的净效果决定扩张，不用迁移数量或显示成功代签性能收益。

## 3. 与在途统一合成施工的关系

统一合成和输入归属由[现有施工计划](统一合成与输入归属-分阶段施工计划-2026-09-22.md)及其当前施工方维护。本轮不改那份计划或其 Host/native 源文件，不复制当时工作区验证数字作为本项目的前置完成证据。

首次接入需消费的能力：世界表现提交位置、相机/几何代次、捕获延迟的处理约定、暂停/场景清理、设备生命周期、面板/HUD 遮盖及调色顺序。这是后续消费者需求，不要求当前施工方无条件预建通用场景图。

BP8 首批按 2026-09-24 用户确认的独立视觉目标施工：天气不要求原 AS2 粒子轨迹或捕获帧精确对齐，也不以旧版受限密度为美术验收上限。AS2 发天气状态，C# 管视觉所有权，原生 GPU 在同一合成输出绘制。随后单独接入氛围叠加，所有命名预设和直接 `<Overlay>` 由原生合成，AS2 不再绘制氛围回退；天空仍在 AS2。该简化不替代面板遮盖、场景清理和弱机实测。

GitHub #83 是旧渲染架构裁决候选，#103 是现场输入长期契约，均不能直接冒认为本次统一合成施工卡。当前专项尚无核实的一一对应卡时，使用上述仓内计划作为外部前置；未来有准确卡号再建立 native blocked-by，不为满足格式制造重复施工卡。

## 8. BP8 天气本地候选（2026-09-25）

用户授权本地施工，并接受以新视觉目标替代旧 AS2 粒子逐帧等价。AS2 天气规则与旧 Host 回退保留；Host 确认实际原生画面就绪后，每连接代切换显示端。原生合成器同帧绘制雨、雪、沙尘、雾和刀痕；氛围叠加、天空及天气玩法未迁移。

本地证据：新鲜 asLoader CS6 Compiler `0/0` 与 SWF 刷新，WorldLightingBridge focused `17/17`，协议延迟专项 14 组无失败；独立 GPU 夹具五种类型均执行，雨/雪/雾有实际截图，包含雨粒子的自动调色与视口矩阵通过。初版配对游戏开发候选已构建并核对 manifest 哈希；这些只覆盖 `compiled`、`candidate_built` 与隔离夹具的 `candidate_executed`，不代签游戏内观感。

2026-09-25 维护者运行初版配对开发候选后，反馈进入预期有天气的关卡仍看不到粒子。新鲜 `logs/launcher.log` 中雪地 `snow/0.7` 与刀痕 `slash/0.6` 均为 `weatherNative=true`，证明 AS2 已交出显示权；但 07:18:46 窗口移动后，Flash 客户区比 WGC 捕获底边多 1 像素，合成器持续报告 `source_outside_capture`，本次运行没有任何 `world_lighting_frame_handoff`，原生天气因捕获栅栏未通过而保持关闭。这是一次真实候选执行失败，不能记为天气 `e2e_verified`。Host 已改为只容忍各边最多 2 像素的已测量交集，超出仍拒绝，并增加原生天气状态日志；以这次实测坐标写入回归，全量 Launcher `5832 通过 / 4 跳过`。新隔离候选 `weather-geofix-0925` 的完整性校验通过，未启动游戏、未修改正式 runtime。下一步用新候选复查雪地与刀痕画面、窗口移动、面板遮盖、夜间观感和弱机成本；#118 保持开放。

同日上午的新候选实跑与截图指出第二轮观感问题：雪花在白色雪地上缺少对比，室内刀痕受 AS2 性能档位 `3` 清零且本身偏细，原生尺寸未跟随游戏镜头缩放，雨的落地弧线尚未迁移。后续源码改为：雪花浅色中心加冷灰轮廓，刀光增加长度/可读性；Host 从现有逐帧 F 包读取镜头比例，原生粒子按 1024×576 设计空间与镜头比例定尺寸；AS2 旧质量档只约束 AS2 回退，Host 对原生绘制使用固定有界预算；雨花在同一批次中按旧 AS2 的 Ymin/Ymax 纵深地面带绘制，不声称逐物体真实碰撞。AS2 focused 18/18 与 fresh CS6 asLoader Compiler 0/0、Host 全量 5832/4、原生 HLSL VS/PS 严格编译及雪/雨/刀光隔离 GPU 预览已通过；自动合成报告通过 3 次像素证明且最大误差 0。新配对候选 `weather-visual-0925` 已构建并通过完整性核验，原生 DLL 与 GPU 预览 SHA-256 一致；正式 runtime 未改。游戏内雪山、翅虎堂和雨花的观感、遮挡及性能仍待新候选复查，#118 保持开放。

用户继续指出尺寸虽已随镜头变化，刀光位置仍固定于屏幕，要求全部原生粒子跟随世界画面的平移与缩放。前版确实只用了 F 包的 `scale`，没有把 `x/y` 用于粒子位置。原生着色器现改为稳定世界锚点经 `stage = cameraOffset + world * cameraScale` 投影；雨、雪、沙尘、雾、刀光及雨花均使用这条路径，长地图的周期边缘回绕对大雾团与刀光淡出。场景中实际使用的 8 处 `<Preset>` 只有 `毒气/腐蚀/寒铁` 会展开粒子；`警报/医疗警报/工业警报` 只展开 AS2 氛围叠层，仍按此前范围暂留 AS2。雨雪沙尘也可由 `WeatherCondition` 直接触发。五种类型的移动镜头隔离 GPU 夹具均执行成功；带平移的刀光自动合成报告通过 3 次像素证明且最大误差 0。新配对开发候选 `weather-world-0925` 已构建、完整性核验通过，原生 DLL 与夹具 SHA-256 一致；正式 runtime 未改。游戏内镜头运移、缩放、遮挡及性能仍待该候选的人验，不能用静态预设清单或隔离夹具代签真实观感。

## 9. 氛围叠加本地候选（2026-09-25）

维护者明确要求把氛围预设全部迁移，且不保留 AS2 回退；天空盒仍是独立范围。`EnvironmentConfig` 保留场景预设和直接 `<Overlay>` 的解析，`GameWorldOverlayRenderer` 只投影封闭状态；`WorldLightingBridge` 将其并入现有 `world_lighting` 场景快照。Host 对 10 种命名氛围预设和直接叠加项映射原生编号，按场景就绪与捕获栅栏清理/启用。原生合成器在调色主 pass 内绘制低强度、可区分的灯光、雾色和扫光；后续天气粒子仍在主 pass 后绘制。直接叠加项保留色值、径向模式和脉冲参数。命名预设以新视觉目标重做，不要求旧 AS2 像素等价。

本轮专项证据：AS2 focused `23/23`，fresh CS6 asLoader publish Compiler `0/0` 且 SWF 刷新；严格类归属审计 main `0`、asLoader `668`、交集 `0`。Host 全量 `5844 通过 / 4 跳过`。HLSL `ps_4_0 /WX` 通过；11 个氛围编号均在隔离 GPU 夹具成功出帧并留截图，医疗警报的自动合成夹具 3 次像素校验最大误差 `0`，寒铁镜头平移/缩放参数经夹具接受。这些是源码、编译和隔离呈现证据，仍未代签实际游戏场景的遮挡、可读性、转场和性能。
