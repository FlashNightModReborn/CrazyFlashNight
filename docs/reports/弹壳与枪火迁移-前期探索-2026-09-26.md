## 1. 已讨论的方向与尚未裁定的选项

本轮讨论已支持以下方向，具体 wire schema 与首批视觉验收仍由后续消费者确定：

- AS2 决定实际发射；原生承担弹壳纯视觉运动，最终静止后批量回传姿态，AS2 帧尾限额写入既有地面位图。
- 弹壳按素材按需创建临时单元体，烘焙共享 BitmapData 后移除临时 MovieClip；缓存可跨场景，队列与地面实例随场景清理。
- 枪火变体在创建时从有限预设中选定，动画与光源共享结果；新增表现不执行通用 ActionScript 解释器。
- 视觉随机流与战斗随机流解耦，接受隔离后建立新的随机基线；不为了维持旧消费序列而继续空耗战斗随机数。
- 点光源是后续扩展，首版枪火动画与局部照明分开验证。

以下为**建议默认值，不是已获维护者确认的产品结论**；均不阻塞当前静态探索：

| 剩余选项 | 建议默认值 | 改选会增加的范围 |
|---|---|---|
| 落地印章是否必须逐枚保留 | 有界装饰；超预算可抽样或丢弃，限制每帧写入及局部累计密度 | 全量保证需要更长排队、交接保留和积压处理 |
| 空中弹壳/枪火的遮挡要求 | 白名单小素材可以提到捕获画面上方，面板开启时遵守既有抑制规则 | 必须穿插人物/掩体前后时，需要额外遮挡数据或拆层 |
| 弹壳的地面与出膛高度 | AS2 提供明确地面参数；首版保持现有落地语义，轨迹参数可改善 | 改为真实场景碰撞、台阶或更真实的枪口高度属于另一项表现设计 |
| 首批枪火范围 | 从一个常用短动画开始，保持原稿；旧通用枪火另做变体适配 | 同时翻新全部枪火或加入新随机风格会扩大美术验收 |
| 第一版局部光的目标 | 无阴影的二维局部照明，光源与天气共用坐标和受控强度 | 真实遮光、法线受光与投影需要新数据 |

离线资料与代表探针已经具备。后续共享代码接入以当前发布批次交出的稳定接口和写入窗口为准，不重复建设已完成的子弹显示底座。

## 2. 弹壳资源盘点

扫描范围为 [原版素材库-子弹的弹壳目录](../../flashswf/arts/原版素材库-子弹/LIBRARY/弹壳)；
不是所有历史素材库或运行时可达 linkage 的全集。

本次解析到 **18 个导出 linkage**：全部为单帧、无脚本、无嵌套元件引用；
未检出滤镜、渐变、位图填充、补间或遮罩。适合按种类缓存静态印章。
完整名称与逐文件 SHA-256 在调查快照中，不在长期契约维护另一套名单。

首次盘点 [bullets_cases.xml](../../data/items/bullets_cases.xml) 时有 13 个不同 casing 名称，`加强步枪弹壳` 未解析。
后续已核实素材与 AS 链接均存在，正确名称为 `加强弹壳`；工作区与已提交库 SWF 的导出表也支持该名称。
修复 `8554961ff589caa0a737b2fb375567866be7d005` 已单独提交推送，纵向联弹加强材质映射改为 `加强弹壳`。
修复后有 **12 个不同 casing 引用，全部能在 XFL 与已提交库 SWF 导出表中解析**；该疑点已关闭，无需重画或新增 linkage。
[ShellLoader](../../scripts/类定义/org/flashNight/arki/bullet/BulletComponent/Loader/ShellLoader.as)仍直接传递 casing 名称，运行实例重启后读取新配置；本任务未做游戏内复验。
原始 JSON 中的 13 名称和缺项保留为修复前快照，不手改历史证据冒充新扫描结果。

当前 [ShellSystem](../../scripts/类定义/org/flashNight/arki/bullet/BulletComponent/Shell/ShellSystem.as)有三个需要带入新合同的行为：
地面线为出膛位置的 y + 100；首次触地播放一次声音；弹跳/滚动结束后才调用 add2map3。
纵向联弹、纵向机枪联弹、纵向手枪联弹的模板采用“原版”模拟，其他标准模式已有弹跳和滚动。

印章实现应直接接受缓存 BitmapData 和完整矩阵，队列保存不可变姿态值。
[CorpseStampSystem](../../scripts/类定义/org/flashNight/arki/corpse/CorpseStampSystem.as)目前只有复用画刷，没有队列、预算或场景去重。
[DeathEffectRenderer](../../scripts/类定义/org/flashNight/arki/corpse/DeathEffectRenderer.as)含尸体压暗和仅保留缩放符号的矩阵逻辑，不能直接当作新弹壳的完整姿态合同。

AS2 draw 支持 BitmapData 直接作源；帧尾合批指统一限额调度多次 draw，不代表一次 GPU draw。
参见 [Adobe AS2 语言参考镜像](https://open-flash.github.io/mirrors/as2-language-reference/flash/display/BitmapData.html)。
缓存保留原色，按显示端共同确定调色、透明边缘、注册点与采样约定；不把某次昼夜调色烘入跨场景印章。

以下差异决定如何复用，不能仅把现有子弹类型改名后用于弹壳：

- **快照与事件**：现有 F 包第 5 节是完整位置快照，新增了显示所有权字段；一次发射/落稳事件不能直接套用“新快照覆盖旧快照”的丢弃语义。复用通道和身份规则，分别确定事件保留、抽样与拒绝。
- **生命周期**：[BulletVisualProbe](../../scripts/类定义/org/flashNight/arki/render/BulletVisualProbe.as)依赖仍存活的 AS2 对象；联弹的[渲染组](../../scripts/逻辑/战斗系统/战斗系统_fs_联弹管理.as)仍每帧写 MC 的 x/y。弹壳方案保持“只发初态、原生独立推进、AS2 无逐粒子活动 MC”的目标，不能照搬这条热路径。
- **容量与优先级**：256 是普通弹加联弹单元体的绘制条目上限，Host 子弹节另限 65,536 字符，样式上限为 16。弹壳与枪火应有独立装饰预算，不能挤占此配额导致真实弹体回交或不可见，也不把 256 自动当作所有粒子的全局上限。
- **故障回交**：现有子弹可恢复隐藏 MC 的 alpha/visible，超限联弹整组回交；弹壳原生自主运动后，AS2 没有逐帧当前姿态，不能直接“取消隐藏”恢复。建议装饰效果采用有界清退/淡出；若要求无缝恢复，需另做姿态回传与所有权交接。致命合成器故障沿用当前会话结束策略，不新增裸 Flash 续玩要求。
- **暂停**：子弹沿用 AS2 位置快照，暂停时位置不再推进；自主运动的弹壳与短动画还要显式消费游戏时钟。现有子弹暂停人验不能直接证明新粒子时钟正确。
- **层级、调色与光照**：当前子弹 pass 位于天气/氛围之后，沿用世界矩阵或 LUT。弹壳是否受雾遮盖、枪火自发光及局部照明要分别指定；新增柔光只绘制弹体周边图元，没有形成照亮场景/天气的局部光场。

仍不冻结 ABI 6、section 编号或统一“大粒子协议”。Compositor、Host 会话/控制器、F 包入口和资源闭包属于当前列车共享输入，本轮只读。

**发现的说明漂移**：[data/combat_visuals/README.md](../../data/combat_visuals/README.md)仍称“仅影子采样、数据不进入原生画面”，且其包头例子缺少所有权字段；BulletVisualProbe 与 BulletVisualFrame 的开头注释也仍沿用影子阶段描述。
应以实际 native/shadow 分支、解析器与新版长期契约为准。这是说明与源码的冲突，不是本次已复现的运行错误；适合在列车收口时修正文档/注释，不在冻结期间修改其发布输入。

## 6. 后续最小施工包与停止点

1. 以已提交 ABI 5 与本轮发布的最终身份为接续基线；复用已完成的世界输出、镜头、能力协商和清理入口，仅重新核对正式交付状态，不把它们重复列成从零施工。
2. 选步枪弹壳和突击步枪枪火作代表，完成紧致裁切/注册点、纹理缓存和带纹理四边形绘制。
   不先铺满全部 18 种弹壳或 18 个配置效果名。
3. 弹壳增加纯视觉运动、落稳批回传与 AS2 印章队列。
   首次触地音效沿用音频通路并有独立预算；最终静止才写地面。
   地面回执不等于对应 Flash 帧已被捕获，设计有界末态保留/淡出并验证双画与空档。
4. 枪火增加短寿命帧序列和视觉变体选择器，再单独增加二维局部光。
   两者共享事件身份和世界坐标，但分别验收动画与照明。
5. 随机隔离先查消费者边界。当前 EffectSystem、BloodBarEffectHandler 仍直接用共享引擎，
   玩法的 MultiShotDamageHandle、DodgeHandler 等也用同一个单例；
   只移走弹壳和一款枪火不能宣称全游戏画质已与战斗随机完全解耦。
   新视觉使用稳定事件身份派生种子，不从战斗引擎逐发抽种子，也不按“实际显示数量”生成事件编号。

人工主要判断提层遮挡、轨迹、落地接缝、枪口同步和夜间观感。
机器验证场景/连接切换、暂停、重复与迟到事件、预算耗尽、资源缺失及玩法随机消费边界。
净成本比较分“同表现同数量”和“改善表现后总成本”，不从素材声明次数或静态导出推导 FPS 增益。

达到“代表素材已定位、适配入口已定位、复用缺口明确、关键反例列出”后，当前前期探索即可停止。
剩余纹理像素、实际时序和净收益需要运行候选；继续扩写协议或全量美术导出不会替代这些证据。

### 7.1 最终实现

- [CombatFxBridge](../../scripts/类定义/org/flashNight/arki/render/CombatFxBridge.as)只发送出生事件、游戏 tick 和贴图回执。原生接管时不创建活动弹壳/枪火 MC，弹壳旧池改为实际回退时按需创建。
- [CombatFxEngine](../../launcher/src/Guardian/WorldCompositor/CombatFxEngine.cs)负责抛射、重力、弹跳、滚动、首次触地音效和最终落稳。纵向联弹的装饰弹壳也使用标准轨迹；玩法子弹仍为 AS2 权威。容量、单次展开和落稳回包均有独立上限。
- [DecalStampQueue](../../scripts/类定义/org/flashNight/arki/render/DecalStampQueue.as)在首次需要时烘焙一份小位图并移除临时源 MC；按完整世界位姿、旋转/镜像和背景层原点，帧尾限额写入现有 layers[2]。场景内队列/密度/总量有界，素材缓存跨场景保留。
- 枪火由原 SWF 定向导出，保留帧序列与注册点。通用枪火随机脚本变成创建时选预设；a0/a2 的空画面与 Y=0 移除按源保留。扩展预设使用同一 variants 消费者，新增源脚本仍需明确适配。
- `VisualRandom` 隔离 ShellSystem 与 EffectSystem 的视觉随机消费；C# 从事件种子派生轨迹/变体。其余历史视觉消费者未全面审计，不能声称全游戏画质已与战斗随机完全解耦。
- ABI 6 纹理 pass 顺序为弹壳、现有原生子弹、枪火，整体低于 HUD/功能面板。弹壳参与世界调色，枪火保持自发光；当前没有环境点光源。

图集 66 帧、2048×1072、PNG 364,293 字节；单份 BGRA 纹理为 8.375 MiB。Host 缓存、native 上传副本和 GPU 纹理分别占用内存。AS2 仅持小型落地印章缓存；尚未测量整进程内存相对旧池的净变化，也不以 PNG 大小代替显存。

## 9. 枪火点光源可见度修正（2026-09-27）

用户截图显示极暗商店中枪火精灵明亮，但周围照明难以辨认。保留原图和当次日志于
`tmp/combat-fx-lights-validation/user-light-too-dim.png` 与 `tmp/combat-fx-lightfix-validation/user-session-original-light.log`。
日志同时包含普通光照 L0、L5 和高级夜视仪切换，且有枪火存活而灯已结束的抽样；没有用最后一条 L5 状态代签截图精确时刻。

修正两个呈现问题：原来的 2–3 tick 二次衰减过快；普通光照 LUT 的暗蓝色又被用于压低直接光。
当前从中性源纹理做有界曝光响应，枪火暖色不再继承普通光照 LUT 的环境暗蓝；夜视的矩阵色向仍保留。
峰值保持两帧再线性衰减，10 种预设为 4–6 tick，半径 118–205，能量 1.3–2，叠加响应封顶 0.78。
纯黑源不凭空发光，半径外像素保持，玩法逻辑、AS2 事件/编译产物和迁移名单均未在这次反馈修正中改变。

GPU 回归改用生产 `hardlight-dusk-v4` 的 L0/L5 和真实通用枪火参数，另按矩阵路径验证夜视。
在同一蓝灰源材质、同一修订参数下，旧 shader 的 L0 中心 RGB 为 `[15,42,53]`，新 shader 为 `[77,79,77]`；

暖色贡献按源材质分通道比较，不要求所有材质都变成同一橙色光球。

这是受控源经真实 WGC/D3D11 合成后的像素验证；最终游戏内可读性仍需维护者复看修正候选的光照。
