# 火凤 AS2 多阶段与转场动画

本批只接入 AS2 生命周期和原稿演出，外部渲染、烘焙优化及新增光照后置。
原有战斗 AI、普通招式、属性成长和最终死亡结算继续复用公共实现。

## 行为与归属

`PhoenixPhaseController.as` 由 asLoader 提供，火凤本体在公共初始化完成后调用
`_root.火凤阶段初始化(this)`；资源 SWF 不嵌入控制器类。
火凤自己的初始化入口显式传递 `this.等级`，仍使用原怪物 XML 与公共成长公式。
控制器同时以单位自己的方向、身高倍率和状态完成初始化，避免旧帧函数中的
未限定 `myxscale`／`状态` 读入根节点或其他角色的值。只在火凤本地修正，公共 AI 不变。

- 普通火凤从一阶段开始；生命打空进入下一阶段，不再使用 1500 血提前触发。
- 非最终阶段的致死写入在 HP accessor 内截住，公共 HP 暂存为 1；重复致死、治疗和
  状态切换不能跳过转场，不提前发布公共击杀、死亡、奖励或清场。
- 第一转场固定地面，等待新倒地元件加载后播放其 1–30 帧（完整倒下、躺地；
  31–66 帧属于旧起身，交由新演出替换），再播放原稿 1–80 帧；35 帧产生一次局部爆气。
- 第二转场固定原 X／地面纵深，接管并撤销旧浮空任务；播放原稿 82–182 帧，159 帧原地砸地。
  82–93 帧先稳定原高度并蓄焰，94–121 帧以起止速度均为零的曲线托升，
  到原示意舞台的 208.95 像素高度；122–150 帧滞空，151–159 帧落回原地。
  已有更高高度的空中触发保持该高度，不强行降低。
  只改变演出纵向高度，空中段不显示影子；不追踪目标。
- 普通攻击在转场内停下；演出与控制器共用游戏帧推进，读取既有暂停状态。
- 二阶段保留攻击乘 0.7、行走速度乘 1.5；其余速度沿现有派生关系。
  第三阶段保留 1500 最大生命及原余烬表现，不新增永久霸体。
- 涅槃重生仍先应用既有伙伴进阶，再从二阶段起步，保留回血和抗击倒分支；
  只有一次通向最终阶段的转场，使用同一个控制器。NPC 不安装控制器。

判定由现有子弹属性、BulletFactory 和碰撞／伤害链承接，不由特效面积决定。
初版爆气／砸地局部半宽为 75／90，纵深范围 30，伤害取当前攻击的 0.02／2 倍
（至少 1 点输入威力）；冲击除数 1／0.25，水平击退 8／20。爆气伤害刻意很低，
用于验证真实管线；最终实伤仍受常规抗性等规则影响，不保证每个对象固定掉 1 血。

## 唯一美术源与装配

画师原始交付完整保留在
`flashswf/arts/new/Codex素材源稿/火凤转阶段/火凤转阶段.rar`，SHA-256：
`d4496e35cb3c1a74498cb67a66059bd58e9cca722605de860886fb6df4746434`。
修改美术应更新该交付中的 XFL，经审查更新来源身份，再重跑装配；不手改派生库副本。

`build.py` 只装配 `转阶段动画` 的可达闭包到现有 `Codex专用素材.xfl` 的
`Codex/火凤转阶段/` 命名空间，复用已有 things-new 共享库挂载。
保留原 Matrix、帧时长、滤镜、混合和分层；删除未参与运行渲染的新版 rig 作者缓存，
移除原稿的方向／音效／自删除脚本，由控制器持有演出生命周期和攻击事件。
包装元件统一采用原角色倒地元件的注册位移 `(409.1, 177.8)`，不以会变形的影子中心
重新定位人物。原倒地第 30 帧与新起身首帧的人体件相差约 0.1–0.3 像素，直接接续。
演出结束先切回站立，下一帧确认新 `man` 已加载再恢复其可见性与控制权，避免读到旧动作。
原始 DOMDocument 在第 82 帧把舞台实例从 `ty=669.5` 改为 `460.55`，第 159 帧回到
`669.5`。该父级位移由 AS2 同一帧时钟接管：先约 0.4 秒蓄焰，再约 0.9 秒缓慢托升；
不使用起步最快的抛升曲线。原稿的余烬火焰经装配为现有演出元件的私有 `charge` 子层，
82–117 帧逐渐增强并随人物上升，118–127 帧退去。子层所有火焰均为 Graphic，逐帧同步，
不新增发射器、攻击判定或独立计时器，也不增加运行时 linkage／来源映射。人物原动画不重做。
地面与空中触发均以当前高度开始，最后砸回同一地面锚点。

## 验证入口

```powershell
powershell -File scripts/run-phoenix-phase-tests.ps1
powershell -File scripts/run-phoenix-phase-tests.ps1 -Capture
powershell -File scripts/run-phoenix-phase-tests.ps1 -CaptureLift
python -X utf8 tools/phoenix-phase-assets/verify.py
```

专用宿主导入真实火凤、转场资源与公共名字血条；真实 XML 初始化、致死处理器和
转场攻击的生产碰撞／伤害结算均保留。奖励仅用观察替身计数，不读取或改写玩家存档。
截图使用真实 Flash BitmapData 无损记录，不把静态导出当成实际运行。
`-CaptureLift` 只采样 82–136 帧的升空段，每两帧采一张 180×240 的真实演出画面，
避免连续高分辨率滤镜采样耗尽 CS6 进程内存。`-Capture` 是较重的完整关键帧采样，
不与升空段采样叠用。内存不足或采样未闭合时保留失败记录；保存编辑文档并正常重启
CS6 后，先按测试播放器控制与未知状态恢复协议核对，再续跑，不能删闸绕过。
功能 fixture 隐藏舞台容器以避免连续渲染干扰行为验证，指定帧仍单独渲染真实矢量与滤镜；
因此此测试不证明实际战斗帧率。蓄焰先于离地、上升首尾速度、火焰逐帧与两处暂停同步均有专项断言。
左右追击、纵深移动和攻击由真实 `CombatModule` 与原移动、
状态、动画完成函数执行，覆盖普通三个阶段及涅槃起始阶段，并以根节点异号倍率排除串用。
`verify.py --trace <本轮完整日志> --report <输出 JSON>` 绑定完整唯一 runId、零失败、
原始归档、装配清单、控制器和三个本地构建 SWF 的 SHA-256。
测试宿主自己编入控制器并导入真实资源，asLoader 另做生产提供者编译；不将构建升级为标准入口执行。

按归属分别用真实 CS6 编译 Codex 专用素材、things5 和 asLoader；前两项 publish
只证明本轮资源构建，focused runner 的唯一完整 runId 和零失败断言才证明专项行为。
游戏内观感、完整战斗性能和标准入口验收需另行记录，源码／编译／fixture 不互相代签。
