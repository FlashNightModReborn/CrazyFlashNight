## 1. 案件概述

玩家主存档 `crazyflasher7_saves` 自 **2026-09-11 00:25:31** 起每次 `SharedObject.flush()` 均返回 boolean `false`，sol 与 JSON shadow 双双冻结（金钱 2,025,211 / 等级 41 三源一致）。ProcMon 捕获（**当前为字符串级证据**，事件级结构化验证进行中，见 §3 边界与 §6）显示：**8 次 flush=false 的窗口内未见任何 sol 相关文件系统活动**——指向否决发生在 Flash 进程内、文件操作之前。在该证据强度下，文件系统层（ACL/杀软文件拦截/共享冲突/磁盘满/配额文件）**仅对这几次调用**排除；**不排除更早的初始化失败沿用，也不排除文件系统调用之前的用户态拒绝**。根因未锁定。

次生损害：fail-fast 设计下 dirtyMark 永真 → 事件驱动存档全部转为真实全量存盘；关机栅栏拦截退出（玩家杀进程逃生）；reveal 期 launcher UI 线程两次停滞（一次至进程被杀、一次约 24s 后自愈，具体等待关系未确定，见 §3）；多实例残留导致 BGM 叠播。

**代码机制事实（均已核源码）**
- 加载走 launcher 快照注入，protocol 2 快路径不触碰原生 SO（`SaveManager.as:1398-1416, 1440-1442`）——"加载成功"不证明原生存储后端已初始化。
- flush 唯一提交点 `flushSO`（:3487-3522）；shadow 门控 `if(ok && socket)`（:1285）——flush 失败时 shadow 不同步，**shadow 不是独立故障备份**。
- dirtyMark 仅成功分支清除（:1249-1255）→ 事件驱动挂钩（切场景/淡出/约 13 处 UI 关闭）全部真存盘；重试按钮链零节流；关窗 fence 首次触发恢复事务、fatal_blocked 后直接失败（`DetachRecovery.cs:283-293`）；toast 无去重。

- 装配面板绑定存在且 flush_failed 时 fence 拦退（`DetachRecovery.cs:306-316`）；无绑定直接放行（:264-268）。

## 4. 已排除（含裁决校正后的精确边界）

- 存档内容（仅磁盘样本级；当前内存载荷≠旧样本）。
- 配额：**仅排除"允许存储但需交互扩容"分支**（该分支语义为返回 `"pending"`，与日志 boolean `false` 不符）；**不排除**"持续拒绝/全局拒绝/其他不可保存"分支（可直接 `false`）。截图旧用量（716KB/1MB）不代表本轮完整载荷大小。
- 只读属性（归档属性≠现场 ACL/共享模式/安全策略）、文件截断（长度自洽+格式走通）、非法存档名（字节级干净）、测试覆盖钩子（生产无调用方）、mms.cfg（两目录均无）。
- 版本全局缺陷：限"该版本不在所有条件下必坏"（开发机同源码同启动器版本 flush=true×6；执行身份一致性待核，见 §6）。
- 多实例僵尸 Flash 锁（首次失败时无他 Flash 实例；**不排除** launcher/扫描器/同步程序等其他进程持冲突句柄）。
- 腾讯系杀软**文件层**拦截（字符串级零 I/O 与之不相容；用户态提前拒绝不在此列）。

**边界**：以上排除作用于"这几次 flush 调用中的文件层失败"，证据强度为字符串级；不排除"更早的后端初始化失败沿用"与"文件系统调用之前的用户态拒绝"（第二轮裁决 Q1/Q5）。
