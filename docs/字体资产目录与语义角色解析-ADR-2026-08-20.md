## 0. 决策摘要

1. 在项目根部建立唯一的 C# / Web 运行时字体入口 `fonts/`；顶层分为受版本控制的 `permanent/` 与整体 gitignored 的 `temporary/`。`launcher/web/assets/fonts/` 只保留由 XML 生成的协议投影，不得保存字体二进制；旧 `%LOCALAPPDATA%/CF7FlashNight/fonts/` 导入路径已经退役。`闪7重置版字体/` 保持为待随 Flash UI 退役的 legacy 作者目录，不纳入本次收口。
2. `fonts/fonts.xml` 是字体资产、下载来源、语义角色与预设映射的唯一人类可编辑真源；`fonts/fonts.xsd` 只负责结构约束，跨引用、格式、哈希、字符覆盖与可达性由语义校验器负责。
3. 文案人员继续使用熟悉的 XML / JSON 工作流，不要求维护 CSS、C# 字体族名、SHA-256 计算或下载缓存。首期不建设 Electron、Web 编辑器或字体工作台。
4. 工程复杂度集中到单一 CLI `tools/fontctl/` 和运行时 resolver。CLI 默认非交互、可无人值守，提供中文诊断、稳定退出码与 `--json` 机器输出；未来任何 GUI 只能是同一 XML / CLI 的薄壳。
5. 字体模型至少分为 `asset → face → role → preset/context`。业务消费者只引用稳定 role / preset ID，不裸用“思源宋体”“Microsoft YaHei”等物理 family；系统 UI、符号字体和程序化 path glyph 可作为显式例外登记。
6. resolver 冻结为 face-major：先按 role/preset 的 face 顺序，对每个 face 依次检查 `temporary/custom → temporary/cache → permanent/runtime`，该 face 无命中才进入下一 face，最后才到 system fallback。较晚 face 的 cache/custom 不得越过较早 face 的 permanent。临时缺失且声明远程来源时允许后台下载；下载等待或失败期间仍立即使用常驻或系统回退，网络不得成为同步启动门。
7. `temporary/custom` 服务开发者、文案与玩家手工投放；`temporary/cache` 只由下载器维护；`temporary/generated` 只保存可重建投影和诊断。三者不得混成一个无法区分来源的平面目录。
8. 文件自动扫描只负责“发现与报告”。未在 XML 中取得稳定 asset ID 或显式 role / preset 绑定的文件不得按遍历顺序自动改变游戏字体；同名、同 ID 或内部 family 冲突必须确定性拒绝或解释。
9. C# 与 Web 必须消费同一规范化解析结果。首次实现允许 C# 与 CLI 使用不同语言，但必须由共享 fixtures 锁定 XML 归一化、优先级、fallback 和错误语义，禁止两套独立映射表。
10. 首次原生施工后，普通字体文件、下载地址、role 和 preset 修改必须保持数据驱动，不要求修改或重新编译 C#。触及 resolver 实现、协议、打包器或 native 字体生命周期时，仍按 Launcher runtime 构建与发布规则处理。
11. 首期及本 ADR 后续 Gate 的唯一新增投资方向是 C# / Web runtime。不得为 Flash / FLA / XFL 新建平行字体目录、XML 映射、CLI 子命令或 CS6 验收链；旧 UI 迁移时随组件退役旧 face 依赖。若旧作者字体被重新选入 C# / Web，必须作为新的 runtime asset 重新经过许可证、hash、字符覆盖与视觉验证，而不是整体搬迁。
12. Gate E 接受 14 asset、28 role、9 preset、受控 exact-set Web handler，以及 JetBrains Mono / Source Han Serif CN Regular 两项常驻集合；26 个正常 role 与 9 个 preset 均为 `accepted`，另有 2 个 tooltip compatibility role。后续仍可通过 XML 数据变更统一调整。Native 首期保持重启生效，不做热加载。

## 1. 背景、现状与决策驱动

### 1.1 当前运行链

Gate E 后，[`fonts.xml`](../fonts/fonts.xml) 声明 asset、face、role、preset、residency、下载来源、字节与 SHA-256；[`FontPackTask`](../launcher/src/Tasks/FontPackTask.cs) 将新下载写入 `fonts/temporary/cache/`。[`RuntimeFontCatalog`](../launcher/src/Fonts/RuntimeFontCatalog.cs) 校验 XML SHA-256 绑定的生成投影，按 face-major 解析并把每个成功项冻结为进程生命周期的已验证 byte snapshot。Web、Skia 与 Native GDI 复用该快照；`WebResourceRequested` exact-set handler 只提供 `https://cfn-fonts.local/<declared-file>`，以内容 SHA-256 ETag 配合 `private, max-age=0, must-revalidate`，不再目录映射或暴露可枚举目录。未命中不缓存，FontPack 后台下载完成后仍可首次命中；FontPack 的状态/完整性查询则刻意绕过成功项缓存并重新读盘，继续暴露运行中的磁盘替换或损坏。

Web 的 `@font-face`、role custom property、Canvas、动态 SVG、Bridge 预热和 tooltip compatibility 均由 `launcher/web/generated/font-catalog.*` 驱动。Native HUD、Combo、伤害数字、FPS/mono 与 symbol 通过语义 role 创建 `Font`；Source Han 私有字体选择按进程缓存，修改后重启生效。`font-pack-manifest.json` 已成为同一次 `fontctl generate` 产生并由 `--check` 锁定的 Bootstrap 兼容投影，不再是人工 inventory。

Flash / FLA 制作字体仍位于 `闪7重置版字体/`，该作者链不扩建；长期由 C# / Web UI 迁移消解。Gate E 已让非程序创作者通过一个目录完成“放入字体—指定用途—运行验证”，不要求维护 CSS/C# family。

### 1.2 本轮静态盘点

| 范围 | 机械事实 | 结论边界 |
|---|---|---|
| 现役 FontPack manifest | 5 groups、14 files、`119,211,978` bytes（113.69 MiB）；只有 92,380-byte JetBrains Mono 是 shipped fallback | 证明当前最佳视觉高度依赖下载，不证明 URL 当前可用 |

| Web 生产样式扫描 | 排除 `dev/mockups/reference/lib` 后 34 个 CSS、293 个 `font-family`；69 处使用现有语义变量、35 处 `inherit`、189 处为其他直接声明或 `@font-face` alias | 证明角色化已有雏形但未收口；不把文件数或声明数冻结为未来合同 |
| Web 非 CSS 消费 | Canvas、动态 SVG、Bridge 预热和 [`tooltip.js`](../launcher/web/modules/tooltip.js) 的 AS2 `FONT FACE` 转换仍可直接产生 family | 仅改 CSS 变量不能完成迁移 |

盘点同时发现现有映射漂移：字体 README 的 group 总量低于 manifest 实值；Klee One 已从主要 role 链移除但仍随整组下载；Task Panel 使用精确 `Source Han Serif CN Heavy` alias，而部分 Workbench / Arena 栈只写中文 family 后回退 Regular；现有生产闭包脚本又把 manifest 路径和 `cfn-fonts.local` URL 当作固定输入。迁移必须先生成依赖图，不能只移动目录。

### 1.3 决策驱动

- 文案人员是字体表达的主要使用者，熟悉直接编辑 XML / JSON，但不具备或不应承担程序构建知识。
- 项目现有自定义音乐与压缩包覆盖安装已接受“玩家向游戏目录投放资产”的模型；本 ADR 不把安装目录写权限设为阻断前提。
- 字体选择包含不可替代的艺术判断，但哈希、格式、路径、缓存、下载、C#/Web 绑定和审计应由后端自动化吸收。
- Agent 与开发者需要可检索、可解释、非交互的 CLI，而不是需要维护独立前端状态的重型工具。
- 字体变化应尽量成为数据变化；不应因为把“情报标题”从 A 字体换到 B 字体就重新构建原生 Core。
- 网络不可用、字体缺字或文件损坏只能降低视觉质量，不得阻断游戏核心入口。

### 1.4 目标

- 一个目录回答“字体文件在哪里”，一个 XML 回答“字体是什么、从哪里来、用于什么”。
- 文案能够通过复制文件和编辑 XML 完成常规字体试验。
- C#、Web CSS、Canvas/动态 SVG 与兼容数据入口能解释到同一 role / asset。
- 临时覆盖、下载缓存、常驻资产和系统回退有确定性顺序与可观测 provenance。
- CLI 能在实现前发现未登记文件、断引用、缺字、重复映射和仍裸用 family 的消费者。
- 迁移完成后淘汰多份手工清单，并保持离线可用、可打包、可审计。

### 1.5 非目标

- 首期不建设 Electron、Web 字体编辑器、字体商城或通用素材管理平台。
- 不要求程序自动判断“哪个字体最有艺术表现力”。程序只提供发现、校验、预览所需数据和确定性解析。
- 不要求首期热加载 GDI `PrivateFontCollection`；允许以进程重启作为 native 字体生效边界。
- 不把系统 consent / security UI、`SystemFonts` 或 PlayerInfo 的程序化 path glyph 强行改成可替换 runtime 字体。
- 不为 Flash / FLA / XFL 建立字体目录、作者环境安装器、face 映射、迁移工具或 CS6 验收；旧 Flash UI 的字体依赖随对应 UI 迁移一并退役。
- 本 ADR 不授权自动修改 Flash 作者字体或把运行时 promotion 当成字体艺术验收；实现与发布仍分别服从各自 Gate。
- 不因目录统一而自动获得任何第三方字体的再分发权。

## 3. 目标目录与来源模型

### 3.1 目录冻结

```text
fonts/
  fonts.xml
  fonts.xsd
  README.md

  permanent/
    runtime/

  temporary/                 # 整体 gitignore
    custom/                  # 文案、开发者、玩家手工投放
    cache/                   # 下载器拥有
    generated/               # resolver / CLI 可重建投影与报告
```

规则：

- `permanent/runtime/` 只容纳经过版本治理、许可证记录、manifest 引用、完整性和体积审计的运行时字体。
- `闪7重置版字体/` 不移动进 `fonts/`，resolver、CLI、打包器和运行时均不得扫描；未来若复用其中单个字体，按新的 `permanent/runtime` asset 独立引入。
- `temporary/custom/` 当前允许 TTF / OTF / WOFF；WOFF2 只允许进入 hash 固定的 cache/permanent，local custom WOFF2 没有覆盖权。Git、打包器和正式闭包默认排除整个 temporary。
- `temporary/cache/` 禁止人工当作长期素材库；清理和覆盖只按 asset ID、期望 hash 与 provenance 执行。
- `temporary/generated/` 无独立真值。删除后必须可由 `fonts.xml + permanent + custom + cache` 确定性重建。
- 覆盖补丁不得递归清空 `temporary/`；若将来改变补丁器行为，须先更新本文和发行说明。

### 3.2 解析与获取分离

解析器每次为一个 role 请求生成 face-major 有序候选。先完整处理第一个 face 的三层来源，才处理下一个 face：

1. face 1：XML 允许且通过实际解析探针的 `temporary/custom` exact candidate（当前不含 WOFF2）→ 与 XML asset 版本/hash 匹配的 `temporary/cache` → `permanent/runtime`；
2. face 2..N：重复同一来源顺序；
3. role 声明的 system family / generic fallback。

`fontctl resolve` 必须输出 `candidateOrder=face-major`。Node 对 TTF/OTF/WOFF custom 只给出 `runtime-probe-required`，不能代签 Host parser；只有位于静态首选之前的未决 custom 会把结果降为 `provisional-node-fallback`。较晚 face 的未决 custom 不影响已经由较早 face 确定的静态选择。Node 不探测本机 system family，选中 system fallback 时必须改为 `provisional-system-availability`。`hostExactSelection` 恒为 false；`authoritative=true` 仅限无未决项的 Node 静态来源模型，`parityScope` 只描述候选顺序/静态完整性覆盖，不得写成实际 parser 或 render parity。

“临时缺失时下载”属于 acquisition，不改变当前帧的本地 fallback：

```text
resolve locally
  ├─ hit temporary/permanent/system → 立即返回可用字体
  └─ downloadable asset missing     → 记录 missing，后台下载到 staging
                                          ├─ verify + atomic publish → 下次解析命中 cache
                                          └─ fail                  → 保持 permanent/system
```

存在 URL 不得导致 permanent 被跳过；下载超时不等于字体解析失败；网络下载完成也不得在未定义的 GDI 生命周期中强行替换已加载 family。

### 3.3 自动发现与确定性绑定

- `scan` 递归发现受支持扩展名，读取内部 family/subfamily、weight/style、字符表和文件 hash。
- 发现不等于启用。文件必须获得唯一 asset ID，并由 role / preset 显式引用后才可改变渲染。
- `temporary/custom/<declared file>` 只有在格式受支持并通过实际解析探针后才可覆盖同 asset 的常驻候选；当前 WOFF2 即使容器有效也继续 cache/permanent。仅仅内部 family 相同不构成覆盖权。
- 同一层出现重复 ID、大小写折叠冲突、同 path 多声明或一个物理文件被声明成不兼容 face 时 fail closed。
- CLI 输出未登记字体和可复制 XML 片段；默认不自行修改 XML。任何 `--apply` / `--write` 必须显式且可复核 diff。

### 3.4 身份

- `assetId`：稳定文件/发行身份，不随中文显示名变化；建议使用小写 ASCII `kebab-case`。
- `faceId`：一个可选择的 family + weight + style + stretch 组合；同 asset 可提供多个 face。
- `roleId`：消费位置与排版语义，例如 `native.hud.body`、`web.intelligence.title`；不得使用具体字体名。
- `presetId`：一组 context 下的 role override，例如 `intelligence.diary`、`intelligence.terminal`。
- 文件 hash 是内容身份和下载完整性，不替代稳定业务 ID；更新字体版本必须显式更新期望 hash / bytes 并产生审计差异。

## 4. XML 语义合同

### 4.1 最小模型

| 层 | 必须表达 | 不负责 |
|---|---|---|
| asset | ID、显示名、文件、格式、target、许可证、可选下载来源、bytes/hash | 业务场景 |
| face | asset、family alias、weight、style、stretch、支持的 renderer | 下载策略 |
| role | 稳定 ID、显示名、有序 face/system fallback、必需/可选策略 | 单篇文案内容 |
| preset | context 下 role → face/role override | 物理文件完整性 |
| bundle | 可选的下载/预取组合 | 消费者选择字体 |

## 5. 文案、开发者与 Agent 工作流

### 5.1 文案人员

常规试验流程冻结为：

1. 将 TTF / OTF / WOFF 放入 `fonts/temporary/custom/`；WOFF2 试验必须使用声明完整性的 cache/permanent，当前不能作为 local custom 覆盖；
2. 在 `fonts.xml` 添加或复制一条 font / face 声明；
3. 修改 role 或 preset 引用；
4. 运行 `validate` 与 `generate`；
5. 启动游戏；启动时 Host 复核 XML-hash 投影并输出可理解错误；
6. native 字体按首期 restart boundary 生效。

文案不需要运行 Electron、不需要编辑 CSS/C#、不需要手算 hash，也不需要理解 WebView2 虚拟主机。临时字体没有远程发布要求时可省略 download 和发行 hash；CLI 仍自动记录 observed hash 供诊断。

### 5.2 开发者与 Agent

建议入口保持单一：

```powershell
node tools/fontctl/cli.js scan
node tools/fontctl/cli.js validate
node tools/fontctl/cli.js resolve --role web.intelligence.title --preset intelligence.diary --explain
node tools/fontctl/cli.js audit-usage
node tools/fontctl/cli.js sync --group expressive-handwriting
node tools/fontctl/cli.js generate --check
```

Gate E 的六个命令与写入边界如下：

| 命令 | 默认行为 | 可写范围 |
|---|---|---|
| `scan` | 扫描元数据，报告新增/缺失/冲突 | 无 |
| `validate` | XSD + 语义 + 文件 + 许可证字段 + fallback 校验 | 无 |
| `resolve` | 对 exact role/context 输出候选、拒绝原因和最终命中 | 无 |
| `sync` | 下载缺失 remote asset 到唯一 staging，校验后原子发布到 cache；`--check` 只读 | 仅 `temporary/cache` |
| `generate` | 生成 Web/C# 共享 JSON、CSS、JS 与 Bootstrap 兼容 manifest；`--check` 只读 | 默认仅 `launcher/web/generated` 与 `launcher/web/assets/fonts/font-pack-manifest.json`，或显式隔离输出根 |
| `audit-usage` | 扫 C#/CSS/JS/运行时数据中的裸 family 与旧路径 | 默认无；只产报告 |

所有命令必须：

- 默认非交互且无确认弹窗；
- 支持 `--json`、稳定 schema、确定性排序和非零失败码；
- 区分 warning、当前 fallback 可用、阻断错误与 pilot debt；
- 在错误中返回 XML path/line、asset/face/role ID、候选来源和建议动作；
- 不把网络失败、许可证缺字段和艺术选择混成一个 `font_failed`；
- 不要求 GUI、浏览器登录或本机全局安装字体。

## 6. Runtime 消费合同

### 6.1 单一 resolver 语义

生产 Host、CLI 和测试必须对同一 fixture 产生相同的目录拓扑、来源顺序与结构拒绝；实际 parser 的裁决权只在 Host：

- 规范化 asset/face/role/preset 图；
- 来源优先级与拒绝原因；
- remote missing / downloading / verified / failed 状态；
- system/generic fallback；
- target / format 的静态可用性；custom 的动态可用性由 Host 探针裁决；
- stable diagnostics code。

实现跨 Node/C#，由 XML SHA-256 绑定的规范化投影锁定目录行为，但不伪造 parser parity。Node 对结构有效的 TTF/OTF/WOFF custom 输出 `runtime-probe-required / eligible=false`，并把下层命中标为 `provisional / non-authoritative`；C# 以真实 OTF/TTF/WOFF 正例及伪 SFNT 负例锁定实际探针，WOFF2 仅在 hash 固定的 Web-only 资产上标为 `pinned-web-structure-only`。共享矩阵另覆盖有效 WOFF2 custom 拒绝并回退、缺失、重复、损坏、hash mismatch、下载失败、preset override、fallback cycle 与不支持格式。

### 6.2 C#

- `RuntimeFontCatalog` 在早期日志建立后、WebView2/Native HUD 构造前加载投影并复核 XML hash，按 role 创建和持有 `FontFamily` / `PrivateFontCollection`；resolver 单次读取候选并保存已验证字节，Native 通过 `AddMemoryFont` 使用同一快照，业务 widget 不再拼接字体路径。
- role API 必须携 size、style、unit 等渲染参数；face 映射不能吞掉调用方的布局意图。
- `SystemFonts`、Segoe UI Symbol 等系统所有面，以及 PlayerInfo [`PlayerInfoPathGlyphAtlas`](../launcher/src/Guardian/Hud/PlayerInfo/PlayerInfoPathGlyphAtlas.cs) 的程序化 path glyph，通过例外表保留，不伪装成可下载 TTF。
- 首期 catalog 和 private collection 采用进程生命周期；XML / custom 变化提示“重启生效”。热换需另立生命周期设计，不能泄漏 collection 或让旧 Font 对象悬空。
- FontPack 下载和 native prewarm 已统一到同一 resolver；FontPack 在 bytes/hash 后复用 `RuntimeFontCatalog` 对同一 byte[] 执行实际探针，TTF/OTF/WOFF 走 runtime parser，Native TTF/OTF 再走 GDI，WOFF2 Web-only 只允许显式结构状态且 Native 拒绝。未经这些门的 cache 文件不会成为已安装候选；runtime resolver 另以单次读取快照消费，验真后不再按可替换路径二次打开。

### 6.3 Web

- CSS 消费者使用生成的 role custom property；Canvas / 动态 SVG 使用生成的 JS role registry，不自行复制 family stack。
- `@font-face` alias 由 catalog 生成，role 必须引用该 exact alias，消除中文内部 family 与 CSS alias 漂移。
- WebView2 使用受控 `WebResourceRequested` handler：只响应 XML 已声明的安全 basename，逐文件走来源优先级，并直接返回 resolver 的已验证字节快照及 CORS/CORP/no-store 头；不再把字体目录映射为虚拟 host，也不在验证后重读路径。
- 独立 Web harness 必须得到与 Host 相同的生成 catalog fixture；不得因为没有 `cfn-fonts.local` 就跳过 role contract。
- Bridge 预热按实际可见 role 请求；Tooltip compatibility、Jukebox Canvas 与 Factions 动态 SVG 也已接入生成 API。

### 6.4 兼容入口

- [`tooltip.js`](../launcher/web/modules/tooltip.js) 对 AS2 `FONT FACE` 的兼容必须经受控 alias 表解析；现有 `ms mincho`、`fixedsys` 可以保留兼容 role，但不得允许任意数据绕过 catalog。
- JS Canvas、动态 SVG、CSS inline style 和 C# `new Font(string, ...)` 纳入 `audit-usage`；迁移结束后只允许明示 allowlist。
- XFL `face` / `DOMFontItem` 不进入 catalog 或 `audit-usage`。AS2 `FONT FACE` 仅在其内容已经进入 C# / Web 渲染边界时作为 legacy 输入做 alias 收口；这不授权修改 Flash 源或为其补建字体系统。

### 6.5 普通字体变更不重编译

首次引入 resolver 会触及 C#、Web、打包和测试，必须走相应 runtime 构建边界。完成后，下列变化应只修改 `fonts.xml`、字体资产或可重建投影：

- role / preset 绑定；
- remote URL、hash、bytes；
- permanent / custom 文件；
- system fallback 顺序；
- bundle / prefetch 组合。

如果普通映射变化仍要求编辑生成的 C# 常量并重编 Core，Gate B 不通过。只有 resolver 代码、协议、native loader、Web resource handler 或打包器实现变化才进入原生 release source。

## 7. 下载、完整性与许可证

### 7.1 Remote

- 只允许 HTTPS；host allowlist 为 XML 中的 `github.com`、`cdn.jsdelivr.net`。Node sync 与 C# FontPack 对 requested URL 和每次 redirect 后 URL 都重新校验 scheme/host；C# allowlist 直接来自同一生成投影。
- remote asset 必须声明 SHA-256 和期望 bytes；空 hash 不得视为通过。
- 下载先进入唯一 staging 文件，设置最大响应/落盘体积。Node sync 完成 bytes/hash、扩展名、magic、glyph 目录与 outline 结构门，但不冒称执行了 Launcher parser；C# FontPack 在同一下载快照上追加 catalog 绑定与实际 parser，Native 还追加 GDI，只有全部适用门通过才以不破坏旧有效 cache 的方式发布。WOFF2 Web-only 只记录 `pinned-web-structure-only`，不得冒充 actual parser。
- cache key 至少绑定 `assetId + expectedSha256`；并发 sync 不得共享可猜的单一 `.tmp` 所有权。
- cancel、网络失败、hash mismatch 或 publish 失败只清理本事务 staging，不先删除旧有效目标。
- 日志记录 requested URL、final URL、bytes、hash、错误分类和最终来源，但不把本地任意绝对路径暴露给 Web 内容。

### 7.2 Local custom

- custom 文件不要求预先声明发行 hash，但生产 resolver 必须单次读取候选、做有界结构检查，再对同一字节真正调用字体解析器并记录来源：TTF/OTF 走 SkiaSharp `SKTypeface.FromData`，WOFF 在逐 table 边界、展开总量和 zlib 长度复核后重建 SFNT，再走 `SKTypeface.FromData`；Native TTF/OTF 还必须以同一字节通过 `PrivateFontCollection.AddMemoryFont` 探针并从该快照加载。正例测试已证明三种可覆盖格式能被该路径解析，替换原路径后已解析对象的 bytes 仍保持不变。当前 SkiaSharp 3.119.4 无法解析仓库内有效 WOFF2，且工程内没有共同 WOFF2 解码器，因此 local custom WOFF2 明确 fail-closed。Node 只做结构/元数据门并对其他 custom 输出 `runtime-probe-required`，不得把 header、目录或 metadata 检查称为解析成功或 C# parity。
- custom 只在本机/当前覆盖包中生效，不自动复制进 permanent、Git 或正式发布资产。
- 损坏或不支持字体只隔离该 candidate；role 继续 permanent/system fallback。

### 7.3 Permanent runtime

- permanent runtime 字体必须有许可证标识、来源、hash、bytes、target 和打包闭包。
- legacy 作者字体不因磁盘上存在而获得 runtime 身份；复用时必须逐个作为新 asset 完成许可证与嵌入边界审计。
- 字体子集化会改变 bytes/hash/coverage，必须成为新的 asset/version；不能在构建中静默改写原 asset 后沿用旧 identity。

## 9. 证据分层与验收矩阵

| 层级 | 必须证明 | 不能代签 |
|---|---|---|
| 静态 inventory | 文件、引用、角色、裸 family、许可证字段和路径闭包 | XML resolver 行为、实际字形 |
| Schema / CLI fixtures | 解析、优先级、fallback、错误码、生成 determinism | Host/Web 真实消费 |
| Host unit/integration | C# face 生命周期、cache 验证、prewarm 顺序、role API | Web CSS/Canvas、真实观感 |
| Web harness | CSS alias、role/preset、Canvas/tooltip、布局和离线 fallback | Host↔WebView2 正式旅程 |
| isolated runtime pilot | 实际进程路径、字体来源、可见角色、重启和故障回退 | promotion、标准入口 |
| promoted / standard entry | 正式 release identity/closure 与部署后入口 | 未覆盖字体/场景或许可证法律结论 |

任何 Gate 的“全绿”只覆盖其实际执行的层。尤其：CLI 能解析字体不证明 GDI/WebView2 渲染正确；系统 fallback 可用不证明设计意图成立；维护者挑选某个字体不证明许可证允许随发行版分发。

## 10. 风险、成本与缓解

| 风险 | 影响 | 冻结缓解 |
|---|---|---|
| XML 变成另一份重复清单 | 继续手改 manifest/CSS/C#，漂移更严重 | XML 单真源；过渡投影只能生成并 `--check` |
| role 过粗 | 一次替换破坏任务、情报、战斗等不同视觉语义 | 分域 role；preset/context 覆盖；Gate A inventory 冻结 |
| role 过细 | 文案难以理解、映射重复 | 中文 label、role inheritance、preset；CLI 报 unused/duplicate |
| 任意文件自动抢占 | 文件遍历顺序或内部 family 冲突造成不可复现视觉 | 发现与启用分离；stable ID + XML explicit bind |
| 网络阻塞启动 | 无网玩家卡在下载 | acquisition 与 resolve 分离；立即 permanent/system fallback |
| custom/cache 混放 | 下载器误删玩家字体，无法解释来源 | `custom/cache/generated` 三目录和 provenance |
| 字体损坏或恶意文件 | GDI/Web parser 崩溃或资源耗尽 | 体积上限、hash、magic、解析探针、candidate 隔离 |
| 字体度量变化 | 溢出、数字错位、点击区与视觉不一致 | role-specific metrics pilot、多 DPI、Canvas/GDI 测量 |
| C# / CLI 解析漂移 | Agent 检查通过但运行时选择不同 | normalized topology/source/diagnostics fixtures；CLI 对待 Host 探针的选择必须显式 provisional |
| 为待退役 Flash 建平行字体治理 | 重复盘点、目录、工具和 CS6 验收投资，且未来仍要删除 | Flash 作者链明确冻结在范围外；只在 C# / Web 边界处理仍可达的 legacy 输入 |
| 生成物变成人工真源 | 修改 XML 后仍需手修 CSS/JSON | generated header、只写 generated 目录、`generate --check` |
| 每次映射都重编 Core | 文案试验成本过高并扩大发布链 | runtime data loading；普通映射不生成需编译的 C# 常量 |
| GUI 先行 | Electron/前端依赖吞噬核心施工和 Agent 上下文 | 首期明确不做；未来 GUI 必须为 XML/CLI 薄壳 |

主要实施成本是跨 C#/Web 的 resolver、字体元数据解析依赖、旧 production closure 迁移和多 renderer 视觉验证。回报是字体选择从程序修改降为可审计数据修改，并把文案、开发者、玩家和 Agent 的入口收束到同一目录/合同。

## 11. 被拒绝方案

### 11.1 保持现状，只补 README

拒绝。当前 runtime manifest、CSS、C#、JS 和数据已经形成多真源，README 无法机械阻止 alias、总量和可达性漂移。

### 11.2 首期先做 Electron / Web 字体编辑器

拒绝。文案已经能编辑 XML/JSON；GUI 会先引入打包、依赖、前端状态与 Agent 维护面，却不消除 resolver、下载、安全和跨 renderer 合同。

### 11.3 内容直接写物理 family

拒绝。会把 `Source Han Serif CN Heavy` 等实现细节扩散到每篇文案，统一替换无法完成，也会重现 AS2 `FONT FACE` 旁路。

### 11.4 目录扫描后“第一个匹配 family 胜出”

拒绝。文件顺序、内部命名、大小写和多 face 字体均可能变化，无法解释、复现或安全回退。

### 11.5 URL 存在时必须下载成功才查 permanent

拒绝。远程获取不能阻断本地可用字体；下载只提升后续解析优先级，不撤销 permanent/system fallback。

### 11.6 C#、Web 各自解析和维护映射

拒绝。允许跨语言实现，不允许跨语言拥有不同规范化结果；fixtures 和生成投影必须把差异变成测试失败。

### 11.7 将 Flash 作者字体纳入首期统一治理

拒绝。Flash UI 长期迁往 C# / Web；为其建立 authoring 目录、55 个 face 映射、安装/校验工具和 CS6 Gate 会形成明确的重复投资。旧目录保持 legacy；只有被 C# / Web 明确选中的单个字体才按 runtime asset 重新进入本合同。

## 13. 文档与维护触发器

发生以下变化时必须同轮更新相应 canonical doc，并运行 `node tools/validate-doc-governance.js`：

- `fonts/` 路径、XML/XSD、CLI 入口或生成物位置变化；
- asset/face/role/preset 语义或来源优先级变化；
- C# / Web 字体消费协议、虚拟 host 或生效生命周期变化；
- 字体下载、hash、许可证、打包和 cache policy 变化；
- 新 renderer 加入或旧裸 family allowlist 退出；
- 若未来反转范围、要求把 Flash / FLA / XFL 作者字体纳入统一治理，必须另立或修订 ADR，不得悄悄扩入现有 Gate；

- 当前字体操作与迁移状态：本文 + `fonts/README.md`；`launcher/web/assets/fonts/README.md` 只记录 generated compatibility 目录边界；
