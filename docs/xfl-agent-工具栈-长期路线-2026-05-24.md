# XFL Agent 工具栈 — 长期投资路线

- **建立日期**：2026-05-24；**能力复核**：2026-09-05，QJZ171 装配及图标/掉落修订已由人类验收。
- **性质**：通用工具的投资记录。具体任务操作以 [美术资产装配](../agentsDoc/art-asset-assembly.md) 为准。
- **当前状态**：命名校准、专项依赖追踪、度量衡与确定性 XFL 装配已可用；尚无通用反向依赖、跨库迁移或任意形状生成器。

## 1. 能力按操作验证，工具按需求建设

XFL 是可机器读写的源文件。Agent 可以检查、复制、装配和修改原生元件，也可以针对任务生成需要的包装层、帧和形状；能否交付应由源结构、CS6 原生保存/发布、实际消费者和视觉结果判断。不存在按模型身份禁止 DOMShape 或图标工作的边界。

2026-09-05 的 [QJZ171 案例](QJZ171-独立物品与Flash资产流程标定-2026-09-05.md) 已验证：保留 402 个原生 DOMShape 的分件导入、MovieClip 接口包装、作者独立库、共享库挂载、遮罩特写图标、完整掉落帧与嵌套倍率修正。它证明这些操作能够交付，没有证明任意矢量化、复杂骨骼或所有动画都已经自动化。

因此撤销原路线中“DOMShape / icon 属于 agent 能力外”的判断，以及等待三个月、六个月或累计若干请求才允许操作的日历门槛。**未建设通用工具，不阻止已经授权的具体任务使用脚本完成装配。** 保留 Layer 名称仅用于区分工具职责，不要求按编号逐层解锁。

## 2. 现有工具与能力边界

| 层 | 已有能力 / 入口 | 仍需验证或建设的部分 |
|---|---|---|
| Layer 0：一致性校准 | [audit / rename_a_class / fix_includes](../scripts/tools/xfl/README.md)、[linkage scanner](../tools/linkage_scanner/scan_linkage.py) | 自动修复限定明确无歧义的命名与 Include；不处理链接 ID 内容冲突 |
| Layer 1：检查 | [专项前向依赖追踪](../tools/monster-reskin-pipeline/README.md)、[度量衡](../tools/asset-metrology/README.md)、现有 XML/AS 搜索 | 尚无通用反向 where_used、全仓 attachMovie 图或可靠孤儿判定 |
| Layer 2：结构编辑 | 作者隔离库、元件复制、引用与矩阵修改、命名接口、共享导入装配 | 通用跨库迁移必须处理所有引用、冲突和保存后的变化；一次专项成功不代表任意搬迁安全 |
| Layer 3：生成 | 已有原生分件的总装、图标时间轴、遮罩包装与独立物品接线 | 任意 SVG/位图到 DOMShape、自动人体重绘等分别验证；不因没有通用生成器拒绝具体任务 |
| Layer 4：语义差异 / 合并 | 作者专属文件先减少二进制竞争 | 真正遇到共享文件评审/合并瓶颈时再建设；不宣称当前已有语义合并 |

CS6 的 GUI 宿主仍负责选定源格式（FLA 或 XFL）的原生保存及 AS2/SWF 发布。XFL 接替后移除旧 FLA，依据维护历史和现役发布入口判断单一编辑源，细则见 [装配入口](../agentsDoc/art-asset-assembly.md)。已有 [JSFL 与计划任务管线](../scripts/FlashCS6自动化编译.md) 可触发这些动作，不需重复实现另一套编译器。

## 3. 验证与投资规则

| 场景 | 处理方式 |
|---|---|
| 一个明确的资产任务 | 先用已知元件、确定性 XFL 编辑与 JSFL 完成最短闭环；在副本或作者自有源上工作 |
| 同类操作反复消耗时间 | 抽取真正重复的输入、转换和检查，放入 tools 并记录参数；不把含本机绝对路径的临时脚本直接改名入库 |
| 一次批量修改风险较高 | 提供可审阅差异或 dry-run，先做有代表性样本；样本覆盖由引用/动画/导出差异决定，不按固定等待月份 |
| 推广为通用工具 | 明示支持的元件、属性和冲突类型，用异质样本验证；遇到不支持的结构应报告而不猜测 |
| 暂无收益的工具 | 保留为候选，不启动投机建设；不把“不建工具”变成“不能做资产”的规则 |

验证分四层，按本次改动选择相应消费者：

1. **源结构**：XML 可读、命名/Include/引用闭合，注册点和接口保持；修改 FLA/XFL 后运行 Layer 0 与 linkage scanner。
2. **原生产物**：CS6 能打开/保存对应源，发布日志新鲜且无编译错误，SWF 确实更新，导出和共享导入符合目标。
3. **装配消费者**：纸娃娃、第一帧图标、第二帧掉落、Web 烘焙分别检查；公式/截图/索引中任一层通过不替代其余层。
4. **体验**：由需要的人类感知完成观感和战斗手感验收。已授权可恢复的机器工作继续，不新增 acceptance 文本、逐字批准或发布状态机。

硬边界仍适用：不手改 SWF；不把 publish marker 单独当成功；不让外部编辑与 CS6 未保存缓存互相覆盖；linkageId 撞车类内容归属冲突按 [AGENTS.md](../AGENTS.md) 由人工 CS6 修。不要从“模型进步”推导任何特定文件都可以省略验证。

## 4. 知识归属

- 可复用的装配步骤、字体/UAC/缓存问题和目标选择：维护 [agentsDoc/art-asset-assembly.md](../agentsDoc/art-asset-assembly.md) 及其对应工具文档。
- 原稿、分件、枢轴与装配参数：放在素材所属目录；不要混入会被 CS6 另存重建的 XFL 目录。QJZ171 示例见 [Codex素材源稿](../flashswf/arts/new/Codex素材源稿/README.md)。
- 当次取值、用户裁定和验证范围：放 docs 案例；数值和正式矩阵仍由各自 XML/JSON 真源维护。
- 临时导出、截图、编译输出与中间尝试：放 tmp；复用工具需要脱离 tmp 输入才有长期价值。

## 5. 相关但独立的能力

### FLA rig overflow 修复

[FLA-rigPropagationMatrix-溢出导致元件不可编辑](../scripts/优化随笔/FLA-rigPropagationMatrix-溢出导致元件不可编辑.md) 保留为症状触发的修复入口：轴歪、编辑闪退、无法另存 XFL 三者同时出现时检查。它处理压缩 FLA 中的损坏缓存，与日常 XFL 一致性校准不同；不把罕见修复扩张为常规重打 FLA 流程。

### 换皮参考管线

[monster-reskin-pipeline](../tools/monster-reskin-pipeline/README.md) 自身仍只读，负责动作、叶子件、局部原点和多姿势参考。这是该工具的实际职责，不是对所有 agent 编辑能力的限制。最终矢量回填可由人类编辑或确定性 XFL 操作完成，具体路径按装配入口验证。

整机概念图不能直接机械切片为可用人体件；共享件、遮挡面、关节余量、动作标签和攻击点仍需逐件处理。QJZ171 的静态武器成功不取消已有的人体结构与动作检查。

### 其他入口

- AS2 编码、API 和编译规则：[as2-anti-hallucination.md](../agentsDoc/as2-anti-hallucination.md)。不因 XFL 装配能力提升而删除真实 AS2 语言限制。
- 编译与行为验证：[testing-guide.md](../agentsDoc/testing-guide.md)。
- 物品配置和 evidence：[balance 落盘契约](../tools/cf7-balance-tool/docs/agent-balance-record-design.md)。
