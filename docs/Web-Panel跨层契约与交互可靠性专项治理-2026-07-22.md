# Web Panel 跨层契约与交互可靠性专项治理（2026-07-22）

## 1. 结论与范围

本轮缺陷不是单个按钮或单个常量的孤立问题，而是 Web → Host → AS2 跨层迁移中两类契约未被共同执行：

1. **边界语义混用**：Host 把 NPC 商店数量写成固定 `1..100`，但 AS2 权威交易计划允许更高数量；Web 又会采用权威 `maxPurchasable`。三层分别自洽，组合后却会在“最大”或累计 `+5` 超过 99 时被 Host 拒绝。
2. **失败后状态未定义**：结算页只覆盖成功 preview 和未知写结果对账，没有规定只读 preview 被确定性拒绝后，意图、权威明细、按钮和二级页应恢复到哪一份状态。
3. **复合悬停缺少空白终态**：共享 Tooltip 为支持“触发物 → 可交互浮层”过桥而延迟隐藏；若延迟结束时没有重新确认指针已落入真空白区，旧简介会成为幽灵 UI。KShop、NPC 商店、合成与装备调制共用该基础设施，因此不能按单页面补丁处理。

专项第一批覆盖直接共享交易/筛选/Tooltip 基础设施的 `npcshop`、`kshop`、`crafting`。Inventory、Skills、Equipment Tuning 等已有更强实例租约或写对账测试的领域继续保留各自门；以后新增或修改数值边界、命令映射、失败分类时，必须先登记到本专项的机器可读契约，不再增加无审计的跨层副本。

## 2. 数值边界的三种权威

所有跨层数值字段必须明确属于下列一种语义，不能只写一个裸 `max`：

| 类型 | 负责层 | 示例 | 约束 |
|------|--------|------|------|
| 协议/传输护栏 | Host | NPC 购买数量必须为正整数且不超过 AS2 可安全处理的技术上限 | 可在 Host 固定；必须大于等于业务可能返回的范围，并由共享边界向量回归 |
| 静态业务规则 | AS2 权威服务，Host 可作同值防御 | 合成份数 `1..99` | 允许重复校验，但必须由机器契约审计两端一致 |
| 动态业务规则 | AS2 权威服务 | NPC `purchaseLimit/maxAffordable/maxByCapacity/maxPurchasable` | Host 禁止复制固定业务值；Web 只能展示/限制交互，preview/commit 必须重新裁决 |

`launcher/contracts/panel-contracts.v1.json` 是可执行登记表，包含领域命令映射、`flashResponseTask → hostResponseHandler` 精确绑定、读写级别、数值字段权威与共享边界向量。注释中的注册不算可执行证据，同一 response task 也不得重复或错绑。它不是运行时价格或存档权威，也不替代 AS2 的最终裁决。

## 3. Preview / Commit 失败恢复契约

页面必须区分“意图是否被权威接受”和“写结果是否可知”，不能统一进入一个 `error` 布尔值：

| 结果类别 | 本地意图 | 最后权威投影 | 写门 | UI 行为 |
|----------|----------|--------------|------|---------|
| preview 成功 | 保存为新检查点 | 替换 | `idle` | 重绘明细并允许继续调整/提交 |
| preview 普通读失败（非权威拒绝、timeout、disconnected、畸形/未知回包） | 回滚到最近成功检查点 | 保留最近成功投影 | `idle` | 明示已恢复；加减、返回和重新选购继续可用 |
| preview 权威失鲜（如 `stale_state/item_not_found/invalid_quantity/insufficient_quantity/material_missing`） | 不把旧投影冒充当前 | 重新 snapshot | 保持只读恢复流程 | 清除分歧意图，禁止用旧 lease/token 自动重放 |
| preview 明示 `requiresReconcile` / `reconcile_required` | 不猜测 | 等待新鲜完整 snapshot | `needs_reconcile` | 阻止新写，直到越过 watermark 的对账完成 |
| commit 未知或畸形回包 | 不回滚成“未交易” | 等待新鲜完整 snapshot | `needs_reconcile` | 绝不自动重放 token 或 commit |
| commit 权威成功/确定性失败 | 采用回包状态 | 替换或保留权威状态 | `idle` | 成功清单清空；失败显示原因并允许受控重试 |

NPC 结算页的检查点绑定一次成功 `tradePreview` 的 `purchases/sales` 与同一份 settlement。返回选购、重新打开结算、organizer 重绑 lease、面板关闭时必须清除旧检查点，避免跨会话或跨容器版本恢复陈旧引用。`tradeCommit` 在途时返回、加减、最大、移除与重复提交必须同时禁用。Crafting 同样用 `category + recipeIndex + craftCount` 绑定成功 preview checkpoint，不再把普通读超时冒充为写对账。

## 4. Tooltip 复合悬停契约

共享 Tooltip 的可见性由一个复合 hover scope 决定：

```text
触发物 hover ─┐
               ├─ owner/binding 仍有效 ──> visible
浮层 hover ────┘

触发物和浮层均未命中 + hide grace 到期 ──> hidden
scope dispose / panel close ───────────────> hidden（立即）
```

固定不变量：

- 从触发物移动到浮层时不得闪烁或提前关闭，浮层内滚轮与键盘阅读继续可用。
- grace 到期必须根据真实 PointerEvent/命中状态再次判断；mouse 与 pen 都不能依赖 UA 是否额外合成 `mousemove`，指针已在真空白区时不得继续显示旧内容。
- anchored focus A → hover B → leave B 只在 A 仍连接且 scope 有效时恢复 A；detached owner 不得复活。
- `hide()` 是确定性销毁，必须清掉 trigger/surface hover、待执行 timer 与恢复焦点状态；面板关闭或 scope dispose 不走延迟。
- 回归必须派发真实 pointer/mouse/pen 事件并经过 `elementFromPoint`，不得用直接调用内部函数代替浏览器事件链；仍使用 `showAtMouse/followMouse/hideHover` 的 legacy 消费者也必须保留物理鼠标探针。

## 5. 可执行治理门

专项不以“文档已同步”为完成条件，代码门由以下部分组成：

1. `node tools/validate-panel-contracts.js`：校验契约 schema、命令映射、response task 与精确 Host handler、authority/固定边界组合，并剥除注释后对照 TaskRegistry、Host 与 AS2 可执行锚点，阻止旧 NPC `100` 上限或回包路由漂移回流。
2. `node tools/test-panel-contracts.js`：对契约和源码副本做 **17/17** 变异测试，覆盖命令漂移、动态业务边界被 Host 固定、边界向量缺失、handler 错绑/重复绑定与注释伪证据。
3. Launcher xUnit 直接读取同一份 `panel-contracts.v1.json` 的 NPC/Crafting/KShop 边界向量；当前全量 **1181/1181**，NPC `100/101/4549/999999` 必须送达 Flash 权威，`0/1000000` 必须在 Host 前置拒绝。
4. NPC browser harness **80/80** 覆盖大数量、checkpoint/旧 epoch、权威分歧刷新、commit 在途交互锁与未知写零重放。
5. Crafting browser harness 三视口 **76/76** 覆盖读超时/迟到/断线/畸形恢复、权威失鲜 snapshot、未投递 commit 确定失败和已投递 commit 对账。
6. KShop browser harness **88/88** 使用真实 pointer、pen 与物理 mouse 覆盖“触发物 → 浮层”与“快速划入真空白区”两个相反场景，并同时验证 `bindAsync` 与 legacy `showAtMouse/hideHover`。
7. `tools/validate-launcher-release-policy.ps1` 将契约校验纳入 production policy；契约或关键实现漂移时不得生成可推广候选闭包。

## 6. 维护规则

- 新增 Web cmd、C# action、AS2 handler、response task 或读写级别时，同轮更新机器契约与相应领域测试。
- 数值字段新增固定上限前，先标明它是 transport、static business 还是 dynamic business；动态业务上限不得进入 Host 常量。
- 每个会改变可见本地意图的 preview 控件，至少覆盖成功、确定性拒绝、stale、timeout/断线四类结果；会写存档的 commit 另覆盖未知结果对账。
- 共享生命周期组件改动必须在至少一个真实消费者 harness 中用真实事件验证，纯函数单测只作补充。
- Dev harness、xUnit 和 AS2 TestLoader 是分层证据；没有实际 candidate + Flash socket + WebView2 的领域 E2E 时，不得把它们合称“已部署”或“正式验收”。
