## 已冻结范围

- NativeHud `GAMESETTINGS` 与 AS2 `openSettings` 都进入同一个 Web-only `settings` Panel；旧 Flash 设置界面仅保留不可达资产。设置在 1024×576 anchor 内全屏铺满，明确复用游戏启动前 Launcher Web 壳的 DLS 青、锈红、骨白、品牌铭牌、终端状态与编号页签，不使用双栏 Workbench shell。
- 游戏端权威为 15 项设置与 35 项键位，包含“奔跑键/组合键”；性能只保留 `0/1`，历史 `2/3` 归一为 `1`。
- 游戏设置/键位使用草稿与“应用并保存”；音量支持即时 preview 和界面音效试听，放弃、关闭、重绑或断线后 30 秒 expiry 恢复。
- 镜头倍率用进入设置时的单帧 Flash 静态快照，在全屏二级模拟器中相对入口倍率做等效缩放；不是实时画面。截图保留 16:9 内容区的物理输出尺寸，不再生成 `512×288` 代理；DPI Unaware Flash 在高 DPI 显示器上的较小逻辑 GDI 源会先还原到该物理尺寸，入口基线再铺满预览视窗，放大时继续使用还原后的自然像素。最大接受 `4096×2304 / 8 MiB`，超限、均匀近黑或捕获失败时明确降级为无预览。关闭动态镜头仍固定应用基础倍率，不能再把它误解成“关闭缩放”。
- Launcher 偏好逐项即时落盘，Web 偏好复用各面板既有 localStorage key；点歌器 Flash 规则和 Web 主题统一放在“本机与 Web”。
- 顶层导航只保留“游戏 / 键位 / 本机与 Web”三页，并与品牌、同步状态放在同一顶栏；不再单独占一行。作弊后端所有模式可用，游戏页首屏已有紧凑输入、二次点击执行和帮助入口，不再维护重复的“作弊码”专页。指令由 `launcher/web/help/cheat-codes.md` 维护并在模态帮助中逐条一键复制，挑战模式只展示三条模式切换帮助。复制不执行，常用命令一键执行按钮留给修改器迁移。
- 强制控制只保留“尝试复活”和“返回基地”，放在默认游戏页首屏且都是单击执行；不重复安全退出，不直接改 HP 或绕过复活限制。
- KeyManager 订阅按逻辑键名跟随重绑定。双 Number 位掩码/输入协议优化不在本轮，后续用独立 benchmark 决定。

## 第二轮体验打磨

- 修复了“进入设置后没有截图”的首要代码原因：旧判定只看平均亮度，暗色基地画面可能被误判为空黑帧；现改为同时检查亮度跨度、方差和高亮采样，并补充接受/拒绝数值日志。
- 设置根壳已从双栏 Workbench 默认样式切换为游戏启动前 Launcher bootstrap 语言；共享的是现役启动器令牌，不复制第二份近似配色。
- 键位页改为左右两列分区板，组内使用 2/3 列紧凑网格；1024×576 与 1600×900 自动检查均确认 35 项同屏、内容区无纵向滚动。
- 这仍不是物理 WebView2 + 真实 Flash 捕获证明。若本轮真机仍显示“未捕捉到图片”，请保留同次打开对应的 `[PanelHost] settings entry preview sample:` 与 `settings entry preview encoded:` 日志行，用于区分无窗口、空白帧、编码失败或 Web 消费失败。

## 第三轮体验打磨

- 默认游戏页改成单个“游戏常用设置”首屏：流程救援、声音、画面/性能和作弊码都无需切页或滚动；镜头缩放降到其后的二级入口。
- 作弊码首页入口只提供输入、二次点击执行和完整帮助，不增加回血、等级等一键包装，因此没有提前吞并修改器迁移的功能边界。
- 键位键名与键值均提升到 12px；35 项继续同屏的空间来自缩短摘要标题区、组间距与文字—控件空白，自动门同时限制逐行最大空隙不超过 9px。
- 镜头倍率改为全屏二级模拟器。预览以首次权威 snapshot 的倍率为入口基线，0.6× 会明显缩小、2.2× 会明显放大裁切；“动态镜头关闭”只改变模式说明，不再吞掉基础倍率效果。

## 第四轮体验打磨

- Host 不再把进入帧缩成 `512×288`：现在按原始 16:9 裁切尺寸以 JPEG quality 90 传递真实宽高，并在 `4096×2304 / 8 MiB` 边界外拒绝，不静默降质。Web 也按同一宽高、比例和长度合同 fail closed。
- 全屏镜头预览的图片不再继承旧内联窗尺寸；入口基线的宽高都铺满 16:9 视窗，倍率只负责中心缩放与裁切。自动门同时检查自然尺寸仍为 fixture 的 `1024×576`，避免回退低清代理。
- “游戏 / 键位 / 本机与 Web”三页已并入 Launcher 顶栏，删除独占一行的导航和重复“作弊码”页；作弊输入与帮助直接留在游戏首屏。
- 常态页删去内部实现说明和重复帮助文案；流程救援、保存、镜头、键位等说明改用项目共享 `PanelTooltip`，支持鼠标悬停与键盘聚焦，面板内不保留原生 `title`。

## 第五轮体验打磨

- 真人截图对应的 Host 日志确认输出位图为 `1600×900`、编码后 `218015` 字符，但这只能排除 Web 端 `512×288` 代理，不能证明 Flash client DC 已写满输出；随后第六轮闭环确认采集端还存在一个独立 DPI 虚拟化缺陷。第五轮同时定位到模拟器 CSS 遗留的 `max-width:720px`，它会使 1.0× 只占左侧舞台约 65%。
- 已移除固定宽度帽。入口帧现在按 16:9 在舞台宽高共同允许的范围内取最大尺寸：1600×900 自动场景中为 `1096.875×616.992`，占舞台可用宽度约 98.9%，剩余窄边来自等比高度约束，不再出现截图中的大片黑区。
- 视觉门新增“预览至少利用 95% 舞台可用宽度”断言；旧 720px 布局会直接失败，避免以后再次出现“图片填满了一个过小容器但测试仍通过”的假阳性。

## 第六轮 Agent Runtime 专项闭环

- 增加了 production allow-list 内的 exact `settings` 与 `settings_camera_preview` 诊断入口；后者只能映射到同一设置实例的固定 `initialView:"camera_preview"`，等待权威设置 snapshot 后进入二级页，不接受自由参数，也不应用或保存设置。
- 闭环不再用最小 `session.status` 猜 Flash 是否就绪，而是通过 metadata-only grant + `window.list` 等待 surface 从启动期 `200×101` 稳定到约 `1601×900`，随后再用 fresh WebOverlay WGC 读取镜头页原生 BGRA。输入安全仍保持 fail-closed，没有为调试放宽 foreground guard，也没有为嵌入 Flash 增加 pixels/input 能力。
- 修复前原生 `1600×900` WGC 帧整体纯黑 `55.96%`，右侧 1/3 为 `96.09%`、底部 1/3 为 `98.13%`。这证明黑区已经被烘进 Host 生成的入口图，而不是预览窗缩放或 Agent Runtime 降采样。
- Host 日志确认根因：Flash 为 DPI Unaware，`windowDpi=96`、`monitorDpi=144×144`；PMv2 Host 看到的物理 output 是 `1600×900`，但 Flash GDI client DC 只有约 `1067×600`。旧代码直接请求 `1600×900 BitBlt`，未写入的右侧和底部保持黑色。
- 当前实现只对该 DPI 虚拟化模式逐轴计算 source，并用 HALFTONE `StretchBlt` 还原到物理 output；其他 awareness 保持 1:1，GDI 返回 false 时显式失败。修复后同一闭环整体纯黑降到 `4.50%`、右侧 1/3 `7.84%`、底部 1/3 `3.65%`，有效活动范围覆盖宽高 `99%+`；机器证据已关闭大片黑边，锐度与整体缩放感仍留给本单的人类观感验收。

## 人工旅程（约 12–18 分钟）

1. 从 NativeHud 打开设置，再关闭；随后从 Flash/AS2 设置入口打开。两次都应进入同一铺满可用 anchor 的 1024×576 Web Panel，四周不再保留旧卡片式空白，旧 Flash 设置 MovieClip 不应出现。检查品牌铭牌、终端状态、DLS 青/锈红/骨白和切角结构是否与“启动游戏前”的 Launcher Web 壳属于同一语言，而不是双栏 Workbench；三页切换应直接位于同一顶栏，内容应紧接顶栏开始。
2. 使用一个历史 33 键存档或等价测试档。确认所有名称可读，绝不出现 `undefined/null`；原自定义键保留，“奔跑键/组合键”补到末尾；应用、保存、完整重启后仍是 35 键。1024×576 下 35 项应同屏可达且无需滚动，键名/键值大小应适合窗口模式阅读，按键控件应紧邻对应文字而不是隔着大片空白；若当前档有重复/保留键，面板应能打开并逐项修复，而不是整页拒绝。
3. 在键位页验证：绑定重复键会被拒绝且不自动交换；Esc 只取消捕获；F1–F12 被拒绝。改一个真实战斗键后，立即验证普通按下、长按/连发或相关组合订阅跟随新键，旧物理键不再触发。
4. 拖动总音量/BGM，听是否即时且不过度打扰；点击“试听界面音效”。分别验证“放弃游戏改动”、右上角关闭和等待断线 expiry 后恢复原音量。再应用新音量并重启，确认真实读回。
5. 确认性能选项只有 `0/1`。用历史 `2/3` 档打开时应显示 `1` 和迁移提示；应用保存并重启后不再重复提示。滚到常用区下方打开“镜头预览”：入口倍率下截图应在保持 16:9 的前提下占满左侧舞台，不得再次只显示成约 720×405 或在右侧留下大片黑区，也不得拉伸；细节锐度至少与进入设置时的 Flash 原始画面一致。再分别调到约 0.6× 与 2.2×，确认静态入口帧明显缩小和放大裁切。关闭动态镜头时基础倍率仍必须生效；开启动态镜头只改变游戏运行模式说明，不应重置倍率。Esc 应关闭二级页并把焦点还给入口按钮；再次进入设置应取得新入口帧。
6. 修改 Launcher 音效/环境音、地图显示、片头与启动页字号，再修改技能确认、调制确认、任务对话、点歌器主题、五子棋音轨和全部物品密度（含竞技场）。确认点歌器三项 Flash 规则也在同一页，且仍由底部应用保存；Host 项应立即反馈保存/回滚。重开相关长驻 Panel、必要时重启，确认消费者读取新值。
7. 不切页，直接用游戏首页作弊码输入执行一个只读命令，确认第一次点击只进入待确认、第二次才执行；再从同一行打开帮助，确认等级调整 `#level:15` 和其他现役指令齐全。任选一条点击复制，确认剪贴板内容精确且没有自动执行。顶层不应再出现重复“作弊码”页；挑战模式确认输入后端仍可用，但帮助只剩 `hardmode/easymode/challengemode`。不得出现 `/console` 或回血/升级等快捷修改器按钮。
8. 打开设置后不切页，确认首屏立即可见“尝试复活/立即返回基地”。在关卡结束/死亡场景单击“尝试复活”：只应重新拉起现役询问复活流程，复活限制仍由原流程处理。再单击“立即返回基地”，应无额外确认、立刻跳过当前流程并由 Host 精确关闭 Panel。
9. 在试听中、保存中和普通空闲态分别尝试 Esc、背景点击、右上角关闭、重复打开/重绑和短暂断线。不得出现卡住的暂停、幽灵 Panel、旧实例回包覆盖新页或音量长期滞留。

## 需要反馈的体验问题

- 启动器壳视觉是否已经对题；游戏页常用区能否在不缩字的前提下首屏完成，键位 12px 字号与紧邻控件是否已经兼顾可读性和密度？
- 音量拖动 preview 的节奏、试听音效响度和反馈是否自然？
- “应用并保存 / 放弃 / 重试保存”的关系是否一眼可懂？
- 键位冲突、保留键、迁移提示和捕获状态是否足够显眼？
- 全屏静态镜头模拟是否足以理解倍率，还是仍会误解为实时画面？0.6×/2.2× 的缩放中心、外围提示和裁切感是否接近游戏实际结果？
- 入口截图是否真正铺满预览窗，锐度是否已经达到原始 Flash 捕获分辨率；放大后是否仍有明显的低清代理感？
- 首页作弊码输入是否足够顺手且不过度抢占注意力；帮助分组、复制按钮和执行二次确认是否自然，挑战模式的模式切换帮助是否容易发现？
- 常态页面删减文案后是否更清爽；鼠标悬停或键盘聚焦时的通用注释是否及时、位置合理且没有遮挡关键控件？
- “尝试复活 / 立即返回基地”的首屏位置、颜色和单击反馈是否符合高频救援用途？
- Launcher/Web 偏好聚合后，是否仍有一个常用偏好找不到或生效时机不清楚？

反馈最好按“场景 → 操作 → 预期 → 实际 → 主观感受”给出；截图或短录屏只需覆盖有问题的节点。收到反馈后的下一轮先做体验打磨并复跑受影响门，得到人类确认后，才进入中文 commit、正式 deployment build、push 与后续发布流程。
