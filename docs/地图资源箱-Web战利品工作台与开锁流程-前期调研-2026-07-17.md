## 0. 一页结论

方向**可行且值得做**，治理顺序应先建“场景瞬态战利品容器”的权威闭环，再把 Lockbox 作为部分高价值箱子的前置开锁步骤。不建议先把 Lockbox 硬接到旧 AS2 资源箱小窗口：这会形成一次性跨栈胶水，后续迁 Web 时仍要重做容器寻址、生命周期与奖励提交。

立项时确认的 legacy 基线（仅用于解释迁移动机，不代表当前实现）：

- 箱子互动当时是同步路径：按下互动键后立即 `publish("kill")`，地图元件当场标记 `_killed=true`。
- 网格箱不是“地面拾取格”：开启动画帧才即时创建 `new ArrayInventory(null, row * col)`，然后打开旧 AS2 `资源箱界面`。
- 该 legacy 临时库存无稳定 `containerId`、不在 `InventoryPanelService` 容器注册表内，当时无法被 Web inventory-domain 权威寻址。
- **立项时已存在奖励丢失缺陷**：多个箱子同时与玩家 area 相交时，一次全局 `interactionKeyDown` 会被每个箱子独立消费；它们同时开箱后又重用同一个 AS2 `资源箱界面` 实例，后到库存会覆盖界面绑定，使先前的临时库存不再可达。当前中央裁决已按数据安全缺陷处理该 fan-out，而不是把它留作 UI 优化。
- Lockbox 当时已有正式 Web panel、确定性 core / solver / generator、音频与 QA，但普通 `minigame_session` 只到 Host 日志，不回 AS2、不提交奖励。
- XML DOM 排除注释后，当前有 28 个相关 `Identifier` 条件分支声明，落在 27 个实际 `Instance` DOM 节点；按 `文件 + SubStage id + Instance id` 折叠后为 26 个逻辑实例身份。“夺取材料”一个 DOM 节点在修罗难度为装备箱、否则为资源箱；“超市废墟”有两个实际节点复用同一 `Instance id`，分别只对互斥的主线进度 3 与 4—5 有效，因而归为一个逻辑身份。按逻辑身份与难度分支投影，修罗为网格 9 + 直投 17，非修罗为网格 8 + 直投 18；其他进度门还会继续缩小当时可见数。

当前工作树由中央箱候选先限定六类箱体领域，再由 `LootContainerService` 承接域内全正网格 intent；准入后的箱型名、当前三种尺寸、地图与 rollout ID 都不参与 shape 选择。直投箱与保险柜破碎保留地面掉落；已 reservation/materialized/active/suspended 的同 target 由 break guard 拦截重复奖励。当前协议、状态机与验证证据以 S0/S1S2 ADR、[AS2 UI 到 Web Panel 迁移护栏](../agentsDoc/as2-web-panel-migration.md) 和 [验证矩阵](../agentsDoc/testing-guide.md) 为准。

推荐目标流程：

```text
互动箱子
  → AS2 创建 chestSession（暂不 kill）
  → Web Lockbox（可配置跳过）
  → 一次性开锁结果回到 AS2
  → AS2 复核 session 并驱动开箱动画
  → 开盖帧由 AS2 滚落物并注册 lootContainer
  → Web “背包—战利品箱”双栏
  → 空箱 consume / 非空 suspend 或明确放弃 / 场景失效后按对应状态收束 lootContainer
```

本治理候选的“审慎”含义是：批准后冻结权威边界、数据安全不变量、可解释终态、未知写对账、持久化验收和发布门；feature-specific wire 字面量、panel 拓扑、领域超时与玩家文案仍须按阶段取证，但共享工作台的布局 profile、焦点栈、生命周期、响应监听所有权、CSS 与验证门已经由 canonical 规范冻结。批准后的任何阶段都不得以“只是 spike”为由绕过一次性消费、零重复滚奖和无静默吞奖三条底线。

### 2.3 旧资源箱 UI 的数据语义

1. `掉落物转换为物品栏` 在开启帧一次性滚落物，随后把 `target.掉落物 = null`。
2. 容器是真实 owned `ArrayInventory`，但只被 UI 图标和 `IconFactory.inventoryContainerDict` 间接持有，没有可跨 AS2/Web 请求的稳定地址。
3. 旧 `InventoryIcon` 允许在已显示的 `ArrayInventory` UI 间拖动；K 点、材料、情报存在点击即领取分支。legacy 货币路径有一处必须显式纠正的缺陷：正式物品内部键是 `金币`、展示名才是“金钱”，但旧分支比较 `this.name === "金钱"`，合法 `BaseItem("金币")` 因而不会命中。`ItemUtil` 还把 `经验值 / 技能点` 作为经济伪物品处理，旧资源箱 UI 没有对应显式领取分支。新服务不得复制这份不完整 / 错键的 legacy 判定。
4. 临时容器不入存档。窗口或场景销毁后，未取走内容没有对账 / 恢复机制。
5. legacy 数据容量与视觉网格存在历史隐患：`ArrayInventory` 构造和旧 UI 对过小 / 过大 `row×col` 的处理不是同一处约束。
6. **多箱覆盖的确切机制已确认**：
   - 每个箱子都用 `subscribeGlobal("interactionKeyDown", ..., target)` 独立订阅同一全局输入；现有路径没有“本次输入唯一互动目标”裁决器。
   - 同时命中的箱子都会 `publish("pickUpBox") → publish("kill")`，因此问题不是玩家手动快速点了两次，而是一次输入的 fan-out。
   - `_root.从库中加载外部UI("资源箱界面")` 以固定 identifier 作 MovieClip 实例名；已有实例时直接返回同一对象，不新建窗口。
   - `IconFactory.createInventoryLayout` 发现同一 UI container UID 已注册时，调用 `resetInventoryLayout` 将其 `inventory` 改绑到新对象并重置既有图标。旧临时库存失去可达 UI，其未领奖励因而丢失。

### 2.4 已知缺陷的修复不变量

新路径在 S0 开始就必须满足：

1. **一次互动输入最多提交一个箱子**。多个箱候选同时命中时，由中央裁决器以稳定规则选一；具体排序在 S0 冻结且必须可确定性复现。箱子身份只由 `target.presetName` 的显式白名单 `保险柜 / 生存箱 / 装备箱 / 资源箱 / 纸箱 / 隐藏资源点` 判定，不得用默认 `row/col` 把投影召唤器等非箱元件误分类。
2. **同一时刻最多一个 active chest / loot flow**。首版遇到第二个请求应拒绝或保留为 `AVAILABLE`，不得提前 kill，也不得把新容器重绑到旧 session。
3. **未被选中的邻接箱子必须保持可互动**。当前 flow 完成 / 关闭后，玩家可再对其发起新会话。
4. **每个已创建的 loot container 必须有独立身份与状态**。即使异常路径生成了第二个容器，服务也必须拒绝覆盖；最终终态只能是 `CONSUMED / ABANDONED / EXPIRED`，非空正常 close 可暂处非终态 `LOOT_SUSPENDED`。
5. **不用“多开几个 Web 窗口”作为首版修复**。核心问题是输入唯一性与数据生命周期；窗口并行会反而放大暂停、焦点、奖励对账和放弃语义。
6. **中央裁决覆盖所有互动箱，但不改变 direct 奖励分支**。`row/col` 任一非正的资源箱、纸箱、隐藏资源点仍走既有直爆逻辑；两个直爆箱或直爆箱与网格箱重叠时，同一次输入也只能选择一个，未选中的目标保持可互动。
7. **跨消费者优先级在 S0 冻结**。`SceneInteractionManager.currentMC` 是显式场景互动，它对箱候选具有独占优先级，禁止同键又开 chest flow。非箱 `InteractionHandler` 目标（如投影召唤器）和地面 `PickUpManager` 在 S0 显式保留 legacy 共消费：它们可与当次裁决胜出的唯一箱子同时生效，但不能导致第二个箱提交。这是为了不借箱子修复暗中扩张为全游戏互动重构，必须有混合 fixture 记录；以后若改为全局互斥须单独 ADR。

### 2.5 Lockbox 的当前边界

可复用部分：

- 正式运行目录：`launcher/web/modules/minigames/lockbox/`。
- 确定性核心、solver、generator、变体数据、Web panel、音频、Node QA 与 browser harness 都已存在。
- `onOpen(initData)` 已接受 `profile / source / familySeed / variantIndex`，可承载箱型映射与可重现 seed。
- panel 打开已进入通用 `webPanelPause` 暂停 lease，不需要另造小游戏暂停系统。

仍未具备的生产能力与当前 S0 边界：

- 普通生产 `minigame_session` 只被 Host 解析并写日志，没有 AS2 action / response 闭环；S0 的专用 dev wire 与它隔离。
- Web 生成的 `sessionId` 不是 AS2 箱子实例签发的一次性权威 token。
- 普通 Lockbox result 以及 S0 的无奖励有限 result 均不可直接当奖励 commit 凭证。
- S0 actual wire 已按 ADR 接入真实源码；基于 `a8a760a3cc` 的 `chest-s0-a8a-local-r3/r4`、FCA19 及其他旧隔离 candidate 均只保留为历史诊断。dormant S0 Host/source 已进入本轮 promoted tree/runtime，但 S0 双开发门保持关闭，也没有运行 S0 exact 双-marker。xUnit、Node、Browser shim、TestLoader、promotion、标准入口的 loot smoke 或基础握手都不能写成“S0 feature E2E”；中央裁决器不是默认断开的模型，它随 AS2 发布后会改变六类箱的全局选择行为，仍须单独做玩家可达 actual-feature 与全局回归。
- `PanelHostController` 现为 S0 提供调用方预留 `requestToken + flowHandle + panelInstanceId + documentEpoch` 的 tracked queue、执行前 recheck 和可观察 `PostToWeb` 结果；只有 Web 回传 exact bind 才视为已打开。bind timeout 仍按 `OPEN_BIND_UNKNOWN` 处理，只能 exact query / close，不能猜测 unbound。
- S0 同名 / 重复 open 在身份分配和映射替换前 fail closed，不复用通用 rebind；Web 的 stale instance / epoch 消息不能改变当前 flow。
- `minigame_session` 仍只是观测信封，不具备 call / ack / active-instance 业务语义；Host 入口先做精确归一化和去敏，S0 持有 pause 时消费所有小游戏信封，pause 释放后仍消费所有 Lockbox 信封。只允许有限四字段 telemetry，畸形 Lockbox 固定丢弃且不得序列化原始 payload、session、handle、fixture 或奖励 descriptor。S0 业务继续走受 dev gate 保护、不可 HTTP 调用的专用实验 task。
- Host 已在 active / unknown flow 期间拦截通用 unpause 和其他 panel 编排。Web DOM teardown、native `PanelHost` close 与 AS2 权威终态是三项独立证明：socket 断开或 native close 不能冒充 DOM close ack；只有对应状态所需的证明全部收齐，才可尝试释放全局 pause。外部 pause-release 回调若失败，Host 必须保留 terminal flow、identity 与已收齐证明并继续重试；只有回调已成功，才可 reset coordinator 并签发 fresh arm。
- Host reconcile 已改为按 `OPEN_BIND_UNKNOWN / REVOKE_PENDING / RECONCILE_REQUIRED / RESULT_APPLIED / KNOWN_TERMINAL` 状态驱动：重复发 exact bind/close query，直接向 AS2 作因果 authority query，在 result 已应用后只轮询终态而不重放写，并重放最后一份 Web 权威投影、重试 exact native close，直到各层证明收敛。bind、result、正常 close 与 force-teardown 的 ack 丢失都保留原 identity 并有重试路径。
- `webDocumentEpoch` 已由 Host 单调生成并绑定 arm/open/bind/result/query/close。只有同一待处理 `NavigationId` 依次观察到 `ContentLoading` 和成功 `NavigationCompleted`，才可把旧 DOM 记为已 teardown；失败、ID 错配、same-document 或 fragment 导航均不得释放旧 flow，导航未决时也不接受 Web 消息或 begin。导航开始会原子失效尚未消费的旧文档 arm，完成后只能用 fresh capability 重臂；begin 预留与 open execution gate 均与 navigation-pending 状态串行。
- `dev_lockbox_s0` 在 `XmlSocketServer` 的 dedicated handler 中先于 `MessageRouter` 截获，普通 Web、HTTP、TaskRegistry、console 与 `minigame_session` 均不可调用；畸形专用 JSON也在原文日志前 fail closed，capability 只记摘要。
- AS2 独立门已冻结为 authored target 的 exact `chestS0As2GateId === "local-as2-dev-s0-v1"`，并与 `chestS0FixtureId / preset / row / col` 一起观察；Host bootstrap 不能替代该门。socket disconnect generation 进入单调 high-water：任何 `Ready <= high-water` 永久拒绝；观察到高于 live 的 disconnect，即使尚未见对应 Ready，也要推进 live generation、作废旧 binding/retry 并请求 exact native close，但仍不得伪造 AS2 terminal 或 DOM proof。scene teardown 释放 target 并保留最小因果 tombstone。same-process 新 generation 以 fresh capability/bootstrap 显式区分 `resumeActive=false/true`：false 只把本地孤儿 pending 按已知 no-write 收束，true 才恢复 Host 已持有的 exact active identity，且 `resumeActive=true` capability 绝不能被新 begin 消费；旧 capability 不跨 generation 复用。
- panel busy 不预分配或污染新 identity；原 panel 回到 idle 后必须重新 arm，下一次请求才以 fresh identity 进入 tracked open。LazyLoader 已处于 `LOADING` 时的 `wire_loading` 也是 transient arm rejection：fresh arm 不抢占旧 LOADING owner、不触发第二次 load，Host 只在 loader / queue settle 后用 fresh capability rearm；它不是已知 open/bind failure。
- S0 仍无玩家可达双 marker、真实 XFL 目视或游戏内混合证据，也仍不提供任何真实奖励、loot container 或持久化能力。dormant S0 Host/source 虽已随正式身份部署，但双开发门关闭且未运行 exact fixture，故不能把 promotion 或本轮 loot canary smoke 写成 S0 actual-feature 跨栈；`a8a` r3/r4、FCA19 与更早 v1 candidate 仍只作历史诊断。

## 4. 推荐权威边界

### 4.1 AS2 是箱子与奖励 SOT

AS2 应继续决定：

- 当前场景、箱子 MovieClip 和角色是否仍可互动。
- 箱子类型、进度门、是否已开启 / 被击碎 / 正在处理。
- 掉落概率、PRD key、数量、`总数` 消耗与 `BaseItem` 构造。
- 临时 `ArrayInventory` 实例、物品移动 / 领取与存档 `dirtyMark`。
- chest / loot session 的签发、一次性消费、注销和过期拒绝。

Web 不应自行滚奖励，也不应把 Lockbox 分数 / 评级直接换算成物品。如需将开锁表现影响奖励，应由 AS2 根据经验证的有限档位（例如 `base / bonus`）重算，而不信任 Web 上送任意数值。

### 4.2 Host 是运输与 panel 生命周期边界

Host 应负责：

- 在 AS2 `panel_request` 与 Web panel 之间传递只读 initData。
- 把结构化的开锁 result 转成明确 AS2 action，再把 AS2 的最终接受 / 拒绝回到 Web。
- 管理 panel 打开、替换、关闭、暂停 lease，以及按 AS2 authority 状态执行断线恢复或清理。
- 记录去敏的 session 观测信息；不将完整奖励内容或可重放 token 泄漏到常规日志。

### 4.3 Web 是展示、输入与意图层

Web 应负责：

- 渲染 Lockbox 与 loot 双栏，发送用户意图。
- 进行本地 UX 预检、pending 锁定、超时后对账和友好错误展示。
- 保持 `containerId + physicalSlot + lease` 地址，不从 DOM 位置推断物理槽位。
- 将 `金币 / K 点 / 经验值 / 技能点 / 材料 / 情报` 显示为 AS2 snapshot 投影，通过明确 claim 意图领取；wire 使用内部稳定键，玩家文案才使用“金钱”等 displayName。

### 4.4 信任模型与非目标

首版安全目标是抵抗跨栈协议中的畸形、迟到、重复、断线未知结果与旧 session 重放，并保证 Web 无法夹带物品、数量、货币或任意 bonus 直接写入经济。AS2 只接受当前 active chestSession 绑定的有限结果枚举，复核箱子 / 场景 / 变体绑定并一次性推进状态；奖励内容始终由 AS2 在开盖帧滚动。

本地单机环境下，首版**不声称抵抗玩家主动修改 Web、Host 或 AS2 进程**。Web 上送的“已完成 Lockbox”在该威胁模型中是受 session 约束的本地完成意图，不是对玩家实际操作过程的密码学证明。若以后要求抗本地篡改，必须另立 ADR，定义可复核动作轨迹 / 终局证明、验证方和性能预算；不得把 `sessionId + success` 白名单误写成“已防伪造”。

无论是否扩展抗篡改，result 都不得包含奖励 descriptor、任意奖励倍率或可直接兑换的分数。未来若允许表现影响奖励，只能上送有限档位意图，再由 AS2 按本地规则重算并裁决。

## 5. 推荐状态机

### 5.1 箱子会话

```text
AVAILABLE
  │ interaction + AS2 revalidate
  ▼
LOCK_PENDING ── known cancel / gameplay failure / pre-materialization failure ──► AVAILABLE
  │ verified success / configured skip
  ▼
OPENING_ANIMATION
  │ XFL open-frame callback
  ▼
LOOT_COMMIT_PENDING [opening reservation]
  │ materialize once + register + bind
  ▼
LOOT_ACTIVE
  ├─ remaining <= 0 + close ────────────────────► CONSUMED
  ├─ non-empty + close(abandon=false) ──────────► LOOT_SUSPENDED
  │    └─ same scene + exact target anchor reopen ► LOOT_ACTIVE
  ├─ non-empty + close(abandon=true) ───────────► ABANDONED
  ├─ safe scene / authority invalidation ───────► EXPIRED
  └─ panel/mount/connected/socket detach ───────► LOOT_COMMIT_PENDING [transport detach]

LOOT_COMMIT_PENDING [claim journal / transport detach]
  │ causal lootQuery → effects → suspended/terminal pause handoff
  ├─ any proof incomplete ──────────────────────► LOOT_COMMIT_PENDING
  ├─ all proofs + remaining items ──────────────► LOOT_SUSPENDED
  └─ all proofs + authoritative empty ──────────► CONSUMED
```

异常边：

- `LOCK_PENDING / OPENING_ANIMATION` 或尚无可恢复 inventory 的 opening reservation 遇 authority 销毁时可以进入 `EXPIRED`，后续 result / callback 零副作用；一旦存在 exact claim journal、mandatory effects 或 `transportDetachNeeded`，scene cleanup 必须返回 `commit_pending` 并保留 authority，禁止越过证明链写终态。场景清理现在是 teardown barrier：`SceneManager.removeGameWorld():Boolean` 在 `expireScene()` 未成功时必须在任何 inactive/dispose/dispatcher/gameworld teardown 前返回 `false`；根场景淡出时间线立即停止，只排一个下一帧重试，成功后才继续播放。`cleanupForRestart():Boolean` 也必须在任何 manager dispose 前先做 loot preflight，失败时保持整个 runtime 原样，禁止形成半清理。
- 已知取消、已知玩法失败或**物化前**的 panel failure 可以撤销当前 attempt 并回到 `AVAILABLE`；当前 `chestSession` 随即失效。S1/S2 已物化后的 panel open/mount failure、connected recovery 与 socket detach 不适用该边：它们必须在原 session/container 上进入 persistent transport pending。迟到的旧 result 永久 stale，不得在原 session 上重放玩家写意图。
- Web / Host 断线不可默认视为成功或失败。若提交结果未知，必须查询 AS2 当前状态；查询必须证明在未知请求之后处理，或返回 AS2 已接受的 call / commit 身份。只有跨过该因果水位且 AS2 明确仍为 `LOCK_PENDING`、原请求确定未提交时，才允许用户发起新意图。
- S0 开锁 flow 的 panel bind ack timeout / 断线仍是未知写：chest 保持 `LOCK_PENDING`，Host candidate 投影为 `OPEN_BIND_UNKNOWN`，单 active flow 与 pause lease 继续持有。只有 exact flow / instance 的因果查询证明未 bind，或 exact instance 已关闭并获得 ack，才将 attempt 撤销回 `AVAILABLE`；证实已 bind 就恢复原 panel，不签第二 session。S1/S2 loot 不复用该 S0 result wire，而按上一条进入同对象 transport recovery。
- 重复成功回包：只有首个合法 commit 能将状态从 `LOCK_PENDING` 推进，后续返回“已提交 / 状态已前进”语义，不得误用表示奖励已取空的 `CONSUMED`。
- 已有 active chest / loot flow 时又收到箱子互动：新目标保持 `AVAILABLE`，返回可观测 busy，不发布 kill。S0 当前各层模型字面量分别为 AS2 `busy`、Host `Busy`、Web `flow_busy`；在 production wire 冻结前不得把其中任一字面量冒充跨栈正式协议。
- `LOOT_ACTIVE` 或 `LOOT_SUSPENDED` 的墙钟不活动超时不得自动进入 `CONSUMED` 或 `ABANDONED`。`close v1` 固定为 `remaining<=0` 优先 `CONSUMED`（包括 `abandon=true`）、非空 `abandon=false` 为 `LOOT_SUSPENDED`、非空 `abandon=true` 才为 `ABANDONED`；只有场景 / authority 安全失效才可进 `EXPIRED`。
- 每个终态至少在当前运行期保留 `{sessionId, terminalKind, reason, remainingCount}` 的去敏审计记录；不记录完整奖励 descriptor 或可重放 token。
- `LOOT_COMMIT_PENDING` 是 AS2 内部的逻辑原子边界，必须区分 opening reservation、exact claim journal / mandatory effects、persistent transport detach。opening 先铸造一次性 open-commit 身份，把已物化奖励计划 / 容器引用挂到 session，再完成注册与一对一绑定；claim 只按 exact operation/fingerprint 对账并前滚；transport 只按 causal query 完成 journal、effects 与 suspended/terminal pause handoff。初次与 reopen failure 都保留同一物化结果和 anchor，非空回 `LOOT_SUSPENDED`、空回 `CONSUMED`、anchor 失效回 `EXPIRED`；任一步骤未完成都留在 `LOOT_COMMIT_PENDING`。Flash renderer、claim-only adapter 与 observer recovery 不得旁路该硬栅栏。

### 5.2 战利品容器会话

```text
REGISTERED / LOOT_ACTIVE
  └─ claim accepted ───────────────────────────────► LOOT_COMMIT_PENDING [claim journal]

LOOT_COMMIT_PENDING [claim journal]
  ├─ known no-write proof ─────────────────────────► LOOT_ACTIVE
  ├─ exact causal query settles journal/effects ───► LOOT_ACTIVE
  └─ transportDetachNeeded ────────────────────────► LOOT_COMMIT_PENDING [transport detach]

LOOT_COMMIT_PENDING [transport detach]
  └─ causal query: journal → effects → suspended/terminal pause handoff
       ├─ any proof incomplete ────────────────────► LOOT_COMMIT_PENDING
       ├─ proofs complete + non-empty ─────────────► LOOT_SUSPENDED
       └─ proofs complete + empty ─────────────────► CONSUMED

LOOT_ACTIVE
  ├─ remaining <= 0 + close ────────────────────► CONSUMED
  ├─ remaining > 0 + close(abandon=false) ──────► LOOT_SUSPENDED
  │    └─ same scene + exact target anchor reopen ► LOOT_ACTIVE
  ├─ remaining > 0 + close(abandon=true) ───────► ABANDONED
  └─ safe scene/authority teardown，且无 pending ─► EXPIRED
```

容器 ID 只要求 session-scoped 唯一，不要写入长期存档。建议逻辑形状为 `loot:<sceneEpoch>:<sequence>`；具体字面量须在 S1 协议评审后冻结。

容器规则：

- `CONSUMED` 只表示 AS2 权威确认容器已空并正常结束；不能表示“窗口关了”。
- `LOOT_SUSPENDED` 是非终态，不能表示 detach、recovery 或已放弃。它只在同一 scene、同一 target anchor 下允许再次互动，复用同一 `{chestSessionId,lootContainerId,containerEpoch}` 与同一 inventory；重开必须签发 fresh `closeLease/panelInstanceId/openAttemptSeq`，旧 lease/instance/attempt 的迟到消息零副作用。AS2 open initData 含 attempt，Host binding 保留但投 Web 时剥离；Web 业务信封不新增该字段。不同 target 仍受单 active-flow busy 约束，跨场景或 Flash/Launcher 重启不持久化。
- recovery proof 与普通业务查询必须保持三种不可混用的 exact shape：Host→AS2 `lootPanelRecovery` 是严格八键 `{task,action,chestSessionId,lootContainerId,containerEpoch,openAttemptSeq,recoveryNonce,reason}`，`reason` 只允许 `web_mount_failed / web_open_failed`；普通 Web `lootQuery` 仍是严格七键 `{task,action,callId,v,chestSessionId,lootContainerId,containerEpoch}`；仅 Host 内部 detached reconcile 可发送严格九键查询，即在七键上追加 `openAttemptSeq + recoveryNonce`。`recoveryNonce` 是 Host 生成的不透明关联证明，proof 字段不得投给 Web，也不得进入十五键 AS2 业务响应或二十键 Host 投影。普通七键查询不能结算 detached recovery；ACTIVE/pending mutation 只接受 exact attempt + nonce 或 exact socket-generation proof，而同 attempt 已安全 authority-close 为 suspended/terminal 后，九键只读查询可按完成证明投影，不能反向复活旧 binding。
- `ABANDONED` 只允许由玩家对当前剩余数量作显式二次确认后进入；确认请求同样需要新鲜容器状态，避免确认时内容已变化。
- `EXPIRED` 表示场景或 authority 已不再允许访问；必须保留失效原因与剩余数量，不能伪报为已领取。
- `remainingCount` 统一表示仍可领取的非空 source entry / slot 数，不是将各 `value` 相加。放弃确认必须同时投影新鲜 snapshot 中的真实堆叠量 / 特殊资产数额，不得用这一个计数伪装资产总量。
- 一个 chestSession 在运行期至多绑定一个 lootContainer，一个 lootContainer 也只能属于一个 chestSession。容器进入任一终态时，必须在同一 AS2 authority 提交中同步更新 chestSession 终态、撤销全部 lease、释放 active-flow owner 并生成回包；`LOOT_SUSPENDED` 不释放该 identity/inventory owner，但必须撤销旧 closeLease，等待 same-anchor reopen 重铸 lease/instance/attempt。attempt-bound pending 只覆盖本次 reopen 发出到 Host accepted callback；接受前失败恢复 suspended，accepted 后 exact-attempt 故障才可 recovery。不得让查询观察到“容器已终结但箱子仍 `LOOT_ACTIVE`”或相反状态。
- 任意终态的 snapshot / write / close 重入都必须零副作用并返回可对账状态。未知写结果只拉快照，不自动重放 move / claim / close / abandon。
- 普通 owned item 的转移必须无损保留 `BaseItem.toObject()` 描述符：`name`、深克隆的 `value`与 `lastUpdate`。装备的 `value.level / tier / mods` 等全部状态随描述符转移；禁止只用名称 / 数量重建一件“看起来相同”的装备。
- 特殊资产 claim 以 `{containerId, containerEpoch, slot, slotLease, callId}` 或等价唯一身份串行化。AS2 必须先预检查完整资产描述符与目标域，再建立可恢复 commit record，记录 source 与目标域的 before / expected-after 投影。只有目标增量、原有持久化副作用和 source 删除全部确认后才对外成功；中断时由记录完成或恢复同一提交。目标是 before 时才可安全执行，已是 expected-after 时只补完 source 删除，任何歧义都 fail closed 进入对账；禁止盲目再调一次 `ItemUtil.acquire`或先删 source 后调目标域。
- 用来解除未知状态的 query / snapshot 必须跨过 Host/Web 各自的单调 freshness watermark；只有 matching pending call/identity 的回包可用畸形或尚不能证明的更高 revision 抬高该 unknown operation 水位，不能直接变成已知 authority 或覆盖 last-known projection，其他 call/identity 不得抬高水位。普通“看起来较新”但低于水位的 snapshot 不得清除写门，后续 proof 也不得把模型回滚到水位以下；普通七键 query 不增加 `reconcileAfterCallId` 等 wire 字段。
- Host/Web 运输断线本身不是 AS2 容器失效条件。只要 Flash authority 与场景仍存活，必须保留原 `containerId` / inventory 与 target anchor，并取得因果新鲜的权威投影；初次与 reopen failure 统一收束为 `LOOT_SUSPENDED / CONSUMED / EXPIRED`，禁止重建容器、重滚奖励或显示 Flash 网格 UI。
- 单 active flow 与“非空不自动放弃”结合后，不得形成永久不可见死锁。`LOOT_SUSPENDED` 提供同场景同 target-anchor 的原 triple/inventory 重开；若 Web 链仍故障，就显式保持挂起和诊断，不用旧 UI 伪装恢复。

### 5.3 故障与恢复矩阵

| 故障点 | AS2 权威动作 | Host / Web 恢复 | 禁止行为 |
|---|---|---|---|
| **S0 / 未物化**：panel 尚未打开或明确打开失败 | 以同一 identity 撤销未消费 chestSession，箱子回 `AVAILABLE`，等待已知 ack | 收齐 Web 已知 unbound / exact close、AS2 已知撤销和 native exact close 后再恢复焦点、释放全局 `webpanel` pause lease | 先 kill、先滚奖、把失败当成功，或混用 DOM/native close proof；不得把该边套到已物化 S1/S2 |
| **S0 / 未物化**：panel DOM 可能已 bind 但 bind ack timeout / 丢失 | 保留 `LOCK_PENDING` 与原 chestSession，拒绝新箱 | Host 进入 `OPEN_BIND_UNKNOWN`，按状态重复 exact bind/close query；已 bind 则继续，只有 DOM + authority + native 三层收束后才撤销并释放 | 把 timeout 当已知未打开、签第二 session、提前 unpause 或只关视觉层；S1/S2 使用 transport pending |
| Lockbox result 已发送但回包未知 | 保留真实当前状态，提供跨过未知 call 的只读 session 查询 | 因果新鲜查询后投影 `LOCK_PENDING / OPENING_ANIMATION / LOOT_COMMIT_PENDING / LOOT_ACTIVE / terminal` | 用无 watermark 的旧读解除 pending，或自动重发旧 result |
| 开盖 callback 重复或回包未知 | 以 open-commit 身份幂等；至多物化一次奖励并绑定一个容器 | 查询 `LOOT_COMMIT_PENDING / LOOT_ACTIVE / terminal`，用同一物化结果继续完成 | 以动画帧重入重新滚奖，或注册失败后丢掉已物化奖励 |
| 容器终态提交中断 | 保持单一 authority 提交或可恢复 commit record，不暴露半终态 | 查询必须返回 chest / container 一致的 active 或 terminal 投影 | 先释放 flow 后终结容器，或先删容器后留下 `flow_busy` |
| 特殊资产 claim 在目标增加 / source 删除之间中断 | 保留唯一 claim commit record，对比 before / expected-after 后只补完未完成半边 | 投影 `WRITE_PENDING / RECONCILE_REQUIRED`，因果新鲜对账后才重开写 | 重调 `ItemUtil.acquire`、重新 claim，或在目标未确认时清空 source |
| 初次或 reopen 的 Web / Host 断线，Flash 与场景仍存活 | 保留原容器/anchor，先持久化 transport flag 并拒绝第二箱覆盖 | causal query 收束 journal/effects 后，非空回 `LOOT_SUSPENDED`、空回 `CONSUMED`、anchor 失效回 `EXPIRED`；同 anchor 可再次请求 Web | 自动 abandon、创建替代容器、重滚奖励或显示 Flash renderer |
| 写命令 timeout / 畸形回包 | 保留权威结果，允许带因果水位的 snapshot 对账 | 进入 `RECONCILE_REQUIRED`，只读对账越过 unknown call watermark 后再开放写 | 用普通 snapshot 提前解门，或网络层重放 move / claim |
| close / abandon 回包丢失 | 返回当前终态或仍 active 的权威状态 | 查询终态并重放权威投影；已终结后分别收集 DOM close 与 native close proof，仍 active 则重新投影 | 重放破坏性 abandon、把 native close 当 DOM ack，或仅 `Panels.close()` |
| 已 accepted 的 panel / Host force-close，但 Flash 与场景仍存活 | 先持久化 `transportDetachNeeded` 并保持 `LOOT_COMMIT_PENDING`；causal query 按 journal→effects→pause proof 推进 | 初次与 reopen 都只收束为 `LOOT_SUSPENDED/CONSUMED/EXPIRED`，保留同一 inventory/anchor | 把 pre-accept failure 误送 ForceDetach、调用 Flash renderer、把 force-close 冒充玩家 abandon、重放经济写/事件 |
| scene unload / authority teardown | 仅在无 claim journal、mandatory effects、transport flag 且 `expireScene()` 可安全收束时原子撤销 lease并标记 `EXPIRED` | 有 pending 时返回 `commit_pending`，teardown barrier 保留 authority、gameworld、dispatcher 与 collision 并单飞重试；成功后才继续原场景清理 | 越过 pending 写 `EXPIRED/CONSUMED`、先拆世界再重试、迁入新场景或重滚奖励 |
| Flash 进程完全结束 | v1 不持久化未领取 loot container | 已成功领取内容按正式存档回读；未领取内容不承诺跨进程恢复 | 从 Web cache 复活物品，或由恢复协议重建容器 / 重滚；关卡自身既有重置语义另行核对 |

“未领取容器不跨 Flash 进程恢复”是首版明确限制，不是正常关闭时吞奖的许可。生产观察若显示崩溃损失不可接受，应在扩面前另立持久化 ADR；在此之前不得偷偷把临时容器塞进长期存档 schema。

### 5.4 面板编排原则

- 开锁和 loot 可在同一 Host panel 生命周期内做 same-panel flow，也可以两个 panel 实例串联；S0/S2 只比较实例拓扑、转场体感与 pause 连续性，不重新定义焦点语义。两种方案都必须使用共享 `FocusScope` / lifecycle 规则，准确处理初始焦点、Tab 环、Esc、背景 inert 与 opener restore。
- 不得在中间转场释放又重获 `webpanel` pause lease，避免游戏世界闪进一帧。
- 玩家发起的正常关闭是领域动作，不能只 `Panels.close()`：复用 close v1，空箱优先提交 `CONSUMED`；非空 `abandon=false` 进入 `LOOT_SUSPENDED` 并关闭当前视觉层，非空 `abandon=true` 经放弃确认后才提交 `ABANDONED`。取消放弃仍保持原 panel / binding / `LOOT_ACTIVE`。
- transport close、视觉 close 与领域 close 必须分层。`LOOT_SUSPENDED` 是正常领域关闭后的可重开状态，不是 detach；reopen 的 pre-accept 拒绝、同步发送失败或异步打开失败必须继续保持 suspended anchor 且不回弹旧 UI。只有新 visual binding 已 accepted 后再发生 transport / Host 故障，才允许 ForceDetach 并进入 persistent transport recovery。
- force-close 在 Flash / 场景仍活时只分离 binding并进入 persistent transport pending，保留原容器及可达恢复入口，不得冒充 abandon / expire；authority teardown 也只有在无未决 journal/effects/transport flag 且可安全收束时，才按 §5.3 进入 `EXPIRED`。进程已退出则遵守“不恢复未领取容器”的明确限制，不伪造终态回包。

- 取消不会把箱子留在 `_killed=true` 但未开启的中间态。

- result 回包丢失时只查询 session 状态，不自动重发；重复开盖 callback 的 spy 计数仍为 1，且没有真实奖励 / 容器副作用。
- 对两个贴邻箱按一次互动键，只有一个进入 `LOCK_PENDING / OPENING_ANIMATION`；另一个保持 `AVAILABLE` 且稍后可单独打开。

- 真实 WebView2 中人工核对键盘全流程、FocusScope trap / restore、中文长文案、系统缩放 / 输入法、三视口和 reduced-motion；headless Edge 证据不能替代此门。
- 运行态无 AS2 资源箱小窗口双开。
- Web 不持有奖励权威、不可以从本地 state 恢复出已被 AS2 拒绝的物品。

### S3：Lockbox 生产开锁闭环

**目标**：将 Lockbox 从观测性 `minigame_session` 推进为可安全驱动 chestSession 状态转换的业务流。

必需能力：

- 箱子签发 session，变体 / seed 与箱型映射为只读参数。
- result 结构白名单、session 一次性消费、stale / duplicate / unsupported 拒绝。
- result 超时或未知时先作跨过 unknown call 水位的 AS2 权威查询，不重放旧提交。
- Host 日志对 session/token 去敏，Web 玩家界面不显示协议语汇。
- result 不携奖励 descriptor、倍率或可兑换分数；验收表述遵守 §4.4，只证明 session 约束与一次性状态推进，不虚构“已证明玩家真实操作”。

结束门：

- Lockbox Node QA + browser harness 全绿。
- Launcher xUnit 覆盖路由 / 回包 / 断线 / duplicate。
- fresh Flash trace 覆盖成功、失败、取消、过期、重复回包、result ack 丢失后查询与重复开盖 callback。
- 游戏内端到端手测确认一个真实箱子只会开启 / 滚奖一次。
- 若该阶段导致 Launcher Host/native 产物变更，只有冻结 immutable Git-tree v2 request、由至少两个不同 signer + `faultDomain` 对同一 build identity / payload closure 形成 quorum、取得 production policy receipt，并在 v2 strict verifier 与原子 promotion 全部通过后，才可将“Host 生产可用”记为通过。单机 build、自由文本 builder ID、历史 v1 candidate 或源码 xUnit 都不能代替此门。

### S4：开锁配置、观察期与旧 UI 资产清理

**目标**：在 S1/S2 已经彻底切断 Flash 网格 UI 运行时入口的前提下，控制 S3 开锁频率、完成观察，并在证据充分后清理不可达 Flash UI 资产。资产清理不得反向阻塞 Web-only 失败暴露；`资源箱界面` 仍被同一 XFL 作为 `仓库界面` 实例复用，仓库拆分或迁移前不得删除该共享 symbol。

- S3 Lockbox 可先用于保险柜 / 生存箱，再按价值配置装备箱；这只决定是否先开锁，不改变全正网格 Web loot 选择器。
- 普通资源箱、纸箱、隐藏点的爆落路径保持不变，除非另有游戏设计评审。
- 观察失败率、放弃率、平均时长与打断感，不把调试 telemetry 长期暴露给玩家。
- 旧 `创建资源箱图标`、地图箱对 `资源箱界面` 的调用、claim-only adapter 与 observer recovery 在 S1/S2 即必须归零；S4 只处理地图箱专属且已经不可达的 Flash 资产与兼容残片。共享 `资源箱界面` symbol 必须等仓库拆分/迁移后再删。任何重新引入 renderer 的提案都属于架构回退，必须另立 ADR，不能当应急开关。
- candidate 启动、Launcher 重启、正式 promotion 或回滚前必须先阻止新 loot open，并证明所有 active/pending 瞬态容器已收束；v1 不跨 Flash 进程恢复未领取容器，无法证明 drain 完成就中止重启 / 切换，不能把丢失未领物当回滚代价。
- 扩面前汇总 `CONSUMED / ABANDONED / EXPIRED` 原因与 remainingCount；若完整进程退出造成的未领取奖励损失不可接受，先立持久化 ADR，不用重滚奖励兜底。
- 至少一个真实存档完成“开箱 → 分类型领取 → 存盘 → 完全退出 → 重启回读 → 已领取资产存在且无 session/container 重放副本”的证据链后，才允许宣称生产可用；若关卡原本会刷新箱子，证据必须把既有刷新与本协议重复提交分开。

## 8. 预估改动面（非文件承诺）

### AS2 / asLoader

- `InteractionHandler`：从“互动即 kill”拆出可延迟的箱子互动编排，或委托新 `ChestSessionService`。
- `InventoryPanelService` 或独立 `LootContainerService`：瞬态容器注册、snapshot、claim / transfer、close / abandon、三类终态、reconcile、same-object recovery 与过期。
- `关卡系统_lsy_地图元件.as`：掉落滚动与开盖 callback 的新委托；保留 `row/col` 任一非正的爆落分支。
- `物品系统_WebView.as`：服务安装 / gameCommands 入口（如选择新服务）。
- 对应 TestLoader 测试类与 manifest / asLoader 注入接线。
- 经济写成功路径沿用各领域持久化契约；普通 inventory 写显式 `dirtyMark`，特殊资产不得因统一 claim 抽象漏掉原有副作用。

### Flash XFL

- 箱子共通时间轴回调；应尽量收敛到 AS2 委托，不在 6 个 symbol 内复制业务协议。
- 若改 `flashswf/arts/new/素材库-地图元件/`，它是独立素材库 XFL，发布目标必须是该 `.xfl` 与对应 `素材库-地图元件.swf`，不得泛化成 `-Target main`。
- 旧 UI 退役若改 `flashswf/UI/物品与技能相关界面/`，同样必须独立 publish / verify 其 SWF。

### Launcher Host

- panel 路由、开锁结果 action / response、只读 session / terminal 查询、同容器 same-object recovery 与异常关闭。
- InventoryTask 增量命令或独立 LootTask；选择须以“领域边界是否真正独立”评审，不以文件数最少为目标。
- Launcher xUnit 覆盖协议映射、保留键、回包整形、active instance、超时 / 断线 / stale、未知写对账与 close ack 丢失。
- 生产 runtime 发布遵守 [runtime-build-reproducibility.md](runtime-build-reproducibility.md)：`launcher/build.ps1` 仅作本地 prepare → pure producer → policy 兼容检查；正式列车必须以 `new-runtime-build-request.ps1 -SourceKind Treeish` 冻结 immutable Git tree，由注册本地 X509 worker 与另一真实 `faultDomain`（推荐 GitHub hosted OIDC/Sigstore）对同一 build identity / payload closure 取 quorum，签发 production policy receipt，再由 `tools/promote-runtime-bundle.ps1 -RequestId ... -PolicyReceiptPath ...` 经 v2 strict verifier 原子提升。禁止单机复制 candidate、自由文本 ID 冒充 signer、伪造 faultDomain 或跳过 receipt。

### Launcher Web

- `loot` feature 采用 `transfer-pair` profile，组合共享 `panel-runtime / workbench-lifecycle / workbench-focus / workbench-primitives / workbench-components`，再加载 loot presenter/runtime，最后由 facade 编排；不得直接安装 Bridge response listener。
- Lockbox 从只日志 session 推进为有业务回执的编排接缝，但保留 `minigame_session` 作观测信封，不恢复分游戏命令。
- lazy registry、build 必需集与 panel layout 只有在实际新增 panel ID 或依赖闭包时更新；依赖顺序必须保持“共享层 → feature → facade”。如采用 same-panel rebind，不虚构新 ID。
- Web 协调器显式建模 `write_pending / reconcile_required / terminal`；任何 timeout、断线或未知 close 都不得从本地 cache 猜成功。

## 10. 评审风险清单

| 风险 | 影响 | 首选缓解 |
|---|---|---|
| 互动即 kill 与异步小游戏冲突 | 取消 / 失败后箱子已死，无法重试 | 在 kill 之前创建 chestSession，成功后才推进旧动画 |
| 全局互动事件 fan-out | 一键同时 kill 多箱，开启动画并发 | 中央候选裁决；一次输入最多提交一个箱子 |
| 场景 / 非箱 / 地面拾取也消费同一全局键 | 开 panel 的场景互动与 chest flow 同时提交，或修箱子时意外改掉其他系统手感 | 显式 preset allow-list；`SceneInteractionManager.currentMC` 对箱独占；非箱 / 地面拾取的 legacy 共消费保留并用混合 fixture 锁定 |
| 纯文本数箱把 XML 注释 / 互斥分支当运行实例 | S4 铺开面、箱型频率与 fixture 代表性全部失真 | XML DOM 排除 comment，分开报告条件分支声明、实际 `Instance` DOM 节点与去重逻辑身份 |
| 单例资源箱 UI 重绑 | 后到容器替换 `IconFactory` 绑定，旧奖励失去可达入口 | 每容器独立 ID + 单 active flow 守卫 + 拒绝覆盖 |
| 临时容器无地址 | Web 无法安全 snapshot / mutate | session-scoped ID + registry + epoch + close cleanup |
| 滚奖 / 注册 / bind 非原子 | 注册失败后奖励不可达，或 callback 重入再次滚奖 | `LOOT_COMMIT_PENDING` 单物化记录 + chest/container 一对一提交 + failure injection |
| 物化循环中途失败 | RNG / PRD / `总数` 已改变但 plan 未挂载，恢复时重滚或跳项 | 完整预检查；冻结逐规则 append-only 进度或 RNG/PRD/总数全量回滚方案；注入 roll/create/add 内部失败 |
| Web result 被当经济凭证或“真实操作证明” | 夹带 / 重放奖励，或作出超出本地信任模型的安全承诺 | AS2 一次性 session 复核；掉落仍在 AS2 滚；按 §4.4 限定威胁模型 |
| 特殊资产被当普通 item move，或复制 legacy 错键 | `金币 / K点 / 经验值 / 技能点 / 材料 / 情报` 进入错误容器；“金钱”与 `金币` 混用导致合法奖励不可领 | 独立 claim 语义、内部键白名单与受影响领域 snapshot |
| 特殊 claim 跨域半提交 | 目标已增加但 source 仍可领造成复制，或 source 先删造成吞奖 | 串行化 claim commit record、before / expected-after 对账、三个中断点 failure injection；歧义 fail closed |
| 受上限领域静默 clamp | 情报已满 / 容量不足时 source 整格删除，目标只接收部分甚至零 | v1 按 source entry 全有或全无预检查；cap-reached 保留 source；已满 / 差部分容量 / ack 丢失 fixture |
| 普通物品按名称重建 | 装备强化、阶级、配件或时间戳丢失 | 传递 / 比对完整 `BaseItem.toObject()` 描述符，专门装备 fixture 及重启回读 |
| 直投箱被中央裁决误改路 | 普通资源箱 / 纸箱 / 隐藏点不再爆落，或也进入 Lockbox | 中央裁决仅限制“选一”；对 `row/col` 任一非正保留 direct 处理器并建混合回归 fixture |
| 非空箱直接关闭 | 奖励静默丢失，玩家误解 | 领域 close 返剩余数，显式 abandon 确认 |
| 正常关闭与 force-detach 混淆 | 玩家取消放弃后面板仍消失，留下隐藏 active flow | 正常关闭保持 panel 直至终态；仅 transport/force-close 可 detach 并保留恢复入口 |
| 终态合并 | 放弃 / 场景失效被误报为已领取，无法审计与恢复 | 严格区分 `CONSUMED / ABANDONED / EXPIRED` 与 reason / remainingCount |
| 奖励生成后断线 | 重开时吞掉原容器或重新滚奖 | Flash 存活时保留原容器/anchor；未知结果查询 / 对账；初次与 reopen 统一 suspended/terminal，不自动重放 |
| 非空不自动放弃 + 单 active flow | Host 消失后形成不可见永久锁，后续箱子全部不可用 | `LOOT_SUSPENDED` 支持同场景同 anchor 的原 triple/inventory 重开；Web 仍故障时保持显式挂起与诊断，不调用旧 UI |
| 只测运行态不测存档 | 领取看似成功但重启丢失，或 session/container 重放出额外副本 | 分资产存盘 + 完全退出 + 重启回读门，并与关卡既有刷新语义分账 |
| 开锁频率过高 | 打断战斗节奏，小游戏疲劳 | 只对高价值箱配置开启，普通箱保持快取 |
| Flash 网格 UI 回退残留 | Web/Host/focus/protocol 缺陷被旧界面掩盖，双路径成为维护门槛 | S1/S2 即让正常与故障入口都不可达；failure 保持 `SUSPENDED/COMMIT_PENDING` 并显式诊断，S4 只清不可达资产 |
| 中间 panel 切换暂停闪断 | 战斗世界在背后推进一帧 | 全流程串行保持同一个全局 `webpanel` pause lease，真机 trace / 视觉验证；不虚构 per-flow lease |
| Host queue accepted 被误当 panel 已打开，或同名 Lockbox rebind 实例分裂 | 箱子进入 pending 但 DOM 未绑定；旧 Web session 用新 `panelInstanceId` 写入；bind ack 丢失被误当未打开 | exact `flowHandle + panelInstanceId` bind 才算打开；timeout 进 `OPEN_BIND_UNKNOWN` 并查询 / exact close；S0 拒绝同名重开 / 通用 rebind |
| bind / result / close / teardown ack 丢失后只做单次补偿 | flow 永久占用，或为“恢复”而重放写、重复 kill | Host state-driven reconcile + Web exact retry；result applied 后只轮询终态并重放权威 projection，原写永不重放 |
| 导航、新空 DOM 与 native close 被混成一个关闭证明 | 旧 Web 实例仍可能存活时提前释放 identity / pause，下一 flow 与旧消息交叉 | 仅 matching `NavigationId + ContentLoading + success` 证明 DOM teardown；失败 / 错配 / same-document 不释放；DOM、authority、native close 分证 |
| reconnect orphan 与 busy 重试复用旧 identity | 无 Host active 时悬挂本地 pending，或 busy flow 污染下一次 open | fresh capability 下精确区分 `resumeActive=false/true`；false known-no-write 收束 orphan，true 恢复 exact active；idle 后 fresh rearm |
| XFL 编译目标选错 | 误编 main 或遗漏素材库 SWF | 显式独立 `.xfl -PublishOnly -VerifySwf` |
| Host 源码已改但 runtime 仍旧，或历史/单机 candidate 被当正式产物 | 测试覆盖与玩家实际闭包不一致，且无法证明可复现 | immutable Git-tree v2 request + 不同 signer / `faultDomain` quorum + production policy receipt + v2 strict verifier + 原子 promotion |
| 共享 workbench / Host API 基线漂移 | 按旧函数或旧 panel lease 假设施工，破坏现有面板 | 每切片按当前 HEAD 复核；方向可复用不等于调用形状已冻结 |

## 12. Compact 恢复卡

如后续会话因 compact 丢失上下文，先读本节，再按需回读前文。

1. **目标不是“打开 Lockbox”**，而是“建立 AS2 权威的瞬态 loot container，用 Web 双栏展示，Lockbox 作可配置前置步骤”。
2. 当前设计在 `InteractionHandler` kill 前先交给 `LootContainerService.beginFixture`：正网格由 Web authority reservation 接管，超界正网格 fail-closed，非正 direct 才走地面掉落。S0 exact fixture 仍由 `ChestSessionService.beginFixture` 独立拦截且双门默认关闭；中央六类箱 arbiter 随 AS2 发布进入注入面，必须人工回归。
3. 原版多箱丢奖的根因是“全局互动事件同时命中多箱 + 固定 `资源箱界面` 单例 + `resetInventoryLayout` 改绑新库存”。新路径必须做一次输入选一箱，且同时只有一个 active flow。
4. 当前生产资产中网格 preset 恰为保险柜 / 生存箱 / 装备箱，但选择器不按名称或 2×4 / 4×4 / 4×8 白名单。XML-aware 声明/节点/逻辑身份准确计数以最新审计为准；非正网格的普通资源箱 / 纸箱 / 隐藏点继续地面掉落。
5. 旧网格箱的 `ArrayInventory` 是瞬态真库存，但无 `containerId`；现有 inventory-domain 文档明确将其排除。
6. Lockbox core 可用；普通生产 Lockbox result 仍只进 `minigame_session` 日志，不是奖励权威。S0 另有双门默认关闭的专用 dev wire，不得外推成生产 business route。
7. close v1：`remaining<=0` 优先 `CONSUMED`，非空 false 是非终态 `LOOT_SUSPENDED`，非空 true 才是 `ABANDONED`；suspend 仅同场景同 target anchor 重开原 triple/inventory 并重铸 lease/instance。初次、reopen 与断线 failure 都 Web-only 收束为 `LOOT_SUSPENDED / CONSUMED / EXPIRED`，Flash renderer 不可达。
8. `LOOT_COMMIT_PENDING` 必须把奖励单次物化、容器注册和 chest/container 一对一绑定收成可恢复提交；容器终态、chest 终态、lease 撤销与 active-flow 释放同步完成。
9. 普通 item 保留完整 `BaseItem.toObject()`；特殊资产是 `金币 / K点 / 经验值 / 技能点 / 材料 / 情报`，以可恢复 claim commit 完成目标增加 + source 删除；“金钱”只是显示名。
10. 未知 result / move / claim / close 只用跨过 unknown call 水位的查询或 snapshot 对账，不自动重放；普通旧读不能解门。首版不声称抗玩家主动修改本地进程。
11. 正常非空 close(false) 进入 `LOOT_SUSPENDED` 并可由同 anchor 重开；取消 abandon 保留原 panel。pre-accept / 同步 / 异步 / accepted 后 transport failure 均保留同一 inventory/anchor 并回 suspended/terminal；journal/effects 未收束则保持 `LOOT_COMMIT_PENDING`。
12. 成功经济写必须按资产类型完成存盘与完全重启回读；未领取瞬态容器 v1 不跨 Flash 进程持久化，也不得从 Web cache 复活。关卡既有刷新语义与协议重复提交必须分开核对。
13. 中央互动裁决覆盖所有箱型但只改“一次选一个”；它不是默认断开的实验模型，AS2 发布即影响六类箱。`row/col` 任一非正的 direct 爆落语义不变，发布前必须有单箱、邻箱与跨消费者混合候选回归。
14. 施工顺序为 `S0 无奖励编排 spike → S1 loot authority + 全正网格 Web-only → S2 Web 双栏 → S3 Lockbox 生产闭环 → S4 观察 / 不可达资产清理`。S1/S2 在 S3 前用 configured skip，不依赖实验性 result wire；S4 不保留 Flash recovery renderer。
15. Host/native 变更的生产门是 immutable Git-tree v2 request、不同 signer + `faultDomain` quorum、production policy receipt、v2 strict verifier 与原子 promotion；单机或历史 v1 candidate 不是可发布 runtime。
16. 当前是 `APPROVED_BASELINE_V1` + `APPROVED_S0_ACTUAL_DEV_WIRE_SHAPE` + `APPROVED_S1_S2_ALL_POSITIVE_GRID_WEB_ONLY`；批准依据见 §1.6。六类箱体领域准入后，所有正整数 `row/col` 是 Web intent，支持 `1×1`、`col<=8`、`capacity<=64`；超界 fail-closed，production XML/runtime marker=0；不迁移 direct/break，也不含 S3 或发布豁免。
17. S0 源码已补齐 state-driven reconcile、四类 ack-loss、result-applied 无写终态轮询、权威投影重放、DOM/native close 分证、严格 NavigationId 证明、`resumeActive` 孤儿语义与 busy 后 fresh rearm；最新分层计数见 §7 检查点。
18. 旧 immutable tag/source、request `FBA91942…31AE4`、quorum、receipt、promotion 与 standard-entry 只证明单-canary历史树；build/closure/Core `2A0CD… / 3B837… / 0F58…` 以及更早 candidate 都不代表当前 source 已部署。
19.
