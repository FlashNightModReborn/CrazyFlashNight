## 0. 结论

地图资源箱迁移只保留一条产品路径：

```text
六类地图箱领域准入
        ↓
正整数 row/col ──→ AS2 LootContainerService（唯一奖励权威）
        ↓                         ↓
  Web loot panel ← Host panel 生命周期 / 运输边界
```

- 六类地图资源箱中，所有合法正整数网格统一进入 Web loot；不按地图、箱型或尺寸配置 rollout。
- 只有精确 `row == 0 && col == 0` 的直投箱继续按原玩法落地掉落，它不是 UI 回退；负数、单边为零或正负混合都属于坏配置并 fail-closed。
- 攻击破碎继续按破碎玩法落地掉落，不打开 Web；装备箱与生存箱的破碎时间轴必须实际调用统一破碎脚本。
- 正网格畸形或超出 Web 上限时 fail-closed：不 kill、不滚奖、不显示 Flash UI，也不改成地面掉落。
- Web/Host/连接失败只允许保留或恢复同一个 AS2 权威容器；不得切换到 Flash renderer、claim-only adapter、观察者 renderer 或第二套奖励对象。
- Lockbox S0 平行状态机全部退役。未来若立项开锁玩法，必须以独立协议和独立计划重新评审，不能复活 S0 或插入当前 loot 前置分流。
- 旧 `资源箱界面` 库 symbol 仍被仓库界面共用；当前完成标准是地图运行路径不可达，而不是在仓库拆分前物理删除共享资产。

## 1. 为什么这不是“给每个箱子做一套路由”

旧箱型最终都汇入 `_root.地图元件.掉落物转换为物品栏` 一类网格领取语义。迁移边界应按行为而不是按关卡枚举：

这里的“汇入”只用于界定应迁移的历史行为集合，不代表继续把 `_root.地图元件.掉落物转换为物品栏` 留作运行时挂钩。该函数在箱体已经进入开启/死亡时间轴后才执行：此时再接管已经来不及为奖励建立 kill 前 reservation，也无法阻止相邻箱被同一次全局输入同时命中、证明 own-kill，或在普通关闭后按 exact anchor 恢复同一份战利品。因此当前最小安全切点是 `InteractionHandler` 在 kill 前预留唯一 authority，随后由所有箱共用的根开启回调只激活这同一份 authority。旧转换函数及其 Flash renderer 已从地图生产代码删除；这是一条前移后的统一路径，不是按六种箱型复制六套实现。

1. `BoxInteractionArbiter` 先确认对象属于六类地图箱，防止其他带 `row/col` 的地图元件被误劫持。
2. `LootContainerService.classifyMapChestShape()` 只判断网格语义：
   - 正整数且 `col <= 8`、`row * col <= 64`：Web loot；
   - 正整数但畸形或超界：fail-closed；
   - 精确 `0×0`：原地面直投语义；
   - 其余非正、混合或缺字段：fail-closed。
3. 箱型名称、关卡路径和当前常见的 `2×4 / 4×4 / 4×8` 都不是 rollout 条件。

因此不需要：

- 为每张地图逐一登记；
- 为六类箱分别复制 service；
- 为每种尺寸建立 feature flag；
- 建九站或全地图人工矩阵；
- 保留旧 UI 作为“安全回退”。

静态扫描负责全量覆盖生产 XML 和 XFL 接线；真人只验证少量能够代表不同时间轴与玩法语义的样本。

## 2. 权威边界

### 2.1 AS2：唯一业务权威

AS2 负责：

- 箱体准入、距离裁决和一次输入至多命中一个箱；
- 掉落规则预检、一次物化、箱体 own-kill 与开盖时间轴；
- `chestSessionId ↔ lootContainerId ↔ ArrayInventory` 一对一绑定；
- 领取、关闭、挂起、放弃、过期及存档脏标记；
- 权威 revision、operation id、slot lease 与 close lease；
- 查询未知结果，不重放未知写操作。

奖励从 loot 单向进入玩家权威域。普通物品保留真实 `BaseItem`，特殊资产先完整预检，再事务式增加目标并删除源。任何失败不得产生第二份奖励对象。

### 2.2 Host：运输与 panel 生命周期

Host 不决定奖励，只负责：

- 严格校验 Web/AS2 信封；
- 将同一个 loot binding 绑定到 tracked panel；
- 管理 pause、窗口打开/关闭、焦点、重连和 teardown；
- 在结果未知时查询 AS2，不代替 AS2 推断结果；
- 证明关闭的是 exact `panelInstanceId`，避免旧回包关闭新页面。

### 2.3 Web：展示与意图

Web 只负责：

- 展示背包与战利品箱；
- 发出 snapshot、tooltip、claim、close、query 意图；
- 顺序执行“全部领取”，遇容量不足保留箱内剩余物；
- 在同一 loot panel 内进入背包—战备箱整理页；
- 显示同步中、容量不足、已挂起和终态。

Web cache 不是权威，不得在重启后自行复活 loot。

## 3. 最小状态机

下图只表达正常主链与玩家可见终态；打开、运输或恢复失败的精确收束由随后约束定义。

```text
AVAILABLE
   │ 预检 + 预留 + 一次物化
   ▼
LOOT_COMMIT_PENDING
   │ own-kill + 开盖帧 + panel handoff
   ▼
OPENING ───────────────→ LOOT_ACTIVE
                              │
           ┌──────────────────┼───────────────────┐
           │普通关闭/运输故障 │领空               │明确放弃
           ▼                  ▼                   ▼
     LOOT_SUSPENDED       CONSUMED            ABANDONED
           │
           ├─ 同场景同 anchor 重开 → LOOT_ACTIVE
           └─ anchor/场景失效 ─────→ EXPIRED
```

约束：

- `LOOT_COMMIT_PENDING` 未完成 journal/effects/proof 时不得伪装成终态。
- 非空 X/Esc/backdrop 是 `LOOT_SUSPENDED`，不是放弃；同场景同 anchor 可继续领取。
- “放弃剩余”必须是独立危险操作，并二次确认后进入 `ABANDONED`。
- 空箱只进入 `CONSUMED`；关闭后自动回游戏。
- 场景销毁前必须先让 loot authority 收束；未完成时 teardown fail-closed 并重试。
- v1 不跨游戏进程持久化瞬态 loot；同进程内场景或 anchor 失效时进入 `EXPIRED`，进程退出后不承诺恢复或记录新的终态。

## 4. 必要复杂度与应删除的复杂度

### 4.1 当前必须保留

这些机制直接防止重复领取、丢奖或错误关闭，不属于回退：

- 单一 AS2 authority 与一次物化 journal；
- operation id、authority revision、slot/close lease；
- stale/重复回包隔离；
- 未知写结果只查询、不重放；
- pause 与 exact panel close 证明；
- `LOOT_SUSPENDED` 同 anchor 恢复；
- 场景 teardown barrier；
- 同一 panel 内 organizer，保持同一 binding 和 pause；
- `BoxInteractionArbiter` 的单箱裁决；
- 有界 tombstone/recovery proof，防止迟到回包污染新会话。

这些边界已经对应实际出现过的多击、断连重连、迟到或错配回包、关闭未响应与焦点恢复问题。删除它们只会把故障变成偶发丢奖或复制，而不是降低产品复杂度。

### 4.2 本轮删除或禁止新增

- Flash 资源箱 renderer 运行时回退；
- claim-only / observer recovery 双路径；
- 地图、箱型、尺寸 rollout marker；
- S0 `ChestSessionService / ChestS0SocketBridge` 及 Host/Web 平行状态机；
- S0 dev gate、bootstrap、adapter、actual-wire、专项 harness/verifier 和发布资产要求；
- “Web 失败就落地掉落”或“Web 失败就重新滚奖”；
- 为未来 Lockbox 预留的生产分流；
- 将历史 candidate、旧 promotion 或 dormant code 当作当前验收门。

### 4.3 暂不继续扩张

- 不做跨进程瞬态 loot 恢复；
- 不做多箱并行活动会话；
- 不做通用分布式事务框架；
- 不把普通 Lockbox 小游戏接入地图箱；
- 不为删除共享 `资源箱界面` 提前拆仓库 UI；
- 不把代表性真人验收扩成逐地图巡检。

## 5. 交互定案

### 5.1 领取

- 单击/双击/Enter 可领取单项；“全部领取”按启动时冻结的物理 slot 队列严格串行。
- 容量不足必须证明零写，保留当前 binding 和箱内剩余物；不得自动关闭。
- 普通堆叠可以进入已有堆叠，独立装备若无空格则留在箱内。
- 领取最后一项后进入 `CONSUMED`，面板自动关闭并回游戏。

### 5.2 整理背包

- 容量不足时在当前 loot 页面直接显示“整理背包”。
- 点击后在同一 tracked panel 内切换到背包—战备箱整理页，不先回 AS2 再打开另一个 panel。
- 可执行背包↔战备箱转移，以及经二次确认的整格丢弃。
- 返回战利品前重新取得 fresh snapshot；失败就停留在整理页，不重放领取或关闭。
- 整理页 X 返回 loot；loot 首页 X 才挂起并回游戏。

### 5.3 关闭与放弃

- loot 首页 X/Esc/backdrop：非空时 `LOOT_SUSPENDED`，空时 `CONSUMED`。
- 顶部“放弃剩余”：二次确认后 `ABANDONED`。
- 按钮必须 single-flight；视觉 pressed 状态不能替代 Host/AS2 回包。
- 关闭、确认或整理按钮需要在缩放、焦点恢复和 WebView2 重激活后保持一次点击可用。

## 6. 施工范围

### AS2 / Flash

- `BoxInteractionArbiter`：六类箱领域准入和一次输入单箱裁决。
- `LootContainerService`：唯一 loot authority、状态机、事务与恢复。
- `InteractionHandler`、根资源箱开启/破碎回调、`SceneManager`、`ServerManager`：只接 Web loot 与 teardown 边界。
- 地图元件 XFL：六类 canonical linkage 使用统一开启回调；所有可攻击箱的“破碎”标签帧必须调用统一破碎脚本。已从 `LIBRARY` 删除未进入 Include closure、与现役 symbol 复用 itemID/linkage 的旧顶层资源箱/隐藏点及资源箱私有碎片闭包，避免未来工具误选旧直投脚本。
- `asLoader.swf`：AS2 逻辑最终发布目标；地图元件库另按独立 XFL 发布。

### Launcher Host

- `LootPanelCoordinator / LootTask / InventoryTask`：tracked binding、严格协议、organizer 路由和 exact close。
- `PanelHostController`：保留 tracked panel/idle fence；不保留 S0 专属 global gate。
- `WebOverlayForm / XmlSocketServer`：只保留通用或真实 loot 使用的路径。

### Launcher Web

- `loot-state / loot-panel / loot-view / loot-inventory-organizer`：唯一地图箱 UI。
- 普通 Lockbox 小游戏本体可作为独立模块保留，但 production 地图箱没有 S0 bootstrap/adapter/wire。

## 7. 验证矩阵

### 7.1 自动化全量门

自动化负责全量而非真人穷举：

- 扫描所有 `data/stages` 箱声明和六类 preset；
- 扫描地图元件 XFL Include closure、canonical linkage、开启/破碎回调位置；
- 覆盖 `1×1`、容量 64、列上限、畸形/超界、direct 和 break 对照；
- 覆盖全部六类箱的 item catalog、双字段同时缺省时的数量 `1/1`、单边缺省/显式坏值 fail-closed、特殊资产组合；Web、精确 `0×0` 直投和攻击破碎共用同一规则校验器；
- 负向扫描 Flash renderer、rollout marker 和 S0 生产引用为零；
- AS2 TestLoader：authority、arbiter、journal、失败注入、恢复和 teardown；
- Host/Web：协议 schema、重复/stale/unknown、ack loss、disconnect、organizer、焦点和 exact close；
- Launcher 全量测试、Web QA、release policy、文档治理；
- fresh Flash CS6 TestLoader trace 与 `asLoader.swf` publish；
- 独立地图元件 XFL publish、compiler error 检查和 SWF 脚本反查。

当前最小充分命令集以 [testing-guide](../agentsDoc/testing-guide.md) 的地图资源箱行和各脚本自身帮助为准。本轮实际执行 stage/wiring、map-loot TestLoader、Launcher 全量、loot state/browser harness、共享 focus/workbench audit、普通 Lockbox、runtime policy 与文档治理；只有触及共享布局或 CSS 时才追加视觉 atlas 与 item-grid 全矩阵。

生产地图声明/节点数量只报告，不作为禁止合法关卡增删的硬编码白名单。

### 7.2 真人代表性集中场

真人只做无法由静态或模型测试替代的实时输入、时间轴和视觉确认：

1. 从正常标题帧入口进入一次，确认 NativeHud/刘海屏按正式指令唤起，而不是 watchdog 或调试旁路。
2. 装备箱正常 Web 打开，全部领空后自动回游戏；全程不得出现 Flash 箱 UI。
3. 生存箱在满背包下领取混合物：可堆叠项进入已有堆叠，独立装备保留；同页整理后返回并领完。
4. 保险箱非空普通关闭：单击即可挂起并回游戏；同 anchor 重开，内容与 identity 连续，再领完。
5. 装备箱和生存箱各攻击破碎一次：出现地面掉落，不开 Web、不重复奖励。

精确 `0×0` direct 由自动门覆盖；若集中场已有该夹具，可顺带目视确认，但不为它另打一轮战斗。其他非正或混合尺寸属于应被自动门拦截的配置错误，不用真人验证“无事发生”。经济数值、存盘和重启读回尽量由自动化对账，不重复消耗真人时间。

无需建立九站，也无需逐地图手工开箱。若任何正网格箱出现 Flash UI、静默落地或重新滚奖，直接判失败并修代码，不启用回退。

## 8. 发布与证据口径

严格使用：

```text
compiled → candidate_built → candidate_executed → e2e_verified
→ promoted → standard_entry_verified
```

- `launcher/build.ps1` 最多证明 `candidate_built`。
- 必须从精确 candidate 路径运行并核对 build identity / payload closure，才能进入 `candidate_executed`。
- 真人集中场绑定该 candidate 后才能记 `e2e_verified`。
- 正式 runtime 必须走 immutable tree request、本地 X509 + GitHub Hosted OIDC/Sigstore 双 signer/双 faultDomain、production receipt、v2 strict verifier 和原子 promotion。
- promotion 后必须从 `automation/start.ps1` 或根 bootstrap 标准入口复核同一正式身份，才能记 `standard_entry_verified`。
- 历史 candidate、旧 SWF、`publish_done.marker` 或“页面曾打开”都不能外推当前树已发布。

## 9. 当前状态与剩余门

旧合并树 `c887f2689d9b9c9ec342e4887de3804c9ed06acd` 的候选曾达到 `candidate_executed`，但已被本轮规则收敛、Host 单入口与 XFL 清理源码取代，不能继续晋级。此前同一地图箱实现已由真人覆盖领空自动关闭、满背包部分领取、同 panel 整理/转移/删除、挂起重开、存盘回读；这些行为证据可用于缩小重复人工范围，但最终身份仍须重建 candidate，并补“正常标题帧/NativeHud + 一个正网格箱 Web 打开并领空”的短 smoke，不重复整套笛卡尔积。

最终提交树仍须依次完成：

1. 从正常标题/存档入口进入当前精确 candidate，确认 NativeHud 正常唤起，并打开一个正网格箱完成 Web 打开与领空；watchdog reveal 不算正常进档证据。
2. 检查该次 fresh 日志与候选 identity，达到 `e2e_verified`；当前无 tracked 临时关卡夹具待恢复。
3. 再次 fetch 并确认远端仍是当前合并树的祖先，重跑最终门禁。
4. 进入 v2 正式发布，并从无参数标准入口对同一正式 identity 复核最短 smoke。

## 10. 变更纪律

- 不手工编辑 SWF；AS2 `.as` 保持 UTF-8 BOM。
- 修改协议、测试入口、构建门或路径时，同轮更新 canonical doc 并运行 `node tools/validate-doc-governance.js`。
- 临时关卡夹具必须在发布前精确恢复。
- 不用注释、休眠脚本、环境变量或 feature flag 保存已退役实现；Git 历史已经承担追溯职责。
- 不把 source 编译成功、candidate 成功或正式部署混为同一结论。
