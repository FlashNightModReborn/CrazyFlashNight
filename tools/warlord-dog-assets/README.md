# 军阀铁卫犬

阶段 3、档次 2.5 的军阀战犬，使用 R2 苏式装甲犬原稿。其职责是带盾承受首轮射击，完成一次有效撕咬和反机械放电，为后方步兵提供集火机会。首次放电后阵亡仍可完成编队职责。

## 实现与验收边界

原生装配、独立控制器、军阀遭遇数据和加载链已接入。真实 CS6 专项已完成 60 项断言，包含实际攻击碰撞扣血、单次电击、独立盾层、韧性、完整回充、暂停、目标版本、死亡生命周期、8 种动作切换后的灭灯重绑，以及集火排除当前玩家和非战斗 AI。原生图像另有 11 张固定画布捕获。

亮屏条件下完成三组、各三次、交换阵营的 18 局对照。军阀在蓝方时，三突击兵 0/3 获胜，完整犬编队 3/3，关闭能力的同面板犬编队 1/3；军阀在红方时，两个控制组均败，完整犬三局存活到 60 秒上限，超时保留为未定胜负。留用原型面板与能源参数，没有靠继续增加面板实现目标。之后显式补上集火排除当前玩家的边界，重新取得 60/0、最终 asLoader 编译 0/0，并以最终字节复验蓝方核心配对：三突击兵败，完整犬胜且两名步兵存活。

斗兽人物模板蓝方带现有佣兵 HP×3，犬在本次结果中保持 847；两侧分开比较，不把这组结果写成故事关中立军阀的完整体验。第一口与首次击杀的逐局时刻没有进入标准 Worker 结果，不能补造成功率或时序。故事关三方交火、实体操作仍待人类验收。维护者已认可后续四足撕咬与口腔修正，并授权配齐三犬头像后提交推送；未执行正式 runtime 部署。

路径未识别、揭幕停滞的前两轮和主动中止的延长轮均保留。延长轮在源审发现玩家筛选边界后经绑定客户端中止，不计入编队结论。亮屏请求只在本会话明确授权后执行一次，28 分 32 秒后在同线程释放；连续显示通知、8 段 Worker GUI 生命周期、资源与存档保护均已核验。没有放宽捕获围栏或伪造揭幕。

## 规则

- 出生满能源盾。自身盾容量大于零时，灯亮、附带有限韧性，并允许一次放电；其他来源的护盾不授予这些能力。
- 普通撕咬命中具有 `机械` 抗性条目的敌人时创建单体 `磁暴射线`，明确采用魔法／电伤害；机械值为零也算，只有装甲条目不算机械。其他目标仅承受普通撕咬。
- 成功创建射线即撤除自身盾与韧性、熄灯；破盾使用相同恢复流程。等待期间没有部分盾，普通受击不重置等待，暂停不推进恢复，充满后一次性恢复完整盾。死亡和卸载终止生命周期。
- 首次确认有效目标或换目标时向同场景、同阵营的战斗 AI 发一次集火令，带最小间隔，显式排除当前玩家、NPC、地图元素和 `None` AI。指令不消耗能源，熄灯仍可使用；后续正常 AI 可以重选。它不改变敌人的攻击目标。目标版本也参与比较，避免 AVM1 同名 MovieClip 重用吞掉新指令。
- 选敌沿用现有 AI。护盾期增加韧性，不默认提供刚体、强制控制免疫或额外击退免疫。
- 生物装甲犬沿用军阀抗性结构，以装甲替换人类条目；不添加机械属性。装甲条目是伤害分类与破击入口，不等于通用减伤率。

### 扑咬支撑修正

R2 原稿的 FK 适配只对齐最低脚掌，抬起前躯后两侧后脚仍会同时悬空。第一次修正只补后腿与近侧前脚支撑，仍保留抬起远侧前脚，用户认为发力不自然，旧预览保留为被否定的视觉方案。当前 `bite-support.json` 与 `bite_support.py` 将整段攻击改为四足撑地：四个脚掌全程保持各自初始站姿的矩阵，不抬脚、不滑步；远近脚原有透视高度不同，不强行拉到同一屏幕水平线。

第 4–21 帧将躯干、头颈、装甲与四个腿根整体变换为低姿态，再以等长骨段求解全部四肢，不单独把肩关节从胸甲上移开。前压与回拉的躯干倾角为 −3°／−1.5°；关节承接身体运动，脚掌不随躯干浮起。颈部、头与嘴部上锚点相对躯干的原有运动保留，但在场景中的绝对轨迹随整体姿势改变。参考军警犬／盗贼犬预览，攻击下颌相对头部的转角限制为 −8° 到 18°，保留同一转轴与张合时刻，避免大张角叠加长口吻形成黑色帆布状口腔。其他六个动作、攻击事件、伤害发射器与原时间节奏不变；视觉层的静止脚掌关键帧会按相同值合并，不改变逻辑事件层。

参考 [犬类捕食动作观察](https://doi.org/10.1016/j.applanim.2024.106402) 对咬住后牵拉的姿势描述，以及 [犬咬合力研究](https://pubmed.ncbi.nlm.nih.gov/32587065/) 对颌肌与咬合的分析。四足持续撑地是本单位站姿连咬的美术约束，不声称所有犬类咬击都必须四足着地，也不把接地点数量直接换算为伤害数值。
