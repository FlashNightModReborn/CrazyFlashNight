## 1. P0：协议冻结 + Spike + 后端骨架

**P0 状态（2026-10-18）**：B0 通过（64 项插话测试、全量 893 passed）；G0-2/G0-3/G0-4 通过（新增 24 项全绿）；G0-1 部分通过——Top-Level WinForms 浮窗已可编译/单测，但 `GuardianForm` 失活会触发 `OverlayBase` 隐藏并抑制对话 widget，焦点路待修。详见 §12。

### G0-1 输入控件与 IME Spike（GAME）

**目的**：确定在 Native 自绘对话框上叠加输入控件的可行方案。

- 候选 A：WebView2 输入浮层（复用现有 web overlay 的 IME/焦点/输入经验）。
- 候选 B：WinForms TextBox 子控件（原生，样式需自绘边框/背景）。
- 必测：
  - 中文输入法组词、候选窗定位；组词 Enter 不触发发送。
  - 获得焦点时游戏热键/按键采样被暂停；失焦恢复。
  - 点击输入框不触发“下一条”；点击“下一条”不被输入层吞掉。
  - 透明/分层窗口上的绘制、z-order、缩放/DPR、全屏切换。
  - 视觉风格与对话框面板一致。
- 产物：一段可运行的最小验证（不进正式代码路径也可），记录选定方案与失败项。
- 通过标准：能在 Native 对话 UI 上稳定输入/发送中文，不误触游戏输入，不破坏原有推进。

### G0-2 Native 会话拼接与 finish 契约（GAME）

**目的**：证明 Host 在本地追加/替换台词后，仍能通过 AS2 v2 的 finish 校验。

- 现有事实：
  - `NativeDialogueBookSession` 持有不可变行集、`_index`、`applyAppend`（尾部追加、restartIndex 重播）；没有“从中间替换剩余行”的 API。
  - `NativeDialogueService.as:369-374`：`advance_past_end` 要求 `finalIndex == AS2 rowCount-1`；`close` 允许 `[0, rowCount-1]`。
- 必做：
  - 在会话中区分 `WireRowCount`（AS2 原始行数）与本地增强行列表。
  - 增加 `ReplaceFrom(startIndex, replacement, resumeOriginalIndex)` 或等价 API；本地插入不改变 `WireRowCount`。
  - 组末 finish 用 `WireRowCount-1`；提前关闭用原始范围内索引。
  - 单测：原 3 行 + 本地新增 2 行 → 播放到末 → 发出 `advance_past_end, finalIndex=2`，AS2 校验逻辑通过。
- 产物：C# 单测 + 一段说明；不改 AS2 源码（除非验证发现额外校验，见 5.1）。
- 通过标准：本地增强行可播放、可中途替换、finish 通过；原任务状态机钩子不受影响。

### G0-3 逐句 SSE/首句尽早上屏（GAME + BACK）

**目的**：证明“第一句完整到达即可播”，不等待整轮/结束语/plan。

- 用假流（测试桩）模拟：`line1` → 1.5s → `line2` → 2s → `done`；Host 在第一句到达时即播放。
- 覆盖：
  - 玩家 `$PC` 台词播放期间首句到达 → 排队，玩家台词播完再播。
  - 关闭/取消 → 在途请求取消，未播 line 不进已播历史。
  - 拆分线：一条长句拆成 2 段且带 `split` → 前置段输入暂锁、末段开始显示即解锁；自然多行不锁。
  - 首句前的工具/草案等待 → 显示等待状态，不插过渡台词。
- 产物：Host SSE 客户端可注入假流；单测/工装记录时间线。
- 通过标准：首句播放时间≈首句到达时间（不等 done）。

### G0-4 字数实测（GAME）

**目的**：把源码估算（约 195 中文字可见）校准成实际值。

- 在 Native 正文框用代表性中文（含标点、长句）逐级加长，记录不滚动/不裁切的可见容量。
- 记录：容量、85%（硬上限）、70%（提示词上限）。当前建议 165 / 135；玩家输入 150。
- 若实测偏离，按同比例调整并同批回写《协议》5.6。
- 产物：一行校准记录（环境/分辨率/字号/实测值）。

### B0 后端骨架（BACK）

**目的**：在不接真模型的前提下，把端点、请求/SSE、JSONL 解析、拆分、session 对账的骨架立起来。

- 新增 `services/dialogue_interject/`：
  - `schemas.py`：请求、SSE 事件、JSONL 行、plan。
  - `parser.py`：逐行 JSONL、括号剥离、字数拆分、情绪回落。
  - `plan.py`：任务 n/nochange/remove/end 宽容校验。

  - `prompts.py`：日常/任务提示词骨架（先占位，P2/P4 填实）。
  - `api.py`：`POST /api/game/dialogue-interject`、`POST /api/game/dialogue-interject/finalize`。
- 用假 LLM 流测试：首句先出、拆分、零有效修复一次、error/done。
- 不修改终端 `/api/game/ask` 行为。
- 通过标准：假流下协议全链路可跑；单元测试全绿。

### G1 游戏请求与流

## 3. P2：日常核心

### G2 日常播放与状态机

- 新增/结束语播放：`add`/`closing` 逐条；无结束语时最后一条新增即结束语。
- 日常成功轮不接回原作剩余：AI 行播完即组末（`advance_past_end` 仍用原文最后一行编号）；失败轮才把原作剩余接回当前点。P1 现有 `PlayLine` 以 `_wireResume` 接回原文，P2 必须改成“成功不接、失败显式接回”。
- 输入可用：玩家 `$PC` 行隐藏；等待首句“……”，AI 每句从开始显示即可输入（不必等逐字/整轮播完）；拆分前置段可暂锁、末段恢复；结束语同口径。
- 点击语义：打字中先补全；结束后推进；最后一条关闭整个对话 UI。
- 失败/超时/零有效：无额外台词，回原对话剩余；已播 `$PC` 保留。
- 中途插入（v1 默认开放）：补全当前句→取消在途→播 `$PC`；已收未播转参考续写，新一轮同 session。
- 重复触发：新 `dialogue_instance_id`/新 session。
- closing 收尾：`advance_past_end`/`close` 一发生就隐藏输入、真取消在途流并按已播 finalize；已收到未插入的台词不再进本组。
- finalize：每轮结束可发 best-effort finalize；关闭/组末的最终 finalize 为权威收尾。
- **组类型标记（P2 前置）**：AS2 `SetDialogue`/`handleAssign`/book 报文透传可选 `dialogueKind`；`GetTask`＝`task_pre`，`TaskRewardCommit`＝`task_post`；Host 缺省 `daily`。P2 只做识别与门控，任务插话仍关闭，等 P4。
- 单测/工装：状态迁移、关闭取消、失败回退、组类型缺省/标记、finalize 时机。

### B2 日常编排

- 日常提示词：角色扮演 + 场景/NPC/记忆/RAG + 已播历史 + 剩余参考 + 玩家输入；JSONL add/closing；135 字；无动作描写。
- 工具：终端全量；查询预取可用；记忆可用；委派保留但降权。移除 B1 的临时“本轮只能对话”规则，工具与提示词同批启用。
- 参考续写：请求 `reference_continuation` 已接入上下文；上一轮未播 add/closing/edit/remove 按《协议》5.1 渲染。
- 任务草案：抑制过渡语；等草案；最终对话+结束语；草案保留。
- session：首次插入种入前文；已播追加；失账轮玩家行保留、无 AI 回复；接受每轮 best-effort finalize 的全量前缀对账。
- 测试：草案路径、普通路径、失败路径、session 角色映射（$PC=user，其他 NPC=`【…】` user）、reference 续写、工具启用后仍离线。

**P2 出口**：日常普通聊天 + 失败回退 + session 落库可用；任务草案路径可在 P3 收尾。

## 4. P3：日常草案、终端 session、委派

- 草案确认/取消/讨价还价走既有工具链；发布走既有写盘/热重载。
- 关闭对话后草案保留；终端可继续。

- 委派 `delegate_dialogue_rewrite`：日常保留；提示词“只有非常必要时才调用”；确认后台 worker 不阻塞首句；若明显影响则切到禁用。

**P3 出口**：日常全功能可玩；终端能回顾；无持久覆盖层写入。

## 5. P4：任务核心

### G4 任务播放与计划应用

- 任务 id 链路：AS2 在 `dialogueKind` 同批透传 `dialogueTaskId`（`GetTask`、`TaskRewardCommit`、选关界面三处），Host 存进 book 会话；缺 id 或读不到本任务时任务插话 fail-closed。
- 任务上下文采集：completed/upcoming（任务前/后映射见《协议》4.2）；从现有任务目录（`MapTaskCatalog`/`MapRuntimeContent`）与当前存档的 `tasks_to_do`/`tasks_finished`、`next_task_id` 生成，不让后端反查游戏任务表。
- 请求：`mode=task`、`dialogue.kind=task_pre/task_post`、task_context、remaining 相对编号、played、reference。
- 计划应用：
  - `add` 先播；
  - `plan` 到达后按 end/edits 构建后续：edit→替换；nochange/缺失→原文；remove→跳过；end 之后用原文（忽略编辑/移除）。
  - 播放推进时标记已越过；编辑版已播放→进入已播历史；未播放→下一轮参考。
- 中途插入（任一句播放中，禁言除外）：补全当前句→取消在途→播 `$PC`；未播 add/edit/remove 转参考；`add` 段且 plan 未应用时播放点不变，改写/原文播放中从下一条未越过处重新编号。
- mute：首句化解；输入禁用+提示；本组重置；禁言是任务唯一整组锁。
- finish：组末用 AS2 原始 finalIndex；提前关闭用 close。
- 单测：各种 end/remove/nochange 组合、已播/未播边界、中途插入、mute、finish。

### B4 任务编排

- 任务提示词：任务前/后上下文；只 Query+记忆；回主线；只改当前 NPC；按编号；优先 end；不做无意义微调；mute；JSONL。
- 任务 plan 校验：宽容；非法忽略；end 指到被移除条目时跳到下一条。
- session：同一组多次插入历史正确；终端的角色映射同日常。
- 测试：任务前/后、end 缺省整组替换、remove、nochange 缺失、mute、失败回原。

**P4 出口**：任务插话全功能可玩；任务状态机不受影响。

## 10. 回滚与开关

- **不设特性开关**：只要通讯终端 exe 可用（`ragTerminalService` 存在），Host 就构造输入层、挂会话钩子与焦点门；未发现 exe 时输入入口自然不出现，原对话逻辑完全不变。原 `dialogueInterjectEnabled` 配置项已移除。
- 输入条挂在**对话面板右上角、关闭钮左侧**（不占画面右上角，也不遮关闭钮）：收起态是 52×30 的黑色长方形箭头（左上折角、无红条），下沿贴住对话框黑色头条上沿；点击从箭头处向上展开输入面板，箭头旋转 180°，再点收起。展开面板右沿始终停在关闭钮命中区左侧，底边与对话框头条上沿重合，越界收回视口内；发送、失焦或本组结束回到箭头。点击输入条不触发 HUD/对话隐藏（走 `InterjectInputForegroundProbe` 前台窗口白名单）。
- 展开面板与对话框原版皮肤同源（`launcher/web/assets/dialogue-ui/source.svg`）：平涂 #191919 黑色头条带 45° 斜线刻纹、左上折角、等效半透明灰面板（不透明中灰近似）、方角灰/黑边多行输入槽（至少三行，聚焦加粗为黑色）、纯文字字数计数、方角黑色动作块（白字）、与收起钮同尺寸的浅灰箭头开关；不使用圆角、渐变、光晕、红色或蓝色点色。终端未启动/模型未配置时正文为禁言样式，提示分别为「请先启动聊天终端」「请配置模型API」，底部按钮为「启动」「配置」；点击只拉起终端或打开配置小窗，对话不推进、不发送。收起箭头用 Tooltip 显示同一提示。
- 配置小窗是终端前端的独立 `/config` 路由，由 Host 用**无边框 WebView2 浮窗**承载：页面自带标题栏与关闭按钮（不再显示系统白标题栏），窗口按 DPI 缩放、内容超出时在页面内滚动。打开时先读后端内存，再读共享 localStorage，自动带出模型名称/API Base/API Key；三字段顺序与推导逻辑对齐终端「佣兵档案配置」（模型名 → API Base（含平台快速选择、留空按模型名推导）→ API Key（显示/隐藏、记住 Key））。
- 与游戏内终端 iframe 共用同一 WebView2 user data folder 和 `http://127.0.0.1:7077` 源，并通过 `--disable-features=ThirdPartyStoragePartitioning` 关闭 Chromium 第三方存储分区，使 iframe 与 `/config` 顶层页**真正共用前端 localStorage**（`player-settings` / `player-api-key`），不写任何本地明文 key 文件。`remember_api_key=false` 时 key 只在 sessionStorage；此时配置页优先从后端内存取 Key。升级到本版后，旧分区里的配置若读不到，重新保存一次即可。
- 后端 LLM 配置只存进程内存：`/api/game/llm-config` GET/POST 读写内存，exe 重启后由前端页面按 `llm_config_updated_at` 双向同步（较新一方胜），不落盘。
- 后端新端点独立，不影响 `/api/game/ask`；回滚走 Host 版本回退或移除 exe。
- 数据回滚：插话 session 与记忆是新增数据，不改变原作 XML/JSON；不在本批清理既有 session。
- 如果 G0-1/G0-2 失败，P2/P4 不进入施工，文档保留作为后续方案。

### 11.1 所有权

| 范围 | 建议负责 | 说明 |

## 16. P6：物品赠送与索取（2026-10-23 设计冻结，未施工）

**状态**：只完成需求/协议与施工设计；未改代码、未编译 SWF、未重打 exe、未进游戏。协议正文见《协议》§7.5；后端落点见后端仓《12-对话内嵌插话-后端实施指引》§21。

### 16.1 已冻结的口径

- 只在日常插话注册赠送/索取/取消索取三个工具；任务插话与终端不注册，靠提示词推辞/拒绝。
- 赠送池＝核心任务奖励池全量；索取池＝有正常获取途径的物品 ∪ 金币 ∪ 玩家当前持有物品名；过滤无价格、战场补给、修改器/任务关键/绑定物品；索取不含经验值/K点/技能点。
- 赠送单次价值上限按“传话”类任务（阶段基数×好感系数）；超量自动降数量，金币/经验按 500 取整；1 个都超则拒绝；无硬频次上限。
- 组内保留逐轮赠送明细；跨组只保留按物品名合并的数量总账。
- 索取成功不直接扣物品，先出 pending claim 和两按钮；点“赠送”才真实扣除；玩家打字聊天时 claim 保留，模型可取消。
- 两按钮＋原输入框，保持现有面板高度与占位文案；不改成“还是聊天…”。
- “我接了/我不接”在插话输入条改为 action 直连，只省一次路由 LLM 调用；确认文案生成那次 LLM 保留。

### 16.7 风险

1. **回执丢失/未知写**：物品已动但账本未记；必须 action_id 幂等、Host 重试、日志对账，不得盲重放。
2. **背包满/情报溢出**：赠送失败或部分折算；模型必须按实际结果说话。
3. **金币扣款**：不能复用 `ItemUtil.submit`；必须走现有事务/脏标路径，失败不得先扣。
4. **模型过度赠送**：单次价值上限不防反复赠送；先靠提示词与组内明细，现场不对再加冷却。
5. **装备同名不同强化**：v1 按名字匹配，可能扣错槽位；需现场确认可接受度。
