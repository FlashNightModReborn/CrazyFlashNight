# 对白权威迁移 wire v2：协议全文与分期立项（2026-09-16 修订稿 v3，GPT6 Pro 裁决后）

**文档角色**：对白系统「C# 本地播放 + AS2 保留剧情与生命周期权威」迁移的协议级立项。本稿经 Wave 1 六路调研、Wave 2 五路对抗复核、**GPT6 Pro 架构裁决**三轮收敛；相对 v2 的修订全部来自裁决回执（对照见 §10）。**按裁决：终态可靠收口是方案 A 的最低成立条件，不是可推迟的可靠性工程。**

**输入**：调研/复核十二份（`tmp/dialogue-authority-study/`）；GPT6 Pro 裁决回执（2026-09-16，`gpt6pro.txt`）。

## 1. 背景与目标

现状：AS2 `NativeDialogueService` 持会话（句序/finish/cancel/暂停 claim/followingEvent），每句发一帧快照给 C# 呈现；advance/close 经 socket 回 AS2 裁决再发下一句。

路线（裁决批准）：

- **公共核心（先行）**：会话入口整本下传，C# 本地驱动换句/打字/换图/预取；**AS2 是"内容修改与剧情结束"的线性化点**——C# 的本地点击只是终态请求，不是已提交的终态；AS2 保留剧情权威（finish/cancel/followingEvent/claim 原样）。
- **静态源纵向切片（与核心并行打通一条）**：静态对白源由 C# 直读装配（多数已在 `DataQueryTask`/`XmlDataLoader` 现役管道），**正常路径不把整本内容绕回 AS2**；其余静态源按覆盖成熟度接入。
- **AS2 保留**：身份/外观快照裁决（含 speakerName 相关分支）、动态佣兵人格对白装配、AVM1 内存中已成形的行数组（authored `默认对话`/`本段对话`）、运行时身份判定与活态权威值（玩家名/heroTitle/外观偏好/任务状态/运行时设置）、producer 选择状态（组游标/随机消耗顺序/池规则）。

**明确不做**：followingEvent 发布（dispatcher 在 AVM1 对象图）、暂停 claim（PauseManager claim-OR）、外观冻结计算（读活 MC）、facade 桩化、AS2 零对白状态（裁决确认：escrow 换名不等于零状态，不值得推进 C）。字符串替换、静态 XML 归一化、book 结构构建可以迁移——**要保留的是权威值、身份判定和冻结时点，不是每一行字符串处理代码**。

## 2. 收益核算（裁决口径；所有数字为场景预算，非实测分位数）

**总述（最可信表述）**：普通换句不再唤醒 AVM1、不再往返主线程；**收益集中在负载相关等待和每次换句的协议处理成本，而不是一个固定帧延迟或已证实的 GC 百分比。**

| 项 | 口径 |
|---|---|
| advance 点击→上屏 | 现状 ~11–36ms（静态分段预算，非主游戏分布实测）；A 后 ~5–20ms（鼠标路径预算目标，未经双输入实测） |
| 延迟尾部 | 现状 ~110ms@30fps 饱和（降帧至 ~180ms，场景估计非 p99）；**A 后 ~40–55ms 场景预算（非硬上限）** |
| AVM1 帧内 CPU | 每次普通本地换句不再回 AS2（方向成立）；原"每句 4–8ms"缺直接对白路径 profiling；**入口（buildBook）、确认与终态成本仍在** |
| 入口爆发 | buildBook 单帧 ~5–40ms 仅作风险预算（协议允许规模远不止 38 行）；低端机开场掉帧观察项 |
| GC | **删除百分比**（无对象图计数/GC 时间证据）；持久池数千对象级为定性描述；**镜像退役范围按最后一个读者判定**（MercLibrary 池/npc 默认对话/任务回放等读者仍可能保留数据） |
| 成本归属纪律 | v1 入口 capturePortraits 是既有成本，不算 v2 新增；v2 提前物化整本，玩家中途关闭时会做掉 v1 原本无需处理的后续行工作——**总 CPU 不保证下降**；末行 finish 与 v1 最后一击同样要回 AS2，不算新增路径 |

**验收端点（施工后实测收紧）**：最后一次输入→面板隐藏 / 最后一次输入→followingEvent 发布 / pending 解除→已请求终态真正提交。注意 v2 提前隐藏面板会拉大"面板已消失但剧情尚未推进"的感知间隔，与"多一段网络路径"不是同一结论，分开测量。

## 3. 权威划分（一期）

- **C#**：不可变 book 表示（inline/source 同一宿主）、当前句 index、本地 revision（每 requestId 单调 ++，与 index 方向无关）、换句/打字/立绘/配图状态、closing 状态机（终态请求的持有与重试）。
- **AS2（线性化点 + escrow）**：会话生命周期、requestId 唯一发号、epoch（行集代际）推进、**终态裁决**（接受/拒绝终态请求）、followingEvent 持有与一次性消费、stage claim、追加/覆盖入口语义、场景 teardown 取消、发送失败/断线兜底、facade。
- **共享不变量**：`nd:<n>` 单调发号；`_maxSequence` 前沿 + hide 墓碑；socket-only 边界；两个方向各自 FIFO、跨方向交叉由 epoch/身份字段裁决（不允许实现层洗牌猜测）。

## 4. wire v2 协议全文

### 4.1 版本与能力握手（caps-required，每代重发）

- `native_dialogue` task 内 v1/v2 共存；`TryParse` 按 `version` 分派，未知 op fail-closed。
- **caps 下行通道 = `OnClientReadyForGeneration` → `PushToClient`**：`{task:"dialogue_caps", modes:["snapshot","book"]}`；AS2 `onSocketData` 加专用分支。**迟到的 caps、异步响应和 timer 均受连接代约束；异步发送使用已有 generation-bound 发送能力；清 caps 闩先于断线收口可能引发的重入。**
- AS2 侧纪律：① caps 闩按 socket generation 作用域，`onSocketClose` 清闩；② **未见本代 caps 不发 book**；③ `wireMode` 按会话闩于 beginSession（v1 起头终身 v1）；配置开关只能影响新会话，不得改变活跃会话的 wireMode。

### 4.2 AS2→C# 帧（version:2）：inline / source 双入口

```jsonc
// inline book（AS2 发号 + 会话信息 + 已成形 lines）
{"version":2,"op":"book","kind":"inline","requestId":"nd:<n>","sceneId":"...",
 "mode":"ordinary"|"stage","epoch":1,"startIndex":0,"advanceKey":13,
 "lines":[{"name","title","text",
   "portrait":{"kind":"static"|"doll","key","expression","appearance"?},
   "imageAction":"keep"|"show"|"clear","imagePath"}]}

// source book（AS2 发号 + 会话信息 + sourceRef + 必需的权威快照；lines 由 C# 装配）
{"version":2,"op":"book","kind":"source","requestId":"nd:<n>","sceneId":"...",
 "mode":"ordinary"|"stage","epoch":1,"startIndex":0,"advanceKey":13,
 "sourceRef":{"type":"stage_dialogue"|"task_text"|"npc_dialogue",
              "key":"...","group":0,"contentVersion":"..."},
 "snapshot":{"heroTitle":"...","playerName":"...","advanceKey":13,
             "portraits":[{/* 行级批量：AS2 按 NativeDialogueAppearance.build 逐行裁决 */}]}}

// 追加（连续代际；baseEpoch = C# 应已持有行集代际，epoch = baseEpoch+1）
{"version":2,"op":"append","requestId":"nd:<n>","sceneId":"...",
 "baseEpoch":1,"epoch":2,"lines":[...],"restartIndex":0}

// 低频变更（白名单字段：advanceKey）；set 不动行集、不 bump epoch
{"version":2,"op":"set","requestId":"nd:<n>","sceneId":"...","advanceKey":32}

// hide：v2 会话带 version:2，字段与 v1 同形（墓碑语义不变）
```

- **同一宿主**：inline/source 在 C# 内部进入**同一个不可变 book 表示**，共用同一套本地换句、预取、closing、确认和回退规则——不是两套会话系统。`sourceRef` 限定源类型/键/分组/内容版本，**不接受任意文件路径**。**C# 拥有内容，不等于 C# 拥有会话发起权。**
- **epoch（行集代际）**：AS2 每发一次 book/append 对 requestId `epoch++`（book=1）；**接受 append 时在发送前推进 epoch，不等 C# ack**。C# 只接受连续代际（`baseEpoch == 已持有代际`），整包验证通过后**一次性原子采用**；缺失、重复、非法跨代一律拒绝，实现不得自行猜测。
- **append 约束**：逐行复用 v1 校验，任一行畸形→整包 fail-closed；`restartIndex` 是合并后数组下标，缺省=0；**合并后 lines.length ≤ 4096（累计容量限制：单个 append 不超限不代表合并后有界）**。
- **报文上限**：`maxMessageChars`（明确 UTF-16 char 口径，不与字节混用）；判定点在 `HandleCurrentMessage` 内 JSON 路由前的 **task 前缀嗅探门**——嗅探必须可靠识别根级 task 与回调关联（禁止会匹配进字符串内容的粗糙子串）；超限直接 reject，不进 `JObject.Parse`。该门只避免 DOM 解析，不声称限制了完整报文的接收缓冲占用。
- **已进入 v2 的会话追加超限**：不得原地改发 v1 show；降级 = **取消旧展示 → 新 rid 的 v1 会话 → 移交同一份 claim 与 followingEvent → 合并内容从第 0 行开始，不在移交中发布事件**（与 stage overwrite 移交模型一致）。
- **回退实现**：book/append 确定失败均以新 rid 强制 v1，作废旧 pending 回调，沿用入口冻结的立绘并跳过 null 行；不改变后续新会话的 caps。v1 每窗口最多 4096 行，合并内容超过此数时按新 rid 连续移交尾部，claim 与 followingEvent 一直保留到玩家结束。回退通道也不可达时才经业务门禁走失败兜底。
- **行物化规则按 producer 分别明确**（不允许统一过滤抹掉入口语义差异）：`handleAssign(null)` 保持 no-op；`beginStage([])` 保持直接完成（publishFollow 不开会话）；book 内 `row==null` → 跳过（**finalIndex 校验基准 = 跳过后的规范化行数**）；`char` 缺失 → `char=""` → portrait 空静态槽（不改变行数与 epoch）；每项与现行行为的差异在 §7 测试登记。
- **A 阶段 C# 禁止发号**；裁决确认 AS2 单一发号覆盖全部场景（含 source book）。**异步 source 请求在发起时就拥有身份**（不是装配完成后才发号）：AS2 接受触发→分配 requestId→绑定 scene/事件/claim→再异步准备内容。未来 C# 主动触发也先向 AS2 提交开始意图，由 AS2 在授权、发号和绑定义务时一次完成——不引入租号及其额度/过期/闲置/并行问题。

### 4.3 mutation 确认（ack = 已原子采用）

- book/append/set 一律以 `sendTaskWithCallback` 发送；C# **在 UI 线程完成校验与原子采用后**，经既有异步响应能力应答（图片下载、解码不必等完）；**禁止持 socket 串行锁等待 UI 线程**。
- 回执字段：`requestId / sceneId / op / requestedEpoch / appliedEpoch / status=applied|rejected / reason`；source 型入口另回传 `rowCount`（规范化行数，供 AS2 校验终态 finalIndex）。
- **异步结果必须校验：连接代 + 会话对象身份 + requestId + sceneId + 操作所属代际**——不得在回调里直接操作"此刻全局的 `_session`"。旧 callback 撞新会话一律拒绝。
- **失败分类**：`set` 失败→保留或恢复上一个有效设置，**不结束剧情**；book 首次采用前失败→允许降级（回 v1 快照路径，wireMode 按会话闩）；append 失败→保住已接受的内容与 stage 义务，再做会话替换或明确的故障恢复。
- **callback 工具修正**：`sendTaskWithCallback` 必须检查底层发送返回值并立即清理失败回调；墙钟期限用**实际时间差**（超时扫描按帧计数在 30fps 下 90 帧≈3–5s、15fps 下≈6–10s，不是固定 3 秒）。
- **调用方统一使用毫秒**：正式启动握手 60000、地图 hello 4000、地图投影/导航/返回计划 3000、Loot/RewardInbox 面板确认 20000；禁止握手 shim 再换算成帧。默认 20000，扫描节拍只影响发现超时的粒度。`node tools/test-server-callback-timeouts.js` 执行生产 shim、握手状态机及发送/扫描分支的确定性时间回归；该验证不代替 AVM1 和真实 socket 旅程。

### 4.4 超时与"结果未知"（否决"超时即 finish"）

- 超时只能证明"结果未知"，不能证明"未采用"。新增只读 `status` 操作：查询同一会话的 `state/appliedEpoch/rowCount`，**与 mutation 在同一采用队列上串行**：
  - 已采用 → 补确认，不重发非幂等 book；
  - 明确未采用或被拒绝 → 进入该操作对应的回退；
  - 仍未知 → **保留托管状态，走明确的连接故障策略——不能伪装成玩家已结束对白**（不得 `finishSession()`）。
- 只需现有会话状态 + 一个查询操作，不引入通用事务框架或持久记录层。
- **查询范围必须冻结**：发送 status 时记录 `maxOpSeq/queryEpoch`，只裁决该序号及以前的未决操作；查询发出后新增的 append/set 保持独立确认。查询在途时其它操作超时仍保留在 pending 表，不能因合并查询而丢失。旧 epoch 的 rowCount 不得覆盖已追加的新行数；缺失/null/非整数 epoch 保持结果未知。

### 4.5 终态竞争（替换 v2 稿的 finish-wins/closing；裁决核心修订）

**AS2 是终态线性化点。** 规则表（写进协议，不许实现自定）：

| 位置与输入 | 规则 |
|---|---|
| AS2 接受 append | **发送前**推进 session epoch（不等 C# ack） |
| AS2 收到 `finish.epoch < session.epoch` | **拒绝旧终态**：不释放 claim，不发布事件，不拆出尾部补播 |
| AS2 收到相等 epoch 的合法 finish | **经业务门禁后**，提交一次终态（terminal→清事件→清会话→放 claim→hide→publish 顺序不变） |
| AS2 收到未来/缺失/非整数 epoch | 拒绝并诊断 |
| C# closing 收到合法的更新代 append | **复活**：原子采用合并行集，按 restartIndex 重播，取消旧 finish 重试，回 active |
| C# closing 收到 set | 更新允许的设置，**保持 closing，继续重试原 finish**（任何新 op 不得单独终止重试） |
| C# 收到匹配 hide、成功采用的新会话，或连接失效 | 结束旧 closing；**被拒绝的高 sequence 报文不能终止它** |

**复活安全的理由（写死）**：同 rid 追加只能由仍有效的 AS2 会话产生——若 AS2 已提交旧 finish，之后的追加应走新会话；若它仍发出同 rid 的更高 epoch append，就说明旧 finish 没有赢。**复活必须与"旧 epoch 绝不结束新行集"配套，不能与 finish-wins 混搭。**

- **finalIndex 校验基准 = 该 epoch 真正下发的规范化行集**（跳过 null 行后的行数）：`advance_past_end` 的 finalIndex 必须等于行数-1；`close` 的 finalIndex 也必须在合法范围内。
- **C# 每次重试发送同一份冻结的终态请求**——不得从已变化的当前状态重新拼 epoch/index/reason。
- **对已提交过的旧 finish**：AS2 允许重发匹配 hide，**绝不再次发布事件**（利用已有发号前沿与会话身份，不加持久日志）——否则 hide 本身丢失后 C# closing 无法完成。

### 4.6 C#→AS2 终态回执与业务门禁

```jsonc
{"task":"cmd","action":"nativeDialogueAction","requestId":"nd:<n>",
 "sceneId":"...","verb":"finish","epoch":<冻结的请求代际>,
 "finalIndex":<规范化行数-1>,"reason":"advance_past_end"|"close"}
```

- **门禁裁决（理由已按 GPT6 修正）**：不加 `nativeDialogueAction` 白名单。理由**不是**"pending 期释放 D 会恢复游戏"（真值表显示 R 保持暂停），而是 `finishSession()` 会**同步发布 followingEvent**——暂停的游戏帧不能阻止 dispatcher 调用产生业务副作用，门禁注释正是针对 pending 期间的竞争写入。
- **所有新增收口路径不得绕门禁**：callback timeout/reject、异步空集完成等路径，不得直接 `finishSession`/`publishFollow`。最低实现 = 会话内"**等待业务提交**"标志：pending 解除后重新核验身份与 epoch，再提交；teardown/cancel 必须能撤销该义务。现有断线/facade 等直接收口路径与新增路径的政策差异要显式列出，不得把已有放行当成新增放行的正确性证明。
- **重试（资源与频率有界，不设次数上限）**：约 0.5–1 秒节拍，独立于输入去抖；每次发送前复查会话、连接代及 closing 尝试身份；首次用户输入仍经 `_inputAllowed()`，已形成的终态请求重试不因面板已隐藏再被拦。"有界"指资源和发送频率有界，不是在 pending 时长未知时保证有限次数结束。
- **AS2 `handleAction` 分版本**：v1 维持 requestId+sceneId+revision 三重校验；v2 校验 requestId+sceneId(+epoch)，verb 只含 {finish}。会话存 `wire:"v1"|"v2"`（beginSession 闩定）。C# 不可对 v1 会话发 finish；OnInput 动词白名单扩 finish。

### 4.7 revision 本地化纪律与 advance() 处置

- 本地 revision = **每 requestId 独立单调计数器，每次 ShowFrame ++，与 index 无关**；禁止按 index 派生。widget 的迟到帧拒绝/手势绑定/SetPortrait 接受门/排版缓存 key/同图跳过语义全部保持。
- **v2 的 `advance()` 一期明确为 no-op** 并移除假进度推进（无生产调用方）；若日后发现实际调用者，改成向 C# 发控制意图，不得恢复 v1 show——facade 看似存在而功能漂移是最差形态。

### 4.8 A+ / source 入口的补充契约（纵向切片范围）

- **异步准备绑定发起时业务意图**：AS2 请求静态装配时即记录会话身份、scene、claim/event 义务和 append/overwrite 意图；不得等结果回来后对"当前恰好存在的会话"决定追加还是覆盖。**迟到的空集结果同样受约束**——旧请求已被覆盖或 teardown 后，不得直接 `publishFollow`。
- **快照保持原有冻结时点**：portrait 在会话入口整体冻结（现行语义）；部分 NPC 文本归一化发生在加载期——冻结时点按 producer 保持，不统一改成会话入口。**仅保存 `targetRef` 稍后重读字段，不算冻结**（需不可变上下文快照）。
- **外观查询含 `speakerName`**：Andy Law 表情后缀分支依赖说话者名称，行级查询必须传入归一化后的 speakerName（或 AS2 完成该分支裁决后传结果）。
- **v1 回退数据路径不得顺手删除**：正常 source 路径不整本绕回 AS2，但故障回退允许按需取得完整行集再走 v1；某静态源尚无兼容旧 Core 的获取路径时，不得同时承诺"删 AS2 镜像 + 任意旧 Core 可回退 + 不加替代数据路径"。

## 5. 失败注入封堵对照（v3 终稿）

## 6. 分期与里程碑（裁决后）

**逻辑上先核心、后更多 producer，不等于两次独立正式发布——按既有发布约束合并列车。**

- **M1 公共核心（A 的最低成立条件）**：inline book + AS2 线性化终态（epoch 门/stale 拒绝）+ closing 复活/重试（冻结请求）+ 采用后 ack + status 查询 + 失败分类 + 异步身份五元校验 + advance() no-op + caps ready-push。双端解析与状态机定向测试。（3–4d）
- **M2 纵向验证（M1 同期）**：真实协议接线集成层（ready→caps→mode→callId 应答→pending 吞 finish→重试收口）+ 效果不变量验收。（1d）
- **M3 一条低风险静态 source book 切片**：sourceRef/快照（heroTitle/advanceKey/speakerName/冻结时点）+ 异步发起身份绑定 + v1 数据回退路径验证。（1–2d）
- **M4 合并列车 + 真机复验清单**（换句手感/双击节奏/连续对话/暂停交叠/pending 中关闭/追加续播/入口掉帧观察/三端点测量）。（0.5–2d 窗口）
- **M5+ 其余静态源按覆盖成熟度接入；动态佣兵与 AVM1 成形数组继续 inline；镜像按最后一个读者判定后清理。**

**不做项**：B（escrow 化——与 A 边界已近，终态收口已在 M1 内）；C（零对白，裁决确认不推进）。

## 7. 测试迁移矩阵（裁决后：完整 v1 保留 + v2 变体 + 真实路由）

**v1 是正式保留的协议与回退路径——它的 show/revision/index/prefetch 断言必须继续存在。** 正确结构是"完整 v1 套件 + v2 变体"，不是原地改写；新增安全修补若有意改变旧故障行为（如行物化规则），单独标明。当前 focused 环境无 caps 时走 v1——**全绿可能一行 v2 都没测到**，报告必须注明 wireMode。

**focused runner 最小装夹**：
- 类级、按连接代生效的 caps 注入入口；测试间清除 caps、代际、会话及回调；
- `sendTaskWithCallback` 桩：捕获并手动触发 applied/reject/超时/迟到回调；
- 可手动推进的时钟及队列（不用真实 sleep）；
- v2 合法 finish 刺激（epoch/reason/finalIndex 合法），不得继续发非法 advance 再把拒绝当校验通过；
- **队列测试模拟"两个方向各自 FIFO、跨方向交叉"**，不把同一方向消息任意洗牌。

**C# 新用例按行为面铺开（不按数量封顶）**：

| 测试面 | 必须包含的反例 |
|---|---|
| 双模与连接代 | 无 caps、旧 Core、旧 AS2、gen≥2 重连、迟到 caps、活跃会话配置切换 |
| 原子采用与容量 | 任一行非法、连续 epoch、错误 baseEpoch、重复 book、单帧超限、累计容量、拒绝后状态不变 |
| 本地播放 | 非末行零回程、单调本地 revision、append 回零、自驱预取、keep/show/clear、迟到贴图与旧手势 |
| closing 竞争 | set 不停重试；新 append 撤销旧终态并复活；旧 epoch 不发布事件；非法高序号报文不终止等待 |
| 回执与故障 | ack 丢失但 book 已采用；status 恢复；旧 callback 撞新会话；断线跨代 timer；终态重试只重发 hide、不重复发布 |
| 剧情与暂停 | D/W/R 组合、真实 pending 吞弃、pending 解除后收口、teardown 胜过待提交、followingEvent 同步重入 |
| source 入口 | 准备中覆盖/取消、迟到空集、内容版本变化、对象消失、冻结时点、v1 数据回退 |

- 至少一组用例**延迟 UI 采用**，证明 ack 是"已采用"而非"已投递"（不得全用 `dispatch = a => a()`）。
- Widget/Cache/Clock/Markup 套件维持原样（task 层迁移红利）。

**真实协议接线层（必须存在）**：每代 ready → caps 到达 → AS2 选模式 → mutation callId 应答 → rewardPending 实际吞 finish → 重试后 hide 收口——由使用真实入口分支的集成测试或定向联调承接，不得把直调 Service 冒充已测。

**最终验收查效果不变量，不是计数**：旧会话事件最多一次、cancel 为零；旧回调不影响新会话；旧 epoch 不结束新行集；不释放其他暂停所有者；pending 时不经新增旁路发布事件；连接健康且 pending 最终解除时，不留下永久隐藏的 closing 会话。

## 8. 风险与未决项

1. **callback 超时阈值**：用实际时间差；初值 ~3s，联调按 PerfTrace 收紧。
2. **双击节奏漂移**：真机手感复验；备选 C# 侧 40–80ms 换句去抖窗（协议外选项）。

5. **旧 Core 混流**：caps-required + 发布说明注明配对关系。
