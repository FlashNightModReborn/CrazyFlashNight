# 铁枪会支线一期：任务规格

> **文档性质**：任务落地规格。本文承接 `docs/铁枪会支线一期-第一防线建设大纲.md`，用于逐个任务确定 ID、条件、NPC、对白节拍、完成条件、奖励、解锁内容、系统依赖与验收标准。
>
> **施工原则**：随任务推进补系统能力，随功能落地做验收。不先做完整泛化系统。

## 二、公共约束

- 任务链继续使用 `铁枪会#N` 口径，具体编号按最终 ID 顺序调整。
- 前治安官在一期完成前应优先位于第一防线，不再由主线22直接放入基地大厅。
- 第一防线告示板是一期主链的核心承载设施：先作为任务入口，再扩展为长期玩法入口。
- 当前不做实时车辆单位、车队 AI、移动护送路径和车辆血量系统；车队用地图点、残骸、临时防线和对白表现。
- 具体奖励数值先占位，等任务与系统切片跑通后再按当前经济节奏调整。

已确认的参照样本：

- `武器大师` 不是异名 key 路线。健身房与第一防线两个场景实例都使用 `名字 = "武器大师"`，闲聊 XML 也只有 `<Name>武器大师</Name>`。
- `武器大师` 的双地点成立，是因为任务层使用 `get_npc_hotspot` / `finish_npc_hotspot`，地图层使用 `master_swordman_gym_avatar` 与 `master_swordman_first_defense_avatar` 两个 avatarId。
- `武器大师` 在地图上能分开摆放，是因为两地使用了不同头像资源：`武器大师头像.png` 与 `武器大师头像第一防线.png`。前治安官当前复用同一头像资源，因此地图层已补充 per-placement `relX/relY` 覆盖能力，让同一头像能在不同 hotspot 使用不同坐标。
- 当前 `初始化NPC` 已支持检索名分流；`目标.名字` 仍是默认 key，但 `对话名`、`任务名`、`商店检索名`、`技能检索名` 可分别覆盖。

NPC 检索名分流能力：

- 不建议把第一防线前治安官改成 `名字 = "前治安官_第一防线"`。这会污染任务 NPC key、地图 label、商店/技能查询与任务文本口径。
- 已给 `初始化NPC` 增加可选字段：`对话名`、`任务名`、`商店检索名`、`技能检索名`。四者为空时全部回退 `名字`，因此旧 NPC 不受影响。
- 第一防线实例保持 `名字 = "前治安官"`，同时指定 `对话名 = "前治安官_第一防线"`；XML 中新增 `<Dialogues><Name>前治安官_第一防线</Name>...`，但 `SubDialogue` 内显示名与立绘仍写 `前治安官`。
- 本期只实际使用 `对话名`。`任务名`、`商店检索名`、`技能检索名` 是技术储备，用于未来同一可见 NPC 需要不同任务身份、店铺库存或技能导师表时再启用。

处理原则：

- 任务与地图层仍以显示名 `前治安官` 作为角色口径，但所有涉及前治安官的新任务必须显式写入 `get_npc_hotspot` / `finish_npc_hotspot`。
- 一期前半段使用 `first_defense`；一期收束任务再把大厅侧显示、对白与任务入口切到 `base_lobby`。
- 第一防线地图定位应从 `launcher/web/modules/map-panel-data.js` 添加，再运行派生脚本生成 `task_npc_registry.json`，不要直接编辑注册表产物。

前治安官第一防线阶段文案备忘：

- 核心定位：他明确知道第一防线问题重重，撑下来千难万难，但必须在所有人面前扮演成"局面仍在掌控中"的人。
- 公开口吻：像旧治安体系的前线长官，使用"警长"、"命令"、"各队"、"火力线"、"撤离路线"、"活着回来"等强组织词，刻意表现得运筹帷幄、无所不知、无所不能。
- 情绪功能：他需要时刻煽动士气。口号可以存在，但口号下面必须压着具体调度：记名、接应、断后、补给、火力、撤离和伤亡登记。
- 私下层次：对主角或少数关键人物可以露出真实判断：人手不足、物资不足、纪律不足、派系协调脆弱。但不能在公开场合承认"可能守不住"。
- 人物矛盾：他不是盲目乐观，而是在用表演维持秩序。玩家应能逐渐看出他在"演"，同时理解他为什么必须这样演。
- 避免写法：不要写成普通热血队长、单纯口嗨的警长，或真的相信后援无穷无尽的乐观派。任何"必胜"句式都应暗含"必须靠纪律和消耗把胜利做出来"。

| 所属链 | `铁枪会#1` |

| 核心目标 | 协助第一防线建立"第一防线告示板/前线调度板" |
| 完成结果 | 告示板可用，后续告示板任务入口具备承载点 |

### 4.2 剧情目标

Shop Girl 告知玩家：A兵团决定给第一防线投入一批佣兵协助前治安官建设据点，但第一防线不是成熟据点，缺少能统一登记任务、调度救援、发布拾荒委托和收拢求援信息的前线设施。

玩家前往第一防线与前治安官商谈。前治安官承认自己有名义和旧治安网络，但缺少能把 A兵团佣兵、公社新人、拾荒者、临时护卫队和后勤需求汇总起来的工具。玩家协助把告示板搭起来，作为后续救援、拾荒、护送、尸潮预警任务的入口。

### 4.3 告示牌/告示板美术约束

本设施建议命名为 **第一防线告示板**，对白中可称"前线调度板"。它不是普通木牌，而是半手工、半电子化的前线调度设施。

建议视觉要素：

- 底座来自废车门板、路牌、铁丝网、脚手架或防爆盾拼装。
- 板面有纸质委托、手写路线、弹孔、污渍、血迹、旧地图碎片。
- 局部有 A兵团临时标记、前治安官的治安章/封条、公社物资标签。
- 可以留出一个小型电子终端、信号灯、破旧屏幕或接线盒，为后续铁枪图腾接入留视觉位置。
- 不要画成完整、整洁、现代化的公告屏；它应体现第一防线半建成、资源紧张、多方共治的混乱状态。

功能暗示：

- 纸质委托：救援、拾荒、护送、盗贼截击。
- 地图标记：贫民窟、废城、车队残骸、补给线。
- 电子接口：后续可接入铁枪图腾，显示高科技订单或信号任务。

### 4.4 对白节拍

**接取：Shop Girl**

1. Shop Girl 说明第一防线清理后没有真正稳住，只是从"尸群占据"变成"人类勉强站住脚"。
2. A兵团愿意派佣兵过去，但不可能让每个求援都直接进基地流程。
3. 第一防线需要一个前线调度点，用来挂任务、登记伤亡、收集拾荒需求和发布救援请求。
4. Shop Girl 让玩家去第一防线找前治安官，确认他是否能接住这套调度方式。

**交付：前治安官**

1. 前治安官说明自己能统筹军警宪政派残部，但目前第一防线人手混杂，靠口头命令会失控。
2. 他承认公社新人、佣兵和临时护卫队都需要一个能看见任务优先级的公共节点。
3. 玩家协助完成告示板布设。
4. 前治安官确认告示板可用，并指出第一批求援很快就会贴上来。

### 4.5 完成条件

当前推荐以已上线的基建雏形为主路径：

- **主路径**：使用 `conditions` 的 `infraLevel` 检测 `前线调度板` 达到 `1` 级；交付后开放后续任务。
- **旧特殊需求路径**：任务系统仍保留 `special_requirements.infrastructure`，但 70001 不建议使用这条旧路径，因为 `conditions` 能给任务面板提供进度行并受派生校验覆盖。

推荐任务数据片段：

```json
"conditions": [
  {
    "type": "infraLevel",
    "params": { "name": "前线调度板" },
    "target": 1,
    "label": "前线调度板建成"
  }
]
```

Web 面板入口已挂到 `_root.基建系统.第一防线调度板.启动任务面板()`。调度板不是新的通用选关系统，而是现有 `tasks` panel 的场景聚合模式；这样保留告示板的独立视觉与任务聚合能力，同时复用现有副本简报、DialogueView 和进关桥接。

### 4.6 奖励与解锁

奖励暂定：

- 金币：少量
- 经验值：少量
- 可选材料：低阶建筑/维修材料

解锁：

- 第一防线告示板可见/可交互。
- 后续任务 `70002 新人救援` 可从告示板进入或由前治安官引导到告示板。
- 第一防线进入"半建成但可调度"状态。

### 4.7 系统依赖

已具备/可复用：

- 任务支持 `get_npc_hotspot` / `finish_npc_hotspot`，确保前治安官交付地点为第一防线。
- 基建系统已能读取 `前线调度板` 配置，并按等级控制场景元件显隐/帧状态。
- 任务 `conditions.infraLevel` 可检测 `前线调度板 >= 1`，并能在任务面板显示进度。
- 基建等级已随存档保存/恢复，可作为任务完成条件。
- 前治安官已注册/派生到 `first_defense`，旧基地大厅任务已补 `base_lobby` hotspot。
- `前线调度板` 已能打开 `tasks` panel 的 `dispatch-board` 模式，第一防线皮肤、板内任务聚合、详情、对白和进关命令均已接线。
- 任务数据已支持 `dispatch_board` / `dispatch_order` / `dispatch_kind`；当前只正式使用 `story` 类型。

需接线：

- 基地大厅 `sheriff_avatar` 的 `主线#22` 显示规则后续需要移除或改为铁枪会支线驱动。

可延后：

- 告示板在地图面板中的独立导航。
- 面向长期肉鸽、周期委托的 `contract` / `mode` 分类及其刷新、锁定、结算规则。

### 4.8 验收标准

- 完成主线13后，玩家能接到 `前线调度板`。
- 玩家能从 Shop Girl 接取，并被引导到第一防线前治安官。
- 建成 `前线调度板` 后，任务条件 `前线调度板建成` 显示满足，任务可交付。
- 交付后，`前线调度板` 基建保持 1 级，第一防线告示板在场景中处于可用状态。
- 点击/触发调度板时能打开第一防线皮肤的调度板界面，并列出当前可见的板内任务。
- 后续 `新人救援` 的入口有明确承载点，不再凭空出现。
- 未接取任务不能绕过任务状态直接进入关卡；进关成功后 Web panel 应关闭。

70001 与 70002 的交接 NPC、地点相同，沿用任务系统的同 NPC 自动接取后续任务能力。70002 接取后在第一防线调度板出现；玩家从调度板阅读可重复战前简报并进入关卡，不会在每次出击时重放一次性接取剧情。

对白职责必须保持三层隔离：

- `get_conversation`：只在首次接取时播放，负责交代求援来源、前治安官公开动员与私下真实判断，可以包含角色关系和剧情悬念。
- `mission_briefing`：每次从调度板出击前均可播放，只负责目标、路线、接应点、撤离规则与公开威胁；不得提及老佣兵是否生还等关卡内揭示。
- `finish_conversation`：首次完成后播放，负责确认老佣兵结局、登记伤亡和引出补给线不可持续的问题；同时交代前治安官把无人机组件经 `soldier` 送去鉴定，铁枪会认出自治区旧镇暴标准并提供 `下挂镇暴装置` 样品。这里是一次性非正式渠道，不提前完成铁枪图腾合同。

完成后的调度板条目不消失，而是转为“已结案·复盘案例”。复盘属于非剧情重演：允许玩家再次进入同一关卡，但不重新接取 70002、不重复播放接取/完成对白，也不重复结算金币 3000、经验值 2500 与 `下挂镇暴装置` 的任务交付奖励。关卡自身掉落、经验和未来肉鸽结算另按关卡规则处理；第二架无人机固定掉落八门插件属于预设关卡经济投放，允许在复盘中重复获得。

调度板视觉分两层：第一防线板体使用稳定的场景皮肤垫图，确保地点身份和布局不随任务跳变；以后可给任务详情配置个性化情境图，但只进入右侧简报区，不替换整块板体。当前可优先复用任务既有 `imageurl` 语义及副本海报烘焙链，确认 PNG/manifest 路径后再决定是否新增独立 `mission_art` 字段。

### 5.2 剧情与玩法目标

玩家沿失联队伍最后留下的撤离标记杀入尸群，找到由老佣兵组织起来的公社新人。老佣兵已经以临时封锁线、分组和撤离标记为新人争取到时间，但本人未能撤回。玩家需要把能行动的幸存者带回，最后在第一防线外缘击退追来的盗贼。

关卡采用“第一防线出发 → 逆向深入郊区 → 卫生所确认幸存者 → 战斗吉普调查与引尸坚守 → 压迫式返程 → 第一防线盗贼战”的往返结构；具体地图顺序和事件不在本规格重复维护。

关卡需要通过场景、战中对白和情报物品明确表达：

- 公社新人缺乏废城经验，原有“佣兵老带新、沿途拾荒”的扩张方式伤亡极高。
- 老佣兵不是无意义团灭；他们把散乱新人组织成临时队列，并留下了足以让主角完成救援的防线与标记。
- 前治安官公开把救援包装成调度体系奏效的胜利，私下承认路线只是失联前的最后记录。
- 调度板解决了“如何让队伍行动”的问题，没有解决补给线过长、前线战力不足的问题，为 70003 铺垫。
- 玩家先在 SubStage 1 观察第三阵营无人机用麻痹冲刺和镇暴射线驱赶僵尸，再在最终战面对“无人机压制/记录 + 战犬试探”的盗贼组合；第二架无人机掉落八门插件，防线物资箱提供霰弹枪和弹药，让玩家在后续波次中立即使用学到的反制方法。
- 无人机残骸只承担鉴定线索，不承担铁枪会临时逆向研发。铁枪会继承西南自治区工业层的镇暴标准、库存和成熟产线；70002只提供一次样品与能力证明，稳定商业接口仍留给70008。

### 70003：补给线试行

**保留为独立行动关**：70002 负责还原老佣兵已经结束的断后行动，70003 则让玩家实时护卫上一关获救的脆弱新人完成第一次自主外勤。新人不再由老兵现场带队，需要自行分工、搬运障碍、标定射界、建立后撤点并展开临时阵地；玩家负责在部署窗口承受尸群和盗贼压力，保护关键人员与物资。

本关不得重复车队残骸调查、吉普起爆、卫生所救援和第一防线盗贼终战。难度升级来自友军保护、布防时间窗与有限容错，剧情结论是“新人已经学会阵地方法，但现有脆弱兵力仍不足以维持拉长的补给线”。具体路线、友军失败阈值和阵地部署节点在 70002 灰盒后另开关卡规格。
