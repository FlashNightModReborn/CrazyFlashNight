## 已实现的范围

1. 一个有效 F 包中，F6/F7 保留原有两次灯位选择与滞回计算，最后只提交一次组合原生快照。
   帧结束仍在同一同步调用中；不等待 UI 定时器。清理立即提交并取消待发结果，
   外线程更新不能加入旧批次。批次不跨域持锁，保留现有锁顺序和故障分类。
2. F8 header/行/字段采用 span 解析，保留原始字段数、数值/容量、顺序和有限性校验。
   联弹直接填充最终拥有的数组；普通弹和联弹在生产提交中保持独立的不可变快照段，
   不为每次提交拼接一份大数组。显式读取 `Instances` 时仍得到稳定的合并快照，
   原 `Compose` 对借用输入仍复制。原生记录格式、运动、镜像与生命周期不变。
3. 特效实例数据变更才上传；同一缓冲由弹壳层和命中/枪火层共享，不重复上传。
   镜头/灯光变化不迫使未变的精灵数据上传。
4. 原生光场按灯记录、灯数、相关呈现参数与捕获代次缓存；关闭、恢复与新会话重验。
   世界输出继续使用现有画法。`ProbeGetWorkStats` 是可选的计数诊断，原 ABI12 与 Stats 布局保持。

AS2、XFL、派生图集、伤害、穿刺预算、RNG 和射速门槛未改；不新增显示回退。

## 同输入 CPU 对照

本机为 Intel Core i7-9750H，GPU 夹具适配器为 UHD 630。旧 Core 为冻结的生产字节
`3E57BA63AFA2B6F5CC9263F7E6CB9087ECE6D0B895FB70FC522DFD784B4AC431`。
相同夹具分别引用旧/新 Core，交替运行两对；每档预热至少一秒并采七次，下面取两轮中位数平均。
每次重放含出生和 31 帧的多个八单元组、镜像、暂停与运动，以及一枚固定普通弹。

| 联弹单元 | 旧 CPU ms | 新 CPU ms | 时间下降 | 旧分配字节 | 新分配字节 | 分配下降 |
|---:|---:|---:|---:|---:|---:|---:|
| 128 | 0.49470 | 0.44005 | 11.0% | 739232 | 260728 | 64.7% |
| 2048 | 8.52300 | 7.26205 | 14.8% | 11783792 | 4352072 | 63.1% |
| 8192 | 44.07940 | 29.03940 | 34.1% | 47125648 | 17404256 | 63.1% |

三档输入与最终原生记录 SHA-256 相同，严格语法 corpus 接受结果相同。
初轮短进程仅预热三次，一档出现时间退步；原始记录保留，随后增加时间预热并交替运行。
另有两侧均关闭 tiered compilation 的控制组，方向一致；不混用不同 JIT 配置计算上表。

该结果只覆盖 F8 parser/engine/dispatcher 与记录打包，不包含 F5 parser、真实 socket、
HUD、native setter、GPU、完整 Flash/AI、功耗或游戏 FPS。不能把 8192 单元档称为实战并发资格。
原始和汇总数据在 `tmp/perf-closeout-0930/cost-final-*` 与 `host-cost-comparison.json`。

## 候选与恢复

稳定开发入口已生成并选中 `tmp/runtime-candidates/v2/perf-opt-0930`，状态
`candidate_executed / NOT_DEPLOYED`，仅指受控夹具与前门启动身份，不是完整战斗 E2E。

| 身份 | 值 |
|---|---|
| build identity | `92938A8EC3DB276172FA7B4E36BAFB4F3E502AC525EC2964A3FB08D9477879EC` |
| payload closure | `98351A2F37788B252962BEFA23DD740B5CAA43671B9F5F5C2D2F35BBAE51A626` |
| Core SHA-256 | `FC67DC94F61084F67F0C646BE022C502E9B44C01E7F3F7A89A59D14AB9518A44` |
| native SHA-256 | `76B2424FDCD974604B9AA486397CD7337766FEF3654B9F72D33FBF93A1F9E882` |

夹具加载的是与该候选 Core 相同哈希的实际模块，native 使用候选内绝对路径。
另用实际候选 Core 重跑 CPU workload，三档输出与旧版相同；结果在 `cost-candidate/host-costs.json`，
不把单轮候选时间与上面的交替两轮统计混算。

`automation/dev.ps1 -ReuseOnly` 实跑确认 `isolated_candidate`、实际 Core 路径及上述身份。
没有选择玩家槽位。该次 Flash 预热触发 `prewarm_deadline` 并回到前门 Idle，
因此只声明前门/身份启动，完整游戏进入仍待复测。随后从 Idle/no_binding 关闭本轮自有进程。
上述开发候选阶段保留现有 `本地开发启动.cmd`；当时正式入口和生产部署闭包保持原身份。
恢复可通过 `automation/start.ps1` 选择未变的完整正式配对 runtime；
源码改动按本批差异单独撤回，不能混用旧 DLL/新 Core 或只覆盖一份 SWF。
本机保留旧 Core/原生 DLL与逐文件源码快照于 `tmp/perf-closeout-0930/baseline-*`。
