## 0. 结论

能做到，而且**依然不碰 C# / TS / XFL**。但「不装备也能放」不是加个 `if` 就行，有三件事必须先定死：

1. **MP 不是槽位给的，是技能表给的**。`unit.释放技能(技能名, mp)` 内部已经统一扣蓝，槽位只负责把 `mp` 这个数字递进去。所以免装备释放 = **换一个地方读同一个数字**，不是新写一套扣蓝。
2. **冷却必须换通道**。槽位的 `quick:3` 对未装备技能不存在，硬复用会变成「无冷却无限放」。要加一个 `skill:<技能名>` 通道。
3. **不能用 `技能` + `slot=0` 去发 HUD 反馈**。C# 侧对 `kind=="skill"` 的 `slot` 有 1..12 的硬校验，越界会让**整帧 HUD 数据包被丢弃**（`PlayerHudState.cs:185` + `:122-125`）。这是本轮最容易踩的坑。

## 1. 语义定义（先把「可以放」的边界写清楚）

| 情形 | 搓招（方向+C） | 数字键 | MP | 冷却通道 | 玩家可见反馈 |
| --- | --- | --- | --- | --- | --- |
| 已学会 + 已装备 + 冷却就绪 | ✅ 走**槽通道** | ✅ | 扣 `技能表对象.MP` | `quick:<槽>` | HUD 冷却条（与数字键共享） |
| 已学会 + 已装备但**全在冷却** | ❌ **不回落名字通道** | ❌ | 不扣 | — | 冷却条本身 |
| 已学会 + **未装备** | ✅ 走**名字通道** | ❌（槽是空的） | 扣 `技能表对象.MP` | `skill:<技能名>` | 无冷却条（见 §8） |
| 未学会 | ❌ | ❌ | 不扣 | — | 静默 |
| 技能数据缺失 / 行损坏 / 被动 | ❌ | ❌ | 不扣 | — | 静默 |
| 倒地 | ❌（`释放条件.默认`） | ❌ | **不扣**（扣蓝在条件之后） | 不启动 | 静默 |
| MP 不足 | ❌ | ❌ | 不扣 | 不启动 | 搓招：消息+音效；数字键：HUD toast |

> 「未装备」= `1..12` 号槽里都没有这个技能名；**与「已学会」无关**，学会与否由 `SkillReleaseGuard.resolve` 单独把关。

## 3. 设计：双通道释放

### 3.1 一条裁决链（顺序不可换）

```
releaseBySkillName(unit, 技能名, C键码)
  ├─ 名字非法 / unit 无 释放技能 → null
  ├─ slots = findEquippedSlots(名)
  │    ├─ slots 非空：逐个试「就绪的槽」
  │    │     ├─ 命中 → releaseSlot(unit, 槽, 描述符, C键码)  ← 完全复用数字键逻辑
  │    │     └─ 全部在冷却/损坏 → 返回 {attempted:false, reason:"cooldown"}  ← 到此为止
  │    └─ **绝不回落名字通道**（否则搓招可绕过槽冷却）
  └─ slots 为空（未装备）：
        ├─ info = getSkillDescriptor(名)   （未学会/损坏 → null）
        ├─ 名字冷却未就绪 → 返回 {reason:"cooldown"}
        ├─ unit.mp < info.mp → 本地提示 → 返回 {reason:"mp"}
        ├─ unit.释放技能(名, info.mp, C键码)   ← MP 由这里扣，且只扣一次
        ├─ 成功 → start("skill:"+名, info.cooldownMs)
        └─ 成功 → 刷新 MP 显示
```

### 3.2 MP 结算口径

| 问题 | 答案 | 理由 |
| --- | --- | --- |
| 成本从哪来 | `技能表对象[名].MP`（经 `boundedMetadataNumber(...,1000000)`） | 与槽描述符完全同源（F3），数字键扣多少搓招就扣多少 |
| 谁来扣 | `unit.释放技能` 内部（F1） | 全仓唯一扣蓝点，事务/条件/等级都在里面 |
| 会不会双扣 | 不会，只要搓招层不写 `unit.mp -=` | 我们把「预检查」做成只读判断，仅用于提前提示 |
| 扣在条件前还是后 | 条件**之后** | 倒地/条件不满足时天然不扣，无需额外回滚 |
| 扣完显示谁刷 | `_root.玩家信息界面.刷新mp显示()` | 与 `QuickSkillInputService` 桥接层同一函数（`:58-60`） |
| 未装备时"仅够一次"提示 | **没有** | F6，HUD 快照只覆盖已装备槽；属已知限制 |

### 3.3 冷却通道

| 通道 | key | 何时启动 | 何时检查 |
| --- | --- | --- | --- |
| 槽通道（已装备） | `quick:<slot>` | `releaseSlot` 成功后 | `updateSlot` + `releaseBySkillName` |
| 名字通道（未装备） | `skill:<技能名>` | 免装备释放成功后 | `releaseBySkillName` |
| 战技通道 | `weapon:shared` | 与本方案无关 | — |

两条通道**互不共享**。已知边界（都可接受，见 §8）：
- 未装备时用搓招 → 名字冷却中 → 打开技能面板装上 → 数字键可立刻放一次（面板多半暂停战斗）。
- 反之同理。

若你要求严格一致，见 §9 的可选加固。

### 5.2 C4 · `SkillLoadoutService` 两个公开包装

```as2
/** 该技能当前占用的物理槽（1..12），空数组表示未装备。 */
public static function findEquippedSlots(skillKey:String):Array {
    return equippedSlots(skillKey);
}

/**
 * 按技能名取只读投影（含 mp / cooldownMs / level）。
 * 未学会、行损坏、被动、不可装备一律返回 null —— 与数字键的放行条件严格对齐。
 */
public static function getSkillDescriptor(skillKey:String):Object {
    var sync:Object = synchronize();
    if (!sync.success) return null;
    var info:Object = inspectFromScan(sync.scan, skillKey);
    if (!info.success || !info.learned || info.stateHealth != "ok" || info.writeBlocked === true) return null;
    var metadata:Object = info.metadata;
    if (metadata == null || metadata.Equippable !== true || isPurePassive(metadata)) return null;
    return projectLearned(info, sync.scan);   // 复用既有钳制，mp/cooldownMs 与槽描述符同源
}
```

### 5.3 C6 · `QuickSkillInputService.releaseBySkillName`

```as2
/**
 * 按技能名释放：已装备走槽通道（与数字键共享冷却/HUD），未装备走名字通道。
 * MP 一律由 unit.释放技能 扣，本方法只做「读成本 + 闸门 + 起冷却 + 刷显示」。
 * 返回 null = 名字非法/技能不可释放；否则 {attempted, released, reason, ...}。
 */
public static function releaseBySkillName(unit:Object, rawSkillName:String, keyCode:Number):Object {
    if (!unit || typeof unit.释放技能 != "function") return null;
    var skillName:String = SkillReleaseGuard.normalizeSkillName(rawSkillName);
    if (skillName == null) return null;

    // ① 已装备：完全复用数字键语义
    var slots:Array = SkillLoadoutService.findEquippedSlots(skillName);
    if (slots.length > 0) {
        for (var i:Number = 0; i < slots.length; i++) {
            var slotIndex:Number = slots[i];
            var descriptor:Object = SkillLoadoutService.getSlotDescriptor(slotIndex);
            if (!descriptor || descriptor.stateHealth != "ok" || descriptor.writeBlocked === true) continue;
            descriptor.__domainDescriptor = true;
            if (!isEquippedSkill(descriptor)) continue;
            if (!ManualCooldownService.isReady(ManualCooldownService.quickSkillKey(slotIndex))) continue;
            return releaseSlot(unit, slotIndex, descriptor, keyCode);   // 失败也直接返回，不换槽重试
        }
        // 已装备但全在冷却/损坏 → 到此为止，绝不落到名字通道
        return {attempted:false, released:false, reason:"cooldown", skillName:skillName, slotIndex:0};
    }

    // ② 未装备：名字通道
    var info:Object = SkillLoadoutService.getSkillDescriptor(skillName);
    if (info == null) return null;

    var cooldownKey:String = ManualCooldownService.skillKey(skillName);
    if (!ManualCooldownService.isReady(cooldownKey)) {
        return {attempted:false, released:false, reason:"cooldown", skillName:skillName, slotIndex:0};
    }

    var mpCost:Number = Number(info.mp);
    var cooldownMs:Number = Number(info.cooldownMs);
    if (isNaN(mpCost) || mpCost < 0 || isNaN(cooldownMs) || cooldownMs < 0) return null;

    if (Number(unit.mp) < mpCost) {
        notifyMpDenied(unit, skillName);      // 只读预检，不扣
        return {attempted:true, released:false, reason:"mp", skillName:skillName,
                mpCost:mpCost, slotIndex:0};
    }

    var released:Boolean = unit.释放技能(skillName, mpCost, keyCode) ? true : false;
    if (released) {
        ManualCooldownService.start(cooldownKey, cooldownMs);
        refreshMp(unit);
    }
    return {attempted:true, released:released, reason:released ? "" : "rejected",
            skillName:skillName, mpCost:mpCost, cooldownMs:cooldownMs, slotIndex:0};
}

/** 未装备技能没有 HUD 槽位，走本地提示 + 1s 静默窗口，不走 SkillResourceService（见 F5）。 */
private static function notifyMpDenied(unit:Object, skillName:String):Void {
    if (unit._name != _root.控制目标) return;
    var now:Number = getTimer();
    if (now - Number(unit.__skillMpNoticeAt) < 1000) return;
    unit.__skillMpNoticeAt = now;
    if (typeof _root.发布消息 == "function")
        _root.发布消息("<FONT COLOR='#e87864'>" + skillName + "：MP 不足，无法释放</FONT>");
    if (typeof _root.播放音效 == "function") _root.播放音效("message_ui.wav");
}

private static function refreshMp(unit:Object):Void {
    var interfaceRoot:Object = _root.玩家信息界面;
    if (interfaceRoot && typeof interfaceRoot.刷新mp显示 == "function") interfaceRoot.刷新mp显示();
}
```

### 5.4 C7 · 派发文件的两处调整（相对旧文档 §5.6）

1. **显式传 unit**，不用 `_parent`。`冷兵器主动技能搓招` 是从 `拳刀行走状态机` 里以 `_root.技能函数.X()` 形式调用的，这时函数内 `_parent` 不再指向单位；旧骨架靠 `_parent` 会拿到错误对象。
2. **不要调 `搓招监控`**。它内部第一行就是 `var 自机 = _parent`（`单位函数_雾人_空手搓招指令.as:15`），同样会错对象；改成自己置位。

```as2
_root.技能函数.冷兵器技能释放 = function(自机:Object, 定义:Object, 触发码:Number):Number {
    自机.搓招缓冲已消费 = true;
    自机.当前搓招名 = "";
    自机.当前搓招ID = 0;

    var 结果:Object = QuickSkillInputService.releaseBySkillName(自机, 定义.技能, 自机.C键);
    if (!结果 || 结果.released !== true) return 0;   // 失败也消费输入，避免 6 帧内重试
    return 触发码;
};
```

> 刘海/连击 overlay 的 `Ncombo` 通知（`搓招监控` 里那 8 行）如果需要保留，在这里照抄 3 行即可（`_root.server.sendSocketMessage("Ncombo|...")`），不必依赖 `_parent`。

## 6. 帧级时序（以「未装备 迅斩 · ↘C」为例）

| 帧 | 发生什么 | MP | 冷却 |
| --- | --- | --- | --- |
| n-1 | 按住 ↘，V8 进 state₁ | — | — |
| n | 按 C；同帧 `动作C=true`，拳刀状态机跑帧检查兜底 → 方向命中 | — | — |
| n | `releaseBySkillName`：槽空 → 名字通道就绪 → `unit.释放技能("迅斩", 20, C键)` | **-20** | — |

| n | `状态改变("技能")` → man 被卸载 → 技能容器 attach → 派发函数 return | — | — |
| n+1 | Launcher K 回 `迅斩`；`搓招缓冲已消费` 已置位 ⇒ 不二次触发 | — | — |
| n+150 | 冷却走完，`isReady` 恢复 | — | 结束 |
| 任意 | 按住 C 不放：`__冷兵器技能C已消费` 拦住重复；松手才复位 | — | — |

## 8. 已知限制与风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 未装备技能**没有冷却条** | 低 | 冷却中再按只是「没反应」。若嫌没反馈，可让 `notifyMpDenied` 的错误分支复用一句「冷却中」提示 |
| 未装备技能**没有「仅够一次」提示** | 低 | HUD 快照只覆盖已装备槽（F6）；要补需扩协议 |
| 装备/卸下会切换冷却通道 | 低 | 只影响「面板内换装后立刻放一次」的窗口；面板通常暂停战斗 |
| 用 `发布消息` 而非 HUD toast 提示 MP 不足 | 低 | 与数字键的 toast 样式不一致；根因是 F5 的 slot 校验 |
| 名字通道与槽通道双写 | 中 | 这是刻意的（互不绕过）；真要做到严格一致见 §9-1 |
| 忘传 `detail.mp`、手写死 20 | 高 | 拔刀术会少扣 20、火舞旋风少扣 30（§2.1）；成本只能从 `getSkillDescriptor` 取 |

| 丢 BOM | 高 | 新 `.as` 用「复制现有文件再改名」创建 |
| 回滚 | — | 删 C1/C7，`git checkout` C2-C6/C9/C10；无存档字段、无资源改动 |

## 9. 需要你拍板（只有两条，其余沿用旧文档）

1. **冷却要不要跨通道互通？**
   - A（默认，推荐）：两条通道各管各的，接受「面板换装后可放一次」的边界。
   - B（严格）：释放成功时同时启动 `skill:<名>` 与所有已装备槽的 `quick:<n>`，闸门要求全部就绪。要多改 `releaseSlot` 一处，并更新 `ManualCooldownServiceTest` / `LongGunSubWeaponCoreTest` 的既有断言。

2. **MP 不足的提示样式？**
   - A（默认）：本地 `发布消息` + 音效，零跨层改动。
   - B：正式扩一条 `kind="skillfree"`（C# 允许 `slot=0`）+ `SkillResourceService` 分支，HUD 走标准 toast。**需要 `dotnet build`**，本机 SDK 版本锁不匹配（`global.json` 锁 10.0.300，本机只有 7.0.403），本轮不做。

> 另外沿用旧文档 §9 的三条待决：指令形态（推荐「方向+C」）、门槛是否同时约束数字键（推荐是）、本轮只做 5 个还是加 `六连/空间斩`。
