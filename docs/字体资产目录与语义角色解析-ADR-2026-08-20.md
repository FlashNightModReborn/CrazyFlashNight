# C# / Web 字体资产目录、语义角色解析与低负担创作工作流 ADR

**文档角色**：C# / Web 运行时字体资产目录、XML 真源、语义角色、运行时解析、下载回退、CLI 工具与迁移门的 canonical ADR。当前已实现行为仍以 [`launcher/web/assets/fonts/README.md`](../launcher/web/assets/fonts/README.md)、[`FontPackTask.cs`](../launcher/src/Tasks/FontPackTask.cs) 和 [`NativeHudFonts.cs`](../launcher/src/Guardian/Hud/NativeHudFonts.cs) 为准；本文描述目标架构，不把提案写成现状。<br>
**状态**：`PROPOSED / PILOT_REQUIRED / NOT_IMPLEMENTED`。本文冻结首期边界和验收方法，不宣称根 `fonts/`、`fonts.xml`、`fontctl`、统一 C# / Web resolver 或迁移后的发行闭包已经存在。<br>
**决策日期**：2026-08-20。<br>
**最后核对代码基线**：commit `957678d84bf1f271010cfe68db41df72cfdae606`（2026-08-20）。<br>
**证据边界**：本轮完成仓库静态盘点、配置解析与引用计数；未验证远程 URL 当前可用性、字体许可证法律结论、真实 WebView2 / GDI 渲染观感或正式 runtime E2E。Flash / FLA / XFL 作者字体治理与 CS6 验证已明确排除在本 ADR 首期及后续 Gate 之外。

## 0. 决策摘要

1. 在项目根部建立唯一的 C# / Web 运行时字体入口 `fonts/`；顶层分为受版本控制的 `permanent/` 与整体 gitignored 的 `temporary/`。现有 `launcher/web/assets/fonts/` 和 `%LOCALAPPDATA%/CF7FlashNight/fonts/` 只在迁移期保留，不成为并行手写真源；`闪7重置版字体/` 保持为待随 Flash UI 退役的 legacy 作者目录，不纳入本次收口。
2. `fonts/fonts.xml` 是字体资产、下载来源、语义角色与预设映射的唯一人类可编辑真源；`fonts/fonts.xsd` 只负责结构约束，跨引用、格式、哈希、字符覆盖与可达性由语义校验器负责。
3. 文案人员继续使用熟悉的 XML / JSON 工作流，不要求维护 CSS、C# 字体族名、SHA-256 计算或下载缓存。首期不建设 Electron、Web 编辑器或字体工作台。
4. 工程复杂度集中到单一 CLI `tools/fontctl/` 和运行时 resolver。CLI 默认非交互、可无人值守，提供中文诊断、稳定退出码与 `--json` 机器输出；未来任何 GUI 只能是同一 XML / CLI 的薄壳。
5. 字体模型至少分为 `asset → face → role → preset/context`。业务消费者只引用稳定 role / preset ID，不裸用“思源宋体”“Microsoft YaHei”等物理 family；系统 UI、符号字体和程序化 path glyph 可作为显式例外登记。
6. 顶层来源优先级冻结为 `temporary/custom → temporary/cache → permanent/runtime → system fallback`。临时缺失且声明远程来源时允许后台下载；下载等待或失败期间仍立即使用常驻或系统回退，网络不得成为同步启动门。
7. `temporary/custom` 服务开发者、文案与玩家手工投放；`temporary/cache` 只由下载器维护；`temporary/generated` 只保存可重建投影和诊断。三者不得混成一个无法区分来源的平面目录。
8. 文件自动扫描只负责“发现与报告”。未在 XML 中取得稳定 asset ID 或显式 role / preset 绑定的文件不得按遍历顺序自动改变游戏字体；同名、同 ID 或内部 family 冲突必须确定性拒绝或解释。
9. C# 与 Web 必须消费同一规范化解析结果。首次实现允许 C# 与 CLI 使用不同语言，但必须由共享 fixtures 锁定 XML 归一化、优先级、fallback 和错误语义，禁止两套独立映射表。
10. 首次原生施工后，普通字体文件、下载地址、role 和 preset 修改必须保持数据驱动，不要求修改或重新编译 C#。触及 resolver 实现、协议、打包器或 native 字体生命周期时，仍按 Launcher runtime 构建与发布规则处理。
11. 首期及本 ADR 后续 Gate 的唯一新增投资方向是 C# / Web runtime。不得为 Flash / FLA / XFL 新建平行字体目录、XML 映射、CLI 子命令或 CS6 验收链；旧 UI 迁移时随组件退役旧 face 依赖。若旧作者字体被重新选入 C# / Web，必须作为新的 runtime asset 重新经过许可证、hash、字符覆盖与视觉验证，而不是整体搬迁。
12. ADR 只冻结架构和迁移门。每个现存字体最终绑定哪个 role、哪些预设保留、是否热加载，以及 Web 字体投影的具体实现，均须经 pilot 数据和真实渲染验证后接受。

## 1. 背景、现状与决策驱动

### 1.1 当前运行链

现役字体包由 [`font-pack-manifest.json`](../launcher/web/assets/fonts/font-pack-manifest.json) 声明 group、文件、URL、字节、SHA-256 与 shipped fallback。[`FontPackTask`](../launcher/src/Tasks/FontPackTask.cs) 将下载写入 `%LOCALAPPDATA%/CF7FlashNight/fonts/`，[`WebOverlayForm`](../launcher/src/Guardian/WebOverlayForm.cs) 把单一目录映射为 `https://cfn-fonts.local/`；Web 通过 [`foundation-top.css`](../launcher/web/css/panels/foundation-top.css) 与 [`task_panel.css`](../launcher/web/css/task_panel.css) 声明 `@font-face` 和部分角色变量。

Native HUD 另由 [`NativeHudFonts`](../launcher/src/Guardian/Hud/NativeHudFonts.cs) 按固定文件名查找思源宋体并通过 `PrivateFontCollection` 加载。Combo、伤害数字、FPS、系统图标和旧 overlay 仍有独立硬编码 family。Flash / FLA 制作字体位于 `闪7重置版字体/`，但该作者链不再扩建；长期由 C# / Web UI 迁移消解。

现役 C# / Web 链已经具备下载、哈希和系统 fallback，但资产、角色与消费依赖分散在 JSON、CSS、C#、JS Canvas、数据 HTML 与人工说明中；非程序创作者无法只通过一个位置完成“放入字体—指定用途—运行验证”。

### 1.2 本轮静态盘点

| 范围 | 机械事实 | 结论边界 |
|---|---|---|
| 现役 FontPack manifest | 5 groups、14 files、`119,211,978` bytes（113.69 MiB）；只有 92,380-byte JetBrains Mono 是 shipped fallback | 证明当前最佳视觉高度依赖下载，不证明 URL 当前可用 |
| 根 legacy 作者字体 | 11 个 TTF / OTF、`32,135,667` bytes（30.65 MiB） | 仅记录现状；不进入 `fonts/`、Gate A inventory 或发行迁移，除非单个字体被重新选为 C# / Web runtime asset |
| Web 生产样式扫描 | 排除 `dev/mockups/reference/lib` 后 34 个 CSS、293 个 `font-family`；69 处使用现有语义变量、35 处 `inherit`、189 处为其他直接声明或 `@font-face` alias | 证明角色化已有雏形但未收口；不把文件数或声明数冻结为未来合同 |
| Web 非 CSS 消费 | Canvas、动态 SVG、Bridge 预热和 [`tooltip.js`](../launcher/web/modules/tooltip.js) 的 AS2 `FONT FACE` 转换仍可直接产生 family | 仅改 CSS 变量不能完成迁移 |
| C# 消费 | Native HUD 集中入口只覆盖思源宋体；Combo、Arial Black、Consolas、Segoe UI Symbol、旧 overlay 与系统窗体分散 | 需要 role service 与显式例外，不能机械替换全部 `new Font(...)` |
| Flash/XFL tracked XML | 3,438 个 `face` occurrence、55 个不同 face；31 个 `DOMFontItem`、14 个不同 embedded face | 说明为 legacy 作者链建设完整映射成本很高；本 ADR 据此选择不重复投资，不把这些 face 转成 runtime role |
| 情报真实数据 | 59 个 JSON 均可解析；9 种 skin，481 paragraph、138 heading、35 note、25 handwritten、30 terminalLog、11 outburst；另有 neat/plain/rough/weary writerVoice | `skin × role`、`writerVoice × handwritten`、`tone × outburst/note` 映射有真实数据基础 |

盘点同时发现现有映射漂移：字体 README 的 group 总量低于 manifest 实值；Klee One 已从主要 role 链移除但仍随整组下载；Task Panel 使用精确 `Source Han Serif CN Heavy` alias，而部分 Workbench / Arena 栈只写中文 family 后回退 Regular；现有生产闭包脚本又把 manifest 路径和 `cfn-fonts.local` URL 当作固定输入。迁移必须先生成依赖图，不能只移动目录。

### 1.3 决策驱动

- 文案人员是字体表达的主要使用者，熟悉直接编辑 XML / JSON，但不具备或不应承担程序构建知识。
- 项目现有自定义音乐与压缩包覆盖安装已接受“玩家向游戏目录投放资产”的模型；本 ADR 不把安装目录写权限设为阻断前提。
- 字体选择包含不可替代的艺术判断，但哈希、格式、路径、缓存、下载、C#/Web 绑定和审计应由后端自动化吸收。
- Agent 与开发者需要可检索、可解释、非交互的 CLI，而不是需要维护独立前端状态的重型工具。
- 字体变化应尽量成为数据变化；不应因为把“情报标题”从 A 字体换到 B 字体就重新构建原生 Core。
- 网络不可用、字体缺字或文件损坏只能降低视觉质量，不得阻断游戏核心入口。

### 1.4 目标

- 一个目录回答“字体文件在哪里”，一个 XML 回答“字体是什么、从哪里来、用于什么”。
- 文案能够通过复制文件和编辑 XML 完成常规字体试验。
- C#、Web CSS、Canvas/动态 SVG 与兼容数据入口能解释到同一 role / asset。
- 临时覆盖、下载缓存、常驻资产和系统回退有确定性顺序与可观测 provenance。
- CLI 能在实现前发现未登记文件、断引用、缺字、重复映射和仍裸用 family 的消费者。
- 迁移完成后淘汰多份手工清单，并保持离线可用、可打包、可审计。

### 1.5 非目标

- 首期不建设 Electron、Web 字体编辑器、字体商城或通用素材管理平台。
- 不要求程序自动判断“哪个字体最有艺术表现力”。程序只提供发现、校验、预览所需数据和确定性解析。
- 不要求首期热加载 GDI `PrivateFontCollection`；允许以进程重启作为 native 字体生效边界。
- 不把系统 consent / security UI、`SystemFonts` 或 PlayerInfo 的程序化 path glyph 强行改成可替换 runtime 字体。
- 不为 Flash / FLA / XFL 建立字体目录、作者环境安装器、face 映射、迁移工具或 CS6 验收；旧 Flash UI 的字体依赖随对应 UI 迁移一并退役。
- 不在 ADR 阶段移动字体、修改 CSS/C# 消费者、下载网络资产或重新发布 Launcher runtime。
- 不因目录统一而自动获得任何第三方字体的再分发权。

## 3. 目标目录与来源模型

### 3.1 目录冻结

```text
fonts/
  fonts.xml
  fonts.xsd
  README.md

  permanent/
    runtime/

  temporary/                 # 整体 gitignore
    custom/                  # 文案、开发者、玩家手工投放
    cache/                   # 下载器拥有
    generated/               # resolver / CLI 可重建投影与报告
```

规则：

- `permanent/runtime/` 只容纳经过版本治理、许可证记录、manifest 引用、完整性和体积审计的运行时字体。
- `闪7重置版字体/` 不移动进 `fonts/`，resolver、CLI、打包器和运行时均不得扫描；未来若复用其中单个字体，按新的 `permanent/runtime` asset 独立引入。
- `temporary/custom/` 允许任意受支持字体；Git、打包器和正式闭包默认排除。
- `temporary/cache/` 禁止人工当作长期素材库；清理和覆盖只按 asset ID、期望 hash 与 provenance 执行。
- `temporary/generated/` 无独立真值。删除后必须可由 `fonts.xml + permanent + custom + cache` 确定性重建。
- 覆盖补丁不得递归清空 `temporary/`；若将来改变补丁器行为，须先更新本文和发行说明。

### 3.2 解析与获取分离

解析器每次为一个 role / face 请求生成有序候选：

1. XML 允许的 `temporary/custom` exact candidate；
2. 与 XML asset 版本 / hash 匹配的 `temporary/cache` candidate；
3. `permanent/runtime` candidate；
4. role 声明的 system family / generic fallback。

“临时缺失时下载”属于 acquisition，不改变当前帧的本地 fallback：

```text
resolve locally
  ├─ hit temporary/permanent/system → 立即返回可用字体
  └─ downloadable asset missing     → 记录 missing，后台下载到 staging
                                          ├─ verify + atomic publish → 下次解析命中 cache
                                          └─ fail                  → 保持 permanent/system
```

存在 URL 不得导致 permanent 被跳过；下载超时不等于字体解析失败；网络下载完成也不得在未定义的 GDI 生命周期中强行替换已加载 family。

### 3.3 自动发现与确定性绑定

- `scan` 递归发现受支持扩展名，读取内部 family/subfamily、weight/style、字符表和文件 hash。
- 发现不等于启用。文件必须获得唯一 asset ID，并由 role / preset 显式引用后才可改变渲染。
- `temporary/custom/<declared file>` 可以覆盖同 asset 的常驻候选；仅仅内部 family 相同不构成覆盖权。
- 同一层出现重复 ID、大小写折叠冲突、同 path 多声明或一个物理文件被声明成不兼容 face 时 fail closed。
- CLI 输出未登记字体和可复制 XML 片段；默认不自行修改 XML。任何 `--apply` / `--write` 必须显式且可复核 diff。

### 3.4 身份

- `assetId`：稳定文件/发行身份，不随中文显示名变化；建议使用小写 ASCII `kebab-case`。
- `faceId`：一个可选择的 family + weight + style + stretch 组合；同 asset 可提供多个 face。
- `roleId`：消费位置与排版语义，例如 `native.hud.body`、`web.intelligence.title`；不得使用具体字体名。
- `presetId`：一组 context 下的 role override，例如 `intelligence.diary`、`intelligence.terminal`。
- 文件 hash 是内容身份和下载完整性，不替代稳定业务 ID；更新字体版本必须显式更新期望 hash / bytes 并产生审计差异。

## 4. XML 语义合同

### 4.1 最小模型

| 层 | 必须表达 | 不负责 |
|---|---|---|
| asset | ID、显示名、文件、格式、target、许可证、可选下载来源、bytes/hash | 业务场景 |
| face | asset、family alias、weight、style、stretch、支持的 renderer | 下载策略 |
| role | 稳定 ID、显示名、有序 face/system fallback、必需/可选策略 | 单篇文案内容 |
| preset | context 下 role → face/role override | 物理文件完整性 |
| bundle | 可选的下载/预取组合 | 消费者选择字体 |

`fonts.xml` 可以把简单单-face asset 压缩为一个 `<font>` 元素，但解析后的规范化模型必须保留上述层次。XSD 不得把当前 14 个文件或现有 CSS 变量写死为封闭枚举。

### 4.2 示例形状

以下只冻结可理解性和引用方向；元素名、属性拆分与 XSD 细节在 Gate A pilot 中定稿：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<fontCatalog version="1">
  <fonts>
    <font id="source-han-serif-cn-regular"
          label="思源宋体 常规"
          file="source-han-serif-cn-regular.otf"
          targets="web native"
          license="OFL-1.1">
      <face id="source-han-serif-cn-regular-400"
            family="Source Han Serif CN"
            weight="400"
            style="normal" />
      <download url="https://example.invalid/font.otf"
                bytes="11626108"
                sha256="..." />
    </font>
  </fonts>

  <roles>
    <role id="web.intelligence.body" label="情报正文">
      <use face="source-han-serif-cn-regular-400" />
      <systemFallback family="SimSun" />
      <genericFallback family="serif" />
    </role>
  </roles>

  <presets>
    <preset id="intelligence.diary" label="日记">
      <bind role="web.intelligence.body" face="lxgw-wenkai-screen-400" />
      <bind role="web.intelligence.handwritten" face="jason-handwriting-9-400" />
    </preset>
  </presets>
</fontCatalog>
```

示例 URL 使用 `.invalid`，不是下载配置。正式 URL 必须由 source audit 和下载验证覆盖。

### 4.3 角色粒度

全局 `title/body/mono` 不足以承载现状。首轮 role inventory 至少区分：

- `web.intelligence.title/body/note/handwritten/outburst/archive/terminal`
- `web.task.title/body`
- `web.workbench.title/body/mono`
- `web.stage-select.body/mono`
- `native.hud.body/mono/symbol`
- `native.combat.number/label`
- `native.combo.body`
- `legacy.tooltip.ms-mincho/fixedsys` 等显式兼容 alias

具体集合由 `fontctl audit-usage` 生成并在 Gate A 冻结；不得为了减少 role 数把视觉用途不同的任务标题、情报标题和战斗数字合并。

### 4.4 情报 context

现有 `skin`、`writerVoice` 与 `tone` 已构成真实选择维度：

- `skin` 选择整体 preset；
- `writerVoice` 只覆盖 handwritten / note 等允许个体笔迹的 role；
- `tone` 对 note / outburst 做局部 override；
- 未声明 context 时使用 role 默认链；
- 将来如需单篇例外，只允许引用稳定 `fontPreset` / role override ID，不在内容 JSON 中写物理 family。

静态数据证明该模型可表达当前 59 篇情报，不等于当前每个 face 选择已经通过艺术验收。最终映射必须用真实中文长文、标点、生僻字、数字和多 DPI 进行可见 pilot。

### 4.5 XML 校验

校验至少包括：

- XSD、版本、重复 ID、断引用和循环 role fallback；
- path canonicalization、目录越界、非法扩展名、大小写冲突和不可读文件；
- face weight/style/stretch 合法性及 renderer/format 兼容；
- permanent / remote 的 exact bytes + SHA-256；custom 的 observed hash 与 provenance；
- HTTPS、重定向、最大体积、URL 重复和 cache key；
- role 至少有一个可解析候选或明确 generic fallback；
- preset 只能覆盖存在且允许覆盖的 role；
- 许可证字段与 target policy；
- 已声明字符覆盖要求与实际 cmap 的差异；
- 未使用 asset、不可达 face、永不命中的 fallback 和同 role 重复候选。

## 5. 文案、开发者与 Agent 工作流

### 5.1 文案人员

常规试验流程冻结为：

1. 将 TTF / OTF / WOFF / WOFF2 放入 `fonts/temporary/custom/`；
2. 在 `fonts.xml` 添加或复制一条 font / face 声明；
3. 修改 role 或 preset 引用；
4. 启动游戏；启动时自动校验并输出可理解错误；
5. native 字体按首期 restart boundary 生效。

文案不需要运行 Electron、不需要编辑 CSS/C#、不需要手算 hash，也不需要理解 WebView2 虚拟主机。临时字体没有远程发布要求时可省略 download 和发行 hash；CLI 仍自动记录 observed hash 供诊断。

### 5.2 开发者与 Agent

建议入口保持单一：

```powershell
node tools/fontctl/cli.js scan
node tools/fontctl/cli.js validate
node tools/fontctl/cli.js resolve --role web.intelligence.title --preset intelligence.diary --explain
node tools/fontctl/cli.js sync --missing
node tools/fontctl/cli.js generate --check
node tools/fontctl/cli.js audit-usage
```

命令名在 Gate A 可微调，但能力边界冻结：

| 命令 | 默认行为 | 可写范围 |
|---|---|---|
| `scan` | 扫描元数据，报告新增/缺失/冲突，输出 XML snippet | 默认无；显式 `--write` 才能改 XML |
| `validate` | XSD + 语义 + 文件 + 许可证字段 + fallback 校验 | 无 |
| `resolve` | 对 exact role/context 输出候选、拒绝原因和最终命中 | 无 |
| `sync` | 下载缺失 remote asset 到 staging，校验后发布到 cache | 仅 `temporary/cache` |
| `generate` | 生成 Web/C# runtime projection、manifest 和报告 | 仅 `temporary/generated` 或受版本化生成物 |
| `audit-usage` | 扫 C#/CSS/JS/运行时数据中的裸 family 与旧路径 | 默认无；只产报告 |

所有命令必须：

- 默认非交互且无确认弹窗；
- 支持 `--json`、稳定 schema、确定性排序和非零失败码；
- 区分 warning、当前 fallback 可用、阻断错误与 pilot debt；
- 在错误中返回 XML path/line、asset/face/role ID、候选来源和建议动作；
- 不把网络失败、许可证缺字段和艺术选择混成一个 `font_failed`；
- 不要求 GUI、浏览器登录或本机全局安装字体。

### 5.3 工具布设

```text
tools/fontctl/
  README.md
  cli.js                 # 稳定入口；内部实现语言可在 Gate A 决定
  lib/
    catalog
    metadata
    resolver
    downloader
    generator
    usage-audit
  schemas/
  tests/
    fixtures/
```

不得再为 scan、下载、CSS 生成和 C# 检查分别建立互不共享语义的一次性脚本。若底层元数据解析使用 C#、Rust、Python/fontTools 或原生 helper，`cli.js` 仍可作稳定薄入口，但 helper 版本和输出 schema 必须受测试约束。

### 5.4 GUI 边界

首期没有 GUI Gate，也不把“未来可能做编辑器”写成施工依赖。只有在 XML + CLI pilot 证明仍存在高频、可量化且无法通过更清晰 schema/错误信息消除的创作负担后，才另行评估轻量界面。未来界面不得拥有第二份字体清单、下载状态或 role 映射。

## 6. Runtime 消费合同

### 6.1 单一 resolver 语义

生产 Host、CLI 和测试必须对同一 fixture 产生相同的：

- 规范化 asset/face/role/preset 图；
- 来源优先级与拒绝原因；
- remote missing / downloading / verified / failed 状态；
- system/generic fallback；
- target / format 可用性；
- stable diagnostics code。

实现可以跨语言，但不能以“都能读 XML”为理由接受行为漂移。Gate B 必须包含正例、缺失、重复、损坏、hash mismatch、下载失败、custom override、preset override、fallback cycle 与不支持格式的 exact fixtures。

### 6.2 C#

- 新 `FontCatalog` / resolver 在启动期读取 XML，按 role 创建和持有 `FontFamily` / `PrivateFontCollection`；业务 widget 不再固定拼接文件路径。
- role API 必须携 size、style、unit 等渲染参数；face 映射不能吞掉调用方的布局意图。
- `SystemFonts`、Segoe UI Symbol 等系统所有面，以及 PlayerInfo [`PlayerInfoPathGlyphAtlas`](../launcher/src/Guardian/Hud/PlayerInfo/PlayerInfoPathGlyphAtlas.cs) 的程序化 path glyph，通过例外表保留，不伪装成可下载 TTF。
- 首期 catalog 和 private collection 采用进程生命周期；XML / custom 变化提示“重启生效”。热换需另立生命周期设计，不能泄漏 collection 或让旧 Font 对象悬空。
- FontPack 下载和 native prewarm 的顺序必须统一；未经 resolver 校验的 cache 文件不得先被 `AddFontFile` 使用。

### 6.3 Web

- CSS 消费者使用生成的 role custom property；Canvas / 动态 SVG 使用生成的 JS role registry，不自行复制 family stack。
- `@font-face` alias 由 catalog 生成，role 必须引用该 exact alias，消除中文内部 family 与 CSS alias 漂移。
- WebView2 当前一个虚拟 host 映射一个目录。新实现必须选择“resolved projection directory”或受控 `WebResourceRequested` handler，实现逐文件来源优先级；不能把两个目录都写进注释后仍只映射一个。
- 独立 Web harness 必须得到与 Host 相同的生成 catalog fixture；不得因为没有 `cfn-fonts.local` 就跳过 role contract。
- Bridge 预热按实际可见 role / preset 请求，不裸写 `LXGW WenKai Screen`。

### 6.4 兼容入口

- [`tooltip.js`](../launcher/web/modules/tooltip.js) 对 AS2 `FONT FACE` 的兼容必须经受控 alias 表解析；现有 `ms mincho`、`fixedsys` 可以保留兼容 role，但不得允许任意数据绕过 catalog。
- JS Canvas、动态 SVG、CSS inline style 和 C# `new Font(string, ...)` 纳入 `audit-usage`；迁移结束后只允许明示 allowlist。
- XFL `face` / `DOMFontItem` 不进入 catalog 或 `audit-usage`。AS2 `FONT FACE` 仅在其内容已经进入 C# / Web 渲染边界时作为 legacy 输入做 alias 收口；这不授权修改 Flash 源或为其补建字体系统。

### 6.5 普通字体变更不重编译

首次引入 resolver 会触及 C#、Web、打包和测试，必须走相应 runtime 构建边界。完成后，下列变化应只修改 `fonts.xml`、字体资产或可重建投影：

- role / preset 绑定；
- remote URL、hash、bytes；
- permanent / custom 文件；
- system fallback 顺序；
- bundle / prefetch 组合。

如果普通映射变化仍要求编辑生成的 C# 常量并重编 Core，Gate B 不通过。只有 resolver 代码、协议、native loader、Web resource handler 或打包器实现变化才进入原生 release source。

## 7. 下载、完整性与许可证

### 7.1 Remote

- 只允许 HTTPS；是否需要 host allowlist 在 Gate A 冻结，但 redirect 后仍须重新校验 scheme/host。
- remote asset 必须声明 SHA-256 和期望 bytes；空 hash 不得视为通过。
- 下载先进入唯一 staging 文件，设置最大响应/落盘体积，完成后验证 bytes、hash、扩展名、magic 和字体解析，再以不破坏旧有效 cache 的方式发布。
- cache key 至少绑定 `assetId + expectedSha256`；并发 sync 不得共享可猜的单一 `.tmp` 所有权。
- cancel、网络失败、hash mismatch 或 publish 失败只清理本事务 staging，不先删除旧有效目标。
- 日志记录 requested URL、final URL、bytes、hash、错误分类和最终来源，但不把本地任意绝对路径暴露给 Web 内容。

### 7.2 Local custom

- custom 文件不要求预先声明发行 hash，但 resolver 必须计算 observed hash、解析字体并记录来源。
- custom 只在本机/当前覆盖包中生效，不自动复制进 permanent、Git 或正式发布资产。
- 损坏或不支持字体只隔离该 candidate；role 继续 permanent/system fallback。

### 7.3 Permanent runtime

- permanent runtime 字体必须有许可证标识、来源、hash、bytes、target 和打包闭包。
- legacy 作者字体不因磁盘上存在而获得 runtime 身份；复用时必须逐个作为新 asset 完成许可证与嵌入边界审计。
- 字体子集化会改变 bytes/hash/coverage，必须成为新的 asset/version；不能在构建中静默改写原 asset 后沿用旧 identity。

## 8. 分期迁移与 Gate

### Gate A：Schema、盘点与只读 CLI

目标：不改变任何 runtime 行为，先证明目录和语义可以完整表达现状。

- 新建 `fonts/` 目录骨架、`fonts.xml`、XSD 和 README；`temporary/` gitignore。
- 实现 `scan / validate / resolve / audit-usage` 的只读闭包与 fixtures。
- 从当前 manifest、CSS、C#、JS 和运行时数据生成完整 inventory；每个 raw family 分类为 migrate / compatibility / system-owned / path-glyph。
- 把当前 14 个 manifest runtime asset 和已有 intel role 无损表示到 XML；11 个 legacy 作者字体不进入目标图。
- 冻结首轮 role/preset ID；艺术选择仍可标 `pilot_pending`。
- `node tools/validate-doc-governance.js`、XML/CLI tests、链接和 `git diff --check` 全通过。

Gate A 不得声称 runtime 已使用新目录。

### Gate B：Resolver shadow 与生成闭包

目标：证明 C# / CLI / Web projection 对同一 XML 得到相同结果，但旧 FontPack 仍保持可见 authority。

- Host resolver 与 CLI fixtures exact parity。
- shadow 模式读取新 XML，记录与旧 manifest / CSS / NativeHudFonts 的差异，不改变玩家可见字体。
- 实现 `sync`、安全 staging、cache 和 resolved projection；完成负向矩阵。
- 生成 CSS/JS role registry 和生产资源清单；`generate --check` 零 diff。
- 证明普通 role 映射变化不修改 C# 源码。

### Gate C：Web cutover

目标：Web 的 `@font-face`、CSS、Canvas、动态 SVG、Bridge 预热和 tooltip compatibility 改由 catalog 驱动。

- 生产 CSS 图中 raw family 只剩 allowlist；alias 与 manifest exact-set 一致。
- 情报 59 篇的 skin/writerVoice/tone 代表样例覆盖，含中文长文、标点、生僻字和逐字符 fallback。
- 1024×576、1600×900、1920×1080 与 100/125/150/175% 下检查溢出、行高、Canvas measureText 和布局。
- 下载缺失、离线、损坏 custom、cache mismatch 和 permanent fallback 均有 harness / runtime 证据。

### Gate D：Native cutover

目标：Native HUD、Combo、伤害数字、mono 和 symbol role 受统一 resolver 管理，同时保留 system/path-glyph 例外。

- 启动顺序保证 catalog 校验先于 native prewarm 使用 cache。
- 测试 custom override、cache、permanent、system fallback、style fallback 和 restart boundary。
- 人工确认 HUD、Combo、伤害数字、符号、中文基线与多 DPI；字体变化不得破坏固定宽度、对齐和 hit layout。
- C# 改动按 [`testing-guide.md`](../agentsDoc/testing-guide.md) 运行 Launcher build/tests；自动测试不能代签观感。

### Gate E：打包、退役与 pilot 结论

目标：新目录成为唯一运行时真源，旧路径和双写彻底退出。

- [`pack.config.yaml`](../tools/cf7-packer/pack.config.yaml) 收入 permanent/XML/XSD/必要生成物，排除 temporary。
- 更新 workbench/crafting/equipment 等 production closure 中的旧 manifest 路径与 `cfn-fonts.local` exact-set 合同。
- 旧 `font-pack-manifest.json`、旧 AppData 特定路径和 CSS/C# 手工映射要么删除，要么成为从 XML 生成且由 `--check` 锁定的兼容投影。
- `闪7重置版字体/` 保持在新 runtime 闭包之外；Gate E 不移动、不校验也不重打包该目录。
- isolated candidate 绑定实际进程、build identity 和 payload closure；视觉 pilot 通过不等于 runtime promotion。
- 涉及 Core 的最终 source 必须按现役 v2 双 signer / 双 faultDomain 流程发布；未 promotion 不称部署完成，未从正式入口复验不称 `standard_entry_verified`。

## 9. 证据分层与验收矩阵

| 层级 | 必须证明 | 不能代签 |
|---|---|---|
| 静态 inventory | 文件、引用、角色、裸 family、许可证字段和路径闭包 | XML resolver 行为、实际字形 |
| Schema / CLI fixtures | 解析、优先级、fallback、错误码、生成 determinism | Host/Web 真实消费 |
| Host unit/integration | C# face 生命周期、cache 验证、prewarm 顺序、role API | Web CSS/Canvas、真实观感 |
| Web harness | CSS alias、role/preset、Canvas/tooltip、布局和离线 fallback | Host↔WebView2 正式旅程 |
| isolated runtime pilot | 实际进程路径、字体来源、可见角色、重启和故障回退 | promotion、标准入口 |
| promoted / standard entry | 正式 release identity/closure 与部署后入口 | 未覆盖字体/场景或许可证法律结论 |

任何 Gate 的“全绿”只覆盖其实际执行的层。尤其：CLI 能解析字体不证明 GDI/WebView2 渲染正确；系统 fallback 可用不证明设计意图成立；维护者挑选某个字体不证明许可证允许随发行版分发。

## 10. 风险、成本与缓解

| 风险 | 影响 | 冻结缓解 |
|---|---|---|
| XML 变成另一份重复清单 | 继续手改 manifest/CSS/C#，漂移更严重 | XML 单真源；过渡投影只能生成并 `--check` |
| role 过粗 | 一次替换破坏任务、情报、战斗等不同视觉语义 | 分域 role；preset/context 覆盖；Gate A inventory 冻结 |
| role 过细 | 文案难以理解、映射重复 | 中文 label、role inheritance、preset；CLI 报 unused/duplicate |
| 任意文件自动抢占 | 文件遍历顺序或内部 family 冲突造成不可复现视觉 | 发现与启用分离；stable ID + XML explicit bind |
| 网络阻塞启动 | 无网玩家卡在下载 | acquisition 与 resolve 分离；立即 permanent/system fallback |
| custom/cache 混放 | 下载器误删玩家字体，无法解释来源 | `custom/cache/generated` 三目录和 provenance |
| 字体损坏或恶意文件 | GDI/Web parser 崩溃或资源耗尽 | 体积上限、hash、magic、解析探针、candidate 隔离 |
| 字体度量变化 | 溢出、数字错位、点击区与视觉不一致 | role-specific metrics pilot、多 DPI、Canvas/GDI 测量 |
| C# / CLI 解析漂移 | Agent 检查通过但运行时选择不同 | normalized fixtures exact parity、稳定 diagnostics code |
| 为待退役 Flash 建平行字体治理 | 重复盘点、目录、工具和 CS6 验收投资，且未来仍要删除 | Flash 作者链明确冻结在范围外；只在 C# / Web 边界处理仍可达的 legacy 输入 |
| 生成物变成人工真源 | 修改 XML 后仍需手修 CSS/JSON | generated header、只写 generated 目录、`generate --check` |
| 每次映射都重编 Core | 文案试验成本过高并扩大发布链 | runtime data loading；普通映射不生成需编译的 C# 常量 |
| GUI 先行 | Electron/前端依赖吞噬核心施工和 Agent 上下文 | 首期明确不做；未来 GUI 必须为 XML/CLI 薄壳 |

主要实施成本是跨 C#/Web 的 resolver、字体元数据解析依赖、旧 production closure 迁移和多 renderer 视觉验证。回报是字体选择从程序修改降为可审计数据修改，并把文案、开发者、玩家和 Agent 的入口收束到同一目录/合同。

## 11. 被拒绝方案

### 11.1 保持现状，只补 README

拒绝。当前 runtime manifest、CSS、C#、JS 和数据已经形成多真源，README 无法机械阻止 alias、总量和可达性漂移。

### 11.2 首期先做 Electron / Web 字体编辑器

拒绝。文案已经能编辑 XML/JSON；GUI 会先引入打包、依赖、前端状态与 Agent 维护面，却不消除 resolver、下载、安全和跨 renderer 合同。

### 11.3 内容直接写物理 family

拒绝。会把 `Source Han Serif CN Heavy` 等实现细节扩散到每篇文案，统一替换无法完成，也会重现 AS2 `FONT FACE` 旁路。

### 11.4 目录扫描后“第一个匹配 family 胜出”

拒绝。文件顺序、内部命名、大小写和多 face 字体均可能变化，无法解释、复现或安全回退。

### 11.5 URL 存在时必须下载成功才查 permanent

拒绝。远程获取不能阻断本地可用字体；下载只提升后续解析优先级，不撤销 permanent/system fallback。

### 11.6 C#、Web 各自解析和维护映射

拒绝。允许跨语言实现，不允许跨语言拥有不同规范化结果；fixtures 和生成投影必须把差异变成测试失败。

### 11.7 将 Flash 作者字体纳入首期统一治理

拒绝。Flash UI 长期迁往 C# / Web；为其建立 authoring 目录、55 个 face 映射、安装/校验工具和 CS6 Gate 会形成明确的重复投资。旧目录保持 legacy；只有被 C# / Web 明确选中的单个字体才按 runtime asset 重新进入本合同。

- 用户确认 Flash 字体施工暂不进行，长期通过 UI 向 C# / Web 迁移消解，避免平行治理重复投资；
- 本 ADR 的目录、真源、角色模型、CLI 边界、迁移 Gate 与证据分层提案。

当前未完成：

- 根 `fonts/`、XML/XSD、CLI、resolver、迁移 inventory 的任何实现；
- Web/Native consumer cutover；
- 字体许可证正式审计；
- runtime、视觉 pilot、candidate、promotion 或部署。

ADR 从 `PROPOSED / PILOT_REQUIRED` 进入接受至少要求 Gate A 完成，并由维护者确认：XML 的实际编辑负担可接受、CLI 错误可理解、现有资产/角色能够无损表达、没有把手工复杂度从代码转嫁成更繁琐的 XML。接受 ADR 不等于后续 Gate B–E 已实现。
