# 技能系统 → Web Panel：独立主线工程落地规划

**文档角色**：技能查看、学习/升级、快捷栏装备三条交互从 Flash UI 迁移到 Launcher Web Panel 的专题实施规划 / ADR。本文冻结目标架构、协议形状、切片顺序和验收门；在对应切片落地前，文中的新类、新命令和新面板均是**拟议契约，不是当前实现**。

**最后核对代码基线**：commit `6ff3308f38`（2026-07-15，代码树）；核对范围包括技能引擎、技能 XML/教师 JSON、SaveManager、快捷技能输入与手动冷却服务、旧技能/学习 UI、Launcher Panel 总线及现有 crafting/inventory 纵切。

**前置必读**：跨 AS2 / C# / Web Panel 的通用护栏以 [AS2 UI → Web Panel 迁移指南](../agentsDoc/as2-web-panel-migration.md) 为准；验证命令和 Flash CS6 口径以 [testing-guide.md](../agentsDoc/testing-guide.md) 为准；任务切片服从 [agent-harness.md](../agentsDoc/agent-harness.md)。

## 0. 结论与状态

- 状态：**设计冻结，尚未开始实现**。
- 裁决：建立独立 `skills` 领域和独立 `panel=skills`，**不挂到 `inventory` domain，不等待装备栏 View，不复用 `InventoryCoordinator`、ItemCollection、slot lease 或物品格写协议**。
- 复用边界：可复用 `DualPaneShell`、PanelScale、卡片/筛选/模态等**展示 primitive**；Skill 自有 `SkillCoordinator`、request mux、领域写门和 AS2 权威服务。
- 一个面板覆盖两个入口：`view=manage` 用于查看/整理/装备技能，`view=trainer` 用于教师目录、学习/升级及当前配置回看。不要拆成两个 panel ID。
- 战斗边界：本主线迁移**管理交互**，不把技能施放、MP 判定、手动冷却或被动效果计算搬进 Web/C#。`QuickSkillInputService`、`ManualCooldownService` 和战斗单位仍在 AS2。
- 落地顺序：先抽 AS2 技能/快捷栏模型，再打通只读快照，再迁装备写，最后迁教师学习；入口切换和旧 UI 清理永远在功能闭环之后。

### 0.1 为什么必须独立

技能页和物品页只在视觉上都像“格子 + 详情 + 拖放”，权威模型并不相同：

| 维度 | 物品工作台 | Skill 主线 |
|---|---|---|
| 权威集合 | `ItemCollection` / 物理槽 / owned 容器 | `_root.主角技能表` + `_root.快捷技能栏1..12` + `_root.技能点数` |
| 核心写 | move / merge / swap / sort / trade | learn / upgrade / equip / unequip / passive / reorder |
| 并发凭证 | 容器 epoch + slot lease | 技能态 revision + 学习一次性 token |
| 外部上下文 | 背包、仓库、商店 | 当前教师会话、角色等级、技能点、难度模式 |
| 活体副作用 | 装备属性、库存事件 | 被动技能重算、角色投影、动态 CD/MP、快捷输入描述符 |

把 Skill 塞进 inventory domain 会让 Web/C# 开始理解 `主角技能表` 的数组形状和被动副作用，也会把不存在的“快捷技能 ItemCollection”伪造成物品容器。独立领域能让两条主线只在视觉壳层相交。

### 0.2 本主线包含与不包含

包含：

1. 查看已学技能、等级、说明、类型、消耗、冷却和启用状态。
2. 教师上下文内学习新技能、批量升级到目标等级、技能点结算。
3. 12 槽快捷技能装备/替换/卸载。
4. 纯被动技能启用/停用、混合“被动&主动”技能的正确联动。
5. 已学技能顺序整理，保持旧 80 槽存档形状兼容。
6. 快捷输入从 HUD MovieClip 描述符改读 AS2 领域模型，为 NativeHud 最终删壳解除依赖。

不包含：

- 人物装备栏、药剂栏、背包物品或装备属性迁移。
- 技能伤害/平衡公式、技能树 AI/佣兵元数据改造。
- 把施法、MP、冷却状态机或被动效果计算迁到 Web/C#。
- 第一阶段重做技能图标素材；缺图先走稳定 fallback。
- 在功能切换前删除旧 `物品栏界面`、`学习技能界面` 或 HUD 快捷槽 MovieClip。

## 1. 当前事实基线

### 1.1 权威数据与投影

| 数据 | 当前 SOT | 迁移后所有权 |
|---|---|---|
| 技能静态定义 | `data/skills/skills.xml` → `SkillDataLoader` → `_root.技能表/_root.技能表对象` | 仍由 AS2 加载并向 Web 投影 |
| 教师可教目录 | `data/skills/npc_skills.json` → `NPCSkillLoader` → NPC `.可学的技能` | AS2 创建 opaque 教师会话；Web 不上传目录 |
| 已学技能 | `_root.主角技能表`，固定 80 行，行形状 `[名称,等级,已装备,类型,启用]` | `SkillLoadoutService` 统一读写，SaveManager 形状不变 |
| 技能点 | `_root.技能点数` | AS2 学习事务内扣减 |
| 快捷技能 | `_root.快捷技能栏1..12`，SaveManager `装备储存数据[16..27]` | `SkillLoadoutService` 为运行态权威 facade，root 字段继续作存档兼容投影 |
| 被动效果 | `_root.更新主角被动技能()` → hero `读取被动效果()` → 动态 CD/MP | 写成功后仍由 AS2 同步执行 |
| 快捷施法 | `QuickSkillInputService` + `ManualCooldownService` | 留 AS2；只替换其技能槽描述符来源 |
| `skills_metadata.json` | 佣兵/AI 技能树元数据 | **不是玩家 Skill Panel SOT**，不得拿来覆盖 `skills.xml` |

协议中的稳定身份使用 `skillKey = skills.xml/Name`，不用数组位置或 Loader 临时 `id`。数组位置只作为排序位置投影；XML 重排不能改变存档所指技能。

### 1.2 类型语义不能简化

`SkillDataLoader` 的现行派生规则必须原样保留：

- `passive = Type.indexOf("被动") > -1`；
- `equippable = Type != "被动"`。

因此纯 `被动` 技能不可放入快捷栏、通过开关启停；`被动&主动` 一类混合技能同时 `passive=true`、`equippable=true`，通过快捷栏装备决定启用状态。不能用单个前端枚举把二者压扁。

### 1.3 当前已确认的迁移动因

1. 旧学习确认先执行 `_root.技能点数 -= 总价`，再调用可能因 80 槽已满而返回 `false` 的 `_root.学习技能(...)`，存在扣点但未学会的部分写风险。
2. 装备逻辑写在 `技能图标.xml` 的拖放 hitTest 中，卸载逻辑写在 HUD `快捷技能界面.xml`；规则跨两个 MovieClip，替换槽位时旧技能标志可能残留，且没有统一 dirtyMark 边界。
3. `QuickSkillInputService` 已承接 12 槽按键输入，`ManualCooldownService` 已承接手动冷却权威，但输入服务仍从 `_root.玩家信息界面.快捷技能界面["快捷技能栏"+N]` 读取技能名、MP 和 CD 描述符。HUD 仍是管理域与战斗域之间的隐式数据总线。
4. `技能图标` 有主 FLA 新结构和 `arts/things` 旧结构两个 linkage 导出者；迁移语义已裁决以 12 槽主 FLA 版本为准，但旧 UI 最终清理前仍须确认发布产物的实际命中者。
5. 普通模式通过 `[2]` 阻止同技能重复装备；EasyMode 旧拖放允许再次抓取已装备技能。新服务必须显式建模这个差异，不能靠布尔字段偶然工作。

## 2. 目标架构与所有权

```text
旧技能按钮 / 教师按钮
        │ panel_request(panel="skills", initData={view, trainerSession?})
        ▼
LauncherCommandRouter ── OpenPanel("skills")
        │
        ▼
skills.js + skills-runtime.js
  ├─ DualPaneShell / PanelScale / 共享视觉 primitive
  └─ SkillCoordinator（session mux、busy、write gate、reconcile）
        │ domain="skills"
        ▼
SkillTask（严格白名单、callId、timeout、回包重建）
        │ skillSnapshot / skillEquip / ...
        ▼
SkillPanelService（协议 facade、教师会话、学习 token、原子事务）
        │
        ├─ SkillLoadoutService（80 行技能表 + 12 槽 + revision + root/HUD 投影）
        ├─ skills.xml / npc_skills.json / 当前角色状态
        ├─ 更新主角被动技能 / dirtyMark / SaveManager 兼容字段
        └─ QuickSkillInputService（只读槽描述符；不再要求 HUD MC 存在）
```

### 2.1 分层职责

| 层 | 允许负责 | 禁止负责 |
|---|---|---|
| Web `skills.js` | 选择、筛选、拖放、确认模态、展示权威回包 | 计算学习是否合法、直接改点数/等级/被动、把 UI 乐观态当权威 |
| Web `SkillCoordinator` | callId mux、单飞、迟到回包隔离、`needs_reconcile` | 拼 AS2 game command、理解 `_root` 或存档数组 |
| C# `SkillTask` | command/payload 白名单、超时、回包 schema、写门、重建 `panel_resp` | 读取 XML 替 AS2裁决、缓存角色状态、重放未知结果写 |
| AS2 `SkillPanelService` | 教师会话、快照、学习预览/token/提交、协议错误 | 持有战斗按键/冷却循环、依赖 Web DOM |
| AS2 `SkillLoadoutService` | 技能表/快捷槽一致性、revision、装备/被动/排序、副作用 | 打开面板、处理 callId、依赖可见 HUD |
| HUD MovieClip | 迁移期可选 renderer | 权威技能名、装备规则、卸载规则、施法 gate |

### 2.2 与双栏工作台的关系

Skill 允许复用下列 Web 层能力：

- `DualPaneShell` 的两个 view-slot、挂载/卸载、焦点和 PanelScale；
- 卡片密度、筛选控件、确认模态、tooltip 和拖拽镜像；
- `Panels.register` / lazy registry / PanelHost 生命周期。

Skill 不复用：

- `GridContainerView` 的 `physicalSlot/lease` 语义；
- `InventoryCoordinator`、backpack write gate、`inventory_response`；
- `Offer=ownedItem`、move/merge/swap、装备物品 `containerId`；
- NPC 商店、商城或 crafting 的 token 与状态机。

若直接复用 `DualPaneShell` 会迫使它认识 Skill 命令，应先提取更窄的展示 primitive；不得为“复用”把 Skill 写协议塞回通用壳。

## 3. 面板信息架构

### 3.1 `view=manage`：我的技能

- 左栏：已学技能库。支持类型筛选、文本搜索、按 80 行原始顺序展示和排序操作。
- 右栏上部：当前技能详情，显示等级、类型、描述、MP/CD、被动/主动语义。
- 右栏下部：12 槽快捷栏，显示槽号、当前键位、技能、等级；点击选择为主，拖放为加速操作。
- 纯被动技能在详情区显示启用开关，不出现“装备到快捷栏”。
- 混合被动主动技能显示快捷栏状态，并明确“装备时启用”；不另给独立开关。

### 3.2 `view=trainer`：学习 / 升级

- 左栏：当前教师会话允许的技能目录，只显示 AS2 快照返回的条目。
- 右栏：技能详情、当前等级、目标等级步进器、等级门槛、技能点成本和权威预览结果。
- 用户确认前必须完成 `learnPreview`；仅有有效 `learnToken` 时启用提交。
- 提交成功直接用响应内完整 snapshot 重绘，不依赖“本地减点 + 本地升一级”。
- 可查看当前快捷栏，但教师模式 MVP 不要求在同一个确认模态内连带装备；学习与装备是两个独立写操作。

### 3.3 统一交互准则

1. 点击是完整路径，拖放只是快捷路径；键盘和手柄焦点不能依赖 pointer drag。
2. 槽替换必须明确展示“将替换 X”，由同一个 `equip` 命令原子完成，不先 `unequip` 再 `equip`。
3. 写请求进行中禁用所有 Skill 写按钮；读请求可显示旧快照，但不得清除未知写状态。
4. `needs_reconcile` 时只允许关闭或重新 `snapshot`，不自动重投学习/装备。
5. 所有说明文本按普通文本渲染；若以后返回 HTML，必须走既有 sanitization 边界，不能直接信任 XML 内容。

## 4. AS2 领域模型

### 4.1 `SkillLoadoutService`

拟议路径：`scripts/类定义/org/flashNight/arki/skill/SkillLoadoutService.as`。

职责：

- 规范化 80 行 `_root.主角技能表`，兼容历史字符串布尔值但只写真正 Boolean；
- 读取/写入 `_root.快捷技能栏1..12`，生成与 HUD 无关的槽描述符；
- 维护单调 `skillRevision`，对服务外 legacy 写进行签名探测；
- 原子实现 equip / unequip / setPassive / reorder；
- 每次成功写后统一设置 dirty、重算被动、刷新动态 CD/MP、投影旧 HUD（若存在）；
- 向 `QuickSkillInputService` 提供 `getSlotDescriptor(slot)`。

槽描述符最小形状：

```js
{
  slot: 1,
  equipped: true,
  skillKey: "闪现",
  level: 3,
  mp: 14,
  cooldownMs: 1700,
  iconKey: "图标-闪现"
}
```

这里的 MP/CD 在 AS2 内从当前 `_root.技能表对象` 读取，包含被动导致的动态修正；Web 只展示，战斗释放也从同一描述符读取。HUD 槽可以接收投影，但不再是读路径的前置条件。

### 4.2 revision 与 legacy 共存

当前仍有作弊码、旧拖放、旧学习 UI 等路径可能直接改 root 数据。单纯在新服务写成功后 `revision++` 无法发现外部写，因此服务需维护轻量 `stateSignature`：

- 签名只覆盖 80 行的名称/等级/装备/启用和 12 个快捷技能名，不包含 UI MovieClip 字段；
- 每次 snapshot 和每次写前调用 `synchronize()`；签名变化但不是本服务刚完成的写时，revision 增长并清空所有学习 token；
- 新服务完成写后重新签名并增长一次 revision；
- Web 所有写必须携 `expectedRevision`，不匹配返回 `stale_state` 和最新 revision，不做部分写。

这不是永久双写方案。入口切换后应让所有生产写都经过服务；签名探测保留一段兼容期，用于作弊码/历史存档与回滚。

### 4.3 快捷栏一致性规则

1. **目标槽原子替换**：一次事务同时处理被替换技能、新技能、root 槽字段、80 行标志和可选 HUD 投影。
2. **普通模式唯一**：同一 `skillKey` 已在其他槽时返回 `already_equipped`。
3. **EasyMode 兼容**：保留旧 UI 可重复装备的有效行为；`[2]`/`[4]` 必须按“该技能是否仍出现在任一槽”派生，卸掉一个副本不能把其他副本标成未装备。
4. **纯被动不可装备**：`Type == "被动"` 只能 `setPassive`。
5. **混合被动**：可装备；最后一个槽卸下时关闭 `[4]`，任一槽装备时开启 `[4]`。
6. **冷却不可洗掉**：equip/unequip 不重置、启动或缩短 `ManualCooldownService` 的槽冷却；替换槽位后新技能继承该槽仍在进行的冷却 gate，避免换装绕过 CD。
7. **空/坏存档 fail-closed**：技能不存在、等级非法或槽名不在已学表时不允许施法；snapshot 标记诊断并由显式修复/卸载收敛，不能静默创造技能。

### 4.4 被动与排序

- `setPassive` 只接受纯被动技能；写 `[4]` 后执行完整被动副作用链。
- `reorder` 使用稳定 `skillKey + targetIndex(0..79)`，AS2 现场定位 source；不信任 Web 提供的 source index。
- 排序只交换 80 行，不改快捷槽中的 `skillKey`；完成后重新推导每行装备/启用状态，旧 `对应数组号` HUD 投影由 AS2 刷新。
- EasyMode 下已装备技能的历史可排序行为须纳入基线测试；普通模式保持旧 UI 对已装备技能的限制，除非后续另立产品裁决。

## 5. 教师会话与学习事务

### 5.1 opaque `trainerSession`

教师入口不把 `.可学的技能` 数组交给 Web 再传回。`SkillPanelService.openTrainer(currentNpc, source)` 在 AS2 内：

1. 确认 NPC 存在且当前 `.可学的技能` 为合法数组；
2. 过滤不存在于 `_root.技能表对象` 的名称，并记录目录签名；
3. 保存 session-scoped `{nonce, npcRef, scene/target, catalog, catalogSignature, createdAt}`；
4. 只把 opaque `trainerSession` 与 `view=trainer` 放入 `panel_request.initData`。

每次 trainer snapshot/preview/commit 都重新验证：nonce 是当前会话、NPC/场景仍有效、目录签名未变、会话未过期。任一失败返回 `trainer_session_expired`。新教师入口覆盖旧会话；场景切换或超时使它失效。

### 5.2 学习预览

`learnPreview(skillKey, desiredLevel, trainerSession, expectedRevision)` 由 AS2 计算：

- 技能确在当前教师目录；
- `desiredLevel` 是 `1..MaxLevel`，且严格高于当前等级；
- 角色等级满足 `UnlockLevel`；
- 新学技能时 80 行存在空位；升级已有技能不消耗新行；
- 初学成本使用 `UnlockSP`，升级成本按旧语义 `(desiredLevel-currentLevel) * UpgradeSP`；
- 当前技能点足够；
- 技能元数据和已学状态有效。

可提交时返回一次性 `learnToken`。token 绑定 trainer session、skillKey、当前/目标等级、成本、技能点、revision、目录签名和元数据签名；任一状态变化即不可提交。

### 5.3 原子提交

`learnCommit(expectedLearnToken)` 必须：

1. 先消费 token，重复调用一律 `stale_state`；
2. 按当前状态完整重算 preview，不信任 token 内的展示值；
3. 先验证容量、等级、点数和教师上下文，再开始写；
4. 以备份/回滚保护 `_root.技能点数` 和目标技能行；
5. 学习成功后才扣点，任何失败保持点数和技能表均不变；
6. 成功后 dirtyMark、被动/动态技能数据重算、revision 增长，并返回完整 snapshot。

不得继续调用“先扣点再赌 `_root.学习技能` 成功”的旧顺序。可以抽取无 UI 消息副作用的领域函数供新旧入口共用；旧 `_root.学习技能` 兼容桥最终也应委托它。

## 6. 协议闭环（拟议 v1）

统一约定：

- Web 消息：`{type:"panel", panel:"skills", domain:"skills", cmd, callId, ...}`；
- C# → Flash action：下表 `skill*`；
- Flash 回包：`task="skill_response" + numeric callId`；
- C# → Web：重建为 `type="panel_resp", domain="skills", cmd, original web callId`；
- 所有请求含 `v:1`；未知字段由 C# 丢弃，不透传到 AS2。

| Web `cmd` | Flash action | 写？ | 必需 payload | 成功回包核心 |
|---|---|---:|---|---|
| `snapshot` | `skillSnapshot` | 否 | `view`, `trainerSession?` | 完整 `snapshot` |
| `learnPreview` | `skillLearnPreview` | 否 | `skillKey`, `desiredLevel`, `trainerSession`, `expectedRevision` | 预览 + `learnToken?` |
| `learnCommit` | `skillLearnCommit` | 是 | `expectedLearnToken` | 完整 `snapshot` |
| `equip` | `skillEquip` | 是 | `skillKey`, `targetSlot`, `expectedRevision` | 完整 `snapshot` |
| `unequip` | `skillUnequip` | 是 | `targetSlot`, `expectedRevision` | 完整 `snapshot` |
| `setPassive` | `skillSetPassive` | 是 | `skillKey`, `enabled`, `expectedRevision` | 完整 `snapshot` |
| `reorder` | `skillReorder` | 是 | `skillKey`, `targetIndex`, `expectedRevision` | 完整 `snapshot` |

### 6.1 snapshot 形状

示意形状如下；实现时 C# 测试需逐字段验证类型、范围和数组上限：

```js
{
  success: true,
  v: 1,
  revision: 12,
  view: "manage",
  player: { level: 35, skillPoints: 240, easyMode: false },
  learned: [{
    skillKey: "闪现", orderIndex: 2, level: 3, maxLevel: 10,
    type: "武术-内力", passive: false, equippable: true,
    enabled: true, equippedSlots: [4], unlockLevel: 15,
    unlockSP: 20, upgradeSP: 20, mp: 14, cooldownMs: 1700,
    iconKey: "图标-闪现", description: "..."
  }],
  loadout: [{slot: 1, skillKey: null, keyLabel: "空格"}],
  trainer: null,
  diagnostics: []
}
```

`view=trainer` 时 `trainer` 增加 `{session, entries:[skillKey...]}` 或带完整投影的条目；C# 只验证形状与上限，不自行查 XML。`learned` 最多 80，`loadout` 必须恰好 12，教师目录最多 80，防止异常回包撑爆 Web。

### 6.2 错误码与恢复

稳定错误码至少包括：

| 错误 | 含义 | Web 行为 |
|---|---|---|
| `invalid_payload` / `unsupported_cmd` | 协议非法 | 保持快照，显示错误，不重试 |
| `skill_not_found` / `not_learned` | 技能不存在或未学 | 请求 snapshot |
| `stale_state` | revision/token 过期 | 清本地预览，snapshot |
| `trainer_session_expired` | 教师上下文失效 | 关闭教师模式，提示重新对话 |
| `level_locked` / `insufficient_sp` / `max_level` | 业务拒绝 | 保留权威状态，刷新预览 |
| `skill_table_full` | 新学但 80 行已满 | 不扣点，提示整理/停止 |
| `already_equipped` / `not_equippable` | 装备规则拒绝 | 保留快照 |
| `busy` | AS2 单飞保护 | 短提示，不自动重投写 |
| `malformed_response` / timeout / disconnect | 结果未知 | 若为写则进入 `needs_reconcile` |

只有成功的完整 `snapshot` 能把 C#/Web 的 `needs_reconcile` 清回 idle。`learnPreview` 不是对账快照，不能清未知写状态。任何结果未知的 `learnCommit`、equip、unequip、setPassive、reorder 都不得自动重发。

### 6.3 C# 严格边界

`SkillTask` 参照 `CraftingTask` 的 request mux，但使用独立白名单：

- web callId：`[A-Za-z0-9._-]{1,96}`，活动/近期重复均拒绝；
- token/session：只允许受限 ASCII opaque 字符，长度设上限；
- `skillKey`：非空、长度上限、无控制字符；C# 不判断其是否为真实技能；
- `targetSlot` 仅 1..12，`targetIndex` 仅 0..79，`desiredLevel` 仅合理等级范围；
- `view` 仅 `manage|trainer`；manage 不接受 trainerSession，trainer 必须有 session；
- 回包 clone 后删除 `task`，覆盖 `type/domain/cmd/callId`，不得让 Flash 伪造路由字段；
- close 始终先于 domain route；未知 domain 不能落入 legacy 全局 cmd。

## 7. 入口、回退与切换

### 7.1 AS2 安装点

新增 `scripts/逻辑系统分区/技能系统_WebView.as`，只做 `SkillPanelService.install()` 和受控 root bridge；由 `scripts/asLoaderManifest/frame41.as` 纳入，与物品 WebView 入口并列而不放进 `物品系统_WebView.as`。collapsed manifest 按现行构建流程同步生成/核对。

所有新增 `.as` 必须复制现有 BOM 文件后改名，保持 UTF-8 with BOM。

### 7.2 两个生产入口

1. 我的技能：旧物品/技能界面的技能按钮优先调用 `SkillPanelService.openManage("inventory_skill_entry")`；发送失败立即走旧 `gotoAndStop("技能")`。
2. 教师技能：主 FLA NPC 按钮优先调用 `SkillPanelService.openTrainer(_root.gameworld[当前NPC], "world_skill_trainer")`；创建会话或发送失败立即执行旧 `学习技能界面` 路径。

入口改造分别属于：

- `flashswf/UI/物品与技能相关界面/物品与技能相关界面.xfl` 独立 UI 发布目标；
- `CRAZYFLASHER7MercenaryEmpire/CRAZYFLASHER7MercenaryEmpire.xfl` 主 FLA 发布目标。

两者不能以“改了 AS2”代替对应 XFL 发布。入口切换放到最后一个功能 Gate 后，且必须按各自目标单独发布/验证。

### 7.3 回退策略

- S0–S4 期间旧入口保持默认，新面板只通过测试命令/显式开发入口打开。
- S5 切换时只改两个入口脚本；旧 symbol、旧学习结算和 HUD 槽继续保留一个稳定观察期。
- `sendSocketMessage` 返回 false、教师会话创建失败或启动期服务未就绪时立即进入旧 UI。
- 线上出现阻断时回退入口改动即可恢复旧 UI；不回滚存档形状，因为新服务继续写原有 80 行和 12 个 root 槽字段。
- S6 删除旧 UI 前必须有发布版本观察证据；删除后不再宣称可一键回退。
