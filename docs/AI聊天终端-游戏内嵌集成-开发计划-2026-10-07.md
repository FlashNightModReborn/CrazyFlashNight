**目标**：游戏内打开注册面板 `ragchat`，iframe 加载 exe 页面完成聊天；exe 游戏内全程静默；独立模式回归。

### 1.1 步骤 0：嵌入 Spike（半天，先于一切写码决策）

在 GAME 仓做一个一次性验证页（可放 `launcher/web/modules/ragchat/dev/` harness），确认三件事并记录结论：

1. `https://overlay.local` 页面内 `<iframe src="http://127.0.0.1:7077/">` 能否加载（127.0.0.1 在 Chromium 属 potentially trustworthy，预期可过；若被 mixed content/CSP 拦，转备用方案 §1.5-B）。

3. iframe 内中文 IME 输入可用（WebView2 对 iframe 文本框的组合串支持）。
产出：spike 结论写进本阶段提交说明；若 1 或 3 失败，采用 §1.5-B 备用方案继续，不影响后续步骤编号。

### 2.4 契约增量

`ragchat` 闭环表补 bind/unbind 两行（见 §附 A）；`bind` 标 `transaction`（写 exe 内存态，不写游戏存档），`businessDecisionOwner`＝Host（exe 内存态归 Host 生命周期裁决）。

### 2.5 风险预检

- 换存档热切换：若现役流程总是「回标题→读档」，unbind/bind 挂在标题返回与读档完成两点即可；若存在同进程热切换，须补槽位变化事件——施工前在 `SaveManager`/`fs_bootstrap` 确认实际路径并记录。
- 面板常开期间的时效：exe 投影以最近一次推送为准；对话改写等关键判断都在事件触发当刻进行（数据总是当刻推送），展示性字段可能滞后到下一次落盘/事件，属可接受口径（见需求 FR-4 时效口径）。
- `agent_saves` 目录只在 bind 后出现：游戏侧 LoadVars 探测失败须静默跳过（视为无存档任务）。

### 4.2 BACK 步骤

- **B4-1 事件与触发汇聚**：`POST /api/integration/task-completed`：`{slot_key, task_id, npc}` 按 `(slot_key, task_id)` 幂等去重（落 `memory.db` 新表 `dialogue_jobs` 状态机：received→judging→delegated|dismissed→generating→written|skipped|failed）；仅当当前绑定槽位匹配且模式 embedded 时受理，否则记录后 dismissed。聊天链路内的关系/事实信号由 `TurnOrchestrator` 主 Agent 产出同结构内部触发（不走 HTTP）。两类信号统一进「关键性/衍生影响」初判（任务元数据规则 + 轻量评估），不够格记 dismissed；并加频率限制（同 `(slot_key,npc)` 冷却窗、每会话委派上限）控制成本。
- **B4-2 对话完善子 Agent**（新 `services/dialogue/`，后台 asyncio，与 D3 后台子 Agent 同构 fire-and-steer，不阻塞前台聊天）：由主 Agent/事件处理器委派，入参＝{触发原因, 相关事实, 任务定义（如有）, `progress` 投影（事件当刻推送的那份）, `(slot_key,npc)` 长期记忆与好感度（`saves.<slotKey>` 作用域）}。子 Agent 自主执行：
  1. 候选检索：读 `data/dialogues/npc_dialogue_*.xml` 与该 NPC 任务文本键；**跳过规则**＝`progress.tasks_finished` 命中且 chain 非「委托」的任务，其 `get_conversation/finish_conversation` 键不纳入候选；「委托」副本对话不跳过；日常 `TaskRequirement` 门控对话为主要对象。
  2. 修/加/不动判断：**修**＝既有对话与当前状态明显矛盾（态度/关系/关键信息）时最小幅度措辞修正（replace）；**加**＝无矛盾时优先新增日常对话组（append 新 id），仅在合适时给后续/可重复任务对话追加一两句；**不动**＝无必要则记 skipped 结束。
  3. LLM 生成：少量条目（单次 ≤ 3 条），输出结构化 JSON（schema 见 §附 B-5），含 `reason` 与 `source`（task_id 或会话信号标识）；校验（XML 合法字符、长度上限、npc 存在性、跳过规则回检）不合格则 `failed`。
  4. 写盘：`data/dialogues/agent_overrides/<slotKey>.json` 原子写合并（同 base id 后写覆盖先写）；bump `sync_state.json` 的 `dialogue_version`（与任务版本号同一文件锁，防写撞车）。
- **B4-3 种子**：`core/startup.py` ensure `agent_overrides/` 目录（bind 后按需）。
- **B4-4 测试**：幂等去重、dismissed 路径（不够格/非绑定槽位）、频率限制、跳过规则（主线已完跳过/副本不跳过）、修/加/不动三种产出、schema 校验失败路径、写盘+版本号。
