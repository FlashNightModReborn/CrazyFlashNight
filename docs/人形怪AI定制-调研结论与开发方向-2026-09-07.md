## 0. 结论速览

| 需求 | 可行性 | 一句话结论 |
|---|---|---|
| R1 AI 可切换 | ✅ 现成机制 | `UnitAIInitializer` 已支持 `unitAIType` 字段选行为类，关卡 `<Parameters>` 即可注入，**新增一套 AI 只需改 2 个文件** |
| R2 运行时信息 | ⚠️ 够用但粗糙 | 只有**一个锁定目标**；群体信息只有每 16 帧、250px 扫描的 `nearbyCount/encirclement`；Z 轴阈值被**硬编码成 10** |
| R3 指定主动技能 | ⚠️ 可行但要绕 | AI 唯一技能源是 `已学技能表`，但它是**随机生成 + 全局缓存**的；units.json **无技能字段**，只能在初始化后覆写或改缓存键 |
| R4 出场打拳 | ✅ 可解决 | 不是初始化强制动作，是 AI 首 tick 的 chase 决策触发；已有现成"冻结 AI"门 `_warlordActionAiHeld` 可复用 |
| R5 Z 轴抖动 | ✅ 方案① 更优 | 成因已定位（4 帧决策 × 跑速 ≤5 → 单步 20px ≥ 2×zrange）；**改 `Mover.move2D` 加步长截断**是一劳永逸且集中的改法 |
| R6 技能打断 | ✅ 有明确改点 | `ActionExecutor.canInterruptBody` 的 `<=` 是互切根因，叠加 `commitFrames` 远短于真实动画；CD 已是技能级、平A 缺保底概率 |
| R7 战技注册 | ⚠️ 需 3 步改造 | 战技独立存放在 `主动战技` 槽、只由玩家按键触发、AI 完全不碰；需 push 进 `已学技能表` + 执行分支 + 补 CD 门 |

## 1. 现状架构（新 AI，不是旧 AI）

人形怪走的是 `UnitAI/` 这套 **HFSM + Utility AI** 新系统（48 个 .as，约 7500 行），旧帧脚本 AI 已主动让位（`单位函数_fs_佣兵ai.as:291-299`：`if(_parent.unitAI != null){ this.stop(); return; }`）。

```
StaticInitializer.as:53
  → ComponentInitializer.as:21-23
  → UnitAIInitializer.initialize(target)      ← AI 选型唯一入口
  → BaseUnitAI(target, type)                  ← 工厂，按 type 建行为类
      "Enemy"        → EnemyBehavior
      "PickupEnemy"  → EnemyBehavior + setPickupEnabled
      "Hero"         → HeroCombatBehavior     ← 主角模板单位走这里
      "Mecenary"     → MecenaryBehavior
```

- 主角模板单位走 `Hero` 的依据链：`主角-男.xml:146` 帧脚本 `初始化玩家模板()` → `单位函数_fs_aka_玩家模板迁移.as:2118 使用人形怪AI = true` → `UnitAIInitializer.as:13-14`。
- **友军也装 AI**：`UnitAIInitializer.as:5` 只判 `控制目标 / unitAI==null / _parent===gameworld`，**不判 is_hostile**。

## 3. R2 — 运行时可获得的信息

**A. 单体目标信息**（`UnitAIData.as`，`AIContext.build()` 零 MC 直读）
- `target / tx / ty / tz / diff_x / diff_y / diff_z / absdiff_x / absdiff_z`（`:23-37, 201-205`）
- `targetVX`（`:178-195` 速度追踪，用于预测拦截）、`targetHP / targetShooting / targetState`（`:207-210`）
- `xrange / zrange / xdistance`（`:52, 109-112`）——**`zrange` 被强制覆盖为 10**（`:111-112`，同时把 `self.y轴攻击范围` 刷成 10）
- `AIContext.build()`（`AIContext.as:107-205`）额外产出：`underFire / recentHitAge / encirclement / nearbyCount / enemyLeft / enemyRight / enemyBalance / bulletThreat / bndCorner`

**B. 群体信息（弱项）**
- 只有**一个** `data.target`，没有"场上敌人列表"直接可用。
- 群体统计只在 `ThreatAssessor.updateSpatialAwareness`（`:78-110`）：**每 16 帧**更新，`getEnemyCountInRange(self, 16, 150, 150, true)`（扫描 250px、仅 X 轴），产出 `_nearbyCount`、`_encirclement = min(1, left*right/4)`。

**C. 索敌与刷新间隔**
- AI 路径用 `findNearestEnemy(self, 1)` / `findNearestEnemyWithFilter(self, 1, …)` / `findNearestLowHPEnemy(self, 1, 12)`（`HeroCombatModule.as:400-405`），第二个参数 = **缓存刷新间隔 1 帧**（按需惰性刷新：`TargetCacheProvider` `framesSinceUpdate >= updateInterval` 才重建；另有 `forceRefreshThreshold=600`、`RECONCILE_INTERVAL=300`）。
- `findNearestTarget` **只按 X 轴距离排序取最近，无半径/视野/Z 轴限制**（`TargetCacheManager.as:320-337`）= 全图最近。
- 攻击/索敌阈值按单位可配（`单位函数_fs_佣兵ai.as:38-58`）：空手 `x轴攻击范围=90 / y轴攻击范围=20 / x轴保持距离=100`；兵器 150/20/150；长枪·手枪 400/20/200；手雷 300/10/200。索敌距离 = `sqrt(xrange²+yrange²)`（`玩家模板迁移.as:1932`）。
- **AI tick 间隔**：`UnitUpdateWheel.as:15 WHEEL_SIZE=4`（硬编码）→ 每单位**每 4 帧 update 一次**；`Add()` 无 interval 参数，**不可按单位区分**。灵敏度只能通过 `ActionExecutor.commitBody` 的 `commitFrames × tickInterval` 表达（`BaseUnitAI.as:69-71`）。

## 4. R3 — 指定主动技能

**三个容器，用途完全不同**

| 容器 | 结构 | 谁消费 |
|---|---|---|
| `自机.被动技能` | `{技能名, 等级, 启用}` | 只被 `读取被动效果()` 消费，**不是 AI 技能** |
| `自机.已学技能表` | `{技能名, 点数, 冷却, 消耗, 限制, 距离min, 距离max, 类型, 功能, 技能等级, 上次使用时间}`（`玩家模板迁移.as:374-386`） | **AI 唯一的主动技能源** |
| `自机.主动战技` | 按攻击模式分槽（空手/兵器/长枪/手枪/手枪2）（`:1754-1756, 1809-1845`） | 只有玩家按键触发，**AI 不碰** |

**生成方式**：`初始化可用技能()`（`玩家模板迁移.as:295-425`）从硬编码的 `人形怪技能表`（`:213-236`）**随机**抽 `3+等级/5` 个，并按 `名字+等级+技术` **全局缓存**（`:306-310, 424`）→ **无法按单位名静态指定**。

**配技能途径与限制**

| 途径 | 结论 |
|---|---|
| `data/units/units.json` | **无技能字段**（450 条只有 id/spritename/level/name/is_hostile/height/data.武器） |
| `data/merc/mercenaries.json` | 虎妙 id 5652 有 `"passive"`，`MercLibrary.as:141` 注入 `被动技能` —— **只能给被动** |
| 装备生命周期 initParam | 如 `九命猫妖.as:29-34` 写 `自机.被动技能.拳脚攻击` —— **只能给被动** |
| 关卡 `<Parameters>` | 可写任意字段，但 `已学技能表` 在初始化中被 `初始化可用技能()` 覆盖（`:2230`）且被全局缓存短路 → **必须在初始化之后再写，或改缓存键** |

**技能触发链路**（AI 可直接调用，无需按键）：
`AIEnvironment.as:94-96 routeSkill` → `_root.技能路由.技能标签跳转_旧` → `引擎_fs_技能路由.as:28-58`：`unit.技能名=技能名` → `状态改变("技能")` → `man.gotoAndPlay(技能名)`。前置条件只有 `self.技能等级`（`ActionArbiter.as:377`）与 man 上存在同名帧标签；**不消耗 MP/弹药**。

**类型 / 标签体系（已有，硬编码在 AS 里，`data/` 层无）**（`玩家模板迁移.as:213-236`）
- `类型`：格斗 / 刀技 / 火器 / 增益 / 躲避
- `功能`：爆发输出、远程输出、贴身输出、贴身持续输出、位移持续输出、爆发解围输出、持续解围输出、解围霸体、霸体、防护、速度、高频位移、长距位移、换弹…

**AI 正是按这两维选取技能**：`UtilityEvaluator.as:55-64`（按类型加分、按功能修正）、`StanceAffinityMod.as:24`（`skillAffinity[类型]`）、`TacticalBiasMod.as:20`、`SkillHierarchyMod.as:33`、`RigidStateMod.as:16-21`、`ReactiveDodgeMod.as:14`、`AmmoReloadMod.as:15`；优先级裁决 `SkillCandidateStrategy.as:67-71`。

**缺什么（做 R3 需要补）**
1. 没有正交标签（伤害/控制/位移/大招/增益），只有 `类型 × 功能` 两维；
2. 没有"为指定单位指定技能"的通道（缓存键 + 覆写时机需处理）；
3. 缺"技能动画时长/段数"字段——`commitFrames = 8+勇气*8`（`:2492`）只有 8~16 帧，远短于真实动画（这是 R6 打断问题的放大器）。

## 5. R4 — 出场原地打一套拳

**不是初始化强制动作**：出场是 `状态 = 攻击模式+"站立"` + `gotoAndStop`（`玩家模板迁移.as:2173-2174, 2250`）。

**真实链路**（首个 AI tick 即触发）：
```
出场 ~4 帧后首次 tick
 → HeroCombatBehavior:157 Sleeping→Selector → selector_enter 索敌(:218-243)
 → HeroCombatModule.chase（:152-158）
     if ((攻击模式=="空手"||"兵器") && absdiff_x<=xrange && absZDiff<=zrange)
         self.动作A = true;
 → 单位函数_lsy_主角行走状态机.as:187-199 → 引擎_fs_空手攻击路由.as:90 主角普攻连招开始
 → 载入「空手攻击容器-XX1连招」整段播放（连招期 exitMult+=0.5，:71-77 不会切回移动）
```
即：**只要出场时敌人恰好在攻击范围内，就会先打完一套**。敌人不在范围内则不会（这解释了"有时打有时不打"）。

**可解决，两条路**
1. **零代码**：`UpdateEventComponent.as:103-105` 已有 `if (target._warlordActionAiHeld !== true) target.unitAI.update();` —— 现成的"冻结 AI"门，由 `WarlordActionEncounterService` 设置，语义完全吻合"出场 N 帧不攻击"，**用关卡 Parameters 注入该字段即可**。
2. **更细（冻结但保留移动）**：在 `HeroCombatModule.as:153` 的 if 追加出场保护帧判断 `AIEnvironment.getFrame() >= (self._出场保护至帧 || 0)`，保护帧数同样由 Parameters 注入。

（`self.待机` 不够用：`HeroCombatBehavior.as:287` 只挡 follow 移动，`HeroCombatModule` 无 standby 检查，**挡不住攻击**。）

## 6. R5 — 索敌、移动与 Z 轴抖动

**接近逻辑（Hero 路径）**：`HeroCombatModule.chase:99-201` = 直线靠近 + **5px 死区** + 预测拦截（`:171-197`，leadFrames 4~12）+ 统一出口 `MovementResolver.applyBoundaryAwareMovement`（`:200`）。
**交战期迂回**：`EngageMovementStrategy.apply:65-221` 有 Z 轴蛇形脉冲（`dur=8+rng(0,7)` 帧、`gap=12-(enc+urgency)*5`，`:102-112`）、方向交替 `_pickStrafeDir`（`:231-243`）、反包夹 `safeX`（`:126-135`）、贴边回拉 `edgeMargin=80`（`:139`）。**所以"不能直线靠近、要迂回"已有基础设施，只是调参问题。**

**Z 轴抖动成因（已定位）**
- 阈值：`zrange = 10`（`UnitAIData.as:111` 强制）；进入攻击判定 `absdiff_z < zrange && absdiff_x < xrange`（`CombatModule.as:117`、`HeroCombatModule.as:55-60`，退出带 1.2~1.5 迟滞）。
- 每帧 Z 位移 = 速度本身：`Mover.as:134-146` `vy = dir.y * speed` → `entity._y = (entity.Z轴坐标 += vy)`；speed 取 `行走Y速度/跑Y速度`（`玩家模板迁移.as:495-521`），非主控单位 `跑Y = min(行走Y×奔跑倍率, 5)`（`SpeedDeriveInitializer.as:104-129`）。
- AI 每 **4 帧**才决策一次，而 `上行/下行` 在两次决策间保持 → **单个"决策步"Z 位移 = 4 × 跑Y ≈ 20px ≥ 2 × zrange(20)**，必然跨过 ±10 窗口落到对侧，下一 tick 反向 → 永不进入攻击。
- 代码已自证：`BaseUnitAI.as:69-71`「复合 tickInterval 会导致 Z 轴阈值(10-20px)内振荡永远无法进入 Engaging」。

**两方案评估**
- **方案①（推荐）Z 步长截断**：语义正确、一劳永逸。生效点在 **`Mover.move2D`（`Mover.as:134-146`）** 而非 `chase()`（那里只输出 ±1）。最小改法：给 `move2D` 加可选 `clampStep` 参数（或由 `MovementResolver.applyBoundaryAwareMovement:317-335` 输出阶段写入 `|diff_z|` 供其消费），`|vy| = min(|vy|, |剩余Z间距|)`。副作用：会削弱卡死检测（`stuckProbeByCurrentPosition` eps=6，`UnitAIData.as:398`），贴齐帧应置 `isTryingToMove=false`；与 Phase0 脱困 probe(20~60) 不冲突（位移变小只会更安全）。
- **方案② 切走路**：切换点已存在（`HeroCombatModule.chase:163-167`，`absZDiff<=20` 才允许跑）。但走Y 上限 2.5 → 4 帧仍 10px = 窗口半宽，**只能缓解不能根治**；适合作为①的伴随保险。

**贴身判定**：没有独立 `engageDistance`，等价于 Chasing→Engaging Gate（`HeroCombatModule.as:55-60`）。进入后 `engage()` 每 tick `clearInput`（`:214`），移动仅由 `EngageMovementStrategy` 在 `wantsKite/wantsEvade` 时产生（`:96-97`）→ **已具备"贴身后停止迂回"**，并有防呆兜底必定普攻（`:356-363`）。

## 7. R6 — 技能打断 / CD / 平A

**起止与"是否播完"**：`引擎_fs_技能路由.as:40` `状态改变("技能")` 起；止于 man `onUnload` → `RoutingLifecycle.as:70-97` → `UpdateBigSmallState("技能结束")` + `publish("skillEnd")`。判定 = `ActionExecutor.as:119` `self.状态=="技能"||"战技"` → `_animLocked`。

**CD**：**技能级**已实现 —— `SkillCandidateStrategy.as:46` `if(!isNaN(sk.上次使用时间) && (nowMs - sk.上次使用时间 <= sk.冷却*1000)) reject(REASON_CD)`；写入在 `ActionArbiter.as:378`。单位级无 CD（只有 stance/item 轨冷却，`ActionExecutor.as:315-331`）。

**打断根因（两处，互相放大）**
1. `ActionExecutor.canInterruptBody:152-156`：**技能可无条件互相取消**
   ```as
   if ((_bodyType=="skill"||_bodyType=="preBuff") && (candidateType=="skill"||candidateType=="preBuff"))
       return candidatePriority <= _bodyPriority;   // 同优先级 1<=1 → 放行
   ```
2. `commitFrames` 远短于真实动画：`ActionArbiter.as:385-392` 用 `skillCommitFrames × tickInterval`（8~16 × 1~6 帧），帧锁过期后 `ActionArbiter:204-216` 每 tick 重选，新技能靠 `getContinueScore()`（1.5 + CD boost，`ActionExecutor.as:212-230`）竞争；短 CD 技能（冷却 1~5 秒）boost≈0 → 被新技能压过 → **伤害还没出来就换了招**。

**平A**：`BasicAttackStrategy.as:32-35` 恒出候选 `{name:"BasicAttack", type:"attack", priority:3}`；执行 `ActionExecutor.as:344 self.动作A = true`。概率非显式，是 Boltzmann 竞争（`ActionArbiter.as:371-372`）：平A 基线 0.5（`UtilityEvaluator.as:52`）vs 技能基线 `0.3+技能等级/10*0.7` + 类型加成 → **技能普遍压过平A，需要给平A加保底概率**。

**可加门的位置（按推荐度）**
1. `ActionExecutor.canInterruptBody:149` —— 技能期把 `<=` 改成 `<`，或加 `frame < _bodyCommitUntil && 未播完 → false`；
2. `AnimLockFilter.filter:16` —— 仅在帧锁已过期（动画仍在）时才允许 skill 取消，且只放行 priority=0（解围霸体/躲避）；
3. `ActionArbiter._selectBodyAction:342-365` —— 按技能实际动画时长（需新增字段）设 `commitFrames`，让帧锁覆盖整套动作；
4. 平A 保底：在 `UtilityEvaluator` 或 `ActionArbiter` 给 BasicAttack 加"贴身时最低触发概率"。

## 8. R7 — 战技注册为 AI 可用技能

**现状**
- 战技 = 装备 `<skill>` 节点 → `装载主动战技`（`玩家模板迁移.as:1809-1845`，入口 `单位函数_fs_装备生命周期配置.as:82-85`）→ `自机.主动战技[攻击模式] = {名字, 冷却时间, 消耗hp, 消耗mp, 技能等级, 战技函数}`。
- 实现函数表：`单位函数_雾人_aka_fs_主动战技.as:2` `_root.主动战技函数 = {空手:{}, 兵器:{}, 长枪:{}, 手枪:{}, 手枪2:{}}`，每项 `{初始化, 释放许可判定, 释放}`。
- 触发者：**只有玩家按键** → `释放主动战技`（`:1776-1807`）→ `_root.战技路由.战技标签跳转_旧`（`引擎_fs_战技路由.as:34`）。**AI 完全不碰 `主动战技`**（`AIEnvironment` 只有 `routeSkill`）。
- CD：`冷却时间` 字段存在（`:1818`，下限 100ms）且 UI 消费（`UI交互_fs_玩家信息界面.as:159-170`），但 **`释放主动战技` 里没有任何 CD 判定**。消耗为 hp/mp。

**缺什么**：① 战技不在 `已学技能表`，AI 三个策略源（SkillCandidate / PreBuff / Reload）都读 `已学技能表`，无从发现；② 没有 AI 需要的 `类型/功能/距离min/max/冷却(秒)` 字段；③ 走 `状态改变("战技")`，`ActionExecutor.updateAnimLock:119` 已覆盖该状态（这点有利）。

**最小改造路径（3 步）**
1. `装载主动战技` 末尾（`玩家模板迁移.as:1842` 附近）把战技 push 成一条 `已学技能表` 条目（`类型` 按攻击模式映射：空手→格斗、兵器→刀技、长枪→火器；`功能:"战技"`；`冷却: 冷却时间/1000`）。**必须在 `初始化可用技能()`（`:2230`）之后 push**，否则被覆盖。
2. `ActionExecutor.execute`（`:341` 附近）加 `case "battleSkill": self.释放主动战技()`；`AIEnvironment` 加 `routeBattleSkill`。
3. `SkillCandidateStrategy.collect`（`:29`）或 `ActionArbiter._selectBodyAction`（`:375`）对带 `_slot` 的候选改 `type:"battleSkill"`，校验 `self.主动战技[_slot]` 非空 + hp/mp 足够；并给 `释放主动战技`（`:1792` 前）补 CD 门。

**未找到**：`data/units/units.json` 无任何技能字段；不存在 `自机.主动技能` / `自机.技能列表` 容器；战技的类型/标签在数据层无定义；AI 侧对 `消耗/内力` 无任何判定。

## 9. 已知风险与未决问题

1. **Z 轴阈值被硬编码**：`UnitAIData.as:111` 强制 `zrange=10` 并回写 `self.y轴攻击范围=10`，会覆盖 `单位函数_fs_佣兵ai.as` 配的 `y轴攻击范围=20`。做 Z 轴精确对齐时要确认以哪个为准。
2. **AI tick 固定 4 帧**：`WHEEL_SIZE` 是 private static 且 `add()` 无 interval 参数，想让新 AI 反应更快只能靠 `commitFrames × tickInterval` 间接表达，无法单独提速。
3. **技能缓存键**：`名字+等级+技术` 全局缓存（`:306-310, 424`），给虎妙单独配技能若走同名同等级会命中别人的缓存 → 需要新的区分维度或初始化后覆写。
4. **`_warlordActionAiHeld` 语义**：该门本是为 WarlordAction 遭遇服务设计的，复用做"出场保护"前需确认它不会被其他系统提前清除。
5. **未做实机验证**：以上全部是静态代码结论；Z 轴抖动成因、出场打拳链路建议实机录一段确认（焦点诊断/调试日志）。

## 10. 拟定开发方向（供确认，非开发文档）

**推荐方向 A：新增专用 AI 类型 + 复用通用修复**

1. **AI 类型**：新增 `unitAIType = "HeroUnarmed"`（关卡 Parameters / 兵种配置注入），`BaseUnitAI.as` 加 case，新建 `UnitAI/behavior/HeroUnarmedBehavior.as`（**复用 HeroCombatBehavior 的 HFSM 骨架 + 新的 CombatModule**），只服务空手主角模板单位；其余单位走原路径，零回归。
2. **通用修复下沉（对所有单位受益）**：Z 轴步长截断做在 `Mover.move2D`（加可选 clampStep），由 `MovementResolver` 计算并传入——方案①一劳永逸，方案②（贴身切走路）作为保险保留在 chase 里。
3. **出场保护**：新 AI 内置"出场 N 帧内不输出攻击"（N 由 Parameters 注入），而不是复用 `_warlordActionAiHeld`（避免与该系统的语义耦合）。
4. **技能使用门**：在 `canInterruptBody` / `AnimLockFilter` 层加"技能未播完不可被同优先级取消"，并给平A 加贴身保底概率；技能 CD 沿用现成的技能级 CD。
5. **指定技能（R3）与战技（R7）**：定义为**可拆的第二期**——先做"初始化后按单位参数覆写 `已学技能表`"（加缓存键维度），再做"战技 push 进 `已学技能表` + 执行分支 + CD 门"。是否新增正交标签（伤害/控制/位移/大招）需要你拍板：**沿用现有 `类型×功能` 两维**改动最小，但类型选取的粒度受限于现有 14 种 `功能` 值。

**备选方向 B**：不新增 AI 类型，在现有 `HeroCombatModule` 内按"空手 + 单位标记"加分支。改动更集中，但侵入默认路径、回归风险高，且不利于以后做第二套专用 AI。

**备选方向 C**：只做通用修补（Z 轴 clamp + 出场保护 + 打断门），不动 AI 架构。改动最小、默认 AI 一并受益，但无法给虎妙做专用表现（如特定迂回风格、特定技能偏好）。

**建议**：A 为主（1~4 项），Z 轴 clamp 与打断门按 C 的思路下沉到通用层；R3/R7 视优先级拆为后续。
