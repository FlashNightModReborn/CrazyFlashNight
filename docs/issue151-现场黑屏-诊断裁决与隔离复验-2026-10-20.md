## 4. 静态调查已限定的解释

- 主 XFL 根时间线总长 211 帧；`性能帧率显示器` 跨根帧 1–211 连续存在。不能把 210→211 写成该驱动自动卸载，也不能虚构已定义的 212+ 帧。战斗控制在 210→211 的卸载、跳图与 lease 分支仍有隔离验证价值。
- 原生 Ctrl+Enter / command 20039 是静态覆盖缺口，但没有现场按键或 WM_COMMAND 证据。即使复验可触发，也要核对能否解释全链路沉默，而非只解释黑色画面。
- EventBus 热路径缺少 finally 可留下本次分发状态，但未发现“depth 非零就全局拒绝后续 publish”规则；不能把一次异常直接写成永久停摆。
- `ServerManager.hasSentThisFrame` 属 HTTP `/logBatch` 节流，不是 XMLSocket 业务发送总闸。
- native `consumedSeq` 在拒绝检查和 Original 调用前更新，不证明 AS2 消费；`completedSeq` 的终态一致也不证明全过程未阻塞。
- Host 接收线程同步 dispatch 可能阻塞后续读取，但永久不可释放的锁与最终关闭路径并不一致；暂时卡顿、嵌套泵或特定消费者等待仍未排除。

固定源码入口：[主时间线](https://github.com/FlashNightModReborn/CrazyFlashNight/blob/1191cd50535300c00e6093528d465e4230be505e/CRAZYFLASHER7MercenaryEmpire/DOMDocument.xml)、[SceneTransitionService](https://github.com/FlashNightModReborn/CrazyFlashNight/blob/1191cd50535300c00e6093528d465e4230be505e/scripts/类定义/org/flashNight/arki/ui/SceneTransitionService.as)。

## 5. 第二轮报告带来的待复核约束

- 报告识别 `SceneTransitionFrameClip.onEnterFrame → SceneTransitionService.tick → _retired hide` 为独立于 EventBus/gameworld 的驱动，tr:106 rev5 hide 出现 18 次后消失。它仍共用发送/接收链，故可削弱“只有 frameEnd 失效”，不能直接证明整台 VM 停止。
- 报告指出 `SceneEntryReady` 在 23:41:44.910 有 rootFrame=210。该点距最后 JSON 约 19 秒，不是故障瞬间快照。
- 报告统计最后 JSON 后仍有 34 条 `world_compositor_frame`；结合 WinForms Timer 与锁位置，可反对 Host UI 从始至终完全死锁的强版本，但不能用采样间隔反推出锁等待上界。
- 报告认为 settings opened 前某条 webPanelPause 本地 Write/Flush 已返回；即使源码路径吻合，也不证明 settingsSnapshot 发出或 Flash 接收。
- 报告强调 settings authority v2 不应套用旧日志缺失判据，且 reward-pending 可提前拒绝。需要同 callId 的允许/拒绝/发送结果。
- 报告提示 native 诊断须确认子进程实际 `CF7_FOCUS_TRACE=1`，并取得 Ready 与对应阶段事件；仅开启配置不足以证明探针有效。

这些是有判别力的诊断约束，不是修复。第二轮证据 ZIP 取得后再复算新增机器结果、核验源码快照；未复核项保持原等级。文字报告已取得，不等于报告中的每项检查已由本轮重跑。

## 6. 三条候选路径与判别实验

| 路径 | 最小要回答的问题 | 支持条件 | 不足或反证 |
|---|---|---|---|
| A 根播放/战斗控制卸载/lease | command 20039 是否真实到达，并引出根帧/实例/lease 变化？ | 同次命令、根帧、控制实例、lease 事件及症状串联 | 只黑屏而独立心跳持续，不能解释现场全沉默；没有命令证据不归因 |
| B AS2 多入口丢失或共用发送失败 | 三个驱动入口还在执行吗？序列化/send 前后在哪断开？ | 独立入口、begin/end 与 socket 状态绑定同一运行身份 | 所有观测都共用 XMLSocket 时，接收侧沉默不能区分执行与发送 |
| C Host 读取/分帧/消费者暂时阻塞 | socket 字节已到、完整帧已到，还是 dispatch 未返回？ | read/framing/dispatch begin/end、线程 ID、长度与 callId，配合同次线程栈 | 最后打印消息不能独自定位阻塞消费者；能退出不排除暂时阻塞 |

三条可相互组合，并非互斥根因清单。

## 7. 最小隔离复验工单

1. **身份前置**：记录实际 Launcher/Core/native、Flash EXE、主 SWF、asLoader、配置及 source identity；区分原现场包与重建候选。只用获授权隔离/克隆档，不试写真实玩家槽，不回滚覆盖玩家新差异。
2. **观测自检**：先在正常运行证实三条驱动、发送前后与 Host 读取/分帧/分发均有可对齐事件。每条记录 session、单调序号、线程/入口、begin/end、结果/拒绝原因；限额采样。至少一条关键 Flash 存活观测不只依赖原 XMLSocket 接收链。正常战斗先保留 10 秒基线，确认 native stage9 Ready 与同 session/seq 的 stage1/2；检查 TRACE_GAP，丢记录保持未知。Host 独立采样不得获取被测业务锁。观测期间不得自动重启、重连、重试、吞异常或强清租约。
3. **先自然捕获，再短指纹**：R0 优先补取事故包身份及已有 perf/focus 诊断；R1 在隔离环境自然复现，记录所有输入。R2 每条件独立进程，分别测普通 Enter、`_root.play()`、真实 Ctrl+Enter、command 20039，不把程序化播放等同原生命令。R3 仅在执行范围仍不明时，用同 Adobe 播放器的独立无业务 SWF，在探针已安装且稳定后分别测试一次 throw、重复 throw、受控递归限额；不是在玩家档注入压力，不以 Ruffle/JS 模型代验。
4. **故障仍在时取证**：尽量先保留证据再退出；取得同次 Flash 与 Host 线程栈，根帧/关键剪辑实例、lease、socket 状态与三层画面（GDI HWND、WGC 帧、最终合成）。采集工具与运行权限另按既有规则确认。
5. **settings 闭环**：同一 callId 跟踪 Web 接受、authority 拒绝或允许、Host send begin/end、Flash onData/handler begin/end、response 与消费结果。缺环即停在该边界，不补猜。
6. **无复现收口**：记录运行身份、试验次数、条件与未测项，保留 issue；不以本机未复现否定现场，也不无限增加同源心跳。
