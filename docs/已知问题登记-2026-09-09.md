## 问题 1：焦点在 SWF 内按 Alt，游戏画面卡死

**状态**：预防性修复已部署（`promoted / FIELD_REVALIDATION_PENDING`），正式入口效果待复验。功能契约见[焦点诊断 §9.14](焦点管理-诊断与卡顿排查-2026-05-24.md#914-2026-09-10裸-alt-菜单防护与嵌入菜单清理)，发布身份和部署状态见 [runtime 发布记录](runtime-build-reproducibility.md)。

### 现象

- EXE 启动进游戏，**只有焦点在 SWF 内时**按 Alt 才会卡死；焦点在 Web 面板或其它窗口时按 Alt 无此现象
- 卡死后再按任意键，SWF 立刻恢复
- 卡死期间：Web（WebView2）动画仍正常播放，但鼠标 hover 等交互不触发；SWF 完全冻结
- 按字母键时曾听到系统提示音。单凭提示音不能确认菜单归属，也不能证明它与卡顿互相独立。

### 定位边界：疑似菜单模式，不能只归因于 Flash 的系统菜单位

Flash 是独立进程（`Adobe Flash Player 20.exe`），被 `SetParent` 成子窗口嵌入 Guardian，且 `WindowManager` 会主动把键盘焦点交给它。旧代码两处样式掩码均保留 `WS_SYSMENU`，但这只能证明存在未清理的菜单入口，不能证明原事故的循环必定发生在 Flash 线程。

```
裸 Alt / F10 松开
  → 默认键盘消息处理可向顶层窗口发送 WM_SYSCOMMAND / SC_KEYMENU
  → 顶层 Guardian 原本也会继续交给默认处理
  → 可能进入菜单模式；实际 menuOwner / capture 与停顿线程须从现场确认
```

Windows 的 [WM_SYSKEYUP 契约](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-syskeyup)明确包含向顶层窗口发送 `SC_KEYMENU`。WebView2 有独立 renderer / GPU 进程，因此“Web 动画继续”不能排除 Guardian 消息处理受阻，也不能单独证明 Flash 抢走了 capture。现有 `FocusWindowSnapshot` 的 `guiFlags`、`menuOwner`、`capture` 和窗口 style 可用于复现期间区分这些路径。

### 旧代码定位（原登记提交 `2bed466fd6b4ce887b6e01aa0a7512f1b59e8b6a`）

| 位置 | 说明 |
| --- | --- |
| `launcher/src/Guardian/WindowManager.cs:428-431`（启动早期 hidden 路径） | 只做 `style & ~WS_CAPTION & ~WS_THICKFRAME & ~WS_BORDER \| WS_CHILD`，**从未清 `WS_SYSMENU`** |
| 同上 `:664-667`（full / 重嵌入路径） | 同上，同样未清 |
| 同上 `:434-441`、`:669-676` | 在设置 `WS_CHILD` 后才尝试 `GetMenu`；子窗口返回值未定义，不能据此认定普通菜单已成功拆除 |
| 同上 `:869`、`:941`、`:1005` | `SetFocus(flashHwnd)` 主动把焦点给 Flash 子窗口 —— 决定"只有 SWF 有焦点才会触发" |
| 全仓 grep | 无 `WS_SYSMENU` / `SC_KEYMENU` / `WM_SYSCOMMAND` / `VK_MENU` 任何处理 |

补充：`logs/launcher.log` 显示实际走的是 `path=reveal`（`needFullEmbed=false`），即 style 改写只发生在启动早期的 hidden 阶段；看门狗重嵌入才走 full 路径。两条路径都要改。

### 已实施修复（2026-09-10）

- `GuardianForm.WndProc` 只拦 `WM_SYSCOMMAND` 中掩掉低四位后为 `SC_KEYMENU` 且 `lParam=0` 的裸键菜单激活；原始键盘消息、有字符的菜单请求和 `SC_CLOSE` 继续原处理路径。
- `WindowManager.ApplyFlashChildStyle` 同时服务 hidden / full 两处嵌入，清除标题栏、边框和 `WS_SYSMENU`，仍使用原有 `SWP_FRAMECHANGED`。
- 普通菜单在原窗口尚非 child 时先摘除；`SetMenu` 失败时不销毁仍被窗口持有的菜单；已是 child 的重新嵌入跳过 `GetMenu`，避免把子窗口 ID 当菜单句柄。
- 不更改低级键盘钩子。代码保留 Alt+Space、Alt+字母和 Alt+F4 的宿主命令路径，但实际组合键行为仍须在嵌入的 Flash 上复验，不能由消息过滤单测代签。

### 回归清单

1. 焦点在 SWF 内按裸 Alt / F10、随后按字母，画面与输入持续正常；若再停顿，核对菜单归属诊断。
2. `Alt+Tab` 切出 / 切回、`Alt+Space` 的宿主系统菜单及 `Alt+F4` 退出行为保持可用。
3. 全屏 / 窗口往返及窗口重新嵌入后重复以上输入检查。

### 备注

原登记环境只有 SDK 7.0.403，属于历史记录。2026-09-10 本次施工机器已通过锁定环境门：SDK `10.0.300`、MSVC `19.44.35228.0`、Rust `1.96.0`、Windows SDK `10.0.22621.0`。自动回归覆盖消息过滤边界、菜单拆除失败和真实隐藏 Win32 窗口的初次 / 重复嵌入；它不等同原 Flash 事故真机复现。
