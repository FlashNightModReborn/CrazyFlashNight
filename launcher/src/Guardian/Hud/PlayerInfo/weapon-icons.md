# 装备战技图标

战技槽使用“专用图标 → 物品图标简化描边 → 原有交叉武器图”的回退顺序，保持原来的 26×26 逻辑槽位、标题、按键、冷却遮罩及释放行为。

装备战技数据可声明 `iconKey`，也兼容 `icon`。`装载主动战技` 将该引用与实际授予装备一起保留；常规生命周期加载传入装备名称，动态武器加载沿用自身攻击槽，`兵器` 对应 `刀`。套装或插件授予战技时采用授予装备，不根据当前手持武器猜测。

Host 通过现有 `playerHudSync.weaponVisuals=true` 请求视觉字段。未请求的旧客户端仍收到原来的字段集合；断线后能力退休。`combat.weapon` 的可选 `iconKey`、`itemIconKey`、`sourceItem` 分别为专用图标、装备图标和授予装备名。来源变化参与快照比较，同名战技换装仍会刷新；撤下战技清空引用，旧快照保持不可变。

图像由现有受限 manifest 解析，仅采用物品图标 `f1` 的方形特写构图；`f2` 是世界展示/掉落用的完整贴图，不作为战技图标回退。保留原画布中的朝向、位置与特写比例，不额外旋转或按物体包围盒重新居中。默认描边在实际显示尺寸生成，保留外形、孔洞与少量高反差材质边界，内部保留淡填色。透明画布以不透明的物品笔画及其窄抗锯齿邻域为依据，排除即使透明度超过 90% 的椭圆底影；不按颜色变暗就删除黑色结构。

只有四边一致的薄品质框才会被裁除；不透明背景还要求框内两侧窄条的逐行颜色一致，并仅移除从边界连通的背景。无法可靠分离的全不透明画面、缺失或损坏的物品图标使用原有交叉武器图，不从贴图补出另一种构图。图标缓存按源图标和物理尺寸区分，合计受 16 MiB 与条目数上限约束；绘制复用缓存，不逐帧检测边缘。

验证入口：`scripts/run-player-hud-tests.ps1`、`PlayerHudWeaponIconTests`、`EquipmentBattleIconReplacesOnlyInnerSymbolAndKeepsCooldownFeedback`。AS2 行为和持有生命周期仍由 Flash 裁决；缓存图像、合成预览及单测不代签实战人工验收。
