## 0. 一句话裁决

2026-08-01 集中出现的越级装备、电脑芯片有效等级失真、Equipment Tuning 长停“等待权威预览”、插件空图标、已装备格不可检视，以及角色构筑缺少直觉化直接装备等反馈，不能再按互不相关的 UI 小缺陷处理。

这些反馈共同指向四类跨层问题：

1. **基础目录数据与物品实例有效数据没有稳定边界**；
2. **内部规则键、玩家显示名、图标键没有统一的显式身份合同**；
3. **不同工作台对同类 Flash 回包、写入未知结果和迟到异步的证明强度不一致**；
4. **可检视、可选择、可执行、可拖拽等能力仍由各领域零散绑定，导致视觉统一但行为割裂**。

因此本 ADR 决定先冻结一份全消费者审计基线，再按 A1→A6 修复。A0 已完成并获接受；后续各批仍不接受“顺手补一个 fallback”“仅给该装备加特判”“把规则复制到 Web”“为了复用再造通用工作台框架”等越界施工。

## 2. 审计证据等级与优先级

### 2.1 证据等级

| 标记 | 含义 | 允许的表述 |
|---|---|---|
| `C` Confirmed | 代码路径可以直接证明，或已有精确自动测试/可重复静态事实 | “已确认缺陷/缺口” |
| `O` Observed | 玩家提供了视频或稳定操作反馈，但本基线尚未完成 fresh 游戏复现与日志归因 | “已观察，根因待 fresh 复验” |
| `R` Risk | 静态结构显示保护弱于同类强域，尚不能声称玩家已经触发 | “高风险候选” |
| `D` Decision | 需要产品或架构裁决，当前并非 bug | “待决项” |
| `I` Intentional | 已有明确理由且被测试保护的领域差异 | “有意例外” |

不得把 `O/R/D` 写成已复现故障，也不得用 `C` 的单个样本掩盖同类根因。

### 2.2 优先级

| 级别 | 含义 |
|---|---|
| `P0` | 可能错误允许/拒绝权威写入、留下未知写状态或造成不可恢复阻塞；必须先于体验增强 |
| `P1` | 玩家可见能力割裂、错误解释/恢复缺失、协议保护明显弱于同类强域 |
| `P2` | 可维护性、公共面过宽、重复组合或非阻塞体验债务 |

优先级不是“已确认严重度”的替代品。`R/P0` 表示应优先证明或排除，不表示已经发生数据破坏。

## 3. 全量审计对象与方法

```text
Host owner × exact panel instance × production surface × authority/wire domain
× shell profile × hosting context × query/write capability
```

`WorkbenchViewStack` 的 hosting context 不能再压缩成“standalone/Build-origin”两个布尔值。下表只描述 **Esc/显式 Back 的 ancestor unwind**；普通 header `×` 是 exact-owner Close，不使用此栈。当前可达返回 fence 明细为：

| launch root / 当前栈 | 当前 surface | 一次 Esc/Back 的下一站 | root 终态 |
|---|---|---|---|
| `storage` | direct-launch Storage（battlebox/warehouse root） | 无 parent | 关闭到游戏；warehouse 不据此获得 Tuning sibling |
| `storage(battlebox) → tuning` | Storage-origin pushed Tuning | `storage` | 再次在 root 关闭到游戏 |
| `tuning` | HUD direct-launch Tuning | 无 parent | 关闭到游戏 |
| `tuning → storage(battlebox)` | Tuning-origin pushed Storage | `tuning` | 再次在 root 关闭到游戏 |
| `build` | Character Build | 无 workbench-view parent | 先按 Build 内部 Esc 顺序消费，最终才关闭到游戏 |
| `build → storage` | Build-origin Storage | `build` | 保留 exact Character session |
| `build → storage → tuning` | Build/Storage-origin Tuning | `storage` | 再回 `build` |
| `build → tuning` | Build-origin Tuning | `build` | 保留 exact Character session |
| `build → tuning → storage` | Build/Tuning-origin Storage | `tuning` | 再回 `build` |

上表列的是栈状态而不是新增 Host owner、Shell 或 authority domain。切向已有 ancestor 时是 back/unwind，切向非 ancestor 时才 push；任何行都必须保持同一 `panelInstanceId`、navigation generation、pause owner 与迟到 callback fence。

| owner / 当前 surface | 输入或 reason | 当前消费顺序 | 一次成功消费后的下一状态 |
|---|---|---|---|
| `workbench` / 任意 view | Esc | PreparationMenu → navigation pending 拒绝 → Shell modal → 当前 view 内部消费 → `returnPlan()` → Storage `prepareClose` / Build finalize | 每次只消费最高层；存在 stack parent 时回 parent，root 才关闭 owner |

1. 枚举 `DualPaneShell` 与 `SecondaryPage` 的全部生产直接构造；
2. 枚举主 controller 的 view/profile、embedded writer 与 owner-specific 子路由；
3. 枚举 `ROUTES`、`initData` capability、`navigationOrigin`、close reason 与返回优先级，按语境拆行；
4. 对每个会发送 mutation 的共享 primitive 做反向引用，列出全部直接及组合式消费者；
5. 将每行映射到 §10 行为基线、§12 canonical Gate/coverage drift 和 §13 行动票。任一行缺少后三者之一，A0 surface inventory 都不闭合。

### 3.2 每个命令必须追踪的闭环

```text
Web intent
  → Web exact payload / 当前 owner
  → Host admission 与白名单重建
  → Flash 请求发送结果
  → AS2 authority / 实例资格 / OCC 校验
  → mutation 或只读 projection
  → AS2 postcondition / error code
  → Host 对 pending request 的 exact response 证明与净化
  → Web 采用、确定性失败恢复或 unknown-result reconcile
  → rebind / close / reload 后的迟到回包隔离
```

任何只检查顶层 `success`、数组存在或若干数字，却不证明元素、身份、原请求和后置条件的路径，均不能计为闭环完成。

### 3.3 横向审计轴

每个生产表面必须回答：

- **所有权与表面身份**：`hostOwner / panelInstanceId / surfaceId / ownerContext / wireDomain / shellProfile / hostingContext` 是否明确，主表面、二级页、view/profile 变体与 standalone/embedded 是否被错误合并或重复计数；
- **身份**：内部规则键、显示名、图标键是否独立；哪个字段可用于 mutation、Map key 与 catalog lookup；
- **数据来源**：使用基础 catalog、物品实例有效数据还是只读展示 projection；是否覆盖 tier、涂层/变体、mod、电脑芯片等实例变化；
- **可检视性**：占用、blocked、pending 的真实实体能否由 pointer 与 keyboard focus 获取注释；
- **可操作性**：点击、Enter/Space、按钮与 pointer drag 是否进入同一领域 intent；
- **新鲜度**：是否携 exact panel/session/generation/revision/lease/container version；
- **回包证明**：Host 是否把响应绑定原 pending request，并递归验证后重建安全对象；
- **失败恢复**：确定性 stale 是否自动取得新鲜读；unknown write 是否只对账、不重放；
- **生命周期**：切槽、切 view、rebind、close、WebView reload 后迟到 callback 是否可复活旧 owner；
- **玩家解释**：所有 blocked/error code 是否映射为上下文正确、可执行的中文下一步；
- **验证**：是否有三名分离、实例变体、畸形回包、丢包/超时和真实输入旅程。

## 4. 本轮治理不变量（Accepted target contract）

以下是不依赖具体 UI 方案、已由维护者接受的目标不变量。它们只授权后续实现与验收，不会在对应批次通过前自动变成现役实现事实：

### G1. 规则身份、展示身份与图标身份分离

- 内部规则键只用于 catalog、规则、token 与 mutation descriptor；
- 玩家显示名只用于 copy、ARIA 与搜索展示；
- 图标键只用于图标解析；
- 三者允许全部不同，任一层不得以 `displayName || name` 的 fallback 掩盖 mutation 身份缺失；
- legacy wire 可以暂时由 explicit adapter 翻译，但不能让消费者自行猜别名。

### G2. 已持有装备的资格必须基于实例有效数据

- 基础 catalog 只用于静态定义；
- 已持有 BaseItem 的装备资格、当前用途、有效等级、展示与 tooltip 必须对同一实例得到一致的有效事实；本 ADR 不预先规定必须新增单一 resolver；
- 资格判断不得把实例 `value.level`（强化度）误当角色等级门，也不得忽略 tier/变体/芯片对有效定义的影响；
- Web projection 只能解释或预阻断，AS2 mutation 前必须重新以权威实例校验。

### G3. Host 不得把未证明的 Flash 业务对象直接交给 Web

- route 保留键保护不等价于业务 schema 证明；
- 通用 item leaf 可以共享 validator/sanitizer；领域 envelope、token 与 postcondition 必须由领域 Host 保留；
- 响应必须绑定当前 pending request 的 selector 与 instance；写响应再按领域绑定适用的 write epoch/watermark；
- malformed/near-match response 不得作为权威成功或确定性业务失败被采用；transport pending 必须确定性收口，可能已经执行的写转入 unknown/`needs_reconcile`，不能悬挂等待或产生乐观状态。

### G4. 每个写域必须有明确的未知结果策略

- 命令必须声明 read/write 分类；
- send false、timeout、断线、malformed、response lost 与 WebView 生命周期变化都进入定义好的状态；
- unknown write 只允许重新读取权威状态并对账，禁止自动重放；
- Host 是否必须跨页面生命周期持有写水位线，由每个域审计后裁决，不能默认交给仍存活的 Web 页面。

### G5. 可检视性与可执行性分离

- 对真实占用实体，业务阻断通常只关闭 action，不应同时关闭 pointer/focus inspection；
- blocked item 仍应允许玩家知道“这是什么、为何不可用”；
- 空槽是否提供槽位说明由领域裁决，但不得伪装成真实物品 tooltip；
- tooltip scope 必须跟随 view owner 销毁，迟到内容不得复活 detached node。

### G6. 多种输入只形成同一个领域 intent

- 不建立“所有 EntityTile 的 click/Enter/Space 都只选择/preview”的全局默认；每个 surface 必须按领域、状态与 modifier 明确映射 activation intent；
- Character 候选的现役合同是：第一次 click/Enter/Space 选择并固定预览；同一候选再次 click 或 Space 清除；同一已选候选上的一次明确、非 repeat Enter 等价唯一主 CTA；
- KShop catalog 的 click/Enter/Space 可加购，Inventory 的 `Ctrl+click` 可立即 transfer，Loot 的 Enter 可直接 claim；这些既有领域写语义不得被通用 primitive 抹平；
- 同一 surface 内表达同一业务动作的按钮、键盘路径与成功 drop 必须汇入同一个权威 intent，不能各自拼装 payload 或状态机；
- drop 只形成 intent，不直接改 DOM/本地物品状态；
- 按钮和键盘路径必须保留，drag 不是唯一入口；
- 本轮只复用现役 `InteractionBroker + PointerDragController`，不启用 HTML5 `draggable/drop`。

### G7. 测试必须证明语义，不以高计数替代

- atlas、DOM、CSS 与 synthetic harness 仍必要，但不能证明实例资格与未知写闭环；
- 每个跨层规则必须至少有一个真实反例 fixture 和一个故障注入；
- 普通物品样本不能替代多阶、涂层、电脑芯片和三名分离样本。

### D-01：Character Build 全量背包、拖拽与对比

**状态**：Decision；不是当前 bug 修复。

当前右栏只投影目标槽的筛选候选；AS2 在生成候选时已经按目标 `use` 过滤，Web 实际只收到 filtered `candidates`。AS2 内部虽能构建背包 snapshot，但正常 Character snapshot/Host contract 不提供可直接切换的全量 inventory projection。因此：

## 7. 高风险但尚未证明为玩家故障的候选

### R-01 / P0：Inventory 普通回包缺少递归 Host 证明

## 9. 组件与抽离审计

### 9.1 优先 evidence-gated 候选

以下是静态审计后值得做 spike 的候选，不是 A0 对后续抽象的预授权。每项仍须证明至少两个消费者因同一原因变化、独立契约可测试且净减少改动扩散；否则保留领域实现。

#### A. AS2 实例有效事实一致性 spike

目的：证明并收敛已持有实例的资格、展示与 tooltip 是否取得一致的 effective facts。

若证据表明确需共享代码，最小边界才是：

- 输入真实 BaseItem；
- 输出或返回现役 `item.getData()` 等价的有效定义；
- 基础 catalog 读取仍保留独立显式入口；
- 不持有 UI、session、lease 或领域 mutation。

也可能只需复用并明确 `BaseItem.getData()` 语义、修正错误调用点与增加一致性测试；本 ADR 不冻结新增函数或 API 名。

#### B. item-like leaf schema 与 sanitizer

目的：复用 `ruleKey / displayName / iconKey` 语义和 Inventory 的 item projection 叶节点证明。

最小边界：

### 10.1 Character Build 双模式待决合同

若后续接受 `筛选候选 / 背包全量`，协议/状态枚举使用 `candidateScope:"compatible"|"backpack"` 一类名称，不复用现役视觉密度 `full/compact`：

- 默认仍建议筛选候选，降低误操作与信息噪声；是否持久化偏好另行裁决；
- 当前 AS2 已按目标 `use` 过滤且 Web 只收到 `candidates`，所以 `backpack` 必须先增加 AS2/Host 的全量只读投影；禁止只在 Web 增加一个切换按钮伪装成全量模式；
- 切换必须定义选择槽、焦点、scroll、density、候选预览与 pending 的保持/清理；
- 全量模式应展示不兼容或暂时 blocked 的物品及原因，而不是静默丢弃；
- `compatible` 模式的候选已绑定当前 target，drop 到其他装备格必须拒绝或先按新 target 重新读取候选，不能沿用旧 target 写入；
- `backpack` 模式以实际命中的装备格作为 target；未命中或手枪 1/2 等歧义目标不得猜测；
- 候选格沿用现役首次/二次分叉：第一次 click/Enter/Space 选择并固定 preview，同一 click 或 Space 清除；同一已选候选上的明确非 repeat Enter、主“装备”CTA、CTA 的原生键盘激活与成功 drop 才发送同一个 exact source/target/revision/lease mutation；
- pointer drag 需要阈值、click suppression、目标高亮、空白取消、pointer cancel、lost capture/窗口失焦取消、busy/reconcile 和 tooltip owner 冲突测试；现役 controller 尚无独立 `lostpointercapture`/窗口失焦收口，必须先补并验证该基础机械；
- 满背包卸下必须在提交前给出可理解阻断，但容量权威仍由 AS2 mutation 前复验。

## 11. 协议与数据验证基线

### 11.1 item-like canonical 语义（字段名待裁决）

不先冻结全仓字段拼写，但冻结语义：

| 语义 | 允许用途 | 禁止用途 |
|---|---|---|
| rule key / internal name | catalog lookup、规则、token、mutation、稳定 map key | 玩家显示名、默认图标键 |
| display name | copy、ARIA、展示搜索 | mutation、catalog lookup、稳定 identity |
| icon key | `Icons.*`/Flash linkage 解析 | mutation、规则判断、显示名替代 |

Legacy adapter 必须在单一边界显式翻译，消费者不能写 `icon || name || displayName` 之类的任意猜测链。

### 11.2 owned source 最小 freshness proof

普通 inventory source 至少包含：

```text
containerId + physicalSlot/key + expectedLease
```

跨容器或强域按实际 authority 增加：

```text
expectedRevision / expectedContainerVersion / sessionGeneration / panelInstanceId
```

字段越多不等于越安全；每一字段必须在 AS2 mutation 前被消费，并在 Host/Web 测试中证明 stale/near-match 失败。

### 11.3 preview/commit 最小证明

- preview response 必须匹配原请求 selector；
- token 绑定 preview 的 exact authority 输入；
- 任意新 preview 尝试，包括畸形/失败尝试，如何处理旧 token 必须明确；
- commit token 单次消费；
- success 必须证明预期后置条件，而不是只看 `success:true`；
- timeout/response lost 进入 reconcile，禁止自动 commit 重放。

## 12. 验证基线与未来 Gate

### 12.1 数据 fixture

每个写域按适用性覆盖：

- Web payload near-match/extra key/wrong type；
- Host→Flash send false/throw；
- Flash definitive failure；
- Flash 已写但 response lost；
- malformed/foreign/duplicate/late response；
- timeout；
- panel rebind/close；
- WebView reload；
- socket detach/reconnect；
- reconcile read 再失败；
- 玩家在 pending/reconcile 中重复点击、切槽、Esc 或关闭。

- occupied/empty/blocked/pending × pointer/focus；
