# 消耗品药效与数值治理

本文档描述药剂、食品的运行时 XML 契约。公式、当前家常菜配额和九龙系列完整数值以 [`tools/cf7-balance-tool/docs/potion-balance-rulebook.md`](../../tools/cf7-balance-tool/docs/potion-balance-rulebook.md) 为准；不要再使用历史版 `α=5`、统一 `HoT×0.7` 或价格档位表反推数值。

## 1. 物品与执行入口

- 通用药剂：`消耗品_药剂.xml`
- 食品、菜品：`消耗品_药剂_食品.xml`
- 九龙战斗强化剂：`消耗品_药剂_九龙.xml`
- 子文件登记：`list.xml`
- 效果注册：`DrugEffectRegistry.as`
- Tooltip 注册：`DrugTooltipRegistry.as`

物品使用时按 `<effects>` 中的物理顺序执行 `<effect>`。声明 `buffDomain` 的物品必须把它放在所有持续效果之前，使旧域 Buff 先被移除、新 ID 再被登记。单个即时效果失败不应被误解为事务回滚。

```xml
<effects>
  <effect type="buffDomain" domain="enhancer"/>
  <effect type="buff" property="伤害加成" calc="add_positive"
          value="360" duration="300" buffId="九龙_睚眦_伤害"/>
</effects>
```

## 2. 效果类型

| `type` | 关键字段 | 运行时语义 |
|---|---|---|
| `heal` | `hp/mp/target/scaleWithAlchemy` | 即时恢复；数值可为定值或百分比字符串 |
| `regen` | `hp/mp/duration/interval/mode/id/stack` | Tick 驱动缓释；`mode=total` 表示填写总量 |
| `state` | `key/value/operation` | 设置或增加角色状态，如淬毒 |
| `purify` | `value/clearDebuffs` | 净化麻痹和指定前缀的负面 Buff |
| `buff` | `property/calc/value/duration/buffId/stackable` | 普通数值属性临时 Buff |
| `buffDomain` | `domain` | 清除同域上一次登记的持续 Buff，并开始登记本次 Buff |
| `resistanceBuff` | `value/duration/buffId` | 对 `魔法抗性.电/热/冷/波/蚀/毒/冲` 各增加同值 |
| `toughnessBuff` | `value/duration/buffId` | `value` 使用装备 `toughness` 点数口径，运行时换算为基础韧性的线性增量 |
| `restoreToughness` | 无 | 清零当前冲击残量与衰减基线，再刷新韧性派生显示 |
| `playEffect` | `name/offsetX/offsetY/scale` | 播放表现资源 |
| `message` | `text/condition` | 发布使用反馈 |
| `grantItem` | `name/count/chance` | 发放物品 |
| `global` | `key/operation/value` | 修改受控全局变量 |

`heal/regen/state/purify` 默认受炼金影响；具体字段仍以各效果类实现为准。`buffDomain / playEffect / message / global` 默认不进入 Tooltip，`grantItem` 仍显示实际发放内容。

### 2.1 普通 Buff 的 `calc`

| 值 | 语义 |
|---|---|
| `add` / `multiply` / `percent` | 允许同属性多实例进入加法、乘区或百分比乘区 |
| `add_positive` / `add_negative` | 正向取最大、负向取最小 |
| `mult_positive` / `mult_negative` | 正向乘数取最大、负向乘数取最小 |
| `override` | 覆盖 |
| `max` / `min` | 下限保底 / 上限封顶 |

固定 `buffId` 的再次添加会替换旧实例；`stackable=true` 才会生成独立 ID。可净化负面效果的 ID 必须使用 `debuff_` 前缀。

### 2.2 缓释总量

九龙与当前菜品统一使用 `mode="total"`：先对总量应用炼金，再按 Tick 数分摊，余数分配给前若干 Tick。HP、MP 会生成独立 Buff ID；若物品先声明了效果域，两者都登记到该域。

```xml
<effect type="regen" hp="1500" duration="300" interval="30"
        mode="total" id="九龙_狻猊_缓释" scaleWithAlchemy="true"/>
```

## 3. 一个餐食 + 一个强化剂

| 域 | 当前使用者 | 互斥边界 |
|---|---|---|
| `meal` | 有持续 Buff/缓释的食品与菜品 | 新餐食移除旧餐食登记的持续 Buff |
| `enhancer` | 九龙一至三型 | 新强化剂移除旧强化剂登记的持续 Buff |

两个域可以并存。即时 HP/MP、净化、剧情发放和 `狴犴·零型` 属于 `medical` 语义，不占域也不清掉已有餐食或强化剂。纯即时且无持续效果的牛奶同样不触发餐食替换。

域记录保存在单位的 `_drugBuffDomainRegistry`，只保存 `BuffManager.addBuff()` 返回的真实注册 ID；换域不会逆转已经发生的即时效果。

## 4. 韧性与全抗的特殊路径

装备初始化对韧性使用：

```text
韧性系数 = 基础韧性系数 × (1 + 装备 toughness 总点数 / 100)
```

`toughnessBuff.value` 也使用装备点数，但不能直接把最终韧性系数乘以 `1 + value/100`，否则会二次放大已有装备。运行时实际添加量为 `基础韧性系数 × value / 100`，到期后由 BuffManager 还原；任何添加、替换或到期都调用 `ImpactHandler.refreshImpactDerived()` 重算韧性上限、踉跄阈值和显示比例。

`remainingImpactForce` 是当前累计冲击负荷，数值越低表示韧性槽越满；`impactDecayBaseForce` 是本次命中窗口的绝对衰减基线。因此“完全恢复韧性”必须同时把两者设为 `0`。该操作不改 `lastHitTime`，也不取消已经进入的硬直、击飞或倒地。

`魔法抗性` 是对象，普通 `buff property="魔法抗性"` 不合法；`resistanceBuff` 通过七个叶子路径建立同一个 MetaBuff。韧性、完整恢复和七抗词条均属于新增路径，未完成 Flash 实机回归前保持 `runtime-test-pending`。

## 5. 数值证据

药剂公式 v2 把即时 HP/MP 与缓释 HP/MP 分开，只有缓释分量应用时长折价，并新增装备 `toughness` 输入。人工选择与机械投影分层如下：

| 层 | 文件 | 角色 |
|---|---|---|
| 人工方案 | `tools/cf7-balance-tool/records/potion-balance-plan.xml` | 来源等级、域、状态、例外与备注 |
| 完整审计 | `tools/cf7-balance-tool/records/potion-balance-audit.xml` | 实际效果输入、公式输出、市场价、摘要与源摘要 |
| 运行时旁路 | item 根 `<balance>` | 可从方案与实际 XML 机械重建的最小记录 |

item 根 `<balance>` 会被 `ItemUtil` 从一般物品数据树剥离，普通战斗/Tooltip 不消费它；当前武器玩家摘要解析器也会对 `formulaFamily=potion` 失败关闭。

当前工作簿尚未登记药剂 v2，所有记录必须保持 `authorityStatus=workbook-registration-pending`，状态只能是 `proposed` 或 `runtime-test-pending`。不得仅凭同步工具通过便声称工作簿已确认。

```powershell
cd tools/cf7-balance-tool
npm run potion-balance-sync
npm run potion-balance-check
```

## 6. 产品定位

- 普通医疗药剂：战中即时恢复、净化等明确急救价值。
- 食品/菜品：需要合成，以较高总配额换取战前准备；占 `meal` 域。
- 九龙：WP 在西南自治区注册的本地化战斗强化剂品牌，渠道化批量投放；占 `enhancer` 域。
- `狴犴·零型`：100 金币公共应急品，只恢复韧性槽，不提供持续核心战斗数值。
- `负屃`：保留为后续新 Buff 方向，不创建空壳物品。

九龙一、二、三型分别使用 20、40、60 级来源预算，30 级窗口留给其他药剂系列。完整数值和价格不要在本文件复制，统一查药剂平衡规则表。
