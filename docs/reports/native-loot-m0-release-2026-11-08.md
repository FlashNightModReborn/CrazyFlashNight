# 战利品动态图标 M0 发布记录（2026-11-08）

金币、K 点等图标的内容播放不再被卡片入场动画的 450 ms 截断。每张卡片按内容时钟持续播放，暂停、面板遮挡、抢占和恢复保留相位；静态模式保留静态图。物品、数量、卡片存活期、资产与存档规则保持现役合同。

本次源码为 `369c8cb82ce6457e2172717d4a1c0a16d20f1243`，不可变源码标签为 `runtime-build-v2/20261108-loot-icon-loop-m0-v1`。用户对原 M0 开发候选的实战反馈为未发现明显问题；五个 M0 实现文件再次核对，仍与该人测候选逐字节一致。合并主线后的正式二进制另做了定向测试和普通入口启动、退出检查，没有把这些检查表述为新二进制的实战重验。

完整身份、逐项测试、原始计数与证据边界见 [机器报告](native-loot-m0-formal-release-2026-11-08.json)。云端独立构建与签名见 [Actions 作业](https://github.com/FlashNightModReborn/CrazyFlashNight/actions/runs/42430569436)。部署由正式 promotion 脚本完成，绑定本地注册构建者和 GitHub OIDC/Sigstore 两个独立故障域；没有手工覆盖正式 DLL。

## 实测开销

测试使用实际候选 Core 与 Native 合成模块，在自有的 1024×576 捕获窗口中运行生产 Loot → HUD → 合成上传链路。每组预热 2 秒、采样 8 秒。两个静止角点刻意保留整面 HUD 的包围范围，用于记录小图标脏区触发的整面上传；这不是实战帧率或整帧净收益测试。

| 场景 | 提交次数/秒 | HUD GPU P95 | 合成绘制 P95 | 提交 P95 | 托管分配/秒 | 纹理上传/秒 |
|---|---:|---:|---:|---:|---:|---:|
| 1 张静态卡片 | 0 | 无采样工作 | 0 | 0 | 约 11.7 KB | 0 |
| 5 张静态卡片 | 0 | 无采样工作 | 0 | 0 | 约 11.5 KB | 0 |
| 1 张动图卡片 | 18.11 | 0.207 ms | 0.736 ms | 0.984 ms | 约 42.8 KB | 约 42.7 MB |
| 5 张动图卡片 | 18.36 | 0.213 ms | 1.838 ms | 0.611 ms | 约 105.9 KB | 约 43.3 MB |

热播放期间重新开文件、创建 WebP 解码器、整组解码均为 0；四组采样均未触发 GC，各组 GDI 数前后相同。目录采样与常驻帧绘制的单独 1,000 次循环为 0 托管分配，这不等于整条 HUD 链路零分配。30 轮解码与释放后 GDI 为 21→21，句柄为 387→387；私有内存有所增加，不能据此宣称没有原生堆保留。

冷成本单列：目录准备并遍历所测全部帧，1 张、5 张分别约 44.5 ms、191.0 ms；窗口预热阶段的绘制加提交最高约 102.3 ms。Tick 包含同步回调中的绘制，不能再与 Paint/Compose/Submit 相加。进程 CPU 也包含捕获、呈现、消息循环和采集器，不能全部归到动态图标。

## 保留边界

缓存租约与所有权整理仍属于 M1。本次证据没有消除首次加载峰值，也没有解决小脏区触发整面 HUD 上传；上述约 43 MB/s 仅适用于本次窗口尺寸和测试布局。原有静态模式仍可使用。

发布前已备份正式产物，并对既有 404 份 JSON/SOL 做校验：403 份玩家文件不变，启动器版本标记按预期更新。另有一份未进入初始清单的 9 月历史测试 SOL，已在部署前观测到，部署前后哈希相同，单列于机器报告。回滚备份与失败尝试保存在本地证据包中，没有覆盖玩家存档或清理其他会话的工作区。
