## 1. 背景与现状

### 1.1 现有链路（已核实，证据见 §7 锚点表）

- 后端 exe 启动后：FastAPI 监听 `127.0.0.1:7077`（CORS `*`，无鉴权），前端静态页由独立线程伺服于 `7080–7089` 动态端口（绑 `0.0.0.0`），随后 `webbrowser.open` 打开浏览器，并有 tk 状态窗、MessageBox、提示音、任务栏闪烁等用户提示。
- 任务发布：后端把确认的任务原子写入游戏数据目录 `data/task/agent_tasks.json` 与 `data/task/text/agent_text.json`，并把 `data/rag/sync_state.json` 的 `task_publish_version` +1；游戏侧 `通信_aka_Agent联动.as` 在非战斗图每 7000ms 轮询该文件，版本变化即 `_root.重新加载任务数据` 全量重读。**该热更闭环现网可用，本文不改其基本形态，只做扩展。**
- 游戏内拉起 exe：平板电脑「联络列表」按钮 → `_root.agent.启动外部RAG工具()` → `fscommand("fullscreen","false")` 退全屏 + `fscommand("exec","launch_rag.bat")` 通配启动 `CFN-RAG-v*.exe`。拉起后游戏不暂停、双方无回连、无参数传递。
- 游戏已完成 WebView2 面板迁移：面板懒注册（`panels-lazy-registry.js`）、`panel_request`/`panel_cmd`/`panel_resp` 三层协议、`PanelHostController` 统一焦点/输入屏障/几何、**打开即暂停**（`webPanelPause`/`webPanelUnpause` 租约，`PauseManager`）。
- 存档：AS2 运行期可读当前槽位 `_root.savePath`（如 `crazyflasher7_saves`、`cf7_<28hex>`）；存档键含 `tasks.tasks_to_do / tasks_finished / task_chains_progress` 等；游戏内无好感度系统（好感度仅存在于后端 `npc_state_db.json`，且为全局不分存档）。
- NPC 对话：游戏侧集中在 launcher `DataQueryTask.QueryNpcDialogue` 按 `TaskRequirement <= 主线任务进度` 过滤查询，AS2 消费 `默认对话` 洗牌轮换；launcher `DataCache` 无热失效（改对话须重启 launcher）。
- 后端记忆：`tools/memory.db` 五表全部按 `session_id` 隔离，仅有每 30 条消息的会话内滚动摘要，**无跨对话长期记忆**；`orchestrator/context.py` 有 `save_info` 预留字段恒为 `None`。

### 1.2 问题

1. 游戏内打开终端 = 退全屏 + 弹浏览器，体验割裂；exe 为此带一堆窗口/提示操作。
2. 终端与游戏无通信：不知道当前存档，玩家要手填角色卡；任务、NPC 好感度全局混用，多存档互相污染。
3. 无跨对话记忆，同一存档同一 NPC 多窗口聊天会前后矛盾。
4. Agent 任务完成后 NPC 后续对话无变化，与主线/支线流程可能冲突。

## 2. 目标与非目标

### 2.1 目标

- 游戏内可一键打开/随时关闭内嵌聊天终端面板，打开时游戏暂停、输入被屏障，关闭后恢复。
- 游戏与 exe 建立双向通信：游戏侧可判定 exe 可用并完成存档绑定；exe 侧变更经既有文件轮询通道触达游戏。
- 游戏内使用时 exe 全程静默（仅保留开屏 icon），不弹浏览器、不弹窗、不退全屏。
- 按存档隔离：Agent 任务、NPC 状态、长期记忆均以存档槽位为边界，互不干扰。
- 在合适时机（关键任务完成、关系变化等）由后台「对话完善子 Agent」按存档增量修正/新增 NPC 日常与后续任务对话，避免与主线冲突。
- 游戏外双击 exe 仍是独立聊天系统，与游戏无关。

### 2.2 非目标

- 不改动游戏存档（SOL/shadow）的任何写路径；exe 永不写存档，只消费游戏投影下来的只读信息。
- 不改写游戏 base 对话 XML 原文；对话联动只产出按存档的增量覆盖文件。
- 不做联机/多人/云同步；不做 exe 自动更新；不把 exe 纳入游戏 runtime 发布闭包。
- 不重构现有任务协商/发布管线、RAG 检索、立绘链路的内部逻辑（只接新的存档维度）。
- 不迁移 `cfn-terminal-web` 前端仓进本仓；只约定产物交接。

## 3. 运行模式定义

| 模式 | 进入方式 | 存档绑定 | 长期记忆默认 | 任务发布落点 | 对话联动 |
|---|---|---|---|---|---|
| **standalone（独立模式）** | 用户双击 exe（无参数） | 无 | 关（设置里可开） | 共享文件 `data/task/agent_tasks.json`（现状行为，全存档可见） | 不生效 |
| **embedded（游戏内嵌模式）** | 游戏拉起 exe（`--embedded`）或游戏对运行中 exe 发起 bind | 有（bind 建立） | 开（设置里可关） | 该存档专属文件（见 FR-5） | 生效 |

- 模式由**启动参数 + 运行时 bind 状态**共同决定：exe 以 `--embedded` 启动时全程静默等待游戏面板接入；standalone 启动的 exe 之后被游戏 bind 时，仅获得存档绑定（任务/记忆/联动切到按存档），不追溯改变其已打开的浏览器窗口行为。
- 单实例互斥已存在（`launcher.py` 命名互斥体）：游戏拉起前先健康检查，已运行则直接复用并 bind，不起第二进程。
- 读档/换档/回标题导致槽位变化时，游戏重新 bind（新槽位）或 unbind（回到无存档状态，退化为 standalone 数据行为）。

## 4. 功能需求

> 验收标准中的「验证方式」只指方向；具体验证门与证据术语按 `agentsDoc/testing-guide.md` 选择矩阵执行。

### FR-1 游戏内嵌终端面板

游戏内从平板电脑「联络列表」入口打开聊天终端时，不再退全屏弹浏览器，而是在 WebView2 中打开一个注册面板（id 暂定 `ragchat`），面板内以 iframe 加载 exe 的本地页面。

- 面板复用现有面板基座：懒注册、`panel_request` 打开、`PanelHostController` 焦点与输入屏障、打开即暂停（`webPanelPause` 租约）、关闭即恢复。
- 可随时关闭、随时重新打开；重开为面板新实例（新 `panelInstanceId`），聊天历史由后端会话持久化保证不丢失。
- iframe 内页面与 exe API 同源（`http://127.0.0.1:7077`），SSE 流式聊天、立绘、头像等现有功能全部可用。
- 面板内可正常输入中文（IME）。
- exe 不可用时给玩家可见的明确提示，不静默失败、不残留半开面板。
- **验收**：游戏内打开→输入中文聊天→收到流式回复→关闭面板→游戏恢复且角色不可在聊天期间移动→再次打开历史仍在；独立浏览器模式回归正常。

### FR-2 拉起与握手

- 握手方向：游戏 Host → exe。Host 新增对 `http://127.0.0.1:7077` 的专用客户端（仅回环、有界超时）。
- 打开面板前：Host 先 `GET /api/health`；失败则按既有发现规则（镜像 `fscommand/launch_rag.bat` 的 `CFN-RAG-v*.exe` 通配，落在可配置路径）`Process.Start` 拉起并带 `--embedded` 参数，有界等待健康就绪；再失败则告知 AS2 显示错误提示。
- 健康就绪后 Host 调 bind（见 FR-4），bind 成功才打开面板。
- exe→游戏方向不新建实时通道：沿用 `sync_state.json` 版本号 + 游戏 7 秒轮询（扩展字段，见 FR-5/FR-8）。
- **验收**：exe 未运行/已运行/端口被占三类起手路径各有明确行为；拉起耗时有上界；失败提示可见。

### FR-3 exe 静默化（embedded 模式）

以 `--embedded` 启动时：不打开浏览器、不创建 tk 状态窗、无任何 MessageBox/确认框、无提示音、无任务栏闪烁；保留 PyInstaller 开屏 icon（pyi_splash）；致命错误只写 `cfn-rag.log` 并经 `/api/health` 暴露状态；不启动 7080 段前端静态服务（7077 同时伺服 API 与前端页面，见开发计划）。
standalone 模式维持现有提示行为不变（仅有的安全收敛：静态服务绑定回环地址，见 NFR）。
游戏侧 `fscommand("fullscreen","false")` 随内嵌面板启用而退役（收尾阶段删除旧代码路径）。
**验收**：游戏拉起 exe 全程无浏览器/弹窗/声音；日志可定位启动失败。

### FR-4 存档绑定与角色信息自动填充

- bind 载荷（游戏→exe，Host 转发 AS2 投影）：`{slot_key, character:{…}, progress:{tasks_finished:[…], task_chains_progress:{…}}}`。
  - `slot_key` = AS2 `_root.savePath`。
  - `character` 由 AS2 从存档投影（至少：角色名；可含等级、难度等展示性字段），替代玩家手填角色卡。
  - `progress` 供对话联动判定任务完成态（见 FR-8），为只读投影。
- 后端把绑定结果落到请求上下文（`save_info` 预留字段落地），后续该实例的聊天、任务、记忆、NPC 状态全部按 `slot_key` 作用域。
- embedded 模式前端不再显示角色卡填写表单，改为展示「已绑定存档：角色名（slot 短码）」状态条。
- 投影刷新（游戏→exe，全部幂等、best-effort，复用 bind 端点）：每次打开面板都重推全量 bind（同槽位＝刷新投影）；读档/换档完成时重推或 unbind；存档落盘与任意任务完成时也各推一次投影刷新。exe 永不主动拉取。
- 时效口径：exe 的进度投影以「最近一次推送」为准；面板常开期间靠落盘/任务事件保持新鲜。对话改写等关键判断均在事件触发当刻进行，使用的总是当刻推送的数据；展示性字段（如等级）在长期无落盘的间隔内可能滞后，属可接受范围。
- 换存档/读档后：后端即时切换作用域；前端会话列表按存档过滤展示。
- **验收**：双存档分别 bind 后，互不可见对方会话与任务；角色信息自动出现且无需手填；bind 后推进游戏（完成任务/落盘），exe 侧投影随之刷新；关游戏→换存档→重开联络列表，exe 作用于新槽位。

### FR-5 按存档隔离的 Agent 任务

- 存储：新增目录 `data/task/agent_saves/<slotKey>/`，内放该存档的 `agent_tasks.json` 与 `agent_text.json`（结构与现有共享文件相同）。新文件命名遵守后端命名冻结约束，并同轮更新游戏仓 `.gitignore`。
- 写入：bind 状态下确认发布的任务写入当前存档目录；standalone 写入共享文件（现状）。id 段沿用 `序号登记.txt` 已划的 200001–300000；分配器取号时扫描共享文件 + 本存档文件，保证同一存档可见集合内不撞号。
- 游戏加载：`_root.重新加载任务数据` 扩展为「共享文件 + 当前 `_root.savePath` 对应存档文件（存在才加载）」；读档/换档后触发一次重载。
- 热更：仍由 `task_publish_version` 触发；游戏侧只重载与当前存档相关的文件。
- **验收**：A 存档发布的任务 B 存档不可见；运行中发布新任务 ≤ 约 7 秒后游戏内可见；换存档后任务列表正确切换。

### FR-6 按存档 NPC 状态

- `data/rag/npc_state_db.json`（文件名不变）结构升级为 `{ "global": {…现状平铺内容…}, "saves": { "<slotKey>": {…} } }`：standalone/未绑定读写 `global`（现状行为），bind 后读写 `saves.<slotKey>`。两作用域各自权威，不做双读/回填/迁移。
- 游戏侧只探测该文件存在性（现状），不读内容，故游戏侧无改动。
- **验收**：同一 NPC 在 A/B 存档的好感度/情绪互不影响；standalone 行为不变。

### FR-7 跨对话长期记忆

- `tools/memory.db`（文件名不变）新增长期记忆表，键为 `(save_slot, npc)`；standalone 未绑定时归入独立作用域键。
- 会话内滚动摘要按规则晋升写入长期记忆；后续聊天把该 `(save_slot, npc)` 的长期记忆注入编排上下文。
- 开关：embedded 默认开、standalone 默认关；设置持久化，玩家可改。
- **验收**：同存档同 NPC 开新会话能引用旧会话事实；关档换存档后另一存档无此记忆；standalone 默认不产生长期记忆。

### FR-8 任务/关系驱动的对话联动

- **触发（合适才做，不是每次聊天/每个任务都改）**：两类信号——①游戏通知 Agent 任务完成（`task-completed {slot_key, task_id, npc}`，通知失败只记日志不阻断游戏；exe 按 `(slot_key, task_id)` 幂等去重）；②聊天中主 Agent 识别到关系等级变化、或与既有对话明显冲突的新事实。信号先经「关键性/衍生影响」判断（如：较为关键或有衍生影响的 Agent 任务、关系发生一定变化），够格才委派；并有频率限制控制成本。
- **委派**：判定合适后，把关键信息（触发原因、相关事实、当前关系、进度投影）交给后台对话完善子 Agent 独立执行，不影响前台聊天链路。
- **子 Agent 策略（先修后加，也可不动）**：自主检索该 NPC 对话后——
  1. **修**：仅当既有对话与当前状态明显矛盾（态度不对、关系不对、关键信息不一致）时，做最小幅度措辞修正；
  2. **加**：无矛盾时优先新增一个日常对话组（影响最小）；仅在合适时给后续/可重复任务对话追加一两句；
  3. **不动**：判断无必要时直接放弃（记 skipped）。
- **检索跳过规则**：已由玩家完成、且不可重复（主线/支线等带序号链）的任务，其接/交任务对话键**不纳入**检索候选；可重复的委托副本任务对话不跳过；日常轮换对话（`TaskRequirement` 门控）是主要对象。
- **落盘与合并**：产出写入 `data/dialogues/agent_overrides/<slotKey>.json`（新目录，同轮 `.gitignore`）并 bump `sync_state.json` 的 `dialogue_version`（新字段）；launcher 对话查询按当前 `slot_key` 合并覆盖（replace by id / append 新条目），覆盖层缓存可按版本号或文件变更失效；base XML 永不改写。
- **验收**：触发条件满足且子 Agent 产出后，相关 NPC 对话出现呼应的修正/新增；矛盾对话被最小幅度修正；已完成主线的任务对话不被改写；普通聊天与非关键任务不产生覆盖（记 dismissed/skipped）；B 存档无变化；重启与热更两条路径都生效。

### FR-9 独立模式保持

standalone 全流程（浏览器打开、聊天、任务发布到共享文件、游戏轮询热更）不因本集成回归；embedded 改造不得影响 standalone 的默认行为与默认配置。
**验收**：无游戏环境下双击 exe 的现有旅程逐步回归通过。

## 5. 非功能需求

- **安全**：exe 全部监听面收敛到 `127.0.0.1`（含 standalone 的 7080 段静态服务由 `0.0.0.0` 改绑回环）；API 无鉴权的前提是本机回环 + 游戏 Host 对 iframe origin 做 exact 白名单（http://127.0.0.1:7077），不引入通配。
- **性能**：面板打开到可输入 ≤ 2s（exe 已运行场景）；不新增游戏帧循环负担（轮询保持 7s 节奏，战斗图仍跳过）；对话覆盖合并只发生在查询路径且可缓存。
- **可靠性**：跨层写遵循未知写纪律——Host→exe 的 HTTP 写只重试幂等请求，非幂等（bind 以外暂无）不走自动重放；文件写全部 tmp+replace 原子写（沿用现状）。
- **可维护**：命名冻结（既有文件名/目录名一律不改，只新增）；新增生成物同轮更新游戏仓 `.gitignore`；契约变更登记 `launcher/contracts/panel-contracts.v2.json` 并维护命令闭环表；文档随施工同批修正。
- **证据纪律**：源码成立、候选构建、实际运行、E2E、发布各自独立，不用 `build.ps1` 冒充运行证据；含 Host C# 改动，正式发布须走既有发布协议并获得单独授权。

## 6. 约束与既有合同

- 新增跨层命令/面板属 authority-core 命中项：施工前必读 `agentsDoc/as2-web-panel-migration.md` 权威核心节并按其 §3/§4/§5 接入清单施工。
- AS2 改动前必读 `agentsDoc/as2-anti-hallucination.md`；`.as` 保持 UTF-8 BOM；只用真实 Flash CS6 GUI 编译，目标按归属选择。
- 后端约束见后端仓 `AGENTS.md`：venv 激活后 `python -m pytest tests/`；运行时/开发依赖分列；生成物命名冻结。
- 前端产物交接：`cfn-terminal-web` 仓构建 → 拷入后端仓 `dist/` → 后端打包 exe；本需求不改该链路。
