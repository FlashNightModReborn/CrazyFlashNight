## 1. 文档边界与权威

- `data/items/**/*.xml` 的 `<data>`、`<data_2>`、`<lifecycle>`、`<hitBehavior>` 等是运行时输入；`<description>` 是玩家的风味/说明文本，不是战斗数值源。
- 装备实例的真实数值由 `BaseItem.getData()`、`EquipmentCalculator`、配件/进阶/强化链计算；`<balance>` 不是战斗数据源，不能从简介或 balance 反推运行时值。
- 敌人属性表 `<标识>` 是设计侧标注，不直接进入战斗结算；敌人实际数值以加载后的属性与 `根据等级初始数值` 为准。
- 玩家可见属性标签目前分散在 `TooltipConstants.PROPERTY_DICT`、`PlayerInfoSnapshotBuilder`、HUD Buff 文案和各 Builder 中；它们是展示投影，不是第二套权威。
- **不得重命名 AS2 运行时字段**（如 `unit.装备枪械威力加成`、`unit.装备刀锋利度加成`、`unit.hp满血值装备加层`）。文本统一只改玩家可见字符串、字典映射和必要的只读投影；存档、装备脚本、战斗计算契约保持原字段。

## 2. 术语原则

1. **一概念一词**：同一游戏概念在同一类位置使用同一名称；不同概念不得共用“加成”“威力”“抗性”等泛词。
2. **先标层级，再写名称**：必须说明是基础值、装备贡献、角色总面板、结算值，还是显示派生值。
3. **数值必须带单位**：点数、百分比、倍率、毫秒、帧、米/秒、格、层等不得省略。
4. **区分固定值与百分比**：固定值写“+N”，百分比写“+N%”，独立乘区写“×N”。
5. **不暴露代码字段**：不把 `hp满血值装备加层`、`damageTakenMultiplier`、`remainingImpactForce` 等内部名直接写进玩家文本。
6. **风味文本可保留文学表达，但带数值的句子必须服从本表**。武器名、敌人名、世界观专名不因术语统一而重命名。
7. **先技能、后装备、再其他**：遵循 #266 的范围与优先级；本表先作为后续批次的共同底稿，不一次性全量改写。

## 3. 战斗数值分层

```text
等级 / 单位模板 / 出生难度
        ↓
基础值（hp_min/max、攻击、防御、躲闪、速度等）
        ↓
装备强化、进阶、插件、套装、被动、健身/经脉
        ↓
角色总面板（最大生命、防御、命中、闪避、韧性系数等）
        ↓
武器发射参数（power、split、interval、impact、knockback 等）
        ↓
命中分类（未躲闪 / 格挡 / 躲闪 / 直感 / 跳弹 / 过穿 / 暴击）
        ↓
伤害类型与减伤（物理 / 魔法 / 破击 / 真伤；防御 / 抗性 / 护盾 / 承伤系数）
        ↓
附加结算（毒、吸血、击溃、斩杀、实际命中终结）
        ↓
冲击控制（冲击力、韧性上限、踉跄阈值、击倒/被击、击退）
```

## 6. 计算公式与显示派生

### 6.1 装备数值

- 强化倍率仅作用于 `power / defence / damage / force / punch / knifepower / gunpower / hp / mp`。参考 `EquipmentCalculator.as:169-185`。
- 配件按 `flat → percentage → 独立乘区 → curve → softOverride → override → merge → lockOverride → cap` 计算。参考 `EquipmentCalculator.as:389-438`。
- `toughness / accuracy / evasion / criticalhit / slay / rout / vampirism / lazymiss / poison / magicdefence / weight` 不参与常规强化倍率，只吃固定加算、插件或特殊生命周期。

### 6.2 单次伤害

```text
S = (子弹威力 + 伤害加成) × 随机波动(0.85~1.15)
  + 固伤
  + 目标当前生命 × 百分比伤害%
S ×= damageTakenMultiplier
若暴击：S ×= 1.5

物理/未知：S × 300 / (防御 + 300)
魔法：    S × (100 - 抗性) / 100
破击：    S × 300/(防御+300)
        + S × rate × (100 - 抗性)/100
        rate = 0.1（电/热/冷/波/蚀/毒/冲/基础）
        rate = 0.5（装甲/机械/人类/精英/首领等分类）
真伤：    S
```

- 参考 `DamageCalculator.as:157-186`、`UniversalDamageHandle.as:75-160`。
- 物理与破击的物理部分使用 `300/(防御+300)`；防御 ≤0 时按 1 处理。
- 抗性默认 `10 + 等级/2`；超过 95 后按 `95 + (r-95)/11` 软上限，最高 100；负抗性为易伤。
- `split>1` 时，上式为**单段**伤害；总伤害按实际命中段数累加，并受覆盖率、生命上限、护盾和特殊联弹规则约束。
- 护盾在伤害计算后吸收；真伤可绕过护盾。击溃、斩杀、吸血还受“子弹威力 > 护盾强度”门槛影响。

### 6.3 命中与闪避

```text
最终闪避率 = sigmoid(
  (闪避者等级×10 / 躲闪率 - 攻击者等级×命中率/3) / 40
) × 50%
```

- 未进入闪避系统：目标有 `受击反制` → 格挡；否则未躲闪，全额命中。
- 进入闪避系统：完全躲闪概率 `clamp((等级 - 重量)/100, 0, 1)`；剩余空间中跳弹概率 `clamp((重量-20)/80, 0, 1)`，否则过穿。
- 跳弹：`max(floor(伤害 - 防御/5), 1)`；过穿：`max(floor(伤害×300/(防御+300)), 1)`。
- 联弹/霰弹使用分段躲闪模型，按每段抽样；不要把整串结果描述成一次闪避。
- 高危回避：`lazymiss` 先存为 `value/100`；伤害 > 50% 最大生命时按 `100×value%`，半血上下分别走动态曲线。参考 `DodgeHandler.as:238-305`。

### 6.4 冲击与韧性

```text
韧性上限 = 韧性系数 × 当前生命 × (防御 + 300) / 300
踉跄阈值 = 韧性上限 / 2 / 躲闪率
单次冲击力 = 伤害 × 50 / 击倒率
```

- 冲击槽 150 帧内不衰减，之后到 300 帧线性衰减到 0。
- 超过韧性上限 → 击倒；超过踉跄阈值 → 被击；否则普通受击。刚体不进入击倒/被击。
- 水平击退速度是独立位移参数，不等于冲击力或击倒率。

### 6.5 面板显示派生

- `PlayerInfoProvider.getAccuracy`：`floor(命中率 × 10)`，所以面板“命中率”是内部参数的 10 倍显示。
- `getEvasionCost`：`floor(躲闪率 × 10)`；`getGuardBreakAbility`：`floor(50 / 躲闪率)`；`getStabilityAbility`：`floor(100 × 韧性系数)`。
- `getLazyDodge`：`floor(懒闪避 × 100)`，显示为百分比。
- `getDamageReductionValue`：`1 - 300/(防御+300) × damageTakenMultiplier`，保留 1 位小数；防御 ≤0 的显示与伤害管线按 1 处理的边界不一致，后续需要统一说明或修正。
- 工具提示“冲击力”当前按 `floor(500/impact)`，实际冲击槽按 `伤害×50/impact`，相差 10 倍；在两个口径裁决前，不得把两种“冲击力”混写进简介。

- 验证：按实际改动归属执行 `testing-guide.md` 的 AS2/Web/Host 验证门；不把文档通过当作游戏内验收。

### B3：装备与物品简介

- 范围：`data/items/**/*.xml` 的 `<description>` 中带数值或机制名词的句子；优先装备、武器、插件，再处理药剂/消耗品。
- 原则：风味文本可保留；仅统一术语、单位、作用对象；不批量重写 lore，不把内部字段写进简介。
- 工具：按 #264 的建议增加只读禁用词扫描（内部字段名、`魔法抗性` 直出、`破甲` 误用等）；存量差异一次性清理或显式白名单。
- 验证：数据加载/文本巡检；若涉及生成器或 XML 结构变化，按数据验证门执行。

### B4：通用帮助与词条（可选）

- 评估在帮助面板提供基础属性词条，减少每条技能重复解释。
- 只有在 #266 范围确认后才推进；不把帮助页当作战斗公式权威。

## 9. 待裁决事项

| 事项 | 现状 | 影响 | 建议 |
|---|---|---|---|
| `impact` 显示系数 | tooltip `500/impact`；实际 `50/impact` | 简介无法确定“冲击力”口径 | 先确认是否修正 tooltip 或改结算系数；未裁决前只用“击倒率（原始）” |

| 暴击伤害 | 固定 1.5 倍，无独立字段 | 简介可能写“暴击伤害 +X%” | 只写“暴击率”，如出现暴伤需求另立设计 |
