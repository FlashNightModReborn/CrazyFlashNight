# 地图绘制 SOP 与守则

**适用范围**：`map-production/` 下的矢量战斗地图（无任务、未重置关卡）。  
**当前阶段**：只产出地图资产与环境建议片段，不实装关卡、不改 stage XML、不挂选关。  
**一句话原则**：先取证，再复用，宁可少而精，不要多而糙。

## 0. 三条硬规则

1. **元件少而精。** 一张图 6–12 个主要元件，最多不超过 15 个；宁可把一件做透，不要摆一地简笔画。
2. **复用优先。** 能在现有地图里找到视角、尺度、风格合适的元件，就直接复用并记录来源；新绘只用于没有合适来源的地标。
3. **固定视角立体感。** 所有元件按同一侧视/微俯视角绘制，必须有正面、顶面/侧面、厚度、接触阴影；禁止用单根线、纯色矩形或正面图标代替立体物件。

## 1. 开工前：取证

先读证据，再动笔。至少收集：

| 证据 | 来源 | 用途 |
|---|---|---|
| 关卡任务与剧情 | `data/stages/**/<关卡>.xml`、设计文档 | 确定地标、出入口、战斗节奏 |
| 旧地图 | 对应 `flashswf/backgrounds/*.swf` | 只取空间语法、材质、色板，不照搬像素 |
| 画布与可走带 | 现有同区域地图、环境表 | 1750×600、地墙线 y=352、可走带 y=360–600 |
| 相机与出口 | stage XML / 环境建议 | 1024×576 舞台、出口 x=1700、左进右出 |
| 碰撞与刷怪 | stage XML | 碰撞是障碍轮廓，不是地面边界；本阶段只写建议片段 |
| 可复用元件 | 现有 `*.fla` / `*.swf` 库 | 优先复用，减少手搓 |

把结论写进本关卡的 `design.md`：5 图顺序、每图地标、复用清单、不画清单、证据来源。  
**不要把“变量名里像门”的东西画成门**；只画场景里真实存在、玩家能看到的东西。

## 2. 构图与坐标

- 画布：`1750×600`，`viewBox="0 0 1750 600"`。
- 地墙交界：`y=352`；可走带：`y=360–600`；右侧出口：`x≈1700`。
- 默认左出生、右出口；主推进路线保持在画面下半部。
- 一张图只设 1 个主地标，最多 2 个；其余元件服务地标，不抢戏。
- 前景遮挡不超过画面 15%，不得盖住可走带和出口。
- 图层顺序（XFL 从上到下）：`foreground → mid → gameplay → far-wall → background-bake`。  
  SVG 里按相反顺序写：`background-bake → far-wall → gameplay → mid → foreground`。
- 地面、血迹、光池、接触阴影放在 `gameplay`；道具底座放在 `mid`；近景碎片放 `foreground`。  
  **地面层不能压住道具底座。**

## 3. 元件分级

每个元件先归类，再决定怎么做：

| 级别 | 定义 | 处理 |
|---|---|---|
| **A 复用** | 现有地图里已有的通用元件（箱、沙袋、控制台、门、植物、告示板、灯、管线等） | 直接复制，保留原始比例/矩阵；按目标尺度整体缩放；记录来源 |
| **B 新绘** | 该场景的地标或没有合适来源的专属物件 | 按第 4 节细度标准绘制；数量不超过主要元件的 40% |
| **C 不画** | 角色、敌人、掉落、UI 文本、碰撞线、运行时特效、剧情里没出现的物件 | 不画；需要时写进 `design.md` 的待办 |

### 3.1 复用流程（A 级）

1. 在现有 `flashswf/backgrounds/*.fla` 里找同名/同类别元件；优先找有命名库的室内图（控制室、医院、兵工厂、仓库、指挥外围）。
2. 用 FFDec 导出元件预览：`-format sprite:svg -export sprite <out> <swf>`。  
   先看接触表，确认视角、尺度、色板是否合适。
3. 选中后把 sprite SVG 内联成自包含的 `<g>`：解析 `<use>`/`<defs>`，去掉 `filter`、`clipPath`、`pattern`、`image` 和外部引用；保留渐变（`gradientUnits="userSpaceOnUse"`）。
4. 放进目标 SVG 时用**左下角锚点**：
   `transform="translate(x, bottomY - height*scale) scale(scale)"`。
   只做等比缩放，不拉伸；需要镜像时 `scale(-s,s)` 并同步平移。
5. 记录来源：源 SWF/FLA、sprite ID、原始尺寸、缩放、是否改色、放置坐标。
6. 给元件补接触阴影（`gameplay` 层椭圆/多边形），底座不能悬空。

> 试点期复用库放在 `tmp/component_probe/inlined/`；样张复核通过后再登记到 `map-production/components/`，不要提前把临时产物当正式库。  
> FFDec 只用于取证/预览，不进入交付链；没有 FFDec 的组员向维护者索取已内联的 SVG 元件，不要自行从位图截图描摹。

### 3.2 新绘细度标准（B 级）

一个主要元件至少满足以下 6 条：

1. **有体积**：能看到正面 + 顶面/侧面，轮廓不是一个矩形或一根线。
2. **有结构**：底座、主体、台面/顶盖、连接件分层；至少 3 个明度层次。
3. **有细节**：倒角/包边、接缝、螺栓、散热槽、线缆入口、铭牌（抽象色块，不写可读文字）。
4. **有磨损**：划痕、掉漆、污渍、缺角、积灰，位置不对称。
5. **有接触关系**：底部有接触阴影，和地面/墙面有过渡，不悬浮。
6. **有正确尺度**：按 1.75 m 人物约 150 px 估算；厚度、台面高度、把手位置合理。

**简笔画判定**：把图缩到 50% 看，如果元件只剩一个色块或几根线，没有厚度和结构，就是不合格。  
**禁止**：纯黑/纯白大平面、2 px 单线勾边、正面图标贴到侧视场景、复制整张旧图。

## 4. 材质、灯光与磨损

- 主色：深枪灰、旧混凝土、黑金属；强调色：诺亚蓝白、少量橙色应急灯、黄黑警示条。
- 金属用竖向/斜向渐变 + 边缘高光；玻璃用低透明蓝灰 + 竖向反光；混凝土用大块渐变 + 细裂纹/污渍。
- 一张图只设一个主光方向；顶灯/应急灯要有光锥和地面光池，但不得把可走带照糊。
- 磨损要“局部、不对称”：墙角、门底、台面边缘、常接触的把手附近更重。
- 线缆要有垂坠和固定点；不要画成随机曲线。
- 文字只做抽象色块/刻度，不写可读文案（品牌标识除外，按现有素材原样复用）。

## 5. 标准施工顺序

1. **取证**：读关卡、旧图、现有元件库，写 `design.md`。
2. **选地标**：一张图一个主地标；列出 6–12 个主要元件，标 A/B/C。
3. **粗排**：先画地面、墙、顶、入口/出口、可走带、主光方向；不急着抠细节。
4. **先放复用件**：按 A 级流程放置、缩放、补接触阴影；确认尺度和遮挡。
5. **再画新件**：只补没有来源的地标；按 3.2 标准逐条过。
6. **材质与灯光**：统一色板，补渐变、包边、接缝、磨损、光池。
7. **图层检查**：地面在道具下，前景不挡路，远墙在最后。
8. **静态 QA**：Chrome 打开 SVG，100% 和 50% 各看一遍；对照参考图检查视角、尺度、密度。
9. **编译验证**：SVG → XFL → 真实 CS6 publish → FFDec 首帧导出；核对首帧脚本、尺寸、图层。
10. **交付**：源 SVG、XFL、SWF、复核 PNG、`design.md`、环境建议片段、install/manifest；不实装关卡。

## 6. 验收清单

### 6.1 画面

- [ ] 6–12 个主要元件，没有“为填满而填”的小物件。
- [ ] 每个主要元件通过 50% 简笔画测试。
- [ ] 至少 2 个元件来自现有地图复用，来源已记录。
- [ ] 所有元件同一视角，顶面/侧面方向一致。
- [ ] 地标明确；第一眼能看出这张图讲什么。
- [ ] 没有可读文字、角色、敌人、掉落、碰撞线。
- [ ] 前景遮挡 <15%，可走带和出口清楚。

### 6.2 技术

- [ ] SVG 无位图、无 `<text>`、无外部 `<use>`、无未展开的滤镜/裁剪路径、无弧线命令。
- [ ] 渐变均为 `gradientUnits="userSpaceOnUse"`。
- [ ] 图层顺序为 `foreground → mid → gameplay → far-wall → background-bake`。
- [ ] 地面/血迹/光池在 `gameplay`，道具底座在 `mid`。
- [ ] XFL 由真实 CS6 发布；SWF 首帧为 `_root.贴背景图();`。
- [ ] SWF 尺寸 1750×600，30 fps，无 linkage 导出。
- [ ] FFDec 首帧复核图与 SVG 预览一致（允许滤镜/发光差异）。
- [ ] 包校验通过（strict 按任务要求，缺图时注明预期）。

### 6.3 证据边界

- 只声明“固定视角静态复核”，不声明运行/关卡实装验证。
- 候选构建、真实 publish、静态复核是不同证据；不要用“编译通过”代替“画面通过”。
- 复用元件只证明“该矢量在本次 SWF 中正确渲染”，不证明原地图的运行行为。

## 7. 禁止清单

- 禁止 ImageGen / 第三方生图 / 位图描摹作为正式地图或概念图。
- 禁止复制整张旧图、换色当新图、同一元件无节制铺满。
- 禁止简笔画、正面图标、纯色方块当立体元件。
- 禁止在本阶段改 stage XML、环境总表、正式选关。
- 禁止改 `AGENTS.md` 做全局自动注入；地图规范只在用户指示下读取。
- 禁止把临时验证产物提交进正式包；验证样张放 `tmp/`。

## 8. 常见失败模式

| 现象 | 根因 | 修正 |
|---|---|---|
| 元件像简笔画 | 只有轮廓/单色块，没有厚度和结构 | 按 3.2 补正面/顶面、包边、接缝、阴影 |
| 画面很满但不好看 | 小物件太多，主次不分 | 删到 6–12 个主要元件，放大做透 |
| 像贴纸 | 元件正面朝前、没有透视/接触阴影 | 改成侧视/微俯，补底座阴影和遮挡 |
| 风格不统一 | 复用件色板/尺度差异大 | 统一缩放和色板；必要时做变体并记录 |
| 地面盖住道具 | gameplay/mid 顺序错 | 按图层顺序修正 |
| 编译后效果丢失 | 用了滤镜/裁剪/外部引用 | 内联时去掉不支持特性，改用渐变/多边形补 |
| 可走带被挡 | 前景过大或道具压到 y=360 以下 | 缩小前景，主道具底座保持在 y≥352 的背景侧 |
