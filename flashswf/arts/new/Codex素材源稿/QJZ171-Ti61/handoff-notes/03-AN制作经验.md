# AN 制作经验：让批准画面在编辑之后仍保持一致

## 原生组织

每套素材使用总装 → 主分件 → 必要子件/光效 → 中文细节层 → 独立形状组的关系。完整包包含两套各自独立的库，避免修改实战档时带动展示档。

```text
总装（每套 1）
├─ 主分件（每套 15，包含完整弹箱）
│  ├─ 中文结构/甲面/细节层
│  │  └─ 独立编组内的矢量形状
│  ├─ 所属光效实例（全套共 8）
│  └─ 弹箱：箱体 / 闭合上盖 / 提手（3 个子件）
```

灯晕位于所属机匣、上盖或弹箱内部，移动分件时跟随。装饰分面保留在细节层，螺钉和每条高光无需各自占一个顶层库元件。

## 本轮发现的色面自动合并问题

最初候选的 XML 可以打开、保存和重开，计数也正确。但实际移动父元件内的光效实例后，局部叠色发生变化。矩阵复位完全一致，保存回读却显示一些同层原始色面被 Animate 自动合并；临时的 `isFloating` 属性没有形成稳定的编辑边界。

最终每个独立色面都放入真实的 `DOMGroup / members / DOMShape` 编组中，保留原绘制顺序。重新实际验证后，52 个实例移动复位的全图 RGBA 差异为 0；保存重开也为 0。

这说明“位置还原”与“画面还原”需要一起验证。当前元件内的这些组承担透明叠色的隔离作用；继续修改时进入组内编辑所需形状，完成后回到原层级查看。

## 转轴变化时，形状与渐变一起换坐标

本资产的作者比例为 `s = 0.5`。若某个分件的作者转轴为 `P`，形状点 `p` 的原生局部坐标为：

```text
p_local = s × (p - P)
child_translation = s × (child_pivot - parent_pivot)
```

主分件在总装中的位置为 `s × P - (474.5,207.5)`。总装在 949 × 415 舞台上放在 `(474.5,207.5)`，恢复原来的完整画面。

填充渐变的域和矩阵平移也随分件换算。只移动轮廓、保留原全局渐变中心，会造成反光或光斑相对部件漂移。径向渐变还要保留完整的旋转、非均匀缩放与中心位置。

这些是美术元件的局部坐标。游戏已有的握持点、枪口特效点与角色容器关系仍按上次实装工程处理。

## 转换中保留的细节

| 项目 | 本轮处理 | 对后续修改的意义 |
| --- | --- | --- |
| 线帽与转角 | 遵循 SVG 原属性；未指定时按平端、斜接处理 | 避免细丝、刻线或孔缘因统一圆头而变粗 |
| 透明径向 | 保留色标透明度和完整椭圆变换 | 灯晕不能变成不透明红块，也不能丢失方向 |
| 局部坐标精度 | 转到 twip 前消除浮点计算尾差，再做统一量化 | 父子重分件不应凭计算顺序平移半个最小单位 |
| 复合负形 | 对枪托等实际形状先做原生小样和透明检查 | 源稿能显示孔洞，不自动证明原生解释相同 |
| 图层顺序 | 按 SVG 的覆盖顺序映射到时间轴层次 | 原控制件、夹环、前景侧杆继续遮挡正确位置 |
| 中文名字与引用 | 库路径、时间轴和实例引用对应同一份清单 | 接入与局部修改都有明确入口 |

本轮源稿使用的是已校准的 SVG 子集。新加入文本、位图、滤镜、遮罩、复用引用、整个分组的透明度、非居中径向焦点或其他未覆盖特性时，先检查转换支持范围，并做相关原生小样。

## 验收顺序

1. 在新的输出目录生成候选，检查库引用、层名、分件及局部转轴。
2. 实际打开候选，保存新的 FLA，导出同尺寸透明图。
3. 打开需要编辑的元件；对主分件、弹箱子件及独立光效实例分别移动并复位。
4. 导出复位图，关闭后重开已保存 FLA，再导出重开图。
5. 比较同一环境的完整 RGBA，并检查整枪、透明孔洞、关键局部及实际小尺寸。
6. 只读回读实际保存文件，确认图形、引用和转轴没有丢失。

原生计数主要防止漏件。XML 字符串可能因保存时的默认属性、边记录排序和小数规范化变化；应理解其语义，再用实际图像核对。跨 SVG/Animate 渲染器的抗锯齿差异另行判断，不能用它代替同环境复位检查。

## 原生小尺寸导出

本轮 160、200、300 px 图片是在 Animate 的临时文档内缩放矢量后直接导出。评审裁切框在原生坐标中为 `(14,70,914,270)`；该框只规定预览范围，不规定游戏挂点。

完整弹箱、箱体、盖和提手也分别原生导出，方便查看总装中被挡住的部分。复制到临时导出文档的状态在完成后丢弃，已验收主文件保持原样。
