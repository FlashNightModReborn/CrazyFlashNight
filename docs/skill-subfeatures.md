# 技能子能力合同

代码基线：`4d7034f106dda10f336f6fe21d90280307f98e62` 加 2026-10-25 未提交施工差异。父技能继续拥有学习、等级、SP、旧技能行和总开关；子能力不占新增技能槽，不独立收费或升级。目录的唯一真源是 [SkillFeatureRegistry.as](../scripts/类定义/org/flashNight/arki/skill/SkillFeatureRegistry.as)。本轮接入冲击连携和剑气释放，目录声明各自沿用的父技能等级前置。

## 默认与存档

旧档没有配置时全部默认开启，读取不会生成新字段。只有关闭的稳定 ID 写入角色扩展：

```json
{"skillFeatures":{"v":1,"disabledIds":{"impact_chain.half_reload":true}}}
```

该对象位于 `ext`，运行时为 `_root._saveExt`。最后一项重新开启后移除 `skillFeatures` 命名空间；不修改其他扩展，不删除未知但格式正确的历史 ID。未知版本或畸形配置原样保留，阻止子能力写入，运行时沿用旧行为；UI 明示暂不可修改。有效 ID 为至多 64 字符的 ASCII 小写点分标识，每段首字符为字母，其余允许数字和下划线；至多 128 项，持久值只能为 `true`。第 129 项在写入、revision、dirty 和投影之前拒绝，满表仍可重新开启已有项；最后一项移除与容量拒绝使用不同返回值。

运行时缓存位于所属角色的父技能 `__featurePrefs`。有效条件为父技能启用、达到目录等级并且该子能力没有被关闭。NPC 从自己的父技能读取，不借用玩家扩展。父技能关闭保留选择；重开、升级、重排、存档回读保留选择。读档在扩展恢复后投影，CF6 临时构筑替换被动后也重新投影。

## 写入与界面

管理态选择父技能后进入「子能力设置」次页，沿用共享 SecondaryPage、帮助、返回、关闭和键盘焦点合同。学习界面继续只处理父技能。子能力开关和父技能总开关各自保留；父技能关闭时可编辑已解锁的子能力偏好。

命令闭包为 `setFeature → SkillTask → skillSetFeature → SkillLoadoutService.setFeature`，精确输入为 `v / featureId / enabled / expectedRevision`。它复用技能 revision、提交/回滚、保存 dirty 和已提交属性投影屏障；no-op 不增加 revision、不写存档、不投影。失败回滚恢复原扩展对象引用及被动缓存。未知写锁沿用原协调器，只以绑定原 callId 的新鲜对账快照解除，不自动重放写入。

技能快照增加可选 `features` 数组；每行精确包含 `id / skillKey / label / description / minLevel / unlocked / enabled / effectiveEnabled / writeBlocked`。Host/Web 都检查父技能存在、唯一 ID、类型、等级和有效状态的一致性。成功写回还须证明请求的那项选择；缺失或矛盾的成功返回进入既有未知结果流程。兼容不含该字段的旧快照。

## 战斗消费

冲击连携的半换弹、主手短枪火力、混搭冲击、副武器冲击、副武器火力转化、幽灵装填、霰弹额外冲击、霰弹副武器火力分别在原消费者处设门，默认公式保持原样。关闭半换弹不丢失父技能的伤害加成。幽灵装填关闭后的已付费幽灵弹，仅在已提交 SKILLS 投影时通过既有弹药规范化退回原弹种拆包余额；普通弹、膛内弹和奖励弹保持各自权威，重复投影不得重复退款，重新开启不凭空补弹。普通 STATS 刷新不执行这条弹药恢复路径。

剑气释放组在四个生产搓招函数的最前端检查自身子能力。关闭后返回 0，不跳攻击标签、不消耗普通攻击输入；DFA、旧帧检查及按兵器类型重映射继续沿用。配置 XML 的其他历史 Requirements 漂移不纳入本轮修正。

双枪持续同按 J/K 的换弹修复独立于该框架：装填开始时记录已按住的手，只有松开再按下的对应手才构成新打断意图。该修复不以父技能或半换弹开关作为生效条件。真实键盘手感与正式入口验收另记，见[本轮实现及验证](reports/Issue165与通用子能力开关-2026-10-25.md)。
