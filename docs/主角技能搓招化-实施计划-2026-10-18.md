# 主角技能搓招化 · 实施计划（2026-10-18）

> 参考实现：`scripts/逻辑/单位函数/单位函数_雾人_兵器搓招指令.as` + `单位函数_雾人_空手搓招指令.as`
> 目标：让主角的「技能」（12 槽快捷技能 / F 主动战技）可以用格斗指令输入释放，而不是只按键。
>
> **⚠ 后续范围已收窄**：本文档 §4/§8 的「终结键」「做哪一类技能」等问题已定，最新方案见
> `docs/冷兵器主动技能搓招化-实施方案细则-2026-10-18.md`（只做冷兵器主动快捷技能，C 终结，不改 C#/TS/XFL）。

---

## 0. 一句话结论

可行，而且不需要动 XFL 资源、不需要动 C#（若复用现有 A/B/C 作为终结键）。
真正的工作量在三处：**① 指令表要写进三个 DFA 模组**、**② AS2 要新增一套「技能搓招」函数并挂到待机/行走状态机**、**③ 指令序列必须与前缀冲突的普攻招式错开**。

## 1. 现有搓招链路（先认清改在哪一层）

| 阶段 | 位置 | 事实 |
| --- | --- | --- |
| ① 指令表 | `data/inputCommand/*.xml` + `list.xml` | 纯 XML，`Command`/`Sequence`/`Derivations`/`Groups` |
| ② 编译 | AS2 `InputCommandListXMLLoader` → `InputCommandSetXMLLoader` → `CommandConfig` → `CommandRegistry`（编译成 TrieDFA） | 启动时**一次性**编译，运行期不可再注册 |
| ③ 下发 | `帧计时器.构建搓招模组` → `sendSocketMessage("D"+0/1/2+"\x01"+json)` | 模组只有 `barehand / lightWeapon / heavyWeapon` 三个，id 0/1/2 |
| ④ 匹配 | Launcher `launcher/scripts/src/input-processor.ts`（V8） | 收 `\x04` 的 `mask\|facing\|moduleId\|dtDir`，回 `K` + `chr(cmdId+0x20)` + `cmdName` |
| ⑤ 落地 | AS2 `帧计时器.frameUpdate` → `搓招缓冲ID/名/帧` → `当前搓招名` | 只喂 `_root.控制目标`；有效窗口 `bufferTolerance + 1` 帧 |
| ⑥ 消费 | 各容器帧调用 `_parent.兵器攻击搓招()` / `空手攻击搓招()` → `_root.技能函数.使用XXX()` | 命中靠 `自机.当前搓招名 == "招式名"`，兜底靠帧检查 |
| ⑦ 反馈 | `_root.技能函数.搓招监控(名, 1/2)` | 1=DFA 预输入、2=同帧帧检查；同时置 `搓招缓冲已消费`、推 `Ncombo` 刘海 |

## 2. 决定方案边界的 8 条硬事实

1. **DFA 在 Launcher/V8，不在 Flash 里。** AS2 只负责编译出 DFA 数据并推送，运行期收 `cmdId + cmdName`。→ 新增指令必须走 XML 重新编译，无法热加。
2. **模组只有 3 个，且按「攻击模式 + 兵器动作类型」推断**（`帧计时器.推断动作模组`）。`长枪/手枪/手雷` 模式会落到 `lightWeapon`。→ 技能指令要么写进三个 XML，要么在 AS2 合并进三个模组（推荐后者，避免三份维护）。
3. **`当前搓招名` 只对 `_root.控制目标` 有效**，且 A 输入在 n 帧、cmdId 通常 n+1 帧才到（靠 `bufferTolerance+1` 补偿）。→ 待机态直接读它触发技能，天然晚 1 帧；如果指令以 `A` 结尾，**同一帧普攻已经起来了**。
4. **招式函数是全局 `_root.技能函数.*`，所有单位共用。** 文件名里的「雾人」是历史命名，主角也在用这套。
5. **XML 里的 `<Requirements>` / `<Derivations>` / `<Groups>` 在生产链路里没有消费方**（`requirements` 解析后无人读，`getDerivationMask/getGroupMask` 仅测试用）。→ 能不能放、能派生什么，**只能写在 AS2**。
6. **DFA 命中即触发，不会等更长的序列。** → 指令必须 **prefix-free**：一旦 `↓↘A` 已是「剑气释放」，就不能再指望 `↓↘→A` 之类的同前缀技能指令。
7. **A/B/C 已被占用**：A=普攻、B=跳、C=换弹（长枪/手枪）/挑空（兵器容器）。→ 终结键的选择是整个方案最大的岔路（见 §4）。
8. **`list.xml` 现有 `id="heavyWeapon"` 重复登记**（`heavy_weapon.xml` 与 `cold_arms_weapon.xml`），loader 按 `Set.id` 存 key，后者覆盖前者。动指令表前先确认这是否是有意的。

## 3. 触发位置三选（决定改动面）

| 方案 | 挂载点 | 能力 | 改动面 | 建议 |
| --- | --- | --- | --- | --- |
| **A. 待机/行走轮询** | `主角函数.拳刀行走状态机`（及持枪状态机）在 `动作A` 判定之前 | 站立/行走/跑时输入指令直接放技能 | 小：1 个新函数 + 2 处调用 | **P1 先做这个** |
| **B. 普攻容器内派生** | 兵器/空手容器帧，新增 `技能可派生()` 串（仿 `幻影剑舞可派生`） | 平A 中途搓出技能，最像格斗游戏 | 中：要改 `兵器攻击.xml` / 空手容器 | P2 再上 |
| **C. 帧计时器全局轮询** | `帧计时器.frameUpdate` 每帧对控制目标调一次 | 任何状态都能搓（含受击前、技能中） | 大：状态冲突最多 | 不建议一开始就做 |

> A 方案的天然好处：不进普攻就不会和「A 结尾触发普攻」抢帧；同时 `拳刀行走状态机` 本来就在 `空手站立/行走`、`兵器站立/行走` 下跑，覆盖了绝大多数「想放技能」的时机。

## 4. 触发键决策（唯一需要你拍板的事）

现有事件只有 18 种（8 方向 + A/B/C 按下 + 双击前后 + 4 个 Shift 组合），**没有第 4 个动作键**。

| 选项 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **① 复用 `C_PRESS` 终结** | 技能指令统一 `↓↘→C`、`←↙↓C` 之类 | 零跨层改动 | 长枪/手枪模式 C=换弹，会同时换弹；兵器容器内 C=挑空 |
| **② 复用 `A_PRESS` 终结** | 与普攻同键，靠前缀唯一区分 | 手感最像格斗游戏 | 必须 prefix-free 且要处理「A 已触发普攻」；可用指令空间很窄 |
| **③ 新增第 4 个动作事件（推荐）** | `InputEvent` 加 `D_PRESS`（如 F 之外的技能修饰键，或 A+B 同按合成事件） | 指令空间干净、不抢任何现有键 | 跨层 4 处小改 + 重建 V8 bundle（见 §5-P3）；C# `int.TryParse` 无需改 |

**判断口径**：如果只打算把少数几个技能搓招化，选 ①/②；如果打算把 12 槽技能都做成格斗指令，选 ③。

## 5. 实施步骤

### P0 · 冻结指令设计规则（0.5 天，纯设计）

1. 列出现有全部指令序列（`cold_arms_weapon.xml` 37 条 + `barehand.xml` 7 条 + `light/heavy`），画前缀树。
2. 定技能指令的三条硬规则：
   - **prefix-free**：新指令的任何前缀都不能是已有指令的完整序列；
   - **优先级**：技能指令 `priority` 必须高于同前缀组的普攻指令（TrieDFA 取最高优先级，平局看插入顺序）；
   - **模式白名单**：写明哪些指令只在 `空手/兵器` 可用（避开 C=换弹）。
3. 产出一张「指令 → 技能名 → 可用模式 → 冲突说明」表，作为后续所有改动的唯一真源。

### P1 · 数据层：把技能指令编进 DFA（1 天）

1. 新建 `data/inputCommand/player_skills.xml`（`<CommandSet id="playerSkill">`），一条技能一个 `<Command>`，`action` 写技能名（与 `data/skills/skills.xml` 的 `<Name>` 严格一致，因为 `SkillReleaseGuard` 会校验）。
2. `data/inputCommand/list.xml` 追加 `<Set id="playerSkill" file="data/inputCommand/player_skills.xml"/>`；顺手核对重复 `heavyWeapon`。
3. **合并进三个模组**（关键，别复制三份 XML）：
   在 `帧计时器.构建搓招模组`（或 `CommandConfig.setXMLConfigs` 之后）把 `playerSkill` 的 `commands` 数组 `concat` 进 `barehand / lightWeapon / heavyWeapon` 三份 config，再 `loadConfig + compile`。
4. 验收：启动日志出现 `[CommandConfig] XML 配置已注入: playerSkill` + 三个模组 `Compiled: N commands`，N 比改动前多出技能条数；`D` 消息推送成功。

### P2 · AS2 释放层（1～2 天）

1. 新增 `scripts/逻辑/单位函数/单位函数_主角_技能搓招指令.as`（**UTF-8 带 BOM**，复制现有文件再改名），`#include` 进 `scripts/asLoaderManifest/frame36.as` 的 `f36_8`（`兵器/空手搓招指令` 之后）。
2. 结构完全仿照参考文件（这也是「参考它」的意义）：
   ```
   _root.技能函数.使用<技能名> = function():Number {   // 条件自检 + DFA 优先 + 帧检查兜底
       var 自机 = _parent;
       ... 技能是否装备/等级/MP/冷却 ...
       if (自机.当前搓招名 == "<技能名>") { 释放; return 搓招监控("<技能名>", 1); }
       ... 兜底：直接按键组合 ...
   }
   _root.技能函数.技能搓招 = function():Number {      // 汇总，按优先级 ||
       return 使用A() || 使用B() || ...;
   }
   ```
3. 释放不要自己写一套资源扣除：在 `QuickSkillInputService` 里加一个公开入口
   `releaseBySkillName(unit, skillName)`：扫 `1..12` 找 `_root.快捷技能栏N == skillName` → `getSlotDescriptor(N)` → 复用现有 `releaseSlot(...)`。
   这样 **MP 扣除、`SkillResourceService.begin/finish` 事务、`ManualCooldownService` 冷却、按住锁存语义全部与按数字键完全一致**。
4. 挂载：`主角函数.拳刀行走状态机` 中，在 `if (_parent.动作A)` **之前**插入
   `if (_root.技能函数.技能搓招()) return;`
   命中即 `return`，避免同帧又起普攻。
5. 守卫拒绝要清空状态（参考 `空手搓招指令` 里「诛杀步」的写法）：
   ```
   自机.搓招缓冲已消费 = true;
   自机.当前搓招名 = "";
   ```
   否则指令会被反复重试、把后续输入锁死。
6. 验收：单技能可放；MP 与冷却条与按键释放一致；未装备/等级不足/MP 不足时静默失败且不吞下一步输入。

### P3 · （仅当选 ③）新增第 4 个动作事件（1 天）

| # | 文件 | 改动 |
| --- | --- | --- |
| 1 | `scripts/类定义/org/flashNight/neur/InputCommand/InputEvent.as` | 加常量 `D_PRESS = 18`，`COUNT = 19`，补 `getNames()` / `_nameToId` |
| 2 | `launcher/scripts/src/input-event.ts` | 加 `EV_D_PRESS = 18`（`ALPHABET_SIZE` 目前未被消费，可一并改 19） |
| 3 | `launcher/scripts/src/input-sampler.ts` | 加 `BIT_D = 256` 解码 + `keyD && !prevD` 边沿 |
| 4 | `scripts/通信/通信_fs_帧计时器.as` | mask 打包加 `(Key.isDown(控制对象.D键) ? 256 : 0)` |
| 5 | 重建 `launcher/scripts/dist/hit-number-bundle.js` | `npm run build`（只需 tsc/node，**不需要 .NET**） |

C# 侧**不用改**：`FrameTask.cs` 用 `int.TryParse` 解析 mask，第 9 位天然透传。
验收：`K` 回传的 `typed` 里能出现 D 符号；三个模组指令都能命中。

### P4 · 提示与可视化（0.5 天）

- 已有两套反馈可白拿：`搓招监控` 推 `Ncombo|颜色|DFA 招式名`（刘海）、`FrameTask` 推 `combo|名|typed|hints`（WebView2 overlay）。
- 需要处理的是**噪音**：待机时一按方向就会出现技能 hints。建议在 `buildHints` 或 overlay 侧按 tag/分组过滤（XML `Tags` 有解析、`Groups` 也有，但目前生产链路不消费，需要在 TS 或 AS2 自己补）。

### P5 · 验证与编译（1 天）

**自动**
1. `InputCommandTest` 扩用例：XML → 编译 → 指令唯一性 / 优先级 / 前缀冲突检出。
2. 新增 TestLoader suite：`技能搓招` 命中、守卫拒绝不吞输入、MP 不足不放、未装备不放、冷却中不放。
3. 编译器门：`powershell -ExecutionPolicy Bypass -File scripts/compile_test.ps1 -Target publish -TimeoutSeconds 180`，判据 = 本轮 `compiler_errors.txt` **0 错 0 警** + `asLoader.swf` 刷新。

**手测**

| 场景 | 期望 |
| --- | --- |
| 空手 / 兵器 / 长枪 三模式待机 | 技能指令可放；长枪模式不误触换弹 |
| 连按普攻指令 | 技能指令不会被普攻抢占 |
| 倒地 / 浮空 / 暂停 / 换场景 | 不释放、不残留 `当前搓招名` |
| 多人（`当前玩家总数 > 1`） | 与按键释放行为一致（输入服务本来就有门控） |
| 技能中再输入 | 不重复扣 MP、不打断当前容器 |

## 6. 建议的最小 PoC（半天可跑通）

只做**一个**技能，验证整条链：选一个释放条件最简单、不依赖复杂容器的（如「小跳」或「震地」）。

1. `player_skills.xml` 只写 1 条：`<Command name="震地" action="震地" priority="20"><Sequence><Event>DOWN</Event><Event>UP</Event><Event>C_PRESS</Event></Sequence></Command>`（示例，需先确认 prefix-free）。
2. 合并进三模组 → 编译 → 看 `D` 是否推送、`K` 是否回名。
3. 新文件里只写 `使用震地()` + `技能搓招()` 两段。
4. 挂进 `拳刀行走状态机`，手测空手模式站立按指令能否放、按数字键是否依旧正常。

PoC 通过后再批量扩，不要一上来写 12 条。

## 7. 风险与坑

1. **前缀冲突是头号风险**：DFA 命中即触发，`↓↘A` 与 `↓↘→A` 不可能共存。设计阶段就要把新指令画进同一棵前缀树里检查。
2. **A 结尾指令的 1 帧竞态**：普攻在 A 按下当帧启动，cmdId 下一帧才到。要么让技能指令用 C/新键终结，要么接受「先起普攻再被技能打断」的观感。
3. **模式串味**：`推断动作模组` 对 `长枪/手枪` 落到 `lightWeapon`，意味着这些模式也会收到冷兵器指令。不能让技能指令在这些模式下命中（AS2 里按 `攻击模式` 白名单挡掉）。
4. **XML 门控是装饰性的**：别把「未装备不可放」写在 `<Requirements>` 里，它不会生效。
5. **`搓招监控` 定义在空手文件里**，兵器文件已经在用它。新文件同样依赖它 → include 顺序放在 `f36_8` 内即可（运行期调用，顺序不敏感，但别放到 `f36_8` 之前）。
6. **`.as` 丢 BOM 会被 CS6 静默跳过**（报 0/0 但帧脚本 0 字节）。新文件必须复制现有文件再改名。
7. **`list.xml` 重复 id**：改之前先确认 `cold_arms_weapon.xml` 覆盖 `heavyWeapon` 是有意还是遗留，否则技能指令可能只进了一个模组。
8. **别改 `_root` 一级属性**：新状态放 `_root.技能函数.*` 或 `_root.技能搓招状态` 之类的二级容器（项目约定）。

## 8. 需要你确认的三件事

1. **「主角技能」具体指哪一类？**
   - (a) 12 槽快捷技能（`data/skills/skills.xml`，80 个，走 `QuickSkillInputService`）——本计划主线；
   - (b) 武器主动战技（F 键，`_root.主动战技函数`，走 `WeaponSkillInputService`）——同一套壳，只需把释放调用换成 `releaseUnit`；
   - (c) 两者都要。
2. **终结键**：复用 C / 复用 A / 新增第 4 键（§4）？
3. **触发时机**：只在待机/行走（P1），还是也要普攻中途派生（P2 一起做）？

确认后我按 P1 → P2 逐步实施，每步都给出可回归的单点验证。
