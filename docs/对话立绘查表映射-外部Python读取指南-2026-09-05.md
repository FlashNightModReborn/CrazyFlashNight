# 对话立绘查表映射 — 外部 Python 读取指南

> 2026-09-05 初版。本文描述对话立绘资产（角色 + 情绪 → PNG）的查表协议，供外部 Python 程序直接读图使用。
> 查表语义与 Web 端消费代码 `launcher/web/modules/dialogue/dialogue-view.js`（`buildIndex` / `lookupEntry` / `resolveExpression`）逐条对齐；数据由 `tools/bake-dialogue-portraits.py` 烘焙生成。

## 0. 一句话结论

读 `launcher/web/assets/dialogue-portraits/manifest.json`：
**① 用角色名做归一化查 `entries` → ② 用情绪名按回退链查 `entry.expressions` → ③ 取 `asset.uri`（相对 manifest 所在目录）得到 PNG。**
`external/` 和 `internal/` 都是立绘，区别只是烘焙来源与画布语义（见 §4）。

## 1. 资产总览

目录：`launcher/web/assets/dialogue-portraits/`

| 文件/目录 | 作用 |
| --- | --- |
| `manifest.json` | **查表唯一权威**。schema `cf7-dialogue-portraits-v2` |
| `external/p_*/e_*.png` | 外部角色 SWF 烘焙立绘（68 角色 / 114 表情，画布 1024×576 RGBA） |
| `internal/p_*/e_*.png` | 对话框 UI 内部精灵烘焙立绘（23 角色 / 23 表情，画布 775×1000 RGBA） |
| `report.json` | 烘焙审计报告（`missingFrames` 等），**仅供审计，不参与查表** |

合计 91 个角色、137 个表情。所有 PNG 均为带透明通道的 RGBA。文件名中的 `p_xxx` / `e_xxx` 是内容 hash 目录，**不可猜测、不可枚举推算，必须经 manifest 查表获得**。

## 2. manifest.json 结构

顶层字段：

```jsonc
{
  "schema": "cf7-dialogue-portraits-v2",
  "generatedAt": "2026-08-17T11:03:09+0800",
  "zoom": 1,
  "baseSize": { "width": 1024, "height": 576 },          // external 画布尺寸
  "portraitWindow": {                                     // 按来源(source)取景的裁剪窗口，仅 external 有
    "external-swf": { "x": 30, "y": 30, "width": 880, "height": 375 }
  },
  "heroKeys": ["$PC_CHAR", "主角模板", "玩家"],           // 主角 key（无静态图，见 §3.4）
  "entries": { ... },                                     // 角色 → 条目，查表主体
  "aliases": { "andy law": "Andy Law", ... }              // 顶层别名表：别名 → entries 里的规范 key
}
```

每个 entry（entries 的 value）：

```jsonc
{
  "key": "Andy Law",                        // 规范角色 key
  "aliases": ["andy law", "AndyLaw", ...],  // 条目级别名（与顶层 aliases 内容基本重合）
  "source": "external-swf",                 // 或 "dialogue-ui-sprite"（= internal）
  "sourcePath": "flashswf/portraits/Andy Law.swf",  // 烘焙源（相对项目根），仅供溯源
  "defaultExpression": "普通",
  "expressions": {
    "普通": {
      "uri": "external/p_aecce8196efa/e_7cda072d452b.png",  // 相对 manifest 所在目录
      "width": 1024, "height": 576,         // 该 PNG 画布尺寸
      "frame": 1,                           // 源 SWF 帧号，仅供溯源
      "bounds": { "x": 90, "y": 72, "width": 470, "height": 351 }  // 人物本体在该 PNG 内的包围盒
    },
    "微笑": { ... }, "大笑": { ... }, ...
  }
}
```

情绪（expression）就是 `expressions` 的 key。`普通` 每个角色都有；其他常见值：`微笑`、`悲伤`、`愤怒`、`严肃`、`大笑`、`坏笑`、`无奈`、`惊讶` 等，另有 `XX2` 变体与角色专属表情（如 `黑铁死士`）。**每个角色实际可用的情绪集合以其 `expressions` keys 为准**，不要假设全集。

## 3. 查表算法

### 3.1 角色 key 归一化（对齐 `buildIndex` + `lookupEntry`）

把角色名到 entry 的索引建成“一个 entry 注册三种形式”：原始形式、小写、去所有空白后小写。注册来源有三处，**三处都要注册**：

1. `entries` 的每个原始 key；
2. 该 entry 的 `aliases` 数组；
3. 顶层 `aliases` 映射（别名 → 规范 key，目标存在于 `entries` 时才注册）。

查找时对输入名依次探测：**原始名 → 小写 → 去空白后小写**，任一命中即返回。
输入名先 `trim()`。JS 的 `\s` 含 `\ufeff` 等 Unicode 空白，Python 建议用 `[\s\ufeff]+` 显式匹配（参考实现已含）。中文角色名大小写与空白归一化是恒等变换，原样传入即可命中。

### 3.2 情绪回退链（对齐 `resolveExpression`）

输入情绪 `trim()` 后为空则视为 `普通`。然后依次尝试，取第一个命中：

1. `entry.expressions[情绪]`
2. `entry.expressions["普通"]`
3. `entry.expressions[entry.defaultExpression]`
4. `entry.expressions` 的**第一个**表情（JSON 书写顺序；Python `json.load` 保序，`next(iter(dict))` 即可）

该角色缺这个情绪（例如烘焙时缺帧，见 `report.json` 的 `missingFrames`）时会静默落到回退结果，不报错。

### 3.3 图片路径解析

`asset.uri` 一律是**相对 manifest.json 所在目录**的相对路径（如 `external/p_aecce8196efa/e_7cda072d452b.png`），直接 `portrait_dir / uri` 即可。`asset.width / height` 是该 PNG 的画布尺寸。

### 3.4 主角特例（heroKeys）

`$PC_CHAR`、`主角模板`、`玩家` 这三个 key **不在 `entries` 里**（烘焙脚本按 `SKIP_INTERNAL_KEYS` 排除）。Web 端对主角用 dressup 战斗 rig 实时渲染（`assets/dressup/manifest.json`），**没有静态立绘 PNG**。外部程序遇到这些 key 应显式跳过或走自己的占位逻辑，不要试图查表。

### 3.5 查不到角色时

Web 端显示文本占位框，不落图。资产里有一个真实 entry **`无头像`**（internal，单表情 `普通`），是官方“无头像”占位立绘；外部程序查不到角色时可选用它的图，或自行占位。`无头像` 与“查不到”是两回事：前者是规范条目，能正常查表命中。

### 3.6 游戏数据里的 `角色#情绪` 写法

AS2 对话数据存在 `charBase`（如 `Andy Law#微笑`）中以 `#` 分隔角色与情绪的写法（可多级 `#`，取第一个 `#` 后全部为情绪）。外部程序若直接消费对话文本，可按此拆分；情绪为空按 `普通`。

## 4. external 与 internal 的画布语义（裁剪）

两类 PNG 都是“完整画布 + 人物画在画布中 `bounds` 位置、其余透明”，但取景约定不同：

| | `source: "external-swf"`（external/） | `source: "dialogue-ui-sprite"`（internal/） |
| --- | --- | --- |
| 画布 | 1024×576（源 SWF 舞台） | 775×1000（对话框 UI 精灵画布） |
| 游戏内取景 | 按 `manifest.portraitWindow["external-swf"]` = `{x:30, y:30, w:880, h:375}` 统一裁剪，所有表情共用同一窗口同一缩放 | 无取景窗口，按 `bounds` 底部锚定贴合 |
| 画布杂质 | 遮罩窗口外可能残留美术未精修背景（如 y≈405 以下的“废墟基座”） | 无，画布其余部分纯透明 |
| `bounds` 含义 | 该表情帧人物的原始包围盒 | 人物本体包围盒（实测与 alpha bbox 完全一致） |

外部程序按需求二选一：

- **复刻游戏内对话框观感**（external）：`img.crop((30, 30, 30+880, 30+375))`，即 PIL box `(x, y, x+w, y+h)`；
- **只要人物本体图**：一律按该表情的 `asset.bounds` 裁剪（两类通用），或对 PNG 做 alpha 自动裁边。整图直接用也能看，但 external 可能带窗口外的杂质背景。

## 5. Python 参考实现

依赖仅标准库。直接复制即可用：

```python
# -*- coding: utf-8 -*-
"""CF7 对话立绘查表：角色名 + 情绪 → PNG 路径。
查表语义与 launcher/web/modules/dialogue/dialogue-view.js 对齐，协议见
docs/对话立绘查表映射-外部Python读取指南-2026-09-05.md。"""
import json
import re
from pathlib import Path

PROJECT_ROOT = Path(r"E:\Steam\steamapps\common\CRAZYFLASHER7StandAloneStarter\project\CrazyFlashNight")
PORTRAIT_DIR = PROJECT_ROOT / "launcher" / "web" / "assets" / "dialogue-portraits"
DEFAULT_EXPRESSION = "普通"
_WS_RE = re.compile(r"[\s\ufeff]+")  # 对齐 JS 的 /\s+/g（\s 含 \ufeff）


def _strip_ws(s: str) -> str:
    return _WS_RE.sub("", s)


class DialoguePortraitLookup:
    def __init__(self, portrait_dir: Path = PORTRAIT_DIR):
        self.portrait_dir = Path(portrait_dir)
        self.manifest = json.loads(
            (self.portrait_dir / "manifest.json").read_text(encoding="utf-8"))
        self.entries = self.manifest.get("entries", {})
        self.index = {}

        def register(label, entry):
            if not label:
                return
            self.index[label] = entry
            self.index[label.lower()] = entry
            self.index[_strip_ws(label).lower()] = entry

        for key, entry in self.entries.items():
            register(key, entry)
            for alias in entry.get("aliases") or []:
                register(alias, entry)
        for alias, target in (self.manifest.get("aliases") or {}).items():
            if target in self.entries:
                register(alias, self.entries[target])

    def is_hero(self, name: str) -> bool:
        """主角无静态立绘（Web 端由 dressup rig 实时渲染），应跳过查表。"""
        return str(name).strip() in (self.manifest.get("heroKeys") or [])

    def find_entry(self, name: str):
        name = str(name).strip()
        for probe in (name, name.lower(), _strip_ws(name).lower()):
            entry = self.index.get(probe)
            if entry:
                return entry
        return None

    def find_expression(self, entry: dict, expression: str):
        exprs = entry.get("expressions") or {}
        expression = (str(expression).strip() if expression else "") or DEFAULT_EXPRESSION
        for probe in (expression, DEFAULT_EXPRESSION, entry.get("defaultExpression")):
            if probe and probe in exprs:
                return exprs[probe]
        return next(iter(exprs.values()), None)  # 首个表情（JSON 顺序）

    def resolve(self, name: str, expression: str = DEFAULT_EXPRESSION):
        """返回 dict(png_path, canvas_size, bounds, source, key, expression_used)；
        查不到角色返回 None；主角返回 "hero"（无静态图）。"""
        if self.is_hero(name):
            return "hero"
        entry = self.find_entry(name)
        if entry is None:
            return None
        asset = self.find_expression(entry, expression)
        if asset is None:
            return None
        return {
            "png_path": self.portrait_dir / asset["uri"],
            "canvas_size": (asset.get("width"), asset.get("height")),
            "bounds": asset.get("bounds"),          # 人物本体包围盒，见 §4
            "source": entry.get("source"),          # external-swf / dialogue-ui-sprite
            "key": entry.get("key"),                # 实际命中的规范角色 key
            "expression_used": next(
                (k for k, v in entry.get("expressions", {}).items() if v is asset), None),
        }


if __name__ == "__main__":
    lookup = DialoguePortraitLookup()
    for name, emo in [("Andy Law", "微笑"), ("清水结衣", ""), ("无头像", "普通"),
                      ("不存在的角色", "微笑"), ("玩家", "")]:
        r = lookup.resolve(name, emo)
        print(f"{name!r} + {emo!r} -> {r['png_path'].name if isinstance(r, dict) else r}")
```

预期输出：

```
'Andy Law' + '微笑' -> e_cdd57ddef6ed.png
'清水结衣' + '' -> e_7cda072d452b.png
'无头像' + '普通' -> e_7cda072d452b.png
'不存在的角色' + '微笑' -> None
'玩家' + '' -> hero
```

（`e_7cda072d452b.png` 是“普通”表情的公共 hash 名，多个角色共用属正常现象。）

裁剪人物本体的示例：

```python
from PIL import Image
r = DialoguePortraitLookup().resolve("Andy Law", "微笑")
im = Image.open(r["png_path"])
b = r["bounds"]
face = im.crop((b["x"], b["y"], b["x"] + b["width"], b["y"] + b["height"]))
# external 若要复刻游戏内取景：crop portraitWindow["external-swf"]（见 §4）
```

## 6. 注意事项与陷阱

1. **只查 manifest，不要扫目录**。`p_*`/`e_*` 是内容 hash，文件名与角色/情绪无语义关系。
2. **manifest 是生成物**，由 `tools/bake-dialogue-portraits.py` 从 `flashswf/portraits/*.swf` 与 `flashswf/UI/对话框界面.swf` 烘焙；外部程序发现它缺失/损坏时应报错退出，而不是猜路径。
3. **`report.json` 不是查表输入**。其中 `missingFrames` 列出源 SWF 缺帧而被丢弃的表情（这些情绪在 manifest 里查不到，会走 §3.2 回退链）。
4. **别名归一化三处注册别漏**：只查顶层 `aliases` 或只做 `lower()` 都会漏（例如 `ShopGirl` 这类去空格变体依赖条目级注册 + 去空白探测）。
5. **情绪词表不要硬编码全集**：按目标角色 `expressions` 的 keys 判断；缺情绪时回退链会兜底，不必预检。
6. **`bounds` 是画布内坐标**，原点为 PNG 左上角，单位像素，PIL `crop` 直接可用。
7. manifest 可能随烘焙再生成而更新（新增角色/表情、hash 目录名变化），外部程序每次运行时现读，不要缓存跨版本路径。

## 7. 溯源与权威

- Web 消费端（查表语义的运行时权威）：`launcher/web/modules/dialogue/dialogue-view.js`
- 烘焙脚本（manifest 的生产者）：`tools/bake-dialogue-portraits.py`
- 源资产：`flashswf/portraits/*.swf`（外部角色）、`flashswf/UI/对话框界面.swf`（内置精灵，导出名 `对话框肖像`）
- 相邻但**不同协议**的资产：`assets/enemy-portraits/`（敌人/战队/竞技场，schema 不同）、`assets/shop-portraits/`（商店），各有各的 manifest，不要混用本指南。
