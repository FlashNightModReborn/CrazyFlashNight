### 二次返工：属性 → 子元素

用户追问「`<skill skillReplaceable="false">` 和 `<skill><skillReplaceable>false</skillReplaceable></skill>` 有什么区别，没区别为什么不采用后者」，于是改成**子元素**（共 52 处，20 个文件）。

**查证结论：AS2 侧完全等价。** `XMLParser.parseXMLNodeInner`（`.../gesh/xml/XMLParser.as:55`）两条路径同源：
- 属性：`:71-74` `for (var attr in node.attributes) result[attr] = convertDataTypeFast(attrs[attr])`
- 单文本子节点：`:124-127` `childValue = convertDataTypeFast(cChildren[0].nodeValue)`

`convertDataTypeFast`（`:414`）把 `"false"/"False"/"FALSE"` 都返回布尔 `false` → `=== false` 成立，判定逻辑零改动。

**仅有的两处差异**（都是边界，不适用）：① 属性在子节点循环之前写入 `result`，若属性与子元素**撞名**会被数组提升成 `[属性值, 子元素值]`（`:156-172`）；② 空元素写法 `<skillReplaceable/>` 无文本、无属性 → 解析成 `""` 而不是布尔 `false`。工具侧（`tools/cf7-balance-tool`，fast-xml-parser `ignoreAttributes:false` 默认前缀 `@_`；scanner 用 `@字段名`）两种写法都会各多出一个未注册字段，等价；`weapon-balance.ts` 对 `effectiveSkill` 做 SHA-256 但无落盘基线，不受影响。

**最终形态**：`<skillReplaceable>false</skillReplaceable>` 作为 `<skill>`/`<skill_N>` 的**最后一个子元素**，缩进沿用同级子元素（根层 6 空格、initParam 内 14 空格等）。`<skill>` 原有字段全是子元素（skillname/description/cd/hp/mp/sp），属性形式在本轮之前**全库零先例** —— 这就是采用子元素的原因。

校验：属性残留 0；`git diff --numstat` = **+52 / -0**（纯追加，无 deletions 说明没动其他行、BOM 也没变）；20 个文件中 5 个带 BOM（与 HEAD 一致）、纯 LF；模拟分布 **放行 171 / 锁定 46 / 说明文本 10 / 无战技 1406**，与属性方案逐项相同。

**两个新踩的坑（都是"检查脚本自己错"，不是数据错）**：
1. `git show HEAD:<path>` 传 glob 出来的 **Windows 反斜杠路径会静默返回空**（`capture_output=True` 只看 stdout 就得到"HEAD 无 BOM"的假结论）→ 必须 `f.replace('\\','/')`，并显式判 `if not head: 标记失败` 而不是当成 False。
2. `b.count(b'\r\n') != b.count(b'\n')` 这个式子在**纯 LF 文件上恒为真**（0 != N），被我误当成"CRLF 告警"。判"是否混入 CR"要直接 `count(b'\r')`。

### 追问：不填 `skillReplaceable` 时默认是 true 吗

用户问"用了 `skillReplaceable`，不填时难道默认给了 true 吗"。答：**没有显式默认值，靠严格 `=== false` 判定** —— 缺省解析出来是 `undefined`，`undefined === false` 为假 → 不锁定 → 隐式"可更换"，等价于 `?? true`。这才是"参数可以不填，默认可用"的实现方式（如果反过来用 `!== true` 或 `!x` 判定，缺省就会变成"锁定"，语义就反了）。

核查结论（全仓）：
- 读该键的**只有** `TagManager.isSkillReplaceableLocked()`，三处判定（根 `skill` / `lifecycle.attr_N.skill` / `attr_N.init.initParam.skill_M`）**全部是 `=== false`**，无一处宽松写法
- 数据里**没有任何** `<skillReplaceable>true</skillReplaceable>` 或其他取值，只出现 `false`（负向标记，正例走缺省）
- 边界：被标记元素在父节点下**无重名**（若同名会被 XMLParser 数组提升，标记就丢）—— 全库 0 例；`lifecycle`/`initParam` 下也没有重名 skill 后代
- 隐含风险（**默认放行 = 漏标是静默的**）：将来新增装备若带专属/定制/生命周期战技却忘记加标记，会被静默放开、不会报错。与"默认锁定"相反，这种方案下漏标不自我暴露

**顺手修正注释**（上轮写在属性方案时期，已过期）：`TagManager.as` 特殊槽分支头部注释 + `isSkillReplaceableLocked` 的 javadoc，`EquipmentTestSuite.as` 三条用例的 doc 注释，统一改成子元素形态 `<skillReplaceable>false</skillReplaceable>`，并在判定处点明"必须 `=== false`：undefined 与空元素 `""` 都不算锁定"。`grep 'skillReplaceable="false"' scripts/` 已无残留；两文件 BOM/CRLF/括号/注释块配平均 0 差。
