## 3. 目标单位与注入方式

- 目标：空手主角模板单位（虎妙 / 兵种330 等），`攻击模式 == "空手"`。
- **主注入方式（D9）：装备生命周期内强制迁移 AI**，写在头套的 init 里：
  ```as
  if (自机._name == _root.控制目标) return;          // 玩家永不接管
  if (自机.unitAI != null) 自机.unitAI.destroy();     // 释放旧的（arbiter + 状态机）
  自机.unitAI = new HeroUnarmedAI(自机);              // 我们自己的 AI 对象
  ```
  已核实的四点可行性依据：
  1. `UpdateEventComponent.as:104` 每 4 帧调 `target.unitAI.update()` —— 换对象后照常驱动；
  2. `StaticDeinitializer.as:30` 调 `target.unitAI.destroy()` —— 我们的类实现同名方法即可；
  3. `单位函数_fs_佣兵ai.as:9` 的旧佣兵 AI 发现 `unitAI != null` 就 `stop()` 自退 —— **已被默认 AI 接管，我们替换不会让它复活**；
  4. 外部对 `unitAI` 的唯一读取是诊断埋点，且全部 null 守卫（见第 2 节）。
- **为什么不用 `unitAIType` 兵种注入**：`units.json` 无 `unitAIType` 字段，要支持必须改兵种读取层（他人代码）；且 `UnitAIInitializer`（`ComponentInitializer.as:21`）早于装备生命周期，兵种路径也拿不到"是否戴头套"这个条件。**生命周期方案覆盖面更广**：关卡生成的虎妙与**佣兵里的虎妙**只要戴头套就一律生效。
- **可选保底（零代码，默认不启用）**：关卡 XML `<Parameters>` 写 `unitAIType:HeroUnarmed` 亦可行——`WaveSpawner.as:328-330` 在 `spawnEnemy()` **之前** `cloneParameters`，字段会随 initObject 落到单位上，早于 `UnitAIInitializer`。但此路径依赖 `BaseUnitAI` 新增 case，本次不采用；如需按关卡强制指定 AI（而非按头套），再议。
- 未戴头套 / 玩家控制目标的单位不注入 → 默认 AI 零回归。

## 5. 各模块设计

### 5.1 感知（只读复用）

- 复用 `UnitAIData`：`target / tx / ty / tz / diff_x / diff_z / absdiff_x / absdiff_z / xrange / zrange / xdistance / hp / hpMax / isRigid`（`UnitAIData.as:23-52, 201-210`）。
- 索敌复用现成 `findNearestEnemy(self, 1)` / `findNearestEnemyWithFilter`（`HeroCombatModule.as:400-405`），缓存刷新间隔 = 1 帧（惰性刷新）。
- 群体信息：仅在需要时读 `AIContext.build()` 的 `nearbyCount / encirclement`（**每 16 帧、250px、仅 X 轴**，精度有限，只用于"是否被围"这类粗判断）。
- 已知限制：`zrange` 被 `UnitAIData.as:111` 强制为 10 并回写 `self.y轴攻击范围`；**我们不使用该阈值做攻击判定**，改用自己的 `攻击判定X/Z` 参数（见 5.2）。

### 5.2 移动与 Z 轴精确对齐（D3）

**X 轴**：继续共用 `MovementResolver.applyBoundaryAwareMovement(data, self, wantX, 0)`（wantZ 传 0，绕开它的 Z 输出）。

**Z 轴接管条件**（三条同时满足）：
1. `absdiff_x < 250`（默认，可配）
2. `absdiff_z < 精确对齐阈值`（默认 = **1 个决策窗位移** = 4 × 当前 Z 速度；参数 `精确对齐阈值倍率`，默认 4）
3. 方向为**靠近**（当前 wantZ 与 `diff_z` 同号，不是远离）

**接管后的算法**（在我们的每帧任务里，用现成 `Mover.move2D`）：
```
每帧:
  if (!接管中或暂停或无目标) return;
  var d = target.Z轴坐标 - self.Z轴坐标;      // 用实时坐标，避免 4 帧陈旧
  if (|d| < 0.5) { 停止Z; 接管结束; return; }
  var step = 当前Z速度(跑/走);                 // 每帧位移量
  if (|d| < step) step = |d|;                  // ★末步截断：精确对齐，不再越过
  self.上行 = false; self.下行 = false;        // 交给我们走，避免行走状态机重复位移
  Mover.move2D(self, d > 0 ? "下" : "上", step);
```
- **注册/注销**：`activate()` 内用 `_root.帧计时器.taskManager.addLifecycleTask(this, 标签名, fn, 0, args)`（interval=0 = 每帧），`destroy()` 内 `_root.帧计时器.移除生命周期任务(self, 标签名)`（与 `单位函数_fs_装备生命周期配置.as:173-189` 同款用法）。
- **不接管时**：完全交给原有路径（`上行/下行` + 行走状态机），我们不动。
- 兜底保险（在 Chase 内）：`absdiff_z` 小于一个决策窗位移时切**行走**再靠近（沿用 `HeroCombatModule.as:163-167` 已有的"Z 对齐后才切跑"思路，但只在我们 AI 内生效）。
- 需实机确认：每帧任务与行走状态机的执行顺序，避免"双走"或"漏走"（验收项 V3）。

### 5.3 迂回 / 撤退 / 上下跳（D4）

- **迂回上限**：单次 `Evade` 状态最长 **2~3 秒**（参数 `迂回最长秒数`，默认 2.5），到时无条件回 `Combat`。
- **方向偏好**：撤退/迂回以 **Z 轴（上下）远离**为主，X 轴横向位移设上限（`迂回横向最大位移`，默认 120），避免"越跑越远"。
- **禁止逛街**：`Evade` 期间累计脱离时间超过上限、或目标距离不再缩小，**强制切回 `Combat`**；不给"继续徘徊"的分支。
- **低血脱离**：HP < `低血阈值`(50%) 时允许触发**上下跳**脱离（见 5.7 小跳规则），脱离后按上述限时回战斗。
- **不实现**原 `HeroCombatBehavior` 的 `Retreating`（那是逛街主因）；我们只有短时 `Evade`。

### 5.4 喝药逻辑（独立，D4）

独立模块，不走技能候选（与 `HealExecutor` 思路一致：item 轨独立于 body 轨）：
```
if (血包数量 <= 0) return;
if (状态 == "技能" || 状态 == "战技") return;   // 技能播放中不喝
var ratio = hp / hp满血值;
if (ratio < 0.40) 喝;                          // 必喝
else if (ratio < 0.70) {                       // 想喝：概率随血量线性插值
    var p = (0.70 - ratio) / (0.70 - 0.40);    // 0→1
    if (random() < p) 喝;                      // 越低越容易喝
}
else 不喝;
```
- 调用现成 `AIEnvironment.useHealPack(unitName)`。
- 每次决策（4 帧）最多判定一次，并加最小间隔（默认 1 秒）避免连喝。
- 预期效果：迂回/脱离期间自然把药喝掉。

### 5.5 自研技能脑（D2）

**不复用 ActionArbiter**，我们自己维护：

1. **候选构建**：从 `已学技能表` + 战技条目，按"可用条件"过滤：
   - 距离命中：`距离min ≤ absdiff_x ≤ 距离max`（Z 差另设上限，默认 20）
   - CD：技能级 `上次使用时间 + 冷却*1000 <= nowMs`（沿用 `SkillCandidateStrategy.as:46` 的口径）
   - 状态限制：空中/地面、是否倒地、是否在技能中
   - 特殊规则（5.7）
2. **裁决**：不评分竞赛，用**分层优先级 + 组内随机**：
   - 优先级 0：保命/解围（霸体、躲避类，仅受威胁时）
   - 优先级 1：贴身输出（距离 ≤ 贴身阈值）
   - 优先级 2：中距输出/位移突进
   - 优先级 3：增益（开场或空闲时）
   - 同优先级内**随机取值**（真随机即可）
3. **平A 保底**：贴身（`absdiff_x ≤ 攻击判定X && absdiff_z ≤ 攻击判定Z`）时，先以 **25%** 概率直接出平A（`self.动作A = true`），命中保底就不再走技能裁决。
4. **打断与 commit（不依赖 ActionExecutor）**：
   - 技能/战技播放期间（`self.状态 == "技能" || "战技"`）**不换招**，除非候选来自"优先级 0 保命"或"躲避"。
   - 自维护 `commitUntilFrame`：释放时置 `now + commitFrames`（D10）：
     - **HP ≥ 50%（高血）—— 打完一套**：以动画播完为准（`状态` 回到非技能/战技即视为结束），期间**不接受**同优先级或更低优先级的换招，仅"优先级 0 保命/解围"可强制打断；
     - **HP < 50%（低血）—— 允许被打断**：`commitFrames = 30`（参数 `低血commitFrames`），到点后允许被**更高优先级**技能打断换招（灵活保命），并配 Evade / 上下跳脱离；不是"更坚持"，而是"30 帧后可换"。
   - 同技能 CD 照常生效（防止同一招高频复读）。
5. **释放**：`AIEnvironment.routeSkill(self, 技能名)`（内部 `状态改变("技能")`）；战技走 `_root.战技路由.战技标签跳转_旧(self, 战技名)`（内部 `状态改变("战技")`，`引擎_fs_战技路由.as:34+`）。

## 2026-09-08 补充：实机反馈修复合集（搓招接入 / 平A / 击倒脱困 / 空中出招 / 不可打断）

维护者实机反馈后的五轮修复，全部只动我们自己的 AI 文件（`UnitAI/behavior/HeroUnarmed*` + `九命猫妖.as` + `防具_40+级.xml`），通用层与默认 AI 零改动。

### A. 搓招技能接入（AI 专属触发）

- **机制（已核实全链路）**：玩家搓招 = `InputCommand/CommandDFA` 按键序列（波动拳↓↘A、诛杀步Shift→、燃烧指节→B、能量喷泉↓B、连环踢↑A）→ `_root.技能函数.使用XXX()` 校验被动 → 终点统一是 `_root.空手攻击路由.空手攻击标签跳转(unit, 招式名)`（引擎_fs_空手攻击路由.as:115，非主角-男走 `man.gotoAndPlay`）。
- **AI 侧做法**：跳过输入层，直接调该终点 —— 跳的是同一批招式元件，不碰搓招输入逻辑。条目 `_type:"搓招"` 写进 `已学技能表`。
- **新增 5 条**：连环踢(50–180/拳脚攻击Lv2)、燃烧指节(200–**400**，飞身踢 500 缩 20%/升龙拳Lv1)、波动拳(250–500，照气动波/内力爆发Lv2)、能量喷泉(100–220/裂地拳Lv1+MP≥10%)、诛杀步(200–300 位移突进/拳脚攻击Lv1)。
- **解锁校验**：新增 `_passiveReady(sk)` 复刻玩家侧前置（单位函数_雾人_空手搓招指令.as），被动缺失/未启用/等级不足/MP 不够 → 不进候选。**前提**：虎妙的 `佣兵参数.被动技能` 需含 拳脚攻击/升龙拳/内力爆发/裂地拳 且 `启用=true`，否则这 5 招不放。

### B. 平A 几乎不触发（真根因：一出来就被打断）

平A 不经过 `_release`，`_currentSkillTier` 保持 B 分支复位的 **-1**；下一 tick 状态变"技能"走 `_tryInterrupt`，其换招条件 `(_currentSkillTier < 0 || ...)` 对 -1 恒真 → 任意 tier0 保命技（小跳/闪现/震地）立刻顶掉刚起步的平A。
修复：平A 时置 `自机.虎妙平A中=true`，`_tryInterrupt` 开头守卫 return；tick B 分支（技能收招复位）清标记。三处平A落点（G 保底 / I 兜底 / chaseMeleeTick）均设标记 + 补 `_faceTarget()`。
保底概率 **0.25 → 0.15**（性能考虑），两处同步：`九命猫妖.as` 默认 + `防具_40+级.xml` initParam。

### C. 击倒脱困时序错误（击倒时不跳、倒地后才跳 + 无限小跳）

- **时序**：tick 内 C2（击倒）原本排在 C（空中）**之后**。但破韧/被击飞时「击倒+浮空」是常态（`ImpactStateHandler.as:206-214` AIRBORNE_DOWN：浮空或倒地目标被再击中 → `状态改变("击倒")`）→ 浮空先命中 C 分支并 return，C2 永远走不到；落地后 `倒地=true` 才轮到它。**修复：C2 提到 C 之前**，状态匹配用 `st.indexOf("击倒") > -1`（升空函数.as:176 同口径，防状态名带后缀）。
- **高频**：原条件含 `倒地 == true`，倒地持续期间每 tick 都尝试、小跳 CD(1s) 一到就再放。按维护者澄清**倒地不需要 AI 干预**（有另一套起身方式），C2 只保留击倒；并加边缘检测 `_wasKnockdown` + `自机.虎妙击倒已脱困` 单次标记：CD 未好则下 tick 续试（保证"立刻"），放出即打标记，一次击倒只脱困一次。
- **当前优先级顺序**：A(技能中→先看浮空) → B(复位) → C2(击倒脱困) → C(空中/空手跳) → D 出场保护 → E 喝药 → F 倒地不出招 → G 平A保底15% → H 技能裁决 → I 平A兜底。

### D. 升龙拳后空中技能（踩人/地震/震地）不触发

主动跳跃同样置 `浮空=true`（`PlayerTemplateUnitFixture.as:309`，落地 :96 置 false），但**起跳到落地 `状态` 一直保持"技能"** → 整段空中被 A 分支吃掉走 `_tryInterrupt`；C 分支的 `st=="空手跳"` 对 AI 无效（AI 不按键，走不了 JumpDeriveAction 的 A+B 派生）。
修复：A 分支内加"空中优先" —— 技能播放期间只要离地立刻 `_airSkillTick()`；新增 `_isCurrentAirSkill()` 防反复换招，已出过则静默等落地，空中一律不再走 `_tryInterrupt`。
`_airSkillTick` 全 CD 时**保底强制震地**（忽略 CD，防空中无韧性干等被击倒），仅 MP 不足退化平A。

### E. 铁布衫 / 觉醒霸体 不可打断（表字段驱动）

这两个技能 `优先级:3`，高血时 `minTier=0`、`pick.优先级 < _currentSkillTier` 对任意 tier0 保命技恒真 → 起手即被顶掉；效果在动画尾部结算、且 `单图一次` 标记在释放瞬间已写 → 打断 = 本图永久失去。
- 技能表两条加 **`不可打断:true`**（字段驱动，非硬编码名；后续任何技能照此加即可，兴奋剂/聚气 本次未加）。
- Brain 新增 `_currentSkill:Object`（当前条目引用，`_release`/`_airSkillTick` 释放后赋值，B 分支复位清空）+ `_isNoInterruptSkill()`。
- `_tryInterrupt()` 开头守卫 return；A 分支"空中优先"同样跳过（`!_isNoInterruptSkill() && !_isCurrentAirSkill()`）。
- B 分支异常早退保护：不可打断技能起手后 **<30 帧**就脱离技能状态（多半被外部打断、效果未结算）→ 置 `虎妙已用永久技能[名] = false` 撤销标记，允许重触发（正常打完不受影响，仍只一次）。用 `=false` 而非 `delete`（AS2 delete 对动态属性行为不稳定，判定口径是 `== true`）。
