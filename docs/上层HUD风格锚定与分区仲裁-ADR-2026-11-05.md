**文档角色**：上层常驻 Native HUD（右侧常驻、刘海、左上 Buff／聚焦目标、发布消息、左下事件播报、Combo）视觉锚点、空间分区与消息出口的决策记录和施工入口。实现完成后的当前真相回到 [launcher/README.md](../launcher/README.md) 与对应源码；本文保留裁决、约束和分期。

**最后核对代码基线**：commit `3c2b948d95a489e978b61dbff53cab2c325faf96`（2026-11-05）。

**状态**：决策已获维护者授权（2026-11-05）；P2/P3 初版已构建候选（历史证据见 §7）。同日独立审阅发现的三项边界已修复，当前合同以 §8 为准。维护者已明确回复“验收通过”，授权与治疗数字统一布局共用一批正式发布列车；发布证明和正式入口复验另行记证。

**替代关系**：本文 D1 取代 [NativeHud 常驻 UI 收敛备忘 §3.4](NativeHud常驻UI收敛与地图交互-外部审核备忘-2026-07-10.md#34-视觉语言对齐原版-flash-白框) 的“对齐原版 Flash 白框”视觉裁决。该备忘的几何、路由、状态槽优先级和稳定 bounds 合同继续有效（见 D1 的“保留”）。

## 0. 一页结论

1. **唯一锚点**：底部玩家信息界面的 PlayerInfo SVG 原稿及其 C# 程序化层。上层组件**完整继承**锚点的材质、几何、数字字形和语义色（维护者选择“重”档，不做轻量回声）。
2. **一个原语入口**：`NativeHudTheme` 升级为 v2，提供切角板、斜切标签、技能槽式角标框、分段斜切条和斜体数字等原语；上层 widget 不再各写渐变和边框。
3. **四区分治**：左上只放状态（Buff → 聚焦目标），左下放事件流（结构化事件卡＋fallback 消息），中上为刘海区，右上为操作区。每个区域由**唯一**纯函数仲裁器分配纵向预算。
4. **发布消息降级为 fallback**：`_root.发布消息` → `toast` 这条无结构文本流保留，作为尚未适配消息的兜底出口，并迁到左下事件流上方。凡是能抽象成事件的消息，按领域逐个改为结构化事件进入左下卡片区。左上空间全部让给 Buff 和敌人血条。
5. **Buff 只做基础框**：框体、计时、层数、极性和状态集，不做图标美术。

## 1. 背景：当前问题（以基线源码常量为据）

### 1.1 四套视觉方言

| 方言 | 使用者 | 特征 |
|---|---|---|
| 锚点 A：PlayerInfo 原稿 | 底部 HUD | 炭黑金属板、银色描边加定向明暗、技能栏标签切角与 `////` 斜纹、技能槽四角角标、斜体粗数字、分段斜切 MP／韧性条、青色主强调 |
| B：Flash 白框 | `NativeHudTheme` → 右侧、刘海、SafeExit、Combo、小地图 | 直角、1px 发丝框、左上和右下角标，**禁止切角** |
| C：半转译 | `PlayerHudFocusTargetWidget`、Buff 卡、`LootFeedWidget` | 借用 A 的切角和斜条，但材质常量各自手写 |
| D：未设计 | `ToastWidget`、刘海信息行 | 裸文字或 Flash HTML 色 |

### 1.2 空间碰撞（1024×576 设计坐标）

| 区域 | 碰撞 | 依据 |
|---|---|---|
| 左上 | 发布消息固定在 (5, 50)、宽 285、最多 8 行；聚焦目标顶部 = Buff 内容高 + 4，每行 30＋3。**没有 Buff 时有 2 个目标、或有 1 行 Buff 时有 1 个目标**，就会压到消息 | `ToastWidget.FlashX/Y`、`PlayerHudFocusTargetWidget.BoundsForBuffCount`、`PlayerHudBuffLayout` |

| 中上 | Combo 固定在 y = 32＋2，最大宽 480 居中（x ≈ 272–752）。刘海信息行（如“波次”）同样从 y ≈ 34 开始，每行 20。**两者在战斗中常常同时出现，直接重叠**；刘海展开后信息行下移，Combo 不跟随。480 宽也越过了左上安全列（≤300）和右侧动作行（≥724） | `ComboWidget.ScreenBounds`、`NotchWidget` 高度计算 |

## 2. 决策

### D1 风格锚点与强度

- 锚点是 `launcher/src/Guardian/Hud/PlayerInfo/Assets/*.svg` 与 PlayerHud 程序化层。新视觉以锚点为准，不再以原版 Flash 物品栏白框为准。
- 强度为“重”：上层与底部使用同样的板材渐变、银色描边、切角和斜纹装饰、斜体数字、分段斜切条，不做降权回声。遮挡问题通过空间仲裁和半透明消息行控制，而不是削弱材质。
- **保留**（来自 07-10 备忘）：右侧 `3×50＋3×34 = 252px` 动作行与 32px 行高、刘海安全宽度公式与 400px 上限、状态槽优先级（SafeExit ＞ 可交付 ＞ 普通通知）、刘海动画期间固定最大 bounds、1px 结构线不随常见缩放变粗、语义色只表达语义。
- **废止**：“外层直角、禁止切角”“hover 只提亮角标”这两条视觉限制。外轮廓允许并推荐使用锚点切角。

### D2 Token（P0 阶段从原稿精确提取，下表为初值）

| 类别 | 初值 | 来源 |
|---|---|---|
| 青色强调 | `#5EEFFB`；高亮 `#66FFFF`；深蓝 `#0033CC` | `mp/rim.svg`、`mp/fill.svg` |
| HP | `#FF0000` → `#330000` | `hp/fill.svg` |
| 金属中性 | `#8E8B77`、`#696969`、`#4D4D4D`、`#3E3F31`、`#2A3228` | `mp/backplate.svg` |
| 描边／暗部 | `#31322C`、`#111111`、`#444444`、`#E5E5E5` | `hp/rim.svg`、`mp/fill.svg` |
| 警告／超额 | 琥珀 `(241,201,112)`；珊瑚 `(255,102,86)` | PlayerHud 程序化常量 |
| 货币 | `#FFD700` | 现 `NativeHudTheme.Gold` |
| 数字 | 现役 Aero 矢量数字（`PlayerHudTextCache`／路径字形图集） | PlayerInfo |
| 斜切角度 | ≈12.5°（标签、分隔线与斜体字共用；分段条斜率待 P0 量取） | `mp/rim.svg` 分隔线 dx/dy ≈ 2.45/10.75；`live/skill-label.svg` 字形竖笔 149/706 |
| 动效 | 180／230／360ms 过渡，1300–1500ms 呼吸；遵循 `hudMotionMode` 三档；空闲零重绘 | 玩家 HUD 动效合同 |

### D3 原语（`NativeHudTheme` v2）

`Plate`（切角双层板：银色描边加金属渐变，可选斜纹）、`NotchPlate`（下沿双切角）、`SlantTag`（斜切标签）、`SlotFrame`（四角角标槽）、`SegBar`（分段斜切条，带残影和超额层）、`Numeral`（复用 PlayerInfo 数字栅格）。右侧、刘海、Combo、聚焦目标、Buff 框、消息行和 Loot 卡只调用这些原语。原语和 PlayerHud 共用同一份 token，不复制常量。

### D4 分区

```text
TL 状态列 x 6–300：Buff 栏 → 聚焦目标（仅此二者）
TC 刘海区：刘海 → 持续状态条（波次等）→ Combo（并入同一纵向预算，宽度受刘海安全宽度约束）
TR 操作区：动作行 → 状态槽 → 小地图（沿用 RightHudLayout）
BL 事件流 x 6–300，底边 460 向上：结构化事件卡（下）→ fallback 消息（上）
中央世界保留区：HUD 不进入
底部：PlayerInfo 锚点，不动
```

### D5 仲裁

- `HudZoneLayout` 汇总 TL 实际底边、BL 卡片顶边及刘海最大稳定占位；纯函数决定 fallback 区域和 Combo 顶边。
- TL 采用每页 4 行 Buff 加翻页条、最多 4 个目标的静态预算，保留全部目标；fallback 按剩余高度减行，无空间时隐藏。结构化卡片和 Boss 行不被挤出。
- 刘海展开/收起时一次性预留完整工具栏、子菜单或图表占位。以逐行取整后的实际像素高度换回设计坐标，Combo 顶边向上取整，避免高缩放下的一像素碰撞；动画中不逐帧调整占位。
- xUnit 矩阵覆盖 256 项 Buff 分页＋4 目标、5 卡＋待显示行＋8 消息、刘海展开＋4 信息行＋Combo 命中态，以及 1024×576、1600×900、1920×1080、2560×1440、4:3 与超宽黑边。状态占满导致 fallback 隐藏是明确的低优先级退让，不把它当成缺图。

### D6 消息出口：fallback 与逐项适配

- `toast` 文本流保留为 **fallback**，进入 BL 事件流上方的消息行。Flash HTML 颜色映射到语义色板；可见行数由仲裁器给出，寿命和淡出沿用现合同。
- 新增结构化事件通路，模式参照 `loot` v1：带版本号、闭集 `kind`、严格校验、fail-closed、fire-and-forget；Host 只做投影，不反写游戏状态。迁移**按领域逐项**进行：每完成一个领域，就把该领域的 `_root.发布消息` 调用点改为结构化事件。没有迁移的领域不受影响。
- 分类目标：

| 类别 | 例子 | 唯一出口 |
|---|---|---|
| 关卡／战斗持续状态 | 波次、模式、残敌 | TC 持续状态条 |
| 任务／系统状态 | 任务已达成、存档 | TR 状态槽 |
| 操作回执 | 面板 `Toast.add` | TC 瞬时行；面板隐藏期间的新回执恢复后开始曝光计时 |
| 可事件化的游戏事件 | 装备／单位／拾取／关卡事件 | BL 结构化事件卡（逐项迁入） |
| 物资／击杀 | 获得、失去、击杀 | 现有 Loot 卡，不变 |
| 其他 | 未适配文本 | BL fallback 消息 |

### D7 Buff 基础框（不含图标美术）

26px 技能槽式四角角标框；计时与技能冷却同语言（纵向遮罩＋琥珀分界线），右下角显示剩余秒数；左上角为层数；底部 2px 轨表示极性（青＝增益、珊瑚＝减益、灰＝中性）；临近结束时左上和右下框角红灯（与技能“仅够一次”同语言）；组卡激活时加青色内框；悬停和翻页保持现合同。图标位先用中性占位字形，正式图标留给后续内容专项。

### D8 排除

修改器（尚未迁移）、Buff 图标与文案、`NativeTooltipWidget`（已统一）、对白、NPC 菜单、引导、完整 Web 地图。

## 3. fallback 方案可行性

结论：**可行**，迁移成本按领域线性增长，不需要一次性完成。

- 现状规模：`scripts/**/*.as` 中 `发布消息(` 调用 415 处，其中包含约 50 处测试替身和 `scripts/unused` 下的 18 处。主要分布：装备函数 70、单位函数 67、通信 36、引擎 30、UI 交互 21、场景类 16、Initializer 15、关卡系统 12。生产实现只有一处：`scripts/引擎/引擎_fs_调试模式.as`，向 Host 发 `toast`。
- 有利条件：
  - 入口单一，fallback 不需要改动任何调用点。
  - `loot` v1 已经证明了结构化 fire-and-forget 通路和 Host 只投影的模式。
  - 左下事件卡的视觉和调度已经存在。
- 约束（迁移每个领域时必须处理）：
  - `ServerManager` 的控制台命令通过临时替换 `_root.发布消息` 来收集输出。被迁移的调用若不再经过该函数，控制台结果会变空，所以结构化事件需要保留文本摘要，或由控制台另行订阅。
  - 多个 AS2 测试通过替身断言消息内容（如 DrugProhibition、PickupEffectService、TitaniumSetRuntime），迁移时需同批更新断言。
  - `调试模式` 和 socket 断线时的本地路径必须保留文本回退。
  - 消息文本可能含 Flash HTML（`font color`、`BR`），结构化字段不能把 HTML 直接带进卡片。
  - 迁移会改 AS2，需要按 [AS2 验证](../agentsDoc/testing-guide.md#as2) 用真实 CS6 编译和 focused TestLoader；Host 侧按 [Host 验证](../agentsDoc/testing-guide.md#host)。

## 5. 风险

| 风险 | 缓解 |
|---|---|
| “重”材质铺满上层，遮挡游戏画面 | 分区限制面积；消息行半透明；中央保留区写入仲裁断言 |
| GDI+ 切角和渐变增加合成成本 | 静态部分缓存位图；沿用 33ms 合成上限与空闲零重绘；P4 对比重绘和合成成本 |
| 左上让位后，fallback 消息被事件卡挤压 | fallback 是最低优先级，这是有意的；常见消息逐项结构化后，fallback 流量会下降 |
| 迁移期间新旧消息样式并存 | fallback 行同样使用 D3 原语，只是信息密度不同 |
| Combo 入区后影响搓招可读性 | Combo 命中态在 TC 区享有临时高优先级，P4 人验重点检查 |

## 6. 维护者裁决（2026-11-05）

1. 视觉稿方向接受，强度“重”。
2. 面板 `Toast.add` 操作回执改走刘海临时行（fallback 消息行已过载）。
3. 结构化消息迁移（M*）认可但后置；本轮只做 fallback 转位。
