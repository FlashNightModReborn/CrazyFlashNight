# 统一输入 R12：窗口切换显示连续性

日期：2026-09-24。基线：commit `5c02a103603ca60ccadd62348fe83753838fb0ca` 加 R12 未提交工作树。

## 人验事实与根因

用户反馈 R11 其他未发现明显问题，但缩放、拖拽与前后台切换会短暂露出 AS2 UI。现场 `logs/c1-input-acceptance/20260924-101916-592-c4d0e156` 的 closure 为 `7d8813179ff0da151ef2b6beca7ecc586d420466056504cd8c8def98d4f963d4`，正常退出；8 次 Web 退休／重建，其中6次保留草稿。保留草稿的退休→新端点 boot 完成约 0.49～2.02 秒；这个计时不包括后续页面和草稿恢复。

源码中 `Panels.close()` 清空透明页面，随后 `RootVisualTarget=null` 和控制器 `Close()`；下层 world/HUD 继续合成，直到新的 Web 页面恢复。控制器确切退休是 R11 阻止旧 HWND 键盘尾包跨 epoch 的隔离边界，不能为了消除闪露而撤销。

同一屏幕采样检查实际运行旧 R11 冻结包，57 个样本中17个露出 AS2 心跳色块，按预期失败。它补足了源码判断与用户观察之间的可复现证据，不把普通游戏历史焦点问题统一归因于此。

## 修复边界

- 独立 C1 DComp 树增加模态底层遮挡及置顶的不可交互位图；位图没有 HWND、输入 owner 或取消 ACK。底层覆盖客户区扩展余量，调整大小时不会因旧帧尺寸暴露新的边条；位图随客户区缩放。
- 取消先关闭页面输入并取消组合输入，再抓取仍显示的 Web 画面；提交保留画面后，才执行原页面清理和控制器退休。实际读到的草稿仍由生产页面合同恢复，截图不作为业务数据。
- 新页面恢复草稿后，两个 animation frame 加 WebView CapturePreview 检查完成，且 controller、round、presentation serial 仍匹配，才撤去保留位图并允许后续正常输入准备。旧回调丢弃；预览超时5秒失败关闭准入，迟到结果不揭开画面。
- 模态底层保持到正常关闭页面；截图提交／绘制检查不等于 DWM 扫描输出，也不等于输入获准。[CapturePreview 官方语义](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2.capturepreviewasync)只是捕获 WebView 正显示的图像。API 层结果之外另采实际屏幕像素。
- 新控制器已 boot 但显示未就绪时，仍可恢复已保留草稿。这两项就绪不能混为一谈：中间 v2 候选在“退休→新 boot→再次 cancel”后等待不前，被自动矩阵抓到，v3 明确分开恢复入口与输入准备后通过。失败原始记录保留。

只修改 C1 诊断夹具及其 input-island 页面；不修改正式 Host 输入政策、不重编 AS2、不更新正式 runtime、不访问真实玩家槽位。不构造新的焦点重试循环。

## 人力补验

同一个根目录入口 `C1统一输入验收.bat`，无需 Flash 编译。打开页面并输入已确认草稿，连续拖动／缩放、最大化／还原、切出返回；不应露出下层 AS2。重建期间允许看到静止、不可操作的旧页面；恢复后草稿和新的完整点击正常，取消后立即回到世界。只补这组问题，原通过体验不用重复。

重建耗时、冻结期间的视觉感觉和跨 DPI／真实鼠标拖拽仍由人验决定。本修复解决呈现空档，不宣称控制器重建已零延迟。人验入口、范围和回传说明见[人验指南](../统一输入-C1人力验收-2026-09-24.md)。本轮未提交、推送或发布。
