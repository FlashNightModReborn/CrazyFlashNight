## 产品与界面

角色只有一个暂存区，保存当前库存。可堆叠物品跨来源合并，装备按完整实例保留。已保存库存不占用资产写权限，不因尚未整理而阻止任务、下一关或正常返回；真正结果未定的写仍保留恢复保护。

暂存、战备箱和仓库共用 `InventoryStorageWorkbench`、`OwnedInventoryViewShell`、物品视图、QuickTransfer、拖拽、数量控件、注释绑定与 CSS；左背包、右来源，从“暂存”入口直接进入对应来源。暂存仅允许领取，没有存入、交换、丢弃、制作或战斗消费入口。全局筛选后每页最多 32 项，堆叠数量在共享底栏输入或滑动；“领取”按权威规则自动归位，明确目标格不兼容时保留来源并说明原因，已装备同名药剂可自动补入药剂栏。Ctrl 使用共享快捷转移语义。

批量为“选择本页 → 执行所选”，暂存每批最多 32 条、普通收纳最多 50 条；翻页、筛选或切源清空未提交选择。暂存允许非前缀成功并保留受阻项，普通收纳保留前缀停止语义。当前没有跨页“全部取出”自动循环；关闭后已发出的写仍核对原操作，不重复领取。复用格子在切源时保留注释绑定，只清理退役视图；迟到回包不能污染新来源。

“无限空间”是取消战备箱格子配额的整理体验，不是对无限物理内存、文件大小或保存时间的承诺。列表窗口固定；实际 SOL 字节和完整保存耗时另测，不能以分页测试替代存档规模验证。

## 权威和数据

AS2 是物品与 SOL 权威，Host 校验角色、面板会话和精确协议，Web 提交意图并展示已确认结果。`_saveExt.rewardInbox` v2 包含 `storeId`、`commitRevision`、单调 `sequence`、稳定 `entryId/revision`、完整 BaseItem、最近一次命令回执及旧兼容证明。

库存条目采用替换方式更新：候选拥有独立列表，追加或部分取出替换受影响行，不原地改写已提交行。旧扩展保持为回滚前像；候选中的其他扩展分离复制。完整保存后的私有 retry image 与公开 SO/root 投影仍深度分离。

旧 v1 root 必须先按原 entry/descriptor/lease 身份恢复，继续保持 F1′ 的 N+1 和 terminal ACK；迁移不能抢占活动根事务。旧 batches 在真实迁移提交中移入当前库存后清空，旧 receipt、terminal proof 与有界迁移标记保留。K 店每次最多迁移 40 行，使用当前 token/行指纹，并在同一 full save 清理根和嵌套镜像；最近一批迁移证明保存在 legacy 中，不形成第二个库存。K checkout 和原 legacy receipt 保留既有协议。

查询不调用 ensure/materialize/ACK/advance/save。空角色打开空暂存区也不创建存档扩展。旧物资迁移使用单独写命令；角标始终读已提交前像。只有已知空集合 `{}` 归一为 `[]`；非空坏数据和未知版本不当作空库存吞掉。

## 来源提交

- 任务：先扣交付物，再规划奖励。能放入常规目标的物品直接入库，余量暂存；任务实例、奖励、消耗、经验、等级、技能点与身价合在一次 full save。可靠成功后才播报和执行可选后续任务。
- 关卡：奖励只冻结一次，全部暂存与源 `stashed` 同原返回保存屏障提交。报告只读；旧部分领取存档只迁移剩余量。原 64 项生成上限保留。转场本身仍禁止新的关卡准入，已暂存库存不承担这个门控职责。
- 地图箱：只接管已授权的正网格箱。计划阶段不扣来源，源消费证明与暂存同存；true 后执行实体结束。已物化的旧箱在关闭或清场时保存剩余物品，包括 own-kill 投影失败后的唯一库存。未打开箱和直接地面掉落保留原规则。
- 礼包：单开或 2～64 连开冻结全部随机结果、一次扣包、一次 receipt、一次 fence，停留当前物品页。旧 v1 新开包拒绝，旧 receipt 查询/重放保留。在线补给和旧手雷槽恢复接入同一保管思路。
- 首次可靠入账计获得；暂存转到背包属于内部移动。情报上限计算包含暂存持有量，暂存物资不自动用于交任务、制作或战斗。

地图源使用本次世界代际和箱体序号。现役存档不恢复完整 gameworld/箱体实例，因此重建世界是新代际；当前代际的消费证明随库存落盘，不能只依赖死亡动画标记去重。

## 完整保存与恢复

`beginRewardCommit → commitRewardCandidate` 是唯一候选完整提交路径。来源、目标、进度、回执、SO 数据及顶层镜像属于同一个候选。明确 false 在完整恢复后允许重新执行；未知结果保留原 afterimage、冻结冲突写/换档/其他保存，query/resume 只重新提交相同映像。true 后的通知、对话或 shadow 失败不能回滚资产。

本地成功只代表 SOL 既有合同，不称 shadow 双副本原子提交。v2 档不能裸回退到不识别它的旧程序；回退版本仍须保留 v2 读取、恢复和取出能力。
