## 1. 当前结论与范围

**技术储备足以开工，建议将现场对话迁移与高清立绘治理合并立项、分批交付。** 人形怪战利品头像已经打通最有价值的外观解析与跨端合成链；剩下的主要难点是按句人物与表情、正确取帧、高清交付，以及对白与场景/面板之间的生命周期。它们是可以拆开的工程问题。

**完整落地的难度为中等偏高，收益高。** 仅替换边框、文字和按钮是中等工作量；保留全部现场语义、覆盖动态佣兵和特殊立绘，并在大窗口下稳定展示高清人物，需要跨 AS2、C#、Web 和离线美术管线协同。当前适合先形成清晰分片，待正在进行的宿主施工收束后接续，不宜同时修改同一批焦点与窗口代码。

收益优先级依次是：人物/表情正确且不缺图，大窗口下脸部与线条清楚，现场操作与转场可靠，最后才是下载/磁盘体积与格式收敛。单纯将现有 PNG 改成 WebP 不能补回细节、错误取帧或丢失的表情。

| 技术储备 | 当前可复用内容 | 尚缺的部分 |
| --- | --- | --- |
| 人形外观 | 装备/外观键解析、男女 rig、遮挡与纸娃娃渲染、Host 调度及缓存 | 每句独立对象快照、表情帧、大尺寸输出与缓存分档 |
| Web 对话 | `DialogueView` 已由任务面板消费，具有头像解析、裁切、回放列表 | 现场单句推进、关闭结果、输入消费、场景取消；不能直接把回放列表改名上线 |
| 静态立绘 | 有来源裁决、manifest、透明边界、语义去重与严格文件集合 | 时间轴层级解析、特殊动态立绘、高清内置导出、WebP 交付配置 |
| C# 宿主 | NativeHud 合成、局部命中、字体、图像解码与输入观察 | 对话键盘路由、大面积重绘成本、压隐后恢复语义 |

## 2. 调查方法与覆盖范围

本轮读取生产源码、数据索引、manifest、PNG 的尺寸/alpha 边界以及 SWF 二进制标签，不运行 SWF 动作脚本。调查快照记录 517 个输入文件的 SHA-256、字节数、读前/读后 HEAD 和读取期间变化检查；这为以后复核提供定位依据，不是新的运行时权威清单或发布门。

| 文本来源 | 调查范围 | 对白行数 | 动态人物引用 | 未匹配静态 key 引用 | 表情缺失而落回默认的引用 |
| --- | --- | ---: | ---: | ---: | ---: |
| 普通 NPC | `data/dialogues/list.xml` 引用的 13 个 XML | 693 | 47 | 14 | 30 |
| 任务文本 | `data/task/text/list.xml` 引用的 13 个 JSON | 2,427 | 693 | 3 | 33 |
| 关卡作者数据 | `data/stages` 下 235 个 XML | 420 | 248 | 7 | 3 |

合计 3,540 行。动态指 `$PC_CHAR`、`玩家`、`主角模板`，按当前 manifest 的 `heroKeys` 分类；未匹配与表情回退按现有 Web 的大小写/空白别名规则核对，不能直接等价为旧 Flash 的实际缺图数。关卡部分是作者数据盘点，不证明每个文件正式可达。运行时生成的雇佣兵台词另计。

任务文本另有 96 次配图指令：56 次打开、40 次 `close`，涉及 53 个不同图片路径，本轮检查均存在。单个任务文本数组最长 38 行。关卡数据有 17 行为其他人物指定 `主角模板`，并有 2 个 `FollowingEvent`，均在教学关卡中接 `NextStage`、无参数。不能只测一段普通 NPC 闲聊就宣布全部迁移。

## 3. 现场对白的真实入口与权威

| 入口 | 当前生产路径 | 迁移时必须保留 |
| --- | --- | --- |
| 普通 NPC | `XmlDataLoader.LoadNpcDialogues` → `DataQueryTask` 的 `npc_dialogue` → 地图元件组装 → 菜单选择 → `对话赋值到对话框` | 条件筛选、随机/轮换顺序与 NPC 关联留在现有权威侧；无需再造一份文本数据库 |
| 任务接取/完成 | 任务系统 `SetDialogue`；`TaskRewardCommit.resolved` 在提交后展示完成对白 | 对白是已提交任务的可选展示消费者；展示失败不重放奖励、扣物或自动接取 |
| Web 任务交付 | `TaskPanelService.handleFinish` → `FinishTask` → 上述提交后对白 | 面板已经打开时仍可能发起现场对白，需要显式交接/排队策略 |
| 关卡事件 | `StageEvent.executeDialogue` → `StageInfo.parseSingleDialogue` → `SetDialogue` | 关卡暂停、人物属性投影和后续事件，不能交给 Web 任意调用 |
| 人形佣兵 | `MercSpawner` 按性格和随机池生成台词，行内携真实单位对象 | 按该单位冻结可序列化外观；不能把所有 `主角模板` 都画成当前玩家 |
| 非人形佣兵 | 非人形刷新脚本构造 `堕落城盗贼` 加佣兵名称表情 | 名称实际承担变体选择，缺少该表情会画错角色 |

关键源文件：[对话文本入口](../scripts/展现/UI交互/UI交互_lsy_对话文本.as)、[现场 UI 逻辑](../scripts/展现/UI交互/UI交互_lsy_对话框UI.as)、[关卡事件](../scripts/类定义/org/flashNight/arki/scene/StageEvent.as)、[关卡人物解析](../scripts/类定义/org/flashNight/arki/scene/StageInfo.as)、[任务服务](../scripts/类定义/org/flashNight/arki/task/TaskPanelService.as)、[任务提交](../scripts/类定义/org/flashNight/arki/task/TaskRewardCommit.as)、[佣兵生成](../scripts/类定义/org/flashNight/arki/merc/MercSpawner.as)。

现有数组字段为名称、称号、头像 key、正文、表情、目标对象、配图；现场 UI 还接收可选滤镜风格和参数。`$PC`/`$PC_TITLE`/`$PC_CHAR`、`角色名` 特判、Andy Law 的全局立绘类型后缀、配图延续与 `close` 都是兼容项。普通刷新代码不会自动替每句没有配图的对白清空上一张图。

旧 `对话赋值到对话框` 会追加数组，但把进度重置为 0；覆盖入口会清空重建。迁移不能悄悄将其解释为普通 FIFO。应在 AS2 兼容入口中明确保留或经过调用方核对后收敛。原生输入也要明确“先补全文字，再前进一行”，并处理 Enter 长按与交互键松开条件，避免一次按键既开对白又跳过首句。

## 4. 立绘债务：优先修复取帧与身份

### 4.1 当前产物的量与有效细节

当前 [manifest](../launcher/web/assets/dialogue-portraits/manifest.json) 为 `cf7-dialogue-portraits-v2`，生成时间 `2026-09-11T02:04:08+0800`，包含 94 个条目、140 个表情/PNG。磁盘与 manifest 引用集合一致，没有多余或缺失 PNG；记录了 bounds 的图片与实际 alpha 边界一致。

| 类型/样本 | 整图尺寸 | 实际人物非透明范围或观察 |
| --- | --- | --- |
| 外部产物整体 | 110 张 1024×576、7 张 550×400 | 整图大部分可能是透明区，不能据画布尺寸认定高清 |
| 内置产物整体 | 22 张 775×1000、1 张 851×1000 | 同样需要看人物有效像素 |
| Blue / 普通 | 1024×576 | 可见范围 300×325 |
| Andy Law / 普通 | 1024×576 | 可见范围 473×355 |
| 武器大师 / 普通 | 851×1000 | 可见范围 388×354 |
| 室友 / 普通 | 1024×576 | 全透明；NPC 文本引用 4 次，任务文本引用 7 次 |

140 张中有 115 张非空图的可见高度不足 400 像素。当前 PNG 共 16,829,925 字节，约 16.05 MiB；若同时把所有完整画布解码为 RGBA，理论像素量约 321.66 MiB。这不是实测常驻内存。两边尺寸都翻倍会把解码像素量变成四倍，因此需裁切元数据、按需加载和缓存上限，不能无差别全量预解码。

### 4.2 已定位的时间轴解析问题

[烘焙器的 `timeline_labels_from_swf_xml`](../tools/bake-dialogue-portraits.py) 对 XML 逐行匹配 `FrameLabelTag` 与 `ShowFrameTag`，没有限定主时间轴层级；嵌套 sprite 的帧也累计进了主时间轴帧号。对当前源 SWF 直接解析标签，再与 manifest 的 `frame` 比较，外部 117 个产物中有 44 个同名根标签帧号相符、11 个不相符、62 个没有同名根标签。最后一类包含正常的单帧默认图，不能整体报错。

| 例子 | 当前 manifest 记录帧 | 当前 SWF 同名主时间轴标签帧 |
| --- | ---: | ---: |
| Andy Law / 侦查2 | 47 | 38 |
| Andy Law / 微笑2 | 52 | 43 |
| Andy Law / 严肃2 | 67 | 55 |
| 清水结衣 / 微笑 | 21 | 10 |
| 清水结衣 / 思考 | 51 | 40 |

完整 11 项在调查快照的 `sourceFrameMappingAudit.mismatches`。已有 [report](../launcher/web/assets/dialogue-portraits/report.json) 还列出 13 个 `missingFrames`，其中部分源帧实际存在：清水结衣“比划”位于根帧 46，报告请求帧 58；堕落城盗贼“摇滚学姐/掠夺少女/精锐掠夺少女”位于 19/26/33，报告请求 43/50/70。这是应先修正的取帧定位问题，不能将报告中的缺帧一概归因于原画不存在。

“室友”则有另一层语义：源 SWF 根时间轴只有 1 帧，男女标签在 sprite 6 的第 2/16 帧，嵌套动作引用玩家性别，根动作调用 `初始化人物立绘`。普通静态根帧导出不能等价复现这类运行时选择。需要定义男女变体与选择规则，而不是删除透明图或用另一人物代替。以上证明静态映射及产物缺口；本轮没有在游戏中执行原 SWF，未对每张现有图片作实际表情人验。

### 4.3 素材与数据覆盖缺口

未匹配 key 的完整清单已随快照保存。需要先核对别名/作者数据/可达性，再决定补图：NPC 的 `LSY大人、heeho君、三蝶、排骨、机哥、阿波`；任务的 `heeho君、短波无线电`；关卡的 `Bass、黑铁会盗贼`。例如名称相似的外交部长条目也应查明确切别名，不能自动做模糊匹配。

66 次表情回退既含源 SWF 没有对应表情的情况，也含导出器漏帧。需要分成“源有而漏导”“嵌套动态变体”“作者引用但源无”“允许的默认表情”逐项处置。Andy Law 类型后缀和运行时佣兵不完全体现在这些静态计数中，仍需专项覆盖。

## 5. 高清导出与 WebP 的实施路径

### 5.1 已有抗锯齿，不等于已有高清细节

当前外部导出默认 `zoom=1`、`supersample=3`：先以 3 倍渲染，再以 LANCZOS 缩回 1 倍。外部资源已有抗锯齿处理；问题在于最终仍回到旧尺寸。内置导出未乘 supersample，代码记录过放大时的 `Odd number of new curves!` 异常，本轮没有重试，不能断言现在仍必然失败，也不能假设只改 `zoom` 就能全量成功。

现有 72 个源 SWF 中，13 个含位图定义，59 个含形状且未发现位图定义；这描述源定义，不证明每张最终立绘的渲染构成。Blue 与 Andy Law 样本未发现嵌入位图；The Girl 含 5 张 1672×1980 的 lossless 位图，现有生成器注释说明其舞台放置约 320×369。恢复这类素材应从源重新渲染，不能对低分辨率 PNG 放大后称作恢复原画。

### 5.2 先做有界试导，再决定全量参数

建议用 Blue、The Girl、武器大师、清水结衣、室友，以及男女纸娃娃各一个外观开展小样。覆盖普通矢量、嵌入位图、内置元件、错误取帧、运行时变体和动态表情。

1. **先校准取帧**：按容器读取标签与帧，明确根时间轴、嵌套 sprite、动态变体；固定来源和帧后再比较清晰度。
2. **主路径**：FFDec 对固定根帧/元件按目标尺寸渲染，适量超采样后降到交付档位。画布、显示矩阵、遮罩和透明裁切必须一起计算。
3. **内置放大失败时**：先在隔离临时目录复现单元件问题；比较隔离版本的 FFDec、有限 SVG 导出后栅格化、现有 CS6/JSFL 元件快照路径。SVG 的遮罩/滤镜兼容要逐样验证，不能直接把整套源当作无损 SVG 管线。
4. **嵌入位图**：可以评估提取原位图，但必须恢复原显示矩阵、裁切及图层关系。原画尺寸较大不代表提取后可以直接替换。

本机 `ffdec.jar` 的 `project.properties` 记录版本 21.1.1；当前上游 CLI 文档已有 frame/sprite WebP、SVG 等能力，不能把最新版文档当作本机版本已经具备并验证。[FFDec CLI](https://github.com/jindrapetrik/jpexs-decompiler/wiki/Commandline-arguments) 与[功能限制](https://github.com/jindrapetrik/jpexs-decompiler/wiki/Features)仅提供试验方向。现有 [JSFL host](../tools/cf7-animate-kit/packages/jsfl-host/host/cf7ak-runner.jsfl) 已封装 `exportStagePNG`/`exportFrameSequence`，这不证明高清元件装配已经完成；使用时需待当前 CS6 作业释放，并隔离文档与输出目录。

### 5.3 用屏幕中的人物尺寸决定交付档位

保留项目 1024×576 逻辑画布和统一缩放，不扩大游戏逻辑视野。目标像素应由“人物逻辑高度 × 实际画布到物理像素的缩放”计算，或者在 Web 中由最终 CSS 尺寸乘 DPR 计算；不要两种方法叠乘。

例如人物显示高度为 320 逻辑像素、16:9 视口完整容纳游戏时，1920×1080、2560×1440、3840×2160 分别需要约 600、800、1200 个纵向有效像素。Blue 当前 325 像素高在这些尺寸下都需放大。数值是布局示例，最终档位应按原型实际显示框和目标机器冻结。

建议从普通/高清两个交付档位起步：manifest 保留源画布、裁切矩形和注册点/逻辑显示关系；当前与下一位说话者优先加载，其他按需。小头像、商店卡片、现场立绘各自选择尺寸，避免改一个全局数值使战利品播报也解码大图。

### 5.4 WebP 纳入治理，但由质量试样决定参数

建议以无损 WebP 作为立绘交付的首个候选，PNG 继续可作为无损中间件；只有实际小样证明质量可接受时再讨论有损。`-q 100` 不等于无损，`-lossless` 才明确无损；需要保留全透明像素 RGB 时还需 `-exact`。色彩配置也应显式处理，`cwebp` 默认不复制元数据。[官方编码选项](https://developers.google.com/speed/webp/docs/cwebp)

本机 Pillow 的 WebP 能力可用，报告的 libwebp 为 1.6.0；现役 NativeHud 已通过 [MapHudImageDecoder](../launcher/src/Guardian/Hud/MapHudImageDecoder.cs) 使用 SkiaSharp 解码图片，因此没有新增一套解码栈的必要。但其默认最大边长为 512，现场高清必须传递合适尺寸，不能继承该默认值。本轮没有编码对比或解码基准，不给出项目压缩率、解码提速或最终包体承诺。

格式改动会触及生成器 URI、格式检测、尺寸读取、文件集合检查和消费者缓存；不能只替换后缀。现有六项来源冲突裁决必须保留，[来源策略](../tools/dialogue-portrait-source-review/authority-policy.json)决定用哪套美术，不能因另一套更容易导出就改人物。`bake-shop-portraits.py` 依赖对话 manifest 与生成器摘要；对话生成器改变后，应按既有规则重建商店 provenance/派生 sidecar 并验证，即使商店 PNG 本身未变。

## 6. 动态纸娃娃的复用边界

现役链为 [DollPortraitBakeService](../launcher/src/Guardian/Hud/Loot/DollPortraitBakeService.cs) → `dollBake` → [doll-bake.js](../launcher/web/modules/doll-bake.js) → `MercPortraits`/`DressupDollRenderer` → `doll_bake_result` → `DollBakeTask` 校验和缓存。它已有同键去重、请求归属和失败后重试，适合作为共享服务基础。

现场使用至少需要补齐四件事：

- **按句外观**：`target` 可以是真实佣兵，也可以是 `StageInfo` 从兵种 Type 或独立装备字段生成的对象。AS2 在接受对白时生成脱离 MovieClip 的外观快照，明确性别、脸、发型、遮挡后的部件和实际 keyMap；不跨桥传 MovieClip，也不在 Web 用当前玩家替换所有模板人物。
- **表情**：现有男女基本脸型源各 10 帧，但 dressup manifest 均按 `frame1_plain_stop` 折为 1 帧。首帧 stop 是动画播放约束，不应阻止点选表情标签；新增表情导出与选择映射，不要全局取消静态折叠，让所有皮肤自行播放。
- **姿态与取景**：当前回放为 `battle/空手站立` 胸像，旧现场模板用对话 rig；这涉及武器收纳、身体姿态和脸部尺度。复用渲染器不代表二者视觉等价，第一轮样图应选定现场目标，不在迁移时顺手换人物风格。
- **独立缓存规格**：战利品 key 含外观 tuple，但没有表情、rig、尺寸档位和资源版本，PNG 校验还固定 256×256。高清另设规格/命名空间，复用调度而不破坏图标合同；异步返回必须校验当前对白及外观身份，旧帧不能覆盖新人物。

现有 renderer 已根据最终画布尺寸及 DPR 设置 backing pixels，清晰度问题不能一律归因于未处理高 DPI。还需检查各皮肤源像素、采样方式和有效脸部大小。隐藏 Web 时的首次烘焙、冷缓存切换、断连重试需要候选实测；`TryPostToWeb` 成功仅证明投递，不证明画面已生成。

## 7. 宿主呈现路线与现场生命周期

### 7.1 建议优先验证 NativeHud，保留有界 Web 呈现备选

建议第一份现场原型采用 **C# NativeHud 对话组件 + 共享头像服务**。原因是普通 NPC 对话原本不自动暂停，当前 NPC 菜单也在迁往 NativeHud；已有局部命中、字体和图片解码可以接续。Web 的 `DialogueView` 继续服务回放，人物解析/资产选择应共用数据规则。

这是一项待原型验证的推荐，不是已经证明最低成本。两条路线的真实新增工作如下：

| 路线 | 可复用 | 必须补齐/实测 |
| --- | --- | --- |
| NativeHud | 当前 HUD 窗口、鼠标命中、字体、图片解码；纸娃娃仍可由 Web 合成 | HTML 子集/换行与打字布局、键盘消费、高清图片与宽幅界面的合成开销、暂时压隐后的恢复 |
| 有界 Web 对话呈现 | DOM 排版、现有头像视图与画布、回放相关样式 | 新的现场呈现生命周期、空闲 Web 唤醒、无强制暂停/背景截图的显示路径、焦点和输入边界 |

不能将普通 full panel 作为现场对白的直接替代。[PanelHostController](../launcher/src/Guardian/PanelHostController.cs) 现有打开路径先 `AssertWebPanelPause`，再压隐 HUD、截图背景、`ResumeForPanel`；[WebOverlayForm](../launcher/src/Guardian/WebOverlayForm.cs) 关闭后会隐藏控制器/窗口并冻结 UIData。旧“常驻透明 overlay”的注释不足以证明当前存在一条可直接显示现场对白的空闲路径。

NativeHud 也有实际成本：[NativeHudOverlay](../launcher/src/Guardian/NativeHudOverlay.cs) 按可见组件 bounds 的并集分配合成位图。大立绘和远处其他 HUD 可能把重绘范围扩大；打字期间只在新增字符时重绘，静态停 tick，图像缩放结果和文字排版可缓存。原型需测连续对白、拖动/缩放窗口、同时播报时的 UI 线程耗时，不能只看单张截图。

### 7.2 AS2 保持一个无头现场会话

建议保留 `SetDialogue` 与两个数组入口作兼容门面，把现场状态从可见 MovieClip 中移出：AS2 持有当前句序、追加/覆盖、场景归属、暂停责任与结束回调；C# 管呈现与输入；Web/图片服务管美术合成。Host 仅请求补全文字/下一句/关闭，不接收任意任务结算或关卡事件执行权。

建议 wire 至少能区分当前会话、当前句和所在场景；只引入抵御迟到输入/异步图片所需的身份，不新增持久日志或通用事务体系。配图用明确的 keep/show/clear 语义，路径由本地资源解析器处理。读取对话自身不新增存档写入。

| 情况 | 建议语义 |
| --- | --- |
| 普通 NPC 闲聊 | 保留不额外暂停；完成后关闭其会话与图片 |
| 关卡剧情 | 由入口一次性建立暂停责任；最后一句完成后，由 AS2 消费对应后续事件 |
| Web 面板内触发任务完成对白 | 任务先保持已提交结果；对白交给明确的面板→现场交接或面板内展示/关闭后排队方案，不能让两个可见 UI 各自恢复暂停 |
| 主动关闭 | 与既有“结束对白是否执行后续事件”的产品语义对齐；绑定当前会话，不能把旧关闭落到新会话 |
| 转场/重载 | 取消旧会话并清除旧事件、目标与图片；不把场景清理当作玩家读完 |
| 切出窗口/最小化/临时压隐 | 隐藏、取消未完成手势，保留可恢复的对白进度与暂停责任；不自动结束剧情 |
| 呈现失败 | 不推进未读剧情，不重放已提交奖励；保留可恢复状态并使用既有错误提示/恢复入口 |

当前 NPC/tooltip 的 `INativeHudSuppressionAware` 要求压隐时终结短交互会话，该语义不能直接套到长剧情。键盘需要接入已有输入观察并限定当前窗口/对白消费，不新增另一套全局钩子。

### 7.3 暂停与回调是本次迁移的重点边界

[PauseManager](../scripts/类定义/org/flashNight/arki/pause/PauseManager.as) 的普通 lease 记录 `prevValue`，释放时只比较当前布尔值是否等于自己设置的值；它不是会合并多个暂停所有者的引用计数。静态反例：A 从 false 租用 true，B 随后从 true 租用 true，A 先释放会恢复 false，而 B 仍在。这是源码推导的边界，不是本轮复现的玩家事故。

因此不能只在新对话模块里调用一次 `lease(true)` 就认为问题解决。当前 `StageEvent` 在 `SetDialogue` 之前直接写 true，新模块随后申请 lease 会把 true 记作原值，结束时可能留在暂停。任务面板关闭又可能恢复自己的旧值。施工时应统一入口与交接顺序，保证一个明确的暂停责任，或者在重叠确属必要时单独实现并验证该窄范围的所有权协调。不要顺手改写全项目 PauseManager。

旧 `onClose` 同时清 UI、写 `_root.暂停=false` 并发布 `followingEvent`；[场景转换](../scripts/逻辑/关卡系统/关卡系统_lsy_场景转换.as) 又先调用旧关闭，再清 followingEvent。新入口要分清 finish/cancel，并在发布回调之前取走旧会话事件，防止回调同步打开新对白后又被旧清理覆盖。`StageEvent` 的带参事件还使用 `toArray(...).unshift(...)` 作为 args，需专项核对；本轮找到的两项没有参数，不能据此声称有参执行已验证。

## 8. 建议施工分片与成本判断

下面按可交付边界拆分；研发用时是排期估算，不是本轮实测产能，也不包含等待当前施工、CS6 空档或人类体验验证的时间。两个高风险小样完成前，不应给出小时级承诺。以熟悉本工程的实现者计，完整范围宜按约 **8–15 个有效工程日的量级**预留；自动化协作可能缩短机器工作时间，但内置导出或宿主路线改变也可能扩大范围。

| 批次 | 具体工作与产出 | 完成依据 |
| --- | --- | --- |
| A：先消除两项主要不确定性 | 修正时间轴定位的隔离试验；六类高清小样；NativeHud 现场骨架含中文长句、配图、一次动态换人 | 确认内置高清导出路径、现场呈现路线、目标视口与像素档位；不做全量转换 |
| B：共享人物与资源 | 按句外观快照、表情导出、身份/规格缓存；修补漏导与室友变体；正式高清/WebP manifest 及派生商店闭包 | 人物与表情正确，源/帧/裁切可追溯，旧小头像不退化；资源未命中有明确回退 |
| C：现场对话主链 | AS2 无头门面、C# 呈现、输入、打字与配图；接通普通 NPC、任务和关卡入口 | 追加/覆盖与完成/取消清楚；普通 NPC 不新增暂停；关卡末句事件只执行一次 |
| D：交接与退役 | Web 任务交付重叠、转场/压隐/断线、迟到回包；替换直接 MovieClip 可见性调用；清理 live UI 实例 | 候选真实旅程通过后退役旧可见界面，按实际影响选择编译与部署范围 |

预算受限时优先完成 A+B，先让任务回放等现有消费者受益，再做 C+D。不要先删除旧可见入口、再发现高清内置元件无法导出。相比整套迁移，单独转格式的风险较低，但玩家收益也较低，不应抢占取帧和有效分辨率的优先级。

暂不扩张的范围：所有 SWF 的通用运行时重建、全游戏 PNG 统一转码、整套存档/任务权威迁往 C#、全局暂停管理重写、统一实时动画系统、AI 重绘立绘。当前目标是准确呈现既有美术并替换现场 UI。

## 9. 验证与旧 UI 退役要求

本轮验证只覆盖读取的内容与已有轻量合同测试。施工验证应沿功能风险追加，不建立新的发布收据体系。

| 验证层 | 必须覆盖的有区分度用例 |
| --- | --- |
| 资源/纯逻辑 | 同名根标签不受嵌套帧影响；男女室友；清水结衣/Andy Law 类型2；静态未匹配 key；真实目标与当前玩家不同；表情/尺寸/资源版本变更不会读旧缓存 |
| 展示与输入 | 1024×576 逻辑布局在 1080p/1440p 的实际缩放，必要时加 4K；黑/浅背景 alpha 边缘；中文长句/HTML 子集、打字补全、长按、快速双击、下一句图片冷加载；打字和静态状态的重绘成本 |
| 候选真实旅程 | 普通 NPC→闲聊；人形佣兵不同外观与表情；教学对白→NextStage；NPC 接取/交付→连续任务；Web 面板远程交付→现场对白；配图 show/keep/close；对白中转场、切出/恢复与断线 |
| 任务与存档回归 | 已提交奖励在呈现失败/重试后不会重复；任务结果按既有保存链落盘，重启回读。仅验证本次影响的旅程，不把所有任务系统重跑一遍 |

`TaskPanelService` 仍有保存/恢复 `_root.对话框界面._visible` 的调用；主 XFL 还包含旧实例，并从 `flashswf/UI/对话框界面.swf` 导入。迁移需找到这些实际引用，不能只把 `SetDialogue` 改成发消息后删除 MovieClip。

编译默认先看 asLoader 业务注入；移除主 XFL 实例或导入时才涉及 main。独立 UI XFL 如确实修改，直接指定该 XFL 和对应 SWF 编译；不因旧 UI 曾经存在就无条件重发它。特别是旧对话框 SWF/XFL 仍是内置静态立绘和男性脸型的美术来源：**退役现场运行的 UI，不等于删除美术真源。**

实现时按[迁移护栏](../agentsDoc/as2-web-panel-migration.md)、[测试矩阵](../agentsDoc/testing-guide.md)同步现役协议与入口文档。触及 Launcher 原生源码的正式部署继续走[既有 runtime 流程](runtime-build-reproducibility.md)；工程测试、candidate、promotion 和正式入口业务复验分别记录，不能以本报告或图片检查代替游戏内体验通过。

## 10. 重置后接续工作

1. 先读本报告，再看调查快照的 `inputs` 与当前相关文件差异。优先复核正在施工的 `PanelHostController`、`WebOverlayForm`、`INativeHudWidget`、`NativeMenuBridge`、`MercSpawner` 和 `TaskPanelService`，沿用其最终接口。
2. 从 A 批次启动：先修正并验证取帧解析，再在明确隔离的输出目录做小样。当前 baker 会清空其 output/tmp 目录；未配置候选目录时不可拿生产路径做试验。
3. 以实际小样决定内置导出路线、NativeHud/有界 Web 选择、动态人物姿态和高清档位。可自动完成的调查、生成、检查继续执行；只有美术主观取舍或不可替代的体验判断需要测试员介入。
4. 冻结上述小样结果后进入 B/C/D，并在真正改变现役协议时更新对应 canonical doc。本报告保留研究结论，不承担未来运行时状态清单。
