# 战斗表现迁移契约

**文档角色**：AS2 战斗表现按白名单迁入原生合成器的长期契约；只维护权威、路由、资源与验证边界。<br>
**最后核对代码基线**：commit `fa9f455e74` + 2026-09-26 本地首批子弹原生显示候选；不代表正式 runtime。<br>
**状态**：路线已对齐；BP8 天气与相邻氛围叠加已进入正式 runtime，首批普通/加强普通子弹的原生显示仍处于隔离候选。源码、隔离预览和候选构建各自只证明其对应层级，净性能收益与游戏内观感仍待实测。

## 1. 目标、范围与归属

目标是减少主 Flash 的显示对象、时间轴、显示属性写入和绘制压力，降低战斗峰值；新增通信与原生绘制成本必须计入净收益。C# 管理表现资源和生命周期，具体批量绘制可由现有原生合成器扩展承担，不限定为 C# 逐像素绘制。

首批候选包括小型联弹、常用简单子弹、射线风格、点集/曲线残影和简单打击效果。天气粒子是共享底座的相邻消费者，不因此迁移天气业务权威。人物主体、地图背景、天空拆层、完整 Flash 运行时替代和碰撞/伤害模拟迁移不在默认范围。

运行时允许长期混合：某项没有迁移价值、行为复杂或遮挡要求不适合时，可以继续由 AS2 绘制；不以清空所有 AS2 视觉为完成目标。

分批范围、issue 指针和进展只维护在[路线图](../docs/战斗表现迁移-路线图与验收-2026-09-22.md)。[统一合成与输入计划](../docs/统一合成与输入归属-分阶段施工计划-2026-09-22.md)拥有呈现根、输入归属和源捕获拓扑，本契约是其消费者，不复制协调器或新增一个前景窗口。

相邻职责：UI 面板与 HUD 迁移归 UI 路线；通用美术编辑/装配归[资产装配](art-asset-assembly.md)；战斗数值归玩法；焦点现场归因继续按既有诊断合同。新增跨域能力以主交付物归属，其他位置只链接，不重复建卡。

## 2. 逻辑与表现权威

- AS2 保留碰撞、伤害、穿透、命中顺序、游戏随机数和逻辑生命周期。原生画面不能反向决定伤害或命中。
- 原生可以承担渐隐、闪烁、装饰性抖动、轨迹外观、粒子运动等纯视觉计算。表现随机数独立；迁移不能意外改变战斗随机序列。
- 普通子弹可逐步拆成逻辑对象与显示单元，但不能为复用联弹渲染而继承联弹的分组伤害、衰减或其他玩法语义。
- 帧脚本逐项分类：纯视觉可转动画数据或适配器；播放/生成装饰性效果可转事件；生成真实子弹、改伤害或决定游戏状态的逻辑保留在权威端。不能把导出图片等同于迁移脚本。
- 血液、碎片中的重力和渐隐本身不是禁区；涉及出血来源、地图碰撞、地面贴图或单位引用时，先核清依赖。首批不承诺接管飙血。

## 3. 白名单与显示所有权

白名单的最小判定对象是具体素材、行为适配器和层级要求的组合，不按“所有联弹/所有射线”整体放行。首个实现建立一份机器注册表；AS2 与 Host 使用同一份定义生成或协商结果，不维护两套独立启用清单。

注册表需表达的语义如下；具体文件格式、wire 字段和版本方案由首个实际消费者确定，本文不预建通用协议：

| 语义 | 要解决的问题 |
|---|---|
| 源身份与派生资源版本 | linkage、实际源库与当前派生物是否匹配 |
| 行为适配器与支持范围 | 静态、帧动画、拖尾、变换、混合等能力是否满足 |
| 绘制层与调色参与方式 | 前景是否合法；是否发光；是否参与世界调色 |
| 准入与启用状态 | 未支持、实验、已验收；资源是否已就绪 |
| 缺能力时的处理 | 未创建原生实例前走 AS2；运行中的容量超限和显示端切换须避免隐形伤害或双重绘制 |

第一版优先在实例生成时选定显示端，生命周期内不逐帧来回切换。一次生成只能有一个显示端负责；AS2 原生显示不能先隐藏再假定桥接一定成功。批次/实例身份、创建/更新/销毁的顺序及重复包处理必须明确。

能力缺失、版本不匹配或资源未就绪时，未接管的实例继续走原有 AS2 路径。容量超限或仍在运行的正常显示端切换中，已接管实例须保持可见且只由一个显示端绘制；回交只恢复当前显示状态，不重放伤害或业务事件。暂停恢复、面板遮盖、场景切换和 DRS 交接按这些在线行为验证。

本地启动器与世界合成器是当前游戏会话的必要组成部分。世界合成器致命故障按现有路径结束本次游戏，不要求已接管子弹在裸 Flash 中继续可玩。子弹帧校验/提交失败仅撤销子弹能力，世界画面仍可运行，须把存活弹体交回 Flash。XMLSocket 断开会尝试重连，Ready 态还有 10 秒失联退出看门狗；断线时恢复已隐藏弹体并清理原生帧，避免重连窗口内出现隐形伤害。首批不要求注入式断连后由裸 Flash 完整续玩。

此处的 AS2 单项表现保留不等于允许关闭已发布的整体合成/光照配对。整会话故障继续遵循启动器的退出和重连策略。

## 4. 层级与可读性

已接受小型子弹和适合前景的效果位于人物上方，不以取得主 Flash 透明纹理作为首批前置。大型爆炸、浓烟、依赖人物前后遮挡的视觉首批保留 AS2。

“小型”按实际屏幕覆盖、持续时间、亮度及密集战斗叠加效果判断，不单凭素材尺寸。放大、拖尾、加法混合或高密度发射的变体可以有不同准入结果。

原生世界效果须低于 HUD 和功能面板。现存 AS2 面板若已烘进不透明捕获画面，需用已验证的面板状态抑制/裁切世界表现；不得假定在捕获上方画出的效果自然位于该面板下方。

普通弹体/烟尘与自发光射线/火花可以选择不同的世界调色参与方式。光照、锐化和透明混合顺序以实际合成管线验证；素材更清晰不代表夜间可读性已经通过。

## 5. Flash 真源与导出

遵循各素材现有的唯一编辑源，不擅自将所有库统一迁成某一种格式。XFL/FLA、实际发布 SWF 与派生图片的关系按[资产装配](art-asset-assembly.md)核对；来源不清时先查维护链。

| 素材类型 | 可选派生形式 |
|---|---|
| 简单静态矢量 | SVG、路径或构建/加载时栅格化纹理 |
| 纯视觉逐帧动画 | 透明帧图、图集及帧序列 |
| 简单补间 | 静态资源加变换/透明度曲线 |
| 程序化射线与残影 | 参数、几何与原生算法适配，不强行烘成图片 |
| 未覆盖脚本、滤镜、遮罩与混合 | 显式记录不支持，保留 AS2 或专项转换 |

派生物保留注册点、裁切偏移、原始尺寸、帧时长、循环规则、颜色/alpha 约定、混合方式和必要的嵌套变换。图片正确但元数据缺失仍不算可用。

派生清单绑定源及依赖摘要、导出器/格式版本、产物完整性和体积预算。支持定向再生、过期检查及失败报告；不人工修补派生图集作为第二编辑源。参考[物品素材工作台](../tools/asset-workbench/README.md)和[XFL SVG 导出](../tools/xfl-ui-svg/README.md)，复用经验证能力，不宣称其已支持全部战斗时间轴。

运行时避免逐实例逐帧解析/栅格化 SVG；缓存资源，按有限尺寸档位或合适的几何表达绘制。是否采用图集、路径网格或专用着色器由真实素材和测量决定，不预建完整 Flash 渲染器。

## 6. 数据、时序与性能

共享底座提供世界到呈现空间的变换、几何代次、资源缓存、精灵/线带/曲线绘制、混合、生命周期和场景清理；不复制输入归属或在表现层抢焦。

不同消费者保留不同数据更新方式：子弹接收权威运动状态，射线接收已确定的路径/命中段，残影接收生成时几何；AS2 按帧/批次提交这些紧凑数据。天气在场景、配置或连接状态变化时投影类型、强度与雨花地面带，复用现有 F 包逐帧镜头变换；C# 管理视觉所有权，原生合成器自行生成、更新和批量绘制粒子，不逐粒子桥接。旧 AS2 质量字段为协议兼容而保留，原生忽略该档位并使用固定有界预算。

坐标一致不等于时间一致。必须处理源捕获延迟、几何/相机变化、动态分辨率交接和旧场景包；捕获时间戳不冒认为 AS2 语义帧号。第一版写清采用的同步/插值策略与已知偏差，不能掩盖迟到的命中效果。

战斗绑定表现跟随游戏时间；暂停、慢动作、严重卡顿和恢复的规则显式定义。天气可采用独立的纯视觉更新，但暂停/场景切换仍需受控。不能用无限外推让效果跑在权威对象前面。

天气首批采用程序化世界锚点的装饰粒子，允许与旧 AS2 轨迹、数量和随机数不同；原 AS2 表现受性能限制，不作为新美术目标。雨、雪、沙尘、雾、刀痕及雨花统一按现有 F 包的 `gameworld x/y/scale` 投影到显示视口，平移和缩放跟随世界画面；长地图用边缘回绕维持分布，回绕处对大雾团和刀光淡出，避免整屏固定的贴膜感。不要求与某个 AS2 帧或 WGC 像素帧精确配对。AS2 保留天气选择、场景/夜视/奖励等权威；AS2 只投影天气状态，不创建粒子剪辑、逐帧更新或显示回退。Host 每连接代确认原生能力，场景切换、断连和合成器失效须清旧原生状态；原生不可用时天气会暂时缺失。氛围另由场景预设选择，借 `world_lighting` 投影到 C# 与原生合成器；10 种命名预设和直接 `<Overlay>` 都不再由 AS2 绘制，也不设 AS2 回退。旧 Host 与新 asLoader 必须配对，否则天气和氛围都会缺失。天空盒仍留在 AS2。

F 包镜头与伤害数字共用逐帧入口；天气及氛围的原生镜头状态在该入口直接更新，受场景就绪与会话生命周期门控，不等待 Host UI 定时器。原生 worker 在实际绘制前读取最新镜头，避免在节拍等待前缓存一次旧坐标。静态场景预设仍低频走 `world_lighting`，不把镜头逐帧数据复制进该包。

雨花的落点在撞击时刻确定为世界坐标；显示寿命内只改变弧线尺寸和透明度，镜头投影可以移动其屏幕位置，但雨滴风速不得继续推动已经落地的雨花。雨花仍使用纵深地面带，不声称物体表面碰撞。

**世界表现预设的数据权威**：场景 XML / AS2 选择天气类型、强度和氛围名称；`data/environment/presentation_presets.v1.json` 唯一持有命名氛围与天气的视觉数值，Host 启动时严格加载、记录文件 SHA-256 并投影到 ABI 4 原生画法类型。原生只保留画法公式与 512 粒子的硬安全上限；AS2 不维护氛围名称白名单或默认色。直接 `<Overlay>` 选择自定义画法，命名预设的变体另建目录项。调色、强度、粒子数、速度、尺寸、雨花寿命等数据改动须校验并重启消费者，但不构成二进制源码变化；新增画法或修绘制算法仍走配对候选与独立正式 runtime 发布。无效/缺失目录不得静默使用编译期默认色或恢复 AS2 氛围绘制。作者字段与命令见[世界表现预设](../data/environment/README.md)。

容量、队列、透明覆盖和显存都有边界；降级影响表现，不改变伤害。关键命中提示与装饰性天气使用可区分预算，避免天气耗尽战斗提示预算；具体阈值在首批实测后确定。

比较收益时绑定相同场景/战斗负载、窗口与源渲染分辨率、quality、构建身份和 DRS 策略。记录 AS2 帧耗时分布/停顿、Host CPU、GPU/上传与通信、内存及队列丢弃；不可获得的指标明确缺失。使用斗兽标定等既有入口，固定条件比较净成本，再验证动态调度下的真实体验；不预写 FPS 提升百分比。

## 7. 验证与人类节点

自动验证按实际改动选择[AS2](testing-guide.md#as2)、[Host](testing-guide.md#host)、[跨层](testing-guide.md#cross-layer)和[派生物](testing-guide.md#derived)入口。只改文档执行[文档验证](testing-guide.md#docs)。AS2 实际编译继续要求真实 CS6 与本轮目标证据。

关键反例包括：缺资源/过期派生、重复创建/销毁、旧场景更新、暂停恢复、相机/分辨率变化、队列拥塞、容量超限、正常显示端切换、子弹通道拒绝，以及未白名单实例继续由 AS2 绘制。致命设备故障核对会话结束与清理路径；断连保护核对显示权交还，不要求裸 Flash 续玩。验证伤害/碰撞不变与显示接管分开，不能以截图证明逻辑等价。

密集度验收优先覆盖仍可操作的实战负载：命中与生命周期保持 AS2 权威，弹体不能产生隐形伤害或越过 Web 遮盖，显示权切换不能留下重影。首批 256 上限约束白名单的原生绘制条目：普通弹每枚占 1，枪式联弹每个有效单元体占 1；非白名单仍由 Flash 绘制，联弹组本身不按 1 个条目计。它不是 AS2 的逻辑子弹数上限。跨界与回落可用定向注入验证数量上限、整组回交和单向所有权，不要求维护者在几乎不可操作的真实战斗中凑出 257 个绘制条目。极端超限时先守住桥接/GPU 资源上限与无隐形伤害，容许帧率下降，不承诺流畅；安全验证不代签极端负载下的性能。

人验按可运行批次合并：首个战斗候选看位置/时机/遮挡，新增表现类别看风格和夜间可读性，扩大常用白名单时看密集战斗与切场景。只对具体已测条目记结果，不要求每个静态导出单独打断人类；也不因机器通过便宣称整类视觉已验收。

保留 compiled、candidate_built、candidate_executed、e2e_verified、promoted、standard_entry_verified 的证据边界。本契约、建卡和源码施工均不自动触发正式发布；发布仍需其既有授权与协议。

## 8. 维护方式

契约变化才更新本文；批次范围、结果和下一步更新同一份路线图；实现后资源/能力/白名单具体枚举归机器清单。GitHub Epic 是长期调度入口，子 issue 是有边界的交付包，不复制本文全文。

建卡不授予施工或发布权限。待办加入 Inbox，依赖及共享文件就绪后再转 Ready；完成卡核对证据后关闭并归档，未完成卡保持开放可见。只在真实阻塞存在时使用 blocked-by，不把可并行的素材调查串成全局等待链。
