# 地图内容创作工作台：第二阶段产品与 C# 权威收束

文档角色：第一阶段发布期间的研究结论、第二阶段设计与实现边界。原设计基线：commit `049eb27e3ed6c5ee264d38b29806ad219267e6d2`；2026-09-06 已按“可行，开工”授权在 `3ac9227cbdfdeb6d73f99e408414b03bfc338b5d` 后的工作区实施。

状态：内容工作台、同一 C# 地图域、有限 AS2 桥与消费者切流已完成机器验证，并按维护者对作者流程的反馈修复。2026-09-07 按明确授权完成上游集成、双故障域共识与原子 promotion，当前为 `promoted`；不把作者流程确认或部署本身扩张成全部正式入口业务验收。当前能力／命令见[工作台说明](../tools/map-workbench/README.md)，发布结果与分层证据见[两阶段施工记录](地图工作台与CSharp收束-两阶段施工-2026-09-06.md)和[运行库记录](runtime-build-reproducibility.md)；第一阶段发布不代签本阶段。

## 1. 产品结果

第二阶段不以“把规则搬到 C#”作为完成定义，而要让剧情和美术能完成一条实际内容生产闭环：创建地图页面与地点表现，接入已制作的场景和 NPC，配置剧情条件，比较不同进度下的玩家表现，检查影响，然后应用或撤回。

复用第一阶段的大画布、属性栏、专注模式与真实生产 MapPanel。新增页面、地点、图块、驻点、素材和条件编辑，不再以手改 JSON、JS、AS2 常量或数字 SpriteId 作为正常作者操作。

本阶段不制作任意 Flash 场景、角色动画，也不成为完整任务/对白/商店/战斗单位 IDE。这些本体继续使用既有制作源和 CS6 流程；工作台提供发现、绑定、缺项诊断和打开制作入口。界面必须分别显示“地图展示已配置”和“真实场景 / NPC 接入已就绪”，不能把画了头像称为新增了可对话 NPC。

## 2. 第一阶段冻结时确认的阻碍

| 现役实现 | 创作能力被卡住的原因 | 第二阶段处理 |
| --- | --- | --- |
| C# 定义可容纳多页，但 AS2 catalog、派生器和 HUD mode 固定四页 | GUI 放开第五页后，运行时仍可能拒绝或误分类 | 完整切换消费者后开放结构创建，页分类数据驱动 |
| 8 组地图解锁 switch、头像最小进度 / 基建 OR | 不能表达前期出现、后期迁走及一般组合条件 | C# 同一有界条件求值器，保留现有精确语义 |
| NPC registry 从头像 label / hotspot 派生，别名还有手写副本 | 改显示名、复制头像和改驻点会影响任务身份 | 稳定人物、驻点与表现身份分离 |
| 当前地点按 sceneName / frame 首项命中 | 复制一处表现可能被误当成另一个物理地点 | 一个物理地点可有多处地图表现，路由不重复定义 |
| 预览固定全部解锁、无任务标记 | 作者无法验证剧情进度效果 | 真实只读快照与独立模拟方案，经同一 C# 投影 |
| 旧头像导出器直接覆写 JS，场景导出器固定源 SWF / 页 / SpriteId | 接成按钮会覆盖第一阶段薄适配器并重建第二份真源 | 导出器只产候选图片与来源片段，由统一维护内核应用 |
| 第一阶段单 JSON 原子保存，资源仅检查路径形式 | 导入、删除与多文件任务绑定不能保证一致回退 | 扩展候选、引用检查和可恢复批次应用，不承诺多文件系统原子写 |

以上为冻结版本的阻碍，不是当前实现说明；旧派生器／AS2 catalog／头像 XML 已删除，原文可从上述 Git 基线追溯。当前入口：[C# 领域](../launcher/src/Data/MapDomainService.cs)、[事实桥](../scripts/类定义/org/flashNight/arki/map/MapDomainBridge.as)、[HUD](../scripts/展现/UI交互/UI交互_lsy_UI管理.as)、[作者预览](../launcher/web/modules/map/authoring/preview-host.js)与[素材候选](../launcher/src/Data/MapAssetCandidates.cs)。旧导出命令只保留退役提示，不再覆写生产 JS。

## 3. 作者能力与写入源

### 3.1 页面、地点和表现

- 页面新建、复制、改名、排序、尺寸和背景；对象树管理地点、图块、头像与分层。
- 地点绑定已登记的真实目的场景；图块支持新增、替换、位置、尺寸、层级和一个地点多图块。
- 区分稳定物理 `locationId` 与页面表现 ID。既有 hotspot 身份通过机械映射接入；复制页面默认产生新表现 ID、复用原地点引用，不暗中创建第二个路由。创建新物理地点须选择唯一、已就绪的场景绑定。
- 删除前列出任务端点、NPC 驻点、地图表现和素材引用。存在引用时先停用、解绑或重绑，不静默删掉消费者。

### 3.2 素材与世界接入

- 浏览已有素材、导入图片、从已发布 SWF 定向提取；来源、裁切、透明边缘、像素尺寸和候选对比可见。
- 来源定位使用已发现的元件 / linkage 与源摘要；数字 SpriteId 只能是该摘要下的提取定位信息，不是持久内容身份。
- 校验真实解码、格式、尺寸、大小、路径与来源漂移；重新计算资源清晰度能力，不能让新页沿用旧四页的手写 capability。
- 显示真实场景和 NPC 实例的绑定状态。对已接入的 NPC，统一驻点 presence 结果驱动 AS2 实例启用 / 隐藏；AS2 仍拥有实例化、点击、对话、商店和任务执行。
- 复用物品素材工作台中适用的候选与恢复原语，不把地图伪装为 `icons/dressup` 项目，也不复制一套素材权威。

参考：[素材工作台内核](../tools/asset-workbench/core.py)、[地图 WebP 审计](../tools/audit-map-webp-assets.js)、[取景能力](../launcher/web/modules/map-fit-presets.js)、[真实 NPC 初始化](../scripts/逻辑/关卡系统/关卡系统_lsy_地图元件.as)、[美术装配规范](../agentsDoc/art-asset-assembly.md)。

### 3.3 NPC 与任务端点的唯一权威

| 内容 | 唯一人工真源 | 派生消费者 |
| --- | --- | --- |
| 地图页、地点、表现、地图条件 | 地图定义 | 生产地图、HUD、导航投影 |
| `npcId`、显示名、legacy runtimeName / alias、稳定 `placementId`、驻点 presence | 地图定义中的人物 / 驻点记录 | 头像、真实实例适配、任务端点解析与引用索引 |
| 某任务选择谁接取 / 交付、固定或跟随 | 该任务原有 `data/task/*.json` | 任务索引、TaskPanel、地图标记与现场匹配 |
| 任务前置、目标、对白、奖励、链序号 | 既有任务制作源，不由地图工作台编辑 | 现役 AS2 任务服务与 task catalog |
| 图像字节、来源和共享引用 | 受验证的素材候选 / manifest 闭包 | 图块与头像表现 |

现役任务源是 JSON，`data/task/list.xml` 仅列出 JSON 文件；[TaskDataLoader](../scripts/类定义/org/flashNight/gesh/json/LoadJson/TaskDataLoader.as) 以 `childType:"json"` 合并任务。不能再造地图 `taskBindings` sidecar 与任务源双写。

工作台仅开放已有任务的接取 / 交付端点，展示标题、前置、对白和奖励只读摘要。可采用结构化 `get_endpoint / finish_endpoint`：

- `fixed(npcId, placementId)`：目标固定；驻点当前不存在时解释不可达，不擅自跳到别处。
- `followCurrent(npcId)`：当前事实下必须唯一解析出有效驻点；零个不可达，多个配置冲突，禁止取数组首项。允许同时多驻点的 NPC 默认使用固定端点，或另有明确唯一的跟随组。

迁移同一 role 后，新端点与旧 `*_npc / *_npc_hotspot` 不得同时作为人工真源；旧字段若仍供适配消费者使用，只生成内存投影。已填写 hotspot 的任务保持固定语义。空 hotspot 的历史任务在 [TaskUtil](../scripts/类定义/org/flashNight/arki/task/TaskUtil.as) 中表示任意同名现场可匹配，不能仅因地图只有一个驻点就强制固定；先验证实际 NPC 实例闭包，不能证明等价的保留只读 legacy 适配，在作者实际重绑时明确选择。

按 taskId 由 C# 定位源文件，以白名单字段补丁、原文件摘要和引用校验保存；浏览器不能指定任意路径。任务 ID、前置、条件、奖励、对白、`finish_remote` 和任务增删不在本编辑器范围。

## 4. 剧情条件与预览

条件使用有界结构树：全部满足 / 任一满足；任务链区间、历史任务完成 / 未完成、进行中、已达成交付条件、基建拥有 / 等级，以及现役地图确实依赖的交通工具 / 白名单世界事实。任务、链、物品和世界事实从真实目录选择，提供中文名称；不开放脚本、`eval` 或任意 `_root` 字段。限制深度、叶子数与引用规模，循环和未知事实给出具体错误。

可见、地点可进入、具体关卡可进入、NPC 存在、任务可接取、已达成交付条件、现在可导航必须分开解释。地图入口开放不能绕过关卡 `UnlockCondition / AltUnlockCondition`。

必须保持的现役语义：

- `tasks_finished[id] > 0` 是历史完成，不是待交付任务。
- `task_chains_progress` 是已完成的最大链序号，不代表之前所有任务均完成，也不是“当前做到第 N 个”。
- 任务可交付性来自现役 AS2 `taskCompleteCheck`，涉及物品、剩余关卡和任务条件，不能用 C# 的链进度推算代替。
- 大学外围为“大学 ≥7，或（主线 ≥28 且有摩托车 / 越野车）”；大学内部只看大学 ≥7。自行车不满足第二路径。

证据：[现役任务系统](../scripts/通信/通信_鸡蛋_任务系统.as)、[地图服务](../scripts/类定义/org/flashNight/arki/map/MapPanelService.as)、[关卡解锁](../scripts/通信/通信_鸡蛋_XML与JSON解析.as)。

预览提供两个清晰分区：只读实时事实、命名模拟方案。允许比较两个进度，查看出现 / 隐藏 / 锁定原因、当前值、要求值和命中 OR 分支。模拟方案不改玩家存档；手调主线=30 不能自动制造“历史任务全部完成”。缺少必要事实时显示未知，不默认解锁。生产与预览使用同一 C# 求值器和 MapPanel，不保留独立全解锁假状态作为剧情验收。

呈现层另明确区分“创作视图”和“玩家预览”（2026-09-07 反馈修复）：前者默认开启，允许选择隐藏页／分层并编辑隐藏图块、地点和头像，以文字／虚线标识；后者按所选方案严格隐藏，画布只读，整页隐藏显示原因与切回入口。两者输入是完全相同的 C# 结果，不把显示便利变成业务解锁。未知外观只使用基础图／占位，不能推断动态性别。切换不修改草稿、模拟或导航条件；父层选页只接受明确选择，不再消费迟到重绘中的旧页值。该呈现边界不扩张 Host 命令或游戏事实权威。

## 5. 有限 C# 领域与执行新鲜度

AS2 按定义引用集合提供窄地图事实：链进度、必要任务历史 / 进行中 / 可交付状态、基建、必要交通工具和动态头像事实、当前场景、导航生命周期阻止原因。用事实 revision 与 scene epoch 区分状态变化；内容版本与事实版本分开。

C# 拥有地图规则、身份 / 别名、驻点选择、任务地图端点解析、地点路由资格、当前地点解析与生产投影。AS2 保留任务接取 / 完成、背包与奖励、存档、StageRunSession、场景执行及执行前生命周期检查。不迁移通用 Gameplay StateCore，不在 AS2 留第二份地图规则作 fallback。

导航请求由 C# 基于当前内容和事实重新准入；AS2 消费结果前核对当前会话、内容版本、事实版本、scene epoch 与生命周期条件，陈旧结果拒绝并刷新。任务完成最终仍重查现役任务条件。

结算后前往继续只登记意图，不冻结胜利时的目的地；终态、Web exact close 和 pause lease 释放之后，重新取得事实并选择当前可交付任务。奖励可能让列表靠前的另一个任务刚好达成，旧选址不得覆盖新结果。参考 [StageRunSession](../scripts/类定义/org/flashNight/arki/scene/StageRunSession.as) 的 `requestReturnDeliverableLocal` 与关闭后 fresh resolve。

切流必须覆盖完整地图、TaskPanel 详情 / 前往、HUD `td/tdh/tdn/tdr`、奖励结算后导航、四源当前地点解析 / HUD mode、NPC 接取索引、真实 `NPCTaskCheck` 与 `canAutoAcceptNextAtFinishNpc`。只修红点或任务“前往”不算端点闭环。

## 6. 应用、撤回与退役

继续沿用摘要冲突保护、预览零写、原字节撤回、未知结果查询；扩展到定义、候选素材和必要任务源字段的可恢复批次。完整列出变更文件，提交前校验全引用集合；记录恢复信息后进行逐文件替换，进程启动前检查未完成批次，恢复或拒绝使用不一致内容。不能把普通文件系统多次替换称为多文件原子事务。

撤回只恢复本批确实改动的字节，不覆盖后续独立编辑；新增素材须无剩余引用才可清理，共享素材不随一次撤回被删除。草稿、磁盘已应用内容与当前游戏加载内容分别展示。先采用应用后重启，热更新不是本阶段完成前置。

短期对照只作迁移比对，没有发布权或常驻双权威。消费者全部切换后删除四页白名单、AS2 地图解锁 switch、旧头像求值、重复别名和地图选址；删除无消费者的 `map_catalog.json / task_npc_registry.json / map_hud_data.json` 加载、DataCache、boot query 与生成步骤。仍供事件日志等消费者使用的 `task-catalog.json` 保留，静态端点校验改为调用同一 C# 入口。

当前 Web `evaluateCondition` 仅是 conditionId 到 AS2 unlock flag 的展示映射，不是链进度业务求值器。应按实际职责收束枚举、别名和宽松缺省，保留 renderer、命中和相机。旧素材导出器覆写生产 JS 的模式必须退役。

## 7. 施工切片与验收

先冻结身份、条件、事实 / snapshot 和写入源，再实施可验证切片：

1. C# 领域模型、有限事实桥与 legacy 导入；现有四页逐项等价，不同时改剧情数值。
2. 同一求值器的原因树与双进度预览；随后完整消费者切流及真实 NPC 适配，解除固定页 / 组限制。
3. 页面 / 地点 / 驻点结构操作、任务端点编辑、候选素材与引用检查；UI 和素材子任务可以按不重叠文件并行，领域权威由主责统一。
4. 多文件应用 / 恢复 / 撤回与第五页夹具；删除已切换兼容链，同步 canonical doc、自动化入口与发布闭包。
5. 隔离候选的人类验收与反馈迭代，之后再按授权发布。纯内容应用不另造 runtime 共识门；真正改变 DLL 的第二阶段实现仍走既有双故障域发布。

合并成三次人类产品判断，其余边界由机器覆盖：

- **新地点从制作到玩家入口**：建立第五页、导入图块、接入已发布且唯一登记的场景，配置两条剧情开放路径；比较早期锁定和后期可达。应用后完整地图、小地图和普通导航一致，具体关卡另锁时原因清楚。
- **同一 NPC 随剧情迁移**：A/B 驻点互斥，后期头像变化；一项任务固定驻点、一项跟随当前驻点。真实场景实例、接取 / 交付、红点、任务前往与 HUD 一致；固定目标消失不误跳。同轮保留武器大师同时两驻点与历史别名行为。
- **复制内容并安全撤回**：复用部分素材、新增部分素材，自动重建表现 ID；删除被任务引用的地点给出具体影响。应用重启后撤回精确恢复，共享素材和后续独立编辑不丢失。

机器专项另覆盖大学 OR 边界、未知事实、零个 / 多个跟随驻点、别名、当前地点歧义、跨批次冲突、导入失败与中断恢复，以及“领取奖励使 A 新达成，结算关闭后按新事实选 A，旧 B 结果迟到被拒绝”。这些是功能验证，不是新增人类回执或通用发布状态机。研究时未运行这些旅程；实施后的机器结果另记入施工记录，仍不得外推三条真实游戏旅程已经通过。
