## 结论

可以扩大，但应以“装备贡献 → 单位内归并 → 有限实际灯”的方式接入。五件蓝晶是五个可独立卸载的贡献者，通常只输出一盏身体柔光；兵器按持用、展开和既有激活窗口决定贡献。刀光轨迹本身继续由原渲染器绘制，不逐段生成灯。

保留当前手电的方向和复合柔光。近身光只有空间范围接近、颜色和用途兼容时才合并；同区弱装饰光可由更强的手电近身光覆盖。异色且位置不同的光剑灯可以保留一个独立小灯，不能为了压成一条记录而把白手电染成蓝色、把整个角色周围扩大成巨型光球。

本轮不修改装备数据、AS2/native 实现、SWF、开发候选或正式 runtime，也不改变插件防御数值。以下是可供下一轮施工使用的建议。

## 建议接入顺序

| 分组 | 代表装备 | 接入建议与真实条件 |
|---|---|---|
| 首批身体柔光 | 蓝晶、次品蓝晶五件 | 作为同单位的蓝晶贡献组。两套男女小腿都有 `#5264B0` glow；其他四部位不能声称都已有发光滤镜。按在装贡献归并，不凭空新增必须凑齐三件/五件的门槛；强度和范围有上限 |
| 首批持用兵器 | 绝地武士佩剑、审判日夜闪、十文字光剑、血色光剑天秤 | 持用且实际发光部分可见时提供局部光，优先复用刀口采样；收起/隐藏时清除。激光剑同属此类，但先确定重名素材的实际 owner |
| 状态适配 | 主唱光剑（展示名吟唱圣光）、光剑天秤、电感切割刃、光刀狮子、光刃摩羯 | 读取现有展开、形态、负载或激活窗口；不能全部改成常亮。主唱的话筒形态不套用光剑灯；天秤的默认/CD、攻势、守御各自有刀光条件；狮子在 WeaponSkill 后启用，摩羯沿用 150 计数窗口 |
| 次批素材复核 | 热能武士刀、冰魄神斩、月光大剑、诛神剑、应援棒；先进防护服、自由骑士、黑犀、芬里尔等 | 已发现相应彩色滤镜或动画信号；先判断发光区域、当前帧和实际素材来源，再选常驻或条件灯，不以题材名称直接放行 |
| 不自动接入 | 普通刀光/速度拖影、黑色或白色描边、夜视镜、只有描述命中的装备 | 保留其现有表现；环境照明须另外有明确来源与状态依据 |

蓝晶鞋的素材里还保留 `onEnterFrame` 发射“子弹化水晶”的业务脚本。新增灯光应与之隔离，不能为了做光源顺手删除、迁走或改写这些攻击行为。

血色光剑虽然没有 GlowFilter 扫描命中，但[现役外观代码](../../scripts/逻辑/装备函数/血色光剑天秤.as)明确控制 `fxGrip/fxBreath/fxFlow/fxBurst`：握柄光跟随可见性，呼吸/流光跟随主武器持用，爆发另有短时条件。它不属于“只有猩红天秤战技期间才发光”；小范围照明应读取这些现有条件。绝地武士佩剑同样不能只因零 GlowFilter 就排除，仍需核对等离子剑身和现有粉光刀光的实际显示。

## 三层设计

```mermaid
flowchart LR
    A[防具与兵器生命周期贡献] --> B[AS2 按单位和光源用途归并]
    B --> C[身体柔光与独立方向源]
    C --> D[稳定的可见灯预算]
    D --> E[原生局部光场]
```

### 贡献层：装备只申报自己的光

每个来源记录装备实例、槽位、独立句柄、颜色/半径/强度配置、激活规则及可复用锚点。换装注销自己的句柄，不关闭整个单位的光组；新对象即使复用原 MovieClip 路径，也必须取得新 actor 身份。

身体装甲检查在装、存活、可见与场景；兵器再检查持用、展开与激活状态。新的照明生命周期可标为 `independent`，仅观察既有状态，不注册战技或写回玩法字段。光剑天秤原来的 `bound` 生命周期函数保持原义，不能借新光效解除战技竞争条件。闪避加成继续只归战术手电插件。

### 归并层：同一单位、同一区域、相容颜色

建议每单位默认一盏身体光，持用兵器在需要时增加至多一盏局部光；手电和激光按真实发射器保留方向。双持的方向不能平均成角色正前方，也不跨单位合并。

- 同色装甲取最强贡献作为基础，其余只作小幅、有上限的补充；半径按覆盖上限或最大有效半径确定，不随件数相加。五件蓝晶不会变成五倍亮度、五倍范围。
- 聚合 id 绑定 scene/actor 身份与光源角色，不绑定当前最强的一件装备。摘下一件后更新原记录，避免删除重建导致闪烁。
- 同区不同颜色默认让主要光源决定色调，弱贡献受上限约束；蓝、红、白无条件平均容易失去各自辨识度。异色重要光源可以保留独立小灯，合并数量不作为硬目标。
- 当前手电的近身和前照共用 RGB。最低风险路线保留该复合记录：当它足以覆盖身体区域时，抑制重复的弱装饰照明，保留装备本身的 Flash 辉光；不能只改 RGB 就宣称合并了蓝甲和白手电。需要多色复合时再明确扩展记录和 shader。
- 白名单发光兵器的刀光只产生有限的短时强度/范围包络，复用当前武器源；一段攻击的多个刀口和历史残影不各建一盏灯。普通速度残影不参与。

### 预算层：优先级加稳定持有

先保持当前总上限 16。当前 Host 只保留已有常驻 id、新 id 按数字填空，并没有玩家/远近优先级；大量 NPC 装饰灯提前占满后，玩家新拿出的功能灯会进不来。

建议顺序为玩家有效光源、近处有效功能光源、可见装饰光、远处装饰光；枪火使用余量。高优先级常驻灯可以替换低优先级装饰灯；同级使用距离迟滞和最短驻留，避免排序微变就逐帧换灯。死亡、卸载、断连和场景失效立即撤销，不受驻留时间拖延。

最低改动方案是在 AS2 聚合器输出前选择本 tick 的至多 16 条完整快照记录：未被选中的旧 id 从快照缺席，Host 现有逐出/保槽逻辑即可处理高优先级替换，不必仅为优先级再增加 wire 字段。候选选择与距离分数须单次计算/缓存，不能在每个来源回调里重复排序；被预裁剪数量在 AS2 计数，不能期待 Host 统计尚未收到的记录。

装饰灯可设置软配额，防止铺满场景并吃尽枪火余量；具体数字由人形 NPC 密度和压测决定，暂不把所有常驻容量硬切成新的固定配额。暂停冻结既有显示状态，移动锚点仍按游戏视觉 tick 更新，不能把位置更新降到每秒数次而产生追赶感。

## 性能与协议边界

现役 native 在 256×144 HDR 光场中使用一次 `Draw(lightCount*6,0)` 绘制所有局部灯，随后世界/天气/弹体共享采样。16 盏并非 16 次 drawcall。合并的主要收益是减少来源遍历、坐标转换、字符串/解析、GPU 记录和重叠光场覆盖；不能在没有压测的情况下承诺 FPS 增幅。

AS2 当前 `owns()`、`ownsNear()` 和完整快照存在重复扫描；扩展到每个身体部件都会放大成本。应把贡献归属、参数归并和插件签名判断放在装备/状态变化或一次 tick 缓存中；每个活跃组只更新必要坐标并发送一次聚合记录，复用现有刀口采样与 scratch 对象。不要每帧扫描 MovieClip 树、解析 XML、逐残影调用 getBounds 或创建临时数组。

当前 `EquipmentLightBridge.drawn()` 只接受长枪/手枪槽；初始化器把非 flashlight 分支当成 laser；Host 的 `l` 记录严格要求 kind=1..2。发光防具和兵器不能只补 XML 就生效。

最低复杂度扩展是新增明确的常驻径向类型与来源/预算语义、协商新能力；Host 可以将其映射到现有 native kind=0 的软径向绘制，同时由常驻快照持有生命周期，不能经枪火出生事件反复续命。在仍使用原 16-float 布局和 kind=0 绘制语义的前提下，native ABI 9 不必因新增 AS2/Host 来源类型而机械升级。若要独立的近身 RGB、不同衰减或新几何，再按实际 ABI 变更升级；不可让旧 native 将新类型误读成激光。

## 施工与验证建议

1. 先完成单位贡献组、径向常驻类型与稳定预算，接蓝晶/次品蓝晶及一把单色光剑，保持第三轮手电原有观感。
2. 再接已确认素材 owner 的持用光剑；对天秤、主唱、电感和激活窗口兵器分别写只读状态适配器。
3. 最后扩入第二批素材。没有明确发光部位、帧状态或真实装载来源的条目保持待查，不由自动扫描直接改成白名单。

最小验证覆盖：五件装甲只输出一个身体组；混穿/逐件卸装不叠亮或闪烁；白手电与蓝甲/红剑不串色；不同形态、收枪、暂停、死亡与同路径重建及时正确清理；16 灯饱和时玩家后来进入仍能取得优先席位、枪火不逐帧抢常驻席位；刀光段数增加不等于灯数增加。再测 AS2 每帧耗时、传输量、光场覆盖和实际候选中的走位/挥刀观感。

资产摸底和简单单色接入难度中等；单位级归并、预算与身份清理难度中等偏高；多形态、旧时间轴业务和多色复合是主要复杂部分。SWE-2 适合并行识别、提炼状态门和独立反审，共享聚合器与预算策略应由主控集中实现和验证。
