# 打桩机分层拟合

本目录记录火药燃气液压打桩机及其重锤进阶形态的数值方法与当前玩法裁定。运行数值唯一真源为 [物品 XML](../../../../data/items/武器_长枪_近战.xml)，预算裁定在 [design.json](design.json)，[model.ts](model.ts) 读取现役数据并复用工作簿对应的枪械、刀公式。维护者已于 2026-10-02 确认既有机制的当前实战表现无问题；本轮收口另将运行倍率取整、接通进阶外观并整理说明。公式报告仍保留新增机制未纳入基础 DPS 预算的边界。

## 分层拟合

维护者于 2026-10-02 指定：原版 35 级、80 kg，特殊玩法隐藏 1 层＋金币高价 2 层，共 3 层；重锤版 55 级、150 kg，共 5 层，定位毕业武器。两者使用榴弹弹药，枪械面板都按 0 加权计算。重锤使用专属进阶材料；正常获取途径已按维护者决定冷藏，现阶段保留为修改器可取得的武器。此为打桩机专项裁定，不把“金币高价 2 层”扩展成全部武器的通则。

1. 枪械使用实际重量、弹容、间隔、冲击和榴弹弹药价格，在 0 层下求解 `averageDPS ≈ weightedDPS`。不先扣掉防护重量，也不把总 3／5 层再乘进枪伤。
2. 防护预算为刀页同等级、同重量下的锋利度差：`刀(totalLayers) - 刀(0)`。物理刀公式为 `level×10×1.25^layers + weight×3`，相减后重量项抵消。80／150 kg 已进入枪械及负重计算，不再重复转让一次。
3. 依 `刀!C10/J18`，1 锋利度可换 1.5 防御或 3 HP。首轮将差额七成用于防御、三成用于 HP，分别取最近 5 点，并报告折算残差；可在总预算内更换分配。

原版锋利度差 333.59375，落为 350 防御＋300 HP，回算 333.33333。重锤差 1128.466796875，落为 1185 防御＋1015 HP，回算 1128.33333。伤害、数值与舍入对账均由模型重新读取 XML；这里的两组数用于解释首轮裁定，不供运行时加载。

`impact=1` 以及 `accuracy/evasion/toughness=300` 是维护者明确保留的击倒、必杀与跳弹定位。按该输入复算，基础面板分别取 8270／17420。重锤的零层刀锋利度原为 1000；装甲/立场机制支付半层，免费碎石再支付半层，独立按 `55×10×1.25^-1+150×3=890` 写入 `bladePower`，再走装备强化倍率和常规全身刀锋利度加成，不再乘枪威力或继承枪伤配件。斩杀、吸血、毒、击溃、暴击与命中来自宿主已结算的战斗词条，经兵器槽及本次刀技子弹传递；不重新应用插件，也不重复加生命/防御。瞬步斩、凶斩等仍走现役刀技链。双方 `<balance>` 保持 `unresolved`、隐藏玩家平衡摘要。v1 台账中的 `weightLayers=0` 表示进入基础枪械公式的层数，总层、防护转让及新增机制由本专项模型补充。

## 原版近战与换弹代偿

维护者于 2026-10-03 授权原版加入普通狂野锤，并将两形态的普通主仓换弹延迟设为 `+200%`。原版按刀页 0 层得到 `35×10+80×3=590` 物理锋利度，沿常规强化倍率和全身刀锋利度加成；只在真实刀槽为空时借用当前长枪。原版保留旧枪械开火动画，刀装扮独立旋转，并在实体前端建立三个有面积的刀口区域；不接入重锤的蓄压、装甲破击、碎石、燃料或专属战技。两种锤共用已结算词条投影，真实冷兵器不受影响。

`reloadPenalty=200` 在生产 `ReloadManager` 中成为基础 100 加 200，即无快速换弹时普通主仓动画约为原来的 3 倍。枪械师仍按原有节省帧数比例缩减主仓负担；重锤联动补燃料在主仓负担之后加 25，单独补燃料仍使用原有 25。翻滚换弹继续调用 `SkillReloadCore.reloadAllWeapons`，照常消耗弹药储备并补弹，不进入普通换弹慢放路径。

此代偿用于限制高重量枪模式持续输出、提高切锤的价值。8270／17420 枪械面板和重锤运行倍率不因换弹变慢而上调；专项报告单列真实换弹负担与工作簿固定 900 ms 假设。公式 DPS 因而是同口径预算参照，不能当作新增换弹惩罚后的实战 DPS。隔离夹具验证成本和路径；维护者于2026-10-03确认本轮可行并授权发布，这不扩张为全部配装或设备的穷尽验收。正式运行库与入口结论见[runtime发布记录](../../../../docs/runtime-build-reproducibility.md)。

## 时序参照与运行三档

同一枪械预算反推的精确倍率保留为比较参照。面板取最近 10 点，参照倍率保留 6 位小数；运行时只读 XML 中已授权的易读档位：N1 为 1.5，S1 为 1.5／2／3。取整不修改默认工作簿公式，也不把差值隐藏为新的公式解。

- N1：计数 30 帧＋准备动作 15 帧（首帧重合），共 44 帧。射后 60 帧间隔与 56 帧回收取较大值，再加 44 帧，连续蓄力击发的机械间隔为 104 帧，即约 3.4667 秒。使用此间隔、3 弹容求出 27220 面板，倍率约 1.562572。
- 满匣 S1：整匣榴弹弹药价格仍为 2500，输出弹容改为 1，联弹段数仍为 3。原工作簿的周期为 `interval×(cap-1)+900×dw`，直接把弹容改为 1 会消去所有射击间隔；原表照算仅约 9930，不能据此宣称获得更强爆发。本专项通过 `computeWeaponRowWithCycleOverhead` 向完整弹匣周期及其非换弹部分显式加入 `max(60,68)+44=112` 帧、约 3.7333 秒，求出 51110 面板，倍率约 2.933984。默认 `computeWeaponRow` 的全部输出及 formula=1 不变。这是有披露的时间模型扩展，不是原工作簿单元格的直接结果。
- 运行档位与三个机械弹仓指示窗一致：`ceil(余弹×3/当前容量)`，分别取 1.5／2／3 倍。默认 3 发时对应 26130／34840／52260 面板，相对原拟合约为 -4.00%／-11.04%／+2.25%。扩容到 6 发时，余弹 1–2／3–4／5–6 发分别对应三档；任何容量满仓均为第三档。每次仍只产生一次原有联弹输出，成功后清空当时余弹；N0／N1 只消耗 1 发。默认容量下一发过载与普通蓄力同为 1.5 倍。

控制器按本次实际射击间隔（含现役射击核心修正）阻止提前蓄力，回收更长时等回收结束后再计数。准备就绪后的松键保留蓄力。120 MP 与 10 秒冷却继续保留，由真实提交触发，但未用于提高上述伤害预算。报告中的机械间隔、战技冷却、公式 900 ms 换弹假设分开呈现；桩击判定按姿态配置的完整出桩帧采样一次，N1/S1不再只取未伸足的首帧；显示、原击发时刻与联弹次数不因采样改变。现有游戏机制的实战体验已由维护者确认；当前数值取整与扩容分档另由真实射击核心回归，不将公式拟合等同于完整毕业装备强度标定。

## 内置燃料与特殊槽切换

内置模块声明在重锤生命周期的 `initParam.flamethrower`。装备根层保留锁定的“打桩过载”，控制器只在自己的同一个长枪特殊槽里投影当前角色：待机为副武器补装，就绪为过载，准备/回收/转换时不允许 F 提交。K 只在普通枪态喷火；R 沿现役主副武器换弹链补装，主仓满时也能补燃料。Q 满充后的松开不取消，再次按下会播放卸压动作回到副武器态。阶段变化不重新配置弹仓，不重置共享战技冷却。

副喷火沿用战术版的 850 威力、220 ms 间隔、45 弹速、10 散射、100 击倒率和 `bulletsize=25` 对应的副武器 `range=25`，弹容为 12。沿现役副武器的加成规则，不额外套主长枪强化/枪械攻击/枪械师射线倍率。一个燃料罐补满一仓；首次预装、R/F 补装、换装恢复都由 `LongGunSubWeaponCore` 和物品 `subweaponShot/subweaponReloadCount` 维护。

三个燃料消费者共用一个已装余额：K 喷火、枪械联动、锤战技联动。装备联动通过 `consumeLoadedAmmo` 消费已付费的组弹药，核对确切宿主与运行状态；不能从 onFire 武器或带额外 HP/MP 成本的配置借此绕过扣费。只有 S1 过载的成功回执才消费对应火焰；N0/N1 不耗燃料、不追加烈焰。S1 按实际消耗的主弹和可用燃料取弱档前缀、最多三档；空油不阻断机械桩击。每档消耗一格，威力为当前副喷火模板的 1／1.5／2 倍。

机械桩击保持物理；N1/S1 各带 1% 击溃，S1 再带 13% 斩杀。刀口与碎石为装甲破击，碎石威力为当前刀锋利度的 0.5 倍。默认在狂野一/五段触发；锤战技“燃气破坏”借用破坏殆尽起手，50 MP、共享 10 秒冷却，成功后开启 180 帧窗口，刀口带 0.05% 击溃和 6% 斩杀，指定一/四/五段与重砸节点消费燃料产生对应烈焰，缺油时退回碎石。额外效果不再扣 MP。按动作节点去重，不按三个刀口或素材判定帧数重复发射。

三种烈焰素材自带魔法/热的首帧脚本；联动火焰携带本次付费 `hitBehavior=pileBunkerFuel`，在命中结算前恢复立场破击。此资格随已发射实例保存，与射手之后的油量或形态无关。火焰没有被赋予机械桩击的击溃/斩杀参数。主桩击即时结算，火焰按素材判定帧命中；主击先杀死目标时，稍后火焰不再对尸体追加伤害或立场字样。同一发伤害内部的破击计算早于斩杀，斩杀不会抹去已经生成的立场破击标签。真实素材首帧与伤害处理器由 focused suite 对照；维护者已确认当前实战无问题，该反馈不扩张为所有配装、敌人和设备的穷尽验收。

上述击溃、斩杀、碎石和燃爆保留已试玩参数，报告标为 `runtime_candidate_not_in_base_DPS_budget`。基础枪械公式通过不代表这整套新增机制已完成平衡。对照武器骨肉破碎锤现役为 60 级、80 kg、锋利度 800，附带巨体破击与常驻吸血/暴击/击溃/斩杀；后续比较完整战技周期及配装，不只比较锋利度数字。

## 进阶与获取边界

保存身份仍是 `火药燃气液压打桩机`，进阶值为 `重锤`，静态形态键 `data_pilebunker_m7`，显示名为“重锤燃气打桩机”。基础形态使用原外观与原生命周期，在其中增加普通狂野锤，无专属战技；重锤形态覆盖外观、战技和 M7 生命周期。旧基础物品不自动进阶，不迁移玩家存档。

`重锤改装组件` 是专属材料占位，暂复用铁枪核心图标、回收价为 0。维护者已明确将获取链冷藏：现阶段仅按修改器可取得的武器保留，不为本轮新增商店、配方、掉落或任务。未来恢复投放时再设计成本与支线；不能用通用二阶组件进阶，也没有第二个独立武器物品身份。

## 来源与复算

公式权威为仓库 `0.说明文件与教程/武器-技能数值-价格-合成表填写的参考公式（修改后请勿上传git）.xlsx` 的 `枪械!Q1/Q3`、`刀!J3/C10/J18` 和 `装备价格!J5`。登记 v1 工作簿来自 `ac112ec210d7`，SHA 在 design 中；现役文件整体 SHA 不同，但本轮比较的枪械、装备价格、刀页值与公式全部一致。未改工作簿、版本映射或默认公式；S1 时间扩展仅由本专项显式调用。

从 `tools/cf7-balance-tool` 运行：

```powershell
node node_modules/tsx/dist/cli.mjs models/pilebunker/model.ts --check
npm test -- packages/xml-io/tests/pilebunker-progression.test.ts
npm run balance-sync -- --check
npm run balance-check
```

模型报告写入 `tmp/pilebunker-m7/balance-report.json`。变更设计预算后先复算并明确更新 XML，再通过台账同步器更新两种形态的摘要与指纹。Flash 验证使用仓库根的 `scripts/run-pilebunker-m7-tests.ps1`；先执行原版真实素材与刀口碰撞，再执行重锤首次就绪、拒绝扣费、射后切换、刀技首判定和卸载。`scripts/run-player-manual-input-tests.ps1` 覆盖 +200% 主仓负担、枪械师比例、主副仓联动及翻滚技能补弹。既有实战反馈、数值回归与外观预览各有证据范围；获取途径继续冷藏。角色构筑的实例外观协议及验证入口见[美术装配](../../../../agentsDoc/art-asset-assembly.md)。
