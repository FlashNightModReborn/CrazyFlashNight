## 1. 现状事实（决策依据，已核验）

- **壳**：`arena-panel.js`（4936 行单文件 IIFE）自写 header + 四视图互斥整页切换（`:172-251`），`Workbench.*` 零引用；仅消费 PanelScale / PanelTooltip / Icons。
- **样式**：`css/panels/features.css:6267-9302` 约 3000 行 `--arena-*` 私有 token 孤岛，零 `--wb-*` 消费；动效硬编码（`:6547-6548`）；`arena/dev/harness.html:11-24` 存在第三份 token 拷贝（`--arena-harness-*`）。
- **模式**：`ARENA_MODES` 共四项——标准 / 定制赛 / 堕落 / 爬升（`arena-panel.js:81-92`）；堕落、爬升 `requiresRosters`，harness 未载 `arena-meta-rosters.js` 时 tab 直接不渲染。
- **既有产品合同**：卡片主按钮「⚔ 开始挑战」grid 直入战场（`arena-panel.js:326`），次按钮「🔍 查看对手」进 detail；测试合同 `grid-direct-enter`（`qa-suite.js:19,46`）。
- **竞态机制**：`_session` / `_previewPending` dedup / `_previewCache` 按 cardIdx 落 cache；已有用例 `preview-switch-race`、`roll-again`（单卡换一批）、`reroll-all`。
- **测试现状**：`qa-suite.js` 22 用例，无堕落/爬升覆盖（harness 不载 rosters，结构性缺失）；`tools/run-arena-harness.js:15` 单视口入参、默认 `1600x900`（偏离 1024×576 逻辑画布），无多视口编排，testing-guide:33 日常调用不带 `--viewport`。
- **势力卡规模**：`arena-meta-rosters.js` 实载 20 势力 / 1576 元战队；堕落/爬升按势力出卡，经 `FALLEN_MIN_UNITS=4` 过滤后略少于 20——超过标准模式的 ≤12 张，但量级有限，不需要虚拟滚动。
- **SOT**：`data/arena/arena_config.xml:2-6` 自述「未被代码加载」，运行时真值硬编码在 arena-panel.js。

## 2. 目标态架构决策

- **D1 挑战浏览器**：标准 / 堕落 / 爬升三模式共用一个 Arena Challenge Browser，`profile:'catalog-decision'`（封闭枚举内，无需新 profile）。左栏 = 模式内卡目录（保持模式内滚动与选中），右栏 = 选中对手持续 preview（阵容/风险/押金/奖励）+ 唯一确认区。「换一批 / 全部重抽」进左栏控件条。
- **D2 定制赛**：不硬塞 catalog-decision。总览保持独立；红蓝阵容编辑**先验证现有 `transfer-pair` 是否够用，不够再按流程申请新 profile**（先入 canonical doc，禁止在 feature CSS 里创造新结构，WB129）；深层参数页接 `SecondaryPage`（inert / Esc 分层 / opener 焦点归还）。
- **D3 结算页**：不双栏化。保留全屏战果仪式与 `custom_result` 回开路径，只接 skin、共享状态色、焦点恢复、Esc、reduced-motion。
- **D4 美术策略**：建立 `data-workbench-skin="arena"`，共享语法而非抹平身份——橙黑、大理石、L 角、红蓝阵营色保留；token 全部改消费 `--wb-*` / `--dls-*` + color-mix，动效全 token 化、零新增 keyframes，focus 环交 states.css（WB135）。
- **D5 冻结面**：AS2 协议零改动（`ArenaPanelService` 五 handler + callId 桥、`ArenaTask.cs`）；SOT 不在本轮；Router/Mux 等体系批次。

**P0 须冻结的合同（施工前以文档裁决）：**

1. 四模式到目标态的映射表（D1/D2/D3 各归属）。
2. 「⚔ 直接挑战」去留：取消 / 保留 / 改为汇入同一 commit handler 的快捷键——三选一明文裁决，禁止在布局重构中隐式变更该产品+测试合同。
3. 重抽失效语义：全部重抽 → 整个决策面失效（清空 selection 与 commit 可用性）；单卡重抽 → 保留位置，新 preview 到达前禁用该卡 commit。迟到回包隔离用 **模式 + 稳定卡 ID + session/generation** 三元组（在现有 `_session` 守卫上扩展）。
4. 定制赛 / 结算页边界（D2/D3 的适用范围）。

## 3. 批次划分（P0–P5，每批独立可验收可回滚）

- **P0 合同冻结**：纯文档。产出 §2 四项合同裁决 + ADR 适用范围增补 + profile 映射登记。**ratchet baseline 不提前登记**——与第一个真实 DualPaneShell 构造点同批（P2）入 `workbench-ui-ratchet-baseline.json`。
- **P1 可复用基础层（先补网，后重构）**：拆出 `css/workbench/arena.css`（治理约束照抄 `team.css:75-83`）、建立 skin/token 终态、reduced-motion、焦点与 tooltip scope、消除 harness 第三份 token 拷贝。**测试基线先行**：runner 补多视口编排且默认对齐 1024×576；harness 加载 `arena-meta-rosters.js`，补堕落/爬升用例；补长文本、空态、失败态、键盘、overflow 基线。性质 = 对现行实现的 characterization test，A/B 任何走向都复用。
- **P2 挑战浏览器双栏化**：标准/堕落/爬升迁入 DualPaneShell；落地 P0 裁决的直接挑战与重抽竞态语义；势力长列表做密度/滚动记忆；qa-suite 同步改写全绿；ratchet 构造点本批登记。
- **P3 定制赛选择性收敛**：SecondaryPage 栈、共享 modal/CommitBar、焦点栈；保留现有复杂编辑信息架构，不机械复刻战队；`arena-custom-side-workbench` 本地命名规范化（避免与共享 Workbench 语义撞车）。
- **P4 工程与结算页收尾**：4936 行 facade 拆为 shell / challenge-browser / custom-editor / result / preview-authority；结算页独立视觉精修（D3）；atlas 场景族与 strict audit 接门。
- **P5 独立 SOT 项目**：裁决 XML 成为运行时真源或正式废弃销账；触及 C# snapshot、enter payload、文档/验证合同（testing-guide:32-33 门），**不与前端迁移共批**。

## 4. 验收口径

- 现有 22 用例行为合同不倒退 + 新增堕落/爬升覆盖。
- 三个明确视口：1024×576 / 1366×768 / 1920×1080（1024 下零横向溢出）。
- focus / Esc 分层 / busy 守卫 / reduced-motion；重抽竞态（全部失效、单卡禁 commit、迟到回包丢弃）。
- 势力卡 0 / 最大数量边界；真实字体与长中文文案。
- `audit-workbench-ui.js --strict-warnings` 0/0（WB128/129/135 + ratchet 触碰行）+ `check-workbench-css-bundle.js` + atlas。
- **证据上限**：自动 harness 通过只算 mock-browser 证据；终验须真实 WebView2→AS2 链路 + 游戏内视觉/键盘验收。

## 5. 非目标与边界

- 不做：玩家投注 UI（架构文档已定首期不做）、观战/标定 runner 前端化、arena_config.xml schema 重设计（P5 只做真源裁决）、Router/Mux 迁移、roving 网格导航 / 虚拟滚动 / 拖拽（势力卡量级不需要）。
- 对齐天花板 = 战队终态，不追加战队自身未竟项为竞技场义务。
- AS2 侧权威逻辑（押金、抽签、跳关、标定 runner）全程零改动。
- 若体系先于本轮产出新共享沉淀（如 tabNav 上收共享层），P2 直接消费最新共享层，不复刻 team 私有模式。
