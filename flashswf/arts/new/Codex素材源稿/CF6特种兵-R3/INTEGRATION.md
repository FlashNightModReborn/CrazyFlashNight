# 接入边界和待测项目

## 本轮可用成果

这是独立、可重建的 SVG 替换候选，12身体+匕首+盾母件，以及29个变形/死亡/碎盾派生件。`asset-manifest.json` 是所有152个依赖 Shape 的准确文件映射；不要仅导入站姿图片，也不要把559/580/629拆成三个从零独立图集。

1. 先在副本工程导入 `parts/` 和 `variants/`，按原Shape ID映射。`preserved/` 是原共用资源，通常不需要重导，但可用于独立核对。
2. 原局部原点、viewBox和导出宽高保留。导入程序若自动紧裁、平移到中心或改变SVG缩放，应先修正导入流程，不能通过移动原骨架矩阵掩盖偏差。
3. 关节边缘是有意开放描线。填色仍闭合，不能为“修SVG”给所有路径补闭合黑线，否则会重新出现玩具式关节环。
4. 29派生件使用原裁切与原bitmap矩阵投射新图集。尤其575/577/578碎盾和522–544头/断臂混合件不要另画成不相干碎片。

## 本包已验 / 未验

已验：原SVG尺寸与坐标、全部替换内部引用、纯矢量约束、原资源字节保留、原时轴559帧静态装配、每条可见分支关键姿势、盾窗透明、81fill碎片覆盖、独立冷重建。

未验：Flash CS6 / Animate 对SVG clipPath、use及已登记的linearGradient/radialGradient（硬金属反射及布料/皮革漫反射）的导入行为、FLA层级/注册点落地、真实游戏像素尺寸、运行时shader/滤镜、脚本stop/goto与随机死亡选择、盾击/碎盾后状态切换、受击混合、实际碰撞与武器逻辑。没有生成或提交生产FLA/SWF。

手枪238–253仍是原图占位，按用户要求留待新版武器单独替换；本包不宣称完成手枪重制。

## 进入游戏前的重点测试

- 559走路和近战：膝甲随原胫件稳定，不漂移；手指与枪柄、匕首柄的层级原样。
- 580盾窗和持盾手：窗内能看到原应可见的枪/手/布料，盾体遮挡不漏手、不吞枪；站、走、射击、近战、双受击分支都要测。
- 579碎盾：六片布局、冠徽/CF连续性、消失帧与原血烟一致。此11帧静态序列不能代替整个死亡控制流。
- 629撞车：完整盾与身体脱离，盾窗和徽记随原旋转，落地后间距一致；不改rig。
- 558三个死亡分支：爆头的细片保留，断臂段的袖甲与血口衔接，完整身体倒地不过分露连接端。
- 真实游戏倍率：优先检查红眼、CF盾徽、三条护膝筋、枪/手的读形。不要以放大原新图替代游戏尺寸验收。
