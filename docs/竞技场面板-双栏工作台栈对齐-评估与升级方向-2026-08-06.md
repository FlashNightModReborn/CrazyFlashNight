## 2. 目标态架构决策

- **D1 挑战浏览器**：标准 / 堕落 / 爬升三模式共用一个 Arena Challenge Browser，`profile:'catalog-decision'`（封闭枚举内，无需新 profile）。左栏 = 模式内卡目录（保持模式内滚动与选中），右栏 = 选中对手持续 preview（阵容/风险/押金/奖励）+ 唯一确认区。「换一批 / 全部重抽」进左栏控件条。
- **D2 定制赛**：不硬塞 catalog-decision。总览保持独立；红蓝阵容编辑**先验证现有 `transfer-pair` 是否够用，不够再按流程申请新 profile**（先入 canonical doc，禁止在 feature CSS 里创造新结构，WB129）；深层参数页接 `SecondaryPage`（inert / Esc 分层 / opener 焦点归还）。
- **D3 结算页**：不双栏化。保留全屏战果仪式与 `custom_result` 回开路径，只接 skin、共享状态色、焦点恢复、Esc、reduced-motion。
- **D4 美术策略**：建立 `data-workbench-skin="arena"`，共享语法而非抹平身份——橙黑、大理石、L 角、红蓝阵营色保留；token 全部改消费 `--wb-*` / `--dls-*` + color-mix，动效全 token 化、零新增 keyframes，focus 环交 states.css（WB135）。
- **D5 冻结面**：AS2 协议零改动（`ArenaPanelService` 五 handler + callId 桥、`ArenaTask.cs`）；SOT 与权威重算闭环为独立项目（§3 P5）；Router/Mux 等体系批次。
- **D6 权威门禁（二审新增）**：P2–P4 批级验收 ≠ 生产就绪。权威重算 / SOT 闭环（P5）落地并经真实 WebView2→AS2 链路复验前，竞技场目标态整体保持 **NOT_PRODUCTION_READY**，对外不得宣称「栈对齐完成 / 生产验收通过」。

**P0 合同裁决（二审固化，以下为终裁，不再开放）：**

1. **四模式映射**：标准 / 堕落 / 爬升 → D1 catalog-decision 挑战浏览器；定制赛 → D2（总览独立 + 参数页 SecondaryPage；阵容编辑先验证 `transfer-pair`）；结算页 → D3（不双栏化）。
2. **「⚔ 直接挑战」= 裁决为快捷键汇入同一 commit handler**：卡片不再承载独立直入按钮（满足 `workbench-ui-system.md:211` 每个决策面唯一主 CTA、位于非滚动 decision footer）；卡片交互统一为选中语义（click / 方向键浏览），commit 只从右栏确认区发起，选中卡上 `Enter/Space` 作为同一 commit handler 的快捷键别名。裁决理由：三个选项中唯一同时满足唯一主 CTA canonical 与保留快速入场能力者。原 `grid-direct-enter` 用例改写为 keyboard-commit 预期行为变更，其余 21 项用例行为合同不倒退。
3. **重抽失效语义**：全部重抽 → 整个决策面失效（清空 selection 与 commit 可用性）；单卡重抽 → 保留位置，新 preview 到达前禁用该卡 commit。迟到回包隔离用 **模式 + 稳定卡 ID + session/generation** 三元组（在现有 `_session` 守卫上扩展）。
4. **定制赛 / 结算页边界**：按 D2 / D3 适用范围执行；`arena-custom-side-workbench` 本地命名规范化，避免与共享 Workbench 语义撞车。
