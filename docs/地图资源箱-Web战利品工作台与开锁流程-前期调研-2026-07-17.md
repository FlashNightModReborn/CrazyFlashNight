## 0. 一页结论

方向**可行且值得做**，但建议先建“场景瞬态战利品容器”的权威闭环，再把 Lockbox 作为部分高价值箱子的前置开锁步骤。不建议先把 Lockbox 硬接到旧 AS2 资源箱小窗口：这会形成一次性跨栈胶水，后续迁 Web 时仍要重做容器寻址、生命周期与奖励提交。

当前关键事实：

- 箱子互动现为同步路径：按下互动键后立即 `publish("kill")`，地图元件当场标记 `_killed=true`。
- 网格箱不是“地面拾取格”：开启动画帧才即时创建 `new ArrayInventory(null, row * col)`，然后打开旧 AS2 `资源箱界面`。
- 该临时库存无稳定 `containerId`、不在 `InventoryPanelService` 容器注册表内，目前无法被 Web inventory-domain 权威寻址。
- **已存在奖励丢失缺陷**：多个箱子同时与玩家 area 相交时，一次全局 `interactionKeyDown` 会被每个箱子独立消费；它们同时开箱后又重用同一个 AS2 `资源箱界面` 实例，后到库存会覆盖界面绑定，使先前的临时库存不再可达。新架构必须把该问题当成数据安全缺陷修复，不是可延后的 UI 优化。
- Lockbox 已有正式 Web panel、确定性 core / solver / generator、音频与 QA，但 `minigame_session` 目前只到 Host 日志，不回 AS2、不提交奖励。
- 关卡 XML 中当前检出 36 个相关实例；其中 17 个使用物品格（13 装备箱 + 3 保险柜 + 1 生存箱），其余 19 个是直接爆落路径。

推荐目标流程：

```text
互动箱子
  → AS2 创建 chestSession（暂不 kill）
  → Web Lockbox（可配置跳过）
  → 一次性开锁结果回到 AS2
  → AS2 复核 session 并驱动开箱动画
  → 开盖帧由 AS2 滚落物并注册 lootContainer
  → Web “背包—战利品箱”双栏
  → 关闭 / 场景切换后注销 lootContainer
```

### 2.3 旧资源箱 UI 的数据语义

1. `掉落物转换为物品栏` 在开启帧一次性滚落物，随后把 `target.掉落物 = null`。
2. 容器是真实 owned `ArrayInventory`，但只被 UI 图标和 `IconFactory.inventoryContainerDict` 间接持有，没有可跨 AS2/Web 请求的稳定地址。
3. 旧 `InventoryIcon` 允许在已显示的 `ArrayInventory` UI 间拖动；金钱、K 点、材料、情报则走点击即领取的特殊分支。
4. 临时容器不入存档。窗口或场景销毁后，未取走内容没有对账 / 恢复机制。
5. 当前数据容量与视觉网格存在历史隐患：`ArrayInventory` 构造和旧 UI 对过小 / 过大 `row×col` 的处理不是同一处约束。
6. **多箱覆盖的确切机制已确认**：
   - 每个箱子都用 `subscribeGlobal("interactionKeyDown", ..., target)` 独立订阅同一全局输入；现有路径没有“本次输入唯一互动目标”裁决器。
   - 同时命中的箱子都会 `publish("pickUpBox") → publish("kill")`，因此问题不是玩家手动快速点了两次，而是一次输入的 fan-out。
   - `_root.从库中加载外部UI("资源箱界面")` 以固定 identifier 作 MovieClip 实例名；已有实例时直接返回同一对象，不新建窗口。
   - `IconFactory.createInventoryLayout` 发现同一 UI container UID 已注册时，调用 `resetInventoryLayout` 将其 `inventory` 改绑到新对象并重置既有图标。旧临时库存失去可达 UI，其未领奖励因而丢失。

### 2.4 已知缺陷的修复不变量

新路径在 S0 开始就必须满足：

1. **一次互动输入最多提交一个箱子**。多个候选同时命中时，由中央裁决器以稳定规则选一；具体排序可在 S0 冻结，但必须可确定性复现。
2. **同一时刻最多一个 active chest / loot flow**。首版遇到第二个请求应拒绝或保留为 `AVAILABLE`，不得提前 kill，也不得把新容器重绑到旧 session。
3. **未被选中的邻接箱子必须保持可互动**。当前 flow 完成 / 关闭后，玩家可再对其发起新会话。
4. **每个已创建的 loot container 必须有独立身份与终态**。即使异常路径生成了第二个容器，服务也必须拒绝覆盖，并让每个容器显式进入 `CONSUMED / ABANDONED / EXPIRED` 之一。
5. **不用“多开几个 Web 窗口”作为首版修复**。核心问题是输入唯一性与数据生命周期；窗口并行会反而放大暂停、焦点、奖励对账和放弃语义。

### 2.5 Lockbox 的当前边界

可复用部分：

- 正式运行目录：`launcher/web/modules/minigames/lockbox/`。
- 确定性核心、solver、generator、变体数据、Web panel、音频、Node QA 与 browser harness 都已存在。
- `onOpen(initData)` 已接受 `profile / source / familySeed / variantIndex`，可承载箱型映射与可重现 seed。
- panel 打开已进入通用 `webPanelPause` 暂停 lease，不需要另造小游戏暂停系统。

尚未具备：

- `minigame_session` 只被 Host 解析并写日志，没有 AS2 action / response 闭环。
- Web 生成的 `sessionId` 不是 AS2 箱子实例签发的一次性权威 token。
- 当前 result 可用于观测，不可直接当奖励 commit 凭证。
- 没有定义取消、失败、重试、断线、场景切换与箱子被破坏时的交叉状态。

## 4. 推荐权威边界

### 4.1 AS2 是箱子与奖励 SOT

AS2 应继续决定：

- 当前场景、箱子 MovieClip 和角色是否仍可互动。
- 箱子类型、进度门、是否已开启 / 被击碎 / 正在处理。
- 掉落概率、PRD key、数量、`总数` 消耗与 `BaseItem` 构造。
- 临时 `ArrayInventory` 实例、物品移动 / 领取与存档 `dirtyMark`。
- chest / loot session 的签发、一次性消费、注销和过期拒绝。

Web 不应自行滚奖励，也不应把 Lockbox 分数 / 评级直接换算成物品。如需将开锁表现影响奖励，应由 AS2 根据经验证的有限档位（例如 `base / bonus`）重算，而不信任 Web 上送任意数值。

### 4.2 Host 是运输与 panel 生命周期边界

Host 应负责：

- 在 AS2 `panel_request` 与 Web panel 之间传递只读 initData。
- 把结构化的开锁 result 转成明确 AS2 action，再把 AS2 的最终接受 / 拒绝回到 Web。
- 管理 panel 打开、替换、关闭、暂停 lease 与断线清理。
- 记录去敏的 session 观测信息；不将完整奖励内容或可重放 token 泄漏到常规日志。

### 4.3 Web 是展示、输入与意图层

Web 应负责：

- 渲染 Lockbox 与 loot 双栏，发送用户意图。
- 进行本地 UX 预检、pending 锁定、超时后对账和友好错误展示。
- 保持 `containerId + physicalSlot + lease` 地址，不从 DOM 位置推断物理槽位。
- 将金钱 / K 点 / 材料 / 情报显示为 AS2 snapshot 投影，通过明确 claim 意图领取。

## 5. 推荐状态机

### 5.1 箱子会话

```text
AVAILABLE
  │ interaction + AS2 revalidate
  ▼
LOCK_PENDING ── panel open failed / cancel policy ──► AVAILABLE 或 ABANDONED
  │ verified success / configured skip
  ▼
OPENING_ANIMATION
  │ XFL open-frame callback
  ▼
LOOT_ACTIVE
  │ close / empty / scene change / timeout
  ▼
CONSUMED
```

异常边：

- 箱子在 `LOCK_PENDING` 期间被击碎或场景卸载：注销 chestSession，后续 result 返回 `session_expired`。
- Web / Host 断线：不可默认视为开锁成功；是否允许重试由冻结策略决定。
- 重复成功回包：只有首个合法 commit 能将状态从 `LOCK_PENDING` 推进，后续返回 `already_consumed`。
- 已有 active chest / loot flow 时又收到箱子互动：新目标保持 `AVAILABLE`，返回可观测的 `flow_busy`（字面量待 S0 冻结），不发布 kill。

### 5.2 战利品容器会话

```text
REGISTERED
  → SNAPSHOT_ACTIVE
  → WRITE_PENDING
  → SNAPSHOT_ACTIVE（成功重投影 / 失败保留）
  → EXPIRED（关闭、清空、场景卸载或策略过期）
```

容器 ID 只要求 session-scoped 唯一，不要写入长期存档。建议逻辑形状为 `loot:<sceneEpoch>:<sequence>`；具体字面量须在 S1 协议评审后冻结。

### 5.3 面板编排原则

- 开锁和 loot 可在同一 Host panel 生命周期内做 same-panel flow，也可以两个 panel 实例串联；S0 应用实验确认转场、焦点与 pause lease 哪种更稳定。
- 不得在中间转场释放又重获 `webpanel` pause lease，避免游戏世界闪进一帧。
- loot panel 关闭是领域动作，不能只 `Panels.close()`；必须先让 AS2 注销 / 确认容器，再退出视觉面板。

## 6. 待评审决策表

下表的“推荐默认”为调研建议，**尚未冻结**。每项冻结后应在 S0/S1 的 ADR 小节中记录理由。

| 决策 | 推荐默认 | 理由 / 代价 |
|---|---|---|
| 哪些箱型进 Lockbox | 保险柜、生存箱默认开；高价值装备箱可配；普通资源箱 / 纸箱 / 隐藏点保持爆落 | 不把 36 个实例全部变成高频打断 |
| 失败是否可重试 | 首版允许重试，不重滚奖励；实际惩罚另立游戏设计评审 | 先验证技术闭环，避免技术失败直接吞奖励 |
| 玩法结果是否影响奖励 | 首版只控制“开 / 未开”；bonus 延后 | 防止把 Web 分数提前变成经济权威 |
| loot 是否可放回背包物品 | 不可；只允许 loot → 背包 / 相应领域 | 瞬态箱是奖励源，不是仓库 |
| 关闭后剩余物品 | 显式二次确认放弃；空箱可直接关 | 比当前静默丢失更清晰，但需要新 close 协议 |
| 背包满 | 面板保持打开，显示权威容量错误；不自动丢弃 | 与 inventory-domain 一致 |
| 金钱 / K 点 / 材料 / 情报 | 独立 `claim` 语义，成功后由 AS2 转入相应领域 | 不能用普通 `move` 塞进背包 |
| 断线恢复 | S0/S1 只做明确终止 + 可重试，不做跨 Launcher 重启恢复 | 当前箱子本就不持久化；先不扩张到新存档 schema |
| 箱子被攻击 | `LOCK_PENDING` 期间暂停世界，正常不会继续受击；仍对 scene unload 做过期保护 | 复用 Web panel pause 而不引入箱子无敌状态 |
| 多箱同时命中的目标裁决 | 一次输入只选一个；建议按可交互距离 + 稳定实例次序决胜，具体公式在 S0 fixture 中冻结 | 先消除一键 fan-out；不在文档期凭空确定不可验证的体感规则 |

## 7. 建议施工阶段

### S0：单箱型编排 Spike

**目标**：不引入经济写入，验证“AS2 互动 → Lockbox → AS2 单次回执 → 开启动画”。

范围：

- 只选 1 个保险柜 fixture / 测试关卡，不批量改箱子 XFL。
- fixture 同时放置 2 个可被同一次互动命中的邻接箱，专门复现原版覆盖丢奖。
- AS2 签发 chestSession，Host 传递，Lockbox 回结果，AS2 拒绝 stale / duplicate。
- 开锁后可临时继续走旧 UI，但只作证明编排接缝的 spike，不合并为最终产品路径。

结束门：

- 取消不会把箱子留在 `_killed=true` 但未开启的中间态。
- 双击 / 重复 result 只能推进一次动画。
- 对两个贴邻箱按一次互动键，只有一个进入 `LOCK_PENDING / OPENING_ANIMATION`；另一个保持 `AVAILABLE` 且稍后可单独打开。
- 面板转场中 pause lease 不闪断，焦点可正常恢复。

### S1：瞬态 loot container 领域能力

**目标**：让 AS2 临时 `ArrayInventory` 变成在会话内可寻址、可过期的权威容器。

必需能力：

- register / snapshot / tooltip / transfer-or-claim / close-or-abandon / scene cleanup。
- session-scoped `containerId`、`containerEpoch`、slot lease 与过期错误。
- 单向收取策略、背包容量预检、原子提交、失败不丢物。
- 金钱 / K 点 / 收集品与普通 owned item 的明确分流。

结束门：

- AS2 TestLoader 覆盖空箱、满背包、stale lease、duplicate close、scene cleanup、特殊资产 claim。
- 任意 `EXPIRED` 容器写命令都零副作用。
- 掉落只由 AS2 滚一次，Web/Host 日志不包含可重放奖励凭证。

### S2：Web 背包—战利品箱双栏

**目标**：复用 workbench 家族展示 primitive，完整替代旧 `资源箱界面`。

建议交互：

- 左侧背包，右侧小型战利品网格；右侧不分页，尺寸依 snapshot 容量。
- 单击选择 + 双击 / Ctrl 快速收取 + pointer 拖放。
- “全部收取”必须使用有界队列或领域批量命令，不并发风暴。
- 关闭时显示剩余物数量，非空箱走明确放弃确认。

结束门：

- Node 状态测试 + browser harness 覆盖三视口、鼠标 / 键盘、满背包、过期、关闭确认、特殊资产。
- 运行态无 AS2 资源箱小窗口双开。
- Web 不持有奖励权威、不可以从本地 state 恢复出已被 AS2 拒绝的物品。

### S3：Lockbox 生产开锁闭环

**目标**：将 Lockbox 从观测性 `minigame_session` 推进为可安全驱动 chestSession 状态转换的业务流。

必需能力：

- 箱子签发 session，变体 / seed 与箱型映射为只读参数。
- result 结构白名单、session 一次性消费、stale / duplicate / unsupported 拒绝。
- result 超时或未知时先查 AS2 权威状态，不重放旧提交。
- Host 日志对 session/token 去敏，Web 玩家界面不显示协议语汇。

结束门：

- Lockbox Node QA + browser harness 全绿。
- Launcher xUnit 覆盖路由 / 回包 / 断线 / duplicate。
- fresh Flash trace 覆盖成功、失败、取消、过期、重复回包。
- 游戏内端到端手测确认一个真实箱子只会开启 / 滚奖一次。

### S4：箱型配置化、观察期与旧 UI 退役

**目标**：控制开锁频率，完成真实内容铺开，最后退役只属于网格箱的 AS2 展示入口。

- 先上保险柜 / 生存箱，再按价值配置装备箱。
- 普通资源箱、纸箱、隐藏点的爆落路径保持不变，除非另有游戏设计评审。
- 观察失败率、放弃率、平均时长与打断感，不把调试 telemetry 长期暴露给玩家。
- 旧 `创建资源箱图标` 和 `资源箱界面` 只能在新路径真机观察达标后退役。

## 8. 预估改动面（非文件承诺）

### AS2 / asLoader

- `InteractionHandler`：从“互动即 kill”拆出可延迟的箱子互动编排，或委托新 `ChestSessionService`。
- `InventoryPanelService` 或独立 `LootContainerService`：瞬态容器注册、snapshot、claim / transfer、close、过期。
- `关卡系统_lsy_地图元件.as`：掉落滚动与开盖 callback 的新委托；保留 `row/col==0` 爆落分支。
- `物品系统_WebView.as`：服务安装 / gameCommands 入口（如选择新服务）。
- 对应 TestLoader 测试类与 manifest / asLoader 注入接线。

### Flash XFL

- 箱子共通时间轴回调；应尽量收敛到 AS2 委托，不在 6 个 symbol 内复制业务协议。
- 若改 `flashswf/arts/new/素材库-地图元件/`，它是独立素材库 XFL，发布目标必须是该 `.xfl` 与对应 `素材库-地图元件.swf`，不得泛化成 `-Target main`。
- 旧 UI 退役若改 `flashswf/UI/物品与技能相关界面/`，同样必须独立 publish / verify 其 SWF。

### Launcher Host

- panel 路由、开锁结果 action / response 与异常关闭。
- InventoryTask 增量命令或独立 LootTask；选择须以“领域边界是否真正独立”评审，不以文件数最少为目标。
- Launcher xUnit 覆盖协议映射、保留键、回包整形、超时 / 断线 / stale。

### Launcher Web

- `loot` panel 组合层，复用 `workbench.js / inventory-runtime.js / inventory-ui.js`。
- Lockbox 从只日志 session 推进为有业务回执的编排接缝，但保留 `minigame_session` 作观测信封，不恢复分游戏命令。
- lazy registry / build 必需集 / panel layout 如新增 panel ID 才更新；如采用 same-panel rebind，不要虚构一个新 ID。

## 10. 评审风险清单

| 风险 | 影响 | 首选缓解 |
|---|---|---|
| 互动即 kill 与异步小游戏冲突 | 取消 / 失败后箱子已死，无法重试 | 在 kill 之前创建 chestSession，成功后才推进旧动画 |
| 全局互动事件 fan-out | 一键同时 kill 多箱，开启动画并发 | 中央候选裁决；一次输入最多提交一个箱子 |
| 单例资源箱 UI 重绑 | 后到容器替换 `IconFactory` 绑定，旧奖励失去可达入口 | 每容器独立 ID + 单 active flow 守卫 + 拒绝覆盖 |
| 临时容器无地址 | Web 无法安全 snapshot / mutate | session-scoped ID + registry + epoch + close cleanup |
| Web result 被当经济凭证 | 可伪造 / 重放奖励 | AS2 一次性 session 复核；掉落仍在 AS2 滚 |
| 特殊资产被当普通 item move | 金钱 / K 点 / 材料 / 情报进入错误容器 | 独立 claim 语义与受影响领域 snapshot |
| 非空箱直接关闭 | 奖励静默丢失，玩家误解 | 领域 close 返剩余数，显式 abandon 确认 |
| 开锁频率过高 | 打断战斗节奏，小游戏疲劳 | 只对高价值箱配置开启，普通箱保持快取 |
| 旧 AS2 UI 过早删除 | 新链失败后无 fallback，还扩大 XFL 风险 | S4 真机观察后再退役 |
| 中间 panel 切换暂停闪断 | 战斗世界在背后推进一帧 | 一个 flow 持有同一通用 pause lease，真机 trace / 视觉验证 |
| XFL 编译目标选错 | 误编 main 或遗漏素材库 SWF | 显式独立 `.xfl -PublishOnly -VerifySwf` |

## 12. Compact 恢复卡

如后续会话因 compact 丢失上下文，先读本节，再按需回读前文。

1. **目标不是“打开 Lockbox”**，而是“建立 AS2 权威的瞬态 loot container，用 Web 双栏展示，Lockbox 作可配置前置步骤”。
2. 当前触发在 `InteractionHandler.executePickup` 中立即 kill；要接异步开锁，必须在 kill 之前引入 chestSession。
3. 原版多箱丢奖的根因是“全局互动事件同时命中多箱 + 固定 `资源箱界面` 单例 + `resetInventoryLayout` 改绑新库存”。新路径必须做一次输入选一箱，且同时只有一个 active flow。
4. 有网格的只是保险柜 / 生存箱 / 装备箱，当前关卡静态实例数 3 / 1 / 13。普通资源箱 / 纸箱 / 隐藏点继续爆落是推荐默认。
5. 旧网格箱的 `ArrayInventory` 是瞬态真库存，但无 `containerId`；现有 inventory-domain 文档明确将其排除。
6. Lockbox core 可用，但 result 目前只进 `minigame_session` 日志，不是奖励权威。
7. 施工顺序优先 `S0 编排 spike → S1 loot authority → S2 Web 双栏 → S3 Lockbox 生产闭环 → S4 铺开 / 退役`。
8. 第一个真实施工任务开始前，先冻结第 6 节待评审决策，至少确认多箱目标裁决、失败 / 取消、剩余物关闭、特殊资产 claim 和箱型范围。

**下一段建议开场**：从 S0 的一个保险柜 fixture 开始，先设计 chestSession 状态转换和最小回包，不先写 loot UI。
