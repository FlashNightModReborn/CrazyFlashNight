# 怪物标识（`<标识>`）规则书

> 权威来源：`0.说明文件与教程/武器-技能数值-价格-合成表填写的参考公式.xlsx` 的 **《怪物大致面板》** 页。
> 工具只做翻译与复算，不覆盖工作簿规则；工作簿文件名写明「修改后请勿上传 git」，不要把它的改动纳入提交。

## 1. 范围与真源

| 层 | 位置 | 角色 |
|----|------|------|
| 公式 | 工作簿《怪物大致面板》 | 唯一公式权威 |
| 正算 | `packages/core/src/formulas/monsters.ts` | 十项系数 → 面板（N~W 列） |
| 反推 | `packages/core/src/formulas/monster-solve.ts` | 面板 + 已给系数 → 其余系数，含档次扫描 |
| 阶段规则 | `packages/xml-io/src/monster-stage.ts` | 关卡/任务数据 → 首次出场阶段 |
| 普查与写回 | `packages/xml-io/src/monster-flags.ts` | `data/enemy_properties/*.xml` 模板清点与 `<标识>` 补丁 |
| 命令 | `packages/cli/src/monster-flags.ts` | `monster-census` / `monster-solve` / `monster-flags-apply` |
| 口径配置 | `data/monster-census.json` | 字段映射、主线阶段分档表、章节归属、排除规则 |

`<标识>` 是**设计侧溯源标注**：全仓检索 `.as/.cs/.ts/.js/.json` 均未发现运行时代码读取 `档次系数` 等字段，游戏只读模板里的面板数值。
所以补写或修正 `<标识>` 不会改变游戏数值，属于低风险改动；反过来说，标识写错也不会立刻在玩法里暴露，必须靠复算偏差发现。

## 2. 十项系数与面板的可辨识性

工作簿用 C~L 十列算出 N~W 八项面板加金币/K 点价格。反推时「面板能定住谁」决定工具能给什么、不能给什么：

| 系数 | 工作簿列 | 能否由面板定 | 依据与精度 |
|------|----------|--------------|------------|
| 阶段 C | C | **能**（不靠面板） | 首次出场关卡反查，见第 3 节 |
| 档次系数 D | D | **不能** | 主观定档（样貌与招式）；面板单独定档实测 top1 只有 7/29 且整体偏低 |
| 成长系数 E | E | 能，但需要 D | 空手 MAX/MIN 比值、经验 MIN、经验 MAX 三条独立通道互为交叉校验；通道分歧 >10% 时报警并怀疑 C/D |
| 攻速系数 F | F | **不能** | F、G、H 在空手攻击里只以乘积 `G·√H·1.2^(F-3)·1.1^(I-2)` 出现，面板只能定住乘积 |
| 攻击倍率 G | G | **不能** | 同上，必须由攻击动作观测拆分 |
| 段数系数 H | H | **不能** | 同上。持续型攻击按每 15 秒总段数折算，一招一式按单次动作段数 |
| 速度系数 I | I | **能，但只按定义取** | I 的定义就是移动速度档次：工作簿 D15 的 10~40 慢=1、40~60 中=2、60~90 快=3，**取 `速度_min` 与 `速度_max` 的均值落在哪一档**，区间上限归本档（均值正好 60 读 2）。现存 9 例人工标注实测：均值读法 8/9、`速度_min` 6/9、`速度_max` 2/9。区间跨两档时另给两档中点候选（如 50~75 → 均值档 3、中点 2.5），体育老师这类实操标 2.5 的怪取中点。面板只在 J 与 L 都已给定时当校验用：`solveSpeedFactorFromDefense` 由防御 MAX 反推 I（能还原 2.5 这类非整档值，残差可到 0.1% 内），与定义档差 ≥0.5 就在 `notes` 报警，**不覆盖定义值**；只有查不到移动速度区间时，闭式解才直接给值 |
| 高攻低血防 J | J | 能，但需要 D 与 I | 防御 MIN 闭式解，实测残差约 3% |
| 霸体系数 K | K | 部分 | HP 相对 J/L/I 解的残差即霸体乘子；只在 `D<9 且 K>3` 或 `D>12 且 K<5` 分支可反解，整数位仍须按击退/击飞动画复核。韧性系数高于 20 时每 20 点加 0.1（上限 0.5），是小数位线索 |
| 高防低血 L | L | 能，但需要 D 与 I | 防御 MAX 给出 L/J，乘以 J 得 L |

**依赖链**：`D 人工给定 → I 由移动速度按 D15 定档 → J、L 闭式 → HP 残差 = 霸体乘子 → K 的候选`。
防御 MAX 的反推是 I 的**校验通道**，不是取值通道：速度系数必须由速度数值定义，面板对不上说明面板或速度区间有一处错，报警交人工回查。
残缺行里最常见的正是「九项齐、只差速度系数」，此时也先按移动速度定档；现网 29 行反推最初有 4 行报警——体育老师（人工 2.5 vs 定义 3）、爆胖僵尸（人工 2 vs 定义 1）、闪流步兵（面板 1.84 vs 定义 1）、齐天大圣（面板 0.34 vs 定义 1）。后三行已按定义档写回，报警只剩体育老师：这条通道比的是「标识里已有的值 vs 定义档」，把定义档写进去就必然一致而消音，它们与面板的不合转由「复算最大偏差」现形（闪流步兵 19.5%、齐天大圣 12.8%），别把消音读成已解决。
链条上任一环缺失，工具就退回「只登记缺什么」，不会伪造结论。
F/G/H 与 D 一律由人工补；`unresolved` 字段会把它们显式列出来。

## 3. 阶段反查规则（已实现）

优先级从高到低：

1. 模板已标 `阶段` → 直接沿用，不再猜。
2. **主线关卡**：该关卡对应的主线 id 落在 `mainlineBands` 哪个区间，就是哪个阶段。主线序号严格递增，分界明确。
3. **支线关卡**：取该支线链上最近的**前置主线 id**（支线本身没要求主线 id 时，用它链上前一个任务的），按区间定档后 **+1**。
4. **没有对应支线的关卡**：按关卡 `UnlockCondition` 反查最近主线 id，**+1**。
5. 主线 id 超过 `mainlineCompletedUntil`（现为 77，诺亚前后与雪山尚未划分）→ 记 `deferred`，不给阶段。
6. 在纳入统计的关卡里查不到注册 → 记 `unresolved`。

关卡目录到章节的归属写在配置的 `chapters` / `stageChapterOverrides` 里；
`excludedStagePatterns` 排除魔神图与挑战关卡，`excludedSourceFiles` 排除 `魔神.xml`（魔神图的怪不需要标识）。
被排除后若某模板彻底查不到出场，会列进普查的「无出场记录」，供人工确认排除没有过头。

## 4. 命令

```bash
cd tools/cf7-balance-tool
npm install

# 普查 + 反推候选 + 档次扫描（reports/ 已 gitignore，是临时输出）
npm run monster-census -- --markdown --scan-tier

# 人工定档后：spritename → 档次系数 的 JSON
npm run monster-census -- --tier-hints reports/tier-hints.json

# 单个怪手工复算（不给 --tier 就只输出档次候选排序）
npm run monster-solve -- 敌人-体育老师 --stage 4 --tier 12 --known 速度系数=2.5
npm run monster-solve -- 敌人-黑铁武士 --stage 3 --scan

# 写回：默认 dry-run，只看将要写入的标识；--write 才落盘，--only 做小批试点
npm run monster-flags-apply -- reports/monster-flag-census.json
npm run monster-flags-apply -- reports/monster-flag-census.json --only 敌人-骨刺僵尸,敌人-飞刀小子
npm run monster-flags-apply -- reports/monster-flag-census.json --write
# 人工把档次与取值网格定死后，也可以直接给 spritename → 标识 的数组当候选
npm run monster-flags-apply -- --from reports/pilot-speed.json --write
```

- 跑 CLI 前必须先构建 workspace：`npx tsc -b packages/core packages/xml-io`（tsx 走 `import` 条件解析到 `dist`）。
- `--fallback-tier` 只用于「先跑一遍看看」的实验，proposal 会**主动剔除**它，绝不把假设档次写进数据。
- 写回只动 `<标识>` 块：已有叶子改文本，缺字段合并成一次插入，缺整块则插到模板闭合标签前，中文注释与其余排版保持原样。
- 仅改数据 XML 通常重启游戏即可，不据此重编 SWF。

## 5. 工作流程

1. `monster-census` 出普查表，先看「可自动补」列：阶段与速度系数属机械可填。
2. 人工按样貌与招式定档，写 `reports/tier-hints.json`。
3. 带 `--tier-hints` 重跑普查，检查每行的「反推候选 / 复算最大偏差 / 备注」。备注列把「速度系数定义档 …」这类报警顶到最前面，因为它决定这一行能不能直接写。
4. 复算偏差中位数应在 10% 以内（29 行实测：写回速度系数前中位 7.4%、p90 19.7%，闭式解优先写回后 3.0% / 17.1%，改按定义优先后 4.3% / 19.5% —— 抬高的正是 `闪流步兵`、`齐天大圣` 两行速度定义与面板不合的行，中位数升高就是待回查的信号）；单行超过 20% 先怀疑面板数据或阶段/档次，不直接写回。
5. `apply` 先 dry-run 核对再 `--write`，然后 `git diff` 复核并回跑普查确认 complete/partial 计数上升。写回的格式合同：新字段按**兄弟行缩进**对齐（`天网.xml` 的 `<标识>` 用制表符而子节点用空格，不能跟着块缩进走），不产生只有空白的行，不碰注释。
6. 首批只写机械项（阶段、速度系数），用 `--only` 控制在十几行内验证格式合同，再扩量。速度系数一律按定义取，**不因面板对不上而暂扣**：报警行照常写定义档，但要在备注里留痕、回查面板或速度区间。防御MAX 残差 >1% 的**其余**系数候选（成长、血防、霸体）才暂扣，等人工回查面板；取值本身不再因“不在整档”而暂扣，改按下面的取值词表归档。
7. 通道分歧报警（如「经验MIN 给出 0.626，主通道 0.796」）的行，按备注回查阶段或档次，不要只补一个系数了事。

## 6. 取值词表

反推的连续解不能直接进数据，`snapMonsterCoefficient` 按 **整数 → 0.5 半档 → 0.1 十分档** 逐档放宽，容差 0.05：够得着整数就取整数，`2.014 → 2`；整数够不着才降半档，`2.5 → 2.5`；半档也够不着才降十分档，`1.840 → 1.8`。词表是按现网 25~29 例真值实测出来的，不是假定：

| 系数 | 在 0.5 网格 | 需要 0.1 或更细 |
|------|-------------|----------------|
| 速度系数 | 25/25（唯一非整数就是 2.5） | 无 |
| 攻速 / 攻击倍率 / 段数 / 档次 | 全部 | 无 |
| 霸体系数 | 25/27 | 2 例（2.3、1.1，即韧性带出的 0.1 小数位） |
| 成长系数 | 21/27 | 6 例（0.8、0.9、1.2、1.3） |
| 高攻低血防 | 20/27 | 7 例（0.8、0.9、1.1、1.2） |
| 高防低血 | 19/27 | 8 例（含 1 例 1.25） |

**取值网格只管连续解，速度系数不走它**：`snapMonsterCoefficient` 归档的是成长、血防、霸体这类由面板反推出的连续值；速度系数按 D15 直接定档，本来就是 1/2/3（跨档怪的手感半档由人工写）。体育老师是三方不合的样本：标识人工写 **2.5**、面板按 **2** 生成（取 2 时防御 MAX 残差 0.00%、HP MAX 0.42%、空手 MAX 0.03%，取 2.5 三处都涨到 3.4%~7.8%）、移动速度 50~75 的均值档是 **3**。定义优先之后工具不再替它改值，只报「定义 3 与人工给定 2.5 相差 0.5 档」，最终是改面板还是改速度区间由人工定夺。

## 7. 标识与数值不合时的处置原则

`<data>` 里的面板数值是运行时权威，`<标识>` 是它的溯源标注。两边对不上时按**标识是否齐备**分岔，不看哪边改起来省事：

| 情形 | 处置 | 理由 |
|------|------|------|
| 十项标识齐备（速度系数由 `速度_min/max` 定义即算齐备），面板与之不合 | **改面板数值**：按标识正算、按该行既有的取整粒度回填 | 标识是设计输入，数值是它的输出；补一个与速度对不上的速度系数等于把错处从数值挪到标识 |
| 只有面板数值、没有标识 | **反推标识**：阶段与速度系数机械可取，档次由人工给，F/G/H 要翻 XFL/FLA 观测 | 数值是唯一真源，标识此时才待补 |
| 标识像占位（例如除速度系数外全 1） | 不算「齐备」，回原表核对后按第二行处理 | 占位标识不携带设计意图 |
| 个别通道（如经验）与其余通道分歧过大，成长系数解不出 | 单独处理：可按各通道成长均值统一一个成长系数再重算数值 | 逐通道各说各话时，取均值重算比逐行手工凑更快收口 |

**取整粒度跟着该行自己的写法**，不是全局统一：25 行已标注实测，空手攻击与防御取整到 1，HP 取整到 100，经验取整到 100（早期行）或 1（`天网` 与 `僵尸新单位` 之后的行直接 `round(公式值)`）。半档数值（如 `325.5`）按 Excel 的 ROUND 远离零取 326。
已按此原则处置：`敌人-爆胖僵尸` 速度系数 2 → 1（定义档），数值由 105/323/8900/26000/315 重算为 115/351/10500/31100/326。回填后攻击/HP/防御六条通道最大偏差 0.43%，两条经验通道 1.5%~1.9%：经验公式里不含 速度系数，这一档偏差改前改后相同，属面板原有的粗填，不视为本次改动的残留。

## 8. 已知不可自动化的部分

- 档次系数 D：制作组按风格定档，工具只给排序参考。
- 攻速系数 F、攻击倍率 G、段数系数 H：要翻 XFL/FLA 数子弹、看频率与前摇后摇；持续攻击按 15 秒折算段数。
- 霸体系数 K 的整数位：看击退/击飞动画；工具只给乘子分支与候选值。
- 主线 >77 的阶段划分：诺亚前后、雪山尚未收口，`deferred` 行的阶段等划分规则定了再补。
