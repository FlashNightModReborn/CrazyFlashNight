# 统一窗口合成与输入归属：GPT-6 Pro 裁决准备

**文档角色**：路线裁决输入与证据索引；不是已采纳 ADR，不修改现役合同。<br>
**状态**：历史裁决输入；用户已手动提交并返回回执，后续以[分阶段施工与接班计划](../统一合成与输入归属-分阶段施工计划-2026-09-22.md)为准。<br>
**冻结源码基线**：commit `73c258af5d8df139cad3be3fed8d426eeae6de0b`。<br>
**范围**：窗口合成、输入归属、焦点与恢复；不施工、不提交、不推送、不干预天气发布列车。

本报告正文保留提交前的证据与提问口径；该范围描述当时材料整理任务。当前[原始裁决](../裁决存档/统一合成与输入归属-GPT6Pro原始裁决-2026-09-22.md)已归档，用户另行授权将规划文档提交推送，未授权本轮改运行代码。

## 1. 要裁决的决定

用户希望先保留天气光照卸载、GPU 后处理、动态分辨率与鼠标桥的现有成果，再重设计窗口合成；天气粒子、天空/地图拆分后置。需要决定下一施工阶段的拓扑、输入所有权、最小可玩的纵向样例和旧路径退休顺序。

核心问题不是“合成器是否能显示一张 Flash 画面”，而是：能否让玩家感知的单一游戏会话拥有明确的呈现、输入与恢复规则，同时保留 Flash、WebView2 和 AS2 领域权威。

**成功定义**：允许用户正常切出应用；失焦时无卡键或悬空手势；返回后的新输入可靠执行一次；画面、命中和业务状态不冒认彼此的完成。不能以更强的抢前台、自动重放复活/交易指令，或只减少 HWND 数量代替成功。

## 3. 当前技术与运行拓扑

源码事实以附件原始文件、摘录行号和 SHA-256 为准；历史文档中的阶段数字不作为机器真源。

| 对象 | 当前职责 | 对本次裁决的意义 |
|---|---|---|
| Guardian / WindowManager | WinForms 宿主、Flash 进程嵌入、窗口尺寸与焦点恢复 | 保留真实 HWND/进程边界，不能把一个进程等同一个会话 |
| Flash projector | x64 独立进程；AS2 玩法、部分功能 UI 与输入消费 | 当前鼠标桥有配对二进制要求；键盘、IME 与业务权威不能自动迁移 |
| WorldCompositor | WGC 捕获 Guardian、按 Flash 实际区域裁切、GPU 调色与输出 | 当前是独立 owned layered/noactivate 输出窗口；不是完整统一合成 |
| NativePointerBridge / InputBridge | 宿主转发世界鼠标；Flash UI 线程内映射鼠标状态、调用原窗口过程 | 已取得输入交付控制点；不等于 AS2 接受业务动作 |
| NativeHudOverlay | 主 HUD、对白、复活条件槽等；绘制、命中、手势与显隐 | 多实例存在，不能继续假设全局只有一个 HUD |
| PlayerHudRuntime | 底部、Buff、资源区多表面与相对层序 | 有意避免远隔矩形合成巨型 CPU 位图；合并 HWND 不应退回低效绘制 |
| HitNumber / DesktopCursor | 伤害数字与光标独立呈现 | 生命周期、层序和输入穿透也要纳入最终拓扑 |
| WebOverlay / WebView2 | WinForms WebView2、panel/idle 两套展示状态 | 当前没有完成 CompositionController 接入 |
| InputShield | 透明命中区域与 CDP 鼠标注入；panel 态主要做遥测 | 官方 composition 输入路径可成为替代候选，需逐项验证再退休 |
| PanelHostController | 面板开关序列、确切实例、暂停/恢复和视觉退场 | 应复用现有业务生命周期，不能平行新建第二面板权威 |
| AS2 领域服务 | StageRunSession、存档、奖励、技能/药剂等 | 合成与输入改造不改变持久权威和业务幂等性 |

构建基线为 `net10.0-windows`，WebView2 SDK `1.0.3856.49`、Vortice.DXGI `3.6.2`、SkiaSharp `3.119.4`；以附件项目文件复核。测试员那次 WebView2 runtime 为 `118.0.2088.46`，不能由开发 SDK 版本推断现场 runtime 支持全部 API。

当前两条主要路径不同：

```text
世界鼠标：物理输入 → WebOverlay 的低级鼠标钩子 → WorldCompositionSurface 队列
         → NativePointerBridge → Flash 线程内桥 → 原窗口过程 → AS2

复活操作：物理输入 → Native HUD 窗口命中/Down/Up → RightContextWidget
         → StageOutcomeTask → AS2 StageRunSession → 业务结果/状态投影
```

新世界鼠标桥不会自动修复另一条路径上的复活按钮。

## 4. 现场事实与不可推导项

- 23:04:43.207 的角色投影已经 HP=0；操作故障与复活后很快再次死亡需要分开评估。
- 23:48 的卡顿截图不在两份日志的覆盖范围内。不得用上一运行记录定因。

## 5. 静态发现：请 Pro 逐条复核，避免确认偏差

| 编号 | 代码事实 / 缺口 | 证据等级与待证问题 |
|---|---|---|
| F1 | 每个 NativeHudOverlay 构造均覆盖全局 `FocusWindowSnapshot.Hud` / `FocusTrace.HudInputSnapshot`；主 HUD 后又构造 bottom、buff | 确定的诊断归属缺陷；不能据此宣称它造成业务失败 |
| F2 | PlayerHudRuntime 只订阅 bottom/buff/resources 的 PresentationChanged，不订阅作为锚点的主 HUD | 层序维护覆盖不完整的静态线索；要求给出真正可达的重排序列，不能直接认领截图根因 |
| F3 | World PointerPacket 没有源事件时间、手势/场景/几何代次；已投递 Flash 的包不受清空宿主队列影响 | 可以构造迟到包验证；InputBridge 在 KILLFOCUS 清状态后仍能接收旧 down 并 SetFocus |
| F4 | NativePointerBridge.Send 忽略 PostMessage 返回值；宿主仍更新 deliveredButtons 和写 world_pointer 日志 | 确定缺少投递结果与接收确认；应区分尝试、入队、接收与业务执行 |
| F5 | 捕获 ready 只要求收到过合格尺寸与时间门槛之后的帧，没有持续帧龄条件 | 首次通过后停帧可能仍被判 ready；静态画面/暂停可能合法无新帧，不能机械按固定帧龄杀进程 |
| F6 | 世界输入复用安装在 UI 路径的低级鼠标钩子；换档同步等待呈现锁并调整 Flash 尺寸 | 阻塞与钩子超时风险；尚无现场钩子被移除的证明 |
| F7 | AppActivationState 有 200ms 去抖，OverlayBase 则按 Form Deactivate 立即压隐并取消手势 | 状态口径不同是事实；需要统一协调，不等于应删去失焦取消保护 |
| F8 | world 输入被消费时提前返回，不经过后面的 HookChainResult；现有链也未贯通世界包到桥接接收 | 诊断必须表达“本地消费/拒绝”，不能把缺少下游记录解释为下游吞事件 |

## 6. 候选路线，不预先宣布胜者

| 路线 | 主张 | 主要收益 | 主要风险 / 应证伪项 |
|---|---|---|---|
| A：先统一输入决策，暂保留窗口 | 建立唯一交互协调与表面身份，补输入证据和边沿保护 | 小范围先消除多方恢复冲突 | layered 命中与层序问题仍在；可能形成长期过渡架构 |
| B：先收拢 Native HUD 与输入 | 主 HUD/对白/玩家信息进入统一表面或视觉树，保留 Web panel 接法 | 直接覆盖遮挡和复活路径，缩小窗口图谱 | 全屏 CPU 位图/频繁上传可能退化；Web 接入风险后置 |
| C：先做 Flash + 一个 Web 面板的真实纵切 | 首先验证 WebView2 CompositionController、键鼠/IME 往返，再逐步接 HUD | 最早验证最大未知，复用已有绘制资产 | 首样覆盖面较大；不会立即消除所有 Native HUD 故障 |
| D：完整统一呈现与输入一次替换 | 同时改全部图层和输入端点 | 目标结构最直接 | 回归面过大、难隔离失败、易跨发布和持久业务边界 |
| E：替换 Flash 宿主 | 仅在实测证明 WGC/输入桥是不可跨越阻碍时研究替代宿主 | 可能改变透明度与输入能力边界 | 兼容性/分发/授权/时序/存档路径成本大；不是默认前置 |

现有[长期渲染 ADR §7.2](../launcher-渲染架构-长期决策-2026-05-21.md)倾向 C；本次较早的局部诊断曾倾向 B。请比较实际阻塞与最短可证伪路径，可组合阶段，但不要仅复述任一倾向。

## 7. 目标结构需要回答的具体问题

1. **可见主窗口与捕获来源**：最终由哪个 HWND 呈现和接收输入？Flash 子窗口放哪里、如何保持持续出帧？当前源捕获 Guardian，若未来输出也进入同一窗口，如何证明没有捕获自己产生反馈？不能假设把源隐藏/移出屏幕后 WGC 仍持续更新。
2. **GPU 图层承接**：是单 HWND 内多 visual，还是确实预合成为一张输出？二者分别解决什么，不承诺 Independent Flip/MPO 路径或固定性能收益。
3. **Native 资产复用**：INativeHudWidget、PlayerInfo 分块光栅缓存、伤害数字如何进入合成器？谁持有 CPU/GPU 资源、脏区、提交与失效？禁止把窗口合并等同每帧全屏 GDI 重画。
4. **WebView2**：CompositionController 的原生/托管接入、运行时支持、鼠标/触笔/滚轮、Capture、焦点、IME、拖放、可访问性、DevTools 与 renderer crash 如何接续？何时可以退休 InputShield/CDP 路由？
5. **输入唯一决策**：逻辑 keyboard owner、pointer owner、capture owner 应如何表达？复用哪些现役对象，避免与 PanelHost/AS2 状态机形成双权威？
6. **跨线程与代次**：由谁持有模式切换、手势序号、几何版本与迟到事件拒绝？消息收发失败、队列满、hook 被移除、Flash 卡住如何有界处理？
7. **真实键盘和 IME**：哪些情况必须保留 Flash/WebView 的实际 OS 焦点？不能用 PostMessage 键码成功代签 Key.isDown、长按、组合键与中文输入正常。
8. **恢复协议**：Alt-Tab、最小化、尺寸/DPI变化、DRS换档、转场、面板快速开关、进程/设备重建如何取消旧输入并恢复新输入？第一击用于激活还是执行业务，需明确产品语义。
9. **业务边界**：复活、返回、交易/奖励仍经原 intent/幂等/未知结果合同。画面恢复不能解除未知写锁；迟到点击不得自动重放。
10. **后续粒子/天空**：只预留必要的图层排序、坐标域、调色域、暂停/转场时钟及源能力；不要求现在实现透明 Flash、深度图、任意 provider 框架或新渲染引擎。

## 9. 要求 Pro 的输出

先给明确路线建议及成立条件，再给：

1. 事实纠错表：逐项复核 F1–F8，标注成立、收窄、不成立或材料不足；引用附件路径和原行号。
2. A–E 比较与选择理由，明确首步选 B、C 或其他顺序的判据，列出可能推翻建议的证据。
3. 一张窗口/进程/线程/GPU 拓扑图和一张输入时序图；标识真正的 owner，而非只画模块名。
4. 最小接口和状态边界：哪些复用、哪些新增、哪些退休；给复杂度预算，避免通用框架过度设计。
5. 最小可玩的纵切任务表：源码归属、输入输出、验收、失败后的收缩/回退策略。不要在缺样本时虚构精确工时或收益百分比。
6. 明确能结构性消除的故障类别、仍依赖 Flash/WebView/OS 的类别，以及无法仅靠合成解决的业务问题。
7. 可执行的本地实验清单与最少人工动作，优先不用额外玩家现场就能证伪的部分。
8. 最多列出真正影响路线选择的未决问题；能从附件确认的机器事实不要再让用户转录。

- [PostMessage](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)：成功只是入队且可能失败，不代表接收或业务成功。
- [AttachThreadInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-attachthreadinput)、[SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)：跨线程输入共享和前台设置有约束，不能作为无条件恢复保证。
- [WGC CreateForWindow](https://learn.microsoft.com/en-us/windows/win32/api/windows.graphics.capture.interop/nf-windows-graphics-capture-interop-igraphicscaptureiteminterop-createforwindow)：按 HWND 建立捕获源；不据此承诺隐藏/屏幕外源持续出帧。
