## 1. 问题与收益

SharedObject 保存故障已多轮依赖“测试员操作 → QQ 转述/传包 → 开发机分析 → 再补采”。缺少同轮连续观察，使捕获窗口、实际槽位、文件身份和操作顺序反复成为盲区。
当前案件事实与原始证据定位见[调查文档](存档flush零IO故障-调查进展与证据链-2026-09-18.md#field-20260920)。

未知故障需要临时编写探针、检查此前未预见的资料，并在原机器上验证。逐项穷举诊断命令白名单会把每次新实验变成工具更新；将工具绑入正式游戏 runtime 又会增加发布等待。
本工具的收益是把机器可处理的环境检查、命令、传输、取证与交接交给 Agent，让测试员只承担一次会话授权及确实需要人的 GUI 操作。

## 2. 已确认的范围

- 位于 `tools/cf7-field-support/`，独立构建、版本化和分发；候选包是待双机验收对象，不能由本机通过外推现场可用。
- 面向维护者与受邀测试员之间的可信调试，不作为默认面向所有玩家的常驻远控功能。
- 支持通用命令、临时脚本和诊断产物的传输执行；不要求为每种探查内容重新发布固定业务接口。
- 首包使用成熟 tsnet 用户态组网/中继与 .NET 标准 TLS，不自研密码学或 NAT 穿透；这是 §8 记录的承载调整，通用命令能力不依赖 B 安装 SSH 服务。
- 测试员有独立、明显、始终可用的结束入口；开发者和 Agent 也可主动结束。
- 工具内提供 Agent → 测试员的问答与 GUI 求助，减少 QQ 往返。
- 开发机完成编码、编译和静态验证；被调试端先由维护者第二台开发机承担，工具验收通过后再进入真实测试员机器，不要求测试员安装完整开发工具链。
- 支持下一个 Codex 或其他 Agent 会话接管仍然有效的现场；已撤销权限不能由交接记录恢复。

首版只做单维护者、单目标机器、单有效控制者的闭环。完整桌面遥控、多租户支持平台、永久无人值守、QQ 账号接入、自动正式发布不属于本次交付。

## 3. 组成与责任

| 组成 | 责任 |
|---|---|
| 测试员端诊断助手 | 环境检查、一次性配对、本机授权和计时、执行任务、显示问答、独立结束入口 |
| 开发机连接代理 | 持有远程长连接、保管临时凭据、串行化控制、记录实验、提供本地 CLI |
| Agent CLI | 以结构化参数调用代理，返回可判读结果；不在命令行或输出中暴露凭据 |
| 组网/中继 | 解决跨网可达性；不是用户授权来源，不应因此自动取得明文资料 |

诊断助手独立于游戏进程及其 UI 线程。游戏重启或卡死不妨碍停止诊断；重启游戏也不等于关闭仍明确展示的诊断会话。
控制消息、心跳、问答和停止请求不得被一个长命令的输出或等待阻塞。

现有 [CF7 Agent Runtime](../tools/cf7-agent/README.md) 可参考凭据不回显、CLI 和生命周期处理方式，但其命名管道要求本机同用户、同 Windows 会话及提升级别，不能直接代理成远程身份。
新工具是独立、显式授权的诊断渠道，不扩张内置 Runtime/Wings 的权限，不通过旧特权 HTTP 绕过内置合同，也不把 SSH 可执行命令说成已取得 Flash 像素/输入能力。

## 4. 测试员与维护者旅程

### 4.1 测试员

1. 启动独立工具，检查游戏路径、依赖和网络；多个安装目录存在时明确选择目标。
2. 工具自动执行已说明的准备工作。需要安装、修改系统配置或提权时，先显示具体用途，由本机用户确认；不得静默覆盖既有 SSH/组网配置或新增永久账号。
3. 选择本次诊断范围和有效时间，点击“开始诊断”，生成一次性票据。
4. 点击“复制票据”或导出票据文件，通过惯用的 QQ 等聊天工具手动交给维护者。
5. 配对后显示开发者身份、剩余时间和当前操作；收到 GUI 求助时可以回答、拒绝、稍后处理或结束诊断。
6. 点击“立即结束”，工具立即拒绝新操作并撤销会话，随后显示本轮文件变更及恢复结果。

工具不登录或读取 QQ。首次系统确认/身份登录等不可自动化动作不承诺为零，但不得把端口、密钥、文件路径和逐条命令配置转嫁给无基础测试员。

### 4.2 维护者与 Agent

维护者把票据文件导入本机工具管理的私有目录，再向 Agent 提供文件路径。允许人工直接转交短期票据，但优先使用文件导入，避免秘密进入模型上下文和聊天历史。

能力合同如下，当前可用命令和参数以 [工具 README](../tools/cf7-field-support/README.md) 为准：

| 能力 | 语义 |
|---|---|
| `connect --ticket-file` | 严格解析票据、核验目标/开发者身份，兑换一次并建立连接 |
| `status` | 查询会话有效性、剩余时间、现场身份、当前操作及未结事项 |
| `exec` | 执行通用诊断命令或临时脚本，返回操作 ID、输出、退出状态和不确定性 |
| `put / get` | 传入探针与候选、取回必要证据，校验传输字节 |
| `ask / wait` | 发出具请求 ID 的问题，等待测试员回应或取消 |
| 实验准备/切换/恢复 | 对本轮文件替换、备份和恢复提供可复核包装 |
| `finish` | 请求本机撤销访问、终止受控任务并收束报告 |

问答示例：“请在游戏里点击一次保存，然后选择结果。”测试员可选“已点击 / 没找到 / 暂时不方便 / 结束诊断”，也可输入文字。
等待超时不算确认，回复不代替原生 flush 日志、真实落盘或 GUI 业务验收。文字作为不可信内容显示，不能执行其中的代码、链接或授权指令。
文件选择、认证、UAC 与安全桌面由人处理；不得向测试员索取账号密码或把安全弹窗自动点击能力纳入首版。

## 5. 票据与会话生命周期

### 5.1 两层凭据

一次性票据只用于配对：短有效期、不可猜测、严格 schema、绑定目标和一次性 nonce。开发者提供已验证身份及临时公钥的持有证明；票据不能因被另一个人抢先提交就静默绑定陌生操作者。
首次成功兑换必须原子消费，重复/并发兑换、过期或篡改均拒绝。

配对成功后，票据失效；活动会话由单独的短期授权维持，绑定目标机器、开发者身份、会话代际和本机有效期。不是“一条命令一个票据”。
密钥或票据不得进入 Git、命令行参数、普通日志、接班文件；秘密只在受保护存储/内存中处理，不能给所有用户永久安装同一个开发者公钥。

### 5.2 状态和结束条件

`未开启 → 准备环境 → 等待配对 → 活动 → 撤销/清理 → 已结束`

- 结束原因包括：测试员主动结束、开发者完成、控制连接确认断开、心跳超时、有效期到达、助手崩溃、注销或机器重启。
- 本机独立监护有效期与心跳；远端不能自行续期。网络失联只能在有界超时内识别，不能承诺物理断网零延迟。
- 撤销先停止接纳请求，再关闭全部相关通道与执行资格；最后删除临时认证材料并收束受控进程和文件状态。
- 旧会话不得在网络恢复、重启或换一个 Agent 后自动复活；重新接入必须获得测试员的新票据。
- 对心跳、会话和操作超时设置明确上限，具体值由实现中的单一配置真源维护并在 UI 展示；活动流量不能无限延长本机授权。

SSH 的密钥到期、删除密钥或单个通道关闭都不能独立证明会话和后台任务已结束。应管理本会话启动的进程树，并验证停止、异常退出和清理失败路径；Windows Job Object 是进程收束工具，不是任意代码的完整沙箱。
不得将玩家原本运行的游戏、QQ 或其他进程纳入无差别清理。通过系统服务等外部代理创建的任务须单独登记，不能假定它们自动属于子进程树。

### 5.3 跨 Agent 会话接班

开发机连接代理持有长连接，Agent 通过受保护的本地接口调用。Agent 对话结束不等于控制连接断开；下一会话可接管仍有效的连接，但不延长测试员授权期限。
一次只允许一个控制者执行命令，避免两个 Agent 并发改变现场；状态查询和结束入口保持可响应。
交接记录只包含案件标识、非秘密会话引用、运行身份、已做实验、结果、待核对操作、文件变更和证据位置，不含票据或私钥。
下一 Agent 必须先查询真实活动状态和未结写操作；交接文件是上下文，不是授权凭证。首包使用 CLI 连接代理保持 TLS 长连接，当前 Windows 用户/会话的本地命名管道调用不延长目标授权。

## 6. 信任与隐私的真实边界

本工具允许受信开发者以测试员授予的权限执行通用命令，不以固定文件/命令白名单限制所有未知故障的探查。
授权界面须如实说明：这些命令可能访问当前用户有权访问的资料；资料可能通过开发机交给模型服务分析；结束访问不能回收已经传出的内容，也不会自动撤销已发生的持久修改。

默认使用现场当前用户的普通权限，以保留真实 AppData/存储身份；不得为省事切换管理员用户而改变故障条件。需要提权的工具单独说明并由本机确认。
不采集与案件无关的资料；默认导出最少必要证据。命令输出、ProcMon 数据、全局 Flash 设置和崩溃转储可能夹带隐私，采集/上传前须考虑该实际范围，不能把“加密通道”等同“无数据外传”。
这次完整 `sys` 包包含其他站点设置，不能成为所有远程诊断默认整包采集的理由。

审计用于核对误操作、残留和数据去向；它不是阻止恶意已授权 shell 修改凭据、创建持久任务或另行传输数据的绝对边界。
威胁模型是受邀、受信但可能犯错的开发者与 Agent，加上不可信网络和可能泄露的短期票据；不能对用户宣传成可对抗拥有同等主机权限的恶意操作者。

## 7. 开发机到现场的实验部署

工具必须支持：**开发机编码/编译 → 上传 → 校验 → 临时部署/执行 → 采集结果 → 恢复或记录保留状态**。
脚本/探针迭代不要求重新发布工具，也不要求先完成正式游戏列车；工具本身仍需独立版本、来源/完整性校验及必要安全更新。

| 产物 | 现场处理 |
|---|---|
| 独立脚本/探针/辅助程序 | 放在会话临时目录，确认完整传输后执行 |
| AS2/Web/数据测试文件 | 在明确授权的文件范围内暂时替换；备份原件并记录原/新哈希、目标路径和使用进程 |
| C# Host/DLL 候选 | 采用符合现有合同的候选导入、完整性验证和候选入口，不直接覆盖正式 runtime |
| 最终正式修复 | 另按该产物的正常提交、发布和现场复验流程交付 |

现有 [candidate 入口](runtime-build-reproducibility.md#evidence-states) 限定规范目录、metadata、manifest 和运行身份；跨机候选导入需要适配与实测，不能假定任意搬运或复制 DLL 可用，也不能关校验凑通。
AS2 探针在开发机使用真实 Flash CS6 GUI 按所属目标编译，保留 BOM 与新鲜编译证据，不让测试员安装编译环境，不手工改 SWF。

实验部署包装至少做到：

1. 确认真实目标、当前进程/账户、基线文件和现有修改；上传至不可直接执行的暂存状态。
2. 校验完整内容和哈希，登记原件备份及本轮替换集合；处理对应进程/文件占用后再切换。
3. 运行时记录实际加载的文件、路径、PID/启动时间和构建身份；文件已上传不等于实际运行过。
4. 恢复只处理本轮登记对象。当前文件仍匹配本轮装入版本时方可按记录恢复；出现其他修改则保留现场与备份，报告冲突，不覆盖用户后续差异。
5. 写操作结果未知时先查操作状态和现场，不因断连、超时或换会话盲目重放。

断连立即撤权，不等于立即无条件回滚全部文件。工具应在本机按已授权、状态确定的恢复计划收束；清理失败保持可见，并在下一次本机启动时提示残留，不自动重连或恢复远端权限。
真实存档不作为通用文件替换目标；写测试使用专用 SO/克隆槽，原字节保全。因故障涉及路径/用户身份，不能将“换目录的最小程序成功”外推为原游戏保存链正常。

## 8. 实现选择与停止扩张点

首版分成三个可验证切片，保留一张主施工卡，不先铺多层子 Epic：

1. **接通并能结束**：环境准备、双机网络、票据兑换、连接代理、命令/文件通道、本机停止与失联失效。
2. **可完成一轮实验**：产物校验/临时切换/恢复、日志回传、问答、非秘密交接、单控制者接管。
3. **双开发机验收与独立交付**：维护者两台真实开发机上的完整使用旅程、异常矩阵、可验证发行包及使用/恢复说明；通过后再进入 #106 的测试员现场实战。

网络承载在首个技术 spike 中选定成熟组网或中继，比较首次人工步骤、普通 Windows 用户权限、会话撤销、依赖体积和维护成本。
Tailscale/tsnet、SSH over 私网、受控中继均是候选，不在没有双机验证时宣称某一方案已经接通。开通外部服务、使用凭据或安装软件须有对应授权。
工具可自动准备可逆环境，优先便携/自包含组件；系统级变更记录实际差异和关闭办法，不改写既有全局配置来省实现工作。

### 8.1 首包具体选择（2026-09-21）

维护者补充约束：测试员没有配置能力，工具应自行准备网络；实战可能跨半个地球，同局域网策略不能作为交付依据。源码采用集中大提交，构建/双机迭代不要求先提交；完整问答与 C# 候选导入保留在首包范围。

- GUI 使用独立 C# / .NET 10 / WinForms、自包含 Windows x64 ZIP；开发机用 CLI，测试员不安装编译工具链。
- MeshCentral 便携 Assistant 源码未提供其管理 CLI 的 `runcommands` 路径，不能把完整 MeshAgent 的能力直接代签便携端；首包不引入完整远程管理服务器。网络改用随包 Go `tsnet` 小组件，B 只接受该组件转发到 loopback 的 TLS；不安装系统 VPN/sshd，不开公网明文入口。
- tsnet 使用临时节点；首次申请链接由维护者在 A 机批准。B 无需管理账号、端口或密钥。A 首包使用已登录同一 tailnet 的系统客户端。没有可用的账号/ACL/跨网路线时不假装“零外部前置”；这些由维护者验收时落实，不自动开通服务或改策略。
- 配对票据固定目标 TLS 证书及短期秘密；开发者展示 TLS 客户端证书指纹，B 在窗口核对后才原子消费票据。网络加入并不授予诊断执行权。活动会话仍保留有界失联撤权；本轮未采纳“断网自动续接旧授权”的放宽建议。
- 长命令异步返回 operationId，问答/状态/结束独立响应；传输分块、最终哈希校验。首包不交付跨会话断点续传、多 Agent 并行修改或通用自动回滚。
- 临时文件恢复限定本轮登记对象，保护后续差异。候选按现有 manifest/metadata/完整性合同导入规范目录，启动继续调用现有 `automation/start.ps1` 与 bootstrap 校验，不覆盖正式 runtime。
- 本机使用真实 TLS、隔离文件和进程树测试；真实 producer 候选可做打包/传输/导入校验，但不等于游戏已执行。实际 tsnet 首次网络申请、双机路线、断网与候选业务旅程留给随包验收清单。直接启动 tsnet 申请网络身份的本轮检查被自动审批拦截（仅返回 `blocked by policy`），未绕过，不写成已实测。

维护者随后在 B 机明确开启 0.1.0 候选、完成网络加入并核对指纹。双机确认普通权限探针执行、上传/执行哈希一致及输出回传。B 截图暴露了填入选项后问答正文被压缩及授权说明截断，首轮选项回包不算问答界面通过。

0.1.1 改为正文保底高度、内容滚动与固定停止入口；维护者在 B 确认显示正常，完整文字回复明确本轮为同一局域网 Wi-Fi。随后完成专用 tmp 样本的替换/恢复/冲突保全、真实 producer 候选跨机导入、规范入口启动及目视正常关闭；保护存档和正式 runtime 的前后字节比较无变化，相关游戏进程已退出，开发者结束会话后代理退出。准确状态是局域网验收切片通过，候选仅到启动界面的 `candidate_executed`，不计为整卡关闭、业务 E2E 或正式发布。历史切片见 [验收记录](evidence/field-support-lan-acceptance-2026-09-21.json)。

维护者要求将新问题提示音/醒目提醒与下一轮不同网络验收一并进行；真实跨网/中继、主动撤销与断网/异常退出等剩余旅程仍待验证。原始机器信息、票据和现场输出只保留本地验收目录，不随文档公开。

0.1.2 将“不阅读 README 也能完成协作”作为下一轮用户旅程：GUI 固定显示当前步骤、操作人、下一步按钮与停止入口；网络申请、票据发送、身份核对、问答提交和结束恢复均有明确状态。每个新事项提醒一次，可分别关闭声音和后台提醒；后台提示不自动激活窗口，点击才定位当前有效事项，取消/到期会清理旧提醒。恢复入口自动发现本机登记的变更并保留冲突，不要求测试员选择 JSON。这些增强仍属于独立工具候选，具体操作见 [工具说明](../tools/cf7-field-support/README.md)，真实不同网络与听感/注意力结果按 [验收清单](../tools/cf7-field-support/acceptance.md) 记录。

构建入口、依赖版本、包清单、当前限制与可用 CLI 统一维护在 [工具 README](../tools/cf7-field-support/README.md)，双机步骤见 [验收清单](../tools/cf7-field-support/acceptance.md)。本 ADR 不复制动态产物计数与哈希。

0.1.2 的后续热点切片已通过 B 答复确认上游为手机移动数据，实际直连、隔离文件往返和前台提示音成立；后台提醒前连接中断。B 记录 `connection_closed`，不是按钮撤销或授权到期；旧 A 端只留 ended，无法恢复底层根因。0.1.3 因此补充两端结束诊断及 GUI 结束/重新准备状态，仍需真实链路复验，不将本机持续连接检查升级为跨网稳定性证明。切片见 [热点验收记录](evidence/field-support-hotspot-acceptance-2026-09-21.json)。

0.1.3 随后的真实双机复验中，B 运行身份匹配交付包，热点直连持续观察超过五分钟，隔离 1 MiB 文件往返哈希一致；测试员明确确认后台提示音、弹窗、不抢焦点及点击回到问题均正常。B 主动结束后，测试员确认结束标题、重新准备入口和旧等待文案清除，A 代理退出且 CLI 无法继续访问。该轮切片通过，详见 [0.1.3 热点与提醒回执](evidence/field-support-hotspot-013-acceptance-2026-09-21.json)；此前断连根因仍未知，中继/跨洲、长时稳定与完整 #105 验收保持未完成。

代码位于 `tools/` 不等于免于审查。独立工具按自身构建/测试/签名或完整性分发；若施工实际触及游戏部署闭包，仍执行对应 runtime 规则。

## 9. 首版验收与关闭条件

### 后续双机施工安排（2026-09-21 维护者决定）

- A 机进行实际开发和构建，B 机通过工具接收探针/候选、运行与取证。可在源码尚未集中提交时传递带身份与哈希的候选；阶段成果仍按维护者习惯集中提交，不要求每个试验都通过 Git 推送。需要模拟测试用户拉取更新时，再对明确提交做 Git 更新验证。
- 多条施工可以并行开发；共用 B 游戏目录、游戏进程或同一实验会话的修改与候选运行依次执行。下一 Agent 先读取活动状态和未结操作，不以换 Agent 为由重放未知写。
- 持续连接观察服从本次明确授权：默认 45 分钟、单次最多 120 分钟；到期或断开后重新配对，不延长旧授权或引入永久入口。分多次施工积累的时长与一次连续连接时长分别记录。
- 其余断网/异常退出、Agent 接班与争用、真实 B 静音/取消/到期等项目沿用 [既有验收清单](../tools/cf7-field-support/acceptance.md)，在相关施工触发时验证；中继和跨洲只按实际发生的路线计证据。0.1.2 的未知断连仍保留，后续若复现先取两端记录再判因。
- 本轮只提交工具源码、说明和已完成回执，不发布游戏 runtime，不提交工具 ZIP、网络状态、票据或现场原始日志。#105 保持开放、Status=待验收并归档；后续回执满足剩余条件时再恢复卡片或完成关闭，不另建重复跟踪卡。

### 9.1 自动验证

- [ ] 票据篡改、过期、重放、并发兑换、错误身份/目标均拒绝；首个成功兑换只能产生一份活动授权。
- [ ] 断网、心跳超时、到期、助手异常退出、注销/重启后旧授权无效；不会凭旧交接文件自动恢复连接。
- [ ] 长命令、持续输出和无响应任务不阻塞停止入口；结束后新命令/传输/问答请求拒绝，受控进程按归属收束。
- [ ] 文件传输不完整/哈希错误不能执行；替换前目标漂移拒绝；恢复冲突不覆盖新差异；中断后的写操作不盲重放。
- [ ] 凭据不进入输出、日志、Git 或交接文件；本地接口校验调用身份，网络输入和票据均按不可信数据解析。
- [ ] 问答请求 ID、迟到回答、拒绝、取消和超时正确关联；没有回复不会推进依赖人类确认的实验。
- [ ] 两个 Agent 争用控制、代理退出、接班时存在未结操作等情况下状态一致，单控制者规则有效。

### 9.2 维护者两台开发机验收（#105 关闭依据）

开发机 A 运行维护者连接代理与 Agent；开发机 B 运行实际分发形态的诊断助手，充当被调试的“测试员端”。由维护者按给普通测试员的中文指引操作 B 端，人工验收也由维护者完成，不要求真实测试员先承担工具验收。
使用专用测试目录、文件和存档副本，保留两台机器的既有环境；不得靠手工预装密钥、私下脚本或未声明的开发依赖跳过工具准备流程。

- [ ] B 端从独立工具启动完成准备、生成票据，经惯用聊天工具人工转交，再由 A 端导入；记录实际人工步骤、现有/缺失依赖处理和失败提示。
- [ ] A 端生成一个可识别探针，上传至 B 端执行，返回与实际路径/文件哈希/进程对应的证据；使用拟交付的组网/中继链路，不用单机回环或协议 Mock 代签。
- [ ] 记录实际网络拓扑及连接路线。至少覆盖一次真实跨网或中继路径；可让 B 端使用手机热点等可用条件。同局域网直连结果单独标注，不外推为已覆盖公网/NAT。
- [ ] Agent 发一次必要的 GUI 求助，维护者在 B 端完成/拒绝后，A 端收到对应结果。
- [ ] 下一 Agent 会话读取交接并接管尚有效的连接；B 端结束后再次接管被拒绝。
- [ ] 长命令运行期间由 B 端主动结束，核对本机撤销、远端拒绝、进程与文件收束；另覆盖真实断连的有界失效、助手异常退出及重启后的旧票据拒绝。
- [ ] 对至少一类临时文件替换完成备份、执行确认和恢复；C# 候选跨机路径若未实现/未验，必须明确记为未交付，不能声称实验部署全闭环。
- [ ] 工具版本、支持环境、启动入口、关闭/恢复说明和本轮结果进入工具 README；不把未来设计命令当成可用入口。

工具关闭凭证是上述自动验证与维护者双开发机工具验收通过，记录验收人、日期、工具包身份、A/B 环境、网络路径、各项结果和未覆盖范围。**不要求真实测试员预先签收工具，也不要求先查清 SharedObject 根因。**
首版不需要正式游戏 runtime promotion 才能完成；若实际实现引入该要求，需先显式调整范围与卡片完成条件，不能暗中追加整条游戏列车。

### 9.3 通过后的测试员现场实战（#106）

双开发机通过后，才向测试员提供已验收的工具包和简明操作说明，并按 §10 接续存档故障。首次现场接入核对环境适用性后进入真正的故障实验；不再要求测试员重复承担整套工具异常矩阵。
双开发机通过不证明无基础用户已经完成实测、不证明所有测试员环境兼容，更不证明本案根因或修复成立。现场若发现工具自身问题，按实际缺陷记录修复；工具与故障的验收结果分别保留。

## 10. 工具完成后回到存档故障

工具 #105 经维护者双开发机验收并交付后，维护者回到原排查会话继续故障 #106，测试员使用已验证的工具包提交新鲜票据；Agent 先查询会话有效性和现场变化，不复用旧票据或把旧样本当现役状态。
首轮目标是保全现役身份，在同一实验窗口里完成“启动前捕获 → 原生保存结果 → 同上下文独立小 SO 对照 → 新进程读回”。
根据结果再决定检查存储策略、实际文件访问、初始化状态或当前载荷；当前没有证据授权把某个方向写成根因。

原始诊断包、SOL、Flash 设置包和会话记录均保留本地，不随 issue 或 ADR 上传。故障的时间线、哈希、未完成实验与关闭标准继续归[调查文档](存档flush零IO故障-调查进展与证据链-2026-09-18.md#field-20260920)。
