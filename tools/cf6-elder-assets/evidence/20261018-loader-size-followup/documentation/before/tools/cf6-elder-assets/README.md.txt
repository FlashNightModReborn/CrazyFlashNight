# CF6 老头与老头机器人装配

本目录维护人形 R7、机器人 R7 和角色局部变形的确定性 XFL 装配。人形为阶段 8／档次系数 9，机器人为阶段 8／档次系数 20，默认先人形、再生成机器人。当前 R22 已完成维护者指定的 60–100 级强度矩阵；低等级不作为本轮通过条件。机器验证、玩家体验和正式 runtime 发布分别记录。

## 当前校准结果

60／80／100 级、两个对手、双方各三次共三十六场，实际 2 胜、34 负，无平局或超时，且每场恰好完成一次老头人形到机器人的交接。兽王按维护者追加口径逐场确认一形态濒死狂暴或已打穿一形态，并最终自然落败；不再以兽王终场净削血作为通过门槛。EXUSIAI 每组六场的平均与中位全链净削血均须在 50%–80%；维护者已明确允许少量胜局，各组仍须以落败为主。原始零胜局计划、口径变更及原口径失败判定都保留。

最终主线源码下重新完成四组真实 CS6 回归，共 2,671 项通过、零失败：老头行为及护盾、音频、玩家瞄准、十二个原生绘制点。十二张当前图像与 R21 对应图像逐像素相同；这次没有重新执行 805 点完整扫描。另有当前 C5 公共加载器下的大头完整十八场全胜，以及当前合并源码的九组 Host 定向测试 508 项通过。Host 早先全量测试的 120 项资源窗口前置失败仍保留，不用定向通过替代全量通过。

Host 测试另外封存实际源码与程序集。既有 C# 文件的 Git 换行差异单列，分别保留测试原件、提交对象和实际检出内容的哈希，并核对差异仅为换行；精确复现该次 Host 测试源码时使用封存原件，不把普通检出文件称为同一执行字节，也不扩改全仓格式。战斗资源、AS2 和原有执行绑定仍按实际检出字节严格核对。

汇总入口：[本轮证据](evidence/20261017-calibration/summary.json)。实际对战使用冻结 C5 加载器与 R4 隔离 Host 候选；后来合入的 AI 终端源码只做源码回归，未借此发布新终端功能。测试期间临时保持唤醒已结束，真实存档、原始失败和编译记录均保留。本包在提交前封存，实际 commit／push 以 Git 历史为准；未进行正式 runtime 发布。玩家手感、物理音频、弱机性能和标准入口体验仍分别待验收。

## 当前护盾与射击规则

机器人起手射程为 750，人形为 500。普通束与重束沿既有枪口和光束轴延长到局部 600 像素，画面与真实碰撞同源。普通红束第 29 帧发射、完整动作 44 帧，起手间隔 80 帧；重束第 35／47／59／71 帧依次发出 ×0.5／×1／×1.5／×2 波伤害，完整动作 106 帧、冷却 600 帧。第 11 帧起锁定方向与纵深，后续段不追踪，走出射线后可避开剩余段。

重束由有效红束易伤，或本人真实砸地命中后的 180 个有效帧窗口授权。砸地窗口绑定同一目标实例，不施加易伤；MISS、换目标、同名换代、目标死亡、本人死亡或到期都会失去资格。起手时至少一条资格须剩余 72 帧；持续阶段两条资格都失效或动作取消便停止剩余段。砸地倍率为 ×18，普通束为 ×3；面板由同一工作簿公式重算，不直接叠加旧面板。

连打真实命中盾容量为当前满血 5%；强度率从 1 级的 30% 平滑到 99 级的 12%，时限从 120 帧到 60 帧，超界取端点。砸地真实命中硬盾容量为当前满血 0.75%、强度率 10 倍、时限 120 帧。光束起手盾容量为当前满血的 `0.2 × min(0.6, 1 / (1 + (等级 / 20)^2))`，公式内等级限制在 1–99；覆盖普通束／重束完整 44／106 帧动作，中断撤回。各层先将实际攻击力乘 `55/43` 再应用各自强度率；光束强度率为 75%，最高 800。各层只管理自己的身份，不删除其他来源护盾。

机械应激盾按累计损失初始满血的每 5% 强制补充，实际转换 30% 所失生命，本层容量上限为初始满血的 7.5%。每个有效帧另补当前缺失生命的 1/6400，上限为初始满血的 1/6400；三十帧最大预算为初始满血的 0.46875%，仅损血 20% 时为 0.09375%。新补充合并本层剩余容量后重设线性衰减，不重复缩放旧容量；没有继续补充时 36 帧耗尽，持续刷新时不保证第 36 帧消失。它不治疗实际 HP，也不撤销触发击已经结算的吸血。所有单位使用相同伤害管线，没有对手名称、兵种或玩家身份分支，也没有按目标设置伤害上限。

## 动作与适配

| 形态 | 原动作 | 帧数 | 伤害触发帧 | CF7 行为 |
|---|---|---:|---|---|
| 人形 | 970 连射 | 53 | 13、21、29、37 | 四发锁定方向的穿刺子弹，每发空手攻击力 ×1 |
| 人形 | 972 刺击 | 34 | 7 | 物理近战 ×1，随后有界推进 |
| 机器人 | 994 普通红束 | 44 | 29 | 波属性魔法 ×3，真实命中施加易伤 |
| 机器人 | 994 派生重束 | 106 | 35、47、59、71 | 易伤或本人砸地命中窗口门控，波属性依次 ×0.5／×1／×1.5／×2、粗度 ×3 |
| 机器人 | 997 连拳 | 40 | 9、26 | 两次物理近战 ×1、各 0.5% 击溃，保留两次推进段 |
| 机器人 | 1007 砸击 | 62 | 37 | 物理近战 ×18、10% 斩杀和强击退 |

人形使用原 12／13 帧受击分支和 89 帧倒地恢复；独立人形死亡在原停止帧 31 注销。机器人使用 12／13 帧受击分支、不浮空；按当前大于 9 帧的观测规则属于长受击，结合韧性 40，霸体系数为 3.2。111 帧死亡演出由身体内部时钟完成。暂停、硬直和旧动作 token 不允许新增攻击。近战区域子弹、穿刺子弹、冲击和伤害结算均走现有 CF7 入口，没有直接扣目标 HP。

机器人近战在各招式接触前暂时持有刚体；普通红束／重束分别在完整 44／106 帧动作中持有刚体。两项分别保存和恢复原值，不减少伤害。普通红束前 22 帧可转向同一实例并每帧至多移动 3 像素对齐纵深，第 23 帧起锁定；重束第 11 帧起锁定并持续到末段。硬直、暂停、目标替换或旧身体不允许继续跟踪。踢击与砸击不获得光束的抗击退。普通红束第 30 帧、重束末段后的第 72 帧恢复原抗击退状态，因此收招期间仍可被水平推动；正常收招、中断或死亡恢复仍持有的刚体与抗击退状态。

身体使用收到的最新版矢量稿。共用刺刀 484 在原包仍为位图，本目录的 `bayonet.svg` 保留其原轮廓与配准，明确改为原生矢量；金色仍由原时间轴颜色变换产生。原位图枪口改用已装载的 CF7 枪火；机器人爆炸使用 CF7 小火焰爆炸的私有纯矢量副本，去掉原碰撞、脚本和音轨，伤害单独按一次性亡语结算。不把参考位图带入运行库。

两种形态各自持有独立地面阴影。身体、阶段过渡与阴影都跟随世界 Z；变形开始时清零真实被击移动所用的 `speed`，避免人形在过渡中继续滑行。机器人落地约束与阴影不会写入其他单位的同名公共阴影槽。

## 连续两阶段

人形默认 `老头变身=true`；显式 `false`、`0`、`"false"`、`"0"` 使用独立人形。非法值明确诊断并关闭变身。关卡人数留给机器人阶段结算，人形不重复掉钱；经验沿用标准死亡检测。

变形采用原 2008 的前 93 帧角色部分，换入当前两份 R7 分件，保留身体替换顺序和过渡碎片。原 94–283 帧全屏放大、主角立绘、场景跳转和音乐控制保存在原稿中，不执行为战斗单位脚本。这里不是完整剧情过场的接入声明。

第 93 帧只尝试生成一次机器人。继承位置、方向、等级、阵营和产生源；不继承旧 HP、MP、面板或 Buff。普通对象 token 绑定世界、父实例、身体和新实例，初始化版本及上下文一致后才显示后继、退出前阶段。返回为空、名称碰撞、身份丢失、上下文不一致或初始化超时均进入明确错误状态，不自动重放生成。

每个形态结束时的 `CF6_ELDER_COMBAT_END` 分开记录出招、发出接触判定，以及 `beamActual`／`heavyActual` 的实际命中段数与倍率和。后两项只由正式伤害结算确认的真实命中钩子记账，MISS、同发重复回调和旧射手不计入；多目标时每个光束段仍只记一次。倍率和不是累计损血，不能替代对手回血后的净生命交换。后继的 `CF6_ELDER_PHASE_READY` 则记录真实初始化的等级、血量和攻防，用于核对两阶段没有继承旧面板。

## 数值校准口径

单工作环境下，规划器按每场最大帧数和场间余量核算运行预算；若六场可能超过 P0/P1 的 15 分钟上限，就按阵营分成同一环境中的两个串行批次，每批三场。本轮在保留原规划的基础上，进一步拆成每批一蓝一红两场、共十八个串行批次，拆分前后的战斗输入逐项核对。每场 5,400 帧、每批 900,000 毫秒上限及重复次数保持不变。

当前采用 60／80／100 级、两个对手、双阵营每侧三次的完整 36 场；兽王逐场检查濒死狂暴或已打穿一形态，并自然落败。EXUSIAI 每组六场检查平均与中位净失血均为 50%–80%，允许胜局为严格少数，败局须占多数；无平局、超时或交接错误，老头只生成一次机器人。逐场最小／最大值、胜负和区间外场次照实报告，组内均值不能代替逐场结果。

兽王自身还有兽形，参考净削血仍统一使用两形态的固定满血总量：兽形未出现时保留其完整血量，已经出现则计入最终剩余血量。原斗兽汇总只加入已生成的后继，而且其满血值可能在采样前已经被击溃降低，因此其百分比保留为原始字段，不能混作统一分母。[analyze-arena.py](analyze-arena.py) 从执行时哈希相同的 XML 和等级公式计算固定总量，逐场核对首形态实测初始生命，输出新的分析文件；不修改原始回执、对手或斗兽运行逻辑。本轮复算须显式指定 `--expected-levels 60 80 100`，默认 30／60／99 仅为兼容历史分析。

[assess-arena-targets.py](assess-arena-targets.py) 在上述统计之外生成当前验收判定，输入为完整逐场结果、字面诊断、按战斗起止时间匹配的狂暴通知和用户改口径的授权补充。诊断按对手、等级、阵营和 runId 联合匹配，不把不同对手复用的 runId 当同一场。兽王的正向狂暴记录可来自受击回调或专属消息；二形态生成则明确记录为一形态已击败。零命中计数不推断从未狂暴，终场低血也不替代状态证明。旧净削血通过字段和新验收通过字段分别保留。

历史版本的对战仅证明其自身执行身份；当前结论由上述 R22 完整矩阵支持。阶段／档次保持用户指定的 **人形 8／9、机器人 8／20**；攻速、伤害倍率、段数、霸体系数来自上述动作和受击观测，未用面板反推替换观测。完整公式输入与输出见 [balance-inputs.json](balance-inputs.json)，由 [balance.py](balance.py) 生成。

自由分配采用人形成长 1、高攻低血防 2、高防低血 4；机器人成长 1.0、高攻低血防 2、高防低血 34。此次校准保持这些分配，只通过护盾、动作时序与实际招式倍率调整；高防低血分配用于延长物理交战并减少可被兽王吸血回补的生命总量。高防低血 34 超出公式工具的参考区间 0.1–10，是本候选明确保留给人工复核的分配选择；没有修改公式、参考区间、对手或伤害结算。
