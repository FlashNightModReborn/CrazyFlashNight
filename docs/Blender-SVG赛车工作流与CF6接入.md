# Blender→SVG 赛车工作流与 CF6 接入

**文档角色**：83 号赛车的绘制与 CF6 接入案例。运行、装配与测试命令见[车辆工具](../tools/cf6-vehicle/README.md)。

## 1. 固定镜头赛车

83 号双加特林赛车采用固定正交镜头。源模型由单图重建，隐藏面的推断和机械运动需要分开核对。
公开工程直接维护 A07 车辆库中的原生 XFL 矢量和相位。

历史主链为：

`GLB → Blender 网格/材质/纹理与固定镜头渲染 → 投影/语义明暗 → 轮组和枪管三维运动投影 → SVG → 可编辑 XFL`。

V11 是保形基线，恢复车尾暗壁、局部接触线、玻璃透明度并去除重复线；
V16 只联合简化四条静态明暗路径，不增加新运动几何，不代表全面美术升级。
本轮从**提供的冻结 SVG 和原生包**做检查与重包装，没有重跑整条主链。

## 2. 可以复用的经验

以下算法因果来自保全的工程记录；本轮复核后述结构范围，不将旧调查写成新的跨模型实测。

### 几何、明暗和设计图形分别核对

外轮廓一致不代表内部体积正确。旧车尾问题来自同材质墙面/地面合并，以及法线单光源分档忽略真实阴影与遮蔽。
V11 的固定镜头渲染引导恢复暗面；换相机、几何或照明必须重渲染，不能沿用旧亮度图。

R3 徽记和拉花是设计复用，不是后续版本从 GLB 自动恢复。再次追踪烘焙贴花会与保留图形叠加出双箭头。
透明度另行维护：风挡恢复为源 alpha 0.42，不等于颜色和 PBR 反射完全还原。

### 动画先审计转轴和运动角色

不能旋转按一个视角裁切好的整轮 SVG：遮挡切口和固定卡钳会错误地跟着转。
真实轮辐、轮毂标记和枪管使用三维运动后重新投影与可见性计算，固定件保持原绘制顺序。
深度槽中的枪管身份可能随相位变化；运行包装应驱动整个槽的帧，不能按静态枪管 ID 重排。

### 相邻色块共享边界

V16 使用有效平面分区的共享边简化，避免独立简化带来裂缝。参数不是最大像素距离保证；
局部节点比例、ZIP 体积和边段数不能换算成帧率。rejected 分支仅保留为历史代码，不进默认命令。

### 原生 XML 保留绘制上下文

提供的原生资产不仅有 `DOMShape`，还有承载成员、渐变或透明度的 `DOMGroup`。
重包装比较完整形状/组内容及绘制顺序，不能只按形状数量认定相同。
实例变换、颜色或滤镜超出当前 identity 包装支持时明确拒绝，不静默丢失。
原图层、同名内部层及固定卡钳位置保留；物理文件名使用短稳定名称，来源映射进入清单。

CS6 原位保存返回失败后，用显式新 XFL 路径另存，重开该路径可正常编译。写回会重整 Edge 节点和矢量编码。
本轮在接近 A07 的比例对照 32 个相位和静止姿态，约 200 万像素中有 198 处差异，全部相位可定位。
涉及编辑往返时，在目标尺寸复验像素并记录差异范围。

## 3. 原生装配与游戏接线

`CF6Vehicle` 的 `LIBRARY/Codex/Roadster83Offline` 是新车体和动作分件的原生编辑源。
`Visual` 为单帧总装，各运动部件使用独立的停帧 MovieClip。轮组、近枪、远枪分别驱动。
`roadster-profile.json` 保存轴距拟合矩阵、运动实例和时钟参数，装配器使用原车 29 帧状态封装和受击位移。
`Cf6VehicleService` 负责车辆运动、战斗与生命周期。`Cf6VehicleTimeline` 只递归推进带原作标量元数据的剪辑。
共享库通过 `things-new` 导入车辆，启动逻辑由 `asLoaderLogic` 提供。

## 4. A07 转动与命中反馈

### 真实旋转与原版玩法的边界

车轮按相对地面的路程与轮周长之比推进。A07 读取主角的实际 X 位移和 1791 沥青层的逐帧位移。
该层常规轴向位移约 19.1 原作单位/帧，末帧到首帧使用相邻区间的平均步长，将画面回卷与车轮路程分开。
两只近侧车轮的主要纹理每圈重复七次。巡航每逻辑帧约转 34°，超过轮辐间距的一半，因而容易显成倒转。
A07 在每帧 22.5° 至 36° 之间渐变到环状轮辐，固定卡钳与轮胎保留在各自绘制层。
后移时显示清晰轮辐，巡航时原生渐变环的权重约为 88%，前移时完全由渐变环接管。
减速时从真实距离累计的相位恢复清晰轮辐。
加特林保留 M134 的成功发射脉冲加速、无脉冲衰减规则，两枪分别计时，同枪六个深度槽共享相位。
每枪 150 ms 首颗成功入队后，按 50、100 ms 刻度补出两颗同向尾弹。普通路敌可被尾弹穿过，
Boss 的有效命中和扣血沿首颗的原车战扫掠。尾弹对 Boss 的真实接触只驱动 A07 显示层上的两帧短闪。
尾弹显示、容量和回收归对应车辆会话。Boss 段先筛选 X 轴重叠的尾弹，再用原扫掠计算接触，
墙体在尾弹出生时计算。曳光和短闪复用进场预绘的剪辑。

新资产一圈有 32 个相位，而 M134 系数使用其原动画帧单位，不能直接照抄。
提案从 M134 基础物品配置及脚本默认值提取计数参数，并绑定两处来源与共用控制器身份。
枪管按 M134 每 6 帧重复的可见周期换算，采用 2.4 圈/秒上限。32 相位的频闪以 A07 实景为准。
A07 候选保留 1803 的 29 帧状态和 1801 的 6 帧受击位移。一次持续放置使旋转主体跨射击状态常驻，
死亡关闭本次时钟，复活初始化，房间拆除仍经现有车辆会话清理。

### 尺度与枪口不是同一个缩放问题

`consumer-proposal.json` 使用审计轮胎中面轴心与原车两个轮槽拟合等比矩阵，并绑定相关源码哈希。
不用外侧轮毂盖中心替代轮轴，不重复乘章节世界倍率。

本轮两轮拟合后，新枪轴端点相对旧火焰元件注册点仍有约 26 个原作坐标单位的横向差。
这只是几何诊断：火焰注册点、子弹根坐标与子弹视觉子件偏移不同，不能当作可见端点或命中误差。
后续需对照原生画面协调三者，不能为对齐图片悄悄改变投射物碰撞、发射位置和玩法常量。

## 5. 验证与维护

装配和 AS2 各自用[车辆工具](../tools/cf6-vehicle/README.md#重建与验证)重新生成并校对。
原生车辆回归在 Flash 内核对后移清晰轮辐、巡航混合和前移环状轮辐，并配对重放 Boss 有效命中、投雷与击破。
A07 正常入口的画面由玩家试玩确认。更新形状、轮组或遮挡关系时，直接编辑车辆库的原生分件，再以 CS6 发布车辆库。
