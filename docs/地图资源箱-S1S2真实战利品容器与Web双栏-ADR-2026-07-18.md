## 1. 纠错结论与范围

截图对应 `data/stages/副本任务/夺取材料.xml | SubStage 5 | Instance 0` 的 `装备箱`。两条掉落区间 `强化石 5..10`、`强化石 25..30` 与画面中的 6、29 完全一致。它没有 S0 双 marker，而 S0 又强制只接受无奖励 `保险柜` fixture，因此旧 AS2 `装备箱` 小窗是现有实现的确定结果，不是 Web 加载偶发失败。

本切片只处理：

- AS2 一次物化、会话内可寻址的瞬态 loot container；
- `loot` 专用 Host route 与 Web “背包—战利品箱”双栏；
- 单向领取、权威关闭、明确放弃、丢 ack 只读对账；
- 初次 open、reopen、mount、navigation 与 socket failure 都保留同一 `ArrayInventory` / target anchor 并收束为 `LOOT_SUSPENDED`；空容器为 `CONSUMED`，anchor 已失效为 `EXPIRED`；任何失败都禁止调用 Flash 网格 renderer；
- 所有已准入箱体的正整数 `row/col` 网格意图由统一 shape classifier 接管；能力内走 Web，能力外显式 fail-closed；
- 生产 selector、协议、领域与回归自动门。

本切片明确不处理：

- S3 Lockbox 生产开锁；
- `row/col` 任一非正的资源箱、纸箱、隐藏资源点；
- 以射击破坏代替正常交互、或重写装备箱/生存箱的历史破碎时间轴；
- 旧资源箱 UI 资产的物理删除；地图箱运行时入口已不属于允许路径，但 `资源箱界面` symbol 仍被 `仓库界面` 复用，必须先拆分或迁移仓库再清理共享资产；
- 绕过 runtime v2 request、不同 signer/faultDomain quorum、policy receipt、strict verifier 或原子 promotion。

## 2. 不变量

1. 奖励只由 AS2 滚一次，Web 与 Host 不接收可重建奖励的真值。
2. 自动路由网格目标在完整预检和物化成功前不 kill；物化结果先挂到 `LOOT_COMMIT_PENDING`，再提交唯一 opening kill。
3. `chestSessionId ↔ lootContainerId ↔ ArrayInventory` 一对一；第二个 active flow 不得覆盖第一个。
4. 普通物品移动时保留原 `BaseItem` 对象引用，包括 `level/tier/mods/lastUpdate`。
5. 材料、情报、金钱、K 点等特殊资产必须先完整预检，再以可回滚事务提交；目标不能完整接收时 source 整格不变。
6. 只允许 loot → 玩家权威域；背包 → loot、swap、任意目标槽伪造和普通 discard 均拒绝且零副作用。
7. `close v1` 不扩 wire：`remainingCount<=0` 优先归一为 `CONSUMED`（包括 `abandon=true`）；非空 `abandon=false` 为非终态 `LOOT_SUSPENDED`，非空 `abandon=true` 才为 `ABANDONED`；场景销毁只有在无未决 journal/effects/transport flag 且可安全收束时才是 `EXPIRED`。
8. 写入 timeout、断线或回包损坏不得自动重放 claim/close，只能查询跨过相应 operation identity 的权威状态。
9. Host/Web 失败只允许恢复同一个已物化容器，禁止重新读取或重滚 `target.掉落物`。
10. `BoxInteractionArbiter` 六 preset 只做箱体领域准入且不得放宽；进入该领域后，所有正整数 `row/col` 都表达 Web intent，`col<=8 && row*col<=64`（含 `1×1`）进入 Web，超界或畸形正网格 fail-closed。只有 `row/col` 任一非正的 direct 箱继续地面掉落；XML/runtime rollout marker 不再是选择器输入。
11. 每次网格物化前冻结唯一 outcome bonus（`逆向`）和 exact PRD engine；数量 `span=max-min+1` 必须不超过 AVM1 `random(n)` 的 `2^31-1` 上界，超界在任何随机推进前 fail closed。
12. claim 的 destination 已落地、source 删除失败且无法证明回滚时必须保留 exact pending journal；Web/Host 不重放写，只以 causal `lootQuery` 前滚。scene cleanup 也必须先完成或证明回滚，不能直接清 journal。
13. 普通 X、Esc、backdrop 都是 `close(abandon=false)`：非空箱先形成权威 `LOOT_SUSPENDED` 再回游戏；只有“放弃剩余”及二次确认可发送 `abandon=true` 并进入 `ABANDONED`。
14. recovery control、detached proof 与普通 Web query 是三条独立 wire：严格八键 recovery、严格九键内部 proof query、严格七键普通 query；proof identity 不得投给 Web，也不扩 AS2 15 键 / Host 20 键 response。
15. Flash 网格 renderer、claim-only adapter 与 observer recovery 都不是当前产品恢复路径。初次/重开/断线失败统一保留同一 inventory/anchor 并进入 `LOOT_SUSPENDED`（空→`CONSUMED`，anchor 失效→`EXPIRED`）；已经物化后的异常若 exact journal/effects/proof 未收束，继续停在 `LOOT_COMMIT_PENDING`，不得借旧 UI 绕过。
16. Host/Web 各自维护独立 freshness watermark；只有 matching pending call/identity 的畸形或未证明更高 revision 才抬高该 unknown operation 的水位且不覆盖 known authority，其他 call/identity 不得抬高，后续 proof 不得低于该水位；普通七键 query 不增加 `reconcileAfterCallId` 等 wire 字段。claim success 必须精确证明 revision `+1`、remaining `-1`、operationId 命中与 requested slot 为空；close success 必须精确证明 revision `+1`、本次 operation 与 close 意图对应的 expected state / remaining。capacity failure 只有 strict raw failure shape、exact current binding 与完整 known prestate 同时成立，且已知 revision、remaining、lastAppliedOperationId、`closeLease`、`containerVersion`、requested slot 与 slot lease 全部不变时才可跳过；错误名本身不是证明，Host 只在该 exact prestate 下保留已知 `closeLease/containerVersion`。
17. scene teardown 是 authority barrier：`SceneManager.removeGameWorld():Boolean` 在 `expireScene()` 未成功时必须在任何 inactive/dispose/dispatcher/gameworld teardown 前返回 `false`；淡出时间线停止且只排一个下一帧重试，pending 收束成功后才继续播放。`cleanupForRestart():Boolean` 也必须在任何 manager dispose 前先做 loot preflight，失败时保持整个 runtime 原样，禁止半清理。
18. ordinary `target_full / inventory_full` 只打开同一 tracked `loot` panel 内的嵌入式 organizer。子页全程保持 exact `panelInstanceId`、Coordinator `Bound`、原 pause lease 和 AS2 `LOOT_ACTIVE`，不发 `lootClose`、不切换 panel、不借道 AS2 HUD。库存 settled 后仍必须取得 fresh `ACTIVE` loot snapshot 才可返回主页；失败留页且绝不 replay 写操作。

## 3. 生产选择器

生产选择器分成不可互换的两层：先判断地图元件是否属于箱体领域，再对已准入箱体读取旧容器 shape。六 preset 只承担第一层，统一 shape classifier 只承担第二层：

```text
地图元件
  ├─ 不在六 preset 箱体白名单 ─→ 保持非箱原路径（不得仅凭 row/col 劫持）
  └─ 已准入箱体                ─→ 统一 shape classifier
       ├─ 正整数且 col <= 8、row*col <= 64 ─→ Web loot reservation（1×1 有效）
       ├─ 超界或畸形                           ─→ fail-closed（不 kill、不滚奖、不显示 Flash UI）
       └─ row、col 任一非正                    ─→ direct 地面掉落
```

`target.presetName` 的六值白名单只用于箱体领域准入；准入后，当前恰有的 `2×4 / 4×4 / 4×8` 只用于资产审计与代表性 E2E，不参与 Web shape 选择。`chestRolloutId / lootFlowProfile / unlockPolicy` 已从生产 XML 与运行时路由权威中移除；不得通过重新注入 marker 恢复单-canary 或旧 UI 旁路。

能力内网格还必须通过掉落规则、S0 排他、active/reservation 唯一性与 authority 预检；失败时保持 target 可诊断且不 kill。掉落规则中的 `最小数量/最大数量` 若任一缺省，由 planner 私有归一为 `1/1`，不要求批量改写生产 XML；显式值仍须为合法正整数，且 `最大数量-最小数量+1 <= 2147483647`。当前生产集合由审计从 XML 实际结构推导，不是运行时白名单；审计应展开允许的单层难度 `CaseSwitch`，验证物品目录闭包、概率、有效数量区间与可选总数，不能把互斥分支误计成同时奖励。

## 4. AS2 权威状态机

```text
AVAILABLE
  └─ supported positive grid + no active flow ─→ LOOT_COMMIT_PENDING
       ├─ 未物化且不可恢复的 pre-commit 失败 ─→ EXPIRED（不暴露半份奖励）
       ├─ 已物化但 journal/effects/proof 未收束 ─→ LOOT_COMMIT_PENDING（硬栅栏）
       ├─ 初次 open Web/Host failure ─→ LOOT_SUSPENDED（空→CONSUMED；anchor 失效→EXPIRED）
       └─ own-kill + open-frame 成功 ─→ LOOT_ACTIVE
             ├─ remaining <= 0 + close ─→ CONSUMED
             ├─ remaining > 0 + close(abandon=false) ─→ LOOT_SUSPENDED
             │    └─ same scene + exact target anchor reopen ─→ LOOT_ACTIVE
             │         └─ 任一 reopen failure ─→ LOOT_SUSPENDED（空→CONSUMED；anchor 失效→EXPIRED）
             ├─ remaining > 0 + close(abandon=true) ─→ ABANDONED
             ├─ safe scene/authority teardown（无 pending）─→ EXPIRED
             └─ accepted Web/Host detach ─→ LOOT_COMMIT_PENDING + persistent transportDetach
                  └─ exact journal/effects/pause proofs ─→ LOOT_SUSPENDED（空→CONSUMED；anchor 失效→EXPIRED）
```

`LOOT_COMMIT_PENDING` 有三个不可混淆的阶段：opening reservation 尚无 `pendingCommit`；claim 双资源写在 exact `pendingCommit` journal 存在时禁止任何 UI 暴露；transport handoff 以持久 `transportDetachNeeded` 封锁所有旁路。只有未物化、没有可恢复 inventory 的 pre-commit failure 才可进入 `EXPIRED`。一旦完成物化，初次和重开故障都保留同一 inventory 与 target anchor；exact journal/effects/pause proof 收束后统一进入 `LOOT_SUSPENDED`，空为 `CONSUMED`，anchor 失效为 `EXPIRED`。不得清空来源、重滚奖励或调用 Flash renderer。

claim 提交 journal 冻结 operationId/fingerprint、source exact item/slot，以及 ordinary empty/merge、scalar 或 collection destination 的 exact before/after。destination 写 API 返回 false/throw 不能直接解释为未写；只有观察到 destination-before + source-present 才可清 journal 回到可服务状态。destination-after + source-present 保持 `LOOT_COMMIT_PENDING`，`lootQuery` 按同一 journal 只前滚 source 删除。成功 operation journal 写入后，dirty 读回验证、loot lease cache 与 destination cache 失效是分段幂等的 mandatory effects；全部完成前仍为 `LOOT_COMMIT_PENDING`。transport detach 先持久化 flag；一旦 exact recovery nonce 已登记，只有严格九键 proof query 可推进，普通七键 query 只能得到 `commit_pending`。初次 open 与 reopen 都只执行 journal/effects 和 suspended/terminal pause handoff；任一必要阶段 false/throw 都只重试未完成阶段。claim/close/snapshot/tooltip/scene terminal 均不得旁路，并按子事件至多发布一次。

Flash 网格 UI 不再拥有正常入口或故障恢复入口。`LOOT_SUSPENDED` 是玩家普通 X、Esc、backdrop 以及 Web-only transport failure 后的非终态：仅同一 scene、同一 target anchor 的再次互动可复用同一 triple/inventory，重开必须重铸 `closeLease`、`panelInstanceId` 与 `openAttemptSeq`。初次与重开失败都只能收束为 suspended/terminal。场景离开只有在 `expireScene()` 成功后才可继续 teardown；pending 时必须保留整个 authority/world 并单飞重试。

## 5. 冻结 wire v1

### 5.1 打开面板

AS2 只发送：

```text
task = panel_request
panel = loot
source = map_chest
initData = {
  v, chestSessionId, lootContainerId, containerEpoch,
  openAttemptSeq, displayName, capacity, columns
}
```

AS2 `initData` 严格八键；`openAttemptSeq` 是正整数 attempt 因果身份。Host 在 `OpenRequest/Binding` 保留它，生成 `panelInstanceId` 后投 Web 时剥离它，所以 Web initData 仍严格八键 `{v,chestSessionId,lootContainerId,containerEpoch,displayName,capacity,columns,panelInstanceId}`。open payload 不含物品、数量、概率、掉落规则或经济指令。

### 5.2 Web → Host → AS2

顶层 task 为 `loot_request`，版本固定 `v=1`。所有命令共有且只共有 11 个键：`{type,task,domain,panel,v,cmd,callId,panelInstanceId,chestSessionId,lootContainerId,containerEpoch}`；Host 要求 `type=task`、`task=loot_request`、`domain=panel=loot`，并用当前 binding 重建发往 AS2 的身份。动作与 AS2 action：

| cmd | AS2 action | 必需业务字段 |
|---|---|---|
| `snapshot` | `lootSnapshot` | identity、epoch、loot/backpack window |
| `tooltip` | `lootTooltip` | identity、epoch、source slot ref |
| `claim` | `lootClaim` | identity、epoch、operationId、`direction=loot_to_player`、source ref、`targetContainerId=背包` |
| `close` | `lootClose` | identity、epoch、operationId、closeLease、abandon boolean |
| `query` | `lootQuery` | 无额外业务字段；Host→AS2 严格七键 |

额外键严格为：`snapshot={loot:{offset,limit},backpack:{offset,limit}}`；`tooltip={expectedAuthorityRevision,source}`；`claim={expectedAuthorityRevision,operationId,direction,source,targetContainerId}`；`close={expectedAuthorityRevision,operationId,closeLease,abandon}`；`query={}`。普通 Web `query` 经 Host 重建后的 AS2 wire 必须严格为 `{task:'cmd',action:'lootQuery',callId,v,chestSessionId,lootContainerId,containerEpoch}` 七键，不能携带 `openAttemptSeq/recoveryNonce`。`source` 又严格为 `{containerId,slot,expectedLease,expectedContainerVersion}`。Host 必须验证当前 active `loot` panel、exact `panelInstanceId`、identity 与字段白名单，再转发给 Flash；Web 请求不能携带 `source=map_chest`，该受信 source 只存在于 AS2 打开面板信封。queue accepted、消息已 post 或 native 窗口存在均不等于 Web 已绑定。

### 5.3 AS2 → Host → Web

Flash `loot_response` 使用固定 15-key 顶层 union，每次都包含：

```text
task, callId, success, error,
chestSessionId, lootContainerId, containerEpoch,
authorityRevision, lastAppliedOperationId,
state, remainingCount, closeLease,
snapshots, tooltip, terminal
```

Host 校验后发给 Web 的 `panel_resp` 严格为 20 键：上面 15 键，加 `{type,domain,panel,cmd,panelInstanceId}`；固定 `type=panel_resp`、`task=loot_response`、`domain=panel=loot`，`callId` 换回对应 Web callId。该信封没有 `v`、`source` 或奖励配置字段，额外键一律拒绝。

- success 时 `error=''`；失败时不得携带猜测性 mutation；
- 非 tooltip 回包 `tooltip=null`；
- 非终态 `terminal=null`；
- 无 snapshot 时 `snapshots=[]`；
- active snapshot/query/claim 返回 `[lootSnapshot, backpackSnapshot]`；
- `CONSUMED/ABANDONED/EXPIRED` 的 close/query-terminal 返回空 snapshots；`LOOT_SUSPENDED` 也是非终态成功投影，`terminal=null`，旧 closeLease 已失效，等待同 anchor 重开时签发 fresh lease/instance；
- `terminal={kind,reason,remainingCount}`；
- `closeLease` 只在 active 权威投影中有效，终态或错误为空串。

### 5.4 Host → AS2 recovery control

Host 只可为当前 exact accepted visual binding 发送严格八键扁平命令 `{task:'cmd',action:'lootPanelRecovery',chestSessionId,lootContainerId,containerEpoch,openAttemptSeq,recoveryNonce,reason}`。`recoveryNonce` 是 Host 生成的 opaque 因果值；`reason` 只允许 `web_mount_failed | web_open_failed`。不得夹带 `panelInstanceId`、奖励字段或额外键，nonce/attempt 也不得投给 Web。AS2 在三元 identity 与当前 attempt 精确命中时可先登记 exact nonce；若 accepted callback 尚未被 AS2 观察，只返回 `recovery_pending`，不得提前推进 transport，callback 到达后才继续同一 proof。旧 attempt、零/坏 attempt、stale、terminal、畸形、nonce 冲突或未知 reason 都是零副作用。reopen 发出前先登记 opening pending：pre-accept 拒绝、同步发送失败或异步打开失败撤销 pending 并恢复 `LOOT_SUSPENDED`；只有 accepted 后的 exact-attempt 故障才允许 ForceDetach。该命令不是 `lootClose`，不能生成 `ABANDONED`；reopen 收束时 inventory 已空可为 `CONSUMED`、anchor 失效可为 `EXPIRED`，其余必须回 `LOOT_SUSPENDED` 且不显示 legacy renderer。

recovery 写入后，Host 只能发严格九键内部 proof query：普通七键 `{task:'cmd',action:'lootQuery',callId,v,chestSessionId,lootContainerId,containerEpoch}` 加 `{openAttemptSeq,recoveryNonce}`。该 query 不由 Web 发起，结果不投回已销毁 Web，且 AS2 response 仍严格 15 键、Host projection 仍严格 20 键。pending proof entry 捕获 exact binding/attempt/nonce/generation；只有该 entry 收到通过 sanitizer 的 `success=true` authority projection 才可 settle detached flow，`success=false` 的 terminal-like 回包不能冒充成功。普通七键 query 不得推进已登记 proof 的 transport fence。

AS2 的 completed recovery proof ledger 有界保存旧 attempt 的 authority-closed / connected / socket proof。只有更新 attempt 的 accepted callback、exact recovery command 或 exact proof query 能剪除严格小于该 attempt 的历史；迟到旧 query不得清同代或更新 proof。容量已满且无法安全剪枝时 open/close 以 `recovery_history_full` fail-closed，禁止盲目 LRU。Host fresh admission 同样 fail-closed：`LootTask` 持 admission lease 期间才允许 Coordinator 原子安装新 binding；旧 flow 仍为 write-unknown、detached reconcile、native close 或 pause-release 未决时，新请求返回 `flow_busy`。

## 6. Web 交互与恢复

- 使用 canonical `transfer-pair` profile 和共享 `PanelResponseRouter / PanelRequestMux / PanelLifecycle / DisposableStack / FocusScope / Workbench` 组件，不安装第二个 response listener。
- 左侧背包、右侧战利品箱；右侧容量按 snapshot，不分页。
- pointer、双击/快捷收取与键盘必须走同一个 claim intent；disabled 只作 UX，AS2 仍复核方向和容量。
- ordinary `target_full / inventory_full` 显示“整理背包”并打开同一 loot DOM 内的背包—战备箱子页。子页不调 `close`、`Panels.open('workbench')` 或 `WAREHOUSE`；只允许背包↔战备箱 `autoTransfer` 和经二次确认的背包整格 `discard`。X/Esc/backdrop 在子页时优先执行“返回战利品”；必须等 inventory ready、无 busy、无 `refreshRequired`，再以 fresh `snapshot` 证明 `LOOT_ACTIVE` 才可返回主页。任一同步失败留在 organizer，不 replay claim/close。
- organizer 的 inventory request 顶层恰为七键 `{type,domain,panel,cmd,callId,panelInstanceId,payload}`，固定 `type=panel/domain=inventory/panel=loot`，只允许 strict `snapshot/autoTransfer/discard` payload。Host 必须用 `LootPanelCoordinator.IsBoundVisualExact` 在同一锁内原子证明 state=`Bound`、active binding、PanelHost 与 exact instance，回包回显 `panel=loot` 及同一 instance；旧/畸形请求 fail closed。loot 占用 PanelHost 时，任何其他 panel 的 foreign `close` 必须隔离，不得关闭 loot 或释放其 pause。
- loot **主页**的正常 close 仍先取新鲜权威投影并复用 close v1：空箱归一提交 `CONSUMED`；非空右上 X、Esc、backdrop 发送 `abandon=false`，形成 `LOOT_SUSPENDED` 后关闭 visual binding 并回游戏；只有独立危险动作“放弃剩余”及 focus-trapped 二次确认发送 `abandon=true` 并进入 `ABANDONED`。`LOOT_SUSPENDED` 仅允许同场景同 target anchor 重开同一 triple/inventory，且重开使用 fresh closeLease/panelInstanceId/openAttemptSeq；reopen 任一失败都不得回弹旧 AS2 UI。
- claim/close 回包未知时进入 `reconcile_required`，只发 query；不能重放原 operationId 写入。Host/Web 各自的 freshness watermark 只吸收 matching pending call/identity 中畸形或未证明的更高 revision，且不覆盖 known projection；其他 call/identity 不得抬高水位，后续 proof 必须至少达到水位且不能回滚模型，普通七键 query 不增加 `reconcileAfterCallId` 等 wire 字段。direct claim success 只接受精确 `authorityRevision +1 / remainingCount -1 / operationId / requested-slot-empty`；direct close success 还须精确 `revision +1 / operationId / expected state / remaining`。capacity failure 只有 strict raw failure shape、exact current binding 与完整 known prestate 同时成立，且已知 revision、remaining、lastAppliedOperationId、`closeLease`、`containerVersion`、requested slot 与 slot lease 全部不变时才可跳过；错误名本身不是证明，Host 只在该 exact prestate 下保留已知 `closeLease/containerVersion`。
- ForceDetach 只销毁已被 Host 接受的视觉 binding，不发送 `lootClose`、不猜终态；它只用于 accepted 之后的 mount/navigation/socket/Host 故障，不能替代正常的 `LOOT_SUSPENDED` close，也不能用于 reopen 接受前失败。初次与重开 proof chain 都禁止 renderer，统一回 `SUSPENDED/CONSUMED/EXPIRED`；两者都不重做经济写、dirty/event，不提前放 pause。
- Host 对 queue accepted / `OpenPosted` 后仍未收到 exact bind 的窗口使用 generation/identity-bound、默认 2500ms 的 bind watchdog；超时、mount/open failure、导航或断线只占用一次 recovery signal。`PauseReleasePending` 必须保留 exact coordinator-owned binding并只允许 scoped retry，不能用 generic unpause、提前回 Idle 或解除另一面板的 pause；完成前 fresh admission fence 保持关闭。terminal 与 force-detach exact native close 的 enqueue false、completion false/丢失都必须以有上限的指数退避自主重试，直到 exact `PanelClosed` 或 Host teardown。
- socket replacement 必须先保留更高 generation，再对旧 generation 发布 disconnect，最后发布新 generation ready；frame ownership 同时复核 generation/client/stream，每代 disconnect 至多一次。replacement disconnect 是过渡，不得误判为 prewarm failure 或 Ready zombie；同代自然 EOF/force-close 才是实际掉线。recovery 写失败只能关闭发送时捕获的同一 generation，旧 frame/completion 不得影响 replacement，也不得跨代 PostToWeb 或释放 pause。
- 重复 open/close/query、迟到回包与旧 panel instance 均须幂等或零副作用。

## 8. 发布与回滚

源码通过不等于当前运行时已修复。若改动 Launcher Host/Core，仍必须：
