# 地图资源箱 S0 无奖励编排 ADR（已退役）

> **SUPERSEDED / REMOVED**

**决定日期**：2026-07-22

**状态**：实现、生产接线、开发门、专项测试与发布资产要求均已物理删除。
**当前基线**：[地图资源箱 → Web 战利品工作台·实施与验收基线](地图资源箱-Web战利品工作台与开锁流程-前期调研-2026-07-17.md)

## 决定

地图资源箱不再保留 Lockbox S0 无奖励编排。所有属于六类地图箱且具有合法正整数 `row/col` 的正常交互，只能进入 `LootContainerService` 与 Web loot panel；不得在它之前插入第二套 session、socket bridge、Host coordinator、Web bootstrap、feature gate 或 dormant wire。

本 ADR 是墓碑，不是可执行规范。旧测试 ID、命令、退出门和回滚步骤均已撤销；需要追溯时使用 Git 历史，不得从历史提交复制代码回当前树来“补门”。

## 为什么退役

S0 原本用于在真实奖励接入前验证无奖励 Lockbox 纵向切片。真实 loot authority 完成后，它变成了第二套跨 AS2、Host 与 Web 的并行状态机：

- 手工打开开发门即可绕过真实奖励、claim、挂起与恢复链；
- dormant fallback 会把 Web/Host/focus/protocol 缺陷伪装成另一条“可用”路径；
- 两套 identity、pause、close、reconcile 与发布门产生重复维护；
- 为尚未立项的开锁玩法预埋生产代码，不能证明当前地图箱迁移正确。

项目仍处于本轮全正网格迁移的开发测试阶段，没有兼容旧 S0 行为的上线负担。删除比保留关闭开关更容易暴露真实故障，也更符合单一权威边界。

## 当前边界

- 合法正整数网格：唯一 Web loot 路径；失败显式 fail-closed，不显示 Flash 箱 UI、不重滚、不静默改成地面掉落。
- 精确 `0×0`：维持既有直接地面掉落；这是玩法语义，不是 UI fallback。负数、单边零、混合或缺字段均为配置错误并 fail-closed。
- 攻击破碎：维持既有地面掉落；authority guard 先阻止同一箱重复发奖。
- 普通 Lockbox 小游戏：作为独立 minigame 保留，与地图箱奖励协议无业务接线。
- 旧 `资源箱界面` symbol：地图运行路径不可达；因仍被仓库界面复用，本轮不物理删除共享资产。仓库迁移或拆分后再单独清理。

## 防回归要求

当前测试只保留负向门：

- 生产 AS2、Launcher Host 与 Web 中 S0 类型、marker、文件名和环境开关引用为零；
- 生产关卡中 S0 双 marker 为零；
- 地图箱运行路径不得引用 Flash `资源箱界面`、claim-only adapter 或 observer recovery；
- 普通 Lockbox QA 独立通过，证明删除 S0 没有误删小游戏本体。

这些门由当前 [测试指南](../agentsDoc/testing-guide.md) 与 `tools/test-map-loot-wiring.ps1` 定义；本文件不复制命令或计数。

## 历史证据边界

旧 promotion commit `6218f8b1d82efc57b77131616667fe45f3033297` 曾包含 dormant S0 字节，但双门关闭且没有完成 S0 actual-feature 跨栈验收。它只保留为历史审计输入，既不证明现行树，也不构成恢复 S0 的理由。

未来若确实立项开锁玩法，必须另建 ADR、独立协议和最小验证矩阵，并以不绕过 `LootContainerService` 为前提重新评审。
