# 跨平台素材绘制管线

**文档角色**：持续维护的素材跨平台分工、迁移缺口与复用经验；工具命令仍由各工具 README 维护。

**最后核对代码基线**：commit `ae80ef16a490dcbb8749330a847a7fd64e16d93b`（2026-10-14）。

Linux 可承担参考提取、矢量绘制、离线动作预览、XFL 候选装配和静态检查；当前 CS6 发布、Flash 原生采样与真实游戏验证继续在 Windows 完成。克隆兽首件已在 Windows 完成上述制作链，Linux 与 dot 尚无本管线的实际运行结果。这里记录可迁移的代码依据和待补步骤，不把可行性判断写成跨平台已跑通。

准备把素材制作移到 Linux、dot 或其他云端节点时读取本文；找到所需阶段、工具及验证边界后，回到对应工具入口。普通配色或局部 XFL 修复沿用[美术装配](../agentsDoc/art-asset-assembly.md)，无需重做迁移调查。

## 源与交付归属

初次绘制可用 SVG 作为待认可画稿；参考包保留源文件身份、局部原点、分件对应关系、装配矩阵及动作覆盖。认可并导入后，现役编辑源转入所属原生 XFL，SVG 归档保留为导入依据。后续原生修补不能被旧 SVG 自动覆盖，也不建立 Linux 和 Windows 各改一份的双真源。

克隆兽的[装配入口](../tools/gamma-echo-assets/README.md)、[认可画稿归档](../flashswf/arts/new/Codex素材源稿/γ-ECHO克隆兽-R3/README.md)与[原生清单](../tools/gamma-echo-assets/native-manifest.json)分别拥有操作说明、初始画稿和生成身份。[生成器](../tools/gamma-echo-assets/build.py)会在原生文件偏离上次导入身份时拒绝覆盖；迁移时保留这一保护。

## 阶段与执行环境

| 阶段 | Linux 可承担的工作 | 当前依据与交付边界 |
|---|---|---|
| 参考提取 | 读取 XFL，或经 Java FFDec 提取 SWF 分件和动作参考 | [参考管线](../tools/monster-reskin-pipeline/README.md)已有导出与组包能力；当前默认可执行文件仍为 Windows 入口。FFDec 图像是参考，不能代签 Flash 实机像素 |
| 矢量绘制 | 轮廓、色块、结构线、爪牙骨刺、配色与分件接口修正 | 克隆兽试作使用 Python、Pillow、NumPy 和 SVG；可重复执行的部分仍需从试作目录整理入库 |
| 离线动作预览 | 用固定矩阵重组姿势，浏览器截图、动图和缺件检查 | 试作已有 Node／Playwright 入口，但绑定 Edge 与本地依赖目录；浏览器预览不执行原 AS2 行为 |
| 原生 XFL 候选 | SVG 路径转原生矢量，遮罩与渐变装配，复制受控时间轴并检查引用 | [build.py](../tools/gamma-echo-assets/build.py)、[death.py](../tools/gamma-echo-assets/death.py)、[connections.py](../tools/gamma-echo-assets/connections.py)主要使用 Python/XML；核心不调用 CS6，路径与清单仍需适配 |
| 原生图像分析 | 对 Windows 回传的原始采样解码、生成对照图和连通域检查 | 解码器和[连接检查器](../tools/gamma-echo-assets/check-connections.py)可移植；采样来源、完整性与适用姿势随包保留，不能把本地模拟图写成 Flash 原生采样 |
| 发布与游戏复验 | Linux 可准备输入和分析回传结果 | CS6 GUI 编译、真实 Flash 时间轴和 Windows 游戏入口仍走现有 Windows 工具；正式 runtime 发布另遵其授权与协议 |

FFDec 官方提供 [Linux 与 Java 命令入口](https://github.com/jindrapetrik/jpexs-decompiler/wiki/Commandline-arguments)，Playwright 官方提供 [Linux 浏览器执行方法](https://playwright.dev/docs/ci)。这些证明依赖有跨平台入口，不能替代仓库脚本在目标机器上的实际执行。

## 已确认的迁移缺口

1. **绘制入口尚未完整入库。** 首件 R2 的 `refine_parts.py`、`build_preview.py`、`render_preview.cjs` 与 R3 的配色和动作截图脚本仍在 `tmp/monster-reskin/` 下的试作目录；仓内已有认可 SVG 和原生装配器。后续整理应提取可复用逻辑，将素材配置与绘制配方分开，不把历史成本计算、固定工作目录或临时文件一并提升成公共工具。仅克隆仓库不能复现完整试作过程。
2. **工具发现绑定本机。** [参考导出器](../tools/monster-reskin-pipeline/export_ffdec_assets.py)默认使用 `ffdec-cli.exe`；试作预览指定 `channel: 'msedge'`，从 `launcher/perf/node_modules` 读取 Playwright。迁移时让 Java／FFDec、浏览器和依赖根可配置，并固定实际采用的版本。
3. **清单路径使用了平台分隔符。** `build.py` 用 `str(Path.relative_to(...))` 写入 `owner`、`approvedInput`；当前清单中是 Windows 反斜杠，[verify.py](../tools/gamma-echo-assets/verify.py)又直接将 `owner` 拼入本机路径。Linux 迁移需要统一新生成的仓库相对路径表达，并兼容读取旧清单。历史回执和哈希原件保留，用映射消费旧绝对路径，不能批量改写原始证据。
4. **字体和字节身份需固定。** [连接图解码器](../tools/gamma-echo-assets/decode-connections.py)与[死亡图解码器](../tools/gamma-echo-assets/decode-death-preview.py)写死了 Windows 微软雅黑路径。Linux 应显式选择可用中文字体；标注文字与原始像素分开。XML、JSON、AS2 的编码、BOM、换行和路径大小写按仓库约定核对，不能以重新计算预期哈希掩盖无解释差异。
5. **新环境必须准备构建依赖。** 原生装配需要 `lxml`，绘制需要 Pillow／NumPy，预览需要 Node／Playwright 和浏览器运行依赖；`verify.py` 还读取数值工具构建后的 `dist`。依赖版本与准备方法应归工具 README，不能依赖本机恰好已有的缓存，也不提交 `node_modules`。

dot 是可能的执行节点，管线本身不绑定其专有环境。官方说明其有独立云端电脑，也可使用获准连接的本地电脑；具体仓库访问、依赖安装、图片回读和文件保留能力须在目标任务中检查。连接本机所需的在线条件见[官方 dot 文档](https://learn.chatgpt.com/docs/dots)，不由仓库推定账号权限或电脑已连接。

## 首件留下的绘制经验

- **固定原型与动作接口，再调整画风。** 克隆兽采用原参考轮廓辅助保形，结合色块整理、手写结构线及爪牙骨刺重绘；效果并非只靠自动描摹。延寿型与完全体先共用分件几何，再从已有素材读取各自配色，避免颜色改动带入骨架漂移。
- **整机静帧通过后还要看分件在动作中的连接。** 本次脚爪、牙根及颈肩连接经过后续返修；缩小后的整机观感不能覆盖局部断开。检查应包含局部放大、左右朝向与关键姿势，并保留原点和关节重叠区。
- **活体和死亡资产同时盘点。** 活体换皮完成不等于死亡完整；原模板可能包含专用残躯、伤口和血迹阶段。碎片与攻击拖影有意分离，不能套用活体单连通域要求。现有连接检查器只处理命中的图片，调用方还须确认预期图片齐全，不能把检查器返回通过视为覆盖完整。
- **生成画面与查看画面形成返修循环。** 每轮先产出可读预览，再检查轮廓、遮挡、缺件和风格；冻结认可方向后继续细化。模型能写出 SVG/XML 不代表图像已经达到要求，重复执行未变化的配方也不会自行提高画质。
- **快速行为检查与完整帧导出分开。** 克隆兽已有默认快速入口与显式诊断导出；重型图像导出不必每次局部修改都运行。实际切帧还需等待新 MovieClip 完成放置，不能读到旧引用后把空图当有效样本。具体等待、超时和恢复沿用[专项入口](../tools/gamma-echo-assets/README.md)，不在 Linux 另造一套放宽标准。

此经验覆盖已有原型和骨架的分件重绘。全新骨架、全新动画或不同素材风格需要各自首件验证；不能直接套用本次通过范围或固定单价。

## Linux 首次复跑范围

首次迁移用现有克隆兽做固定样例，先验证工具链，再增加新素材设计变量：

1. 在独立工作副本中准备同一源码与参考包，记录实际依赖版本。输入应包含原始分件、注册点、动作矩阵、认可画稿和对应原生清单；不要依赖 Windows 临时目录或用户真实存档。
2. 完成必要的入口适配后，复现画稿和离线姿势预览。核对输入身份、分件对应、透明背景、预期动作与朝向、非空图和关节区域；像素差异按渲染器和字体来源解释，不用整图平均误差掩盖小面积缺件。
3. 在副本内生成 XFL 候选并执行现有静态校验，比较引用、注册点、时间轴与原生文件身份。相同输入的差异需先解释；遇到原生编辑保护应停止覆盖并确认差异归属。
4. 将候选变化和预览交回 Windows，按所属目标由 CS6 编译并取得新鲜编译证据，再核对 Flash 原生画面和必要的游戏行为。Windows 发现的问题回到同一仓库源修复，下一轮 Linux 从该版本继续。

Linux 端成功只记录实际完成的绘制、预览或静态装配范围；`compiled`、`candidate_executed`、`e2e_verified` 等结论继续遵循[现有证据状态](runtime-build-reproducibility.md#evidence-states)。本流程复用已有工具结果和素材清单，不新增逐步审批、日常打卡或另一份发布状态机。
