## 已确认的开销

材料档案有秒级的自身开销；普通面板背景抓取有几十毫秒的共享开销，个别调用出现两百毫秒以上长尾；转场面板关闭存在重复恢复 Flash 焦点的路径。场景加载仍保留原淡出时间轴的两段纯等待帧。四处可以分别处理，但不能把它们相加当作已经兑现的整体收益。

| 实测对象 | 结果 | 可成立的结论 |
| --- | --- | --- |
| 用户原试玩的 8 次普通转场 | begin → Host reveal 中位 2448.5 ms，范围 1915–2981 ms | 原体验存在秒级等待；是日志观察时间，不是新的 A/B |
| 专用克隆的 5 次基地转场 | AS2 begin → released 中位 2259 ms，范围 2040–2311 ms | 同一机器、已获前台准入的基线；没有优化后的配对样本 |
| 完整材料档案的 5 次 AS2 投影 | 总耗时中位 2127 ms；配方用途整理中位 1669 ms | 配方用途约占各样本总耗时的四分之三至五分之四，是面板自身热点 |
| 35 次普通面板/初始化背景抓取 | capture 中位 41.513 ms；其中 blit 中位 38.456 ms、最大 241.022 ms | 抓取占主导；分配中位 1.272 ms、补 alpha 中位 1.801 ms；本轮没有改抓取内容 |

原试玩材料查询附近的 3334 ms 响应间隔没有完整可配对 fid，不能称为精确往返。本轮已补齐真实结算业务路径、同 fid 的 Host 往返与 AS2 投影计时，见下方专项对照。原试玩结算转场的 6552 ms 包含玩家停留/交互，不能全算加载。

`stage_settlement` 的 `lootMaterials` 原来调用完整材料档案投影器，再丢弃来源、用途和配方等字段，只留下存量展示。地图宝箱与奖励收件箱没有自动承担这份完整档案开销。并行结算使用独立合成表面，普通 Panel 背景截图的开销不能直接套给它。

## 代表路径与计时方法

静态登记核对覆盖 33 个 Panel；实际运行覆盖地图、工作台、材料档案、斗兽、健身、设置和选关七条代表路径，每条重复五次。基线另有五次基地门口/车库转场。后续候选完成六条面板路径共 30 次采样，地图重开和结算旅程的失败记录另留。

所有运行均用专用 `cf7_agent_panelload_1010` 克隆，种子只读。Core 实际路径、PID、build identity、payload closure 与 SHA-256 绑定；页面通过既有固定源端点观测。原玩家槽位、偏好和正式 runtime 文件做前后哈希核对。

计时开关为 `CF7_PANEL_TIMING=1`，默认关闭。Host 向当前可交互 AS2 generation 安装独立 profile，AS2 用 `getTimer()` 记录本次作用域的 elapsed。只输出指标、profile 与 call 标识，不输出材料、奖励或存档内容；AS2 每个 profile 最多记录 4096 条。

| 层 | 观测边界 | 限制 |
| --- | --- | --- |
| AS2 | covered、清场完成、初始化完成、SceneReady、reveal request、released；材料各投影段 | 累计节点与独立作用域分别命名，不能把累计值相加 |
| Host | 排队、抓取/分析/编码/合成、HUD 暂停/恢复、面板打开/关闭、焦点恢复 | 不证明物理显示或真实鼠标体验 |
| Loot 通信 | 相同 fid 的实际转发到响应；AS2 返回同 callId 的投影 elapsed | 历史缺失身份的时间间隔不补成 RTT；本轮结算成功配对仍待补 |
| 浏览器 | mount 后两次动画帧；对应权威响应后两次动画帧 | 外部轮询约 100 ms，隐藏 WebView 不等 RAF；不是完整游戏 E2E |

`baseline-owned-04` 在采样前实际获得所属窗口的前台准入。`baseline-full-01` 和 `optimized-panels-02` 只证明克隆上的真实请求、数据响应及 Web 帧观测，缺少所属前台证明。它们不能与前台样本混算。

## 四项优化及保护边界

**等待帧推进。** [SceneTransitionService](../scripts/类定义/org/flashNight/arki/ui/SceneTransitionService.as) 在真实清场完成后安排进入原第 13 帧；第 17 帧先释放初始化标志、运行原 dirty save 守卫，再安排进入第 30 帧。保留至少一次实际 EnterFrame 边界，只有当前 fade、covered 且未失败/取消的请求可以推进。

第 15 帧任务检查、第 30 帧新世界 SceneReady/Host 呈现门和第 36 帧收尾继续使用原权威。延迟清场若没有 Web 接管，仍续播原时间线；重复完成回调不能误触发续播。原两段名义等待共 20 帧，保留帧边界后能缩短多少毫秒须由实际转场对照确定。

**焦点交还。** [WebOverlayForm](../launcher/src/Guardian/WebOverlayForm.cs) 在当前已连接转场持有遮罩期间，普通 Panel 的 idle/settled 关闭不再重复调用 Flash 子窗口恢复，由转场按当前所属前台交还。外部前台保护及断连兜底继续生效。没有改变玩家输入后端。

**结算存量投影。** [LootContainerService](../scripts/类定义/org/flashNight/arki/item/LootContainerService.as) 改用 `executeMaterialStocks`。仍校验完整目录闭包、材料身份、exact 当前 loot session 和业务 revision，只返回 `{name,displayName,icon,owned}`；每次读当前数量，不构建配方/来源图，不替换已冻结的材料详情 snapshot。

**完整档案的配方复用。** [MaterialArchiveProjector](../scripts/类定义/org/flashNight/arki/item/MaterialArchiveProjector.as) 只在一次同步 snapshot 构建中，按 category + recipeIndex 复用配方解析、原始数量归集、原料展示和产品展示。每个材料仍核对原引用及自己的权威数量；同名产品的不同配方不合并。

复用不跨 snapshot，刷新重新读数量与展示数据。详情向调用者深拷贝，不能通过某材料详情改动另一个材料。权威数量保留原始累加语义，不能使用展示层把零/NaN 兜底为 1 的结果。新增八项 Flash 回归已经通过；完整材料投影 AS2 elapsed 中位从 2415 ms 降至 1119 ms，n=5。

### 结算专项对照

每个版本使用同一份有主线进度的只读种子，各创建三次独立新克隆。正常选关进入「超市废墟 / 简单」，等待真实 SceneReady/呈现交接后，夹具调用既有胜利 facade，再经生产返回基地与并行 Loot 路径查询存量。选择、run/token、容器身份、业务 revision 和请求/响应均使用实际权威，不修改原槽位或直接伪造 loot 数据。

| 指标 ms，n=3 / 版本 | 基线样本 | 优化样本 | 中位变化 |
| --- | --- | --- | --- |
| AS2 存量投影 | 3353 / 2784 / 2605 | 216 / 159 / 198 | 2784 → 198，减少 2586 ms（92.9%） |
| 同 fid 的 Host 往返 | 3441.933 / 2845.314 / 2662.800 | 306.789 / 237.923 / 279.958 | 2845.314 → 279.958，减少 2565.356 ms（90.2%） |
| AS2 结算转场 begin → released | 6294 / 5682 / 5386 | 3518 / 3201 / 2701 | 5682 → 3201，减少 2481 ms（43.7%） |

每个往返通过实际 `materials call=2` 与同次 AS2 `loot.materials.project call=2` 配对；callId 的唯一范围是对应 Core/业务会话，不跨进程拼接。投影 elapsed 已包含在往返内，不能相加。三次是独立克隆的冷路径样本，数量不足以代表全玩家分布；未制造失败或未知写，不盲重放持久操作。

胜利由夹具触发，不称自然战斗胜利验收。并行结算的合成文档刻意没有 debug endpoint，未绕开此边界抓 DOM，也不把上述数据当作最终物理像素、鼠标或视觉验收。

早先种子没有主线进度，正常锁定阻止了进入；更换只读克隆种子后保留相同场景与难度。采样还修正了实际权威快照等待和控制台对下标函数调用的兼容：用已有 `apply` 路径，未修改生产解析器。失败记录保留，未并入成功样本。
