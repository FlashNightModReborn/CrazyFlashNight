## 关键事实

- **技能名 = 容器 linkage 后缀**。`_root.技能路由` 用 `ContainerSpec.getLinkagePrefix(KIND_SKILL)`（`"技能容器"`）拼 `技能容器-<技能名>` 再 `attachMovie`。所以 skills.xml 的 `<Name>` 必须与容器 `linkageIdentifier` 后缀严格相等；**XFL 文件名和符号名带 `（未实装）` 前缀都无所谓**（只影响 asset_source_map 的 `symbolName` 字面量）。
- **技能容器不靠 asset_source_map 才能跑**：`attachMovie` 认 SWF 内 linkage；map 是工具/图标烘焙/装扮反查用。但惯例要补。
- **存档按技能名存**（`mydata[5][N][0]`），不按下标/id ⇒ 重排 skills.xml 槽位不影响旧档。
- **CD 单位是毫秒**（`20000` = 20 秒）。`UnlockSP` 是解锁花费，`UpgradeSP` 是每级升级花费，两件事。
- **`skills_metadata.json` / `skills_tree_config.json` 不是玩家技能面板的真源**（佣兵/AI 技能树元数据；`SkillTreeLoader` 没接进主流程）。新增主动技能不必加。
- **80 个 `<Skill>` 槽位是硬数量**：`<Name>` 为空的槽会被 `SkillDataLoader.applySkillData` 跳过（不进 `_root.技能表对象`）。只填空槽，别增删 `<Skill>` 元素，别改已有槽的语义。
- `Type` 含“被动” ⇒ `Passive=true`、`Equippable=false`；否则可上快捷栏。
- Description 续行沿用 8 空格缩进（与现役条目一致），面板自己处理换行。

## 第 4 步怎么改才过 gate

`tools/cf7-save-repair-dict-build` 的 verify **忽略 `generated.at`**，所以不用装 npm 依赖，手工插入即可；但必须落在生成器排序位：

生成器序 = `dedupeSorted()` = `[...new Set(arr)].sort((a, b) => a.localeCompare(b, 'zh'))`（Node ICU 拼音序）。

自检一条命令（**必须用 Node，Python 排序不是这个口径**）：

```js
const d = JSON.parse(fs.readFileSync('launcher/data/save_repair_dict.json', 'utf8'));
[...new Set(d.skills)].sort((a, b) => a.localeCompare(b, 'zh'))  // 必须逐项 === d.skills
```
