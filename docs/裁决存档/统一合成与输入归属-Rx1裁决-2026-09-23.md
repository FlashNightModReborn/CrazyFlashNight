# CF7：RCE-2 最小可靠修补与 G1/G2 恢复裁决

日期：2026-09-23。性质：独立路线裁决，不是源码改动、施工授权、C1 授权或发布凭证。

输入：`CF7-G1-G2-补证与RCE2反例-20260923.zip`；SHA-256 `63223003ddcb47efc6e084aec68c148fb4b46576d679a4ded3936bf3eb6c2dd9`。冻结基线为 `51e2ebb981f1e9728d54004a41416da03b0545c5` 加包内未提交工作区文件，不能简写为“该提交已验证”。证据定位见同目录《证据索引.md》。

## 一、结论

**选择路线 1：保留紧凑数据包，实行不回绕的有界输入会话，并以完整撤销、排空、恢复及 broker 退出握手续接。** 生命周期只属于输入桥，不得重启整个游戏、重建整体合成路线，或借此迁移 AS2 业务权威。保留 S/P/F 拓扑和现有显示/光照配对。

真正的修复由两部分共同组成：会话内所有比较操作数严格落在同一个小于半范围的数轴区间；新会话获得权威之前，旧会话再无能解释成新输入的数据、控制消息或回调。只实现其中一半不能恢复 G1。

当前判定：G1 BLOCKED；G2 检测逻辑及负控证据可保留，但实际 Guardian 装配未通过，Flash 精确 F-ROI 边界还存在记录不一致；新候选不得进入正式人验或据此进入 C1。旧候选既有人验不作废，但不继承给本次修改。

路线 2 技术上成立，却不是本轮最小方案：必须使所有 floor/high-water 使用无歧义的长期表示，并把每个未处理的短 wire 包不可变地绑定到其完整代次/会话；不能在出队时用“现在的 issuedEpoch 高位”拼出旧包的身份。描述符回收、乱序跨度、跨进程发布、序号回绕与 ABA 都要一起证明。把 uint 改成 ulong、扩大 wire、定期推 floor、遇到零 floor 特判，均不作为本次可验收替代方案。

## 二、证据裁定与纠正

### 2.1 RCE-2 反例成立，但不能倒推短会话事故

生产 `WindowProc` 同时检查 `shared.minEpoch` 与 `localFloor`；`lastEpoch` 前进不会自动推动二者。持续前台且不取消时，两个 floor 可一直为零。此时序号 `0x800000` 与零的差达到半范围，被 `StaleEpoch24` 判旧。这不是到 `0xFFFFFF` 才发生的普通计数器溢出。[E03–E05]

原始长会话序列为 1、4194304、8388607、8388608、8388609；交付增量为 1、1、1、0、0，退出 1、failures=2。默认 19/19 的 wrap 用例主动推进 floor，因此与本反例不矛盾。该长会话用例是生产端点的加速窗口实验，不是百万次物理点击，也不能据此认定它造成了此前短会话的人验故障。

### 2.2 46/46 只证明已经测试的队列边界

跨进程夹具保留价值：真实 broker/DLL，生产发送端，旧 Down 在目标队列中尚未见到，失焦或 Host Cancel 后被拒绝，新的合法代次可重新准入。[E08]

但 S3 的 CancelPostFailure 针对的是**尚未交付的 Down**；不证明“已交付 Down 后 Cancel 投递失败、之后没有任何新包”也会完成释放。各 readmit 先 `FocusChild`，且 Surface 的 focus 回调只是写 `focus_cb`；不证明真实 Guardian 的首击返回及焦点执行链。`MOUSEMOVE+DOWN=2` 是一条 Down 前的重建 hover，不是两次 Down。

### 2.3 当前退出链不满足可续接条件

`NativePointerBridge.Dispose` 只发一次 0xFF，立即释放 Host 映射，不等待排空/恢复/旧进程退出；投递失败也没有完整关闭结果。`Restore` 没有验证全部 WNDPROC/IAT 恢复成功，且在当前回调未返回时已置 stopped。broker 在等待超时后仍卸 hook、删属性并退出，没有证明旧桥已彻底退场；启动也没有独占锁。[E06–E07]

旧 0xFF、0xFC 在普通输入门之前处理；`InputHook` 在 target 为空时可以由任何协议消息触发 Initialize。故“重置两个 floor，立即再 Start”会引入旧包串入、旧控制关闭新桥、两个安装者并存等风险。

### 2.4 对共享内存与 ACK 的纠正

32 位对齐读写“不撕裂”不等于已证明跨进程同步；不能从一次后续 PostMessage 推导任何并发出队者必然按需要观察所有旧/新字段。需要明确原子访问与发布/读取顺序，尤其 stop、floor、issued 和恢复 ACK。[W1–W2]

`consumedSeq` 在拒绝判定和原处理器执行前写入，只是收件记录；Host 又把其低 32 位按有符号值读取。不能把 `consumedSeq >= seq` 升格为完成、排空或恢复 ACK。[E04,E06] PostMessage 成功只表示入队，并不表示处理完成；消息可以先取出而尚未 Dispatch，过滤也可以跳过通常的 FIFO 顺序。[W3–W4]

### 2.5 G2：保留实际证明，收窄几何与退出声明

最终套件是“两项正例＋三项预期失败的负控＋四项非法 CLI”共 9/9，不是九项真实运行成功。[E09]

| 相位 | captured/presented | 记录判定 | 内容证据 |
|---|---:|---|---|
| positive / covered | 122/122 | streaming-under-cover | 4 份 ROI proof，最大 RGB 误差 0 |
| stall-f / covered-stalled | 20/20 | s-chrome-only | 4 份，输入摘要不变 |
| stall-f / covered | 121/121 | streaming-under-cover | 4 份，恢复变化 |
| hold-frames / covered | 0/4 | stalled-under-cover | 能识别呈现旧纹理 |
| capture-output / covered | 240/241 | marker-leak | 品红三点 oracle；本项 ROI 为 null |
| flash / covered | 152/152 | streaming-under-cover | 4 份 ROI，摘要变化，误差 0 |

Flash 四次固定三点都相同，而声明区域的四个完整 RGB 摘要不同。因此“固定三点未变＝Flash 停帧”错误；也没有证据把 `Vector smash protection is enabled` 归因为遮挡节流。

**新增纠正：Flash JSON 的声明 ROI 是 (109,212,640,320)，记录的 F.windowRect 是 (109,213,640,320)。** `Program.cs:208` 采用 embedPanel 矩形，而 `cropIsFRegion` 在 485 行复算同一声明矩形，未独立验证实际 F 客户区。若同坐标系/同一时刻，两者相差一行；包内没有解释坐标或时刻差异。故内容变化及输出对应证据仍成立，但“精确完整 F 区域”未充分证明。下一轮须将实际 F 客户区映射到统一物理屏幕坐标，比较 capture crop、P 输出边界，记录同一次几何版本；无需因此重做整体捕获架构。[E09–E10]

full ROI 证明的是显式采样区域的 RGB 变化与 Present 前 GPU 输出；不是逐帧连续性、扫描输出、业务 ACK、输入延迟或性能收益。JSON 明写 `inputForwarding=NOT_IMPLEMENTED`、`humanAcceptance=NOT_PERFORMED`。Flash 还记录 `ownedFlashExitedNormally=false`，Probe 代码在正常退出超时后会强制清理其自建素材进程；这不推翻此前内容 proof，但不能据此认证正常退出/恢复。只记录 Intel UHD 630，不扩大为多卡、多屏或 DPI 矩阵通过。[E09–E10]

## 三、有界会话的具体数值合同

令 `H=2^23=0x800000`。推荐固化如下保守上限，允许采用更小生产上限，禁止配置放大越界：

| 状态/用途 | 合同 |
|---|---|
| 普通输入和常规取消代次 | 1…L；L=H−3=0x7FFFFD |
| 会话终止保留代次 | 至多 L+1=0x7FFFFE；同次关闭重复请求幂等，不继续递增 |
| localFloor 等派生比较值 | 至多 L+2=0x7FFFFF |
| 未初始化 floor | 0；只在新桥正式 READY 后作为新会话初态 |

在同一会话中，所有参与比较的数值均属于 `[0,H−1]`，两者差的绝对值至多 H−1。因此在该域内，现有 `((e−f)&0xFFFFFF)>=H` 与普通整数 `e<f` 等价，连 floor 始终为零也不会产生半范围歧义。这是代数证明，不依赖队列长度、点击频率或自然失焦。

必须覆盖的操作数包括 wire epoch、Host 发号器、shared.minEpoch、shared.issuedEpoch、lastEpoch、localFloor，以及 lastEpoch+1、max(lastEpoch,issued)+1；在增加和掩码之前检查。普通数据接收门还要独立拒绝零值及超出普通许可域的包，不能让异常值先推动 high-water。

共享 `issuedEpoch` 是签发高水位，只能单调取 max；不能因发送较老缓存包而回写更小值。`minEpoch` 与 `localFloor` 同样不倒退。这里的 max 已由会话数值域约束为普通整数比较；共享访问仍须满足同步合同。

所有发号统一入口：新 Down、Cancel（包括 had=false）、失活、hidden、queue_full、source_gone、target_rebuilt、投递失败。不得遗漏取消导致的增长。保留上限不是游戏时长限制，也不是仅按点击次数计数。

终止清理不是一条碰运气的普通 Cancel：它是仅能撤销/释放的会话控制，不能因 localFloor 又上升一次而被普通数据门永久挡住；也不能借此放行 Down。

所有缓存包、移动合并槽、已调度 BeginInvoke、异步 repaint、Windows 队列项、已取出未分派的 MSG、正在执行/重入的回调，都仍属于旧会话。旧会话不允许在原映射内改回零后继续使用。

序号另作处理：`consumedSeq` 可保留为诊断，但不得参与完成排序。推荐本轮同步实施每会话 packet sequence 的独立 checked 上限 `0x7FFFFFFD`（2^31−3，与 epoch 的 L 不同），为当前有符号观察口径留边界余量。移动包也消耗该预算。关闭控制用单独的会话绑定 ticket，不依赖 ordinary sequence 再增加；工程实现必须分别命名两个上限，避免混用。

geometry 的低 8 位目前不是端点代次权威，不得借给 session 标识来声称消除了 ABA。新手势数受上述发号预算限制；不会靠 gestureSeed 的自然 uint 回绕恢复。

## 四、续接协议：缺一项就不得安装后继

建议状态：`Active → Quiescing → Revoking/Draining → Restored → BrokerExited → Binding → AwaitFreshDown → Active`。另有 `ClosedUnconfirmed`：停新输入、保留显示，不得热接新桥。

### 4.1 先停新手势，不丢合法结束边

在接近上限且可正常服务时，提前预约一次续接；停止接受新 World Down，已准入手势在原会话内完成 Up/Cancel，并等待端点完成。Host 的 IsDragging=false、队列空、Posted、consumed 都不能独自证明端点空闲。

如果失焦、溢出、故障或硬上限已经到达，必须显式中止旧手势，而不是把长按换一个编号偷偷接到新会话。被门拒绝的旧 Down 不暂存、不重放，也不作为新桥恢复后的“第一击”。鼠标仍物理按住时留在 AwaitFreshDown，观察真实释放后才接受新的物理 Down。

窗口级唯一消费继续有效：桥暂不可用不意味着已经归 World 的边可以落到 Native/Web 再触发一次；同时不阻断本来属于其他窗口的输入、物理鼠标移动或既有键盘释放路径。

### 4.2 持久撤销和输入状态清理是两个证明

对当前 session 原子发布 closing/stop 和终止 floor。对该线性化点之后尝试准入的旧数据拒绝。已经在此之前准入并进入原处理器的调用不能声称被追溯撤销；允许它完成并计入待退休集合，随后必须完成取消清理。

撤销状态不依赖 Cancel 的 Post 成功。端点在受控检查点执行幂等清理，归零虚拟鼠标按钮、虚拟捕获、activeGesture，并通过原处理器所需的取消机制释放它自己的状态；只能取消，不合成 Click、Down 或默认 WebMouseUp。真实 Flash 是否释放正确必须实测，不能用 native fixture 的清零代签。

已交付 Down 后的 CancelPostFailure 必须独立测：之后不再发送输入，端点恢复可执行时仍应完成清理。目标线程一直挂死时，只能维持关闭、报告未确认；没有协议能保证不执行代码的线程及时完成清理。不能伪造 ACK，更不能因此创建第二套桥。

当前 `buttons=flags` 把 Shift/Ctrl 位也存入按钮状态，`up && !buttons` 可能不清 activeGesture；焦点分支也没清 activeGesture。新的“空闲证明”必须以鼠标按钮位掩码 `0x73` 判定并统一清理，否则按住修饰键会误判仍在拖拽。[E04]

### 4.3 真正封住所有发包者，排空并退休

Host 停普通发送、刷新 MOVE、待运行 Drain；repaint 请求需有明确的完成/退休记录，超时不等于目标未执行。所有延后回调绑定旧 session，旧实例不得使用新实例的字段再发送。broker 的 Init、Stop 重试也属于发包者。

排空只针对该桥的数据/控制消息及其运行中回调，不吞其他窗口的合法消息。需同时证明：没有生产者还能向旧会话发包；队列中旧包已清掉/拒绝；取出但未分派和重入执行的旧回调不会在后继生效后触达新全局态；原处理器的在途调用已返回。

**投一个 WM_NULL/Stop 就算“排空”、等固定毫秒、见到 stopped=1，均不合格。** 如采用处理器内 ACK，须区分“恢复准备完成”与“该控制调用已经返回”；当前在 Restore 内先写 stopped 的做法不能用来证明其自身已经退出。

鉴于 DLL 有进程全局指针且 IAT 包装器也读取它们，退休边界还包括可能访问旧上下文的包装器/Hook 回调，而不只是 WindowProc。可通过保持旧不可变上下文并延迟回收，或已证明的回调退出协议完成；不要求重新设计渲染引擎。

### 4.4 恢复、退出及独占安装

确认目标当前 WNDPROC/IAT 槽仍由本桥持有后恢复；异常不覆盖别人的新包装器。必须记录实际成功或失败，失败不能发布 restored。随后卸精确 hook，仅删除仍指向本次 mapping/atom 的属性，停止所有控制重试，观察本次 broker 的真实退出。

新 ACK 至少绑定 `(sessionIdentity, requestTicket, completionState)`，按相等匹配及明确状态迁移使用，不借 consumedSeq 排序。共享状态使用文档化原子/同步方法；C# 不可凭空 P/Invoke 一个并不存在的 Interlocked 导出，可使用合法的映射 ref 原子操作或小型本地封装。发布/读取、对象存活及关闭访问必须一起成立。[W1–W2]

broker 在 SetProp/安装之前取得跨版本独占资格。由于当前桥使用进程全局单 target 状态，独占粒度至少覆盖**目标 projector 进程实例**，再核对 HWND/TID/owner，而不只按 PID 数字或版本命名。Host 串行化 Start/Stop，等待旧 broker 退出，拒绝过期 Start completion；其他安装者也不得越过已有未闭合实例。放弃的 mutex 或旧进程突然消失不证明桥已恢复，遇此情况进入 ClosedUnconfirmed。

控制协议/共享布局升版（建议 v4），Host、broker、bridge 配套。Init/Stop/Repaint 同样验证会话归属；迟到的旧控制不能初始化或关闭新桥。普通紧凑数据不增加完整长代次的前提，是上述跨会话隔离已证明，不能倒过来用无 session 字段的包证明自己属于新会话。

只在旧会话确认闭合，或**原目标进程已真正退出、所有旧窗口失效**时，允许以新身份重新绑定。HWND 数值相同、同 PID 但不同进程实例、broker 被杀掉、旧映射打不开，都不是足够替代证据。

### 4.5 保留显示和既有释放能力

输入续接不得调用 Controller 的整体 StopCapture / native.Dispose / owner.Close 路径。Surface 可通过一个稳定的输入会话槽替换已关闭的 sink，保持 output HWND 不变；输入状态与 `_native`、P 的显示生命期分离，保持 S/P/F、光照配对和输出；必要时只显示明确的“输入恢复中/恢复未确认”状态。真实渲染故障仍走既有故障政策，不借此更改。

不为续接新增 AS2 业务命令、存档写入、付费确认、暂停权威或自动重启玩家进程。不拆全局低级 Hook；只修输入会话自身的准入、终止与发布责任。

## 六、必须通过的回归矩阵

以下是合取条件，不可互相替代。新增测试数量不预定，但不得删除旧反例来换绿。

| R02 长期连续性 | 维持前台、不人为失焦；经生产发号及续接跨越累计 H、2^24；至少连续三次真实续接 | 不是到上限永久拒绝：响应正常的端点每次完整退出并重新 READY，之后 fresh Down 正常；没有第二套桥。 |

## 七、恢复 G1/G2 与人验的硬门槛

### Gate A：可复核的有限补丁候选

形成上述输入协议和生命周期补丁，给出全部比较态清单、界限证明、关闭失败分支、成套产物身份。原反例保留，R01–R11 相应机器回归通过。源码、未提交 diff、构建参数、实际加载 DLL/EXE 哈希需关联；本包 manifest 只能证明包内字节一致，不能证明产物由源码重建。

通过 A 只恢复 **G1 技术候选**，不是实际游戏通过；不因输入夹具绿而宣布 G2 或人验完成。

### Gate B：同一真实 Guardian 候选的 G1/G2 装配取证

不要求重做四卡矩阵，也不要求先施工 C1。用真实候选在现有实际路径完成最小非业务写入取证：

- 身份：S/P/F、父/owner/root、PID/TID/进程启动身份、实际模块路径与哈希，Host/broker/bridge/Compositor/asLoader 配套；不把素材 SWF 当 asLoader。
- G1：实际路由与焦点回调、排队旧 Down 的拒绝、正常/失败释放、续接之后 fresh Down；不用强制 FocusChild 代替产品返回链。
- G2：P 覆盖 F 时的实际内容与输出对应，精确客户区/裁剪/P 几何；缩放与最小化恢复后重新取得新几何、新内容证据，不能只看 received/presented 增长。
- 入口与消费：实际 Alt-Tab、任务栏返回；World、Native 与现有 Web 面板各只消费自己的边，不因桥暂停走双重 fallback；记录人工操作与自动注入的区别。

最小化期间允许按现有产品策略停推，不强加“隐藏后仍连续出帧”的新要求；要求恢复后证明实际源、几何与输入权威重新匹配。G2 full ROI 若只在 raw 1:1 诊断模式成立，必须标明；生产含光照/缩放的输出另外按其变换验证，不能强行套用 raw 的零误差断言。

必要的人工进入场景/返回配合属于实验采样，不等于正式人验签字。Gate B 完成且 G1/G2 同一候选全部闭合，才可把整体 G1/G2 状态恢复为 PASS。

### Gate C：进入短人验

只安排既定三组：切出后释放与返回首击；真实 surgery 中文输入/取消（不付费、不提交业务）；缩放/最小化/恢复。专门观察无误触、无粘键、无抢焦、无双消费、无裸源暴露及明显恢复滞后。若自动续接在普通短测中触发不到，单列受控小 cap 的真实装配样本，不能假装已人验到该分支。

新候选每组明确 PASS/FAIL/NOT_RUN，绑定相同构建及实际日志。任何一组失败停止晋级，留最小反例；不以增加重试、强制焦点或取消边界检查“修好”脚本。通过后才具备按原 R1 的限定 C1 样本路线继续申请/执行已获授权工作的条件；不代表 C1 纵切完成、B 开放或发布授权。

## 八、内部顺序、回退与未核验范围

建议施工顺序：先冻结反例和合同；再做原子状态/关闭协议与独占；然后接 checked 发号和 Controller 输入续接；跑边界/真实队列/故障回归；补 G2 精确几何；冻结成套候选，取真实装配证据，最后短人验。各步在同一有限候选收口，不夹带架构重开。

回退只回到一个完整配套候选，不混用 v3 Host 与 v4 DLL，也不在活着的未闭合桥上热换文件。新方案故障分支停新指针、保留既有显示和可用释放/退出能力；确认目标进程退出后再按原启动流程恢复，不自动杀游戏掩盖问题。

本轮实际做了：通读提示词/报告/冻结裁决与计划，审阅相关生产源码与测试/脚本，交叉核对原始日志及 JSON；独立校验 manifest 61 项均匹配；核对 G2 声明 DLL 哈希与 executed-artifacts 记录一致；用自写只读脚本核对原反例和边界代数，缩小位宽穷举 349,504 对、24 位边界 49 对均符合域内线性关系。

**本轮没有执行包内程序或施工命令，没有在 Windows 重跑 selftest/夹具/Host 测试，没有运行 Guardian/真实游戏或做人工体验，没有读取/修改存档，没有修改生产代码、提交、推送或部署。** 可执行产物本体及相关屏幕截图未在包中，未独立证明源码与已运行二进制的构建对应、真实扫描输出、业务 ACK、焦点手感、多屏/DPI 和正常退出。复核脚本退出成功只表示记录/代数复核成功，绝不表示 RCE-2 已修复。
