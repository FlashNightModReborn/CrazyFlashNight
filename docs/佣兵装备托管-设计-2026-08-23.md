# 佣兵装备托管 一期 设计（2026-08-23）

**状态**：施工基线。本文档是三轮调研评估的收口结论兼实施规格；协议字段、错误码、文件触点为施工契约，实现不得静默偏离，被迫偏离必须回写本文档。

## 0. 范围与出范围

一期范围：非战斗地图、佣兵休息（`佣兵是否出战信息[i]==0`）且未阵亡（`!=-1`）、面板 owner 有效时，玩家用背包装备覆盖佣兵固有预设；支持单槽交付/替换/取回；开放槽位 = merc 数组下标 6..15（头/上装/手/下装/脚/颈/长枪/手枪/手枪2/刀）。

出范围：手雷槽（下标 16，纯经济消耗模型，后续"手雷玩法"列车再开）；出战佣兵现场重建（一期换装下次出战生成时生效）；自动"全部返还后解雇"；仓库/战备箱作为来源；`MercLibrary.as:129` 的 `gerenade` 拼写修复（**已知问题**：源数据 16/204 条佣兵配了非空 grenade，修复会激活佣兵 AI 手雷分支 `单位函数_fs_佣兵ai.as:56-60`，属行为变更，归入未来手雷玩法列车，届时需实机验收投掷行为与两个"压缩胶囊"特例）。

## 1. 三层装备权威

- **固有预设**：`merc[6..15]`，装备字符串（createFromString 格式）。池构建/hybridize 定型后终身不变（全仓审计：雇佣后无人改写；world-hire 的项链→军牌映射 `MercPanelService.as:951-952` 属雇佣事务内）。不重复保存第二份预设。
- **玩家托管**：`merc[19].装备托管`，版本化冻结域：

```
merc[19].装备托管 = {
  version: 1,
  loadoutRevision: Number,        // 每次成功写 +1；无托管对象时视为 0
  slots: { "6".."15": { version: 1, item: {name, value:{...}, lastUpdate} } }
}
```

- **运行装备**：出战生成时逐槽取 `托管有效克隆 ?? 预设字符串`。`DressupInitializer.loadEquipment`（`DressupInitializer.as:147-154`）对非字符串值原样透传，因此 attach initObject 直接放 BaseItem 克隆即可，零模板改动。弹量/形态/热量/插件等战斗变化全部丢弃；取回始终返还交付瞬间的冻结物品。
- 旧存档无 `装备托管` 字段时按"无托管、revision 0"判空兼容（同 `价格倍率` 先例），首次写入再创建。
- 预设装备没有取回/出售/拆解/转移入口；托管是位置迁移，不产生 LootFeed gain/loss（走 `transactionWrite` 无事件写 + `publishTransactionChange` 容器事件，不调 `PlayerAssetTransaction`，同 `ManagedLongGunService.as:18` 口径）。
- 损坏/未知版本托管记录占据该槽：出战安全回退预设；禁止交付/替换/取回/解雇之外想象不到的清理一律禁止——交付/替换/取回全部 fail-closed（`custody_corrupt`），恢复走存档修复通道，一期无游戏内逃生门。

## 2. 资格 policy（每个槽）

候选物品须同时满足：装备实例（`value` 为 Object）；`getData().use` 与槽名匹配（规则 = `CharacterBuildService.equipmentUseMatchesSlot`：`use==槽名` 或 `槽=="手枪2" && use=="手枪"`）；`type` 为武器/防具；需求等级 `itemData.data.level <= Number(merc[0])`（**等级门基准 = 佣兵自身等级**，已拍板），否则 `level_locked`。无性别/兵种门（代码库不存在该维度）。

## 3. AS2 领域服务 `MercLoadoutService`（新文件）

`scripts/类定义/org/flashNight/arki/merc/MercLoadoutService.as`，与 ManagedLongGunService 同包。**新文件必须用"复制现有 .as → 改名"保留 UTF-8 BOM**。

静态接口（全部 static；`_busy` 重入锁 + try/finally 释放，复制 ManagedLongGunService 模式）：

- `isWritableSlot(slot):Boolean` — 仅 6..15。
- `hasAnyCustody(merc:Array):Boolean` — 解雇守卫用；只看 slots 是否有任何键（含损坏记录）。
- `getLoadoutRevision(merc:Array):Number` — 无托管对象返回 0。
- `evaluateItemForSlot(merc, slot, item):Object` — §2 policy；返回 `{success, error?, requirementLevel?}`。
- `buildLoadoutProjection(merc, slotIndex):Object` — `{version:1, loadoutRevision, canOperate, combatLocked, deployState, writableSlots:[6..15], slots:{"6":{state:"preset"|"custody"|"custody_corrupt", preset:{name,displayname,icon,level,raw}|null, custody:{name,displayname,icon,level}|null}}}`。`canOperate = !combatLocked && deployState==0`（deployState 从 `_root.佣兵是否出战信息[slotIndex]` 读；slotIndex<0 的池佣兵投影仅 preset，canOperate=false）。
- `buildCandidates(merc, slot):Object` — 先 `InventoryPanelService.buildExternalSnapshot("背包",0,50)` 现场签发，逐槽 `evaluateItemForSlot`；只放 use 匹配该槽的物品（不产生跨槽"不兼容"噪声，同 T800 只列长枪口径）；候选 `{source:{containerId:"背包",slot,expectedLease}, item:<buildItemProjection>, eligible, lockReason, requirementLevel}`。
- `buildSlotTooltip(merc, slot, source):Object` — source 非空：先 `validateExternalSlotRef(source,false)` 复证 + containerId=="背包" + use 匹配该槽，再走 `buildTooltipProjection`；source 空：托管有效→冻结克隆，否则→预设字符串 `createFromString`（应用 `getEquipmentDefaultLevel` 默认强化，与 buildMercSummary 口径一致）。
- `deliver(mercIndex, mercId, slotKey, expectedLoadoutRevision, source):Object`
- `replace(...同参):Object` — 要求该槽已有有效托管（无则 `no_custody`）；旧冻结物重建后写入**新物品原来的背包格**（无需空位）。
- `withdraw(mercIndex, mercId, slotKey, expectedLoadoutRevision):Object` — 预检 `getFirstVacancy`；背包真实持有恢复对象后才删 slots[slotKey]；自动回落预设。
- `buildSpawnLoadout(merc:Array):Object` — 恒返回 `{头部装备:…, 上装装备:…, …, 刀:…}` 十键：托管槽经 `createRuntimeItem` 复证（clone + createFromObject + use 匹配槽名）成功放 **BaseItem 克隆**，损坏/无托管放预设字符串；每次调用全新克隆。不返回手雷键。
- `createRuntimeItem(slot, frozen):BaseItem`、`freezeItem(item):Object` — 复制 ManagedLongGunService 实现，use 复证参数化为槽名匹配。

写操作公共门（顺序即断言顺序）：`_busy` → `validateMercRef`（mercIndex 合法 + `_root.同伴数据[mercIndex][2]==mercId`，否则 `invalid_index`/`merc_not_found`/`merc_id_mismatch`）→ `isWritableSlot`（否则 `slot_locked`）→ `_root.当前为战斗地图==true` → `combat_locked` → 出战信息 1 → `merc_deployed`、-1 → `merc_dead` → `expectedLoadoutRevision != getLoadoutRevision` → `stale_state` → `validateExternalSlotRef`（deliver/replace）→ `unsupported_container`/`stale_state` → policy → 事务。

事务提交序（复制 ManagedLongGunService 三段式）：
- deliver：先写 slots[slotKey]（已存在记录→`custody_exists` 提示改用 replace）→ `tryTransactionWrite(bag, srcSlot, null)` 失败则撤销托管 `commit_failed` → 复查 `getItem(srcSlot)==null`，失败回滚背包原物并视结果 `commit_failed`/`rollback_failed` → loadoutRevision+1 → markDirty → `publishCommittedSlot(bag, srcSlot, "removed")`。
- replace：先留存旧托管记录引用 → slots[slotKey]=新冻结 → `tryTransactionWrite(bag, srcSlot, restoredOld)` → 复查 `=== restoredOld`，失败回滚（背包写回新物品 + 托管还原旧记录）→ revision+1 → dirty → publish "replaced"。
- withdraw：preflight 空位（`inventory_unavailable`/`inventory_full`）→ 重建恢复对象（失败 `custody_corrupt`）→ 写入空格 → 复查 `=== restored` → 删 slots[slotKey] → revision+1 → dirty → publish "added"。
- 成功后 `markDirty()`（`_root.存档系统.dirtyMark = true`），通知隔离用 EventBus recovery token（复制 `publishCommittedSlot` 模式）。
