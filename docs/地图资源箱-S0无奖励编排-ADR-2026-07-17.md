## 2. S0 要证明什么

S0 只证明以下闭环：

```text
一次 interactionKeyDown
  → 中央裁决至多选择一个箱子
  → 精确开发 fixture 签发一个 chestSession（此时不 kill）
  → Host 排队打开 Lockbox
  → Web 对 exact flowHandle + panelInstanceId 完成 bind
  → success / cancel / failure 只提交一次
  → AS2 以当前 session 状态裁决
  → success 才由 ChestSessionService 唯一触发 kill
  → XFL 开盖帧回调被 spy 恰好观察一次
  → 无奖励、无 lootContainer、无经济写、无旧资源箱 UI
```

S0 不能被解释为已经证明奖励安全、断线后的非空容器恢复、玩家真实操作、防本地进程篡改或 Launcher 生产闭包可发布。

## 3. 冻结决策

### 3.1 箱型只认六项 preset allow-list

中央裁决器只把 `target.presetName` 与下列六个字符串做全等比较：

1. `保险柜`
2. `生存箱`
3. `装备箱`
4. `资源箱`
5. `纸箱`
6. `隐藏资源点`

`presetName` 缺失、未知或不在白名单时，该实例不是箱候选。不得用 `row`、`col`、`掉落物`、linkage 名模糊匹配或“拥有 interaction area”作为箱型兜底；投影召唤器等非箱元件即使碰巧拥有相同字段也不得进入裁决器。

中央裁决覆盖六类箱，但 S0 的 Lockbox 实验路径只允许一个精确标记的 `保险柜` fixture：

- 被选中的 `row == 0 || col == 0` 箱仍委托原直爆处理器，绝不签发 `chestSession`。
- 被选中的其他非 S0 箱仍委托各自现有处理器；S0 不改变它们的奖励和 UI 语义。
- 只有同时通过 §3.5 两道开发门、preset 为 `保险柜`、网格有效且 fixture 身份精确匹配的目标，才进入无奖励 Lockbox 路径。

“默认断开”只适用于 `ChestSessionService` 实验 flow 与 Host/Web 接缝，不适用于中央裁决器。`BoxInteractionArbiter` 已在 `InteractionHandler` 初始化路径中对六类箱直接注册，任何包含该源码的 AS2 发布都会全局改变箱子 fan-out。本轮 `asLoader.swf` 已发布，因此中央裁决已进入本工作区的 Flash 注入面；S0 双实验门仍默认关闭，但不能以此豁免全局裁决回归。真实游戏的单箱、邻箱、网格/直投、`currentMC`、投影召唤器和地面拾取已从“发布前门”转为**发布后必须人工验收项**；fresh TestLoader 绿灯不能替代它们。

### 3.2 XML 参数注入时序：在真正提交互动时重读 marker

当前 `SceneManager.addInstance()` 先执行 `gameworld.attachMovie(...)`，之后才以 `ObjectUtil.cloneParameters(inst, info.Parameters)` 注入关卡 XML 参数。箱子时间轴首帧和 `初始化地图元件` 因而可能早于 XML marker 到达。

据此冻结：

- 注册时只缓存目标引用和稳定的 `registrationOrder`，**不得缓存 fixture marker 的真假**。
- 实际胜出后的提交处理器必须从目标对象重新读取当前 XML 注入值，再执行开发门和精确 fixture 判定。
- S0 fixture 使用一个专用、版本化的逻辑标识（语义名 `chestS0FixtureId`，唯一允许值 `insurance-safe-s0-v1`）。实现若因现有 XML 命名约束采用等价字段，必须在测试夹具与本 ADR 同步记录，不能接受任意 truthy 值。
- marker 缺失、晚到但尚未注入、拼写不同、类型不符或值不全等时均 fail closed：不进入实验 wire，并按该箱原有分支处理。
- TestLoader 必须模拟“先 attach/register，后 clone XML 参数，再互动”，证明 handler 读到的是最新 marker；只测初始化时已有 marker 不算通过。

### 3.3 `BoxInteractionArbiter` 的注册、候选与稳定排序

箱实例在地图元件 initialize 时注册，在 cleanup、kill 或 scene unload 时撤销。重复 initialize 的幂等身份是 `target + dispatcher`：同一 dispatcher 重复调用零新增订阅；dispatcher 被替换时必须从旧 dispatcher 精确退订本组件的 local / global / target-event handler，再对新 dispatcher 恰好接线一次。普通 cleanup / kill 只把 target 从 active 候选撤销并保留首次 `registrationOrder`，以便同一目标重建后复用；真实 `onUnload` 还必须从 known record 中 `forget` 已销毁 MovieClip，释放强引用但不回退场景单调序号。对显式白名单识别出的箱型，`BoxInteractionArbiter.register` 失败必须使整个 `InteractionHandler.initialize` 回滚，禁止退回逐 target 的 legacy `subscribeGlobal`，否则会重新引入多箱 fan-out；A03F 固定断言零 per-target global/local wiring、零 pickup、零初始化标记和零残留 record。不得依靠 `for..in gameworld` 扫描，也不得依靠 AS2 `Array.sort` 的稳定性。

每次全局互动输入只建立一次候选快照。候选仍遵守当前距离 `< 50`、area 相交、目标存活和可互动条件。裁决键冻结为以下字典序：

```text
(dx² + dz², registrationOrder)
```

其中距离使用玩家与箱子在现有游戏世界 X/Z 平面的坐标；任一坐标或计算结果非有限时，把距离视为正无穷。先比较距离，距离相等再比较 `registrationOrder`。实现应以一次线性扫描保留最小项；不得假定 `NaN` 比较行为或排序稳定性。

一次输入最多向一个胜出箱提交后续处理。其他同时命中的箱保持未消费、可在后续新输入中单独互动。

### 3.4 与其他互动消费者的边界

S0 不建立全游戏“按键已消费”总线，只收束箱子 fan-out：

- 若 `SceneInteractionManager.currentMC` 存在，则该显式场景互动对箱候选具有独占权；本次不选择箱、不签发 `chestSession`，由现有场景互动路径处理。
- 非箱 `InteractionHandler` 目标继续按 legacy 规则消费同一输入；例如投影召唤器可以与本次唯一胜出箱同时生效，但不能导致第二个箱提交。
- 地面 `PickUpManager` 同样保留 legacy 共消费；地面物可与唯一胜出箱同时被处理。
- S0 不改变上述非箱 / 地面消费者之间的相对顺序。未来若要全局互斥，必须另立 ADR，不能顺手扩张本切片。

### 3.5 两道独立开发门

实验 flow 必须同时通过两道独立门；任一道关闭都 fail closed：

1. **AS2 fixture 门**：当前运行明确处于开发 / TestLoader 允许态，且提交时重读的 `presetName`、网格属性、`chestS0FixtureId` 与允许的 source/fixture 身份全部精确匹配。
2. **Host 实验路由门**：`SteamOwnershipCheck.IsDevRepository(projectRoot)` 为真，且环境变量 `CF7_DEV_LOCKBOX_S0` 全等字符串 `1`；请求来自受信游戏连接并携带唯一允许的 source `as2-chest-s0` 与 fixture `insurance-safe-s0-v1`。普通 `LOCKBOX_TEST` / UI devMode 不构成本门。

两道门之外还必须做输入白名单校验，但不得把“参数校验通过”冒充开发门。现有普通 Lockbox panel、lazy registry 与 `LOCKBOX_TEST` 保持不变；不得新增地图资源箱 S0 专用的生产 AS2 `panel_request` / Host business route / task 白名单。实验 task 不可由 HTTP 或普通 Web 消息直接调用。门关闭时不允许静默降级成“看起来成功”：返回可观测的开发禁用 / fixture 不匹配结果，AS2 撤销未消费 attempt，箱子恢复 `AVAILABLE`。

AS2 门已冻结并落地为 authored target 上的 exact `chestS0As2GateId === "local-as2-dev-s0-v1"`，提交时与 `chestS0FixtureId / preset / row / col` 一起重读；默认关闭，Host bootstrap、普通 Web / HTTP / 控制台消息均不能打开或替代该门。socket disconnect generation 进入单调 high-water：任何 `Ready <= high-water` 永久拒绝；高于当前 live 的 disconnect 即使先于对应 Ready，也必须推进 live generation、作废旧 binding/retry 并请求 exact native close，但不得伪造 AS2 terminal 或 DOM proof。scene teardown 收束 target 并保留最小因果 tombstone。same-process 新 generation 必须使用 fresh capability/bootstrap，`resumeActive=false` 只把本地孤儿 pending 以已知 no-write 收束，`resumeActive=true` 才恢复 Host 已持有的 exact active identity；旧 capability 不得跨 generation 复用。已消费 bootstrap 在 suspend 后即使重新观察到 marker 也不得再 ack、恢复或收束 authority；S08 要求只有 fresh Host bootstrap 才可重新激活并收束 orphan。ordered identity adoption 只能发生在 `_flow == null`；已有 flow 时，同 session/epoch 但不同 `flowHandle/panelInstanceId` 的 ApplyResult/OpenFailed 必须被消费但零状态、kill、ack，原 exact identity 继续有效（S09）。

### 3.6 `ChestSessionService` 状态与唯一 kill 所有权

S0 冻结下列箱 / session 状态；`COMPLETED_NO_REWARD` 是 spike 专用终态，不是 S1 生产领域终态：

| 触发 | 箱状态 | 当前 session 状态 | 副作用 |
|---|---|---|---|
| 初始 / 已知失败撤销后 | `AVAILABLE` | 无 active session | 可接受下一次新输入 |
| 精确 fixture 胜出 | `LOCK_PENDING` | `LOCK_PENDING` | 签发新 session；不 kill、不滚奖 |
| 首个已知 `success` | `OPENING_ANIMATION` | `OPENING_ANIMATION` | 先提交状态，再由 service 发一次 own-kill |
| 首个合法开盖帧 callback | `COMPLETED_NO_REWARD` | `COMPLETED_NO_REWARD` | spy +1；不创建容器、不滚奖、不打开旧 UI |
| 已知 `cancel` / gameplay `failure` / panel 明确未打开 | `AVAILABLE` | 旧 session `REVOKED` | 不 kill；允许下一次输入签发新 session |
| scene unload、authority teardown，或 own-kill 前目标已被外部击碎 / 销毁 | 目标失效 | `EXPIRED` | 后续 result / callback 零副作用 |

状态与时序的硬约束：

- `ChestSessionService` 是 S0 异步保险柜路径触发正常 kill 的唯一所有者。`InteractionHandler` 在签发 session 时不得先 kill。
- 接受首个 `success` 时，先把 session 和箱状态推进到 `OPENING_ANIMATION` 并记录 `killIssued`，再同步发布一次 kill。这样即使 kill 路径重入，也能看见已消费状态。
- own-kill 证明只在该次同步 kill 分发栈内有效；若 adapter 返回却没有同步观察到对应 death，或 adapter 抛错，session 必须以可解释错误进入 `EXPIRED`，不得把之后任意外部 death 误认成 own-kill。同步 scene unload / break / authority teardown 已先形成终态时，返回路径必须保留原终态与原因，禁止二次覆盖。
- 三个 AS2 adapter 在签发前都必须以 `typeof == "function"` 验证；请求、kill 或 frame-spy adapter 的异常必须被包含并收敛到 `REVOKED / EXPIRED`，不得遗留 active 或临时 ownership 标志。
- cancel、failure、打开失败、stale、duplicate 与 unsupported result 均不得 kill。
- retry 只能来自下一次新的互动输入，必须得到新的 session identity。`REVOKED / EXPIRED / COMPLETED_NO_REWARD` 的旧 session 永久 stale；旧 success、cancel、failure 和 callback 全部零副作用。
- 同时只允许一个 active chest flow。已有 active flow 时，新箱保持 `AVAILABLE`，返回可观测 busy；不为它预签 session，也不 kill。
- S0 result 只接受有限枚举 `success / cancel / failure`。结果不得携带奖励 descriptor、数量、倍数、货币、可兑换分数或任意经济指令。

### 3.7 开盖帧 spy 与无奖励保证

S0 必须有可注入的 `openFrameSpy` 接缝，按 `target + active session` 验证开盖帧 callback：

- 精确 fixture 的首次合法 callback 把 spy 计数从 0 变为 1，并进入 `COMPLETED_NO_REWARD`。
- 重复 callback、旧 session callback、其他 target 冒用 callback 或 callback 先于成功 result，计数保持不变。
- 精确 fixture 的 callback 在 S0 被短路到无奖励 adapter，不调用现有掉落滚动、临时 `ArrayInventory`、敌人爆落或旧 `资源箱界面`。
- 非 fixture 的现有 XFL callback 必须原样转发；spy 不得成为全局奖励替代品。
- 自动测试断言 kill 次数为 1、callback spy 为 1、roll/create/container/UI spy 全为 0。

这是一条测试接缝，不授权批量修改箱子 XFL。若实际需要修改独立素材库 XFL，必须另按顶层 XFL 治理与直接 target publish 规则执行；S0 默认优先通过 AS2 全局回调的精确 fixture 分支完成。

### 3.8 Host：排队成功不等于 Web 已绑定

Host 维护 `flowHandle → chestSession` 的私有一对一映射：

- `flowHandle` 由 Host 为每次 attempt 新建，是暴露给 Web 的不透明句柄；Web 不接收 `chestSession`。
- `panelInstanceId` 表示一个实际 DOM panel 实例。Web 只有回传 exact `flowHandle + panelInstanceId` bind ack 后，Host 才可把 panel 记为已打开。
- tracked open 必须在入队前同时预留不可复用的 `panelInstanceId` 与 Host request token；PanelHost 执行队列不得到 `DoOpen()` 时才临时生成另一身份。协调器还必须能按 request token 撤销尚未执行的精确 open，或在执行前再次询问 coordinator 是否仍允许。因果查询若已证明 unbound，旧队列项不得随后晚开同一 flow。
- `PanelHostController.TryOpenPanel()` 或队列 enqueue 返回 true 只表示请求进入异步队列，不能推进 AS2 为“已打开”。
- `TryPostToWeb=true` 在非 UI 线程只表示已经排入 UI 队列，S0 从不把它当终态或 DOM 证明；仍须由 arm/bind/close ack 与 timeout/reconcile 收敛。tracked PanelHost open 在 UI pump 中直投，以保留 execution gate 与实际投递结果的因果顺序。
- S0 的 bind 点冻结为：Lockbox `onOpen` 无异常返回、S0 adapter 已写入 exact identity，且 `Panels` 已把 `_active` 提交为 `lockbox` 后立即回 ack。谜题资源 / 音频 / generator 的 `ready` 是后续玩法状态，不得混成 DOM bind 证明。
- 只有 Web 明确回复非瞬态 lazy-load / bind 失败，或 `PostToWeb` 明确未投递，才是已知 panel-open failure；Host 通知 AS2 撤销 attempt，等待其已知 ack 后才关闭候选并释放 pause。LazyLoader 已有 owner 处于 `LOADING` 时的 `wire_loading` 只触发 fresh capability retry：不得抢 owner、不得二次 load，也不得冒充已知 open failure。
- bind timeout、bind ack 丢失 / 畸形或运输断线都不能证明 DOM 未 bind；Host 进入 `OPEN_BIND_UNKNOWN`，保留原 `flowHandle → chestSession`、原 `panelInstanceId` 候选、单 active flow 和 pause lease。timeout 之后迟到的原始 bind ack 不再具有因果新鲜性，只能由 exact `bind_query_result(bound)` 恢复。只对 exact pair 查询或精确关闭：证实已 bind 时继续原 attempt；因果证明未 bind 或 exact instance close ack 只完成 DOM 侧证明，仍须取得 AS2 已知撤销 / 终态与 native close completion 后才可释放。
- 已有 lockbox candidate / active instance 时，同名再次打开在分配新实例或更换映射前即返回 busy。S0 禁止通用 `onRebind`、禁止用同名 open no-op 复用旧 DOM，也禁止生成“Host 新 instance / Web 旧 session”的分裂状态。
- busy 响应不得预分配或改写 flow identity；只有原 panel 回到 idle 后重新 arm，下一次请求才可用 fresh request token、`flowHandle` 与 `panelInstanceId` 进入 tracked open。
- Host 为每次 Web 顶层文档建立单调 `webDocumentEpoch`。bind / query / exact close 都绑定同一 `flowHandle + panelInstanceId + webDocumentEpoch`；active / unknown flow 存在时禁止热重载。若仍发生文档重建，只有同一待处理 `NavigationId` 依次观察到 `ContentLoading` 与成功 `NavigationCompleted`，才构成旧 DOM teardown proof；失败、ID 错配、same-document 或 fragment 导航都不能释放旧 identity，导航未决期间也不接受 Web 消息或 begin。导航开始原子失效未消费的旧 arm，完成后 fresh rearm；begin 预留与 open execution gate 均和 navigation-pending 串行。
- Web DOM teardown、native `PanelHost` close completion 与 AS2 权威终态分别记录。socket 断开、native close 或新空文档都不能冒充 Web exact close / teardown ack；native close 失败必须对同一实例重试。
- 旧 `flowHandle`、旧 `panelInstanceId`、错配 pair 与其他 panel 的 ack/result 一律 stale，不能推进 AS2。

### 3.9 专用实验 task 与 `minigame_session` 隔离

S0 业务 result 必须走受 §3.5 双门保护的专用实验 task。现有 `minigame_session` 保持观测信封，不获得 call / ack / authority 语义：

- `chestSession`、`flowHandle`、`panelInstanceId`、fixture 身份、奖励字段和原始 result payload 不写入 `minigame_session`。Host 必须在任何日志序列化前先做精确归一化；S0 pause 释放后到达的 Lockbox 信封也仍由 sanitizer 消费。
- 允许的 telemetry 仅为去敏事件类别、有限结果类别、耗时桶和错误类别；畸形 Lockbox 只记固定 drop code，不得把原信封落日志，也不得足以重放业务提交。
- Web 的 Lockbox score、seed、轨迹或输入明细只可作本地玩法 / 去敏观测，不是 AS2 状态转换之外的奖励凭证。
- 普通 minigame 消息不能调用 chest task；chest task 也不能借 telemetry 信封绕过 Host route gate。仅把 task 标成 `httpCallable=false` 不足以隔离，因为当前 Web 通用 `type:"task"` 也会进入同一个 `MessageRouter`；S0 必须在 WebOverlay origin 边界显式拒绝该 task，且只从受信 XMLSocket / AS2 注册入口调用。
- Lockbox core 的 `success` 与 `partial_success` 在 S0 均下转换为有限业务枚举 `success`，`fail` 下转换为 `failure`，用户主动关闭 / 取消映射为 `cancel`。任何其他终态、夹带字段或本地 score 均拒绝，不作宽松 fallback。
- Web production cleanup 不得绑架因果 proof：`onClose` 抛错仍先完成 exact close 与 `close_ack`；forced teardown 中 `onClose` 与 `onForceClose` 均抛错时仍完成 teardown ack。只记录固定 `panel_cleanup_exception` code 与 exact identity，异常文本不得进入证据或日志（AW26/AW27）。
- S0 panel open 的 console 记录必须把完整 `initData` 替换为常量 `[redacted]`，不能只遮顶层 capability；嵌套 browser-host-shim identity 同样全部遮蔽。普通非 S0 panel 仍按原契约只去敏 capability（AW28/AW29）。
- S0 discriminator 遇专属 source/fixture 任一锚点，或完整九字段 `OPEN_KEYS` shape，都会把信封标为 reserved；普通真实 PanelHost partial 与非专属 8/9 字段碰撞在 `ARMED/IDLE` 直通，reserved 后再由 exact validator fail closed。非 `ARMED` 的 reserved `onOpen` 只安排本地视觉关闭 microtask：以单调 open/rebind sequence 与 element token 防陈旧，仅在 token 最新、`!current` 且仍为同一 active Lockbox 时关闭。cleanup 抛错仍令 `active=null` 且只记录固定分类；不得伪造 close/teardown proof、改变 authority 或 consume。后续普通 rebind 取消旧 cleanup 并恢复 DOM；reserved rebind 不得关闭 ordinary active（AW30）。rearm 必须先完整验证新 arm，再原子替换旧 arm；校验失败保留已有可用 arm（AW31）。

### 3.10 未知结果、因果查询与 pause lease

每个写意图有从 1 开始、只在该 flow 内单调递增的 32 位正整数 `flowCallId`（上限 `2147483647`）；它与 XMLSocket / MessageRouter 外层 transport `callId` 是两个字段，禁止复用或相互推断。result/cancel/failure 提交在 timeout、断线或 ack 畸形后进入 `RECONCILE_REQUIRED`，不得自动重发原提交。panel bind 另以 exact `flowHandle + panelInstanceId + webDocumentEpoch` 作未知身份；bind ack 未知时进 `OPEN_BIND_UNKNOWN`，同样不得猜测未打开。

未知状态只能由 AS2 权威查询解除，且响应必须证明其观测水位不早于 unknown call：

```text
observedCallWatermark >= unknownFlowCallId
```

普通旧 snapshot、Web 本地缓存、Host “曾经发送过”记录或队列状态都不能解门。因果新鲜查询可得到三类结论：

- 原 call 已应用为 success：保持 / 恢复 `OPENING_ANIMATION` 或 `COMPLETED_NO_REWARD`，不重发 result、不再 kill。
- 原 call 已应用为 cancel/failure：确认旧 session `REVOKED`、箱回 `AVAILABLE`。
- 已确认原 call 未写入：以已知 no-write 撤销旧 attempt；若重试，由新输入创建新 session。

`queryResult` 自身保持纯读；只有受信有序 task 记录了满足水位的新鲜观测后，才能调用权威 `known-no-write` 收敛入口原子撤销旧 session、恢复 `AVAILABLE` 并释放 active。Web / Host 自报水位或普通旧 snapshot 不能调用该入口。

当前 AS2 的 `webPanelPause / webPanelUnpause` 实际只有一个全局 lease，S0 不虚构“独立 flow lease”。实验协调器从候选建立到已知收束期间必须独占全部 Web panel 编排：开始前要求无其他 active / returnTo / pending panel，期间拒绝其他 panel open 与同名 rebind，并拦截 socket reconnect 的通用 `webPanelUnpause`。queue accepted、panel 转场、result pending、`OPEN_BIND_UNKNOWN` 和 `RECONCILE_REQUIRED` 均不得释放。只有 AS2 已知终态或已知撤销 / `EXPIRED`、Web DOM 已有 exact close / teardown proof、native `PanelHost` exact close 已完成这三层所需证明全部收齐后，才可调用外部 pause-release；回调失败时必须保留 terminal flow、identity 与证明并重试，不得 reset 或 fresh arm，回调成功后才可恢复焦点、释放 identity 与这个全局 lease。S3 若要并行 panel 或真正的多 owner pause，必须先引入可计数 / 可寻址 lease 协议，不能沿用 S0 的全局串行假设。

### 3.11 Host state-driven reconcile 与 ack-loss 收敛

Host 不能把一次 timer 当作“尽力而为”的清理；它必须按协调器当前状态持续驱动同一 exact identity 收敛：

- `OPEN_BIND_UNKNOWN`：重复发送 exact `bind_query`，并用 `close_query` 探测已有 DOM close proof；不创建第二 flow。
- `REVOKE_PENDING`：重发同一 open-failed / revoke 投影、查询 exact close，并确保 native close 已请求；不得把运输失败误记为撤销完成。
- `RECONCILE_REQUIRED`：Host 直接向 AS2 发送因果 authority query，不依赖 Web 先回一轮 `result_query`，更不重发原 result 写。
- `RESULT_APPLIED`：重放最后一份 Web 权威投影，同时只对 AS2 作无写 terminal polling；非终态继续轮询，终态到达后再进入关闭证明收集。
- `KNOWN_TERMINAL`：继续重放最后一份 Web 权威投影；DOM proof 缺失时发 exact `close_query`，native close 未完成时重试同一实例，证明齐全后才释放。

Web actual wire 也必须主动收敛运输丢失：result delivery 未知时按同一 `flowCallId` 重复 `result_query` 直到 reconcile reply，不重放 result；正常 close ack 丢失时响应 Host `close_query` 并重发 exact close ack；forced teardown ack 丢失时保留 `TEARDOWN_UNKNOWN` / tombstone，使用本地重试并响应 exact `close_query`。所有 projection、query、ack 与 retry 都必须携带原 `flowHandle + panelInstanceId + webDocumentEpoch`，迟到或错配消息零副作用。

Host 生命周期还必须满足以下线性化约束：pending generic unpause 在任何已有 arm binding 的早返回之前补发，且补发成功前 begin 最终提交 fail closed、又不得消费现有 Ready capability；bind/authority/binding-ack/retry/reconcile timer 都有 exact owner/version，replace、stop 或 dispose 后的旧 callback 不得清空或污染 fresh slot。所有 Runtime 外部副作用要么在 Runtime lock 内线性化，要么先登记 outbound action；`Dispose` 先禁止新 outbound，再等待其他线程的在途动作退出，同线程 callback 重入允许自行退栈以避免自死锁。当前生产关停顺序固定为游戏 process → `DevLockboxS0Runtime` → `PanelHost` → `WebOverlay`；热 Dispose 清 pending 不是当前可达的 S0 路径，不列入人工退出门，也不为此扩张通用 API。若未来引入热卸载，必须先新增跨 Runtime / UI queue / PanelHost execution 的可取消租约，不能外推当前 shutdown 契约。

tracked `OpenPosted` completion 不是天然新鲜：还要复核 exact active identity、socket generation、document epoch、navigation 与游戏进程身份。失鲜时立即进入 unknown/terminal recovery、重试 exact native close，不启动普通 bind timer；游戏进程被替换意味着旧 AS2 authority 已不可恢复，Host 对旧 identity 投影 `EXPIRED` 并收齐 DOM/native proof，不允许新进程或迟到 Ready 复活旧 flow。pause release callback 期间若采用更高 generation，最终 proof 必须追到新 generation；bootstrap ack 的最终提交也须在同一 lock 内重验 disposed/connection/generation/process/pause-role。

## 4. S0 明确不做的事

- 不调用掉落 RNG / PRD，不改 `掉落物.总数`，不创建或移动任何 `BaseItem`。
- 不增加 `lootContainer`、inventory lease、claim、transfer、close/abandon 或持久化。
- 不把 `success` 当作奖励凭证；不开旧 AS2 `资源箱界面`。
- 不批量修改六类箱 XFL；不铺到玩家正常关卡。
- 不冻结 S1 特殊资产 claim、loot-specific S2 panel 拓扑或 S3 生产 wire 的字面命令；S2 的共享 `transfer-pair` 布局、焦点、生命周期、加载顺序与验证门已经由工作台 canonical doc 冻结，S0 不得另行分叉。

- 不把单机 Host build、历史 v1 candidate、xUnit、旧 runtime 或 `publish_done.marker` 当成生产 / Flash 成功证明；正式 Host/native 发布只认 v2 request、签名/故障域 quorum、policy receipt、strict verifier 与 promotion。

## 7. 回滚方案

S0 不引入数据迁移，因此回滚必须是代码 / 配置级且不触碰玩家存档：

1. 首先关闭 Host 显式 S0 feature gate；实验 task 立即拒绝新请求。
2. 关闭 AS2 fixture 门或移除 dev fixture 的精确 marker；所有箱回到中央裁决后的既有处理分支。
3. 对已经 active 的无奖励 session，按已知取消收束；若运输结果未知，先作因果查询，禁止用回滚动作重发 result。
4. 回滚实验 Host/Web 接缝时只有在 A01—A12、fresh Flash 混合 fixture 与发布前真实游戏混合回归均通过后，才保留 `BoxInteractionArbiter` 的“一次输入至多一箱”修复；不得把默认断开的 Host/Web 实验链当作 arbiter 的发布安全证明，也不得为了撤掉 Lockbox 又无证据地恢复多箱 fan-out。
5. 若裁决器自身出现回归，停止发布该开发 candidate，回退整个 S0 代码切片并记录 A01—A12 的失败证据；不得在生产环境以临时全局 consumed flag 掩盖。
6. 删除 / 停用 dev fixture marker 不需要清档，因为 S0 从未创建奖励、容器或持久化状态。
