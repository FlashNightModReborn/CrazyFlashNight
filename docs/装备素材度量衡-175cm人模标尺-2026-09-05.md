# 装备素材度量衡：175 cm 人模标尺

**文档角色**：首轮尺度标定的历史证据，保留当次读数、推导与样本。现役装配方法见 [美术资产装配](../agentsDoc/art-asset-assembly.md)，程序读取的制作档位由 [profiles.json](../tools/asset-metrology/profiles.json) 维护。<br>
**最后核对代码基线**：commit `6fd5c4065137975e8c2fac9f125ffae465eead17`（2026-09-05 工作树）。<br>
**范围**：`things0` 的常规男主角骨架，`things` 的枪械、裸体部件与防具样本；只读分析源资产。

## 1. 可以先采用的尺子

以「男主角放松空手站立、无头发、无装备，头顶到最低裸脚底 = 175 cm」作为标定约定：

| 所在坐标层级 | 建议制作尺度 | 一个局部像素对应 | 适用说明 |
|---|---:|---:|---|
| 武器直接挂载的外层元件 | **300 px / m = 3 px / cm** | 约 3.33 mm | `枪-长枪-*`、`枪-手枪-*`、主手 `刀-*` 的局部空间 |
| 身体、四肢装备直接挂载的外层元件 | **350 px / m = 3.5 px / cm** | 约 2.86 mm | 常规模型上的制作起点；关节件还须保持注册点与接口 |
| 脸型、面具挂载的外层元件 | **约 300 px / m** | 约 3.33 mm | 头部没有身体那一层约 85% 的缩放；各姿势存在差异 |
| `主角-男` 根元件局部空间 | **约 83 px / m** | 约 12.05 mm | 175 cm 时角色外层为 100%；不包含舞台、窗口或镜头缩放 |

这里的像素是 Flash 的**逻辑坐标像素**。XFL 轮廓的 twip 数值除以 20 才是像素；不能把打印 DPI 或屏幕物理尺寸引入这把尺子。单位依据见 [Adobe Flash CS6 参考手册](https://help.adobe.com/archive/en/flash/cs6/flash_reference.pdf) 的 “Scaling, points, and pixels”。

**300 / 350 是由本次人体标定推导并取整的制作建议；没有在源码中发现作者显式声明的「一米常量」。** 换用其他身高假设或标定姿势，换算值也会改变。

## 2. 推导依据

### 身高参数只控制角色外层比例

[`UnitUtil.as`](../scripts/类定义/org/flashNight/arki/unit/UnitUtil.as) 定义 `STANDARD_HEIGHT = 175`，`getHeightPercentage(heightCM)` 返回 `(heightCM * 100 / 175) | 0`。

[`单位函数_fs_aka_玩家模板迁移.as`](../scripts/逻辑/单位函数/单位函数_fs_aka_玩家模板迁移.as) 将返回值写入角色的 `_xscale`、`_yscale`。因此 175 cm 对应角色外层 100%，并不意味着角色画稿高 175 px。其他身高按整数百分比缩放，装备也随角色一起缩放。

### 人模还有约 27.7% 的内部缩放

[`主角-男.xml`](../flashswf/arts/things0/LIBRARY/主角-男.xml) 的「空手站立」是 XFL `index=2`，也就是 Flash 第 3 帧。其 `man` 实例引用 `sprite/空手待机`：

```text
a = 0.277084350585938
d = 0.276901245117188
tx = 3.4
ty = -62.35
```

[`sprite/空手待机.xml`](../flashswf/arts/things0/LIBRARY/sprite/空手待机.xml) 中取「站立-男」，XFL `index=52`，即 Flash 第 53 帧。递归还原肢体、holder 和裸体基本款的矩阵，测量曲线真实极值，得到：

| 测量对象 | `主角-男` 根坐标中的 y |
|---|---:|
| 基本脸型的头顶轮廓 | -135.372113 px |
| 较低的一只裸脚底轮廓 | +9.820653 px |
| 两者之差 | **145.192765 px** |

脚底不在 y=0，所以不能仅量原点到头顶。此高度排除了头发、名字、碰撞框、武器和控制标记。

```text
角色根坐标中的一米 = 145.192765 / 1.75
                    = 82.967295 px

还原 man 编辑空间中的身高 = 145.192765 / 0.276901245117188
                         ≈ 524.35 px

man 编辑空间中的一米 ≈ 524.35 / 1.75
                    ≈ 299.63 px → 制作时取 300 px
```

轮廓数字不含笔画向外扩张。以当前已烘焙的裸体 PNG、导出倍率与注册点另做 alpha ≥ 128 的投影复算，得到约 **145.46 px**，与 XFL 轮廓法差 **0.27 px / 0.19%**。这个差别不足以改变 300 px / m 的取整结论；PNG 复算只作交叉检查，不代表新编译或游戏现场验收。

### 武器接近原尺寸挂入，身体再缩到约 85%

[`DressupReferenceManager.as`](../scripts/类定义/org/flashNight/arki/unit/UnitComponent/Dressup/DressupReferenceManager.as) 的 `doConfig` 用 `mc.attachMovie(skinConfig, ...)` 挂入装扮，没有按现实尺寸自动归一化。外层元件随后继承 holder 的完整矩阵。

本次从 XFL 重新计算的完整挂载比例：

| 采样位置 | 局部 x 轴长度倍率 | 局部 y 轴长度倍率 | 按统一人体标尺反推 px / m |
|---|---:|---:|---:|
| 长枪站立 → 长枪装扮 | 0.276938 | 0.276847 | 299.59 / 299.69 |
| 手枪站立 → 手枪装扮 | 0.276891 | 0.276801 | 299.64 / 299.74 |
| 兵器站立 → 主手刀装扮 | 0.275891 | 0.275923 | 300.72 / 300.69 |
| 空手站立 → 身体装扮 | 0.236704 | 0.236342 | 350.51 / 351.05 |
| 空手站立 → 上臂装扮，一侧 | 0.235004 | 0.234850 | 353.05 / 353.28 |
| 空手站立 → 脚装扮，一侧 | 0.236691 | 0.236535 | 350.53 / 350.76 |
| 空手站立 → 脸型装扮 | 0.277718 | 0.277538 | 298.75 / 298.94 |

身体在 `sprite/空手待机` 中还有约 `0.854` 的肢体实例缩放，因此约 `0.277 × 0.854 = 0.2367`。同样的一米，需要在身体元件里画得比武器元件更大。

表中的倍率使用矩阵列向量的长度：`sx = sqrt(a²+b²)`、`sy = sqrt(c²+d²)`，没有把旋转后的 `a` 或 `d` 单独误当缩放值。

## 3. 「元件内部」必须指明层级

300 px / m 针对运行时直接 `attachMovie` 的武器外层，而不是随意双击到的最深画稿层。

| 样本中的编辑层级 | 到武器外层的额外倍率 | 该层一米的参考长度 |
|---|---:|---:|
| `枪-长枪-AK47` 外层 | 1 | 300 px |
| AK47 外层所引用的 `素材/突击步枪/AK47` | 3.193054 | **约 93.95 px** |
| `枪-长枪-M4A1` 外层 | 1 | 300 px |
| M4A1 外层所引用的 `M4A1 stadard` | 3.727905 | **约 80.47 px** |

依据分别是 [`枪-长枪-AK47.xml`](../flashswf/arts/things/LIBRARY/1.枪械相关/长枪/枪-长枪-AK47.xml) 和 [`枪-长枪-M4A1.xml`](../flashswf/arts/things/LIBRARY/1.枪械相关/长枪/枪-长枪-M4A1.xml) 的嵌套实例矩阵。AK47 原始素材宽约 110.775 px，经 3.193 倍放大后，才接近外层完整枪械的 353.725 px。

防具同样可能继续包着有缩放的子元件。抽查的远古诛神胸甲身体有 `1.071594` 倍子元件，蓝晶面具子元件为单位矩阵；文件夹名称不能代替变换链。

若内层到外层是等比缩放 `q`：

```text
内层应画长度 = 原型长度（米）× 外层 px/m ÷ q
```

若含非等比缩放或斜切，则使用整个链的矩阵沿目标长度方向计算。长度方向为单位向量 `v` 时，倍率是 `|A·v|`；不能只取 Flash 属性面板的一个百分比。

## 4. 旧枪械的大小不等于人体实尺

在 `things` 中排除枪口定位元件，递归测量第一帧可绘制轮廓：

| 外层武器元件 | 枪体横向长度 | 按 300 px / m 换算的人体比例长度 |
|---|---:|---:|
| AK47 | 353.725 px | 117.91 cm |
| M4A1 | 402.987 px | 134.33 cm |
| M1911 | 101.208 px | 33.74 cm |
| Glock 18 | 91.963 px | 30.65 cm |

作为量级核对，[Colt 2024 MLE 目录，第 26 页](https://www.colt.com/wp-content/uploads/2024/09/24-COLT-2263-COLLATERAL-MLE_Catalog-web-FINAL.pdf) 给同类 M4 的全长为缩托 77.55 cm、伸托 85.80 cm。以伸托尺寸为例，人体实尺应是 `85.8 × 3 = 257.4 px`，现有 M4A1 约为其 **1.57 倍**。这是同类原型对照，未将画稿中的每个配件认定为该目录的完全相同配置。

因此，按真实人体比例制作与沿用旧枪视觉大小会得到不同结果。需要沿用某把旧枪的夸张比例时，可另外记录「视觉倍率」：

```text
最终外层长度 = 原型长度（cm）× 3 × 视觉倍率
```

人体基准默认倍率 1；沿用上述 M4 尺寸关系则约 1.57。不要把一个旧枪样本的倍率提升为所有装备通用的米制换算。

测量时必须排除逻辑标记。现有 Glock 18 的 PNG 外框在除去导出倍率后约 138 px，但实际枪体轮廓宽只有约 92 px，枪口标记会把外框撑大。`MovieClip._width`、整张导出图片宽度都不一定是武器本体长度。

## 5. 直接导入的用法

以一件现实长度 **88 cm** 的武器、源图中枪体自身长 **1200 px** 为例：

```text
武器外层目标长度 = 88 × 3 = 264 px
相对原图的缩放百分比 = 264 / 1200 × 100% = 22%
```

若放进 AK47 那个已经被放大 3.193054 倍的内层素材实例：

```text
内层目标长度 = 264 / 3.193054 ≈ 82.68 px
相对原图的缩放百分比 ≈ 6.89%
```

这是两种编辑位置各自的结果，不是连续应用的两次缩放。源图的 1200 px 指已知物理长度对应的那段内容，不含留白、透明边缘、枪口定位标记，也不能把透视斜拍照片的横向外框直接当全长。

简短速查：

| 现实长度 | 武器外层 | 身体、四肢装备外层 |
|---:|---:|---:|
| 10 cm | 30 px | 35 px |
| 20 cm | 60 px | 70 px |
| 50 cm | 150 px | 175 px |
| 80 cm | 240 px | 280 px |
| 100 cm | 300 px | 350 px |

缩放时同时约定注册点：武器以握持基准对齐，枪口位置另行放到真实枪口；衣物以既有肢体接口对齐。绝对长度对了，握把、双手间距或关节仍可能不合；这类差异可用现有 battle rig 预览核对，不必靠反复重进游戏猜总比例。纸娃娃入口见 [换皮参考管线](../tools/monster-reskin-pipeline/README.md)。

## 6. 精度与适用边界

- 标尺固定使用放松空手站立。七种常态的裸模轮廓高度分别为：空手 145.19 px；长枪、手枪、手枪2、双枪各 138.38 px；兵器 145.73 px；手雷 142.98 px。持枪姿势的可见高度下降约 4.69%，是姿态变化，不能重新强行标成 175 cm 再算出另一把尺。
- 两脚前后景、头部倾斜和绘画比例都在图里。这里建立的是可复用的美术标定约定，不是对画中人体做解剖学测量。
- 350 px / m 是身体件的近似制作尺度。空手站立的左下臂存在不同轴倍率：约 0.234712 / 0.220540，对应约 353.49 / 376.20 px/m。不能为了硬凑一把等比尺而抹掉既有姿态的变形。
- `things` 与 `things0` 同名裸体件也不全相同：本轮上臂轮廓一致，身体和脚存在小修差异。基准以实际人模 `things0` 为准。
- 本轮没有把女姿势、巨拳、乘骑、非人形、特殊武器生命周期脚本或其他素材库全部外推为已验证。窗口大小、镜头与纸娃娃页面的自动适配缩放不影响元件内部这把尺，但会改变截图中的像素数。

