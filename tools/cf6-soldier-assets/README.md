# CF6 特种兵两阶段装配

**文档角色**：源稿归属、确定性装配、装备入口与验证说明。

重启游戏后可在斗兽场搜索“CF6特种兵”。配表明确区分两个生成入口：

| 兵种 ID | 显示名 | 链接 | 默认初始阶段 |
|---|---|---|---|
| 466 | CF6特种兵·二阶段 | `敌人-CF6特种兵` | 普通二阶段，完整生命 |
| 467 | CF6特种兵·持盾一阶段 | `敌人-CF6持盾特种兵` | 持盾一阶段，破盾后进入普通二阶段 |

关卡或斗兽清单的既有 `Parameters.特种兵初始阶段` 接受数值 `1` / `2`，优先于入口默认值。单位表的 `data` 仍只承担既有装备配置；不放置不会被加载器消费的阶段字段。阶段参数改变初始行为，不重新计算入口的基础面板。

普通入口的阶段 **7**、档次 **5** 为制作组指定；持盾入口沿用这个面板基线，并按自身受击能力重算生命，额外通过持盾专属减伤区分。完整持盾两阶段的新定位为**略强于 Wings**，普通二阶段仍保留此前定位；预设不代替实战强度验证。接入普通根 559 与持盾根 580；撞车 629 未接入。

## 军校生武器与外部配置

固定的 CF6 身体接入 `hasDressup=true`、`enableShoot=true`，使用标准装备初始化、射击事件、枪口、弹匣和装填。默认直接读取现役军校生的 `大学军校学员随机兵器表`，不另建随机表：

| 物品内部名 | 显示名 |
|---|---|
| `M4A1改` | M16战术版 |
| `AK74战术版` | AK74战术版 |
| `M4A1战术版` | M4A1战术版 |
| `DD MK18战术版` | DD MK18战术版 |

[`units.json`](../../data/units/units.json) 中兵种 466 / 467 各自的 `data.primary` 是外部长枪入口。默认 `null` 表示使用上述随机池；填写现有武器名则优先使用指定装备。例如：

```json
"data": {
  "primary": "AK47#4",
  "secondary": null,
  "secondary2": null,
  "melee": null
}
```

这里沿用 `BaseItem` 的装备字符串语法，示例表示四级强化 AK47。关卡生成或斗兽测试也可通过既有 `Parameters.长枪` 传入同一配置。重新运行数值生成器会保留现有 `data`，不会把外部装备改回默认值。

首批主动使用长枪主射击和原生匕首；未接入其他武器槽的攻击动作，也未验证特殊武器的专属战技。其他装备数据可沿标准初始化产生属性，但身体仍为 CF6 固定造型。友方非玩家人形沿用标准装备初始化中的生命 ×3 规则，因此红蓝交换不代表实际生命相同。NPC 装填走自身弹匣状态，不读取或扣除玩家背包。

## 动作与权威

| 动作 | 接入方式 |
|---|---|
| 站立、行走 | 原 498 / 500，共 16 / 21 帧；行走兼作奔跑外观 |
| 长枪点射 | 每轮至多三发、射击窗口最多 18 帧，由 `ShootCore` 按实际枪械间隔调度；实际开火切到 CF6 第 3 帧后坐姿势 |
| 装填 | 标准 `ReloadManager`，35 帧基础过程，读取武器装填负担；目前借用持枪准备姿势，尚无专门的手部换弹动画 |
| 匕首刺击 | 普通 517 / 持盾 573，34 帧；第 14 帧一次 101×135 像素近战判定，基础威力为自身空手攻击力 |
| 受击 | 原 518 的 a0/a1，第 8/19 帧恢复 |
| 击飞、倒地 | 原 520 的 1–40 帧用于浮空，41–116 帧用于落地起身；委托 CF7 物理生命周期 |
| 被投 | 原 519，末帧等待外部投掷状态切换 |
| 死亡 | 原 558 的三条完整分支 1–58、59–104、105–139，分别结束时结算一次 |

八条原身体序列共 378 帧。死亡首姿按同一髋部分件对齐站姿，所有动作使用统一接地平移。独立 `soldierShadow` 覆盖所有可见状态，以世界 Z 接地，处理旋转、镜像、浮空和阴影开关。

近身 95 像素内选择匕首，同一纵深 460 像素内选择点射；横向接近停距 420，换目标有 6 帧反应。普通阶段没有攻击霸体；持盾阶段采用刚体门，普通冲击不会使其硬直或击飞，仍可产生受击位移。574 的短受击画稿用于外部明确切入受击状态；它不代表刚体阶段的普通命中会播放硬直。动作 token 同时绑定当前身体、装备对象和初始化版本；切换状态前调用标准射击清理，受击、暂停、死亡和过期引用不能继续出手。

射击窗口之后保留 30 帧强制停火，下一轮最早在本轮开始 48 帧后。提前打满三发、受击、取消或重新进入射击姿态都保留这个时间点；到期后的排队回调也不能耗弹。暂停冻结该单位的计时。停火期间仍可移动或选择近战；标准装填过程独立完成，不为满足射击时限截断装填。

原占位手枪与 CF6 的地面枪口 helper 已退出生产。实际枪口是 `man.枪.枪.装扮.枪口位置`，登记为标准 `长枪_引用`；射速、弹种、穿刺、威力、散射、音效和容量均来自实际装备。逻辑库提供两个薄入口：`_root.主角函数.清理射击任务` 委托 `ShootCore.cleanup`；`_root.敌人函数.标准击杀` 委托 `KillEventComponent.onKill`。资源 SWF 不复制这两个权威实现。

冷却期曾出现上下小幅抽搐：通用 `CombatModule.chase` 在纵向差不为零时写入上下方向；本单位每四帧又按 ±6 像素阈值改写同一组方向，`行走` 在两次决策之间持续消费旧方向，可能越过目标后反向。原生夹具使用真实追击函数复现了目标 Z=201、自身从 200 连走至 216 后反向的反例。

当前保留通用 AI 的索敌，实际移动统一在本单位 `行走` 入口重新计算，每帧覆盖相冲突的追击方向。射程内停稳；纵向超过 24 像素才开始对齐、回到 12 像素内停止；横向超过 460 像素才接近、到 420 像素停止。最后一步按剩余距离限幅，暂停不推进，目标失效清理移动，手动控制仍委托标准行走。该修复同时适用于两个阶段，不改变原画稿或动作偏移。

通用 AI 中保留的 `keepDistance=190` 是旧追击输入，已不决定本单位自动行走的实际停距；当前停距由上述本地策略控制。

## 破盾与生命边界

持盾站立、行走、点射、匕首、受击分别使用 562 / 563 / 564 / 573 / 574。第一次生命耗尽在本单位 `hp` 访问器中进入过渡，对外保留 1 点生命并暂时无敌，取消动作所有权，播放 579 的 11 帧破盾。暂停期间破盾帧与单位计时均不推进；过渡内重复扣血、击杀事件或死亡检查不能提前结算。

破盾后由同一个 MovieClip 进入二阶段，生命恢复至原最大生命的 **35%**，最大生命不变；装备对象、强化等级、初始化版本、已用弹量与停火截止点保留，不重新执行装备初始化。自身持盾刚体解除，外部另行写入的刚体/无敌状态仍保留。最终死亡才委托标准击杀与死亡结算一次。普通入口直接生成时使用完整生命，不先播放破盾。

持盾一阶段额外调用现有 `霸体减伤`，当前预设 **75% 减伤**，对应 `damageTakenMultiplier=0.25`，独立来源为 `CF6特种兵持盾`。它使用现有 `MetaBuff` / `MULT_NEGATIVE` 规则，多来源取最强减伤，不把各来源重复相乘。第一次生命耗尽即移除自身来源，破盾完成前刷新移除队列；普通二阶段不保留这项加成，其他来源的减伤继续存在。没有另造伤害分支或直接改防御面板。

生成参数 `Parameters.特种兵持盾减伤率` 可用 0–99 的数值覆盖默认减伤，0 表示关闭该 Buff；越界或非数值会记录错误并使用默认值。该参数只对持盾一阶段生效，不改基础面板、匕首暴击或破盾后的 35% 续命。

持盾一阶段与破盾过渡使用终结者相同的 `击中效果="击中金属"`，标准受击链生成金属火花且不生成飞血碎片。破盾完成才恢复初始化时的普通受击效果（默认“飙血”），因此触发破盾的最后一击仍表现为金属受击。这里只切换本单位的效果字段，不修改通用受击或血腥开关。

这沿用前治安官的“同一单位拦截首轮致死”的思路，不采用原 CF6 破盾后新建另一只敌人的脚本。没有用真实玩家库存或存档验证奖励；结算边界由隔离的原生夹具检查，斗兽使用专用槽。

## 原版匕首与暴击、斩杀

已重新核对本机原版 EXE 内嵌 SWF 的字节身份，并对照反混淆文本与实际控制流的 AVM1 P-code。普通匕首 517、持盾匕首 573 都在第 14 帧的碰撞 helper 加载时做一次 `hitTest`，随后直接执行 `_root.主角hp -= _parent._parent.攻击力`；命中脚本中没有随机暴击或斩杀阈值分支。

检查到的 16 处配置中，15 处显式攻击力为 20，另有一处盾兵未显式赋值。该位置是否实际进入游戏、最终取得什么数值尚未验证，也未复现玩家回忆的秒杀现场，不能把缺失配置或重叠命中定为原因。原件身份、逐处配置和反汇编见[原版调查](evidence/20261016-threat/original/review.json)。

本次按制作组新设计，让两个阶段共用匕首 **10% 概率 ×6 暴击**及 **5% 斩杀阈值**，通过已有 `CritDamageHandle` / `ExecuteDamageHandle` 结算。暴击回调冻结发射时的数值，不依赖发射者后续状态；斩杀仍要求真实命中、扣血后低于阈值，且基础子弹威力超过护盾强度。普通闪避、联弹全 MISS、护盾强度不足以击穿或满血目标都不能绕过这些条件。概率倍率是 CF7 新设计，不能反称为 CF6 原版机制。

## 数值口径

[`balance.py`](balance.py)调用工作簿对应 [`computeMonsterRow`](../cf7-balance-tool/packages/core/src/formulas/monsters.ts)，只改这两个入口。普通入口阶段 7、档次 5 为人工固定声明；持盾入口记录为沿用普通基线，不另造用户裁决。依据分别保存在 [`balance-inputs.json`](balance-inputs.json) 与 [`shield-balance-inputs.json`](shield-balance-inputs.json)。

依据现行[状态硬门](../cf7-balance-tool/docs/monster-flag-rulebook.md)，装备长枪状态不参与空手/近战系数测量。本单位只量匕首：前摇 13、后摇 20，带 0.2 后摇权重为 17，对应攻速 4；物理倍率 1、段数 1。速度均值 60 对应速度系数 2；短受击、可击飞、基础韧性 5 对应霸体系数 2。

公式面板：生命 **7514–21777**、空手攻击 **268–753**、基础防御 **253–705**、经验 **776–4433**。这不是长枪伤害表；实际生成还受等级、阵营与装备初始化影响。

持盾入口短受击且不可击飞，初始霸体系数为 **4**，对应生命 **6913–20035**；其余上述面板相同。破盾后保留该入口的属性，只切换行为并续接 35% 生命，不重新生成普通入口面板。匕首条件暴击的原始期望倍率为 1.5，另行记录；基础物理倍率仍为 1，不把偶发 ×6 填成每刀确定倍率。
