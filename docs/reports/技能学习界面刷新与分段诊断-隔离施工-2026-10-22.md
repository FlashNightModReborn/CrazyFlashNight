## 日志如何解释

Host 普通 `launcher.log` 新增 `event=skill_response_stage`。同一回包以 `flashCallId`、`callIdRef`、`panelInstanceIdRef`、`cmd`、`epoch` 关联；引用由现有 `AuthorityLogFormatter.CreateReference` 产生。仍须用会话与实际 Core/Web 身份约束现场证据，不能让本隔离树的测试代签测试员旧日志。

| 阶段 | 证明范围 |
| --- | --- |
| `ui_dispatch_requested` | 已处理回包并请求 UI 调度；不声称调度已经入队或执行。 |
| `ui_dispatch_enter` | UI 回调实际开始执行。 |
| `web_post_begin` | 即将进入 WebView2 消息投递。 |
| `web_post_returned` | Host 投递 API 返回 true；不证明 Web 已收到。 |
| `web_post_rejected` / `web_post_failed` | Host 投递返回 false／抛出异常；不撤销已经确认的业务结果。 |
| `web_post_returned_unobserved` | 兼容无 bool 返回的测试回调；不解释成投递成功。生产接线使用 `TryPostToWeb`。 |
| `web_received` | 共享响应路由在当前请求边界观察到回包；不代表快照已校验或应用。 |
| `dom_refresh_begin` / `dom_refresh_end` / `dom_refresh_failed` | 有效快照的同步 DOM 更新开始／返回／抛错。预览回包没有完整快照，不产生这组事件。 |
| `frame_callback` | DOM 更新后的一个动画帧回调执行；不证明绘制、合成或屏幕像素已经显示。 |

`hostElapsedMs` 使用 Host 单调时钟，自该回包请求 UI 调度起计时。`webDurationMs` 来自 Web 本地 DOM 更新区间；接收／开始阶段为零，结束和动画帧阶段为相对时长。两个时钟不相减，Host 收到 Web 观测消息的时间也不等于 Web 实际执行的时间。缺少后续阶段只说明观测停在这里，仍需结合线程栈定位阻塞。

Web 只发送严格八字段 `type/panel/panelInstanceId/callId/cmd/writeEpoch/stage/durationMs`，其中 `type=skill_response_diag`、`panel=skills`。Host 同时复核当前文档、active panel/instance、已投递回包的 exact 请求身份与阶段白名单；未知请求、旧实例、错误 epoch、非法时长及任何多余字段均拒绝。日志不包含技能正文、快照、教师 session 或 token。Host 至多保留 64 份回包观测并按阶段去重；Web 至多保留 8 个诊断 RAF，关闭／重绑先撤销旧回调，只持有关联元数据。观测不新增业务 ACK、写锁释放、重试、看门狗或自动关闭。
