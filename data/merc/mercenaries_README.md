# 佣兵配置文件说明 (mercenaries.json)

本文档说明如何在 `mercenaries.json` 文件中配置佣兵装备及其插件（MOD配件）。

---

## 📋 基本格式

### 装备配置字符串格式

```
装备名#强化等级#进阶名#配件1,配件2,配件3
```

### 参数说明

| 参数 | 必填 | 说明 | 示例 |
|------|------|------|------|
| **装备名** | ✅ 必填 | 装备的ID名称 | `PPK`、`黑框眼镜` |
| **强化等级** | ❌ 选填 | 装备强化等级（1-13），不填默认为1 | `5` 表示 +5 强化 |
| **进阶名** | ❌ 选填 | 装备进阶/涂装名称，留空则不使用进阶 | `二阶`、`三阶` |
| **配件列表** | ❌ 选填 | 用逗号分隔的配件名称列表，留空则不安装配件 | `弹簧,螺丝套件,小型液晶屏` |

---

## 📝 配置示例

### 示例 1：配置手枪（带配件）

```json
"secondary1": "PPK#5##弹簧,螺丝套件,小型液晶屏"
```

**解释：**
- 装备：PPK手枪
- 强化：+5
- 进阶：无（留空）
- 配件：
  - 弹簧（射速增强）
  - 螺丝套件（精度增强）
  - 小型液晶屏（瞄准增强）

---

### 示例 2：配置防具（带进阶和配件）

```json
"body": "红黑色功夫装#3#二阶#可塑式钢板,战术背带"
```

**解释：**
- 装备：红黑色功夫装
- 强化：+3
- 进阶：二阶
- 配件：
  - 可塑式钢板（防御增强）
  - 战术背带（扩展配件槽）

---

### 示例 3：配置近战武器（简单配置）

```json
"melee": "pencil#1##护手,石英磨刀石"
```

**解释：**
- 装备：铅笔（近战武器）
- 强化：+1
- 进阶：无
- 配件：
  - 护手（防护）
  - 石英磨刀石（锋利度增强）

---

## ⚠️ 注意事项

### 1. 配件必须存在
配件必须在 `data/items/equipment_mods/` 目录下的配件列表中定义，否则无法加载。

### 2. 配件类型匹配
配件的 `<use>` 标签必须包含该装备类型：
- 手枪配件只能用于手枪
- 近战配件只能用于近战武器
- 防具配件只能用于对应部位的防具

### 3. 配件槽位限制
配件数量不能超过装备的配件槽位数：
- 默认：3个配件槽
- 可通过特定配件（如"战术背带"）扩展槽位数

### 4. 配件标签冲突
同一 `tag` 的配件不能同时装备。例如：
- ❌ 不能同时装备 "骨芯颅印" 和 "辅助握持板"（它们有相同的冲突 tag）

### 5. 进阶参数占位符
**重要：** 当第三个参数（进阶）留空时，**必须保留两个 `#` 号**：

✅ **正确：**
```json
"secondary1": "PPK#5##弹簧,螺丝套件"
```

❌ **错误：**
```json
"secondary1": "PPK#5#弹簧,螺丝套件"
```

## 🔧 快速参考

### 只配置装备名（使用默认强化等级）
```json
"head": "黑框眼镜"
```

### 配置装备名 + 强化等级
```json
"body": "红黑色功夫装#3"
```

### 配置装备名 + 强化 + 进阶
```json
"body": "红黑色功夫装#3#二阶"
```

### 配置装备名 + 强化 + 配件（无进阶）
```json
"secondary1": "PPK#5##弹簧,螺丝套件"
```

### 完整配置（装备名 + 强化 + 进阶 + 配件）
```json
"body": "红黑色功夫装#3#二阶#可塑式钢板,战术背带"
```

## 🧠 性格配置（personality）

佣兵六维人格默认由「等级 + 名字字符码」的确定性种子生成（`_root.生成随机人格`）。在条目顶层加
`personality` 可按维度覆写，**只影响你写出的维度**，其余仍取随机人格结果。

```json
{
  "level": 30,
  "name": "示例佣兵",
  "id": 900,
  "height": 170,
  "face": 0,
  "hair": 20,
  "gender": "女",
  "personality": { "勇气": 0.9, "技术": 0.2 },
  "equipment": { "head": null }
}
```

- 可配置维度只有六个，键名必须逐字一致（中文）：`勇气`、`技术`、`经验`、`反应`、`智力`、`谋略`。
- 取值区间 `[0, 1]`；越界会被夹回 0 或 1，非数值的那一维会被忽略（六维以外的键一律丢弃，
  写成 `null` 与不写同义——不会被当成 0）。
- 生效范围：待雇 NPC 的对话主维度、战队面板的六维雷达、角斗场标准/隐藏对战（对手卡与实际
  对手同源）、出战佣兵战斗 AI 的实际决策（`配置人形怪AI` 会按覆写后的人格重算派生参数）。
  这些消费方读的都是同一份 `merc[19].性格`，不会各算一套。
- 不生效范围：角斗场 roster / 元战队 / 爬升模式的佣兵对手，以及一切兵种怪——它们没有佣兵
  元数据通道，仍取随机人格（与 authored `passive` 的边界一致）。
- 主动技能**不能**在这里配置：技能的唯一权威源是 `已学技能表`，由等级桶 + 装备组合随机生成，
  调研结论见 `docs/人形怪AI定制-调研结论与开发方向-2026-09-07.md` §4 与 §4.1（佣兵侧可行性复查）。
- 注意 `技术` 这一维会被面板的技能预估读到（`buildSkills` 按 `技术` 档位算缓存键与点数倍率），
  而实战单位首次初始化时人格尚未生成，技能表恒按 `t0` 算——这是上面 §4.1 记录的既有偏差，
  覆写 `技术` 只会让它更明显，不会新引入 bug。

## 🧩 其他顶层可选字段

与 `equipment` 同级，全部缺省即不生效：

| 字段 | 作用 |
| --- | --- |
| `personality` | 覆写六维人格，见上一节 |
| `passive` | 佣兵被动技能表（`{技能名:{技能名,等级,启用}}`），出战单位经 `佣兵参数.被动技能` 生效 |
| `pricemultiplier` | 雇佣价格倍率 |
| `enhancement` | 写入 `merc[19].装备强化度`；出战生成处的注入目前是注释状态，填了暂不影响实战装备强度 |
| `hidden` | 标记为隐藏佣兵（`merc[19].隐藏`）。雇佣列表等消费方按该标记过滤，与池内位置无关 |
| `equiplocked` | 填 `true` 后该佣兵装备固定，托管交付/替换/取回全部拒绝，面板整区禁用 |

以上字段都写进 `merc[19]` 元数据并随存档保存，**只对新读入/新雇佣的佣兵生效**，
改动配置不会追溯修改已有存档里已雇佣的佣兵。

1. 编辑 JSON 文件时注意保持正确的 JSON 语法（引号、逗号、括号等）
