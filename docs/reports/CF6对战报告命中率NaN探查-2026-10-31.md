# CF6 对战报告命中率 NaN 独立探查报告

**文档角色**：针对 [cf6-completion-2026-10-31.json](cf6-completion-2026-10-31.json) 中 `combatComparison.diagnostics` 四组共 32 条单位属性记录 `hit` 字段全部为 `NaN` 的独立根因探查、AVM1 传播链分析与待排期修复方案（跟踪工单：[Issue #183](https://github.com/FlashNightModReborn/CrazyFlashNight/issues/183)）。  
**最后核对代码基线**：commit `29c9c0f75cc653a113b905aeb78d9836bf1df1f8`（2026-10-31）。

## 1. 现象与定性结论

在 [cf6-completion-2026-10-31.json](cf6-completion-2026-10-31.json) 的 `combatComparison.diagnostics.{before,subonly,aionly,full}.panelObservations` 中：

- `before`：10 条单位记录，`hit` 全部为 `NaN`
- `subonly`：6 条单位记录，`hit` 全部为 `NaN`
- `aionly`：6 条单位记录，`hit` 全部为 `NaN`
- `full`：10 条单位记录，`hit` 全部为 `NaN`

合计 32 条记录的 `hit` 均为 `NaN`，而同条记录中的 `dodge` 均为正常有限数（60 级下为 `9.83050847457627`）。

**定性结论**：

1. **并非诊断脚本读错字段**：采样器直接读取了单位运行期权威属性 `this.命中率`。
2. **实际运行期属性被污染为 `NaN`**：敌人初始化链路（`_root.初始化敌人模板` 与 `ParameterInitializer.initialize`）同步了 `基础躲闪率` 与 `基础韧性系数`，但遗漏了 `基础命中率`；随后换装初始化器 `DressupInitializer.computeEquipmentProperties` 对所有 `hasDressup === true` 的单位按 `target.基础命中率 * (1 + target.命中加成 / 100)` 重算 `target.命中率`，因 `target.基础命中率` 为 `undefined`，在 AVM1 中算出 `NaN` 并覆写了原本已设好的 `target.命中率 = 20`。
3. **闪避结算被静默旁路**：主武器、副武器及近战/手雷子弹的 `命中率` 均继承了 `NaN`；`DodgeHandler.calcDodgeRateByLevel()` 未在入口校验 `hitRate` 的有限性，导致 `dodgeRate` 变为 `NaN`，最终在 `DodgeHandler.calcDodgeResult()` 中因 AVM1 的 `NaN > 0.01` 为 `false` 而恒定返回 `DodgeStatus.NOT_DODGE`（除 `lazyMiss` 与 `受击反制` 外，等级闪避完全失效，攻击变为必中）。

## 2. 完整根因链

### 2.1 诊断采样器读取的是运行期权威字段

[tools/cf6-soldier-assets/TacticalAI.as](../../tools/cf6-soldier-assets/TacticalAI.as)（L42–L52）在 `this.soldierClock >= 6` 时输出 `[CF6-TACTICAL-PANEL]` 日志：

```actionscript
_root.服务器.发布服务器消息(
    "[CF6-TACTICAL-PANEL] name=" + this._name +
    " type=" + this.兵种 +
    " mode=" + this.攻击模式 +
    " gun=" + this.长枪 +
    " sub=" + (this.长枪属性 ? this.长枪属性.value.upswitch : "") +
    " grenade=" + this.手雷 +
    " hit=" + this.命中率 +
    " dodge=" + this.躲闪率 +
    " gunDmg=" + this.长枪伤害 +
    " states=" + this.hasLongGunActionStates
);
```

采样器读取的 `this.命中率` 与 `this.躲闪率` 即为单位实例上的正式战斗属性。

### 2.2 单位帧脚本与敌人模板未初始化 `基础命中率`

1. **CF6 兵种第 1 帧脚本**（由 [tools/cf6-soldier-assets/build.py](../../tools/cf6-soldier-assets/build.py) L280–L288 生成）：
   显式设置了 `hasDressup = true; enableShoot = true; 攻击模式 = "长枪"; ... 命中率 = 20; 根据模式重新读取武器加成 = _root.主角函数.根据模式重新读取武器加成;`，随后调用 `初始化敌人模板()`，但**未设置 `基础命中率`**。
2. **敌人模板初始化**（[scripts/逻辑/单位函数/单位函数_lsy_敌人模板迁移.as](../../scripts/逻辑/单位函数/单位函数_lsy_敌人模板迁移.as)）：
   - 在 `根据等级初始数值`（L29–L30）中，同时写入了 `this.躲闪率` 与 `this.基础躲闪率`（60 级下按 `躲闪率_min=20, 躲闪率_max=10` 计算得 `20 + (10 - 20) / 59 * 60 = 580 / 59 ≈ 9.83050847457627`）。
   - 在 L642–L643 中，同步了 `this.基础韧性系数 = this.韧性系数`。
   - 但在 L706 处理命中率时，仅执行了：
     ```actionscript
     this.命中率 = !isNaN(this.命中率) ? this.命中率 : 10;
     ```
     **未同步初始化 `this.基础命中率`**（对比玩家与佣兵模板 [scripts/逻辑/单位函数/单位函数_fs_aka_玩家模板迁移.as](../../scripts/逻辑/单位函数/单位函数_fs_aka_玩家模板迁移.as) L2253、L2834 均显式设置 `基础命中率 = 10; 命中率 = 基础命中率;`）。

### 2.3 `ParameterInitializer.initialize` 遗漏 `基础命中率` 快照捕获

[StaticInitializer.initializeUnit](../../scripts/类定义/org/flashNight/arki/unit/UnitComponent/Initializer/StaticInitializer.as)（L66–L68）依次调用 `ParameterInitializer.initialize(target)` 与 `DressupInitializer.initialize(target)`。

在 [ParameterInitializer.as](../../scripts/类定义/org/flashNight/arki/unit/UnitComponent/Initializer/ParameterInitializer.as)（L13–L20）中：

```actionscript
if (!isFinite(target.基础韧性系数)) {
    target.基础韧性系数 = target.韧性系数;
}
if (isNaN(target.命中率)) target.命中率 = 10;
if (!isFinite(target.基础躲闪率)) {
    target.基础躲闪率 = target.躲闪率;
}
```

`基础韧性系数` 和 `基础躲闪率` 均有非有限数快照兜底，唯独 `基础命中率` 被遗漏，导致进入换装初始化前 `target.基础命中率` 仍为 `undefined`。

### 2.4 `DressupInitializer.computeEquipmentProperties` 覆写 `target.命中率 = NaN`

尽管 `StaticInitializer.as` L68 注释写有 `// 只有主角模板会执行`，但 [DressupInitializer.initialize](../../scripts/类定义/org/flashNight/arki/unit/UnitComponent/Initializer/DressupInitializer.as)（L1312–L1314）的实际条件是 `if (target.hasDressup === true)`。

在 `DressupInitializer.computeEquipmentProperties`（L923–L942）中：

```actionscript
target.根据模式重新读取武器加成(target.攻击模式);
...
target.命中率 = Math.max(target.基础命中率 * (1 + target.命中加成 / 100), DodgeHandler.HIT_RATE_LIMIT);
...
target.躲闪率 = DodgeHandler.applyDodgeBonus(target.基础躲闪率, target.闪避加成);
```

- 在 AVM1 中，`target.基础命中率`（`undefined`）参与算术乘法得出 `NaN`，且 `Math.max(NaN, 0.01)` 返回 **`NaN`**，直接将 `target.命中率` 从 `20` 覆写为 `NaN`。
- 同处的 `target.躲闪率` 因 `target.基础躲闪率` 已是有限数 `9.83050847457627`，计算后保持正常值。

### 2.5 为何专项单测 `Cf6SoldierAssetTest` 未检出

[Cf6SoldierAssetTest.as](../../scripts/类定义/org/flashNight/arki/unit/Action/Melee/Cf6SoldierAssetTest.as)（L168–L185）在测试夹具中桩替换了 `_root.初始化敌人模板`，于 L178 手工注入了 `this.基础命中率 = 20; this.基础命中加成 = 0;`，且未经过 `StaticInitializer.initializeUnit` 与 `DressupInitializer.initialize`。

## 3. 下游子弹与闪避结算传播链（AVM1）

### 3.1 主武器子弹属性生成（`ShootInitCore`）

在 [ShootInitCore.generateBulletProps](../../scripts/类定义/org/flashNight/arki/unit/Action/Shoot/ShootInitCore.as)（L654–L667）中：

```actionscript
var baseAccuracy:Number = Number(parentRef.基础命中率);
if (baseAccuracy > 0 && isFinite(baseAccuracy)) {
    var modeBonus:Number = Number(parentRef.命中加成);
    if (!isFinite(modeBonus)) modeBonus = 0;
    bulletProps.命中率 = Math.max(baseAccuracy * (1 + modeBonus / 100), DodgeHandler.HIT_RATE_LIMIT);
} else if (isFinite(Number(parentRef.命中率))) {
    bulletProps.命中率 = Number(parentRef.命中率);
}
```

由于 `parentRef.基础命中率` 为 `undefined`，且回退分支依赖的 `parentRef.命中率` 已被覆写为 `NaN`，两分支均不命中，`bulletProps.命中率` 保持 `NaN`。

### 3.2 副武器、近战与手雷子弹默认属性（`BulletInitializer`）

[LongGunSubWeaponCore.prepareManBulletProps](../../scripts/类定义/org/flashNight/arki/unit/Action/Shoot/LongGunSubWeaponCore.as)（L97–L130）等未显式设置 `props.命中率`，交由 [BulletInitializer.setDefaults](../../scripts/类定义/org/flashNight/arki/bullet/BulletComponent/Init/BulletInitializer.as)（L45）兜底：

```actionscript
Obj.命中率 = (isNaN(Obj.命中率)) ? shooter.命中率 : Obj.命中率;
```

因 `shooter.命中率` 为 `NaN`，所有攻击生成的子弹 `Obj.命中率` 均为 `NaN`。

### 3.3 闪避率计算与静默失真（`DodgeHandler`）

1. 在 [DodgeHandler.calcDodgeRateByLevel](../../scripts/类定义/org/flashNight/arki/component/StatHandler/DodgeHandler.as)（L166–L181）中：
   入口仅校验了 `targetDodgeRate`，未校验传入的 `hitRate`（`bullet.命中率 = NaN`）：
   ```actionscript
   var dodgeIndex:Number = targetDodgeRate / (1 + 0.08 * targetLevel)
       - hitRate / (1 + 0.08 * attackerLevel);
   return NormalizationUtil.sigmoid(dodgeIndex) * MAX_DODGE_RATE;
   ```
   `dodgeIndex` 为 `NaN`，经 [NormalizationUtil.sigmoid](../../scripts/类定义/org/flashNight/naki/Normalization/NormalizationUtil.as)（L12–L14）后返回 `NaN`。
2. 在 `DodgeHandler.calcDodgeResult`（L194–L206）中：
   - L195–L202 原本的 `if (isNaN(dodgeRate)) { fixShooterAndTargetStats(...); ... }` 兜底块处于注释禁用状态。
   - L205 执行 `return ((dodgeRate > DODGE_RATE_LIMIT) && RandomNumberEngine.successRate(dodgeRate)) ? DodgeStatus.DODGE : DodgeStatus.NOT_DODGE;`。
   - AVM1 中 `NaN > 0.01` 为 `false`，恒定返回 `DodgeStatus.NOT_DODGE`。
   - 因此，攻击命中与伤害结算不会抛错中断（对战报告中仍有正常命中与伤害记录），但**受污染单位的所有攻击均跳过了等级闪避判定**。
