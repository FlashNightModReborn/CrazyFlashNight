## 续31：贴边"滑行且比走路快" → Z 对齐接管改为旗标驱动（不再 move2D 直移）

- 现象（用户实测）：距边 80px 内会移动到边缘了（续26 收口生效），但是"滑过去"
  且速度比走路还快。
- 根因（读引擎侧实证）：
  · 正常走路链路：拳刀行走状态机（单位函数_lsy_主角行走状态机.as）每帧 _parent.行走()
    → 主角函数.行走 读 上行/下行 → 移动("上"/"下", 行走Y速度) + 状态改变(攻击模式+"行走")
    → 主角函数.移动 → Mover.move2D(方向, 速度)。动画与速度都来自这条链。
  · alignTick 之前绕开这条链直接 Mover.move2D(self, "上"/"下", 跑Y速度)：
    ① 不经过行走状态机 → 没有"空手行走"动画，观感平移滑行；
    ② 步长用 _getZSpeed = 跑Y速度 = 行走Y速度×奔跑倍率（非主控 2.5→5）
       → 约为走路两倍速，与"比走路还快"完全吻合。
- 修复（HeroUnarmedMoveHelper.alignTick）：
  · 删掉 Mover.move2D 直移与"清 上行/下行"，改为**只写 上行/下行 旗标**，
    位移交给 拳刀行走状态机 → 主角函数.行走（原生动画 + 行走Y速度）。
  · 步长口径改读 self.行走Y速度（与 行走 同口径，非主控 ≤2.5，回退 5）；
    不再用 z.每帧速度（跑Y速度）。
  · 精确性：旗标无法任意截断步长 → 改为"need <= 一步 就收手并结束接管"
    → 误差 < 一步(≈2.5px)，远小于 攻击判定Z(20)，且不会越过目标 Z 后反向纠偏抖动。
  · 边界：room<=0（已贴边）或 isDirectionWalkable 失败（撞边/被挡）→ 结束接管。
- 配套：新增 HeroUnarmedMoveHelper.syncZAlignInput(self)，在
  applyBoundaryAwareMovement **之后** 调用（其开头 clearInput 会清 上行/下行，
  而接管时 wantZ 已被收口为 0、不会重写 Z 旗标 → 该帧行走状态机会切回站立，
  观感走三步顿一下）。三处调用：CombatModule.chase / engage、Behavior._followWhenNoTarget。
- 同步更新过期注释：MoveHelper 文件头、clampZIntent、CombatModule 两处、Behavior 一处。
- 校验：三文件 BOM 保留、括号平衡 0（CombatModule paren -2 为 HEAD 既有注释文字）。
  用户自行编译实测。预期：贴边最后一程是正常走路（动画+速度），不再滑行/超速。
