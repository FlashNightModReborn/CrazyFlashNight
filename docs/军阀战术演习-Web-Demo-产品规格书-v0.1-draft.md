## 1. 产品定义

### 1.1 一句话定义

《军阀战术演习》是一款带轻量 UI 的单人运营兵棋 Web Demo：玩家通过生产基础兵扩张军力和公共行动点，争夺经济、补给、军需与指挥节点，把战斗伤亡转化为卡牌科技经验，逐步部署精锐级与 Boss 级单位；节点交战由模拟 AS2 战斗节奏的确定性虚拟回合自动结算。

### 1.2 首版需要验证的核心假设

首版不是为了证明美术包装或长期养成成立，而是验证以下问题：

1. **运营是否成立**：控制资源节点能否产生清晰、持续的战略优势。
2. **公共 AP 是否成立**：大量基础兵提供 AP、少量精锐集中消耗 AP 的结构是否好玩。
3. **无单棋子行动上限是否成立**：连续奔袭带来的爽感，能否被 AP、持续伤势、驻军与节点目标自然约束。
4. **战斗是否可解释**：玩家能否从四兵种的真实行为抽象中理解战果。
5. **败者经验是否能反滚雪球**：野战溃败后，玩家能否借伤亡经验完成科技跃迁和重建。
6. **重装越级是否形成科技目标**：重装兵和精锐重装兵能否分别承担二本锚点与三本终局投资。
7. **兵棋外壳是否值得继续投资**：完整打一局后，玩家是否愿意重开、换构筑或调整路线。

### 1.3 v0.1 交付目标

必须交付一款可以在浏览器中完整开始、游玩、结束并重开的 Demo，而不只是战斗公式、命令行模拟器或静态 UI 原型。

交付物同时必须具有：

- 玩家可操作的轻量 UI；
- 可脱离 UI 批量运行的纯逻辑内核；
- 确定性随机种子与事件录像；
- 自动化规则测试；
- 本地统计与结果导出；
- 无后端、无账号、无联网依赖的离线运行能力。

## 2. 范围与非目标

### 2.1 v0.1 范围

- 独立 Web 项目，不放入当前 CF7 工作区施工。
- 玩家军阀对 AI 军阀的红蓝镜像对练。
- 固定九节点、三路地图。
- 八张军阀单位科技卡。
- 单一金币经济、人口容量、公共 AP、生产队列、卡牌升级和升阶。
- 节点移动、自动交战、驻扎、恢复、占领和歼灭胜利。
- 普通、困难等难度只影响 AI 可支配金币。
- 标准对局与一个全兵种测试预设。
- 可观看、加速或跳过的节点战斗过程。

### 2.2 明确非目标

v0.1 不包含：

- AS2、Flash CS6、Launcher Bus 或 WebView2 接入；
- 读取真实存档或直接修改 `pets.xml`、`units.json`、敌人属性 XML；
- 调用真实斗兽作为运行时战斗结算器；
- 正式美术、角色立绘、动画素材、音频或世界观演出；
- 天网、叛乱节点或三方外交；
- 随机地图、随机事件、局外成长、肉鸽遗物或永久解锁；
- 玩家直接操控主角进行动作战斗；
- 真人 PvP、联网排行榜、云存档、账号与服务器；
- 与正式游戏经济或奖励互通。
- 任何第二货币、货币兑换或双资源升阶成本。

这些内容只能在 v0.1 玩法成立以后评估。

### 2.3 单金币决策

v0.1 固定只使用金币。生产新单位与购买卡牌升阶直接竞争同一预算，已经足以验证“扩军、科技、抢经济点”三者的机会成本；再增加一种只服务升阶的货币会同时扩大 UI、AI、地图和数值标定面，却没有当前真实进阶扣款逻辑作为依据。实现中不得预留可见的第二货币槽或虚构兑换规则；若后续测试证明单金币不能产生足够的路线分化，再通过新规格评估场景专属资源。

## 3. 核心术语

### 3.1 两种“回合”

为避免歧义，产品中必须使用完整名称：

- **战略回合（Strategic Round）**：地图运营的完整大回合，包含双方行动和统一结算。
- **战斗回合（Battle Round）**：一次节点交战内部的虚拟时间单位，用于模拟 AS2 中的攻击节奏。

所有“每回合攻击”“推迟一回合”“第 2 回合开火”等兵种描述，均指**战斗回合**。

### 3.2 其他术语

- **节点**：地图上的离散位置，棋子只能沿节点连线移动。
- **所有者**：节点当前记录的阵营颜色；节点无人驻扎时所有权仍保留。
- **占据方**：结算时实际有棋子停留在节点上的阵营，可能与所有者不同。
- **激活节点**：有所有者且 `strategicRound >= activeFromRound`，已经完成占领延迟、可以提供资源和功能的节点。
- **稳定节点**：对某阵营而言，所有者为该阵营、已经激活且未被其他阵营棋子占据的节点。
- **生产节点**：总部或补给节点，可以维护生产队列。
- **补给线**：由稳定的己方节点构成、连接到至少一个稳定己方生产节点的路径；总部和补给节点都可以作为补给锚点。所有权仍属己方但正被敌军占据的节点不是稳定节点，不能作为路径或锚点。
- **棋子**：某个单位卡在一场对局内生产出的具体实例。
- **卡牌**：无限次使用的单位生产蓝图，同时也是该单位类型的科技树。
- **行动组**：玩家一次命令临时选择的棋子集合，不是持久编队对象。
- **公共 AP**：阵营共享的行动点池，可以由普通兵产生、由任意棋子消耗。
- **源分类**：单位在现有战宠数据中的原始分类。
- **战力层级**：兵棋对生产价格、科技阶段和目标标签的重新分类。
- **彻底消灭**：敌方同时失去全部部队、待部署部队、有效生产队列和生产节点。

### 4.3 Demo 数据边界

v0.1 使用一份内置、人工审计的静态 JSON 快照，不在运行时解析项目 XML。快照至少保存：

```ts
CardDefinition {
  cardId;
  unitTypeId;
  identifier;
  displayName;
  sourceCategory;
  powerTier;
  tags[];
  statRanges: {
    hp;
    unarmedAttack;
    baseDefense;
    speed;
  };
  expRange;
  auditOnlyStats: {
    dodgeRate;
    toughness;
    magicResistance;
    equipmentDefense;
    weight;
  };
  allowedPromotions[];
  productionCost;
  populationCost;
  buildRounds;
  deploymentLevel;
  behaviorId;
  sourceRefs[];
  snapshotExtractedAt;
}
```

字段边界固定如下：

- v0.1 战斗只模拟 HP、空手攻击、基础防御、速度、经验区间、显式战斗标签，以及本规格列出的升阶数值加成。
- `auditOnlyStats` 必须从真实条目采集并保存在快照中，供人工比对，但 `VirtualBattleResolverV1` 不得读取它们参与命中、伤害、压制、排序或胜负判定。
- `auditOnlyStats` 至少包括躲闪率、韧性系数、魔法抗性数值、装备防御与重量。普通重装兵基础韧性 20、精锐重装兵基础韧性 30，以及升阶带来的韧性增量，都属于“采集但不模拟”的数据。
- 源条目缺少某项审计字段时，在快照中显式记录 `null` 和来源，不能擅自用 0、默认装备值或相邻单位数据补齐。
- v0.1 的命中率只使用 §12.10 的速度差公式，不读取躲闪率；不得因源数据中躲闪率上下界的异常关系而擅自改写公式。
- 静态快照应记录源文件路径和摘录日期，便于未来重新生成；但运行时不得依赖这些路径存在。One-shot 施工使用与本规格同目录的 `军阀战术演习-Web-Demo-军阀卡牌静态快照-v0.1.json`，不得要求网页端施工 Agent 重新读取整个 CF7 项目。

### 4.4 等级数值

首版沿用现有单位插值口径：

```text
stat(L) = max(1, floor(min + (max - min) / 59 × L))
```

- 难度恒定按 1 计算，不允许难度乘单位 HP 或攻击。
- 进阶纯数值加成在插值后相加。
- Demo 场景的卡牌等级上限初始设为 50，覆盖 Lv.10、Lv.25、Lv.50 三档科技节点。
- 核心数据结构保留可配置等级上限，未来接入正式数据时再决定是否恢复 100 级外推。

### 4.5 核心状态形状

实现允许拆分内部文件，但序列化语义必须等价于：

```ts
GameState {
  schemaVersion;
  rulesVersion;
  configDigest;
  gameSeed;
  strategicRound;
  phase;
  initiativeFactionId;
  commandSequence;

  map: {
    nodes: Record<NodeId, NodeState>;
    edges: Edge[];
  };

  factions: Record<FactionId, {
    gold;
    xpPool;
    populationUsed;
    populationReserved;
    populationCap;
    actionPoints;
    cards: Record<CardId, CardState>;
    productionQueues;
  }>;

  pieces: Record<PieceId, {
    pieceId;
    factionId;
    cardId;
    nodeId;
    hp;
    maxHp;
    commandReadyFromRound;
    failedAssaultLocks: NodeId[];
  }>;

  casualtyLedger;
  eventLog;
}
```

其中：

- `commandReadyFromRound`决定该棋子从哪个战略回合开始贡献公共 AP；不限制其使用阵营已有 AP。
- `failedAssaultLocks`只保存当前战略回合内的失败目标，下一战略回合开始时统一清空。
- `CardState`至少保存卡牌等级、累计投入经验、已获得升阶和生产解锁状态。
- `NodeState`必须分开保存所有者、当前驻军、激活战略回合和节点配置，不能用棋子存在与否反推所有权。
- 所有派生值都应能从序列化状态与版本化配置重算；不得把 DOM 状态当作业务权威。

## 5. 战力层级、价格与生产

### 5.1 初始生产参数

以下为可调参数，但层级关系为固定语义：

| 层级 | 单位 | 金币 | 人口 | 建造战略回合 | 生产解锁 |
|---|---|---:|---:|---:|---:|
| T1 | 突击兵 | 8G | 1 | 1 | 卡牌 Lv.1 |
| T1 | 狙击兵 | 8G | 1 | 1 | 卡牌 Lv.1 |
| T1 | 弹药兵 | 9G | 1 | 1 | 卡牌 Lv.1 |
| T2 | 重装兵 | 60G | 2 | 2 | 卡牌 Lv.10 |
| T2 | 精锐突击兵 | 60G | 2 | 2 | 卡牌 Lv.10 |
| T2 | 精锐狙击兵 | 60G | 2 | 2 | 卡牌 Lv.10 |
| T2 | 精锐弹药兵 | 60G | 2 | 2 | 卡牌 Lv.10 |
| T3 | 精锐重装兵 | 180G | 5 | 4 | 卡牌 Lv.25 |

固定语义：

- 普通重装兵按精锐级定价，不是 T1 的便宜前排。
- 精锐重装兵按 Boss 级定价，不只是在 60G 精锐上小幅加价。
- v0.1 不设置单位唯一或硬数量上限；价格、人口和生产时间承担量产约束。
- 精锐重装兵可以在极后期量产，这是允许的终局构筑。

### 5.2 卡牌不是手牌

- 不抽牌、不弃牌、不消耗卡牌副本。
- 解锁后的卡牌可以无限次下达生产订单。
- 实际限制来自金币、人口、生产槽、建造时间、节点控制与节点容量。

### 5.3 生产队列

- 只有稳定、激活的总部和补给节点可以接收订单。
- 每个生产槽维护独立 FIFO 队列。
- `ENQUEUE_PRODUCTION` 执行时检查 `populationUsed + populationReserved + 新订单人口 <= populationCap`；不满足则整条命令无效。
- 合法下单时立即扣除金币并增加 `populationReserved`。
- 节点在结算时被敌军占据或夺取，该节点所有未完成和等待部署的订单取消；已扣金币不退款，对应 `populationReserved` 在同一原子步骤全部释放。
- 单位完工但节点已满或人口检查失败时，单位留在该生产槽队首的“等待部署”状态，不进入棋盘、不贡献 AP，并阻塞该槽后续订单推进，直到部署成功或整条队列被取消。
- 人口上限在每个 `ROUND_START` 从当时稳定、激活的己方节点重新计算，不是结算阶段产出的流量。
- 等待单位部署前再次检查 `populationUsed + 该单位人口 <= populationCap`；部署成功时将该单位人口从 `populationReserved` 原子转入 `populationUsed`。
- 人口上限下降到低于已用人口时，不杀死现有棋子；`ENQUEUE_PRODUCTION` 与等待单位部署都被禁止，直到重新满足上限。

## 6. 地图与开局

### 6.1 九节点镜像地图

节点：

```text
红方：R-HQ、R-Supply、R-Economy
中立：North-Choke、Center-Command、South-Depot
蓝方：B-Economy、B-Supply、B-HQ
```

连线：

```text
R-HQ      — R-Supply
R-HQ      — R-Economy
R-Supply  — North-Choke
R-Supply  — Center-Command
R-Economy — Center-Command
R-Economy — South-Depot

North-Choke    — B-Supply
Center-Command — B-Supply
Center-Command — B-Economy
South-Depot     — B-Economy
B-Supply       — B-HQ
B-Economy      — B-HQ
```

### 6.2 节点初始参数

| 节点类型 | 驻军容量 | 进攻宽度 | 防守宽度 | 战略价值 | 功能 |
|---|---:|---:|---:|---:|---|
| 总部 | 5 | 3 | 5 | 5 | +5G、+5人口、2生产槽 |
| 补给 | 4 | 3 | 4 | 3 | +6人口、2生产槽 |
| 经济 | 3 | 3 | 3 | 2 | +8G |
| 北部关隘 | 4 | 2 | 4 | 1 | 守方有效防御 +20% |
| 中央指挥 | 4 | 4 | 4 | 3 | 每战略回合 +2 AP |
| 南部军需 | 3 | 3 | 3 | 2 | +6G |

v0.1 固定 `驻军容量 == 防守宽度`，避免产生节点内仍有未参战守军、攻击者却已进入节点的歧义。

`South-Depot` 是只产金币的争夺资源节点；“军需”只是主题名称，不属于“补给”节点类型，不提供人口、生产槽或补给锚点。

### 6.3 标准开局

双方镜像拥有：

- 总部、补给、经济三个初始节点；
- 2 名突击兵、1 名狙击兵、1 名弹药兵；
- 20G；
- 4/11 已用人口；
- 三张 T1 卡牌 Lv.1；
- 其余卡牌 Lv.1，但因生产解锁等级不足而不可生产。

对局从 `strategicRound = 1` 开始。双方三个初始节点在创建对局时就设置为对应阵营所有，且 `activeFromRound = 1`；它们在第一个 `ROUND_START` 前已经是激活、稳定节点。不得把开局节点套用新占领节点的延迟激活规则。

三个中立节点初始 `ownerFactionId = null`、`activeFromRound = null`，不提供任何功能；首次成功占领时再按 §8.3 写入所有者与激活回合。

普通重装兵不作为开局兵力，以保证它作为二本科技目标出现。

### 6.4 测试预设

轻 UI 必须提供一个“全兵种演习”预设：

- 所有卡牌达到生产解锁等级；
- 双方获得高额初始金币和人口；
- 可快速部署 T1/T2/T3 单位；
- 仍使用与标准对局完全相同的规则内核。

该预设用于人类快速验证兵种行为，不是独立玩法模式。

## 7. 战略回合状态机

### 7.1 固定阶段

```text
ROUND_START
→ FIRST_FACTION_ACTION
→ SECOND_FACTION_ACTION
→ SETTLEMENT_AUTO
→ SETTLEMENT_PLANNING
→ ROUND_END
```

奇数战略回合玩家先手，偶数战略回合 AI 先手。双方 AP 都在 `ROUND_START` 同时冻结，避免先手击杀后再削减后手本战略回合行动能力。

### 7.2 ROUND_START

依次执行：

1. 激活上一结算阶段刚占领的节点。
2. 从当前稳定、激活的己方节点重算双方人口上限。
3. 推进所有合法生产队列。
4. 在最新人口上限与节点容量约束下，尝试部署完工单位。
5. 计算双方公共 AP。
6. 清除上一战略回合的临时行动锁。
7. 设置本战略回合先后手。

### 7.3 公共 AP

```text
公共 AP = 战略回合开始时已部署、存活且 commandReadyFromRound <= 当前战略回合的棋子数
        + 稳定中央指挥节点奖励
```

规则：

- 每枚棋子不分层级，只贡献 1 AP。
- 本战略回合刚部署的棋子可以消耗现有公共 AP 行动，但到下一战略回合才开始贡献 AP。
- AP 在战略回合开始时冻结，本战略回合后续伤亡不扣回已经生成的 AP。
- 未使用 AP 在战略回合结束时清零。
- 棋子没有每战略回合行动次数上限。
- “无行动上限”不等于免费移动；每次移动仍然消耗公共 AP。

这条规则有意允许基础兵作为 AP 供给、精锐作为 AP 消耗者。首版不得预先加入每棋子疲劳值或硬行动上限。

### 7.4 移动与行动组

- 一枚棋子沿一条相邻边移动，消耗 1 AP。
- n 枚棋子一起移动一条边，消耗 n AP。
- 行动组只是本次命令选中的 `pieceId[]`，命令完成后不保留编队实体。
- 拆分、重新选择和取消未执行命令不消耗 AP。
- 进入空节点或友方节点为普通移动。
- 进入有敌军驻扎的节点时，在该 `MOVE_OR_ATTACK` 命令内立即调用节点战斗解析器，并在接受下一条行动命令前写回伤亡、剩余 HP、胜负移动和失败重入锁。
- 不能穿过仍有敌军存活的节点。
- 合法命令一旦执行即扣除 AP；战斗失败不退款。
- 无效命令不得改变状态或扣除 AP。

战斗即时写回棋盘状态，但战斗产生的双方经验只登记到 `casualtyLedger`，仍延迟到统一结算入池。幸存者因此可以在同一行动阶段依据最新 HP 和位置继续行动。

### 7.5 容量与进攻宽度

- 任何移动结束时，目的节点都不得超过驻军容量；超出部分留在原节点。
- `pieceIds`是有序列表；需要因容量截断时，列表中靠前的合法棋子优先移动，其余留在原节点。UI应在确认前显示实际移动数量。
- 容量截断时只按实际移动棋子数扣除 AP。
- 进攻方一次最多选择目标节点 `进攻宽度` 数量的棋子参战。
- 进攻命令显式选择数量超过进攻宽度时整条命令无效，不自动替玩家裁掉参战者。
- 防守节点的全部驻军参战，因为 v0.1 的驻军容量等于防守宽度。
- 攻击胜利后，幸存攻击者移入目标节点。
- 攻击失败或战斗达到战斗回合上限，幸存攻击者退回出发节点并保留伤势。

### 7.6 同节点失败重入锁

为防止同一批狙击兵通过“失败撤退—立即重攻”无限刷新开场齐射：

- 一次进攻失败后，所有幸存攻击棋子获得当前战略回合的 `failedAssaultLock(targetNodeId)`。
- 带该锁的棋子本战略回合不能再次进攻同一节点。
- 它们仍可移动、驻守或进攻其他节点。
- 另一批未参与失败进攻的棋子仍可进攻该节点。
- 下一战略回合开始时锁全部清除。

该规则不是普遍行动上限。

### 7.7 合法命令面

行动阶段只接受：

```text
MOVE_OR_ATTACK(pieceIds, originNodeId, targetNodeId)
END_ACTION(factionId)
```

结算规划阶段只接受：

```text
ALLOCATE_XP(cardId, amount)
PURCHASE_PROMOTION(cardId, promotionId)
ENQUEUE_PRODUCTION(nodeId, slotId, cardId)
COMMIT_PLANNING(factionId)
```

- 行动命令不得携带升级、生产或恢复字段。
- 规划命令不得移动棋子或直接改变节点所有权。
- AI与玩家使用完全相同的命令验证器。

## 8. 节点所有权与占领

### 8.1 占领判定

在统一结算阶段，节点同时满足以下条件才改变所有者：

1. 节点上有至少一枚存活的占领方棋子；
2. 节点上不存在其他阵营棋子；
3. 占领方不是当前所有者；
4. 按结算开始前的所有权、激活和占据状态快照，该节点邻接至少一个稳定的占领方节点；
5. 该相邻节点可沿占领方稳定节点连接到至少一个稳定的占领方生产节点。

所有节点使用同一份结算前快照，所以一次结算最多向外染色一层，不能链式连续占领。路径上的每个节点都必须同时满足“所有者为该阵营、已经激活、没有敌军占据”；只保留所有权颜色不构成有效补给线。

v0.1 的补给线只作为“能否完成占领”的门槛，不额外影响已拥有节点的恢复、收入、人口或 AP。是否把孤立节点收益也纳入补给线，留到首轮对局数据之后评估，不在本版预先增加。稳定状态按当前棋盘实时派生：敌军进入即失稳，敌军全部离开或被消灭且所有权仍属己方时立即恢复稳定；占领结算只读取结算开始快照中的最终状态。

### 8.2 敌后占据但未占领

如果棋子停在敌方或中立节点，但不满足相邻补给线条件：

- 棋子继续停留在该节点；
- 节点所有者暂不改变；
- 原所有者不能获得节点收益；
- 占据方也不能获得收益、人口、生产槽或 AP；
- 该节点从被敌军占据起就不是稳定节点；即使所有权尚未改变，也不能充当任一方的补给线路径或生产锚点；
- 后续接通相邻控制线后，才能在结算阶段完成占领。

### 8.3 激活延迟与空节点

- 成功占领的节点记录新所有者，但 `activeFromRound = 当前战略回合 + 1`。
- 新占领节点本次结算不提供收入、人口、AP或生产能力。
- 节点成功占领后，即使驻军后来离开，所有权仍保留。
- 空节点仍可提供收益；敌方只需进入并在结算时满足占领条件即可夺取。

## 9. 统一结算顺序

`SETTLEMENT_AUTO` 必须严格按以下顺序：

1. 冻结节点所有权、占据状态和棋子状态。
2. 汇总本战略回合伤亡，生成双方待结算经验。
3. 恢复全部幸存棋子。
4. 按旧所有权快照判定节点占领。
5. 取消失去或被敌军占据的生产节点队列，并释放其全部预留人口。
6. 结算稳定且已激活节点的金币收益。人口是容量，在 `ROUND_START` 重算；中央指挥 AP 也在 `ROUND_START` 计算，不在此步骤作为收益发放。
7. 判定彻底消灭和战略回合上限胜负。
8. 若对局未结束，进入 `SETTLEMENT_PLANNING`。

`SETTLEMENT_PLANNING` 中：

1. 玩家分配公共经验。
2. 玩家进行卡牌升阶。
3. 玩家下达生产订单。
4. AI 使用同一规则完成科技和生产规划。
5. 卡牌数值变化应用到现存棋子，并保持生命比例。
6. 进入下一战略回合。

节点战斗在行动命令执行时即时结算。恢复、占领、经验入池与分配、卡牌升级、升阶和生产均不得在双方行动阶段中途结算。

## 10. 状态恢复

恢复发生在占领判定之前：

```text
若恢复前节点所有者 == 棋子阵营：
    hp = maxHp
否则：
    hp += ceil((maxHp - hp) / 3)
```

固定语义：

- 刚打下来的节点仍按敌方或中立节点恢复，只恢复损失值的三分之一。
- 死亡棋子彻底移除，不能通过恢复、升级或升阶复活。
- v0.1 只持久化 HP，不模拟 MP、弹药、技能冷却或小队缺员。
- 单次节点战斗中的压制和攻击计时不跨战斗保存。
- 卡牌升级改变最大 HP 时保持生命比例：

```text
newHp = round(newMaxHp × oldHp / oldMaxHp)
```

## 11. 卡牌经验、升级与升阶

### 11.1 公共经验池

- 每个阵营只有一个未分配经验池。
- 战斗经验在统一结算阶段入池。
- 玩家可以把经验投给任意卡牌，包括尚未解锁生产的 T2/T3 卡牌。
- 分配不可撤销，不提供重置。
- 卡牌保留累计投入经验和等级溢出。
- 一次分配允许连续提升多个等级。
- 卡牌等级同时作用于该类型所有现存和未来棋子。

### 11.2 单位经验价值

```text
baseBounty(L) = floor(expMin + (expMax - expMin) / 59 × L)
bounty(L) = max(1, round(baseBounty(L) × 5))
```

其中 `L` 使用该阵亡棋子进入本场节点战斗时冻结的卡牌等级；不得在战略结算升级卡牌后按新等级追溯重算赏金。

每枚棋子阵亡时：

```text
击杀方经验池 += bounty
损失方经验池 += 3 × bounty
```

- 每次阵亡只结算一次。
- 击杀方和损失方奖励都延迟到战略结算。
- 难度不得修改经验奖励。
- 自杀或友军伤害不在 v0.1 中存在。

普通军阀兵 Lv.1 的基础经验约为 52。5 倍总倍率下，损失 5 名普通兵约得到 3900 经验，接近一张普通卡从 Lv.1 升到 Lv.10 的累计需求，作为首轮反滚雪球标定目标。

### 11.3 升级需求

```text
needXP(L → L+1)
= floor((expMin + (expMax-expMin)/59 × L) × L)
```

实现必须使用累计阈值或等价的逐级扣除循环，保留溢出；不得复制现有 AS2 中只升一级并清零溢出的行为。

### 11.4 升阶

v0.1 只开放已确认无运行时副作用的纯数值升阶，并只使用金币：

| 升阶 | 等级 | 金币 | 数值加成 |
|---|---:|---:|---|
| 基础训练 | 10 | 25G | +2000 HP、+30攻击、+100防御 |
| 强化药剂 | 25 | 50G | +3500 HP、+100攻击、+100防御 |
| 超级血清 | 50 | 100G | +10000 HP、+150攻击、+50防御 |

真实进阶实现以同一个“基础训练次数”字段表达阶段：基础训练写入 1、强化药剂写入 2、超级血清写入 3；对应运行时条件和扣款只检查金币。源代码中的第二货币兼容字段在这些方案中恒为 0；v0.1 不建立该货币，也不把这个兼容字段带入状态或 UI。

每张卡的可购买序列固定为：

| 卡牌 | 可购买序列 |
|---|---|
| 突击兵、狙击兵、弹药兵、重装兵 | 基础训练 → 强化药剂 → 超级血清 |
| 精锐突击兵、精锐狙击兵、精锐弹药兵 | 强化药剂 → 超级血清 |
| 精锐重装兵 | 超级血清 |

规则：

- 只有卡牌原数据允许的升阶项目才显示。
- 三阶段的全局顺序始终为“基础训练 → 强化药剂 → 超级血清”；在每张卡自己的可购买序列内必须逐项解锁，不得绕过任何实际列出的前项。
- 源数据从较高阶段起步的卡牌，可以直接购买其序列首项；被省略的低阶段不视为已购买，不收取费用，也不授予对应数值。例如精锐突击兵必须先买强化药剂再买超级血清，而精锐重装兵可以直接买超级血清。
- 每张卡每次战略结算最多完成一次升阶。
- 已购买的升阶数值可累积，不是假装成互斥分支；`CardState` 必须保存已购项目和当前序列进度。
- `常驻淬毒`与`凑数组的`不进入 v0.1。
- 基础韧性与现有升阶中的韧性加成都只保存在 `auditOnlyStats` 或升阶审计元数据中，v0.1 战斗不赋予其效果；UI必须明确说明“本 Demo 暂未模拟韧性”。

## 12. 节点战斗解析器

### 12.1 战斗接口

```ts
resolveBattle({
  battleId,
  seed,
  strategicRound,
  commandSequence,
  nodeSnapshot,
  attackerOriginNodeId,
  attackerPieceIds,
  defenderPieceIds
}) => {
  winner: "attacker" | "defender";
  reason: "wiped" | "mutual_wipe" | "battle_round_limit";
  battleRounds: number;
  pieceResults: Array<{
    pieceId,
    hpAfter,
    dead,
    damageDealt,
    attacksMade,
    suppressionsApplied
  }>;
  casualties;
  eventLog;
  finalRngState;
}
```

战斗种子由 `gameSeed + strategicRound + commandSequence + battleOrdinal` 派生。业务逻辑禁止直接使用无种子的 `Math.random()`。

### 12.2 战斗状态初始化

每次节点交战都是独立战斗：

- `battleRound = 1`；
- 所有兵种攻击计时重新初始化；
- 狙击兵重新获得一次入场齐射；
- 弹药兵重新从第 1 战斗回合装填开始；
- 所有压制状态清空；
- HP从棋盘持久状态继承；
- 卡牌等级与升阶在战斗开始时冻结为本场数值快照。

### 12.3 自动阵型与目标顺序

v0.1 不允许玩家在战斗中点选目标。每个兵种具有固定的阵型档位，普通与精锐变体使用同一档位：

```text
档位 0：重装兵
档位 1：突击兵
档位 2：弹药兵
档位 3：狙击兵
```

界面展示与内部稳定遍历时，先按档位从小到大排列；同档位按当前 HP 比例较高者在前，再按 `pieceId` 排序。这个展示顺序不直接等于普通攻击的最终目标索引。

每次普通攻击独立从当前存活单位中选择目标：

1. 选择仍有存活单位的最小阵型档位；
2. 在该档位内选择当前 HP 比例最低者；
3. 最后按 `pieceId` 稳定决胜。

因此“同位置”明确指同一阵型档位，而不是同一个数组索引：跨档位时前排优先，同档位时集火伤势最重者。除兵种段落明确覆写外，多目标攻击重复使用同一规则，每选中一个目标后将其从本次候选集移除。

重装兵不额外拥有硬嘲讽；它通过自动前排排序自然承担伤害。

所有“最多2个目标”的攻击都只消耗一次攻击机会并进入一次武器冷却，但对每个目标分别进行命中、随机波动、伤害和状态判定；一个目标未命中不影响另一个目标。两个目标不能指向同一枚棋子。

### 12.4 突击兵

```text
首次攻击：战斗回合1
攻击间隔：1
目标数量：1
人类特攻：目标带 human 标签时伤害 ×1.5
```

定位：人类单体持续输出和收割者。军阀镜像对战中人类特攻几乎总是生效，因此突击兵应在同级单挑中击败狙击兵和弹药兵。

### 12.5 狙击兵

```text
首次攻击：战斗回合1的先制齐射阶段
后续攻击：战斗回合3、5、7……
目标数量：最多2
精英特攻：对带 elite 标签的目标伤害 ×1.5
```

规则：

- 第1战斗回合先制齐射占用狙击兵本战斗回合攻击，不再获得普通阶段攻击。
- 双方所有存活狙击兵的先制射击以战斗回合开始快照同时结算；本批次中被击杀的狙击兵仍完成其齐射。
- 每名狙击兵的目标在齐射快照中一次确定；齐射中的过量伤害不会让其他狙击兵临时改换目标。
- 主要目标按“`boss` → 其他 `elite` → 非 `elite`”分组优先；同组先选当前 HP 比例最低者，再按 `pieceId` 决胜。
- 第二目标使用齐射快照中的展示阵型：优先选择主要目标前一位存活单位，没有前一位时选择后一位；两侧都没有时只命中一个。
- 狙击攻击不受普通前排目标优先级限制。
- 每进入一场新的节点战斗都重新获得先制齐射；只禁止同一批失败攻击者在同一战略回合立即重攻同一节点。

定位：先制削血、打击精锐编队、帮助后续单位制造减员。当前 ×1.5 是对精锐编队的软克制，不保证狙击兵在长时间单挑中处决一个满血 Boss。

### 12.6 弹药兵

```text
战斗回合1：装填，不攻击
攻击战斗回合：2、4、6、8……
目标数量：最多2
命中效果：对每个目标尝试施加压制
```

目标选择重复执行 §12.3 的普通目标算法，最多选出两个不同目标。定位：延迟启动的双目标伤害与范围控制，适合对付宽阵和低频高价值攻击单位，但容易被开场快攻或狙击齐射抢先削减。

### 12.7 重装兵与精锐重装兵

```text
首次攻击：战斗回合1
攻击间隔：1
目标数量：1
命中效果：尝试施加压制
```

- 普通重装兵使用真实单位数值并按 T2 精锐级支付成本。
- 精锐重装兵使用真实单位数值并按 T3 Boss级支付成本。
- 两者不额外获得强制嘲讽、额外减伤或攻击归一化。
- 其定位由高 HP/防御、每战斗回合攻击、单目标压制和高战略成本共同形成。

### 12.8 压制

压制只存在于当前节点战斗，采用不可叠加、不可刷新规则：

```text
若目标 suppressionPending == false：
    target.nextAttackRound += 1
    target.suppressionPending = true

若目标 suppressionPending == true：
    本次仍造成伤害，但不再增加 nextAttackRound

目标实际完成下一次攻击后：
    suppressionPending = false
```

补充规则：

- 压制在命中后施加；未命中不施加。
- 如果目标本战斗回合已经攻击，延迟其下一次计划攻击。
- 如果目标尚未攻击，可能把当前攻击推迟到下一战斗回合。
- 狙击兵第1战斗回合先制齐射发生在普通压制之前，不能被取消。
- 多个压制来源可以覆盖多个目标，但不能对同一目标叠层形成永久锁死。
- 战斗结束时所有压制标记清除。

### 12.9 战斗回合顺序

每个战斗回合依次执行：

1. 若为第1战斗回合，结算双方狙击兵同时先制齐射。
2. 清除先制阶段阵亡单位。
3. 生成本战斗回合可行动单位列表。
4. 按速度从高到低行动；平速使用种子化稳定决胜。
5. 单位轮到行动时，若 `nextAttackRound > 当前战斗回合`则跳过。
6. 选择目标、判定命中、计算伤害并立即应用。
7. 目标死亡后立即停止后续行动。
8. 攻击成功后更新下一攻击战斗回合并处理压制。
9. 一方全灭则立即结束战斗。
10. 达到战斗回合上限仍未全灭，守方守住。

速度只决定战斗回合内行动顺序和命中修正，不决定攻击间隔；攻击间隔由兵种行为定义。

### 12.10 初始命中与伤害公式

单位数据中的攻击字段在 v0.1 中解释为“单次有效攻击的基础威力”；不同武器的射速、穿刺、范围和击倒不再从装备槽推导，而由本规格的兵种行为层表达。普通重装兵不再与 T1 单位做攻击归一化，其高基础数值由 T2 价格、人口和生产时间承担成本。

```text
hitChance = clamp(
  0.90 + (attackerSpeed - defenderSpeed) / 200,
  0.65,
  0.98
)

effectiveDefense = defense × (1 + nodeDefenseBonus)

damage = max(1, floor(
  attack
  × damageScale
  × 300 / (300 + effectiveDefense)
  × tagMultiplier
  × random(0.90, 1.10)
))
```

初始参数：

- `damageScale = 5`；
- 战斗回合上限 = 16；
- 北部关隘 `nodeDefenseBonus = 0.20`；
- `nodeDefenseBonus` 只对北部关隘的守方单位生效；进攻方和其他节点均为 0；
- 人类特攻和精英特攻只应用各自兵种拥有的倍率，不因目标同时带多个标签而重复叠乘。

这些参数允许通过批量模拟调整；不得通过暗改单位身份、攻击节奏或压制语义解决数值问题。

### 12.11 战斗结果

- 双方在同一狙击先制批次中同时全灭：战略结果按守方守住处理，`reason = "mutual_wipe"`；双方棋子全部移除，节点保持原所有者且为空，不产生失败重入锁。
- 仅守军全灭：攻击者胜利，幸存者移入目标节点。
- 仅攻击者全灭：守方胜利。
- 达到战斗回合上限：守方胜利，攻击者幸存者撤回出发节点。
- 幸存者保留精确 HP，可以在同一战略回合继续移动或参加其他节点战斗。
- 阵亡棋子立即从棋盘移除，并在同一战斗写回中从该阵营 `populationUsed` 扣除其人口；经验统一延迟到战略结算。

## 13. 胜负条件

### 13.1 默认模式：战略歼灭

“某一时刻场上没有棋子”不等于失败。一个阵营同时满足以下条件时才被彻底消灭：

1. 没有任何已部署存活棋子；
2. 没有任何已经完工、等待部署的棋子；
3. 没有任何仍然有效的生产队列；
4. 不再控制任何稳定、激活的总部或补给生产节点。

效果：

- 野战军团灭但总部仍在，可以领取3倍败者经验、升级卡牌并重新生产。
- 总部丢失但远方补给节点仍在，可以继续生产和抵抗。
- 所有生产节点丢失但仍有残部时，必须继续消灭残部。
- 只有军队与再生产能力同时消失，才真正失败。

占领敌方总部不会立即胜利，只会夺走最重要的生产、人口和收入来源。

### 13.2 战略回合上限

初始上限为 24 个战略回合。达到上限仍未歼灭时，依次比较：

1. 稳定生产节点数量；
2. 当前控制节点的总战略价值；
3. 存活军队的生产金币总价值；
4. 当前金币；
5. 仍相同则平局。

节点战略价值必须显式写入地图配置，不在代码中按节点名称推断。

## 14. AI 与难度

### 14.1 固定 AI 决策优先级

所有难度使用同一套确定性启发式：

1. 防止己方生产节点被夺取或彻底消灭。
2. 完成当前已经开始的节点争夺。
3. 在有明显优势时消灭可击破敌军。
4. 夺取中立经济、指挥和军需节点。
5. 增援受威胁的生产节点与关隘。
6. 向敌方生产节点推进。
7. 生产时优先补足缺失职能，再考虑战力层级升级。
8. 科技时优先完成已经接近阈值的卡牌或当前阵容所需反制单位。

AI 的战斗优势估算使用无随机的快速估值，不通过偷偷读取未来随机结果作弊。所有同分选择按节点 ID、卡牌 ID 和棋子 ID 稳定决胜。

### 14.2 难度

| 难度 | AI初始金币与稳定金币收入倍率 |
|---|---:|
| 简单 | 0.80 |
| 普通 | 1.00 |
| 困难 | 1.25 |
| 极难 | 1.50 |

只对 AI 应用倍率：新对局时 `AI初始金币 = floor(20 × 难度倍率)`；每次结算先汇总 AI 全部稳定激活节点的基础金币收入，再以 `floor(基础收入合计 × 难度倍率)` 一次取整。玩家始终使用 1.00，不逐节点取整，也不允许小数金币。

难度不得改变：

- 单位属性；
- 战斗命中或随机偏置；
- 公共 AP 公式；
- 经验奖励；
- AI 决策规则与搜索深度；
- 节点占领、恢复和生产规则。

## 15. 轻量 UI 产品规格

### 15.1 交互目标

首版 UI 必须让不了解内部公式的测试者能够：

- 看懂当前金币、人口、AP和战略回合；
- 判断节点的所有者、占据方、容量、宽度和功能；
- 选择棋子并移动或进攻；
- 看见 AP 消耗和非法命令原因；
- 观看狙击齐射、弹药装填、压制和特攻；
- 在统一结算中分配经验、升阶和生产；
- 判断胜负来自何种战略与战斗事件；
- 使用同一随机种子重开或导出录像。

### 15.2 一屏布局

- **顶部 HUD**：战略回合、当前阶段、先后手、双方金币、人口与 AP。
- **中央地图**：SVG节点、连线、所有权颜色、驻军棋子、节点状态。
- **左侧卡牌栏**：八张卡牌、等级、经验、战力层级、价格、人口、建造时间、生产按钮。
- **右侧检查器**：选中节点属性、驻军、生产队列、连接节点和可执行命令。
- **底部日志栏**：最近行动、伤亡、金币变化与占领摘要；提供结束行动。
- **结算层**：恢复、占领、收入、经验分配、升阶与生产规划。
- **战斗层**：双方阵型、HP条、战斗回合、当前攻击者、伤害、未命中、装填与压制状态。

### 15.3 战斗播放控制

必须提供：

- 正常播放；
- 4倍速；
- 立即结算；
- 暂停/继续；
- 展开逐战斗回合日志。

战斗核心先同步生成并写回不可变结果与事件日志，战斗层随后只播放该日志；播放、暂停和加速期间禁止提交下一条战略命令。即使选择立即结算，结果也必须由相同解析器和随机种子产生，不能调用另一个简化公式，也不能由动画逐帧反向驱动业务状态。

### 15.4 视觉边界

- 使用纯 CSS、SVG、文字和简单图形；不依赖正式 CF7 美术。
- 单位可以使用带兵种缩写的彩色棋子卡。
- HP、精英/Boss标签、装填、压制、待攻击战斗回合必须可见。
- 狙击齐射、弹药爆炸和压制至少有短暂高亮/位移/状态图标反馈。
- 支持 `prefers-reduced-motion`，减弱动画但保留状态变化。
- 最低可用视口为 1024×576，并适配 1366×768 和 1920×1080。
- 关键操作可通过键盘完成；颜色不能成为唯一状态信息。

### 15.5 测试抽屉

提供折叠的开发者测试抽屉：

- 查看和修改新对局种子；
- 选择标准开局或全兵种演习预设；
- 查看完整事件日志和当前序列化状态；
- 导出/导入录像 JSON；
- 以相同种子重开；
- 快速运行当前节点编队 100 次并显示胜率、平均剩余 HP 和平均战斗回合；
- 显示当前配置摘要，但不得在正常对局中直接修改棋子 HP、金币或战果。

## 16. 统计与玩法评估

所有统计只保存在本地内存或下载 JSON，不发送网络请求。

每局至少记录：

- 对局种子、难度、版本与配置摘要；
- 总战略回合和现实游玩时长；
- 每战略回合双方金币余额与收入、人口容量与占用、AP生成与消耗；
- 节点所有权变化；
- 每张卡的生产数、阵亡数、经验投入、升级和升阶时点；
- 每种兵的伤害、承伤、击杀、压制、未命中和存活时间；
- 每场节点战斗的编队、战斗回合、胜方和剩余 HP；
- 单枚棋子单个战略回合最大移动距离和参战次数；
- 单枚棋子占用阵营 AP 的最高比例；
- 狙击兵开场齐射占总伤害比例；
- 普通兵长期不参战、只贡献 AP 的比例；
- 野战团灭后成功重建次数与最终胜率；
- 精锐重装兵首次生产战略回合、场均数量和金币投入占比；
- 达到战斗回合上限的比例。

首轮评估重点：

- 如果一枚精锐长期消耗超过全阵营 60% AP，检查一子多动是否压制其他决策。
- 如果普通兵大量长期闲置只供 AP，评估是否需要“与己方生产锚点保持补给线才贡献 AP”，但 v0.1 不预先加入。
- 如果战斗回合上限触发率超过 15%，优先调整伤害倍率或上限，不改变兵种行为。
- 如果弹药/重装形成控制锁，先检查压制不可叠加实现是否正确。
- 如果精锐重装兵生产后几乎必胜，优先调高价格、人口和生产时间，不削弱其 Boss 身份。
- 如果一次野战团灭后从未成功重建，检查歼灭条件、经验倍率和生产时序。

## 17. 技术架构与施工边界

### 17.1 建议技术栈

- Vite；
- TypeScript 严格模式；
- React 作为轻 UI；
- SVG 绘制地图；
- Vitest 执行规则测试；
- 无后端、无数据库、无第三方账号；
- 除框架和测试工具外不引入大型状态管理或游戏引擎。

如果施工环境更适合原生 DOM，可替换 React，但纯逻辑核心、接口和验收标准不得改变。

### 17.2 分层

```text
src/
  core/          纯状态机、命令验证、结算、序列化
  battle/        VirtualBattleResolver 与战斗日志
  ai/            确定性启发式 AI
  data/          静态卡牌、地图和初始参数
  replay/        事件录像、导入导出、重放
  simulation/    批量对战与统计
  ui/            React组件、SVG地图、战斗与结算界面
  dev/           测试抽屉和诊断适配
```

约束：

- UI组件不得直接修改 `GameState`。
- 所有变化必须通过经过验证的命令进入纯状态机。
- 战斗解析器不得访问 DOM。
- AI只能提交与玩家相同的合法命令。
- 同一状态、种子和命令序列必须产生逐字段相同的结果。
- 序列化包含 `schemaVersion`、`rulesVersion` 和 `configDigest`。
- 正常运行不得依赖当前 CF7 项目目录或本机绝对路径。

### 17.3 可替换战斗内核

```text
CampaignCore
    ↓
BattleResolver
    ├─ VirtualBattleResolverV1（v0.1）
    ├─ ArenaResolverV1（未来真实斗兽）
    └─ HeroBattleResolver（未来可操控主角）
```

战略层只消费逐棋子战斗结果，不知道战斗由哪种内核完成。未来真实斗兽或主角战斗必须返回稳定 `pieceId`、剩余 HP 和死亡状态。

## 18. 自动化与人工验收

### 18.1 必须提供的命令

```text
npm install
npm run dev
npm run build
npm test
npm run simulate
```

`npm run simulate`必须能在无浏览器 UI 的情况下运行固定种子批量对局并输出 JSON 摘要。

### 18.2 规则验收

必须至少覆盖：

1. 相同种子、初始状态和命令序列得到相同结果。
2. 红蓝阵营交换后的镜像用例不存在固定阵营偏置。
3. 八张卡的四种 ID 映射唯一。
4. 普通重装兵具有 `elite` 标签并按 T2 解锁、定价。
5. 精锐重装兵具有 `boss`标签并按 T3 解锁、定价。
6. 标准开局双方合计六个初始己方节点（每方三个）均为 `activeFromRound = 1` 且稳定；首个 `ROUND_START` 后每方人口上限为 11、四枚初始棋子贡献 4 AP，并存在合法的首次占领路径。
7. 阵营状态、地图收益、升阶成本和 UI 中只有金币，不存在第二货币字段；南部军需稳定激活时提供 6G。
8. 新生产单位本战略回合不贡献 AP，但可以消耗公共 AP。
9. `MOVE_OR_ATTACK` 遭遇敌军时，伤亡、HP、位置和失败锁在命令返回前写回；经验只记入待结算账本，同一棋子随后可依据新状态参加另一场战斗。
10. 失败攻击者不能在同一战略回合重攻同一节点。
11. 超出节点容量或进攻宽度的棋子不会进入目标节点或战斗。
12. 经过但未停留的节点不会占领。
13. 一次结算只能沿旧所有权边界占领一层。
14. 一个仍属己方但被敌军占据的节点立即失去补给线路径和生产锚点资格，并能阻止依赖该唯一路径的占领。
15. 新占领节点只恢复三分之一差值且本次不产出。
16. 生产节点订单因失去或被占据而取消时，金币不退，但其全部 `populationReserved` 被释放。
17. 人口上限在 `ROUND_START` 先于部署重算；超限状态同时阻止 `ENQUEUE_PRODUCTION` 和等待单位部署。
18. 棋子阵亡时立即减少 `populationUsed`，且不会因恢复、升级或升阶复活。
19. 完工但无法部署的单位保留预留人口、阻塞所在生产槽，恢复容量后才能部署并把预留人口转为已用人口。
20. 幸存 HP 可以跨节点战斗保留。
21. 普通攻击先选最小阵型档位，再在该档位选择 HP 比例最低者，最后按 `pieceId` 决胜。
22. 狙击兵在每场新节点战斗第1战斗回合重新先制齐射。
23. 双方狙击先制齐射同时结算。
24. 弹药兵第1战斗回合不攻击，只在偶数战斗回合攻击。
25. 压制不可叠加、不可在目标攻击前刷新。
26. 只改变 `auditOnlyStats` 中的躲闪率、韧性、魔法抗性、装备防御或重量，不会改变同种子战斗结果。
27. 每个伤亡只产生一次击杀方1倍、损失方3倍经验。
28. 经验溢出保留，卡牌升级同步影响现存棋子并保持生命比例。
29. 普通军阀卡不能在未购买基础训练时购买强化药剂，也不能在未购买强化药剂时购买超级血清。
30. 精锐突击/狙击/弹药卡可从强化药剂起步但必须先强化再购买超级血清；精锐重装卡可直接购买其唯一的超级血清，且都不会凭空获得被省略阶段的数值。
31. 每张卡每个战略结算最多完成一次升阶。
32. 一次野战团灭但仍控制生产节点时，对局不会结束。
33. 双方狙击在同一先制批次互相全灭时，节点保持原所有者且为空，不产生失败重入锁。
34. 只有部队与再生产能力同时消失才判定彻底消灭。
35. AI难度只按一次汇总后向下取整的公式改变 AI 金币，不改变单位属性、经验、AP和决策规则。
36. 立即结算与观看战斗得到相同结果。
37. 导出录像后重新导入可重现同一终局。

### 18.3 人工可玩性验收

测试者在不阅读源代码的情况下，应能：

- 在两分钟内开始一局标准对战；
- 理解如何选择棋子、移动、进攻和结束行动；
- 从 UI 判断当前 AP 为什么增加或减少；
- 在战斗动画中分辨狙击先制、弹药装填和压制；
- 理解为什么野战团灭后仍能重建；
- 完成至少一次卡牌升级、一次升阶和一次 T2 单位生产；
- 完成或达到一局24战略回合上限；
- 导出本局结果 JSON并以相同种子重开。

## 19. 冻结语义与可调参数

### 19.1 已冻结的语义

1. 产品是带轻 UI 的可玩 Demo，同时拥有可无头运行的内核。
2. 战略回合与节点战斗回合严格分离。
3. 每场节点战斗重新初始化兵种攻击节奏和压制。
4. 狙击每场战斗第1战斗回合先制，之后奇数战斗回合攻击。
5. 弹药兵第1战斗回合装填，之后偶数战斗回合攻击。
6. 重装兵每战斗回合攻击并尝试单体压制。
7. 压制不可叠加、不可刷新到永久锁死。
8. 普通重装是 T2 精锐级；精锐重装是 T3 Boss级。
9. 普通重装和精锐重装都带 `elite`，精锐重装额外带 `boss`。
10. v0.1 只有金币一种货币，不存在第二货币状态、收入或成本。
11. 卡牌是无限蓝图，单位数量由金币、人口和生产约束。
12. 单棋子没有战略行动次数上限，只有公共 AP 成本。
13. 节点战斗在行动命令内即时结算；其他战略结算不得混入行动阶段。
14. 失败攻击者当战略回合不能重攻同一节点。
15. 恢复早于占领；己方节点满血，其他节点恢复损失值三分之一。
16. 占领要求驻军和旧快照中的相邻稳定己方控制线，一次结算只染一层；敌军占据会立即切断该节点的补给线路径资格。
17. 升阶遵守每张卡源序列中的阶段依赖，不能跳过实际存在的前项。
18. 默认胜利是彻底消灭军队和再生产能力，不是临时野战团灭或单纯占领总部。
19. 败者获得阵亡单位3倍经验，击杀者获得1倍经验，统一在结算阶段使用。
20. 难度只改变 AI 可支配金币。
21. v0.1不接入真实 AS2、存档或斗兽。

### 19.2 允许测试后调整的参数

- 单位金币、人口和生产时间；
- T2/T3生产解锁等级；
- 地图节点收入、容量、宽度和防御加成；
- 初始金币、兵力和人口；
- 经验总倍率与升阶金币成本；
- 战斗伤害倍率、命中上下限、随机波动和战斗回合上限；
- AI金币倍率；
- 战略回合上限与终局计分权重；
- UI动画时长和默认播放速度。

调参不得改变固定语义；若测试表明必须改变固定语义，应升级规格版本并记录理由。

## 20. 后续扩展边界

### 20.1 真实斗兽

当前斗兽可作为离线标定参照，但在能够输入战略 `pieceId`、初始剩余 HP并输出逐棋子结果以前，不作为 v0.1 运行时解析器。

### 20.2 可操控主角

未来棋子可增加：

```ts
combatMode: "AUTO" | "PLAYER_HERO"
```

包含主角的战斗路由到交互式解析器，结束后仍返回与自动战斗相同的逐棋子结果。战略层无需改变。

### 20.3 三方战争

底层使用任意 `factionId`，不把红蓝写死进数据结构。v0.1只实现两方节点交战；军阀、天网和叛乱节点三方规则另行设计。

### 20.4 肉鸽层

随机地图、事件、战前构筑、战役继承和局外解锁位于兵棋内核之外。只有标准镜像对局证明运营、战斗和重玩价值成立后才投资。

## 21. 已确认语义记录

以下项目已于 2026-08-02 全部确认。数值仍只能在 §19.2 边界内依据测试调节：

1. 普通重装兵为 T2 精锐级，生产价初始为60G；精锐重装兵为 T3 Boss级，初始为180G。
2. 普通重装兵带 `elite` 标签，因此受到狙击精英特攻。
3. 所有攻击节奏和压制只属于单次节点战斗，每场新战斗完全重置。
4. 狙击先制在每场新节点战斗触发，不是每战略回合只触发一次。
5. 节点战斗在 `MOVE_OR_ATTACK` 内即时写回；恢复、占领、经验科技和生产统一延迟结算。
6. 失败攻击者本战略回合不能再次进攻同一节点，但仍能进行其他行动。
7. 压制采用“未消费前不可叠加或刷新”的规则。
8. 单棋子无战略行动次数上限，首版只以公共 AP、持续 HP、节点宽度和失败重入锁约束。
9. 默认胜利条件是同时消灭部队与生产能力，不是野战军瞬时归零或占领总部。
10. 节点占领只沿旧快照中的稳定己方补给线推进；敌军占据一个仍属己方的节点也会立即切断路径资格。
11. v0.1 彻底删除第二货币，只保留金币；南部节点为提供 6G 的 `South-Depot`（南部军需）。
12. 双方三个初始节点从第1战略回合起即激活、稳定；新占领节点延迟到下一战略回合激活。
13. 新占领节点本次只恢复三分之一差值，并从下一战略回合生效。
14. 同档位目标优先攻击 HP 比例最低者，不按界面中“高 HP 在前”的展示索引选取。
15. 升阶在各卡自己的源序列内严格逐级；精锐卡从源数据允许的较高阶段起步，但不白送被省略阶段的属性。
16. Demo 卡牌等级上限为50，完整覆盖10/25/50三档科技。
17. 标准开局为2突击、1狙击、1弹药，不提供重装兵。
18. 交付物必须有轻 UI、战斗播放、测试抽屉和完整可玩闭环，不是无 UI 模拟器。
19. One-shot 默认技术栈为 Vite + TypeScript + React + Vitest，核心保持框架无关。

若实现或测试要求改变上述任一项目，必须先升级规格版本并记录理由；施工 Agent 不得自行改写。
