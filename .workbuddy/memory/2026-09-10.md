## buff 百分比 vs 倍率：两套语义并存（2026-09-10 核实）

`scripts/类定义/org/flashNight/arki/component/Buff/BuffCalculationType.as`：

| calc | value 语义 | 计算式 | tooltip 显示 | data 里实际用量 |
|---|---|---|---|---|
| `percent` | **增量小数** | `result × (1 + Σp)`，同类可叠加 | `+120%`（value×100，见 BuffTooltipBuilder） | 0 处（原仅全属性抗性药那 8 条，已合并） |
| `multiply` | **倍率** | `base × (1 + Σ(m-1))`，可叠加 | `×1.15` | 0 处 |
| `mult_positive` | **倍率**，同类取最强 | `result × max(m)` | 走 default 分支，裸数字 `1.05` | 大量（速度药剂 1.02~1.75） |

- 即：**1.2 在 percent 下是 +120%（×2.2），在 multiply/mult_positive 下是 ×1.2**。项目主流是倍率写法。
- `resistanceBuff` 的 `percent` 参数走的是 PERCENT 语义 → `percent="1.5"` = +150% = ×2.5，且同类可叠加
  （全属性药 +120% 与单抗药 +150% 会相加成 ×3.7）。改用 MULT_POSITIVE 则同类只取最强。

## 决策：resistanceBuff 弃用 percent，改用 mult_positive（同日）

- 用户判定 percent 的"1.2 = +120%"不直觉（与项目主流"1.2 = ×1.2"冲突），**不再使用 percent**。
- 参数名直接沿用 `mult_positive`（与 `BuffEffect` 的 `calc` 取值同名，不另起一套），
  语义 = 倍率，内部走 `BuffCalculationType.MULT_POSITIVE`（同类取最强，防止叠药爆炸）。
- 实现里 `mult <= 0 || mult == 1` 一律视为无效（倍率 1 = 无增益）。
- Tooltip 从 `+120%` 改为 `×2.2`（`ResistanceBuffTooltipBuilder` v1.4）。
- 最终数值（`data/items/消耗品_药剂.xml`，脚本 `tmp/retune_resistance_potions.py`）：

  | 物品 | value | mult_positive | price |
  |---|---|---|---|
  | 全属性抗性药剂 | 5 | 2 | 10000 |
  | 电/热/冷/波/蚀/毒/冲 抗性药剂 | 10 | 2.2 | 5000 |
  | 能量抗性药剂（property=基础） | 10 | 2.2 | 6000 |

- `marketPrice` 已按与 `price` 相等同步调整（全属性原本 8000≠7500，现统一 10000）；`valueCap 6100` 未动。
- 平衡工具 `tools/cf7-balance-tool/.../potion-balance.ts` 的 resistanceBuff 分支只读 `value`（×2），
  **不读倍率**，倍率部分不参与平衡计分（既有限制，未改）。
- 仍未 publish，需 `-Target publish` 后实机回归。

## 自检结论（同日）

- `MULT_POSITIVE` 的"同类取最强"是**按每条属性路径独立取 max**：`BuffManager._pathPartsCache`
  以完整路径（如 `魔法抗性.电`）为 key，每条路径一个 PropertyContainer / BuffCalculator，
  各自维护 `_multPositiveMax`。所以全属性药的 8 条路径**都会各自 ×2**，不会被压成只生效一条。
- 九龙 3 条 `resistanceBuff` 只写 `value`，`mult` 默认 0 → 行为不变。
- 9 个抗性药剂的 `<icon>` 与 `svg-待导入/图标-XXX.svg` 文件名一一对应，格格巫商店 9 项均已上架。

## 负抗性 = 易伤：resistanceBuff 放开正负双向（同日，覆盖"mult<=0 视为无效"）

- **设定**：游戏存在负抗性，抗性为负即易伤。伤害公式 `伤害 × (100 - 抗性) / 100`；
  抗性 -50 → 承伤 ×1.5。证据见
  `scripts/类定义/org/flashNight/arki/component/Damage/UniversalDamageHandleTest.md`
  （"魔法负抗性: 增伤, 100*150/100=150"、"抗性-2000 夹取到 -1000, 11倍增伤"）。
- **改法**：`resistanceBuff` 按符号自动分流到保守语义的正/负类型——
  `value>0 → ADD_POSITIVE`、`value<0 → ADD_NEGATIVE`；
  `mult>1 → MULT_POSITIVE`、`mult<1 → MULT_NEGATIVE`（0=抗性归零，负值=反转）。
  正向与负向分属两个乘区，可同时生效（×2 与 ×0.5 并存 → 净 ×1）。
- **方向陷阱（重要）**：倍率是缩放当前抗性值，方向取决于抗性正负。
  抗性为正 ×0.5 → 减抗更易伤；抗性已为负 ×0.5 → 反而**减轻**易伤。
  做易伤 debuff 优先用负的 `value`，别用 <1 的倍率。
- **无效判定改为 NaN 哨兵**：`value=0` 与 `mult_positive=1` 视为"未提供"（无效果）；
  属性缺失/空串同样算未提供——AS2 里 `Number("")==0`，不判空串会把抗性误清零。
- Tooltip（`ResistanceBuffTooltipBuilder` v1.5）：负值自带负号，显示如 `电抗性 -20`。
- **其他 buff 早已支持负向**：普通 `buff` 词条用 `calc="add_negative"` / `calc="mult_negative"` 即可，
  无需改代码；现成用例 `data/items/消耗品_药剂_食品.xml` 的 `calc="add_negative" value="-15"`（防御力 debuff）。
  `TooltipConstants` 里**没有** debuff 专用颜色常量，需要时得新增。

## SVG 导入 Flash CS6 丢色（2026-09-10 实测结论）

- 现象：同一份 SVG，Animate 读取正常，CS6 里"药水颜色那一层"整个消失（形状与描边都在）。
- 原因：CS6 的老 SVG 导入器不支持 **`<linearGradient>` + `fill="url(#id)"`** 与
  **`<clipPath>` + `clip-path="url(#id)"`**。这两个失效后，只有渐变填充、又没描边的图形会直接不可见。
  Animate 新版导入器两者都支持，所以只有 CS6 中招。
- **给 CS6 用的 SVG 只写保守子集**：字面 `#RRGGBB` 填充/描边；不要 `<defs>`、渐变、`url()` 引用、`clipPath`、
  `opacity` / `fill-opacity` / `stop-opacity`、CSS `style=`。
- 替代做法：渐变 → 拆成 2~3 段实色色带；半透明 → 预先与底色混合成实色；裁剪 → 直接把形状 path 画成贴合轮廓，
  并把最外层描边**放在最后绘制**用来遮盖色带毛边。
- `tmp/gen_potion_icons.py` 已按上述约束重写（脚本头有完整说明），9 个抗性药剂 SVG 已重新生成。

## 图标烘焙：耗时与跳过行为实测（2026-09-10）

环境：managed Python 3.13 **没有 Pillow**，沙箱内 `pip install` 被拦；**系统 Python 3.10 自带
Pillow 12.1.1**，脚本 3.10 兼容（`py_compile` + `--help` 通过）→ 用
`C:/Users/Akatosh/AppData/Local/Programs/Python/Python310/python.exe` 跑 bake。

**耗时（`素材库-物品技能图标.swf`，4.79MB / 445 个 linkage 符号）**：

| 步骤 | 耗时 |
|---|---|
| `scan_linkage.py`（纯解析 XFL/FLA，不走 FFDec） | **3 分 21 秒** |
| FFDec `-export symbolClass` | 1.5 s |
| FFDec `-format script:as -export script` | 1.3 s |
| FFDec `-swf2xml` | **191 s / 254 MB XML**（默认 timeout 120s → 必然超时） |
| FFDec `-zoom 10 -format sprite:png -selectid`（9 个） | 1.6 s |
| `bake-icons-offline.py --name <9个> --dry-run` 端到端 | **2 分 05 秒** |

- `swf2xml` 超时**不致命**：`spriteGraphErrors[].error=swf_xml_timeout`，`sprite_graphs[swf]={}`，
  nested audit 回退成全 0 → 静态首帧。对静态图标无影响（项目 testing-guide 也把该错误列为可审计项）。
  想跑完就加 `--ffdec-timeout-seconds 300`，总时长 ~3.5 分钟。
- 时间基本被这一个 SWF 的 swf2xml 吃掉；`--name` 过滤只让它扫 1 个 SWF。

**跳过行为（默认安全，不会覆盖既有图标）**：

- `protect_existing_layout = not --force-overwrite-existing`，即**默认开启**。
  `write_icon_if_needed`：渲染结果与磁盘文件一致（exact 或 micro-diff 阈值内）→ `unchanged`；
  有差异且文件已存在 → `layout_protected`（**保留旧图**，只写进 report）；只有文件不存在才 `created`。
- 额外有 **source-aware refresh**：即使保护开启，只要既有图标的 `bakeProvenance` 可信
  （记录里的 render digest 与磁盘像素一致）**且**源 SWF sha256 与渲染像素都变了，就允许自动覆盖。
  新加的图标没有 provenance → 只走 `created`。
- 全量 `--scope all --force-overwrite-existing` 必须再加 `--allow-layout-regression-risk`，否则直接报错拒绝。
