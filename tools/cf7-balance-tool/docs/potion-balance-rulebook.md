## 2. v2 公式

v1 继续用于既有工作簿校准，不改写其 56 项基线。v2 只解决本轮已经确认的两个缺口：混合食品的即时/缓释分量拆分，以及装备 `toughness` 轴。

```text
instant = instantHp + instantMp
regen   = regenHp + regenMp
regenDiscounted = regen / 2 ^ ((min(regenFrames / 30, 10) + 5) / 15)

buffBase = buffHp + buffMp
         + 2 * defence
         + 50 * magicResistanceInput
         + 3 * damage
         + 4 * punch
         + 50 * speedInput
         + 0.4 * toughness

buffStrength = buffBase * (0.1 + buffFrames / 300)
currentValue = (instant + regenDiscounted) * 2 ^ isGroup
             + 60 * purify
             + toxinStrength
             + buffStrength
valueCap = 100 + sourceLevel * 100
```

约束：

- `sourceLevel` 是最早可批量获取时的玩家进度，不是物品使用等级。
- 混合食品只对 `regen` 分量折价，不能把即时恢复一起按缓释处理。
- 全抗的工作簿输入仍为实际单属性增益的 2 倍；实际全抗 `+10/+18/+23` 对应输入 `20/36/46`。
- 速度输入为“实际加速百分比 ÷ 2”；`+35%/+55%/+75%` 对应 `17.5/27.5/37.5`。
- 按本批约定 `5 toughness = 1 防御`；防御权重为 2，因此装备 `toughness` 的公式权重为 `0.4`。
- `toughness` 的运行时增量必须按 `基础韧性系数 × value / 100` 加到最终韧性系数，不能对已含装备值的结果再做百分比乘算。
- `currentValue <= valueCap` 是硬检查；市场价可以因为渠道、叙事和合成门槛偏离公式价，但两者必须分别记录。

## 3. 产品域

| 域 | 定位 | 持续效果规则 |
|---|---|---|
| `meal` | 食品、菜品、口粮 | 同一单位只保留最近一个餐食的持续 Buff |
| `enhancer` | 九龙及后续战斗强化剂 | 同一单位只保留最近一个强化剂 |
| `medical` | 即时 HP/MP、净化、韧性应急 | 不占餐食或强化剂槽 |
| `weapon-agent` | 淬毒等武器制剂 | 保持武器状态边界 |

一个 `meal` 与一个 `enhancer` 可以并存。域切换只移除通过本次药剂上下文登记的持续 Buff；已经发生的即时恢复、净化、剧情奖励不会回滚。
