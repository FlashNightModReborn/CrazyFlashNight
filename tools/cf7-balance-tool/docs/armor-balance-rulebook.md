## 1. 条款编号与使用约定

条款 ID 固定采用 `ABR-<DOMAIN>-<NNN>`：

- `ABR` 表示 Armor Balance Rule；`DOMAIN` 表示判据域；`NNN` 为域内三位流水号。
- ID 一经被 plan `budgetBreakdown.ruleRef`、审计账本或报告引用，不重排、不复用。规则废弃时保留旧 ID，并注明替代条款。
- 实际使用的条款必须进入 plan 记录的 `budgetBreakdown.ruleRef` 并紧邻客观证据（`evidenceRef`）；仅在自由备注中写“按规则”不构成证据。

## 2. 权威与落盘

| 层 | 防具入口 |
|---|---|
| 人工方案（唯一人工真源） | `records/armor-balance-plan.xml` |
| 机械审计（派生） | `records/armor-balance-audit.xml` |
| 运行时旁路摘要（派生） | 各防具 item 根下的 `<balance>` |
| 公式实现 | `packages/core/src/formulas/armor.ts::computeArmorRow()` |
| 同步 / 反查 | `npm run armor-balance-sync` / `npm run armor-balance-check` |

`armor-balance-sync` 从 plan 与物品 XML 实读数值重新计算审计账本和内联 `<balance>`；`armor-balance-check` 校验 plan 严格解析与预算闭合、工作簿快照、总分拟合带、法抗上限、双价格门、digest 与两份投影的逐字节一致。分数类字段是 `computeArmorRow` 的机械输出，不手工维护。

armor 家族按文件名分治，只允许登记 `data/items/防具_*.xml`，不触碰 weapon/potion 家族的任何文件。

## 3. 数值模型（M 层）

| 条款 ID | 判据 | 来源 |
|---|---|---|
| `ABR-LAYER-001` | K 点购买计 1 层，合成计 1 层，高价计 1 层；三者叠加后最多计 3 层。高价的价格加权仅限只可购买/合成获得的装备。 | 「防具」C25 |
| `ABR-LAYER-002` | 高难度副本/Boss 掉落可为 1-2 层，不与 `ABR-LAYER-001` 叠加，二者取最高；有额外合成成本可再叠 1 层。 | 「防具」C26 |
| `ABR-LAYER-003` | 全新玩法可获得版本红利期，期间额外叠加 1 层。 | 「防具」C27 |
| `ABR-LAYER-004` | 40 级以上装备可有额外 1 层加权作为浮动。 | 「防具」C30 |
| `ABR-LAYER-005` | 减益效果可交换为 1 层加权层级（可叠加）。 | 「防具」C29 |
| `ABR-LAYER-006` | 金币购买物品默认为 0 层；支持负层级，免费赠送的物品可计 -1 层。 | 「防具」C28 |

plan 的 `weightLayers`（M 层）必须等于 `budgetBreakdown` 全部条目 `delta` 之和，这是硬闭合；缺层或溢层都判解析失败，不允许口头解释。

| 条款 ID | 判据 | 来源 |
|---|---|---|
| `ABR-SCORE-001` | 以当前总分≈加权总分为平衡标准：`\|currentScore/weightedScore − 1\| ≤ 0.05` 为硬门。 | 「防具」C22-C23 |
| `ABR-SCORE-002` | 防御以外的单项属性占比过高会占用更多数值模型，通常不超过总分一半；攻击类手套是例外。 | 「防具」D12 |
| `ABR-SET-001` | 同一套装不同部件之间不要偏差过大，否则混装强度偏高；套装审计须逐件对照。 | 「防具」D13 |
| `ABR-RESIST-001` | 法抗均值上限 `S = 10 + lv*0.2`，最高上限 `T = 25 + lv*0.2`；`magicDefence ≤ magicDefMaxCap` 为硬门。单件法抗不要过高，全属性抗性上下身各 15 点封顶，尽可能避免在无作弊可得物品内实装；特定法抗套装每种属性独立计上限、分数合并计算。 | 「防具」C31 与公式列 |

## 4. 价格模型（E 层）

| 条款 ID | 判据 | 来源 |
|---|---|---|
| `ABR-PRICE-001` | 种类系数：防具有主动战技/特效的可为 1.5，效果极其强力时为 2；无购买途径或非购买途径早于购买途径的为 0.5。 | 「装备价格」D22 |
| `ABR-PRICE-002` | E 层（`priceLayers`）只计由装备价格产生的加权层数，不计其他类型层数；金币装备通常最多 1 层，K 点装备通常最多 2 层，不可叠加。属性削弱的廉价物品可计 -1 层。拥有购买以外获取方式的装备不得添加价格正向层。 | 「装备价格」D25-D27 |
| `ABR-PRICE-003` | 强度远超等级限制的彩蛋装备可解锁超过 2 层的价格系数，但大于 2 层时种族系数额外 +1（最低 2），高种姓或强力特效装备填 2.5-3；已完全理解公式时可填小数以微调。 | 「装备价格」D28-D29 |

plan 的 `priceLayers` 必须等于 `acquisition.high-price` 条目的 `delta`（E 层只由价格产生层贡献），这是硬闭合。

| 条款 ID | 判据 |
|---|---|
| `ABR-PRICE-004` | **取整采用规则**：确认价（`adoptedGoldPrice`）可偏离推荐价取整，但必须落在 `[0.8, 1.25]` 带内，并在 plan `note` 记录偏差幅度、取整基准与确认人/确认日期。K 点实售价对公式值偏差不超过 5%，且必须有 K 点商店 JSON 的实售证据（`kpointEvidenceRef`）。 |

## 5. 绿 / 黄 / 红分流

| 条款 ID | 状态 | 判据 |
|---|---|---|
| `ABR-TRIAGE-001` | `confirmed`（绿） | M/E 层预算闭合且每层有可复查证据；数值与双价格硬门全部通过；note 记录取整偏差与确认人。 |
| `ABR-TRIAGE-002` | `unresolved`（黄） | 存在缺失、冲突或需设计取舍的证据（如获取路径层级不一致、套装部件偏差待量化）。保留审计记录并请求人类裁定；不得调系数伪装成绿。非 confirmed 记录同样落盘，但 check 仍须全链自洽。 |
| `ABR-TRIAGE-003` | `invalid`（红） | 记录与客观配置或权威条款直接矛盾，或使用无依据系数凑目标。不得落盘为有效标定；先纠正证据链或数值。 |
