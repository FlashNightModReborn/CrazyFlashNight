## 1. 问题、目标与非目标

### 1.1 问题

H1 调研时的正式 deployed runtime 与 proposal 基线把“消息已发送”“文件已被目录发现”“native load 成功”“播放图在推进”和“玩家真实听到”折叠成近似同一成功面。当时确认的问题包括：

- catalog 曾宣称 OGG，但当时的 native 未注册 Vorbis decoder；
- 11 个 AAC/MP4 文件曾使用 `.wav` 扩展名，另有注册 BGM 缺文件；
- 默认 backend 曾可落入始终成功的 Null；
- BGM/SFX start、readiness 和错误当时没有端到端确认；
- 当时只有 BGM 内部 peak，无法证明 SFX 或 endpoint；
- 当时没有可进入发布门的音频 qualification corpus 和真实 endpoint runner。

这些条目是 H1 因果基线，不是对修复后新 Source S 的描述。当前实现与重入状态见 §2 和 §15.3；正式 deployed runtime 仍保持上述旧能力，直到 H2 后的完整发布链实际完成。

### 1.2 目标

- 让播放器能力成为 native 可查询事实，而不是 C#/文档猜测。
- 让每个 BGM 请求可追踪到 accepted/deferred/started/failed/superseded。
- 让 SFX 预载、未知 ID、节流、丢弃和启动失败可计量。
- 让“全零内容”“增益静音”“Null backend”“设备丢失”“endpoint 静音”可区分。
- 支持当前玩家/资源需要的常见格式，并保留稳定扩展点。
- 让一次最终 promotion 覆盖能力、测试、notice、资产合同与正式入口。

### 1.3 非目标

- 不建设通用媒体播放器、视频 demux、网络流或 DRM。
- 不支持任意安装在 Windows 上的第三方 codec；只公开本 ADR allowlist。
- 不在本轮增加 HRTF、空间音频、卷积混响、MIDI、tracker、ReplayGain 或自动响度改写。
- 不用 limiter/normalizer 掩盖资源或混音错误；可增加 clip counter，改变声音需另行听感决策。
- 不把 AS2 改造成 native API 镜像；AS2 只消费产品级音频语义。
- 不批量重命名全部历史 SFX；文件名当前还是 linkageId 合同的一部分。

## 3. 目标拓扑与权威

```text
AS2 product intent
  ├─ BGM requestId + latest-wins intent
  └─ SFX frame batch + audioReadyGeneration
          ↓
C# AudioTask / AudioCoordinator
  ├─ wire revision / ack / counters / lifecycle
  ├─ capability-driven MusicCatalog
  └─ structured diagnostics

  ├─ real-backend-only context/device fallback policy
  ├─ resource manager + decoder registry
  ├─ BGM/SFX buses + meters
  ├─ device generation/recovery
  ├─ bounded runtime compatibility probe
  └─ offline EOF qualification probe
          ↓
```

|---|---|---|
| AS2 | 场景/BGM/SFX 产品意图、优先级和当前业务语义 | codec、设备、native load 成功判定 |

## 4. 设备与生命周期合同

### 4.1 Production backend

production 必须同时：

1. production compile policy 固定 `MA_ENABLE_ONLY_SPECIFIC_BACKENDS + MA_ENABLE_WASAPI + MA_ENABLE_DSOUND + MA_ENABLE_WINMM + MA_NO_NULL`，或经构建断言证明完全等价；
2. fallback 在 **context 与 playback device 都成功** 后才停止，不能把“第一个 backend 的 context 初始化成功”误当成“该 backend 可播放”；
3. 可由仅编入上述三种 backend 的 `ma_device_init_ex()` 在 device-init 层枚举，或显式逐 backend 完成 context+device；两种实现都必须保留相同结果语义；
4. 导出实际选中的 backend、device name/id、sample rate、channels、format 和 generation；
5. 若从 WASAPI 降级到 DirectSound/WinMM，记录结构化 warning；
6. 三个真实 backend 均失败时进入 `audioStatus=failed_no_output`、不发布 audio ready、目录与播放控制显示不可用及原因。

Null 只允许 test-only/offline qualification build。该构建必须带不可混淆的 capability/identity，且 production policy 明确拒绝。

音频 fail-closed 不等于 Launcher 必须退出；本 ADR 推荐并在 H1 决策块中冻结“明确无音频降级、游戏可继续”。若人类要求音频失败即终止 Launcher，必须改写冻结块后再签 H1。无论进程是否继续，都不得把 Launcher `Ready`、socket 存活或目录可见外推为 audio ready。

### 4.2 Device change

- 默认设备或路由变化推进 `deviceGeneration`。
- 恢复期间暂停接收新 native 播放，C# 进入 `recovering`。
- BGM 保存 current intent、loop、gain 和可用 cursor，在新设备成功后有界恢复。
- SFX 不回放 recovery 期间的历史事件；只统计 drop，ready 后接收新事件。
- `recovering` 覆盖一个 single-flight episode；重复 default-device 通知合并，不并行重建。episode 只推进一次 `audioReadyGeneration`，每次 native initialize 返回的 `deviceGeneration` 由 managed 采用而不预测。
- 最多 5 次 initialize attempt；现役 200 ms runtime poll 以 `1/2/4/8` ticks 退避，即 `200/400/800/1600 ms`、总等待 3000 ms。首次 Initialize 的 `device_unavailable|device_lost` 计 attempt 1，attempt 2–5 不再推进 ready generation；普通 BGM command 的 `device_lost`、recovery replay 的 `not_ready` 与 hot catalog refresh 只进入/沿用同一 active episode/已消耗 attempt budget，不得重置预算或另开 episode。ABI/capability、tuple/device epoch、gain/preload/catalog 等确定性失败立即 fail-closed。
- retry/异步 catalog qualification 均在 owner 生命周期内串行；qualification pending 时暂停 retry。qualification completion 总是先 strict inspect：`QueryRuntime` exception、null/invalid ABI、tuple drift，以及 exact valid tuple 的其他 non-ready 状态立即 terminal；只有 exact valid tuple 的 `Recovering` 或 `Ready` 且 `deviceGeneration` drift 才继续当前 device episode。latest successfully committed BGM intent 的 replay 仍在 `Recovering` 内完成；只有 replay 成功才唯一发布 `Ready`，失败不得 transient Ready。SFX 只 drop/count、不 replay；5 次耗尽后才进入 `failed_no_output`，不无限后台循环。
- shutdown 取消 pending backoff/qualification 并 fence late work；callback、audio write thread 与 timer 均不得直接 mutation。H1 manifest 只冻结 bounded/observable/interruptible/terminal 语义；上述 exact 次数/退避由当前 S 常量和故障注入测试冻结，不能凭 source 结果外推 exact candidate 或真实端点。

### 4.3 Thread ownership

- 所有会改变 engine、sound、resource manager、device 或 decoder 状态的 native API 只由一个 owner queue/thread 串行执行；socket、UI polling、preload worker 和 recovery job 不得直接并发 mutation。
- meter、cursor、capability 和 device state 通过不可变/原子 snapshot 暴露；snapshot 读取不得与 sound/device uninit 直接竞态。
- preload、probe、MF 与 recovery job 必须可取消、可等待；job 不能在 generation 失效或 shutdown 后回写 handle。
- 设备政策故障注入必须持续包含“首选 backend context 成功但 device 失败”，并证明会尝试下一个真实 backend，而不是静默失败或落入 Null；该用例是最终统一矩阵的一部分。

### 4.4 Shutdown

停止 admission → 等待/取消 decoder jobs → 停声源与 device → uninit engine/resource manager/context → 平衡 MF/COM 生命周期。重复 shutdown 必须幂等；不得让异步 preload 在释放后回写 handle。

## 5. 格式与 decoder 合同

### 5.1 H1 推荐矩阵

| Container / codec | Backend | H1 推荐 | 公开扩展名 |
|---|---|---|---|
| RIFF/WAVE PCM/float | miniaudio built-in | include | `.wav` |
| MPEG audio Layer III | miniaudio built-in | include | `.mp3` |
| FLAC | miniaudio built-in | include | `.flac` |
| Ogg Vorbis | official miniaudio libvorbis adapter + pinned libogg/libvorbis/libvorbisfile | include | `.ogg`, content=Vorbis |
| AAC-LC/HE-AAC in MPEG-4 | Media Foundation source/decoder exposed as miniaudio-compatible data source/backend | include | `.m4a`, `.mp4` |
| AAC in ADTS | Media Foundation | include | `.aac`, `.adts` |
| Ogg Opus | official miniaudio libopus adapter + pinned libopus/libopusfile | recommended option | `.opus`; `.ogg` only after content probe |
| WMA/ASF | Media Foundation | defer public promise | none until qualified |
| other | none | reject | none |

扩展名只是发现 hint；container/codec 才决定 decoder。`.ogg` 不能等同于 Vorbis，必须区分 Ogg Vorbis 和 Ogg Opus。

Vorbis 路线在 H1 前已完成显式取舍：当时 vendored miniaudio `0.11.25` 确有可接入外部 `stb_vorbis.c` 的 optional wrapper，cursor 会正常维护；评审所称“push mode cursor 恒为 0”不成立。真正限制是 resource-manager/VFS streaming 会走 push mode，其 length 成功返回 `0`，后向 seek 需要重建 decoder 并向前暴力解码，而且 H1 调研基线尚未 vendored codec 本体。它适合极简 decode 场景，但不满足本轮 BGM 的完整 duration/seek/EOF 资格合同。因此 R2 明确选择官方 miniaudio libvorbis adapter + pinned libogg/libvorbis/libvorbisfile；S 已按该路线 vendored/锁定，`stb_vorbis` 继续作为已评估未选方案。

### 5.2 Media Foundation 边界

- 只接受 allowlist 中明确的 container/codec；第三方系统 codec 偶然能解码不自动扩大 capability。
- 必须支持 wide path、duration、seek、EOF/drain、format change 和 deterministic cleanup。
- COM/MF 初始化、worker thread、取消和 shutdown 必须有专项故障注入。
- 长 BGM 不允许以“全文件预解码进内存/临时 WAV”作为默认生产实现。
- S 已用 bounded Source Reader/data-source adapter 落实该路线；对外 ABI、capability 和结果语义不得随内部实现分叉，MF async/cancel/shutdown 故障注入已进入 final source matrix，仍须由 exact candidate/A6 证明真实运行资格。

### 5.3 依赖政策

- 优先采用 miniaudio 官方 adapter 与 codec 官方源码，不复制来源不明的单头文件 fork。
- exact tag/commit、SHA-256、build flags、license 与上游 URL 进入 tracked lock/notice。
- Vorbis 和 Opus 均为 BSD-family，但仍须分发 notice；不能以“宽松许可证”跳过审计。
- 所有 bundled decoder 静态链接进 `miniaudio.dll`，不增加 loose codec sidecar。

## 6. Native ABI 与 capability

### 6.1 ABI 原则

- 新 ABI 有独立 major/minor；breaking change 增 major，不静默复用现役签名。
- 所有 struct 以 `structSize + abiMajor + abiMinor` 开头。
- caller 分配输出结构和 UTF-8/UTF-16 buffer；native 不把需要跨边界释放的裸指针交给 C#。
- bool、enum、整数宽度固定；不把 C 编译器布局、`ma_result` enum size 或 miniaudio struct 直接暴露给 P/Invoke。
- C# 音频子系统先校验 ABI/capability，再发布 audio catalog/ready；不匹配只令音频 fail-closed，并按 `noOutputPolicy` 进入明确降级，不伪装成 ready。
- path 使用 wide/caller-owned buffer，完成规范化与允许根目录 containment 校验；超长路径显式失败，禁止固定 1024 字符截断。
- gain、fade、seek、loop 等数值先校验 finite 与冻结范围；负 fade、NaN、Inf 或溢出不得进入 native。

### 6.2 Capability 最小集合

```text
abiVersion
bridgeBuildId
miniaudioVersion
decoderBackends[]
containers[] / codecs[] / extensions[]
compiledBackendMask
selectedBackend / selectedDevice
supportsProbe / supportsSeek / supportsLoop / supportsDeviceRecovery
supportsBgmMeter / supportsSfxMeter
testOnlyNullEnabled
```

capability 分成 build capability 与 runtime device state；“编译支持 AAC”不能冒充“当前设备已启动”。

runtime snapshot 另含 `audioStatus=initializing|ready|recovering|failed_no_output|shutdown`、`audioSessionId`、`audioReadyGeneration`、`deviceGeneration` 和最近一次结构化失败；build capability 不得缓存覆盖这些动态状态。

### 6.3 结构化结果

每个可能失败的操作至少保留：

```text
requestId | operation | stage | category | nativeCode | hresult |
decoderBackend | audioSessionId | audioReadyGeneration | deviceGeneration |
retryable | messageKey
```

稳定 category：

```text
ok | missing | unsupported_container | unsupported_codec | malformed |
truncated | io_error | abi_mismatch | not_ready | stale_generation | unknown_id |
throttled | start_failed | seek_failed | device_unavailable |
device_lost | superseded | internal_error
```

不得再把所有 load failure 压成 `-2`，也不得丢弃原始 `ma_result`/HRESULT。

## 7. AS2/C# 桥接合同

### 7.1 Generation 域与状态机

禁止使用裸 `generation`。四个域不可互换：

- `connectionGeneration` 是现役 XMLSocket transport 世代，只防旧连接回调污染，不进入音频 wire 的 ready 判定。
- `audioSessionId` 是 process-scoped UUID；进程启动或 AudioCoordinator/native 完整所有权重建时生成且永不复用。
- `deviceGeneration` 是 native 真实设备生命周期世代，`uint64` 以十进制字符串过 wire；初值 `0`，每次真实设备初始化/恢复 attempt sequence 开始前推进。
- `audioReadyGeneration` 是 C# admission snapshot 世代，`uint64` 以十进制字符串过 wire；初值 `0`，每次初始化、恢复、capability 或 preload snapshot 重建开始前推进，重建结束后以同一世代发布 `audio_ready` 或 `audio_unavailable`。只有 ABI/capability、真实设备和完整 catalog 属于同一一致快照时才 ready。

请求的 `audioSessionId` 或 `audioReadyGeneration` 与当前值不等时返回 `stale_generation`、附 current tuple、零副作用。SFX 只计 `staleGenerationDrops`，不回放；BGM 只有携当前世代时才可 `accepted_deferred`。异步 job 必须捕获 session/ready 及相关 device 世代，完成时再次比对，stale completion 不得发布 handle/snapshot。计数器溢出时建立新 session 并重置；若 wire 无法可靠发布 reset，则音频 fail-closed。响应和诊断携完整音频 tuple，不能用 socket connection 世代代替。

### 7.2 BGM

- 每个 play/stop/seek/loop 请求携 `wireRevision=2`、`requestId`、`audioSessionId` 和当前 `audioReadyGeneration`。
- 结果至少区分 `accepted_deferred`、`started`、`stopped`、`superseded`、`failed`。
- bootstrap gate 只保留最新 BGM intent；被替代请求返回 `superseded`。
- `started` 必须在 decoder/source 初始化与 `ma_sound_start()` 成功后产生，不在 socket send 时产生。
- AS2 业务优先级仍由 `SoundEffectManager` 持有，C# 不重新实现 stage/jukebox/scene 决策。

### 7.3 SFX

- native/C# 完成 preload 后发布 `audio_ready {audioSessionId, audioReadyGeneration, deviceGeneration, loaded, failed, overrides, capabilityDigest}`。
- ABI、decoder registry 或真实 device 失败时改发 `audio_unavailable {audioSessionId, audioReadyGeneration, deviceGeneration, category, messageKey}`；不得同时发布 `audio_ready`。
- ready 前和 recovery 中的 SFX 不排队重放；分别计入 `preReadyDrops` / `recoveryDrops`。
- 每帧 fast-lane 保持批量低开销，不对每一枪做请求/响应往返。
- 汇总暴露 `unknownIdCount`、`throttledCount`、`startFailureCount`、`playedCount`，对首个/采样错误写结构化日志。
- `ma_sound_seek_to_pcm_frame()` 与 `ma_sound_start()` 均检查返回值；只有成功才计 `playedCount`。

### 7.4 Wire migration

- 新 wire 使用显式 revision；schema、AS2、C#、fixture 和文档同轮升级。
- implementation candidate 可短暂接受旧 wire 做差分诊断，但最终 release Gate 必须删除永久 v1 fallback 或证明它仅属于明确的 bounded migration window。
- 触及 `AudioBridge.as` 时先复核实际 source/include 归属；默认优先 `asLoader`，不能未经证据选择 `main`。
- AS2 编译结论必须有 fresh trace/Output；`publish_done.marker` 不单独算成功。

## 8. Catalog 与资产合同

### 8.1 Discovery 与 runtime compatibility probe

`MusicCatalog` 不再拥有硬编码“支持格式”真值。新流程：

```text
filesystem candidate
  → header/container sniff
  → native capability match
  → bounded runtime compatibility probe
  → available | probing | unavailable(reason)
  → catalog projection
```

手工注册但 missing/unsupported 的曲目保留可诊断记录，UI 显示禁用和 reason，不表现为可点击成功项。

玩家热投放文件在 size/mtime 连续稳定后才 probe；复制中的半文件保持 `probing`/`unstable_input`，不得被永久缓存为 malformed。

R2 runtime probe 只回答“当前 capability 是否可初始化并在上限内产出解码帧”，不签完整内容质量：两次 `size+mtime` 观测间隔 1000 ms；文件上限 512 MiB；单次最多 2000 ms、8 MiB 输入、96000 decoded frames；可取消。它不查询完整 duration、不要求 EOF。超时为 `inconclusive_timeout` 而不是 unsupported；有界窗口全零为 `compatible_signal_unknown`，不能写 `ok_silent`。缓存键含 normalized path、size、mtime、首 64 KiB SHA-256、capability digest 和 probe contract revision。

### 8.2 Extension mismatch

- shipped BGM 出现 extension/container mismatch 时，qualification 默认失败；本轮 A5 已把 11 个 AAC/ISO BMFF 伪装 `.wav` canonical rename 为 `.m4a`，未来新增 mismatch 仍须 canonical rename 或显式 owned exception。
- 玩家热投放文件可按内容解码，但必须标记 `extension_mismatch`；不得自动改写用户文件。
- 539 个历史 `.wav`/MP3 多数属于 SFX/linkageId，禁止批量改名；先用 content-based decoder 和 manifest 证明兼容。
- 11 个 MP4/AAC 伪装 BGM 已 canonical rename；缺失 Zenitsu URL 和 latent `apwersound.wav` 分别保留 owned diagnostic，不能用占位静音文件掩盖三种问题。

### 8.3 Offline qualification 与 silent content

只有 offline qualification probe 必须 stream decode 到 EOF，并输出 full SHA-256、frames、duration、peak、RMS、leading/trailing silence 和 non-finite count；单文件上限 120 秒，超时是 qualification failure，不冒充 unsupported。probe VFS 只在零字节物理 EOF 返回 `MA_AT_END`，末尾短读必须先把已读字节交给 decoder；full-hash 同遍扫描验证 Ogg page header/lacing/body 的物理边界，页内 EOF 归 `truncated` 且 `eofState != reached`，完整页再由 decoder 判定 malformed/可解码。`ok_silent` 是合法检测结果但默认不进入可播放目录；若设计上确需静音资源，必须在 asset manifest 显式 allow。该 probe 不得在 catalog/UI hot path 执行。

## 9. 可观测性与“有声”词典

### 9.1 Runtime diagnostics

至少提供：

- BGM/SFX pre-master peak/RMS 与 clip counter；
- source/group/master gain；
- cursor/length/playing/start result；
- selected decoder/container/codec；
- backend/device/state/generation/underrun；
- preload/recovery/drop/error counters。

生产 runtime 不常驻抓取系统 loopback；endpoint capture 仅在显式 qualification/diagnostic 模式启用。

### 9.2 结论词典

| 词 | 最低证据 | 不能推出 |
|---|---|---|
| `referenced` | 配置/AS2 引用存在 | 文件存在 |
| `identified` | container/codec 识别 | 可完整解码 |
| `decoded` | EOF、frame/duration 合法 | PCM 非零 |
| `content_nonzero` | peak/RMS 超过冻结阈值 | 播放图已启动 |
| `graph_signal` | start 成功、cursor 与 bus meter | 真实设备或 endpoint 有声 |
| `device_active` | real backend/device started | 系统 mixer/硬件可听 |
| `endpoint_nonzero` | loopback/端点捕获非零 | 听感质量可接受 |
| `human_audible` | 人工听见 | 无爆音、延迟或平衡问题 |
| `human_accepted` | 完成人工矩阵并签 H2 | promotion 或正式入口验证已完成 |

master/BGM/SFX gain 为 0 时是 `muted_by_gain`，不是 decoder failure。全零 packet 也不能单独代表 stop。

## 10. 构建、身份与发布合同

### 10.1 Build closure

修复后新的 release source S 必须冻结以下 source closure：

- `audio-v2-build-inputs.v1.json` 固定排序 materialize `miniaudio.c + miniaudio.h`、bridge/backend/support/decoder C/C++ TU 与 Xiph source；`build-audio-v2.ps1`/`build.bat` 把它们 deterministic link 为单一 `miniaudio.dll`；
- `decoder-dependencies.lock.v1.json` 固定 miniaudio/Xiph 来源、源码 SHA、flags、license 与 Media Foundation Windows SDK link inputs；`THIRD-PARTY-NOTICES.txt` 承载分发 notice；
- `runtime-inputs.v2.json` 的 native artifact source 覆盖 `.c/.cpp/.h/.rc` 与所需构建脚本/lock，新增 `.cpp` 不再逃逸 build identity；native change gate/workflow 已覆盖 native source 及 Audio v2 contract 触发面；
- qualification runner、observer/stimulus、依赖 manifest、configuration/fixture materializer/operator、asset inventory、endpoint capture/lister 和 draft-only assembler 显式进入 source/policy/qualification closure，不靠目录 wildcard 推断。

第一份失败 S 的 identity/closure 已随静音 attempt 降为历史。S2 随后从静止 source 重生成并 `--check` decoder lock、native build inputs、shipped asset inventory 与 runner dependency closure，完成两个 clean worktree 和 main live producer，三者一致得到 build identity `0044438A…F2FA`、payload closure `32FD1E5B…1EF` 与 runtime manifest SHA-256 `ED2DFB30…EC98`；其 A6 run 又在真实 capture 后暴露 operator artifact/wire canonical mismatch，因此 S2 identity/closure 同样只保留为历史。S3 再次完成相同 identity/closure/manifest 的双 clean repro，却在第三次 A6 暴露 fixture materializer 的 extensionless SFX key 与 production full-filename catalog key 不一致；当前 materializer/test 与 dependency manifest 已改变 artifact source。本文定义的新 S 冻结后仍须由两个 clean worktree 逐项比较 build identity、payload closure 与 file rows，当前没有该新 S 的结果或 candidate identity/closure。

### 10.2 State machine

| 状态 | Audio v2 最低证据 |
|---|---|
| `compiled` | 锁定工具链成功；新增 native/C#/AS2 tests 与受影响现役门通过 |
| `candidate_built` | immutable candidate、manifest、identity、closure 自洽；仍 `NOT_DEPLOYED` |
| `candidate_executed` | exact isolated candidate 进程已按全局 runtime v2 合同实际加载；无设备负例也可达到，但须记录 `audio_device_qualified=false` |
| `e2e_verified` | AS2→socket→C#→native→endpoint；BGM/SFX/格式/故障矩阵与人工听感通过 |
| `promoted` | H2 后 immutable request、双 builder、receipt、strict promotion/full-install verifier 完成 |
| `standard_entry_verified` | 无 candidate 参数正式入口加载同一 identity/closure，并跑音频专项 smoke |

通用 Help panel smoke 不能代签音频专项 standard-entry；Jukebox browser harness 也只证明 UI/控制面。

`audio_device_qualified` 是 Audio v2 的局部资格布尔值，不是新的全局 runtime lifecycle 状态。它至少要求 actual backend/device 已知、非 Null、device started 且 structured evidence 完整；只有 `candidate_executed && audio_device_qualified` 才可继续正向端点 E2E。无设备/首选 backend 失败的负例仍是有效的 `candidate_executed` 证据。

## 11. Qualification 与验收矩阵

### 11.1 Corpus

## 12. 分片施工计划

A1–A6 的 R2 历史施工曾由 R2 H1 解锁；当前 R3 H1/H3 已激活，三项证据修正、隔离构建与 A6 重跑已授权，但 promotion/deployment 仍阻断。当前进度与剩余 Gate 以 §15.3 为准。

## 14. 风险与 stop-loss

| 风险 | 控制 | Stop-loss |
|---|---|---|
| MF seek/thread 生命周期复杂 | bounded A3 spike + fault injection | 无法稳定 seek/cancel 时只保留资产规范化，不硬接生产 |
| 新 codec 扩大 CVE/许可面 | 官方源码、pin/hash/notice、窄 allowlist | 依赖无法可复现或许可不清则拒绝该 codec |
| 设备切换引入双 owner、崩溃或重复播放 | callback notify-only、owner-only mutation、bounded recovery；BGM latest intent，SFX no replay | 物理切换/退出压力出现 crash、stale SFX 或双播即停止 A2/A4 |
| content probe 拖慢 hot reload | background bounded runtime probe + explicit state | 不允许阻塞 UI/Flash ready；超时标 `inconclusive_timeout`，不误判 unsupported |
| 批量改名破坏 linkageId | shipped BGM 与 SFX 分开治理 | 未闭合全部 consumer 前禁止 SFX rename |
| meter 被误解为可听 | 结论词典 + endpoint/H2 | 任何 Gate 以 peak 单签即失败 |
| 一次性范围膨胀 | AUDIO-V2-013 非目标 | 出现 FFmpeg/网络流/DSP 要求时另开 ADR |
