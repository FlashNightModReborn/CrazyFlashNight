## 原生施工交接

| 组件 | 实现入口与待验处 |
|---|---|
| HP、MP、护盾、韧性、经验、武器 | 以 `PlayerHudState` 及 `PlayerHudRuntime` 为读数入口，复用 `PlayerInfoAnimationModel`、`PlayerInfoFrameCompositor`、`PlayerHudAmmoPainter`。保留逻辑帧、超额值、未知值，以及装填明细缺失时的既有降级。 |
| 敌我单位 | `FocusTargetHudService` 选中目标，`PlayerHudFocusTargetWidget` 消费 #304 的共享生命显示核心。保护、首领、交战按原顺序，普通交战至多一名。以场景身份和代际合并友军，名称与健康值只参与显示。生产沿用既有容量合同，5–8 个焦点是扩展容量的压力夹具。 |
| Buff 与淬毒 | `PlayerHudBuffCard`、`PlayerHudBuffLayout` 共享生效实例。比对现有投影后按需补药效来源、能抗期限、淬毒初值或架势威力。中毒、能量抗性用各自倒计时，护盾用量和恢复阶段，技能梁上的武器淬毒用点数。 |
| 顶栏、输入与绘制 | `NotchWidget` 提供稳定底边，`HudZoneLayout` 仲裁给 `ComboWidget`。绘制、点击、悬停与空白透传共用几何。缓存头像及重复材质，按变化区域重绘。在同一游戏场景比较绘制、提交、分配与延迟。 |

离线浏览器已检验 1–8 个焦点、1024×576、4:3 和超宽、100%–175% 像素倍率、静态与减弱动效。底栏按 87 组既有原生样本对照，另有 19 项交互与边界检查。游戏画面背景来自截图，作战遮挡、状态与输入由夹具驱动。原生键鼠透传、移动交火、真实数据和帧耗由 #309 验收，#249 保留到该反馈实机通过。[验证记录](verification.json) · [#304 生命显示核心](https://github.com/FlashNightModReborn/CrazyFlashNight/issues/304) · [#309 原生施工](https://github.com/FlashNightModReborn/CrazyFlashNight/issues/309) · [#249 玩家反馈](https://github.com/FlashNightModReborn/CrazyFlashNight/issues/249)
