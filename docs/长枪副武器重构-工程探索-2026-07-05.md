# 长枪副武器重构工程探索

**文档角色**：长枪下挂 / 副武器完整重构前期探索与审阅计划。  
**最后核对代码基线**：commit `8dee018c07`（2026-07-05）。  
**状态**：Phase A Flash 资产、K/F/R 运行时闭环、F 快装动画、正式 `subweapon` 数据迁移与旧主动战技入口清理均已推进；本轮补做结构治理与验证。

---

## 1. 需求对齐

本轮讨论要对齐的目标：

- 将现有“发射榴弹”从普通长枪主动战技语义中拆出。
- 对带下挂 / 副武器的长枪，按 `K`（功能键B / `动作B`）发射副武器。
- 长枪主射击仍按 `J`（功能键A / `动作A`）。
- 副武器有独立控制，不再表现为“按 F 直接发射的主动战技”。
- 双枪模式没有主动战技是刻意平衡设计；带副武器的长枪也应沿用同一语义：装备副武器占用长枪战技空间，不能再配置普通长枪战技。
- UI 希望尽量复用双枪的第二弹药显示路线，降低 UI 施工量。

关键设计判断：

- **推荐复用双枪 UI 第二行字段**（`子弹数_2 / 弹夹数_2`）。
- **不推荐直接复用双枪射击 / 换弹整套路线**。双枪射击核心强绑定 `手枪 + 手枪2`、`枪2.枪.装扮.枪口位置`、双枪换弹动画与 `WeaponStateManager`，不适合作为长枪下挂机制的运行时真源。

## 3. 目标架构

### 3.1 新概念：长枪特殊槽

建议把长枪的“F 战技 / 下挂副武器”统一看成一个互斥特殊槽：

```text
LongGunSpecialSlot:
  none
  weaponSkill       普通长枪主动战技，F 释放
  subWeapon         长枪副武器，K 发射，可选 F 装填
```

设计含义：

- 没有特殊槽：普通长枪，只能 J 主射击。
- `weaponSkill`：保持现有长枪主动战技，F 使用。
- `subWeapon`：长枪获得 K 副武器发射；F 不再释放普通长枪战技。

这与双枪模式无主动战技的平衡语义一致。

### 3.2 新运行时组件：LongGunSubWeaponCore

建议新增类或帧脚本级模块：

```text
LongGunSubWeaponCore
  init(unit, config)
  canFire(unit):Boolean
  fire(unit):Boolean
  canReload(unit):Boolean
  reload(unit):Boolean
  updateAmmoDisplay(unit):Void
  clear(unit):Void
```

职责边界：

- 只处理长枪副武器。
- 不污染 `ShootCore.secondaryParams`。
- 不把 `攻击模式` 改成 `双枪`。
- 不发布 `WeaponSkill`，避免触发普通战技监听器。
- 可发布新事件，如 `LongGunSubWeaponFire` / `LongGunSubWeaponReload`，供装备外观或后续 UI 监听。

### 3.3 数据模型

当前正式数据已经迁移为 `<subweapon>`。active `data/items` 不再使用 `<skill><skillname>发射榴弹</skillname>` 作为运行时入口。

推荐正式 schema：

```xml
<subweapon>
    <name>M203榴弹发射器</name>
    <description>...</description>
    <cd>1000</cd>
    <capacity>1</capacity>
    <reserveName>榴弹弹药</reserveName>
    <bullet>榴弹</bullet>
    <sound>shoot.wav</sound>
    <split>1</split>
    <diffusion>10</diffusion>
    <velocity>20</velocity>
    <range>50</range>
    <impact>10</impact>
    <power>3000</power>
    <damageType>物理</damageType>
    <magicType></magicType>
    <powerMultiplier>1</powerMultiplier>
    <reloadMode>hybrid</reloadMode>
    <linkedReloadOnMain>true</linkedReloadOnMain>
    <manualReloadAnimation>longGun</manualReloadAnimation>
    <manualReloadBurden>25</manualReloadBurden>
    <consumeMode>onLoadGroup</consumeMode>
    <consumeTiming>onReloadCommit</consumeTiming>
    <clipCostPerLoad>1</clipCostPerLoad>
    <mp>0</mp>
    <hp>0</hp>
</subweapon>
```

宿主长枪也可以提供副武器倍率，作为平衡性扳手：

```xml
<subweaponPowerMultiplier>1</subweaponPowerMultiplier>
```

历史迁移对照：

| 旧 `<skill>` 字段 | 新 `<subweapon>` 字段 | 说明 |
|---|---|---|
| `skillname=发射榴弹` | `<subweapon><name>...</name>` | 旧入口已迁移；active 数据不再使用该标识 |
| `cd` | `cd` | K 发射节流 |
| `bulletsize` | `capacity` | 当前代码里实际是副武器弹仓可发射数 |
| `clipname` | `reserveName` | 副武器消耗弹药，迁移后使用正式字段 |
| `power` | `power` | 副武器子弹威力 |
| `damagetype` | `damageType` | 伤害类型，旧代码默认 `物理` |
| `magictype` | `magicType` | 魔法伤害属性，旧代码默认 `null` |
| 新增 | `powerMultiplier` | 副武器模块自身威力倍率，默认 `1` |
| `bullet` | `bullet` | 子弹种类 |
| `sound/split/diffusion/velocity/range/impact` | 同名 | 子弹参数 |
| `instantconsume` | `consumeMode=onFire` | 旧即时消耗模式迁移为正式逐发消耗 |
| 新增 | `consumeTiming` | `onReloadCommit` 或 `linkedFirstFire`，用于区分弹药扣除时机；当前正式数据采用 `onReloadCommit` |
| `mp` | `mp` | 每次副武器发射消耗 MP，默认 `0` |
| `hp` | `hp` | 每次副武器发射消耗 HP，默认 `0` |

正式缺省：

- `reserveName` 缺省：`榴弹弹药`
- `bullet` 缺省：`榴弹`
- `capacity` 缺省：`1`
- `sound` 缺省：`re_GL_under.wav`
- `velocity` 缺省：`25`
- `range` 缺省：`50`
- `impact` 缺省：`0.01`
- `damageType` 缺省：`物理`
- `magicType` 缺省：`null`
- `mp` / `hp` 缺省：`0`
- `powerMultiplier` 缺省：`1`
- 宿主 `subweaponPowerMultiplier` 缺省：`1`
- `reloadMode` 缺省：`hybrid`，即 R 主换弹联动补副武器，F 可作为副武器手动快装。
- `linkedReloadOnMain` 缺省：`true`。
- `manualReloadAnimation` 缺省：`longGun`，复用长枪换弹资产。
- `manualReloadBurden` 缺省：`25`，表示复用换弹帧率控制时使用很低负担值，约等价高倍率快装；实现层应设置下限，避免跳过帧脚本。
- `consumeMode` 缺省：`onLoadGroup`。它只表示“1 份弹药换一组发射次数”的弹药数量语义，不等同于完全兼容旧扣弹时机。
- `consumeTiming` 当前正式缺省：`onReloadCommit`。装备初始化后的第一仓由 `initialLoaded` 显式表达；R 联动补装与 F 手动快装都属于副武器装填提交，会立即扣 `clipCostPerLoad` 并标记该组已付费，避免 UI 满仓但备弹不变。
- `clipCostPerLoad` 缺省：`1`。旧 `bulletsize=5` 的金属风暴语义是 `1` 个榴弹弹药支持同一组内 5 发，不是 5 个榴弹弹药。

### 3.4 副武器伤害倍率乘区

副武器核心应内建统一的伤害倍率计算，而不是让被动技能或特殊武器散落在具体发射函数里。

推荐入口：

```text
LongGunSubWeaponCore.calculatePower(unit, longGunData, subweaponConfig):Number
```

推荐公式：

```text
finalPower =
  basePower
  * subweaponPowerMultiplier
  * hostSubweaponPowerMultiplier
  * passiveSubweaponPowerMultiplier
```

字段含义：

- `basePower`：`subweapon.power`，兼容旧 `<skill><power>`。
- `subweaponPowerMultiplier`：副武器模块自身倍率，来自 `subweapon.powerMultiplier`，默认 `1`。
- `hostSubweaponPowerMultiplier`：宿主长枪对所有下挂 / 副武器的倍率，来自宿主 `subweaponPowerMultiplier`，默认 `1`。
- `passiveSubweaponPowerMultiplier`：技能与状态提供的副武器倍率。

当前必须迁入的被动倍率：

```text
冲击连携启用 && 宿主长枪 weapontype == "霰弹枪":
  passiveSubweaponPowerMultiplier = 1 + 0.15 + (等级 - 1) * (0.25 - 0.15) / 9
```

实现注意：

- 倍率统一在副武器核心计算，不再写在 `主动战技函数.长枪.发射榴弹` 初始化里。
- 不把最终值回写到 XML `power`，避免换枪 / 换插件 / 重初始化时重复乘算。
- 第一版建议乘区都使用小数倍率（如 `0.85`、`1.15`），不要混用 `15%` 字符串，降低 AS2 解析歧义。
- 该倍率只作用于长枪副武器子弹威力，不影响主武器 `ShootInitCore.calculateWeaponPower()` 的主射击伤害。

### 3.5 配件计算输出

当前稳定形态下，装备计算输出两个互斥字段：

```text
itemData.skill       普通主动战技
itemData.subweapon   长枪副武器配置
```

规则：

- active 数据中的下挂插件与宿主自带副武器均使用 `<subweapon>`，不再通过 `<skill>` 表达。
- 其他 `<skill>` 仍保持普通主动战技。
- 若宿主已有普通 `skill` 且插件提供 `subweapon`，或宿主已有 `subweapon` 且插件提供普通战技，安装时拒绝，保持“特殊槽互斥”。
- 已安装配件中如果已经存在普通战技或副武器，新特殊槽插件也会被拒绝。

已同步迁移的代码点：

- `EquipmentCalculator.calculate()` 识别 `modifiers.subweapon` 并写入 `itemData.subweapon`。
- `TagManager.checkModAvailability()` 把普通战技与 `subweapon` 统一纳入长枪特殊槽冲突。
- `DressupInitializer.updateWeqaponSkills()` 读取 `data.subweapon` 并装载副武器控制槽，不把副武器装入普通主动战技。
- `单位函数_fs_装备生命周期配置.as` 在长枪已有 `subweapon` 时不再用生命周期 `skill` fallback 补普通主动战技。

### 3.6 输入语义

默认键位：

- `J / 动作A`：主武器射击。
- `K / 动作B`：长枪副武器发射，仅在 `攻击模式 == "长枪"` 且存在 `subweapon` 时消费。
- `R / 动作C`：主武器换弹保持原行为；若配置长枪副武器，主武器实际进入换弹流程时顺带尝试补满副武器弹仓。
- `F / 武器技能键`：普通主动战技；若 `subweapon` 占用特殊槽，则无普通主动战技，F 可作为副武器手动快装入口。

推荐实现：

```text
持枪行走状态机:
  动作C -> 主武器换弹
  动作A -> 主武器射击
  动作B && unit.长枪副武器 -> LongGunSubWeaponCore.fire(unit)
```

K 触发 / 冷却硬规则：

- 现有长枪行走状态机对 `动作B` 是按住逐帧进入射击入口；副武器不能依赖状态机只触发一次。
- 推荐语义：**按住 K 按 `cd` 连发**，与武器射击 / 双枪副手的按住心智一致；不是只响应按下沿。
- `LongGunSubWeaponCore.fire()` 必须自带冷却门禁，例如 `unit.subWeapon.nextFireTime` 或 `unit.长枪副武器冷却截止时间`。每次成功发射后写入 `now + subweapon.cd`。
- K 发射冷却是副武器内部冷却，不默认驱动现有 F 战技进度条；现有战技进度条第一版只服务 F 手动快装控制槽。若未来要显示 K 冷却，应新增副武器 UI 或第二行状态，不复用普通战技冷却含义。
- 按住 K 时每帧调用入口可以接受，但入口必须在冷却未到、弹仓为空、资源不足、状态不合法时无副作用返回 `false`。

注意：空手 / 兵器模式下 `动作B` 仍保留跳跃 / 派生，不应全局改 K 语义。

### 3.7 F 手动快装入口

当前 `flashswf/UI/玩家信息界面/LIBRARY/sprite/战技控制器.xml` 在已扣扳机帧固定调用：

```actionscript
var 释放战技结果 = _root.gameworld[_root.控制目标].释放主动战技();
```

而 `_root.主角函数.释放主动战技()` 当前固定执行：

```text
检查 hp/mp -> 战技函数.释放() -> dispatcher.publish("WeaponSkill", 攻击模式)
```

因此 F 手动快装不能只靠 `释放主动战技()` 顶部旁路。`玩家必要信息界面.刷新(攻击模式)` 当前只有在 `主动战技[攻击模式]` 存在时才显示 `战技栏 / 战技进度条 / 战技控制器`；`战技控制器` 还要求战技栏有 `已装备名` 且进度条 `冷却` 可用才会进入“已扣扳机”。Phase 1 又要断开旧 `发射榴弹` 普通主动战技入口，若没有新的 UI / 输入数据源，F 快装会不可达。

可选方案：

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A. 副武器控制槽 | 给 `主动战技[长枪]` 放入 `isSubweaponControl=true` 的伪控件数据，只驱动战技栏 / 控制器 / 冷却；`释放主动战技()` 顶部识别该标记并转调 `LongGunSubWeaponCore.startManualReloadAnimation()`，动画提交帧再调用 `reloadManual()` | 复用现有 F 控制器与冷却 UI，不改 `战技控制器.xml` | 必须防止它被当作普通 `WeaponSkill` 或普通主动战技生命周期 |
| B. 独立 F 输入路径 | 在主角输入 / 状态机层另接 `武器技能键`，直接调用副武器快装，并另做 UI 提示 | 语义最干净 | UI 与输入改动面更大，容易和现有战技控制器状态冲突 |

推荐第一版采用 **A. 副武器控制槽**。它不是普通主动战技，只是 UI 控制数据；Phase 1 断开的应是旧 `发射榴弹` 战技函数入口，而不是让 `主动战技[长枪]` 完全为空。

控制槽要求：

- `主动战技[长枪]` 可存在，但必须标记为 `isSubweaponControl=true`，并提供 `名字 / 图标 / 冷却时间 / 已装备名` 等战技栏需要的展示字段。
- 现有 `装载主动战技(战技信息, 攻击模式)` 不能直接承载该方案：它要求 `_root.主动战技函数[攻击模式][skillname]` 存在，并且会重建 `当前战技`，不会自然保留 `isSubweaponControl`。
- Phase 1 必须二选一：
  - 修改 `装载主动战技()`：在普通战技函数表门禁之前识别 `战技信息.isSubweaponControl`，构造并保留控制槽对象，跳过 `_root.主动战技函数` 检查。
  - 新增 `装载副武器控制槽(subweaponConfig, 攻击模式)`：直接写入 `this.主动战技[攻击模式]`，字段只服务战技栏 / 控制器 / 冷却，不经过普通战技装载器。
- 推荐新增专用控制槽装载器，避免普通战技装载函数承担过多分支；但无论选哪种，marker 都必须保留到 `释放主动战技()` 可见。
- `释放主动战技()` 在普通战技流程之前识别 `isSubweaponControl`，转调 `LongGunSubWeaponCore.startManualReloadAnimation(this)`。
- `startManualReloadAnimation()` 成功时返回 `true`，让现有战技控制器刷新 MP / 启动 UI 冷却；真正填仓 / 扣备弹发生在长枪 `换弹匣()` 提交帧。
- 不能调用普通 `战技函数.释放()`，不能发布 `WeaponSkill`。
- 装备生命周期、战技栏刷新和 tooltip 若读取 `主动战技[长枪]`，必须识别 `isSubweaponControl`，不能把它当普通主动战技。
- 若不愿污染 `主动战技` 表，则必须选择方案 B，并把独立 F 输入路径与 UI 提示作为同轮实现内容；不能只改 `释放主动战技()`。

### 3.8 装填语义待决策

当前旧机制是“主武器换弹时重置副武器计数”，但弹药实际在首次发射许可中消耗。代码注释里有“默认模式：换弹时消耗”的表述，但真实行为是 `ReloadManager.reloadMagazine()` 只重置 `当前弹夹副武器已发射数`，`单位函数_雾人_aka_fs_主动战技.as` 的释放许可在第一次发射时 `ItemUtil.singleSubmit()`。

完整重构建议把副武器装填独立成清晰状态：

```text
subWeapon.loaded       当前已装填发数
subWeapon.capacity     最大装填发数
subWeapon.reserveName  弹药物品名
```

可选方案：

| 方案 | 控制 | 优点 | 缺点 |
|---|---|---|---|
| A. 主换弹顺带副武器装填 | R 换长枪时补副武器 | 施工小，接近旧行为 | 不够“独立副武器控制” |
| B. F 装填副武器，K 发射 | F 不再是普通战技，而是副武器装填动作 | 语义最清晰，符合“副武器上弹” | 需要 UI 提示，避免玩家以为 F 仍是战技 |
| C. K 空仓时自动尝试装填 | K 既尝试发射也可自动装填 | 操作少 | 容易误耗弹药，反馈不清晰 |
| D. 混合装填 | R 主换弹联动补弹，F 手动快装，K 发射 | 保留旧心智模型，同时给副武器独立控制 | 状态机与 UI 需要明确区分装填来源 |

推荐：**D 作为完整重构目标**。长枪副武器占用特殊槽，K 负责发射；R 主换弹仍顺带补满副武器弹药，以保留玩家已经习惯的旧行为；F 可作为副武器手动快装动作，但不走 `WeaponSkill` 事件，也不算普通主动战技。

具体规则建议：

- R 联动补弹只在主武器实际进入换弹流程并到达换弹提交点时发生；按 R 但主武器无法或无需换弹时，可把副武器作为候补换弹目标；副武器没有足够备弹时，不应白送副武器装填。
- 默认 `consumeMode=onLoadGroup` 只保持旧 `bulletsize` 的弹药数量经济：消耗 `clipCostPerLoad` 个 `clipname`，获得一组 `capacity` 发；不是按缺口逐发收费。
- 当前正式采用 `consumeTiming=onReloadCommit`：R / F 装填提交时立即扣 `clipCostPerLoad` 并写入 `loaded=capacity`；这是更符合“副武器上弹”的新语义，当前测试新版本不再为旧扣弹时机保留默认行为。
- `consumeTiming=linkedFirstFire` 仅作为可选延迟扣弹语义：R 联动补装只在备弹足够时重置 / 标记可发射组，第一次 K 发射时再扣 `clipCostPerLoad`。
- `consumeTiming=onReloadCommit` 下，副武器弹药不足不能取消或回滚主武器换弹。主武器换弹照常提交，副武器保持空仓 / 原 loaded，并给出副武器补弹失败反馈。
- `consumeMode=onFire` 时沿用旧 `instantconsume=true` 语义：每次 K 发射消耗 1 个 `clipname`，R 只在至少可支付第一发时重置同一主弹夹内的可发射计数。
- F 手动快装只处理副武器，不消耗主武器弹匣，不发布 `WeaponSkill`；可发布 `LongGunSubWeaponReload`，并标记来源为 `manual`。
- R 联动补弹可发布同一事件，来源标记为 `mainReloadLinked`，供 UI / 音效监听，但不能触发普通战技生命周期。
- `onFire` 与 `onLoadGroup` 都是正式语义，不应在迁移期吞掉旧数据差异。

### 3.9 副武器装填动画

副武器手动装填第一版不建议新增专用 FLA / linkage 资产。推荐复用长枪上身的 `换弹匣` 动画，并在进入该流程前设置副武器装填上下文：

```text
reloadPurpose = "longGunSubWeapon"
reloadAnimation = "longGun"
reloadBurdenOverride = manualReloadBurden
```

复用资产的理由：

- 能沿用长枪换弹的上身姿态、枪械遮挡、音效帧与 `ReloadManager.controlReloadFrameRate()`。
- 不需要在本轮触碰主 FLA / linkage，降低 Flash 资产施工风险。
- 高加速倍率能补偿“只是装一下下挂武器却播放整段长枪换弹”的违和感。

实现边界：

- 手动副武器装填应调用副武器自己的提交函数，而不是 `ReloadManager.reloadMagazine()` 的主武器弹匣提交逻辑。
- `manualReloadBurden` 建议默认 `25`，可按副武器配置调节；实现层应设置下限，例如不低于 `20`，避免一次推进过多帧导致帧脚本、音效帧或结束帧被跳过。
- R 换弹负担按目标拆分：只换主武器时使用长枪主武器负担；只换副武器时使用 `manualReloadBurden`；主武器与副武器同一段 R 换弹一起补时，使用二者负担之和，避免主副火力总恢复速度过高。
- 如果未来有下挂专用动画，可把 `manualReloadAnimation` 从 `longGun` 切到专用值；第一版不要阻塞在资产制作上。

### 3.10 tooltip / 注释层对接

副武器必须有独立 tooltip 块，不能继续复用“主动战技”块。当前第一版直接由 `TooltipTextBuilder.buildSubweaponInfo()` 承载；若后续信息继续膨胀，再拆 `SubweaponBlockBuilder`。

接入点：

- `TooltipComposer.generateItemDescriptionText()`：在装备描述区读取最终 `baseItem.getData().subweapon`，优先于原始 `item.subweapon`。若存在 `subweapon`，调用 `TooltipTextBuilder.buildSubweaponInfo()` 或 `SubweaponBlockBuilder.build()`。
- `TooltipTextBuilder.buildSkillInfo()`：保持普通主动战技用途；副武器由 `buildSubweaponInfo()` 渲染。
- `ModStatBuilder.build()`：当 `modData.subweapon` 存在时，输出“副武器”块，而不是“主动战技”块。
- `ModsBlockBuilder`：配件摘要中若有 `subweapon`，显示“副武器 + 名称”；`skillSwitch` 仍只代表普通主动战技。

副武器 tooltip 建议展示字段：

| 类别 | 字段 |
|---|---|
| 入口 | `K 发射`、`R 主换弹联动补弹`、`F 手动快装` |
| 弹药 | `capacity`、`loaded`、`reserveName`、`consumeMode`、`consumeTiming`、`clipCostPerLoad` |
| 装填 | `reloadMode`、`linkedReloadOnMain`、`manualReloadAnimation`、`manualReloadBurden` |
| 发射 | `bullet`、`split`、`diffusion`、`velocity`、`range`、`impact` |
| 成本 | `cd`、`mp`、`hp` |
| 伤害 | `power`、`damageType`、`magicType`、`powerMultiplier`、宿主 `subweaponPowerMultiplier`、被动倍率 |

展示原则：

- 装备 tooltip 显示“副武器”块；普通主动战技仍使用 `buildSkillInfo()`。
- 普通长枪战技仍使用 `buildSkillInfo()`；普通战技与副武器互斥的冲突文案由 `TagManager.checkModAvailability()` 和配件 tooltip 对齐。
- 副武器伤害倍率不应只在运行时生效，tooltip 至少要显示最终倍率来源：副武器自身倍率、宿主倍率、被动倍率。若第一版篇幅受限，可以先显示最终伤害倍率与最终威力。
- `consumeMode=onLoadGroup` 必须明确成“每组消耗”，并结合 `consumeTiming` 显示扣弹时机，避免玩家误解为每发消耗；`consumeMode=onFire` 才显示为“每次发射消耗”。

## 4. UI 路线

### 4.1 可复用部分

可以复用现有第二行显示字段语义：

- `玩家必要信息界面.子弹数_2`
- `玩家必要信息界面.弹夹数_2`

XFL 实现事实：

- 入口文件：`flashswf/UI/玩家信息界面/玩家信息界面.xfl`。
- 实际符号：`flashswf/UI/玩家信息界面/LIBRARY/sprite/玩家必要信息界面.xml`。
- 标签帧中 `长枪` 在 index 12，`双枪` 在 index 32。
- 当前最后一个标签帧是 `双枪`：index 32、duration 5，时间轴总长度约 37 帧；新增 `长枪副武器` 更适合追加在末尾，避免插入中间导致既有帧整体位移。
- 第二行 `text2` 和驱动它的 `通用透明组件` 只存在于 `双枪` 帧，不存在于 `长枪` 帧。
- 普通 `长枪` 帧的主弹药文本是直接绑定 `variableName="子弹数"` / `variableName="弹夹数"` 的两个动态文本，不存在 `text1` / `text2` 实例。
- `双枪` 帧的弹药文本是 `DOMDynamicText name="text1"` 和 `DOMDynamicText name="text2"`，由 `通用透明组件` 每帧拼接 `子弹数 / 弹夹数` 与 `子弹数_2 / 弹夹数_2`。
- `组件` 层里的 `通用透明组件` 在 `onClipEvent(load)` 和 `onClipEvent(enterFrame)` 中持续执行：

```actionscript
_parent.text1.text = _parent.子弹数 + " / " + _parent.弹夹数;
_parent.text2.text = _parent.子弹数_2 + " / " + _parent.弹夹数_2;
```

这意味着长枪副武器第二行不能只靠 AS2 逻辑层控制 `ui.text2._visible`。长枪帧上大概率没有 `text2` 对象，必须做 XFL/UI 施工。

推荐 UI 施工方案：

- 新增 `长枪副武器` 帧标签，追加在 `双枪` 之后，建议首帧 index 37、duration 5。
- 按图层分源复制：战技控件相关层复制 / 延展 `长枪` 帧语义；弹药双行显示相关层复制 `双枪` 帧的 `text1/text2 + 通用透明组件` 成套结构。
- 或者直接在现有 `长枪` 帧补入第二行文本与驱动组件，再由 AS2 根据 `hasLongGunSubWeapon` 控制可见性。
- 第一版更推荐新增 `长枪副武器` 帧，避免普通长枪帧承担额外对象与可见性分支。
- 触发条件从 `刷新(攻击模式)` 扩展为：`攻击模式 == "长枪" && hasLongGunSubWeapon` 时跳到 `长枪副武器`，普通长枪仍跳 `长枪`。

不要只把双枪帧的 `text2` 和 `通用透明组件` 塞进普通长枪布局：组件脚本同时写 `_parent.text1.text` 和 `_parent.text2.text`，普通长枪帧没有 `text1` 实例，会形成不稳定对象依赖。

该改动触及 XFL，必须进入 XFL 治理流程：跑 `scripts/tools/xfl/` audit / rename_a_class / fix_includes 三件套，并重扫 `tools/linkage_scanner/scan_linkage.py`；若需要刷新 UI SWF / 主 FLA，应按 Flash 三层目标说明验证，不能只改 `.as`。

显示建议：

```text
子弹数     / 弹夹数      = 长枪主武器余弹 / 主弹药库存
子弹数_2   / 弹夹数_2    = 副武器已装填发数 / 副武器弹药库存
```

如果选择 F 装填副武器：

- `子弹数_2` 显示当前副武器已装填发数。
- `弹夹数_2` 显示 `clipname` 库存。
- 副武器未配置时应回到普通 `长枪` 帧；若采用直接补长枪帧的方案，则隐藏 `text2` 并清理 `子弹数_2 / 弹夹数_2` 的逻辑值，避免沿用上一次双枪残值。

### 4.2 不建议复用部分

Flash CS6 / XFL 是低语料、高隐性状态的资产栈，第一版不建议由 agent 直接施工主 FLA 或手动改 SWF。推荐采用：

- 来源对象：战技控件相关层复制 / 延展 `长枪` 帧；弹药双行相关层复制 `双枪` 帧的 `text1`、`text2`、双行图标 / 背景与 `通用透明组件`。

- 行为要求：`长枪副武器` 帧每帧更新 `子弹数_2 / 弹夹数_2`；普通 `长枪` 帧不出现第二行残值。
- AS2 接口：`刷新(攻击模式)` 或后续适配器能根据 `hasLongGunSubWeapon` 跳到 `长枪副武器`。
- 验收截图 / 操作：普通长枪、长枪副武器、双枪三种模式各截一张图，确认第二行显示与隐藏。

人类负责：

- 在 Flash CS6 中完成帧、元件、层级、实例名与必要时间轴脚本施工。
- 保存 XFL / FLA，并按需要导出 UI SWF。
- 记录是否触碰主 FLA、是否新增 linkage、是否移动共享元件。

- 按 Flash 三层目标选择验证层；涉及主时间轴 / UI 资产刷新时不能把 `.as` 编译等同于完成。
- 结合 TestLoader / 手测矩阵确认普通长枪无第二行、长枪副武器有第二行、双枪旧 UI 不回归。

这个流程可以作为本次资产施工的默认治理方式：agent 不直接改 FLA / SWF；若未来要让 agent 直接编辑 XFL XML，必须先有小范围可回滚 diff 和独立验收步骤。

### Phase A：Flash 资产前置施工与验收

目标：先处理低语料、高不确定性的 Flash 资产施工，让后续 AS2 / 数据 / tooltip 施工尽量连续。

推荐顺序：**先做 Phase A，再进入 AS2 / 数据 / tooltip 施工**。Phase A 不改变运行时逻辑，只准备并验收 UI 承载能力。

人类施工单：`docs/长枪副武器重构-PhaseA-Flash资产施工单-2026-07-05.md`。

agent 先产出施工包：

- 明确目标：`flashswf/UI/玩家信息界面/玩家信息界面.xfl` 与 `LIBRARY/sprite/玩家必要信息界面.xml`。
- 明确方案：第一版新增 `长枪副武器` 帧标签，追加在 `双枪` 后，建议 index 37、duration 5，而不是直接污染普通 `长枪` 帧。
- 明确来源：战技控件相关层复制 / 延展 `长枪` 帧；弹药双行相关层复制 `双枪` 帧的 `text1/text2 + 通用透明组件 + 双行图标 / 背景` 成套结构。
- 明确实例 / 层级要求：`text1`、`text2`、背景 / 遮罩、驱动组件实例名稳定；不新增不必要 linkage；不改双枪帧现有行为；不要只复制 `text2`。

## 6. 平衡与游戏性评估

推荐规则：

- 双枪：牺牲主动战技，获得双手火力。
- 长枪副武器：牺牲普通长枪主动战技，获得 K 副武器与独立装填。
- 普通长枪：保留 F 主动战技。

优点：

- 玩家构筑选择更清楚：爆发技能 vs 挂载火力。
- F 不再同时承担“主动战技”和“榴弹发射”两套语义。
- K 在长枪模式下从闲置输入变成副武器输入，手感自然。
- 下挂插件从“给武器塞一个战技”升级为“给武器加一套副武器系统”，更符合插件主题。
- 副武器倍率成为系统内建乘区后，`冲击连携` 这类被动和单把宿主武器的平衡调参都能走同一条数据链；以后可以用 `subweaponPowerMultiplier` 精调“主枪强但下挂弱”或“主枪弱但下挂强”的构筑差异。

需要警惕：

- 下挂冲锋枪 / 霰弹枪若 K 连发过强，会压过主武器节奏。
- F 装填若没有动画或冷却反馈，会显得像无代价瞬发补弹。
- 副武器使用主枪口位置会在视觉上不够准确，后续可能需要下挂 muzzle 资源点。

## 7. 工程风险

### 7.1 命名风险

现有代码里“副武器”已经被多处用于不同含义：

- 双枪副手：`副手射击中`、`secondaryParams`
- 榴弹战技字段：`副武器子弹威力`
- 资源路径中的“副武器”多指手枪类素材

建议新命名使用：

```text
长枪副武器 / longGunSubWeapon
```

避免只写 `secondaryWeapon`。

### 7.2 与 `WeaponSkill` 事件冲突

旧主动战技释放后会 publish `WeaponSkill`。很多装备生命周期脚本订阅该事件。

长枪副武器发射不应发布 `WeaponSkill`，否则会误触发普通战技联动。

如需事件，使用新事件：

```text
LongGunSubWeaponFire
LongGunSubWeaponReload
```

### 7.3 与双枪 UI 残值冲突

如果长枪无副武器，第二弹药栏必须清空或隐藏。否则从双枪切回长枪时可能残留 `子弹数_2 / 弹夹数_2`。

结合 `flashswf/UI/玩家信息界面/LIBRARY/sprite/玩家必要信息界面.xml` 的实际实现，纯逻辑层控制 `text2` 不成立：`text2` 和驱动它的 `通用透明组件` 只在 `双枪` 帧存在，普通 `长枪` 帧没有该对象。

推荐规则：

```text
攻击模式 == 双枪:
  gotoAndStop("双枪")
  子弹数_2 / 弹夹数_2 = 副手手枪弹药

攻击模式 == 长枪 && hasLongGunSubWeapon:
  gotoAndStop("长枪副武器")  // 新增 XFL 帧，包含 text2 与驱动组件
  子弹数_2 / 弹夹数_2 = 长枪副武器已装填 / 副武器弹药库存

攻击模式 == 长枪 && !hasLongGunSubWeapon:
  gotoAndStop("长枪")
  子弹数_2 / 弹夹数_2 = undefined

其他情况:
  gotoAndStop(攻击模式)
  子弹数_2 / 弹夹数_2 = undefined
```

原因：

- `text2` 每帧都会拼接 `_parent.子弹数_2 + " / " + _parent.弹夹数_2`。
- 现有 `ReloadManager.updateAmmoDisplay()` 在非 `攻击模式 === "双枪"` 分支只更新 `子弹数 / 弹夹数`，不会主动清理第二行。
- 若只在双枪分支写第二行，切回普通长枪时第二行会保留旧值。
- 若只把 `子弹数_2 / 弹夹数_2` 设为空字符串，`text2` 仍会显示固定分隔符 ` / `。
- 若只写 `ui.text2._visible`，普通长枪帧上可能没有 `text2` 实例，长枪副武器第二行也不会显示。

注意：如果只把两个字段设为 `0`，界面会显示 `0 / 0`，这更像“有第二武器但无弹药”。无副武器场景应回到不含第二行的普通帧。

### 7.4 与配件冲突规则

当前 `TagManager` 把插件 `skill` 视为主动战技，若宿主已有 `itemData.skill` 则返回 `-4`。

完整重构后需要明确：

- 普通 `skill` 与 `subweapon` 是否同属特殊槽。
- 推荐同属特殊槽，仍互斥。
- 但错误文案应从“配件无法覆盖装备原本的主动战技”调整为“特殊槽冲突：主动战技与副武器不能并存”。

### 7.5 存档与装备 value

如果副武器装填状态需要跨场景保留，应明确落在：

- `长枪.value.subWeaponLoaded`
- 或运行时临时字段，切场景重置

推荐先作为运行时字段，不跨关卡持久化；等手感确认后再决定是否写入装备 value。

## 9. 待拍板问题

1. **F 是否作为副武器装填键？**  
   推荐：是，但它是手动快装入口，不取代 R 主换弹联动补弹。第一版采用 `isSubweaponControl=true` 的副武器控制槽驱动现有战技控制器，再由 `释放主动战技()` 顶部旁路转调快装；成功快装不发布 `WeaponSkill`。实现上必须新增专用控制槽装载器，或改造 `装载主动战技()` 使其保留 marker 并绕过普通战技函数表门禁。

2. **副武器装填状态是否跨场景保留？**  
   推荐：第一版不保留，切场景 / 换枪重置，降低存档风险。

3. **旧宿主自带下挂是否迁移为 `subweapon`？**  
   结论：已迁移。active 宿主长枪不再通过普通 `skill` 表达副武器。

4. **副武器是否能与普通长枪战技并存？**  
   推荐：不能并存。它是双枪无战技设计在长枪副武器上的延伸。

5. **副武器是否需要专用 muzzle 点？**  
   推荐：第一版复用主枪口 + 偏移；后续由装备生命周期或 dressup 元数据扩展。

6. **副武器倍率是否作为核心内建乘区？**  
   推荐：是。旧 `冲击连携` 已经会提升霰弹枪下挂伤害，迁移后应由 `LongGunSubWeaponCore.calculatePower()` 统一处理；宿主长枪可额外配置 `subweaponPowerMultiplier` 作为平衡性扳手。

7. **R 主换弹是否仍顺带补满副武器？**  
   推荐：是。玩家已习惯旧设计，且当前 `ReloadManager.reloadMagazine()` 已在普通换弹完成时尝试联动副武器；重构后保留这个心智模型，并扩展为“主武器满弹时 R 可候补装填副武器”。当前正式采用 `onReloadCommit`，副武器弹药不足不能取消主武器换弹，也不能凭空填仓。

8. **副武器手动装填是否复用长枪换弹资产并高速播放？**  
   推荐：是。第一版复用长枪 `换弹匣` 资产，设置 `manualReloadBurden` 等高加速参数作为补偿；提交点走副武器装填逻辑，不走主武器弹匣提交。

9. **长枪副武器第二弹药行是否需要 XFL 施工？**  
   推荐：需要。`text2` 只存在于双枪帧，普通长枪帧上逻辑层拿不到稳定对象；第一版新增 `长枪副武器` 帧并按 XFL 治理流程验证。

   结论：需要，且已接入。当前由 `TooltipTextBuilder.buildSubweaponInfo()`、`TooltipComposer`、`ModStatBuilder`、`ModsBlockBuilder` 共同处理；后续可再拆独立 builder。

11. **Flash 资产是否由 agent 直接施工？**  
   推荐：第一版不直接施工主 FLA / SWF。采用 agent 给出精确施工方案、人类在 Flash CS6 中施工、agent 做 XFL diff / linkage / smoke 验收的流程；只有小范围 XFL XML 改动且可回滚时，才考虑 agent 直接编辑。

12. **K 是按住连发还是按下沿触发？**  
   推荐：按住按 `cd` 连发。状态机本来逐帧检查 `动作B`，副武器核心必须用 `nextFireTime` 自行节流；K 发射冷却不默认驱动 F 战技进度条。

13. **默认组消耗的扣弹时机怎么处理？**  
   结论：当前正式迁移数据使用 `consumeTiming=onReloadCommit`。若单件副武器未来改为 `linkedFirstFire`，必须作为延迟扣弹行为单独配置和测试。

14. **数据 fixture 是否只覆盖下挂插件？**  
   推荐：不能。必须同时覆盖插件下挂和宿主自带 `subweapon`，尤其是 `暴君收割机`、`众神之力`、`HK416战术版`、`非规格步枪`。

15. **是否先做人类 Flash 资产施工与 agent 验收？**  
   推荐：是。先用 Phase A 完成 `长枪副武器` 帧和第二行对象的静态资产验收，再进入 Phase 1 逻辑施工。这样把 CS6 / XFL 往返从 AS2 连续施工中剥离出来；动态切帧和真实弹药刷新仍在 Phase 1 验证。

### 已接入：F 快装动画

目标：F 不再瞬时填仓，而是复用长枪 `换弹匣` 资产做高速副武器快装；提交点只调用副武器装填逻辑，不触碰主武器 `reloadMagazine()`。

实现：

1. `LongGunSubWeaponCore.canReloadManual(unit)` 负责预检：有副武器、长枪模式、未满仓、未换弹、备弹满足最低提交需求。
2. `LongGunSubWeaponCore.startManualReloadAnimation(unit)` 清理射击任务，设置 `unit.man.subweaponManualReload = true`、`unit.man.换弹标签 = true`，并 `gotoAndPlay("换弹匣")`。
3. `ReloadManager.initReloadBurden()` 识别 `target.subweaponManualReload`，跳过主武器 tube / 弹匣计算，使用 `config.manualReloadBurden` 覆盖 `reloadBurden`；当前默认 `25`，下限 `20`。若识别 `target.subweaponLinkedReload`，则在主武器负担基础上追加副武器负担。
4. `ReloadManager.reloadMagazine()` 顶部识别 `subweaponManualReload`，改调 `LongGunSubWeaponCore.reloadManual(parentRef)`，刷新 UI，不重置主武器 `shot`，不消耗主武器弹匣。
5. `ReloadManager.finishReload()` 清理 `subweaponManualReload`、`reloadBurden` 覆盖与帧率控制临时字段，避免污染下一次普通 R 换弹。

验证重点：

- F 启动动画，动画提交帧才填满副武器并扣备弹；主武器子弹 / 弹匣不变。
- F 快装中 K / A 射击被 `换弹标签` 阻止；结束后恢复。
- R 普通换弹仍走主武器 `reloadMagazine()`，并继续联动副武器补弹；主武器满弹但副武器不满时，R 作为副武器候补快装入口。
- 副武器备弹不足时 F 不进入动画或动画提交失败后不填仓；普通 R 主换弹不被副武器失败回滚，副武器也不凭空补仓。
- `manualReloadBurden=20/25/50/100` 至少覆盖一轮，确认不跳过 `换弹匣()` 和 `结束换弹()` 帧脚本。
