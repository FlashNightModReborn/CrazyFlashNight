# 统合61式装甲套装设计与实现

统合61号工程·全装型是地面61装甲恢复完整系统后的五件套。它以40级三加权面板、重型结构和固定集成设备支持重火力轮换；普通成套约45级、星座授权约50级是实战标定目标，不由公式分数或专项测试直接认定。

初轮授权为实现、素材接入和 Flash 验证；2026-10-25 维护者随后确认五件文案与胸甲缓冲／泄放叙述，并授权连同 Issue 166–171 修复提交推送及正式 runtime 发布。实际发布阶段与证据见[本批发布记录](reports/统合61与现场修复-正式发布-2026-10-25.md)。与 Issue 166–171 修复会话串行使用同一 CS6，保留其 StateTransition、主角技能和 things0 修复。

## 装备文案

五件采用效果说明与部件背景分段，分别叙述感知、动力与缓冲、负重支撑、行军维修和操纵。胸炮集中在胸甲：护盾缓冲单元平抑供能波动，电热炮定向泄放峰值工况下的富余能量，两者协作维持地面型动力系统在极端工况下的稳定。地面型未完成建线和列装的历史保留，工程解释不新增受击蓄能、自动开炮或过热惩罚。

文案维护源为 [copy.json](../tools/unified61-assets/copy.json)，通过 `sync_copy.py` 精确同步五件 description 及套装说明。精确数值按部件分布，并在套装效果集中保留；胸甲原喷气背包、全部运行数值和事件触发规则保持原值。文案更新只需数据重载，不据此重编 SWF。

## 装备与成本

五件物品为统合61式头部装甲、胸甲、腿甲、手甲和装甲鞋，套装标识为 `unified_type_61_armor`。运行属性、生命周期和限制以[防具 XML](../data/items/防具_40+级.xml)为准；五件门控与星座名单以[套装表](../data/items/item_sets.xml)为准。

首版总重90kg，整套常驻抵消12kg负重。重量参与现行防具预算，也是移动与操作效率的代价；白板预算接近45级钛合金61不等于综合操作效率相同。五件各保留一个等级校正插件槽，内置电力结构，只允许电脑芯片或成长的勋章；强化辅材、未知新挂点与无挂点插件也拒绝。已有禁用规则的21件战术版武器采用同一限制；Origin12、AA12、Vepr12三把原先开放改装的战术版和零槽KING专用品保持原状。

白名单同时用于候选筛选与实际安装判定；本轮不自动拆除历史已安装插件，也不修改真实存档或库存。

三层预算分别来自合成、配方K点成本与高价，不再追加40级浮动或插件限制层。每件首版配方消耗对应旧61一件、高耐力橡胶两份、传感器两份、60000金币及5400K点；头部另需红外夜视仪一件。输出标价170000。配方在[进阶防具](../data/crafting/进阶防具.json)，强化继承完全沿既有铁匠与合成规则，不另造存档写入路径。

防具 plan 记录获取依据，由现有公式生成 audit 和物品 `<balance>`。K点配方使用 `acquisition.kpoint-cost`，证据绑定准确的 `recipeId`，读取 `kprice`，不把金币字段当作K点，也不虚构商店售卖。

## 五件共享系统

只有五件齐备并完成通用 `SetEffectController` 的组件事务后，才启用共享逻辑。初始化失败或拆去任意组件会撤回本套护盾、Buff、事件与夜视注册。胸甲是唯一维护周期；原喷气背包保留为胸甲的独立能力。

共享运行态为 [UnifiedType61Runtime](../scripts/类定义/org/flashNight/arki/unit/UnitComponent/Initializer/UnifiedType61Runtime.as)，[装备帧脚本](../scripts/逻辑/装备函数/统合61套装.as)只注册同步入口，持久回调留在 class。

属性修正由两个 `MetaBuff` 持有的真实 `PodBuff` 结算，HUD显示为「全装助力」「缓冲护盾」，详情读取实际注入数值；破盾时防护状态与抗性详情同步下线。冷绑定与即时添加统一排除独立数值Pod，避免偶发一排匿名状态、重新绑定后又全部消失。护盾容量、胸炮与整备仍由共享运行态和既有护盾/装填系统管理；HUD读取不推进这些状态。

夜视不随破盾或MP不足关闭，也不提供额外扫描、锁定或敌方躲闪削弱。现有夜间金币/经验倍率规则继续由天气系统裁决；夜视不能当作完全没有环境收益与经济关联的装饰。

## 轻盾与叠盾

未破盾时，受击后等待1秒无伤，再按每秒100%本盾上限回充。破盾后的5／3秒是固定重建时间，不会被继续掉血反复推迟。该盾独立于MP，不治疗已经损失的HP。

属性防护覆盖基础、热、冷、电、波、蚀、毒。运行态按稳定基础抗性补足25／45，不降低原本更高的固有抗性；再与满级能量盾的50点增益相加，形成通常的75／95目标。种族、首领等特殊抗性不被这条规则扩写；立场抗性仍由现有护盾容器计算。

高强轻盾与大容量能量盾沿既有护盾栈结算。某一击开始时，表层强度与抗旁路资格可以让可吸收部分继续消耗内层容量；轻盾归零时立即撤销本层盾强、额外抗性和抗真伤，下一击不能借用空壳资格。20%／40%覆盖率是代表遭遇中的观测目标，并非运行时强制上限。

同图重新穿装保留受损比例、破盾时刻、无伤回充延迟与逐枪整备时刻；切换授权不补资源。新场景取得新的内存身份后可给初始满盾和就绪整备。死亡清空轻盾，复活按固定重建时间恢复，不重复赠送初始盾。

## 战技胸炮与枪械整备

成功施放战技的现役 `WeaponSkill` 事件立即补满轻盾，再播放胸炮开门与开火状态。出弹不以命中为回盾条件；没有另加统一内置冷却，保留不同星座战技自身的5／10／30秒等差异。

胸炮使用12霰弹值的纵向穿刺联弹，散射度5。基础威力为触发时通用伤害加成G的十二分之一，保留标准伤害链的再次加算，因此单段基准约13G/12。维护者明确每颗穿刺弹对单体约2段、12颗合计约24段只是平衡标定参照，随敌方碰撞箱和弹道变化，不是固定段数或硬上限。若实际发生24个有效段，基准约26G；此前约13G的估算只适用于12个有效段假设。

水平判定已按维护者确认的范围收口：纵向穿刺在0°/180°也使用既有非水平覆盖率路径，保留7/18、旧几何与补弹节奏。修复前的77段水平样本现与相邻微小角度一致；宽目标仍可超过24段。没有把前置调查中提出的完整几何重定义纳入本轮，详见[水平方向修复与散射5验证](统合61胸炮-水平方向判定修复-2026-10-25.md)。[原调查](统合61胸炮-纵向穿刺联弹段数调查-2026-10-25.md)作为修复前证据保留。

刀槽装备光剑天秤、光斧金牛、光刀狮子或光刃摩羯即可取得授权，无须当前持刀。血色光剑天秤明确排除；以后新增常规星座从中心名单扩展，不按名字模糊匹配。

长枪、主手手枪、副手手枪各有独立12秒整备窗口。实际切入对应枪组时尝试整匣装填；满弹或弹药不足时保留就绪，成功才推进该枪时钟。普通与翻滚换弹不改变整备时钟。

装填调用 `ReloadManager.commitMagazine`，保留枪械师余弹回收、已付费弹药余额和失败回滚。长枪按现役技能装填规则处理联动下挂。不直接修改库存或生成免费弹药。

生产切枪入口新增 `attackModeChanged(unit, previousMode, actualMode)`。它在同步状态作业完成后发布，采用实际模式（手枪请求可能落到双枪），不代表新动作剪辑的 load 阶段已经结束。入口使用显式单位接收者；同模式、缺少武器、被拒绝的切换不发事件。状态作业重入时只由最终成功切换发布，消费侧还核对当前模式，防止旧事件重复驱动整备。
