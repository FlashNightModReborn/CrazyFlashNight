# Web UI 音效 · 语义语言与接入契约（2026-08-15）

状态：已冻结 v1（施工基线）。适用面：`launcher/web/` 全部普通 Web Panel（bootstrap 窗口 + overlay 窗口）。
不适用：三个小游戏（lockbox / pinalign / gobang）保留独立音色设计，只共享全局静音与 AudioContext 生命周期（见其面板 profile `custom`）。
与原生 Audio Platform v2 的关系：无关。Web UI cue 继续走 Web Audio 合成，不经过、也不等待原生桥。

## 1. 设计原则

1. **意图 ≠ 结果**。click 瞬间播放的是"用户按下了"（意图音）；写入类操作的成功/失败只能在权威响应到达后播放（结果音）。听觉含义必须可稳定学习。
2. **声明式优先，命令式兜底**。静态元素用 `data-audio-cue`；只有当结果取决于运行时判断（本地校验、异步响应）时才在代码里命令式播音。
3. **一次动作只响一声**。防双响是硬性规则（见 §5）。
4. **节制、短促、低音量**。沿用 audio.js 既有合成约束；新增音色必须同风格（Oscillator/noise + ADSR，无外部音频资产）。

## 2. 语义词典（13 个事件）

| 语义事件 | 类别 | 含义 | 合成实现 |
|---|---|---|---|
| `hover` | 导航 | 指针悬停 | playHover（既有） |
| `select` | 导航 | 列表项/页签被选中 | playSelect（既有） |
| `navigate` | 导航 | 视图/场景/分页切换 | playTransition（既有） |
| `open` | 导航 | 面板/弹窗打开 | playModalOpen（既有） |
| `back` | 导航 | 返回/取消/关闭 | playCancel（既有） |
| `activate` | 意图 | 按下提交类按钮（只表意图） | playConfirm（既有） |
| `toggle` | 意图 | 开关/勾选/数值微调 | playClick（既有，此前闲置） |
| `destructive` | 意图 | 破坏性动作确认（丢弃/解雇/放弃） | **playDestructive（新增）**：低频重击 + 下行扫频，警告感 |
| `illegal` | 即时反馈 | 操作被本地拦截（锁定/禁用/越界） | playError（既有） |
| `success` | 权威结果 | 权威响应成功（购买/领取/合成完成） | playSuccess（既有） |
| `rejected` | 权威结果 | 权威响应明确失败 | **playRejected（新增）**：下行双音，单次 utterance |
| `unknown` | 权威结果 | 超时/reconcile-required，结果不可知 | **playUnknown（新增）**：中性单 ping，无正负色彩 |
| `ready` | 状态 | 数据就绪/可用 | playReady（既有，2s 去抖） |

**旧 cue 名别名（永久兼容，新代码禁用旧名）**：
`confirm→activate`、`cancel→back`、`transition→navigate`、`modalOpen→open`、`error→illegal`、`click→toggle`。
`hover/select/open(新)/ready/success` 不变。别名在 `BootstrapAudio.cue()` 与 `data-audio-cue` 解析层生效。

## 3. 面板 Profile

| profile | 允许的事件 | 适用面板 |
|---|---|---|
| `standard` | 全部 | map、kshop、arena、workbench、loot、npcshop、crafting、skills、team、stage-select、hairdresser、cutscene-test |
| `quiet` | 除 `hover/activate/toggle/open` 外的全部 | help、intelligence、tasks、dressup |
| `media` | 仅 `back/illegal/rejected/unknown` | jukebox（不污染试听中的音乐） |
| `custom` | 无（公共代理与公共 cue 全面静默） | lockbox、pinalign、gobang |

- profile 归属表集中维护在 `audio.js`（单一位置，不散落到各面板文件）。
- 未登记的面板默认 `standard`。
- 抑制对声明式绑定与命令式 `cue()` 同时生效。
- 小游戏的 `custom` 不等于无声：它们用自己的引擎；全局静音收敛公式为
  `effectiveEnabled = 全局 UI 音效开启 && 小游戏本地未静音`（小游戏上线时再接，本轮不动）。

## 4. 声明式绑定与统一抑制规则

`overlay-audio-bindings.js` 保持"不做默认绑定、只对显式 `data-audio-cue` 元素播音"的定向分派。统一抑制条件（满足任一即静默）：

- `el.disabled` 或 `aria-disabled="true"`；
- 元素或祖先带 `data-busy="true"`；
- 该事件被当前面板 profile 抑制。

`data-audio-hover` 覆写规则不变。keyboard 触发与 pointer 走同一条 click 路径，天然一致，不另建通道。

## 5. 防双响规则（硬约束）

1. 同一手势：元素带了 `data-audio-cue`，其 click handler 就**不得**再命令式播意图音。
2. 本地可拒绝的动作（如加购校验）：**不要**挂声明式 cue；由 handler 按结果播 `activate` 或 `illegal`。
3. 权威结果音（`success/rejected/unknown`）永远在响应回调里播，与声明式意图音不冲突——但同一回调里已播结果音的，附带的 `Toast.add` 就不要再传 severity（§6 二选一）。
4. 已知反例（本轮修复）：kshop 加购按钮 `data-audio-cue="select"` + handler `confirm/error` 双响。

## 6. Toast 音效挂钩

`Toast.add(html, severity?)`：severity 为 `'success'` / `'error'` 时分别播 `success` / `rejected`；缺省静默（现状）。
规则：只在"该路径没有任何显式结果音"的静默路径上传 severity；已有显式 cue 的路径（如 kshop 购买）保持静默 toast，避免双响。

## 7. 全局静音偏好同步（P0）

- `sfxEnabled` / `ambientEnabled` 持久化于 Host `UserPrefs`（%LOCALAPPDATA% launcher_user_prefs.json），权威在 Host。
- Host → overlay 推送协议：`{type:'audioPrefs', sfxEnabled:bool, ambientEnabled:bool}`。
  - 时机一：overlay WebView ready 后（初始值下发）；
  - 时机二：`config_set` 成功落盘且 key 为这两个之一时（变更广播）。
- overlay 侧接收点：`overlay-audio-bindings.js` 内 `Bridge.on('audioPrefs', ...)` → `setSfxEnabled/setAmbientEnabled`。
- bootstrap 窗口路径（`list_resp` + about.js）不变。

## 8. 命令式 API（audio.js 新增）

- `BootstrapAudio.cue(name)`：语义入口，接受新旧名（别名归一），受 profile 抑制。面板代码一律用它，不再各自复制 `playCue` 帮助函数。
- `BootstrapAudio.playDestructive/playRejected/playUnknown`：三个新合成音色（风格同既有：短促、低音量、ADSR）。
- 面板归属 hook（供 Panels 生命周期调用）：`_enterPanel(id)` / `_exitPanel(id)`；profile 表 `PANEL_PROFILES`。
- 既有 `playXxx` 全部保留原签名，行为不变（bootstrap 窗口消费方零改动）。

## 9. 可测试性与验收边界

- harness 中 `BootstrapAudio` 以计数存根替代（既有模式），测试只证明**路由与语义归属**，不证明响度/音色/疲劳度——实际听感验收由人工进行，本契约不声称任何 runtime 听感结论。
- 本轮验收下限：受影响 JS 全量 `node --check`；map / bootstrap / jukebox harness 与 minigame node QA 全绿；C# 侧 `dotnet build` 通过；`node tools/validate-doc-governance.js` 通过。
