# 载具复杂度预算 · 试行 T01

2026-09-19 用户已批准落盘试行。适用配置：Flash CS6、约 20 辆、单车可见宽约 240px。数值尚未由目标端校准，其他配置应另设预算。

来源：[G07 五个原生输入／十个入口实测](../说明/载具复杂度对比.md)。批准的是施工预算与验证流程，不构成旧资产、新候选或目标 CS6 性能通过；既有美术认可及完整母件继续保留。

## 开工前登记

- 实际软件、版本、系统／位数、脚本版本与导入方式：本案目标为 Flash CS6，具体接收环境待实测登记。
- 单车显示宽度／最近观察宽度、同时存在与同时可见数量：本案约 240px、20 辆；最近观察宽度尚未另定。
- 帧率、画质、同场景其他对象与特效，以及原生打开、保存、编辑可接受耗时：由接入方实测填写，不把 30fps 或某台机器的耗时视为默认全局标准。
- 完整母件、加载文件、普通／受损状态、运行时动态入口分别列出；保存源文件与转换器哈希。

## 初始数量预算

| 指标 | 建议起点 | 触发复核 |
|---|---|---|
| 单车普通状态填色记录 | 普通载具 200–500；复杂坦克 800–1,500 | 任一代表状态超过 2,000 |
| 单车图形对象 | 与填色量一起统计，不能靠合成巨型对象规避 | 超过 2,000 |
| 单车边段命令 | 先按不超过 30,000 设计 | 超过 50,000 |
| 待导入单车文件整库的填色／对象 | 各先按不超过 10,000 设计 | 任一超过 20,000 |
| 待导入单车文件库元件 | 先按不超过 300 设计 | 超过 500 或大量单子项包装 |

表中全部为已批准试行的本配置预算值，依据原库样本量级留出复杂履带／武器的余量，而非 CS6 测出的临界容量。触发复核意味着先检查增长原因、做减量或目标端试验，再决定是否追加细节；不按数字盲删结构。低于门槛也不能跳过目标端测试。战损状态应另登记独立预算和同时显示量。

单车统计应覆盖中立、动作端点、至少一个中间姿态、轮履循环和所需战损状态；取代表状态最大值，同时登记是否还有未覆盖姿态。每次记录填色、描边、对象、边段、元件实例、渐变和遮罩。**当前 G07 仅统计初始结构，不能冒充最坏帧。**

整库统计包括文件内所有帧、未用库项和编辑用内容。若只统计静态可达依赖，必须另报整文件，并检查脚本动态创建的符号。复用可以减少独立存储，20 辆运行的实例展开量仍需另外测量。

## 绘制与动画约束

1. 在实际显示尺寸决定细节。先保轮廓、结构、层次、徽章，再安排污渍、划痕和紧固件。亚像素污点优先省略或合并，重要细长线、孔口和高对比标记可例外。动画减细节使用稳定的母件清单，避免逐帧删选导致闪烁。
2. 连续曲面先试少量渐变，平面与折边保留必要平涂。不要逐面追踪三维细碎着色，也不要把每个小面改成一个渐变。渐变域在裁剪前固定，合并前验证原绘制栈；透明层不能直接套不透明扣除规则。
3. 轮廓使用适量曲线与顶点。初次简化可从最终显示尺度 0.15–0.25px 的轮廓误差试起，并复核孔洞、薄边和交接；该值同样是试样参数。描边轮廓化、布尔裁剪前后都报告增长量，不把描边转填充当作自动减量。
4. 重复零件用共享母件与实例变换。刚性移动不逐帧复制整件；形变只更换必要区域。帧数、姿态数由可见误差与循环质量决定，不沿用前案数量。绘制顺序需要的独立组，与负责游戏控制的元件分开设计。
5. 分件保留完整可编辑实体和隐藏延伸，满足移位与战损维护。交付派生版优先裁掉各区域携带的无关整图，或复用共同几何；全套母件在源层保留。不能只挖可见窗口来省面，也不能每个小区域都携带一份完整重型总成。
6. 每次追加纹理、变体或动作，比较单姿态和整库增长。超过本轮预算先处理增长来源。历史试稿和非加载参考保留在源档案，单车交接文件按实际依赖组织，不把全工作室塞进一次包。

## 阶段验证

| 阶段 | 必须回答的问题 | 保存的证据 |
|---|---|---|
| 代表性结构样稿 | 在目标 CS6 能否导入／打开、选择子件、进入编辑、撤销、保存重开？ | 软件环境、同一哈希、各项耗时、峰值内存与是否失去响应 |
| 材质样稿 | 240px 下必要结构是否清楚；渐变／裁剪进入原生后是否一致？ | 同尺度对照、局部结构核查、各指标增量 |
| 代表性动作样稿 | 轮履与俯仰是否导致整库膨胀；20 辆同时运动是否有余量？ | 中立／端点／中间姿态、循环、真实场景帧时间和内存，记录场景内容 |
| 完整交付 | 目标端编辑与真实运行是否仍满足前述约定？ | 当前文件哈希、保存重开、动态入口与原生／游戏各自结果 |

目标 CS6 暂不可用时，可继续必要的源图试验，但不得把 Mac Animate、浏览器静态编队或计数达标写成目标端通过。验证前不要以“已通过”为依据全面追加高成本细节。
