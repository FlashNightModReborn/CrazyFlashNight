# 荒漠灰模空间审阅

本工具把[空间草图](../../docs/荒漠区域草图空间逻辑-2026-10-02.md)转为可旋转、可定位和可导出的三维灰模。它是美术细化前的布局工具，不接入现役选关，也不改变地图解锁、进关或战斗逻辑。

## 输入与编辑归属

- [desert-spatial-draft.json](../../docs/design-data/desert-spatial-draft.json)负责唯一的地理锚点、地区范围、道路邻接、候选剖面和正式入口对应。
- [terrain.mjs](terrain.mjs)负责共用的候选高度场和三视图裁切；[routes.mjs](routes.mjs)负责贴地路面、水系审阅层与明确命名的近区细化。
- [landmarks.mjs](landmarks.mjs)负责可编辑的地形上建筑组、地标体量和场景身份；[model.mjs](model.mjs)组装以上内容并建立统一锚点。
- [civil-massing.mjs](civil-massing.mjs)与[military-massing.mjs](military-massing.mjs)分别负责民用与军事地点的功能分区；[environment.mjs](environment.mjs)从母图既有区域和道路生成稀疏环境线索。
- [viewer.mjs](viewer.mjs)与[viewer.css](viewer.css)负责审阅镜头、标签、地点选择和交互，不成为新的地理源。
- [style-study.mjs](style-study.mjs)组装区域浏览器风格样板；[terrain-study.mjs](terrain-study.mjs)负责地表色域，[landmark-study.mjs](landmark-study.mjs)负责地标材质与竖向剪影。它们可原位回切，不写回母图或灰模GLB。
- [local-detail.mjs](local-detail.mjs)、[local-ground.mjs](local-ground.mjs)与[local-roads.mjs](local-roads.mjs)只在选中地点近看时生成建筑表面细节、贴地场坪和沿原路线的窄路面；[local-navigation.mjs](local-navigation.mjs)保存相机数值书签并显示母图位置。
- [export-glb.mjs](export-glb.mjs)仅导出无贴图灰模，保留分组、局部变换和语义；不支持骨骼、实例或自定义着色器，不能作为精细资产通用导出器。

用户已经选择这份草图作为灰模起点；具体距离、道路纵坡、地标体量、水文设施和默认镜头仍可在灰模中调整。原草图文件保留，不用生成模型反向覆盖它。

## 生成与预览

在仓库根目录使用已有 Node.js；本工具使用仓库自带 Three.js r180，不安装依赖、不访问外部服务。

```powershell
chcp.com 65001 | Out-Null
node tools/desert-graybox/build.mjs
node tools/desert-graybox/build.mjs --check
node tools/desert-graybox/serve.cjs
```

服务打印本机预览网址；在浏览器或 Codex 面板打开该网址。默认使用空闲端口；需要固定端口时加 `--port=端口号`。服务只监听 `127.0.0.1`，只读取本工具、自带 Three 依赖、草图数据和灰模输出，没有写入接口。

页面直接由源码与草图构造模型，更新后刷新即可。下载的GLB来自最近一次构建，修改输入后应重新生成并执行 `--check`。派生输出放在已忽略的 `tmp/desert-graybox/`，不把大型生成物加入源码提交。

## 三个尺度与坐标

| 视图 | 主要检查内容 | 显示高程 |
|---|---|---|
| 区域总览 | 西北山系、军阀腹地、西谷、城市群与林区的远近层次 | 候选物理高程乘3.2 |
| 城市接合 | 两城、公社、总部、基地、登陆口与各类交通的接口 | 同一物理高程乘12 |
| 基地近区 | 监狱院区、东正门、西南后门、训练区及东坡 | 同一物理高程乘8 |

Three场景水平1单位为1公里，X向东、Z为地理北的负值。Y为候选物理高程的米值除以1000，再乘上表的显示夸张。三个视图的同一地点地理坐标和物理地面高程保持一致，显示高度不同。

GLB在外层统一乘1000，使用米为单位，仍保留本轮竖向夸张。`METRES_DISPLAY_HEIGHT_EXAGGERATED`和场景根节点的extras说明该口径；不能直接把导出后的坡面角度当成道路实际纵坡。

区域与城市视图的建筑体量、道路宽度可为辨识而放大；这不改变其锚点间距。基地近区用候选公里占地展开，尚非精细建筑标定。`PLACE_地点ID`保留对象组，`ANCHOR_地点ID`保留原地理坐标、高程、正式入口ID及显示夸张。

通用地标属于独立设计的符号体量，没有可逆的统一缩放倍率。监狱因复用同一总装，另记录水平占地倍率 `footprintScale` 与建筑高度倍率 `buildingHeightScale`；建筑显示高度还叠加该视图的高程夸张，不能只除以一个数字就称为真实建筑。

## 本轮灰模细化

默认预览固定为生产选关相同的1024×576逻辑画幅，页面按16:9等比显示。`composition.mjs`为三个尺度分别选择俯角、方位、主体范围与安全边距；以关卡、相关建筑和地标取景，不以整块地形底板的外框决定缩放。区域图保持A基地在画面中部，9个正式入口和雪山接驳点进入安全框；完整雪峰、林区外轮廓及无关底板可以出画。

“游戏构图”使用上述默认镜头，并显示独立的 `PRESENTATION_SURROUND` 周边地形，承接画幅边缘；“完整沙盘”和“北上俯视”隐藏该组，保留范围检查。外围没有新增地点、道路或控制区，超出已定义高度场的取样延用边界值，仅是呈现用的可编辑背景，不宣称新增地理已成立。母图坐标、距离及原有物理高度场没有因此拉伸或移动。

正式入口及雪山接驳标签先于背景标签放置；选择画外地点会自动转到其近看视角，避免只改侧栏而无法找到对象。构图安全边距不等于已验证生产标题、简报和返回按钮的实际遮挡，正式面板集成仍须另核。

基地常态车道沿训练区南缘铺设，保留正门与近郊分岔之间的连通；图1、图2、图3仍位于原草图锚点。训练场景的中心不等于车道中心。军事/返程线在近区明确图3到图2到图1的接续。这些局部折线细化由 `routes.metrics.localRefinements`记录，不暗改区域坐标。

地表河道单列为常显的 `SURFACE_WATER` 组；“水系参考线”只控制地下、失养及可选设施投影。GLB保留这些独立组供编辑，其默认隐藏意图记录在extras，但通用查看器可能仍将参考组显示出来。地面投影不证明水质、地下工程位置、流向、桥梁承载或输水能力。

本轮把地点从通用盒体进一步拆成有用途的灰模：公社有交割前场、厂区、住区、有限耕地和失养田网；两城有核心街坊、低层过渡与稀疏城缘；军阀各地点区分集结、回收维修、指挥通信、保障、转运与后期驻留。军事围界的开口按既有路网方向推导，地区锚点与实体门口分别记录。功能组使用稳定 `subareaId`，侧栏可定位近看，不生成新的游戏关卡。

环境层保留断续干渠、旧田界、山前砾地、物流分岔旁的空场，以及残垣至林缘的退化痕迹。它们引用已有 `area/route/place`，主动避开道路和建筑组；不靠新增势力或随机堆楼填空。跨水桥涵只标出从已有道路与河道交点推导的候选接口，未证明引道标高、结构承载或实际可通行。近看可以关闭符号化“交通线”，检查院落和建筑分区；基地近区的道路与坡坎原关系继续保留。

“弱透视”是在本独立预览里比较的透视镜头。生产选关当前仍按其既有正交实现运行，这里的试验不修改共用相机控制器。

## 验证与交付范围

区域总览默认打开“风格样板”，可在“表现”下拉框切回“空间灰模”，保持当前镜头比较。样板只调整地表材质、建筑显示高度与明暗：保留地理锚点、地形顶点、路网、建筑水平位置和占地；建筑竖向倍率不是新物理高度。城市接合与基地近区仍使用原灰模。样板采用单方向阴影与克制的边缘渐暗，不把荒漠改成夜景。

“四图对照”打开[比较页](compare.html)，以相同16:9画框显示实时荒漠与三张既有地图的已采用镜头留存。对照图读取本机 `tmp/map-camera-candidates-20260926/shots/` 下的 `base-overview-context.jpg`、`hq-overview-main.jpg` 和 `city-landmark-main.jpg`，来自2026-09-26镜头回合，不表示三张图今天的现役运行截图。此页依赖本机留存文件；缺失时恢复原留存或重新从真实场景截图，不用二维fallback冒充三维对照。

浏览器样板的材质、程序化地表纹理、阴影与竖向剪影不进入“下载当前尺度GLB”。导出继续提供原空间灰模；方向经目视比较确定后，再决定美术接手的展示参数，不把浏览器样板直接视作美术定稿。

总览用于辨认地域关系；点击地图标签或使用“放大地点”进入地点近看，保持原来的观察方向。近看按既有建筑表面增加门窗、厂房大门、屋顶构造、围墙分节、帐篷接缝和地基/场坪痕迹；它们是局部设计候选，不新增主建筑、单位、水源或关卡身份。总览不显示这些细节。

近看中的道路沿原中心线使用较细的显示路幅，仍属于符号宽度；原道路几何不改。“交通线”同时控制当前尺度的道路呈现。定向阴影范围围绕当前地点收紧，保证近看清晰度；回总览后恢复区域阴影范围。

局部标签沿用 `subareaId/designRole`，可进入功能分区；“地点全景”恢复进入分区前的镜头，“返回总览”恢复第一次进入近看前的实际旋转、平移、缩放与投影。前后按钮按9个正式关卡顺序浏览，雪山导航仍是独立入口；换地点不覆盖总览书签。Esc从分区返回地点，再从地点返回总览；输入控件内不拦截。位置小图始终按母图坐标、北向上显示。手动切换区域/城市/基地尺度会结束近看，不持有旧模型引用。

上述局部细节也只属于浏览器样板，不进入原灰模GLB。清理时先销毁局部模块，再销毁风格样板，最后释放原模型；局部模块不得修改或释放原模型资源。

`build.mjs`检查三层地理锚点和物理高程一致、候选剖面匹配、区域图9个有效地点齐全、顶点有限，并验证正交和弱透视下的必保内容进入16:9安全框。每个GLB再由仓库已有GLTFLoader独立读取，对比边界、三角形数、语义锚点及功能子组；`--check`比较重建结果与已有派生物，不修改输出。

`tmp/desert-graybox/manifest.json`记录输入哈希、各模型体积、几何计数与复读结果；机器可计算的数字以该文件为准。三个GLB分别命名为 `desert-region.glb`、`desert-city.glb`、`desert-base.glb`。这些是可编辑灰模，没有声称本机生成或验证Blender工程。

浏览器审阅需看正交与弱透视、三个尺度、地点定位/靠近/回全景、北上俯视、水系开关及窗口改变后的标签。模型生成和浏览器画面只能支持灰模层结论，不能代替真实WebView2/Flash选关接入、玩家体验、美术验收、车辆可通行或弹道验证。

精细建模仍由后续美术机承担。建筑造型、材质、光影、破损和生活细节在灰模体量与接口进一步确定后展开；此工具不构成正式美术冻结或发布授权。
