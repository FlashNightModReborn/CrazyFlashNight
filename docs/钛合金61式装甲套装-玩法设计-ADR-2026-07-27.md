## 0. 决策摘要

### 0.1 已决

1. 套装效果只由五件钛合金61式防具激活；四把配套武器不写入 `setId`、不参与套装件数，避免武器槽和双持P90重复计数。
2. 套装的核心身份是“以MP为统一能源的自维持战斗机甲”，不是某一兵器或枪械流派的专属增伤套。
3. 套装只管理 `AdaptiveShield` 容器中的一个具名专属层；满载、受损、破碎、重启充能均按该层判定，不把其他来源护盾合并进套装状态。专属层先以0容量注册，满血初始化在提交后的首个维护帧免费满盾；带伤初始化及战斗修复没有免费正回复；护盾在线时提供动态重算、至多抵消超重惩罚的负重伺服补偿，满盾后才允许将富余MP转换为双枪弹药。
4. 所有护盾状态都允许MP生命维持。护盾破碎后停止负重补偿与弹药合成，并按当前缺失HP提供不叠层的通用伤害加成。
5. 破盾增伤保持通用全局语义，不增加“兵器伤害”“枪械伤害”等流派标签。血剑依靠主动扣血和多段特效自然成为最适配者，枪械也可兑现短暂的低血增伤窗口。
6. 战斗破盾后，HP达到或超过常规满血值才允许支付一次启动MP进入重启，保留已有超血；重启不直接送满盾，而是从0开始渐进充能。首次正容量出现前若HP再次受损，立即退回破碎维生；本次破碎周期的启动费不退、不重复收取。
7. 钛合金P90获得武器固有的“成功发射回MP”能力，按真实 `processShot` 事件结算，不要求命中。它在套装外把弹药转换为MP，在套装内成为护盾、维生与弹药循环的发电机。
8. 套装对手枪/手枪2每次成功发射返还一发合成成本，形成基础蓝弹守恒；钛合金P90另有武器固有的额外发电。自动补弹只服务手枪/手枪2双枪位，不补M134或钛合金QJZ171。补弹由套装中央维护周期按稳定后的真实 `shot` 原子结算；换弹中、武器身份或弹容漂移时失败关闭且不扣MP。胯部黑盒和大腿黑色装甲解释为弹药材料盒、微型合成器与双通道供弹机构。
9. 五件套为主角注册现役最高级的“高级夜视仪”视觉预设；夜视不依赖护盾存量，也不因MP不足关闭。
10. 自动打药采用“应急自动注射器”定位：只作为破盾且生命危急、MP维生不足时的最后保险；不得扫描整个背包或擅自选择昂贵药剂。
11. 现有胸甲喷气背包仍是单件装备固有能力，不因五件套不足而失效。
12. 钛合金QJZ171作为55级低负载火控分支：五件装甲齐全、专属盾层在线时，以最终装备负重量兑换本枪击溃/斩杀；有效额度到-17kg封顶，分别最多0.15%和10%。它不参与套装件数，也不向其他武器提供此加成；已随S2接入P90/能源闭环，实战在线率仍待标定。
13. 系列采用太空基地舱内作战设定。负重量解释为反重力补偿后的有效负载余量，轻载火控恢复原定低重力工况性能；不把失重解释为消除惯性或后坐。

### 0.2 首期不做

- 不增加武器类型专属伤害Buff。
- 不让血剑、P90、M134或钛合金QJZ171成为套装计数成员。
- 不给M134或钛合金QJZ171自动补弹或无限弹药。
- 不做无条件被动回MP；P90发电必须消耗真实弹药并成功提交发射。
- 不做自动瞄准、自动开火、自动切枪或强制自动换弹。
- 不从背包、仓库或快捷栏之外自动搜寻并消耗药品。
- 不把高级夜视扩张为剑圣套装式扫描、躲闪Debuff或自动锁定。

### 1.3 太空基地驻防背景、供能与火控接口

钛合金61系列最初面向太空基地的低重力、失重舱段和重力方向切换环境设计。其配套武器遵循同一供能与火控标准，系列身份由机甲和枪械的协同接口体现。

**供能关系。** 机甲能源总线服务测距、传感、火控运算和稳枪执行机构。钛合金QJZ171保留独立缓冲电源，因此离开机甲仍能使用现有55级枪械性能和17%自带暴击；机匣预留的供能接口供后续接入整套系统。火药弹仍由既有机枪弹药供应，不能把供能解释为MP替代弹药或自动补充机枪弹匣。

**火控联线。** 双向链路传递机体姿态、角速度、测距和目标解算数据，让枪侧火控把机甲运动和每次击发的扰动纳入校正。低射速为逐发姿态校正和精密毁伤判定留出时间。本项目将它体现为现有暴击和§7.4待实现的条件击溃/斩杀，不借此新增自动瞄准、自动开火或改变玩家的射击方向。

**站内作战环境。** 狭窄舱道、局部失压、强反光与阴影交错，使电子舱密封、可靠传感和火线控制比单纯堆射速更重要。低压环境的散热不能依赖空气对流，武器采用导热结构和热缓冲余量，低速大口径连射也减少连续工作的热积累。该背景解释现有结构和节奏，本次不新增热量条、过热状态或独立电池消耗规则；穿甲弹依然有贯穿风险，不宣称能够保护被命中的舱壁。

**负载与预设性能。** 地面承重和额外携装占用机甲伺服及姿态补偿余量，精密火控于是工作在保守档位。游戏中的负重量视为反重力装置补偿整套载荷后剩余的有效负载额度，计量沿用kg。它不代表惯性消失；后坐与机体运动仍由稳定机构处理。负载进入负区间后，钛合金QJZ171可借助机甲在线基准场恢复结构毁伤和致命部位识别性能。

-17kg是该火控系统的预设校准上限，也是171型号的“17”彩蛋。专属盾发生器同时维持补偿基准场，所以额外火控仍要求专属层在线；继续减重只增加配装余量，不无限提高射速、暴击或百分比伤害。

物品说明已写明五甲、专属盾在线、-17kg封顶和0.15%击溃/10%斩杀上限。持用本枪时，红束透明度直接映射当前火控恢复比例，取消火控文字提示；同类效果取高。套装诊断继续提供fireControlProgress/fireControlRout/fireControlSlay，光束和本发快照共用 `getFireControlProgress()`。

## 2. 设计原则

### 2.1 机制亲和，不做标签特化

套装不写“血剑伤害提高”“P90伤害提高”或“M134伤害提高”。四把武器通过自己的机械属性占据状态机中的不同位置：

- M134最能兑现护盾在线和负重补偿；
- P90最能把弹药转换成MP，再让防具把MP分配给其他系统；
- 血剑最能主动制造并维持缺血，从通用过载增伤中获益；其-99重量也能为轻型机枪分支提供有效负载余量。
- 钛合金QJZ171以自身火控读取负重量与专属盾在线状态，只为本枪恢复百分比机制；不向套装中心追加“机枪伤害提高”一类通用标签。

这样可兼容其他武器，同时保留预定武器组合的最高机制亲和度。

### 2.2 便利性优先减少操作税，不替玩家作战

未来机甲感主要来自以下自动化：

- 自动修盾、维生、能源分配和弹药供给；
- 自动适应低光环境；
- 在明确条件下启动应急注射；
- 用清晰的声音、光效与HUD告诉玩家系统正在做什么。

不通过自动瞄准、自动开火、自动切枪或大范围拾取替玩家完成战斗和资源决策。

### 2.3 MP是能源，不只是技能蓝条

玩家心智应当稳定为：

> 钛合金61式装甲不主要依赖血包维持，而是依赖MP保持护盾、生命维持、弹药与机动系统在线。

因此蓝量见底必须是可感知、可预防的系统性风险；任何“便利功能”都不能把MP管理完全抹掉。

## 4. 护盾状态机

### 4.1 专属护盾层与首次激活

`target.shield` 是单位的共享 `AdaptiveShield` 容器；钛合金只管理其中自己的单层护盾。套装必须创建且只创建一个非临时、可精确寻址的专属层，并把层ID和引用保存在本次套装事务的共享context中：

- 固定可诊断层名为 `titanium_type_61_set_shield`；创建后立即读取 `shield.getId()`，把返回的数值层ID作为 `shieldId` 保存。名称用于初始化时扫描/拒绝同名残留层，运行期状态查询、扣伤回调、修复、重启和清理则以 `getShieldById(shieldId)` / `removeShieldById(shieldId)` 精确寻址，不得把名称和数值ID混为一谈，也不得用容器聚合容量代替。
- 以 `Shield.createRechargeable(maxCapacity, strength, 0, 0, name)` 一类接口创建，明确令 `rechargeRate=0`；免费自动回复不得与MP账本并行。
- `BaseShield` 构造后会默认处于满容量。加入容器前必须显式 `setCapacity(0)`，再以 `preserveReference=true` 注册，使context保存的引用和容器实际消费的对象一致。
- 专属层使用 `resistBypass=false`：它自身不授予抵抗真实/穿透护盾伤害的能力。共享容器若因其他层存在 `resistBypass=true` 而整体进入抗旁路路径，仍服从 `AdaptiveShield` 的现役聚合语义；不得把那项外部能力记到钛合金层名下。`strength` 同时影响单次承伤上限、姿态阻抗及多层排序，必须与最大容量一起标定并落盘，不能把它当作无关占位值。
- 其他来源护盾继续按 `AdaptiveShield` 现役排序和伤害分配工作；它们可以因先承伤而间接保护专属层，但其容量不直接改变本套装的四态、负重补偿或补弹资格。
- 套装降至4件、卸载或初始化回滚时只按ID移除本专属层，不得清空共享容器或误删其他护盾。

每次初始化仍创建新套装事务，先以0容量注册，不迁移旧盾。新单位在最终资源结算后的首个维护帧若HP≥Hmax，免费补到Smax；重初始化还须满足重建前HP≥旧Hmax，避免降低上限伪装满血。机会只检查一次，带伤初始化后自然回满不会补发。免费初始量单独记入 `initialShieldGranted`；后续受损、战斗破盾与复原继续按实际恢复量付费。

以下状态机统一使用：

- `S`：按专属层ID读取的当前容量；
- `Smax`：同一层的最大容量；
- `Hmax`：经现役统一入口取得的常规满HP；HP超出该值时不主动削减；
- `rebootStartupPaid`：仅在当前这一次破碎周期内有效的启动费凭证。

在线时固定 `strength=Smax`，不随残余容量降低；S为0时立即将该层盾强归零。残盾的实际吸收量仍不能超过S，特殊防护门槛则按固定盾强执行。

层缺失、重复层、`S/Smax` 非有限值或 `Smax <= 0` 均是结构错误，应失败关闭并进入可诊断的初始化/维护失败路径，不能退化为读取聚合护盾继续运行。

### 4.2 状态定义

| 状态 | 判定 | 启用能力 | 禁用能力 |
|---|---|---|---|
| `ONLINE_FULL` 满载 | `Smax > 0 && S == Smax` | 负重补偿、轻载火控、夜视、MP治疗、手枪基础返还/P90额外发电、富余MP双枪补弹 | 修盾 |
| `ONLINE_DAMAGED` 受损 | `0 < S < Smax` | 负重补偿、轻载火控、夜视、MP治疗、手枪基础返还/P90额外发电、MP修盾 | 双枪补弹 |
| `BREACHED` 破碎 | `S == 0`，且HP未满或尚未取得启动费凭证 | 夜视、手枪基础返还/P90额外发电、MP维生、缺血通用增伤 | 负重补偿、轻载火控、修盾、双枪补弹 |
| `REBOOTING` 重启 | `S == 0 && HP >= Hmax && rebootStartupPaid` | 夜视、手枪基础返还/P90额外发电、MP充盾 | 双枪补弹；负重补偿与轻载火控在专属层真正大于0后恢复 |

### 4.3 状态转换

```text
ONLINE_FULL
  └─ 专属层受损 → ONLINE_DAMAGED

ONLINE_DAMAGED
  ├─ MP修复至满 → ONLINE_FULL
  └─ 专属层归零 → BREACHED，并重置 rebootStartupPaid=false

BREACHED
  ├─ HP未满 → MP维生 + 缺血通用增伤
  ├─ HP已满但启动MP不足 → 保持BREACHED，不扣费
  └─ HP回满且一次性支付启动MP → REBOOTING，并置 rebootStartupPaid=true

REBOOTING
  ├─ 首次获得正容量前HP受损 → BREACHED，保留本破碎周期的启动费凭证
  ├─ HP再次回满且凭证仍有效 → REBOOTING，不重复收费
  ├─ 首次充能后 0 < S < Smax → ONLINE_DAMAGED，并清除启动费凭证
  └─ 首次充能后 S == Smax → ONLINE_FULL，并清除启动费凭证
```

启动费是发生器在当前破碎周期内的启动成本，不是可退款押金：`REBOOTING` 被受伤打断时不退款，同一破碎周期内也不重复收取。专属层第一次获得正容量后，本次凭证即消费完毕；以后再次归零会开启新的破碎周期并重新收费。套装卸载/回滚也必须清除凭证，不能把它带入下一次激活。

### 4.4 护盾修复

- 专属层未破时，从当前值继续填充；不得用其他护盾层的容量抵消其缺口。
- 每次维护脉冲只按“实际增加的护盾值”扣MP，不能按请求值收费，也不能在满盾时继续扣费。
- 战斗修复不使用免费正回复，实际恢复量进入MP账本；满血初始化的免费量单独记账。
- 护盾受损时关闭弹药合成，防止修盾和补弹同时争抢能源。

### 4.5 全状态生命维持与破盾增伤

专属层归零事件只进入一次 `BREACHED`，不得因周期检查重复发布破盾、重复创建Buff、重复重置启动费凭证或重复启动定时器。其他护盾层归零不触发本套装破盾。

所有护盾状态的每个维护脉冲：

1. 若HP未满，按“基础值 + 缺失HP比例”计算候选治疗量；
2. 按实际恢复HP扣MP，并由统一封顶入口保证最终可以精确到达满HP；
3. 仅在专属层为0时，按治疗后的缺血量覆盖通用伤害加成；在线时这一来源为0；
4. MP不足时只结算实际可支付部分，不产生负MP或免费治疗。

缺血增伤是一个由当前状态派生的单一Buff：

- 不叠层；
- 不快照保存历史最高值；
- 当前为 `五甲实际通用伤害 × 3 × clamp(缺血/Hmax,0,1)^1.5`；
- 血剑本体、血剑特效、P90和M134均可吃到现役通用伤害加成；
- 专属层重新获得正容量后立即清除。

### 4.6 护盾重建

- HP达到或超过常规满血值即可；治疗不削超血，最后一点HP也可精确付费恢复。
- 满HP只授予“允许尝试重启”，不直接授予满盾或正容量。
- 重启按§4.3在每次破碎周期收一次固定启动MP；随后仍按专属层实际增加量逐步收费。
- 启动费已付但可用于充能的MP不足时，保持 `REBOOTING/S=0`；P90仍可发电，下一维护脉冲再按实际可支付量充能。
- 默认不额外要求“连续无伤若干秒”；是否增加稳定窗口保留为实战调参项。
- 战斗破盾重启使用真实0容量，不能塞免费1点技术种子；满血初始化的免费满盾仅按§4.1的一次性资格发放。

### 4.7 负重补偿的Buff语义

负重补偿不能落成一个固定的 `MULT_POSITIVE=1.33`：

- `MULT_POSITIVE` 对同一属性采用取最大值，而不是叠加；若剑圣鞋等外部速度增益更强，钛合金补偿会被正常覆盖，不能把两者相乘理解为套装额外加速。
- `MULT_POSITIVE` 本身不能表达“最终速度不超过正常负重速度”。“封顶到正常速度”必须体现在钛合金这一来源每次写入的补偿值上。
- `DressupInitializer.updateWeightAndSpeed` 会按当前重量和等级重写 `行走X速度` 基值。套装应创建一个具名单一Pod，使用 `UnitUtil.getWeightSpeedRatio(重量, 等级)` 计算当前惩罚，并通过 `BuffManager.setPodBuffValue` 原位更新；换装、等级变化、护盾上下线或基值重写后都要重新计算。
- 补偿来源的建议倍率为 `weightSpeedRatio < 1 ? 1 / weightSpeedRatio : 1`，并对异常零值作防御。这个倍率只把超重后的基值恢复到重量系数1，不能截断其他合法速度Buff。
- `行走X速度` 还会经 `SkillDamageCore.speedToDamage` 进入瞬步斩及多处刀口子弹威力。恢复超重损失会同步恢复这部分速度转伤害；因为钛合金来源只补到正常负重速度，这个副作用也随之封顶，属于已接受的通用消费链，不另造兵器专属加成。

验收时必须覆盖“只有钛合金补偿”“补偿与更强 `MULT_POSITIVE` 并存”“换装改变重量后动态重算”三种场景，不能只看满配463重量下的单个常数。

## 5. 能源优先级与守恒

### 5.1 固定优先级

```text
生命维持 > 护盾重启/修复 > 双枪弹药合成
```

高级夜视和状态诊断不参与持续MP竞争，避免黑暗环境下因能源枯竭进一步失去可读性。

### 5.2 MP储备线

弹药合成只能消费储备线以上的MP：

```text
ammoSpendableMP = max(0, currentMP - ammoReserveFloor)
```

当前首期参数为 `ammoReserveFloor=50%×最大MP`，仅限制补弹；治疗和重启可花到0。玩家需要主动为战技与位移管理蓝量。

该约束保证：

- 低MP时，P90消耗现有弹药恢复能源，不被补弹器立即抽回；
- 到达储备线后，新发射产生的富余MP可以维护后续弹药；
- 护盾或HP需要能源时，弹药系统自动失去优先级；
- 玩家不会因为自动补弹而失去最后一段保命蓝量。

## 6. 钛合金P90：发射发电

### 6.1 触发语义

`processShot` 是事件名，不是 `WeaponFireCore` 的方法名。`WeaponFireCore.executeShot` 在弹药检查与 `commitGuard` 通过后发布该事件；默认订阅者 `FireEventComponent.processShot` 在同一次 `publish` 期间执行 `shot++`。钛合金P90按这次成功发布的发射事件恢复MP：

- 空弹匣、发射提交失败不触发；
- 不要求命中目标；
- 不按穿刺命中数量重复结算；
- 单枪每次事件结算一次，双枪各自发射各结算一次；
- 满MP时只恢复实际缺口，不保存溢出电量。

发电回调不得假定自己运行时 `shot++` 已经完成。订阅顺序不是本机制的契约；回MP只使用事件参数与自身槽位身份，弹药合成留到套装维护周期读取稳定后的真实 `shot`。

“对空气射击也能发电”是明确装备能力，不视为隐藏漏洞。套装外仍需消耗真实冲锋枪弹药，因此本质是弹药到MP的转换。

### 6.2 基础蓝弹守恒与P90额外发电

维护者于2026-09-08确认：`C=3MP/发`同时作为五甲基础发射返还和手枪补弹成本；钛合金P90武器固有额外发电`G=3MP/发`。

| 配置 | 成功发射返还 | 满盾合成成本 | 发射并补回一发的净MP |
|---|---:|---:|---:|
| 五甲＋普通手枪 | C=3 | C=3 | 0 |
| 五甲＋钛合金P90 | C+G=6 | C=3 | +3 |
| 无五甲＋钛合金P90 | G=3 | 无套装合成 | +3，但真实消耗弹药 |

基础返还不依赖盾在线；护盾/治疗会优先消耗这份能源，因此“守恒”只描述发射—合成这两个操作。满MP时按实际缺口恢复，溢出不保留。满盾、储备以上且射速不超过每槽每脉冲3发时可以持续合成；受损/破盾时停止合成，弹药真实减少。

### 6.3 首期供能参数

P90静态间隔90ms、弹容50。仅计算额外G，双持理想弹匣内约66.7MP/s，按原工作簿计换弹约48MP/s；30FPS的实际发射调度、手动换弹及满MP截断仍需实机标定。五甲的基础C不是另一份净发电收益。

原先把P90总回蓝直接设为G≈C的候选已被替代；“50%储备线导致永远回不到65%”仅是旧候选反例，不能用于当前额外发电构筑。

### 6.4 运行时边界

- 共用 `P90初始化` 已读取 `initParam.extraMpPerShot`，仅钛合金P90写入3。普通P90与印花集不获得武器额外发电；既有视觉/弹匣同步继续使用原入口。
- `P90战术版` 虽然已有 `<bulletRate>2</bulletRate>`，但现役初始化不消费它，`MagazineFrameSync.init` 仍按实际弹容重算 `ref.bulletRate`；该死配置不能作为“P90参数链已经生效”的先例。
- `EquipmentFireIntent.isPistolSlotProcessShot` 校验owner、手枪槽、当前攻击模式、真实武器实例与发射身份。`processShot`第五参为提交时武器实例；既有四参订阅者可忽略新增参数。P90还校验装备版本、名称及原dispatcher。
- 开火回MP与弹药合成不在同一个事件回调里互相改写。开火事件只记账MP，套装维护周期再根据真实 `shot` 与MP储备处理弹药，避免订阅顺序影响结果。
- MP恢复使用统一封顶入口。
- P90发电监听归武器生命周期所有，而非五件套事务所有：套装失效后它仍应在套装外工作，套装回滚不得退订它。
- 固有发电使用具名回调，精确 `unsubscribe` 登记在装备的 `生命周期函数列表`。套装回滚只释放基础返还监听；普通装备卸载即使保留dispatcher也能取消固有发电，不借用套装resourceStack。
- 该固有机制属于武器效果层，不能硬塞进 `dualWield/pierce/shotgun` 等公式输入；量化前按武器规则表的特殊机制边界记录。

### 6.5 补弹原子结算与换弹并发

现役枪械用 `shot` 表示当前弹匣已经消耗的发数，因此套装“合成 `n` 发”应把 `shot` 精确减少 `n`，而不是增加弹容或伪造一次换弹。补弹只能由套装中央维护任务调用同步helper完成；`processShot` 回调不得直接改弹药。

每个维护脉冲按以下顺序处理：

1. 只枚举 `手枪`、`手枪2` 两个槽。优先处理缺弹数（`shot`）较大的槽；相同则固定 `手枪` 在前，保证双通道分配可复现。
2. 从槽位重新解析当前武器实例、装备名、弹容、`shot` 和权威换弹状态/代次。武器缺失、不是允许补弹的目标、正在换弹或换弹已进入提交区、弹容/`shot` 非有限整数、`capacity <= 0`、`shot < 0` 或 `shot > capacity` 时跳过该槽且不扣MP。
3. 计算 `availableMP = max(0, currentMP - reserveFloor)`、`affordable = floor(availableMP / C)`，再取 `n = min(shot, affordable, ammoSynthesisMaxPerPulse)`。`C` 必须是有限正数，单脉冲上限必须是有限正整数；参数非法时整个补弹功能失败关闭，不能退化为免费弹药。
4. 提交前再次读取并比对武器实例/装备名、弹容、`shot`、换弹状态/代次与当前MP。任何身份、容量、弹数或换弹代次漂移都放弃本槽本脉冲，不收费，也不沿用旧快照重算到另一把武器。
5. 在同一同步调用栈、没有中间事件发布的临界段内，以第二次读取值重新计算最终 `n`，提交 `MP -= n * C` 与 `shot -= n`。实际MP扣除量和实际 `shot` 减少量必须严格满足 `mpDelta == n*C`、`shotDelta == -n`，且提交后MP不低于储备线、`shot` 不低于0。
6. 资源提交完成后再走现役、带槽位身份的 `updateBullet`/弹匣视觉同步入口刷新HUD；不得触发换弹、不得修改备用弹药库存，也不得把UI回调失败误判为“弹药未生成”而再次收费。UI失败应诊断并在下一次正常刷新中收敛。

AS2虽然是单线程事件循环，换弹、开火和维护任务仍可能在同一帧按不同回调顺序运行，所以不能只靠“不会多线程”省略两次校验。手动换弹已经开始时本脉冲跳过；若换弹先完成，维护任务读取完成后的真实 `shot`；若开火先完成，维护任务读取包含该次发射的真实 `shot`。维护任务提交后才发生的开火留给下一脉冲处理。禁止通过补弹回退或补偿任何已经由手动换弹消费的库存。

## 7. 四把武器的最终定位

### 7.1 M134暴力版：堡垒弹幕

- 依靠护盾在线时的负重伺服维持可操作性；
- 使用1800弹容和最高持续火力完成正面压制；
- 不参与套装自动补弹；
- 护盾受损后，修盾会抢占MP，使其持续安全窗口开始缩短；
- 护盾破碎后失去负重补偿，提示玩家M134平台已经失稳。

### 7.2 钛合金P90：能源与割草

- 对低压敌人时护盾长期满载，富余MP与弹药合成形成持续扫射；
- MP不足时主动消耗现有弹药发电；
- 护盾受损时可边射击边为修盾提供能源；
- 破盾时可作为远程恢复手段，帮助生命维持而不是继续扩大HP风险；
- 套装外仍是公式层级正常、带弹药换MP功能的工具型短枪。

### 7.3 血色光剑天秤：低血过载

- 主动扣血产生额外输出，缺血又提高通用伤害，构成受控正反馈；
- 继续攻击会增加维生MP负担，并推迟HP回满和护盾重建；
- 停止自损则让生命维持逐步结束过载，回到护盾循环；
- 可以持剑制造低血后切枪兑现短暂全局增伤，这是鼓励近远程混用的合法技巧；
- 增伤实时依赖当前缺失HP，不能通过切枪保留历史最高快照。

#### 资产脚本迁移裁决

2026-09-08已将这项迁移作为独立施工接入R04美术，见[迁移记录](血色光剑天秤-R04材质与装备脚本迁移-2026-09-08.md)。现役物品指向Codex新版元件，行为权威为`血色光剑天秤.as`；新版不携带旧影片剪辑的扣血与子弹脚本。旧things切割源保留为溯源和回退材料，禁止让新旧战斗路径同时运行。

每个攻击帧仍有两路独立五择一：刀口3扣3HP并生成999威力血爆，刀口2扣1HP并生成100威力血滴。结算按装备ref统一执行，多个可视实例不重复扣血；实际触发后驱动本剑爆发，短时间触发仅合并视觉。三个刀口及原伤害/代价字段保持原约定。

S3继续从这份新脚本和真实攻击动作标定自损/秒、附加弹频率与特效伤害。R04接入不实现S1/S2的护盾、能源或缺血增伤；原生素材测试也不代替整套构筑的实机曲线标定。

### 7.4 钛合金QJZ171：低负载火控恢复（随套装共同施工）

#### 已有基础与待实现部分

基础物品已按55级、四层静态DPS预算落盘，威力2345、重量20kg、270ms、60发、impact=2、自带17%概率1.5倍暴击，继续使用已验收的10帧射击动画。这些字段不依赖套装；武器不带 `setId`。物品不写无条件击溃/斩杀字段；S2在五甲、专属盾和本枪发射条件成立时投影到当次子弹。

#### 合成定价与机制预算

第一防线铁枪会的`craft.iron-spear.019`已按171000金币、17100 K点，另加QJZ171、GM6山猫、M82A1战术版、电脑芯片、纳米执行单元各一份落盘。总折算成本1071040，比55级四层合成参考901120高18.8565%；完整原料折算与来源见[数值与合成记录](QJZ171-钛合金版数值落盘-2026-09-07.md#171彩蛋合成配方)。

这部分主动溢价为“171”彩蛋与未来套装联动预留。满条件0.15%击溃、10%斩杀按枪械页C32各约一层机制预算，合计约两层；它们是本节条件机制的能力估值，不改当前四层基础预算。18.8565%也不是通用的“两层价格换算率”。9月7日先上线配方；9月8日S2接入五甲/盾在线/负重量门控和百分比机制。保留四层基础身份，条件机制另记，不把物品无条件写成六层。

#### 17kg共享额度与上限

五件唯一防具槽齐全且具名专属盾层 `titanium_type_61_set_shield` 的真实容量大于0时，读取当前全部装备槽的最终重量W。按固定1:1机制预算分配17额度，两项同步增长，不增加玩家分配菜单：

```text
进度 = clamp(-W, 0, 17) / 17
本枪额外击溃 = 0.15% × 进度
本枪额外斩杀 = 10% × 进度
```

这是本枪设计的额度分配，不是工作簿通用的“重量换层”公式；两项上限分别遵守枪械!C32。0及以上无额外效果，-8.5时为0.075%/5%，-17及以下为0.15%/10%。仅读取重量，不回写重量或最终行走速度；原生轻装速度在0及以下已有1.25封顶，不再次因这项能力提高。

五甲44＋血剑-99＋双P90 18＋机枪20=-17（暂不计颈部、手雷和模组）。卸下一把P90为-26、卸下两把为-35，两项效果仍停在原上限，多出的9/18只允许其他携装。其他真正减重的构筑也有效，不检查血剑或P90的名字。

P90的取舍由能源功能体现：放弃它会改变发射回MP的能力，需依靠其他来源维持修盾、维生和重建。不得为了让P90显得必选而另造武器名称门槛。专属盾破碎、五甲不足或使用其他武器时停止本枪新增贡献；保留其他合法来源的效果和基础17%暴击。

#### 伤害链与叠加边界

本枪生命周期在成功发射的属性传递阶段读取当前条件，必须在创建子弹和选择 `DamageManager` 之前完成投影。采用发射时快照，不允许旧弹在飞行途中通过切枪、减重或后来开盾追认加成。监听过滤owner、长枪槽和当前独立物品身份；不要写人物全局击溃/斩杀而让P90、血剑或其他枪共享。

新增贡献与本枪已有同类属性取高值，例如8%已有斩杀与满档10%得到10%，不相加为18%；本枪自身上限不应截断其他来源已有的合法值。套装卸载只使本枪条件贡献失效，不能清除武器通用动画、基础暴击或其他装备监听。

继续服从真实命中与敌方盾强门槛。击溃在每次完整伤害管线里，按目标当前最大HP扣减并产生配对HP损失；斩杀用击溃后的当前最大HP判定。联弹内部段数不等于击溃调用次数，也不按穿透目标数量再乘一次效果比例。后续测试应记录实际 `CrumbleDamageHandle` 调用数，不以伤害数字条数代替。

#### 实战标定

现有数学参考以171每发2.5次独立结算、M134每次扣弹5×2=10段为输入。代表目标为地狱战斗天才的100级JK；该敌人发布SWF覆盖了属性，不能使用普通敌人XML的低级HP模板。此前专项表是5%暴击历史快照，当前基础已提高到17%，上线标定必须使用当前数据。

至少比较普通敌人和高血量目标、0/-8.5/-17/-35重量、卸单/双P90、五甲/盾上下线、同类模组取高值和连续开火换弹。M134的60级枪械防具对照与可继承击溃的末日铁拳变体都应纳入，避免把固定纯枪甲当作全部毕业配装上限。数值上限已决，允许标定的是机制在线率、能源成本、基础威力与整体构筑表现。

## 8. 高级夜视仪

### 8.1 决策

五件套激活时，由头部装甲注册 `data/environment/color_engine_preset.xml:700` 的现役 `高级夜视仪` 视觉预设，默认亮度区间为0～4：

- 只对主角注册，沿用 `WeatherSystem/NightVisionManager`；
- 自动随环境亮度启停，不要求玩家手动切换；
- 护盾破碎、MP不足、持有不同武器均不影响夜视；
- 套装失效、换装、重初始化和场景清理时必须幂等注销；
- 不附带目标扫描、自动锁定、躲闪Debuff或额外伤害。

### 8.2 施工约束

`红外夜视仪初始化` 是普通装备生命周期函数名/装备族称呼，不是视觉预设名。现役红色系视觉预设叫 `浅红夜视仪`，本套装选用的是 `高级夜视仪`。旧初始化当前没有套装 gated init 所要求的显式 `ready_static/ready_cycle/failure` 三态和事务登记。

施工时二选一：

1. 为钛合金61套装增加事务感知的夜视包装函数，内部复用现役注册接口并返回 `ready_static`；
2. 在保持所有旧夜视装备行为不变的前提下，把通用夜视初始化升级为兼容套装事务的实现。

在完成三态与回滚契约前，不得直接给旧函数加 `setGate`。

## 9. 应急自动注射器

### 9.1 定位

自动打药不是常态回血，也不用于维持血剑的低血增伤区间。它是生命维持系统无法继续工作的最后保险：

```text
护盾已破
  AND HP进入危急阈值
  AND 当前MP不足以在下一次维生脉冲内脱离危急区
  AND 玩家明确指定的自动注射槽有药
  AND 该槽冷却可用
→ 自动使用一次
```

建议首轮用约20%～25% HP作为触发候选，并设置更高的复位线形成滞回；最终值待实战决定。

### 9.2 消耗权威

- 玩家必须明确指定八个物理药剂槽 `0..7` 中的一个为自动注射槽；未指定就不自动打药。
- 不扫描背包、不按价格猜测、不在多个药剂中自行“智能选择”。
- 自动与手动共用该物理槽映射的 `drug:<lane>` 冷却、库存扣减、耗尽清栏、炼金加成与 UI 投影；`0↔4`、`1↔5`、`2↔6`、`3↔7` 上下同列共享四条 lane 冷却。
- 自动注射不得替玩家切换药剂组，也不得消费或重置 `drug:switch`；非活动组物理槽是否具备注射资格必须在该功能施工前另行冻结，未冻结时 fail-closed。
- 不直接调用 `_root.使用药剂()` 后另行手扣库存，也不模拟键盘按下。
- 施工时应从 `DrugInputService` 抽取手动/自动共用的“尝试消费指定槽”原语；手动输入和自动注射都通过该入口。
- 一次阈值穿越最多触发一次。仍处危急区时等待冷却结束不得自动连吃，除非先越过复位线后再次跌入。
- 死亡、暂停、无物品、零数量或冷却未完成时失败关闭，不消费物品。

### 9.3 与血剑的关系

- 护盾未破时，即使血剑把HP压低也不自动注射；
- 护盾破碎但HP仍高于危急线时不自动注射；
- 只有进入真正死亡风险且MP维生不足时才接管；
- 因此不会把血剑“主动维持低血”的玩法自动抹掉。

### 9.4 分期

自动注射器列为二期优先候选。首期先证明护盾、维生、P90发电、弹药合成和夜视闭环，再加入会真实消耗库存的自动行为。

## 11. 套装数据与运行时归属

### 11.1 成员与计数

- 中心身份继续使用现有 `titanium_type_61_armor`。
- 只有头、胸、腿、手、鞋五个唯一防具槽计数。
- 五件套采用明确的5件门槛，不先建设3件/5件分段效果。
- M134、血剑、钛合金P90和钛合金QJZ171不写入该 `setId`。
- 胸甲喷气背包继续作为无 `setGate` 的单件生命周期能力。

### 11.2 定制效果

钛合金61式属于高度定制行为，应走 `kind=routine` 的组件化定制路径，不扩张通用模板注册表。这里必须区分“运行时控制器直接读取”和“schema/构建期校验并形成配置契约”两层，不能把后者误写成无效文档字段。

`SetEffectController` 当前直接读取：

- `threshold`；
- `activationGroup`（缺省时回退到效果ID，但本套装必须显式填写）；
- `kind=routine`；
- `components.component_N` 中的 `id` 与 `slot`；
- `prepareRoutine`；
- `cycleRoutine`。

仓库校验器同时把以下字段作为有效配置契约：

- `<mode>` 必须存在且当前唯一合法值为 `member_components`；它不是可随意省略的注释。
- `<requires>` 若存在，会被解析并校验依赖目标、同组约束和依赖图；当前控制器没有独立的 `requires` 运行时分支，因此它不能替代 `activationGroup` 或实际运行时排序，但也不能谎报为“不会生效”的自由文本。

首期单一五件效果不需要 `<requires>`。配置必须显式写出 `threshold=5`、稳定且唯一的 `activationGroup=titanium_type_61_full_set`、`kind=routine`、`mode=member_components`、五个组件以及 `prepareRoutine/cycleRoutine`。若未来拆分多效果或增加依赖，必须同时满足校验器依赖图、共同 `activationGroup` 和控制器实际准备/提交顺序，不能只加 `<requires>` 就声称运行时顺序已经得到保证。

建议组件分工：

| componentId概念 | 所属部位 | 行为 |
|---|---|---|
| `helmet_night_vision` | 头 | 高级夜视静态注册 |
| `chest_life_support` | 胸 | 中央护盾、维生和状态机所有权 |
| `leg_ammo_supply` | 腿 | 双枪弹药合成与槽位均衡 |
| `glove_energy_bus` | 手 | 武器发射/能源接口资格，不增加流派伤害 |
| `boot_servo` | 鞋 | 护盾在线负重补偿 |

五个组件均须成功初始化后才提交套装组。中央周期应尽量只有一个，由共享context处理护盾、HP、MP、弹药和状态转换；夜视、监听和Buff采用事件或静态注册，不为每个部件建立无意义的每帧任务。

### 11.3 Buff边界

- 负重补偿和破盾通用增伤使用具名、可覆盖、可清理的单一来源；负重补偿按§4.7通过 `setPodBuffValue` 动态重算，不写死常数。
- 不在周期中逐帧叠加数值。
- 套装卸载或初始化失败时，专属护盾层、启动费凭证、套装Buff、夜视注册、套装自有监听、维护任务和外部引用必须整体回滚。护盾清理只移除§4.1的具名专属层，不触碰共享容器中的其他层。套装自有dispatcher订阅必须使用可精确退订的具名回调，并把cleanup登记进套装事务 `resourceStack`。
- P90发电监听不属于上述事务资源；其清理由武器/单位生命周期负责，套装失败不能使武器固有效果失效。
- 全局增伤实现应遵循现役通用Buff语义；在兵器/枪械Buff迁移未完成前，不引入新的流派专属属性。
