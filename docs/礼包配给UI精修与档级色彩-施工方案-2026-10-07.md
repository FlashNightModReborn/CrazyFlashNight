**文档角色**：施工方案（前期探索收口）。基线：2026-10-07 工作树。
**前置决策**（已与用户对齐）：

## 2. 金档规则（正交类目）

- 金 = "豁免常规平衡"的分类判断，**只能显式声明，任何派生（价值再高）不得得出金**。
- 视觉：不与三档共用"同款版式换色"，做版式级区分（边框形制/角标），色觉无障碍双编码。
- 排序/分组：金单独成组、标签"特殊"，文案禁止"最高稀有度/顶级"等强度暗示。
- 注意视觉撞车：K店价格色 `--cp-yellow` `#fcee09`（`foundation-top.css:10`）与 special 金 `#FFFF00` 近似——礼包 UI 用金表"特殊档"时须与价格金拉开（DLS 文档明确允许琥珀/金作价格辅助色，`docs/dls-color-system.md:12,185`）。
- AS2 语义色板（`TooltipConstants.as:13-44`）的 `COL_HL #FFCC00`、`COL_DMG #0099FF` 与档级色同值不同义，**勿跨语义复用**。

## 3. 价值轴派生规则（绿/黄/蓝）

**换算链**：物品取 `<price>`（金币购买价；出售价是 `floor(price×0.25×倍率)` 派生值，`UI交互_lsy_物品栏UI.as:18-61`，不作输入）；K点商品 `K点×50`；技能 `SP→K点→金币`。

**数据覆盖**（探查确认可行）：
- 物品 1678/1678 有 `<price>`；技能 80/80 有 UnlockSP/UpgradeSP；K店 226/226 有条目价。
- 礼包 chooseOne/independent 内容物 90 个唯一物品 100% 解析到非零 price；配给 bundle 内容物 46 个唯一物品 100% 可解析，唯一例外 `书中弹药补给包`（price=0，fixed 礼包，估值需递归展开 rewardPack——`data/rewards/README.md:32` 规定产出礼包不递归打开，但估值层面需要递归）。
- 强化等级附加值用强化收益公式派生（`UI交互_lsy_物品栏UI.as:5-13`）；equipment_mods 的 107 个 `<mod>` 本身无 price，插件以其材料物品身份有价。
- `price=0` 共 75 个（礼包/情报/战场补给/部分装备等"非卖品"语义）——**无价物品档级必须显式声明，不参与派生**。

**⚠️ 待用户裁决项（阻塞阈值设计）**：
1. **汇率口径张力**：1:50 是货币面额锚（`data/items/消耗品_货币.xml:33-38` K点条目 price=50），但装备定价工作簿的推导比是 32.5（武器）/28.9–30.8（防具）（参考公式 xlsx 装备价格页 N5:N8/N16:N19；WBR-PRICE-001/004）。价值轴统一用 1:50 会让 K点装备显得比工作簿定价意图"更值钱"。→ **需裁定**：价值轴采用哪个口径（建议：面额锚 1:50，因其是产品决策且玩家可验证；但工作簿口径的偏离要在审计报告中可见）。
2. **SP 换算双链不自洽**：技能点货币条目 price=1500（→ 1 SP = 1500 金币 = 30 K点@1:50），但健身房购买价是 50 K/SP（基础档；`UI交互_aka_健身房训练.as:9-14`，高档位 35/20 K/SP 递减）。→ **需裁定**：SP 估值用哪条链（建议用货币条目 1500 金币，口径与物品一致；健身房价视为市场折扣价）。
3. **付费卡反直觉档级**：300 K 买技能 vs 300 K 买药剂的内容物价值差异大，直接派生会产生反直觉结果。→ 建议：付费卡（kCost>0 的 bundle）档级显式声明，不走派生；或派生+人工复核白名单。

**施工形态**：
- 阈值词典化：价值→档级切分表进受控词典（ui_presentation.xml 同型，或并列新词典），生成期派生写进派生物，运行时不推算。
