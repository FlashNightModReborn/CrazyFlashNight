# 对白权威迁移 wire v2：协议全文与分期立项（2026-09-16 修订稿 v2）

**文档角色**：对白系统从「AS2 权威 + C# 呈现」迁移到「C# 持会话节奏、AS2 持数据装配与责任代理」的协议级立项。本稿是 Wave 1 六路调研收敛 + **Wave 2 五路对抗复核修订版**（相对初稿修正 6 项 P0/方向性缺陷、10+ 处一致性问题，修订对照见 §10）。**尚未授权实现或发布。**

**输入报告**：X=AS2 权威依赖全图、Y=C# 设计空间、L1=生产者形态穷举、L2=潜伏路径实查、L3=暂停/事件对抗、L4=协议字节级对抗、L5=帧泵判定与预算复核；Wave 2 复核报告五份（均见 `tmp/dialogue-authority-study/`）。

---

## 1. 背景与目标

现状：AS2 `NativeDialogueService` 持会话（句序/finish/cancel/暂停 claim/followingEvent），每句发一帧快照给 C# 呈现；advance/close 经 socket 回 AS2 裁决再发下一句。

目标分两步：

- **方案 A（一期）**：会话入口整本下传（`op:"book"`），C# 本地驱动换句/打字/换图/预取；AS2 保留剧情权威（finish/cancel/followingEvent/claim 原样），终态走 `verb:"finish"` 回执。
- **方案 A+（二期）**：静态对白源的装配迁 C#（C# 直读 stage XML 对白/task 文本/NPC 固定对白——多数已在 `DataQueryTask`/`XmlDataLoader` 现役管道内）；AS2 保留：身份/外观快照查询、动态佣兵人格对白装配、**AVM1 内存中已成形的行数组**（authored `默认对话`/`本段对话` 元组容器——编译进 SWF 的运行时数组，C# 无管道可读，仍走 AS2 buildBook）。

**明确不做**：followingEvent 发布（dispatcher 在 AVM1 对象图）、暂停 claim（PauseManager claim-OR）、外观冻结（读活 MC）、facade 桩化（AVM1 显示列表行为）、佣兵人格对白选择逻辑与池包装公式（C15 条件不触发，判定留 AS2）、AS2 零对白状态。

## 2. 收益核算（L5+W2-5 双次修正版；端点已声明）

| 项 | 量级 | 端点/条件 |
|---|---|---|
| advance 典型延迟 | 现状 ~11–36ms（点击→上屏）/ ~7–21ms（点击→ShowFrame）；A 后 ~5–20ms（含上屏，鼠标） | L5 探针修正段表；键盘路径另 +2–4ms |
| 每句消除的固定成本 delta | **~5–16ms/句**（鼠标；b 0–2+c 3–6+d 1–3+e 1–5） | 键盘 delta ~4–11ms |
| 延迟尾部 | 现状 ~110ms@30fps 饱和 / 降帧至 ~180ms → A 后 ~35ms | 尾部=主线程长脚本占用+33ms 合并窗 |
| AVM1 帧内 CPU | 每句 ~4–8ms 归零（A 后）；**会话入口新增单帧 buildBook ~5–40ms（38 行上限），1–5 行常态可忽略** | 总量低于 v1 全程摊销但时域集中，低端机开场可能掉一帧 |
| GC 对象数税 | 持久对白池数千对象级（定性；AVM1 标记成本∝对象数）；**A+ 可退役的是 task_texts/enemy_dialogues 解析池子集**；MercLibrary 池（动态佣兵现役）与 npc 默认对话（作者数据）常驻 | 小但随内容增长 |
| 链路稳定性 | book 单帧原子采用；mutation 请求/响应化消除 v1 每句一次的部分失败面 | — |

**诚实口径**：典型感知收益 5–16ms/句 + 尾部收窄 + 帧时间归还 + GC 减压，不是"去一帧"。

## 3. 权威划分（A 一期）

- **C#**：整本行副本、当前句 index、本地 revision（每 requestId 单调 ++，与 index 方向无关）、换句/打字/立绘/配图状态、closing 暂定终态。
- **AS2（escrow 代理）**：会话生命周期（beginSession/finishSession/cancelSession 原样）、followingEvent 持有与一次性消费、stage claim、追加/覆盖入口语义、场景 teardown 取消、发送失败/断线兜底、facade。
- **共享不变量**：requestId 由 AS2 唯一发号（`nd:<n>` 单调）；`_maxSequence` 前沿 + hide 墓碑语义零改动；socket-only 边界（Web 不可伪造）零改动。

## 4. wire v2 协议全文

### 4.1 版本与能力握手（caps-required，每代重发）

- `native_dialogue` task 内 v1/v2 共存；`TryParse` 按 `version` 分派，未知 op fail-closed。
- **caps 下行通道 = `OnClientReadyForGeneration` → `PushToClient`**（FrameTask ready-push H1/H0 有先例）：C# 在每代 socket ready 时推送 `{task:"dialogue_caps", modes:["snapshot","book"]}`；AS2 `onSocketData` 加 `dialogue_caps` 专用分支。（初稿的 bootstrap_handshake 方案被 W2-2 B2 证伪：握手每进程仅一次，gen≥2 重连永不重发。）
- AS2 侧三条纪律：① caps 闩按 socket generation 作用域，`onSocketClose` 清闩；② **未见本代 caps 不发 book**（旧 Core 收 book 会静默丢→会话悬挂）；③ `wireMode` 按会话闩于 beginSession（v1 起头终身 v1）。
- `config.toml [dialogue] authorityMode="auto|snapshot"` 只可向下强制 v1，不得越过 caps 向上强制 book。

### 4.2 AS2→C# 帧（version:2）

```jsonc
// 会话入口（替代 sendLine(0) 的 show）；mutation 帧一律走 sendTaskWithCallback（见 4.3 注）
{"version":2,"op":"book","requestId":"nd:<n>","sceneId":"...",
 "mode":"ordinary"|"stage","epoch":1,"startIndex":0,"advanceKey":13,
 "lines":[{"name","title","text",
   "portrait":{"kind":"static"|"doll","key","expression","appearance"?},
   "imageAction":"keep"|"show"|"clear","imagePath"}]}

// 追加（复刻 v1 append 语义：扩数组+回 restartIndex）
{"version":2,"op":"append","requestId":"nd:<n>","sceneId":"...",
 "epoch":2,"lines":[...],"restartIndex":0}

// 低频变更（白名单字段：advanceKey）；**set 不 bump epoch**
{"version":2,"op":"set","requestId":"nd:<n>","sceneId":"...","advanceKey":32}

// hide：v2 会话带 version:2，字段与 v1 同形（requestId+sceneId 墓碑语义不变）
```

- **epoch（行集代际）**：AS2 每发一次 book/append 对 requestId `epoch++`（book=1），随 op 下发；**set 不动行集、不 bump**。C# 记录本地已应用 epoch。
- **op 白名单** {book,append,set,hide}（`Text(op, 8)`）；show 仅属 version:1 文法，v2 下出现即拒绝。
- **append 约束**：逐行复用 v1 校验，任一行畸形→整包 fail-closed；`restartIndex` 是合并后数组下标（0≤i<合并后行数），缺省=0；**合并后 lines.length ≤ 4096 重申**。
- **book 非幂等**：要求 `sequence > _maxSequence`；`==` 且同 requestId 的重发 book 拒绝。
- **每个 mutation 帧的大小上限**：`lines.length ≤ 4096` + **报文 ≤ 256KB（UTF-16 char 口径）**；判定点在 **`HandleCurrentMessage` 内 JSON 路由前的 task 前缀嗅探门**（超限直接 bookAck reject，不进 `JObject.Parse`——上限写在 TryParse 层会在锁内 parse 完成后才判定，防 head-of-line 的目的落空）。**AS2 buildBook preflight**：超限回本会话 v1 快照模式（wireMode 按会话闩允许此降级，合法长内容不被整段丢弃）。
- **行物化规则**（buildBook）：`row==null` → 跳过该行；结果空集 → **不发 book**，本地直接 `finishSession()`（保留孤儿 hide，与 v1 发送失败兜底同形）。`char` 缺失 → 按 `char=""` → portrait 落 `{kind:"static",key:""}`（空静态槽），不拒包。
- **A 阶段 C# 禁止发号**：C# 不得自造 requestId；A+ 也不需要（§4.6 废除租号——AS2 始终自发 book）。

### 4.3 C#→AS2 回执与 mutation 确认

```jsonc
// 终态回执（末行 advance 或显式 close）——唯一经 rewardPending 门禁的 v2 回执
{"task":"cmd","action":"nativeDialogueAction","requestId":"nd:<n>",
 "sceneId":"...","verb":"finish","epoch":<C#已应用代际>,
 "finalIndex":<C#终态行号>,"reason":"advance_past_end"|"close"}
```

- **mutation 确认（bookAck）不经门禁**：book/append/set 一律以 `sendTaskWithCallback` 发送，C# 的应答经 **callId 回调路由**返回——`{result:"ok"|"reject", reason:"malformed"|"oversize"|"stale_sequence"|"wrong_session"}`。该通道天然免疫 rewardPending 门（与 caps 同理），误杀面（初稿 P0，四路独立复核收敛）整体消除。AS2 侧 watchdog = **callback 超时**（建议 ~3s，联调按 PerfTrace 收紧），超时 → `finishSession()`（复刻 send-fail 兜底；watchdog 路径不 resend 尾部是有意取舍，与 v1 send-fail 丢尾同语义）。
- **AS2 `handleAction` 分版本**：v1 维持 requestId+sceneId+revision 三重校验；v2 校验 requestId+sceneId(+epoch)，verb 只含 {finish}，其余拒绝。会话对象存 `wire:"v1"|"v2"`（beginSession 闩定）。C# 对称：per-session 记 wireMode，**不可对 v1 会话发 finish**。
- **C# 侧 OnInput 动词白名单扩 finish**；本地 advance 必须在 `_inputAllowed()` 门之后（与 v1 输入许可面一致）。
- **rewardPending 门禁维持吞掉 finish**（不加白名单——L3 裁决：finish 是 followingEvent publish 触发器，白名单=在 pending 期放行事件发布，改变门禁本意；C# 以 closing 重试补偿，§4.4）。

### 4.4 closing 状态机与 epoch 裁决（W2 收敛修订：复活语义已删除）

C# 侧 per-requestId 状态：`active → closing → closed`：

- 末行/close → **closing**：可即隐面板，book 保留、不立墓碑；发 `finish` 回执。
- closing 态收到同 requestId 的 append/set → **不复活**（bookAck 应答 ok 但维持 closing，等 hide/新 book——finish-wins 保证二者必来）；收到 hide / 更高 sequence book → closed（终态化，立墓碑）。
- **回执必达（重试的界，W2 三重收敛写死）**：AS2 `sendHide` 即天然 ack；C# 在 closing 态重试 finish，**仅以 {同 rid hide、同 rid 新 op、更高 sequence 帧、断线} 之一终止——不设次数/时间上界**（pending 窗口无上界，任何次数/时间上界都会回归硬软锁）；间隔为有界节拍（≥100ms 且必须绕过/大于 750ms 同 verb 去抖）；每次发射前复查 per-requestId 状态仍为 closing；`HandleTransportDisconnected` 清空重试状态，跨 generation 不重发。

AS2 侧 epoch 裁决表（写进协议，不许实现自定；epoch 缺失/非整数 → drop+log）：

- `receipt.epoch == session.epoch` → `finishSession()`（正常终态：terminal→清事件→清会话→放 claim→hide→publish，顺序不变）。
- `receipt.epoch < session.epoch` **且存在未 ack 的 append 尾部** → **finish 仍赢**：`finishSession()` 照常，然后把追加尾部按**新 requestId 重发 book**（followingEvent 已消费不带）——复刻 v1「close 先到再 append」的结局（v1 中 append 在 close 后走 `beginSession` 新会话），两端确定、内容不丢、不双渲染。若 `<` 仅由 set 之外的 bookkeeping 偏斜造成而无尾部 → 按 `==` 干净收口。
- `receipt.epoch > session.epoch` → drop+log（诚实 C# 不可达，防御分支）。
- `finalIndex != 本会话末行` 仅在 `reason=="advance_past_end"` 时判异常（Esc 中途关天然 <末行，不误标）。
- watchdog（callback 超时）路径 → `finishSession()`，不 resend（同 send-fail 语义）。

### 4.5 revision 本地化纪律与 advance() 冻结

- 本地 revision = **每 requestId 独立单调计数器，每次 ShowFrame ++，与 index 无关**。**禁止按 index 派生**（append restartIndex 归零会触发迟到帧拒绝）。widget 的迟到帧拒绝/手势绑定/SetPortrait 接受门/排版缓存 key/同图跳过语义全部保持。
- **advance() 冻结**（L3 P1-2 并入）：A 下 `svc.advance()` 不得发 v1 show 污染 book 会话——改本地 index++/no-op；facade `下一句` 生产调用方=0，仅测试与 facade 死路径可用。

### 4.6 A+ 追加项（二期边界，W2-3 修订版）

- **会话发起 = assemble 请求/应答对**（废除租号 ndGrant——其载体方向与 verb 白名单均有误，且 AS2 自发 book 时租号本无必要）：stage/NPC/task 触发点始终在 AS2，AS2 经 cmd 向 C# 发 `assemble` 请求（源标识+行提示），C# 应答行集（**含空集/no-op 显式回执**——空集时 AS2 直接 `publishFollow`，不开会话，复刻 `beginStage([])` 语义）；AS2 收到行集后按 §4.2 自发 book。发号权全程不出 AS2。
- **身份/外观快照查询**（一次性 cmd 应答，**行级批量**）：C# 提交每行 `{charBase, expression, targetRef|attrObj}`，AS2 逐行跑 `NativeDialogueAppearance.build` 返回 portrait 对象（hero/佣兵/无身份三路裁决、Andy Law 后缀、室友分支全部留 AS2）；`兵种库[Type]` 按 type 键纳入查询域。应答字段**必须含 `heroTitle`**（`HeroUtil.getHeroTitle()` 为活态四级优先链，禁止 C# 复刻；`$PC_TITLE` 在生产数据 973 处实例）**与 `advanceKey`**（`KeyManager.getKeySetting("互动键")`；或由 SettingsTask 键位镜像管道供给，实现时二选一写死）。
- **装配覆盖**：以 L1 C1–C16 为准；补充裁决——C5 no-op 按 §4.2 行物化规则落成具体 wire 序列；C6 防护按 §4.2（不拒包）；C2 `角色名` 哨兵**不复刻**（L2 E4：生产零产出，可删；旧格式回流前补数据审计）；C13 随场景门退役自然失效（facade 容忍未知字段纪律不变）；C15 池包装公式判定留 AS2（见 §1）。
- A+ 后 AS2 侧镜像（`读取NPC对话` 类死路径）随 M6 清理；现役 `DataQueryService.query("npc_dialogue")` 消费方不受影响（数据本就 C# 供给）。

## 5. 失败注入封堵对照（W2 复核后修订版）

| 注入 | 现状 | A 后 | 封堵 |

| C# 假死（进程活、socket 半开） | 会话滞留（stage claim 软锁） | **现状同级未封堵**（同形）；callback 超时只覆盖 mutation 期 | 登记，B/C 议题 |

## 6. 分期与里程碑

**一期 A（5–7 人日）**
- M1 协议落地：双端解析（C# op 分派+book/append/set 校验+嗅探上限门、AS2 buildBook/行物化/epoch/wireMode 闩）、caps ready-push、mutation 请求/响应化（callId）、config 开关。（1.5d）

- M3 灰度与回退演练：双模共存矩阵（新 Core+新 AS2=v2；新 Core+旧 AS2=v1；gen≥2 重连仍 v2——caps 每代重发）、断线/teardown/overwrite/pending 中关闭回归。（1d）
- M4 发布列车 + 真机复验清单（换句手感/双击节奏/连续对话/暂停交叠/reward pending 中关闭对白/追加续播/会话入口 buildBook 掉帧观察）。（0.5–2d 窗口）

## 8. 风险与未决项

1. **callback 超时阈值**（~3s）为经验值，联调按 PerfTrace 实测收紧——P1。
2. **双击节奏漂移**需真机手感复验；若差评可在 C# 侧加 40–80ms 换句去抖窗（协议外选项）。
3. **`s.index`/`对话进度` 冻结**：无生产读者，接受冻结；beat 不做。
4. **buildBook 入口单帧爆发**（38 行 ~5–40ms）：低端机开场掉帧观察项，必要时按行流式构包（协议不变，实现选项）。
5. **旧 Core 混流**：caps-required 保证 AS2 不对旧 Core 发 book；反向（旧 AS2+新 Core）走 v1 全路径——发布说明注明配对关系。
