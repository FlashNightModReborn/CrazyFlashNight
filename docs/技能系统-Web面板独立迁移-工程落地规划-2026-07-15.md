### 0.1 为什么必须独立

技能页和物品页只在视觉上都像“格子 + 详情 + 拖放”，权威模型并不相同：

| 维度 | 物品工作台 | Skill 主线 |
|---|---|---|
| 权威集合 | `ItemCollection` / 物理槽 / owned 容器 | `_root.主角技能表` + `_root.快捷技能栏1..12` + `_root.技能点数` |
| 核心写 | move / merge / swap / sort / trade | learn / upgrade / equip / unequip / passive / reorder |
| 并发凭证 | 容器 epoch + slot lease | 技能态 revision + 学习一次性 token |
| 外部上下文 | 背包、仓库、商店 | 当前教师会话、角色等级、技能点、难度模式 |
| 活体副作用 | 装备属性、库存事件 | 被动技能重算、角色投影、动态 CD/MP、快捷输入描述符 |

把 Skill 塞进 inventory domain 会让 Web/C# 开始理解 `主角技能表` 的数组形状和被动副作用，也会把不存在的“快捷技能 ItemCollection”伪造成物品容器。独立领域能让两条主线只在视觉壳层相交。

### 0.2 本主线包含与不包含

包含：

1. 查看已学技能、等级、说明、类型、消耗、冷却和启用状态。
2. 教师上下文内学习新技能、批量升级到目标等级、技能点结算。
3. 12 槽快捷技能装备/替换/卸载。
4. 纯被动技能启用/停用、混合“被动&主动”技能的正确联动。
5. 已学技能顺序整理，保持旧 80 槽存档形状兼容。
6. 快捷输入从 HUD MovieClip 描述符改读 AS2 领域模型，为 NativeHud 最终删壳解除依赖。

不包含：

- 人物装备栏、药剂栏、背包物品或装备属性迁移。
- 技能伤害/平衡公式、技能树 AI/佣兵元数据改造。
- 把施法、MP、冷却状态机或被动效果计算迁到 Web/C#。
- 第一阶段重做技能图标素材；缺图先走稳定 fallback。
- 在功能切换前删除旧 `物品栏界面`、`学习技能界面` 或 HUD 快捷槽 MovieClip。

### 0.3 2026-07-15 评审备忘：成立项与冻结裁决

本轮针对现役代码逐项复核，所提九项问题**全部成立**。其中前四项按原规划字面实现会直接形成业务或协议错误，其余五项会在坏档、断连、HUD-null 或旧存档兼容场景触发。本文已把裁决同步写入对应权威章节，不把本表当作唯一规范。

| 项 | 结论 | 冻结裁决 |
|---|---|---|
| 未学技能可请求任意目标等级但只收 `UnlockSP` | 成立，存在少付技能点的实现漏洞 | `currentLevel=0` 时只接受 `desiredLevel=1`；已有技能才允许一次升多级，并按等级差收 `UpgradeSP` |
| trainer `entries` 同时允许纯 key 或完整对象 | 成立，两种 schema 无法共同冻结 | v1 只保留完整 `TrainerEntry[]`；不返回纯 `skillKey[]` |
| 重复技能行与 `skillKey` 身份冲突 | 成立 | snapshot 按 `skillKey` 去重投影并标坏；涉及重复 key 或重复目标行的写与施法 fail-closed，v1 不自动修档 |
| Web 请求 envelope 未冻结 | 成立 | 业务字段只准放在嵌套 `payload`；顶层业务字段和未知顶层键直接 `invalid_payload` |
| 旧的在途 snapshot 可误清未知写状态 | 成立；后续又发现单纯 generation 仍有超时错位反例 | Host `writeEpoch` + 显式 `reconcileId/reconcileAfterCallId`；只有写定局后的匹配 probe 可清状态 |
| `iconKey="图标-闪现"` 与 Web manifest 不符 | 成立 | `iconKey` 直接使用 manifest 精确键，即 `skillKey`（例如 `"闪现"`） |
| 新 AS2 测试未挂 `TestLoader`，输入/冷却回归不完整 | 成立 | 新增测试与三套固定回归均明文注册；Gate 要求 fresh trace 和明确套件/用例计数 |
| HUD-null Gate 漏掉动态 CD/MP 与旧技能列表投影 | 成立 | 拆成领域重算、可选快捷 HUD renderer、可选旧技能列表 renderer 三层，整个成功副作用链在 HUD-null 下通过 |
| 纯被动 `[2]` 语义未裁决 | 成立；首轮“固定 true”裁决被后续源码复核推翻 | `[2]` 是无业务语义的 legacy shadow，读取/同步不改写并按原值 round-trip；真实启停只看 `[4]`，`equippedSlots=[]` |

复核锚点：旧学习 UI 以 `Symbol 1779.xml::刷新文本` 的 `准备购买的技能等级 == 1` 分支隐藏四个等级按钮；现役 Web/Host envelope 以 `crafting-runtime.js::RequestMux.prototype.request` 与 `CraftingTask.cs::HandleWebRequest` 的嵌套 `payload` 为范式；图标解析以 `icons.js::entry(name)` 精确索引 manifest；HUD 强依赖分别位于 `引擎_lsy_技能系统.as::_root.动态更新技能冷却/_root.排列技能图标`；纯被动旧写位于同文件 `_root.学习技能` 的 `!技能信息.Equippable` 分支；`scripts/TestLoader.as` 是被 gitignore 的显式 scratch runner而非自动发现器。

同时冻结入口决策：我的技能采用与“情报”同类的刘海屏独立入口；教师入口保留 NPC 上下文。旧物品栏技能页在观察期只承担 Launcher 不可用时的旧 UI 回退，S6 退役，不改造成第三个生产入口。

### 1.2 类型语义不能简化

`SkillDataLoader` 的现行派生规则必须原样保留：

- `passive = Type.indexOf("被动") > -1`；
- `equippable = Type != "被动"`。

因此纯 `被动` 技能不可放入快捷栏、通过开关启停；`被动&主动` 一类混合技能同时 `passive=true`、`equippable=true`，通过快捷栏装备决定启用状态。不能用单个前端枚举把二者压扁。

### 1.3 当前已确认的迁移动因

1. 旧学习确认先执行 `_root.技能点数 -= 总价`，再调用可能因 80 槽已满而返回 `false` 的 `_root.学习技能(...)`，存在扣点但未学会的部分写风险。
2. 装备逻辑写在 `技能图标.xml` 的拖放 hitTest 中，卸载逻辑写在 HUD `快捷技能界面.xml`；规则跨两个 MovieClip，替换槽位时旧技能标志可能残留，且没有统一 dirtyMark 边界。
3. 迁移前 `QuickSkillInputService` 虽已承接 12 槽按键输入、`ManualCooldownService` 已承接手动冷却权威，描述符仍取自 HUD MovieClip。S1 已改为从 `SkillLoadoutService.getSlotDescriptor(slot)` 读取，HUD 不再是管理域与战斗域之间的隐式数据总线。
4. `技能图标` 有主 FLA 新结构和 `arts/things` 旧结构两个 linkage 导出者；发布产物已确认 main 的本地 `ExportAssets id53` 先于 `ImportAssets2 things.swf`，而该 import 唯一条目是 `加载MC库0`，没有把 things 的 `技能图标 id2706` 加入 main 字典。旧技能页 slot0/slot1 的 live depth 指纹也与 main id53 精确一致、与 things id2706 互斥，因此 main 的 `attachMovie("技能图标")` 实际命中 12 槽本地版本。双导出仍留到 S6 做资产去重治理，但不再是运行时来源未决。
5. 普通模式通过 `[2]` 阻止再次抓取已装备 source；EasyMode 允许抓取该 source，但两种模式都禁止落到已装备 target。新服务已显式建模这组非对称规则。
6. `SkillDataLoader` 直到 asLoader 后段异步加载完成才建立 `_root.技能表对象`；frame41 安装服务不等于静态数据已就绪，过早 snapshot 不能把全部技能误报为坏档。

### 2.1 分层职责

| 层 | 允许负责 | 禁止负责 |
|---|---|---|
| Web `skills.js` | 选择、筛选、拖放、确认模态、展示权威回包 | 计算学习是否合法、直接改点数/等级/被动、把 UI 乐观态当权威 |

| C# `SkillTask` | command/payload 白名单、超时、回包 schema、写门、重建 `panel_resp` | 读取 XML 替 AS2裁决、缓存角色状态、重放未知结果写 |
| AS2 `SkillPanelService` | 教师会话、快照、学习预览/token/提交、协议错误 | 持有战斗按键/冷却循环、依赖 Web DOM |
| AS2 `SkillLoadoutService` | 技能表/快捷槽一致性、revision、装备/被动/排序、副作用 | 打开面板、处理 callId、依赖可见 HUD |
| HUD MovieClip | 迁移期可选 renderer | 权威技能名、装备规则、卸载规则、施法 gate |

### 2.2 与双栏工作台的关系

Skill 允许复用下列 Web 层能力：

- `DualPaneShell` 的两个 view-slot、挂载/卸载、焦点和 PanelScale；
- `GridDensityController` 的密度偏好、`FilterNavigator` 的按钮/计数/键盘 primitive、确认模态，以及 `PointerDragController + InteractionBroker` 的 pointer 手势/拖拽镜像；
- `Panels.register` / lazy registry / PanelHost 生命周期。

Skill 不复用：

- `GridContainerView` 的 `physicalSlot/lease` 语义；
- `InventoryCoordinator`、backpack write gate、`inventory_response`；
- `Offer=ownedItem`、move/merge/swap、装备物品 `containerId`；
- NPC 商店、商城或 crafting 的 token 与状态机。

若直接复用 `DualPaneShell` 会迫使它认识 Skill 命令，应先提取更窄的展示 primitive；不得为“复用”把 Skill 写协议塞回通用壳。

## 3. 面板信息架构

### 3.1 `view=manage`：我的技能

- 上部主区：全宽已学技能库。“形态 / 配置 / 流派”三组直接 facet 常驻，玩家不进入中间目录即可筛选，三组可组合并可一键清除；名称搜索默认收起并按需与 facet 本地合取。未筛选时仍按 80 行原始顺序展示，排序只由显式操作触发。
- 下部操作带：轻量选择上下文、纯被动开关，以及按槽号 1—12 连续排列的一整排固定 Hotbar。快捷槽使用 `64×64px` 方格、`48×48px` 图标和连续底板，不随技能库完整/紧凑切换而缩放；键位居中、槽号弱化、等级使用右上角标，卸载 `×` 仅在悬停或键盘聚焦时替换等级出现。排序由技能格间拖放或 `Alt+↑/↓` 完成，不再占用常驻按钮。
- 技能说明、MP/CD、彩色效果文本和快捷槽完整名称统一由共享 `PanelTooltip` 提供；页面不保留常驻详情栏。
- 纯被动技能在操作带显示启用开关，不出现“装备到快捷栏”。
- 混合被动主动技能显示快捷栏状态，并明确“装备时启用”；不另给独立开关。

### 3.2 `view=trainer`：学习 / 升级

- 左栏：当前教师会话允许的技能目录，只显示 AS2 快照返回的条目。
- 右栏：只保留选中目标摘要、目标等级、等级门槛、技能点成本和消耗计算结果；技能长说明走共享注释。未学习时目标固定为 1 且隐藏/禁用等级步进，已有技能才显示可跨级步进器。
- 用户确认前必须完成 `learnPreview`；仅有有效 `learnToken` 时启用提交。
- 提交成功直接用响应内完整 snapshot 重绘，不依赖“本地减点 + 本地升一级”。
- 教师页不重复展示快捷栏；学习与装备仍是两个独立写操作，玩家可从顶栏进入管理页完成装备。
- 顶栏“管理技能”可把当前选中 `skillKey` 作为展示提示切到新 manage 实例。Host 暂存 session、清空 learnToken，manage Web 不持有学习 capability；只有该来源实例显示“返回研习”，返回后重新预览。
- trainer 使用独立的“形态 / 学习状态 / 流派”筛选路径；不能把 manage 的配置状态路径套到教师目录。

### 3.3 统一交互准则

1. 装备点击路径保持完整；排序以技能格间拖放为主路径，并保留 `Alt+↑/↓` 非指针兜底。键盘和手柄焦点不能依赖 pointer drag。
2. 槽替换必须由同一个 `equip` 命令原子完成，不先 `unequip` 再 `equip`；默认安全模式明确展示“将替换 X”，玩家显式启用快速模式后可直接执行。
3. 写请求进行中禁用所有 Skill 写按钮；读请求可显示旧快照，但不得清除未知写状态。
4. `needs_reconcile` 时只允许关闭或重新 `snapshot`，不自动重投学习/装备。
5. 技能 description 按 AS2 `htmlText` 处理，只能通过共享 `PanelTooltip.convertAS2Html()` 白名单转换；动态 Web 字段先 escape，禁止把 XML 原文直接交给 `innerHTML`，也禁止再以 `textContent` 暴露 `<font>` 标签字面量。
6. 完整/紧凑只改变技能库布局密度，不改变快捷技能 Hotbar、条目集合、当前选择、筛选路径、authority snapshot 或写协议；偏好按 `panelId=skills` 持久化。
7. 拖拽释放与点击槽位必须汇合到同一快捷栏确认策略和单条 `equip`；无效槽只给拒绝反馈，不发写请求。

### 3.4 same-panel rebind 与 close 生命周期

现役 `PanelHostController` 与 Web `Panels` 对“当前已是同名 panel”的再次打开直接 no-op，不能承载 Skill 的两个 view。`skills` v1 必须增加受控 rebind：

1. Host 每次真实 open/rebind 生成受限 opaque `panelInstanceId`；Web 的 request mux、late response 和 close 都绑定该实例。
2. 同 NPC、同场景、同目录签名的连续 `openTrainer` 在 AS2 侧幂等复用当前 session，防双击制造 A/B 会话；manage↔trainer、教师 A↔B 或 initData 实质变化仍必须 rebind。
3. 无写在途时，rebind 生成新的 `panelInstanceId`，以 active + candidate 两阶段保留教师能力：新实例首个合法 snapshot 才完成 promotion；旧 active 与新 candidate 都进入 Host 跟踪，关闭/切 manage 时逐一撤销，pause lease 只续持、不重复 acquire。
4. `write_pending` 或 `needs_reconcile` 时不允许立刻销毁旧会话。Host 只保留“最后一次 rebind 意图”，待写定局且完成对账后执行；期间 UI 显示 busy。禁止用 session 覆盖逃避未知提交。
5. 全局 close envelope 与 skills 业务 envelope 分开。close 固定为 `{type:"panel",panel:"skills",cmd:"close",panelInstanceId}`，Host 仅在 panel 名与实例均匹配 active panel 时执行；迟到的旧实例 close 只能忽略。idle 时随后立即幂等调用 `skillPanelClose`；写在途/待对账时可先关闭视觉面板，但 Host 必须保留后台 coordinator，完成写定局与 reconcile 后才清 session，不能用 close 抹掉未知状态。
6. ESC、backdrop、lazy open cancel、force close、发送 panel_request 失败和 socket disconnect 都必须最终撤销 trainer session、暂存的 return session 与全部 learnToken。Host 同时跟踪旧 active 与最新 candidate；两个不同 scoped cleanup 尚未发往 Flash 时必须收敛为 `trainerSession=null` 的 global cleanup，不能 last-wins 丢掉其中一个。断线/超时按有界重试保留 gate，重连先完成必要对账和清理，之后才允许新 trainer。
7. Web 内部切换使用两个同形 panel-control envelope：trainer→manage 为 `switch_manage`，仅教师来源 manage→trainer 为 `switch_trainer`，均携嵌套 `{v:1,focusSkillKey}`。Host 同时确认 active panel、当前实例和 `SkillTask` view；切 manage 时 learnToken 作废、session 仅在 Host 暂存并向 Web 投影 `canReturnTrainer=true`，切回时从 Host 恢复。NativeHud manage、旧实例、顶层字段或自行伪造的布尔值都不能取得 trainer capability。

## 4. AS2 领域模型

### 4.1 `SkillLoadoutService`

实现路径：`scripts/类定义/org/flashNight/arki/skill/SkillLoadoutService.as`。

职责：

- 只读扫描 `_root.主角技能表` 的真实 length/稀疏/行形状，兼容历史 Boolean 与字符串表示但不在 snapshot/synchronize 中改写；
- 读取/写入 `_root.快捷技能栏1..12`，生成与 HUD 无关的槽描述符；
- 维护单调 `skillRevision`，对服务外 legacy 写进行签名探测；
- 原子实现 equip / unequip / setPassive / reorder；
- 每次成功写后统一设置 dirty、重算被动、刷新动态 CD/MP、投影旧 HUD（若存在）；
- 向 `QuickSkillInputService` 提供 `getSlotDescriptor(slot)`。

槽描述符最小形状：

```js
{
  slot: 1,
  equipped: true,
  skillKey: "闪现",
  level: 3,
  mp: 14,
  cooldownMs: 1700,
  iconKey: "闪现"
}
```

这里的 MP/CD 在 AS2 内从当前 `_root.技能表对象` 读取，包含被动导致的动态修正；Web 只展示，战斗释放也从同一描述符读取。`iconKey` 必须与 `launcher/web/icons/manifest.json` 精确查表语义一致，v1 直接等于 `skillKey`，不得沿用 Flash linkage 的 `"图标-" + skillKey`。HUD 槽可以接收投影，但不再是读路径的前置条件。若 `_root.技能表对象`、主角技能表或存档上下文尚未就绪，统一返回 `service_not_ready`，不得建立 revision/signature/token 或生成坏档诊断；只读可退避重试，写不得自动重投。

### 4.2 revision 与 legacy 共存

当前仍有作弊码、旧拖放、旧学习 UI 等路径可能直接改 root 数据。单纯在新服务写成功后 `revision++` 无法发现外部写，因此服务需维护轻量 `stateSignature`：

- 签名覆盖外层 length、0..79 行存在性/形状/字段类型、名称/等级/装备/启用、80 行以后非空尾数据和 12 个快捷技能名，不包含 UI MovieClip 字段；纯被动 `[2]` 使用固定 sentinel，避免 renderer 改 shadow 引发 revision 抖动；
- 每次 snapshot 和每次写前调用 `synchronize()`；签名变化但不是本服务刚完成的写时，revision 增长并清空所有学习 token；
- 新服务完成写后重新签名并增长一次 revision；
- Web 所有写必须携 `expectedRevision`，不匹配返回 `stale_state` 和最新 revision，不做部分写。

`snapshot()` 与 `synchronize()` 绝不补齐、截断、排序、替换外层数组或统一改写 Boolean。已有同名物理行但等级不是合法 `1..MaxLevel` 时是 `corrupt_skill_state`，不得按 `currentLevel=0` 另占空行。短表缺行只允许在一次已验证成功的新学习事务中按目标索引原地 materialize；80 行外存在非空尾数据时全局写门 fail-closed。布尔解析必须显式识别 Boolean 和确知的历史字符串，禁止 `Boolean("false")`；`"ture"` 等未知拼写只诊断、不擅自纠正。成功与回滚均保持外层 Array 引用不变。

这不是永久双写方案。入口切换后应让所有生产写都经过服务；签名探测保留一段兼容期，用于作弊码/历史存档与回滚。

### 4.3 快捷栏一致性规则

1. **目标槽原子替换**：一次事务同时处理被替换技能、新技能、root 槽字段、80 行标志和可选 HUD 投影。
2. **普通模式唯一**：同一 `skillKey` 已在其他槽时返回 `already_equipped`。
3. **EasyMode 兼容**：保留旧 UI 对可装备技能重复装备的有效行为；这类技能的 `[2]`/`[4]` 必须按“该技能是否仍出现在任一槽”派生，卸掉一个副本不能把其他副本标成未装备。纯被动遵循 §4.4 的 legacy marker 例外。
4. **纯被动不可装备**：`Type == "被动"` 只能 `setPassive`。
5. **混合被动**：可装备；最后一个槽卸下时关闭 `[4]`，任一槽装备时开启 `[4]`。
6. **冷却不可洗掉**：equip/unequip 不重置、启动或缩短 `ManualCooldownService` 的槽冷却；替换槽位后新技能继承该槽仍在进行的冷却 gate，避免换装绕过 CD。
7. **空/坏存档 fail-closed**：技能不存在、等级非法或槽名不在已学表时不允许施法；snapshot 标记诊断，不能静默创造技能。`unequip(slot)` 对 unknown/unlearned 槽允许只清该 root 槽的安全修复，不要求存在已学行；若槽指向 duplicate key 仍阻断，`equip` 也不得借替换间接改坏 key。
8. **重复行 fail-closed**：`synchronize()` 先建立 `skillKey -> physicalRows[]`；同一非空 key 命中多行时，snapshot 只返回一个稳定投影（取最小物理行作为只读展示源），并写 `stateHealth:"duplicate"`、`writeBlocked:true` 与结构化诊断。equip、unequip、moveSlot 的任一非空源/目标、setPassive、learnPreview/commit、以该 key 为 source 的 reorder、以其物理行为 target 的 reorder，以及该 key 的快捷施法统一返回/记录 `corrupt_skill_state`，不得靠“第一行命中”完成写。
9. **显式修复边界**：v1 不提供 Web 修档命令，也不自动删除重复行；旧 UI 同样不能修复。离线 `cf7-save-repair repair-skill-duplicates` 已交付 dry-run 报告、显式 keep-row、二次确认、备份、过期扫描绑定校验和原子替换。UI 只提示坏档已阻断并引导离线修复，不得在游戏内静默删行；修复后下次 `synchronize()` 确认唯一才恢复写和施法。

### 4.4 被动与排序

- `setPassive` 只接受当前 metadata 判定的纯被动技能；写 `[4]` 后执行完整被动副作用链。
- `reorder` 使用稳定 `skillKey + targetIndex(0..79)`，AS2 现场定位 source；不信任 Web 提供的 source index。
- 排序只交换 80 行，不改快捷槽中的 `skillKey`；完成后重新推导每行装备/启用状态，旧 `对应数组号` HUD 投影由 AS2 刷新。
- reorder 的旧语义已冻结：source 已装备时普通模式拒绝、EasyMode 允许；target 非空且已装备时两种模式都拒绝。两条 target-equipped 负例必须保持零交换。
- 纯被动行的 `[2]` 是无业务语义的 legacy shadow：snapshot、setPassive、reorder、同步与签名均忽略且不改写，现存 Boolean/字符串原值必须 round-trip。新学习可保留旧函数的初值 `true`，但不得建立“始终 true” invariant；启停只读写 `[4]`，snapshot 始终返回 `equippedSlots:[]`。可装备技能的 `[2]` 才按“是否出现在任一快捷槽”派生。
- 新领域规则以当前 `_root.技能表对象[skillKey]` 的 `Passive/Equippable/Type` 为权威；存档行 `[3]` 只是 SaveManager/旧 UI 兼容投影。读取不一致只诊断不改档，该行发生真实领域写时可把 `[3]` 收敛到当前 metadata.Type，并纳入 dirty/revision。
- 同槽 equip、空槽 unequip、相同 setPassive 和同位置 reorder 返回 `success:true, changed:false, revision:原值, snapshot:完整`；不 dirty、不重算。只有真实改变才 `changed:true` 且 revision 精确增长一次。

### 4.5 成功副作用链与 HUD-null 边界

现役 `_root.动态更新技能冷却()` 在领域数值重算后直接遍历 `_root.玩家信息界面.快捷技能界面`，`_root.排列技能图标()` 又无保护调用 `_root.玩家信息界面.刷新技能等级显示()` 并访问 `_root.物品栏界面`。因此只改 `QuickSkillInputService` 不能通过 HUD-null Gate。S1 必须把成功写后的副作用明确拆为：

1. **领域重算**：重建 `_root.主角被动技能` 并计算动态 CD/MP；不得读取 hero、HUD 或物品栏 MovieClip。它与技能行/root 槽写属于同一事务；内部重算以显式 Boolean 报告失败，失败时恢复受影响行、槽、点数、root cache 与描述符，且保持外层数组引用不变，不依赖 production `try/catch`。
2. **hero 投影**：hero 存在时执行 `读取被动效果()`；hero 尚未生成时正常延迟，不回滚已成功领域事务，下次 hero 初始化从 root cache 收敛。
3. **快捷 HUD renderer**：仅在 `_root.玩家信息界面.快捷技能界面` 及目标槽真实存在时，投影技能名、等级、CD、MP 和冷却显示；缺失时正常跳过。
4. **旧技能列表 renderer**：仅在 `_root.物品栏界面` 存在且当前界面为“技能”时重建 80 格，并对 `刷新技能等级显示()` 做存在性保护；缺失时正常跳过。

事务顺序固定为“领域写与 root 重算成功 → revision/dirty → 可延迟 hero 投影 → 可选 renderer 投影”。hero/renderer 失败不得回滚已成功的领域事务，但必须产生日志/诊断；AS2 测试要覆盖 hero/HUD/物品栏均为 null 的完整 learn/equip/unequip/setPassive/reorder，以及 hero 后生成收敛，而不只单测描述符读取。

## 5. 教师会话与学习事务

### 5.1 opaque `trainerSession`

教师入口不把 `.可学的技能` 原对象交给 Web 再传回。现役 `npc_skills.json` 的教师值是带稀疏十进制键的 Object，旧 UI 也是按 0..79 数字属性读取。`SkillPanelService.openTrainer(currentNpc, source)` 在 AS2 内：

1. 确认 NPC 存在；`normalizeTrainerCatalog(raw)` 首选兼容普通 Object 的自有十进制键 `0..79`，同时接受真实 Array，按数值索引升序遍历，跳过空洞，禁止依赖 `for...in` 顺序；
2. 非法键、非字符串值和未知技能写诊断；重复 `skillKey` 保留最小原始索引。目录签名绑定 `index + skillKey`，不能只绑定压实后的名称序列；
3. 保存 session-scoped `{nonce, npcRef, scene/target, catalog, catalogSignature, createdAt, lastTouchedAt}`；
4. 只把 opaque `trainerSession` 与 `view=trainer` 放入 `panel_request.initData`。

每次 trainer snapshot/preview/commit 都重新验证：nonce 是当前会话、NPC/场景仍有效、目录签名未变、连续空闲未超过 120 秒。任一失败返回 `trainer_session_expired`；验证成功后刷新 `lastTouchedAt`，因此 TTL 是成功教师域请求之间的空闲租约，而不是从 NPC 对话入口起算的绝对寿命。进程内最多 1 个 active；同 NPC/场景/目录签名的重复打开复用 session 并续租，其他新教师入口按 §3.4 先安全 rebind 再替换。只有明确 NPC 教师入口可以创建 session；场景/教师/目录变化、连续空闲超时、close/rebind/断线清理仍使会话与其全部 token 失效。

### 5.2 学习预览

`learnPreview(skillKey, desiredLevel, trainerSession, expectedRevision)` 由 AS2 计算：

- 技能确在当前教师目录；
- 若 `currentLevel=0`，`desiredLevel` **只能等于 1**；请求 2..MaxLevel 返回 `initial_level_must_be_one`；
- 若 `currentLevel>=1`，`desiredLevel` 才可在 `currentLevel+1..MaxLevel` 内一次跨多级；
- 角色等级满足 `UnlockLevel`；
- 新学技能时 80 行存在空位；升级已有技能不消耗新行；
- 初学固定成本为 `UnlockSP`；已有技能升级成本为 `(desiredLevel-currentLevel) * UpgradeSP`，两种公式互斥，不存在 `UnlockSP + (desiredLevel-1)*UpgradeSP` 的 v1 路径；
- 当前技能点足够；
- 技能元数据和已学状态有效。

可提交时返回一次性 `learnToken`，TTL 固定 30 秒，每个 trainer session 最多保留 1 个；新 preview 立即撤销旧 token。token 绑定 trainer session、skillKey、当前/目标等级、成本、技能点、角色等级、revision、目录签名和元数据签名；只有这些业务绑定变化会使 token 失效，角色位置等无关状态不参与签名。

### 5.3 原子提交

`learnCommit(expectedLearnToken)` 必须：

1. 先消费 token，重复调用一律 `stale_state`；
2. 按当前状态完整重算 preview，不信任 token 内的展示值；
3. 先验证容量、等级、点数和教师上下文，再开始写；
4. 以备份/回滚保护 `_root.技能点数` 和目标技能行；
5. 学习成功后才扣点，任何失败保持点数和技能表均不变；
6. 成功后 dirtyMark、被动/动态技能数据重算、revision 增长，并返回完整 snapshot；无 hero 时按 §4.5 延迟投影。

不得继续调用“先扣点再赌 `_root.学习技能` 成功”的旧顺序。必须抽取无 UI 消息副作用的领域函数，并提供 `legacyLearnCommit` root bridge；旧教师确认按钮不得自行预扣技能点，仍可写的观察期 fallback 必须整体委托该桥。

### 5.4 wire JSON 序列化边界

真实 `skills.xml` 描述包含多行文本、反斜杠和 `<font color="#...">` 一类双引号。现役 `LiteJSON.stringify` 对字符串不作 JSON 转义，`FastJSON` 又按对象身份缓存，二者均不得用于 Skill 动态 response。`技能系统_WebView.as` 固定使用 `JSON.as`（或经同等 fixture 证明的无缓存 encoder）：领域 metadata 原文不被修改，wire 投影先确定性剔除禁用的 C0/C1/NUL（仅保留 CR/LF/tab），再正确转义引号、反斜杠、CR/LF 与 tab，并只序列化一次。任何 stringify 异常返回可诊断失败，不得发送半截 JSON。

S2A Gate 必须从真实数据抽取：多行 description、HTML 属性双引号、反斜杠、CR/LF/tab、禁用 C0/C1、中文和 4096 边界字符串；输出须由 C# `JObject.Parse`/标准 JSON parser 成功解析，并对合法字符逐字还原、对禁用控制字符得到冻结的剔除结果。尤其要覆盖“写已成功但 response 序列化失败 → reconcile snapshot 仍可成功”的恢复路径，避免永久卡门。

## 6. 协议闭环（已落地 v1）

统一约定：

- skills 业务消息顶层只允许 `{type, panel, domain, cmd, callId, panelInstanceId, payload}`，所有业务字段及 `v` 必须位于 `payload`；全局 panel close 与 `switch_manage/switch_trainer` 使用 §3.4 的独立 panel-control envelope，不经过 Skill 业务 domain route，但两个切换命令的展示字段仍只准位于嵌套 payload；
- C# → Flash action：下表 `skill*`；
- Flash 回包：`task="skill_response" + numeric callId`；
- C# → Web：重建为 `type="panel_resp", domain="skills", cmd, original web callId`；
- 所有业务请求的 `type/panel/domain` 必须精确为 `panel/skills/skills`，`payload` 含 `v:1`；顶层业务字段、未知顶层键、非 object payload 和命令不允许的 payload 字段均返回 `invalid_payload`。C# 只从 payload 白名单重建新对象，绝不把原始对象透传到 AS2。

完整 `equip` 请求固定为：

```json
{
  "type": "panel",
  "panel": "skills",
  "domain": "skills",
  "cmd": "equip",
  "callId": "skills.7.12",
  "panelInstanceId": "skills.instance.7",
  "payload": {
    "v": 1,
    "skillKey": "闪现",
    "slot": 4,
    "expectedRevision": 12
  }
}
```

例如把 `skillKey`、`slot`、`expectedRevision` 或 `v` 放到顶层，即使值合法也必须拒绝。

trainer→manage 控制请求固定为：

```json
{
  "type": "panel",
  "panel": "skills",
  "cmd": "switch_manage",
  "panelInstanceId": "skills.instance.12",
  "payload": { "v": 1, "focusSkillKey": "闪现" }
}
```

返回教师使用完全同形的 `cmd:"switch_trainer"`，但只接受 `canReturnTrainer` 对应的当前 manage 实例。两个 envelope 都不带 `domain/callId`，不是 AS2 业务写；Host 必须拒绝旧实例、错误 view、顶层 `focusSkillKey`、未知键、非整数 `v` 与控制字符。`switch_manage` 使旧 learnToken 作废并把 session 暂存 Host；manage initData 只含 `canReturnTrainer:true`。`switch_trainer` 从 Host 恢复 session，Web 不上传 session。两者都不调用 equip，也不向 AS2 透传 `focusSkillKey`。

| Web `cmd` | Flash action | 写？ | 必需 payload | 成功回包核心 |
|---|---|---:|---|---|
| `snapshot` | `skillSnapshot` | 否 | `view`, `trainerSession?`；对账时成对增加 `reconcileId,reconcileAfterCallId` | 完整 `snapshot` |
| `learnPreview` | `skillLearnPreview` | 否 | `skillKey`, `desiredLevel`, `trainerSession`, `expectedRevision` | 预览 + `learnToken?` |
| `learnCommit` | `skillLearnCommit` | 是 | `expectedLearnToken` | `changed:true` + 完整 `snapshot` |
| `equip` | `skillEquip` | 是 | `skillKey`, `slot`, `expectedRevision` | 完整 `snapshot` |
| `unequip` | `skillUnequip` | 是 | `slot`, `expectedRevision` | 完整 `snapshot` |
| `moveSlot` | `skillMoveSlot` | 是 | `sourceSlot`, `targetSlot`, `expectedRevision` | 完整 `snapshot` |
| `setPassive` | `skillSetPassive` | 是 | `skillKey`, `enabled`, `expectedRevision` | 完整 `snapshot` |
| `reorder` | `skillReorder` | 是 | `skillKey`, `targetIndex`, `expectedRevision` | 完整 `snapshot` |

### 6.1 snapshot 形状

示意形状如下；实现时 C# 测试需逐字段验证类型、范围和数组上限：

```js
{
  success: true,
  v: 1,
  revision: 12,
  view: "manage",
  player: { level: 35, skillPoints: 240, easyMode: false },
  learned: [{
    skillKey: "闪现", orderIndex: 2, level: 3, maxLevel: 10,
    type: "武术-内力", passive: false, equippable: true,
    enabled: true, equippedSlots: [4], unlockLevel: 15,
    unlockSP: 20, upgradeSP: 20, mp: 14, cooldownMs: 1700,
    iconKey: "闪现", description: "...",
    stateHealth: "ok", writeBlocked: false
  }],
  loadout: [
    {slot: 1, skillKey: null, keyLabel: "空格", stateHealth: "ok", writeBlocked: false},
    {slot: 2, skillKey: "闪现", keyLabel: "Q", level: 3, iconKey: "闪现", stateHealth: "ok", writeBlocked: false}
  ],
  trainer: null,
  diagnostics: []
}
```

`view=trainer` 时只允许以下单一完整结构，不再支持纯 `skillKey[]`：

```js
trainer: {
  session: "opaque-token",
  entries: [{
    skillKey: "闪现", currentLevel: 0, maxLevel: 10,
    type: "武术-内力", passive: false, equippable: true,
    unlockLevel: 15, unlockSP: 20, upgradeSP: 20,
    mp: 10, cooldownMs: 2000, iconKey: "闪现",
    description: "...", stateHealth: "ok", writeBlocked: false
  }]
}
```

`TrainerEntry` 必须足以独立渲染未学习技能，目录按教师权威顺序输出并按 `skillKey` 去重（保留首次出现并记录重复目录诊断）。C# 逐字段验证形状与上限但不自行查 XML。`learned` 最多 80 且每个 `skillKey` 只出现一次，`loadout` 必须恰好 12，教师目录最多 80，防止异常回包撑爆 Web。坏存档重复行通过唯一 learned 投影的 `stateHealth/writeBlocked` 和 `diagnostics:[{code:"duplicate_skill_rows",skillKey,rowCount}]` 表达，不把物理行句柄暴露给 Web。

槽指向 unknown/unlearned 技能时仍返回完整槽对象：`skillKey` 保留原值，`level/iconKey` 为 null，`stateHealth:"unknown"`、`writeBlocked:false`，允许用户调用安全 `unequip`；槽指向 duplicate key 时 `stateHealth:"duplicate"`、`writeBlocked:true`。不得用缺字段对象让 Web 猜坏槽语义。

`learnPreview` 的三类响应冻结为：

```js
// 可提交的业务预览
{success:true, v:1, trainerSession:"...", skillKey:"闪现",
 currentLevel:0, desiredLevel:1, cost:20, revision:12,
 canCommit:true, blockingError:null, learnToken:"..."}

// 确定性的业务拒绝：仍是成功解析的 preview，不发 token
{success:true, v:1, trainerSession:"...", skillKey:"闪现",
 currentLevel:0, desiredLevel:1, cost:20, revision:12,
 canCommit:false, blockingError:"insufficient_sp", learnToken:null}

// 协议/会话失败
{success:false, v:1, error:"trainer_session_expired", revision:12}
```

所有写成功统一返回 `{success:true,v:1,changed:Boolean,revision:Number,snapshot:Object}`。Host 除深层 schema 外还验证命令效果：equip 的目标槽必须命中请求 skillKey，unequip 目标槽必须为空，setPassive/reorder/learnCommit 必须与请求及 `changed` 语义一致；业务拒绝固定 `success:false,error,revision` 且不带伪 snapshot。Host 的 PendingRequest 必须保存原请求 `view/trainerSession/skillKey/slot/desiredLevel/expectedRevision/panelInstanceId/writeEpoch`，不能只存 callId/cmd。

### 6.2 错误码与恢复

稳定错误码至少包括：

| 错误 | 含义 | Web 行为 |
|---|---|---|
| `invalid_payload` / `unsupported_cmd` | 协议非法 | 保持快照，显示错误，不重试 |
| `skill_not_found` / `not_learned` | 技能不存在或未学 | 请求 snapshot |
| `stale_state` | revision/token 过期 | 清本地预览，snapshot |
| `trainer_session_expired` | 教师上下文失效 | 保留目录与最后快照，进入不可操作的解释终态；提示返回游戏重新对话，不自动关闭面板 |
| `level_locked` / `insufficient_sp` / `max_level` | 业务拒绝 | 保留权威状态，刷新预览 |
| `initial_level_must_be_one` | 未学技能请求直接升到 2 级以上 | 保留权威状态，把目标等级重置为 1 |
| `skill_table_full` | 新学但 80 行已满 | 不扣点，提示整理/停止 |
| `already_equipped` / `not_equippable` | 装备规则拒绝 | 保留快照 |
| `corrupt_skill_state` | 重复行或其他不可唯一定位的坏档 | 禁用该技能写操作与施法，引导显式修档 |
| `service_not_ready` | 技能静态数据/存档上下文尚未加载 | 只读短退避；写不自动重投，不生成坏档诊断 |
| `reconcile_required` | Host 仍有未知写待对账 | 只允许显式 reconcile snapshot 或关闭 |
| `busy` | AS2 单飞保护 | 短提示，不自动重投写 |
| `malformed_response` / timeout / disconnect | 结果未知 | 若为写则进入 `needs_reconcile` |

#### 6.2.1 写结果分类

Host 必须给每种失败派生 `requiresReconcile`，Web 不按 error 字符串自行猜：

- client 未 ready、请求确定未发送：确定失败，回 idle；
- AS2 明确返回白名单内零写业务拒绝：确定失败，回 idle；
- AS2 明确 schema 完整的成功/changed:false：确定结果，应用权威 snapshot；
- send 返回 false、Host timeout、socket 断开、成功回包 malformed、未知 error：可能已执行，进入 `needs_reconcile`；
- Web 本地 send throw/client timeout：Web 立即进入 needs，并发显式对账；即便 Host 尚处于 `write_pending` 也必须可收敛。

#### 6.2.2 显式 reconcile 握手

单靠“进入 needs 后递增 generation”不足以处理 Web/Host 超时顺序反转。冻结如下握手：

1. Host 是 `writeEpoch/writeState` 的唯一 SOT；每接受一个写先递增 `writeEpoch`。Web 对某写结果未知时生成 `reconcileId`，发送 `snapshot`，payload 同时带 `reconcileAfterCallId=<原写 callId>`。
2. Host 收到该请求时，若目标写仍 active，合并/排队唯一 probe，直到写得到确定或未知终态后再向 AS2 派发 snapshot；不得在 `write_pending` 中先读。目标写已离开 active/recent 表时立即派发，但仍以当前 writeEpoch 为水位。
3. schema 完整且确实在目标写终态之后取得的 snapshot 才由 Host 回写 `reconciled:true,reconcileId,writeEpoch,panelInstanceId` 并清 needs。普通 snapshot、learnPreview、旧实例、ID 不匹配或写前在途读永远不能清门。
4. Web 只接受当前 `panelInstanceId`、匹配 `reconcileId` 且 `reconciled:true` 的 snapshot 退出 needs；任何未知写都不自动重发。关闭重开/断线后的新 Web session 可从 Host 的 `writeState/writeEpoch` 继续对账，不要求记住旧 open generation。
5. Host 默认写 timeout 10 秒、Web timeout 12 秒，但正确性不得依赖该顺序；测试必须强制反转为 Web 先 timeout，并覆盖“probe 先到、写后成功、原成功回包被 Web 丢弃、queued snapshot 收敛”。

#### 6.2.3 普通迟到读与并发矩阵

Host 在所有 Web response 增加 `panelInstanceId/writeEpoch`。Web 保存 `lastAppliedRevision/lastAppliedWriteEpoch`：revision 下降、panel instance 不同，或 snapshot 的 captured writeEpoch 小于最近已应用写的回包一律丢弃；固定覆盖 `R1 snapshot → W 成功并应用 → R1 迟到`，即使当前不在 needs 也不能回滚 UI。

| Host 状态 | ordinary snapshot | learnPreview | 写 | reconcile snapshot |
|---|---|---|---|---|
| `idle` | 最多 1 个 | latest-wins，最多 1 个 | 最多 1 个 | 允许，立即派发 |
| `write_pending` | `busy` | `busy` | `busy` | 合并为 1 个，写终态后派发 |
| `needs_reconcile` | `reconcile_required` | `reconcile_required` | `reconcile_required` | 唯一允许的领域请求 |

每个 SkillTask 总 pending 上限 4（snapshot 1 + preview 1 + write/probe 1，余量 1），active/recent callId 合计最多 256，recent 保留 120 秒；超限确定性返回 `busy`，不得继续创建 timer。

### 6.3 C# 严格边界

`SkillTask` 参照 `CraftingTask` 的 request mux，但使用独立白名单与下列 v1 唯一 oracle：

| 字段 | v1 限制 |
|---|---|
| web `callId` | `[A-Za-z0-9._-]{1,96}`；active/recent 重复均拒绝 |
| `trainerSession/learnToken/reconcileId/panelInstanceId` | `[A-Za-z0-9._~-]{1,160}`；opaque，不解码 |
| `skillKey/iconKey` | 分别 1..64 / 1..128 个 .NET UTF-16 code unit；不 trim/归一化；禁止首尾空白、C0/C1 和 NUL |
| `view` | `manage|trainer`；manage 不接 trainerSession，trainer 必须有 session |
| 整数 | `slot=1..12`，`targetIndex=0..79`，`desiredLevel/maxLevel=1..100`，`revision/writeEpoch=0..2147483647` |
| 玩家/成本 | level 0..9999；skillPoints/unlockSP/upgradeSP/cost 0..2147483647 |
| 动态数值 | `mp` 为有限数 0..1000000；`cooldownMs` 为整数 0..86400000；NaN/Infinity 拒绝 |
| 文本 | `type` 1..64，`keyLabel` 0..32，`description` 0..4096；全部禁止 NUL/C0（description 允许 CR/LF/tab） |
| 数组 | `learned<=80`、`trainer.entries<=80`、`loadout==12`、`diagnostics<=32`、`equippedSlots<=12`；exact key set |
| 枚举 | `stateHealth=ok|invalid|duplicate|unknown`；diagnostic code 只准 `duplicate_skill_rows|duplicate_trainer_entry|invalid_skill_row|invalid_boolean|unknown_skill|invalid_trainer_entry|tail_data|renderer_failed|metadata_mismatch` |

当前 XML 的有效 `MaxLevel` 不超过 20，但 wire 上限保留 100，最终仍由 AS2 metadata 判定。Host clone 回包后删除 `task`，覆盖 `type/panel/domain/cmd/callId/panelInstanceId/writeEpoch`，不得让 Flash 伪造路由字段；任何未知 request/response key 都拒绝。close 始终先于 domain route，未知 domain 不能落入 legacy 全局 cmd。

### 7.2 两个生产入口

`Bridge.send` 在这里仅报告 WebView2 本地 transport 是否成功调用：显式 `false` 保持当前 NPC/管理页并提示连接不可用，`true` 或兼容性的 `undefined` 都不能当作 Host 业务受理。切换消息投递后锁定按钮并等待新 `panelInstanceId` 的 same-panel rebind；3 秒未 rebind 则恢复原页与重试入口。trainer session 是否仍可返回继续由 Host 暂存能力和 AS2 快照校验裁决，Web 不依据 transport 返回值猜测教师失效。

1. 我的技能：`NotchWidget.cs` 与 legacy fallback `NotchOverlay.cs` 的“游戏”工具栏都提供 `技能 / SKILLS`，Character Build 的“技能配置”在 exact retire/recovery settled 后复用同一入口。Router 先建立 typed manage capability 并发送 `{action:"skillPanelOpen",openRequestId}` 做 game-ready / socket / Skill service preflight；AS2 对新 Host 的显式 ID 只接受严格 opaque 值，并把它原样回显到唯一真实 open `panel_request panel=skills,source=nativehud,initData.view=manage`。Router 仅在 nonce、source、view 与 panel baseline 全匹配时消费，再白名单重建 `{mode:"runtime",source:"nativehud",debug:false,view:"manage"}`；该形状没有 `trainerSession` 或 `canReturnTrainer=true`，不创建、恢复或继承教师 session，故两个入口都只能管理自身已学技能与配置。send-false、timeout、Web navigation、socket disconnect 或 competing panel 撤销 capability，迟到或无 nonce 响应不得打开。AS2 暂时接受旧 Host 不带 `openRequestId` 的命令，只发不带 nonce 的 `nativehud/manage`；新 Host 仍拒绝该回包。不得由 Router 同时直接 open 形成双入口竞态；preflight 失败只 toast 并在观察期提示旧物品栏回退。这与“情报”同属 Launcher 独立入口，不先发 AS2 `openEquipUI`，也不经过物品栏。
2. 教师技能：主 FLA NPC 按钮优先调用 `SkillPanelService.openTrainer(_root.gameworld[当前NPC], "world_skill_trainer")`；该请求不得携带 `openRequestId`，Router 只在没有待消费 manage capability 时接受 exact `source=world_skill_trainer + view/trainerSession`，再重建 `{mode:"runtime",source:"world_skill_trainer",debug:false,view:"trainer",trainerSession:"..."}`。教师请求不能抢占或取消 Notch/Character 的“我的技能”等待，`nativehud+trainer` 与 `world_skill_trainer+manage` 均拒绝。创建会话或发送失败在观察期进入已改造为 service bridge 的旧学习 UI；不得把原始目录、mode/source/debug 从 AS2 透传。
3. 面板内切换：trainer 顶栏提供“管理技能”；Host 验证当前 trainer 实例后，以 `view=manage,focusSkillKey?,canReturnTrainer=true` 建立新实例，清空 learnToken 并在 Host 内暂存 session。只有这个派生 manage 实例显示“返回研习”，返回时 Host 复验当前实例并恢复同一 session；NativeHud 直接 manage 不显示。关闭、切走或断线会清理暂存 session，之后仍须重新与 NPC 对话。

入口改造分别属于：

- Launcher C#：`NotchWidget.cs`、`NotchOverlay.cs`、`LauncherCommandRouter.cs` 及对应布局/路由测试；不触发 Flash XFL 发布；
- `CRAZYFLASHER7MercenaryEmpire/CRAZYFLASHER7MercenaryEmpire.xfl` 主 FLA 发布目标。

旧物品栏“技能”按钮在观察期保持原 Flash 行为，**不**改成 `panel=skills` 转发器；S6 随旧技能页一起退役。教师入口不能以“改了 AS2”代替主 XFL 发布。入口切换放到最后一个功能 Gate 后，C# 与主 XFL 分别验证，不能混称同一个编译目标。

### 7.3 回退策略

- S0–S4 期间旧入口保持默认，新面板只通过测试命令/显式开发入口打开。

Flash 验证必须按目标归属执行：AS2 服务优先 `asLoader` + tracked aggregate 生成的 TestLoader 新鲜 trace；S4C/S6 修改独立物品技能/玩家信息 UI 时分别发布对应 XFL/SWF；教师按钮或主库 linkage 改 main 才使用 `main`；既有 things linkage 改 `things.xfl → things.swf`。`publish_done.marker` 不能单独作为成功证据。

## 11. 风险与停止线

| 风险 | 影响 | 停止线 / 缓解 |
|---|---|---|
| 学习扣点与写技能非原子 | 永久损失 SP | S4A 未证明所有失败零写入前，不切教师入口 |
| 未学技能允许目标等级大于 1 | 只付一次解锁费直升高等级 | v1 强制 `currentLevel=0 => desiredLevel=1`，负例必须零写入 |
| 重复技能行仍按 skillKey 写 | 排序/装备/被动/施法命中不确定行 | snapshot 唯一诊断投影；涉及坏 key/行的操作 fail-closed，v1 不自动修档 |
| HUD 仍是技能描述符权威 | NativeHud 删壳后无法施法 | S1 Gate 未过，不进入管理入口切换 |
| 领域副作用仍直连 HUD | HUD-null 时学习/装备成功链空引用 | S1 拆领域重算与两类可选 renderer，完整事务做 null Gate |
| EasyMode 重复技能被误禁或状态错乱 | 行为回归/被动错误 | 以“多槽计数派生标志”建模并做真机用例 |
| 混合被动被压成纯主动/纯被动 | 技能失效 | 始终保留 `passive` 与 `equippable` 两个正交字段 |
| timeout 后重投学习 | 重复扣点/升级 | token 一次性；未知写只 snapshot，不重发 |
| Web/Host 超时错位或旧 snapshot 清 reconcile | 未知写永久卡门或被旧状态覆盖 | Host writeEpoch + `reconcileId/reconcileAfterCallId`；写定局后派发，Web 只认当前实例匹配 probe |
| 教师目录由 Web 伪造 | 越权学习 | 目录只留 AS2 session，C# 不接受原始 catalog |
| 把教师稀疏 Object 当 Array | 全部 trainer 会话创建失败 | 数字键 0..79 升序归一化，同时兼容真 Array |
| LiteJSON 发送真实 description | 非法 JSON，写后无法对账 | Skill wire 固定正确 escaping encoder，标准 parser 特殊字符 fixture |
| trainer 同时容许 key/对象两种结构 | 未学技能不可渲染、Host fixture 无法冻结 | v1 只允许完整 `TrainerEntry[]` |
| Flash linkage iconKey 透传 Web | 全部技能图标进入 fallback | `iconKey=skillKey`，按 manifest 精确查表 |
| 换装重置槽冷却 | 无 CD 连发 | 管理写禁止触碰 ManualCooldownService 状态 |
| 刘海屏新增第六按钮挤压/双实现漂移 | 1024×576 溢出或 Native/legacy 行为不一致 | 两套按钮表同改，固定 game-ready、几何、窄宽度和命中测试 |
| legacy 写绕过 revision | 陈旧 Web 写覆盖新状态 | 共存期 signature 探测；入口切换后收口生产写 |
| 观察期旧 UI 仍直接写 root | 扣点/装备绕过原子事务和坏档门 | S4C 所有可写 fallback 委托 root bridge，否则降只读；未过不得 S5 |
| 同名 skills open 被 no-op | manage/trainer 或教师会话分叉 | panelInstance + same-panel rebind；pending write 后置切换 |
| trainer A/B scoped cleanup 被 last-wins | Host gate 已开但 AS2 active/candidate capability 残留到 TTL | active+candidate 双跟踪；不同未发送 scoped intent 收敛 global；超时重试前 gate 不开 |
| TestLoader scratch runner 被当交付物 | 换机/PR 无法复现 suite | tracked aggregate/template + 临时生成/恢复脚本 + fresh trace hash |
| linkage 双导出误判 | 旧 UI/图标发布异常 | 已由编译产物字典解析 + slot0/slot1 live 互斥指纹确认 main 本地 id53；S6 仍须消解重复导出并做真机回归 |
| 单 PR 同改 AS2+C#+Web+XFL | 无法定位回归 | 严格按 S1/S2A/S2B/S2C/S3A/S3B/S4A/S4B/S5 切片 |

若任一写路径仍需要 Web 直接传 `_root.主角技能表` 行、NPC 原始技能目录、HUD MovieClip 路径或 inventory lease，视为架构偏离，停止实现并回到领域边界复核。
