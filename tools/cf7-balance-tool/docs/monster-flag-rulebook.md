`<标识>` 是**设计侧溯源标注**：全仓检索 `.as/.cs/.ts/.js/.json` 均未发现运行时代码读取 `档次系数` 等字段，游戏只读模板里的面板数值。
所以补写或修正 `<标识>` 不会改变游戏数值，属于低风险改动；反过来说，标识写错也不会立刻在玩法里暴露，必须靠复算偏差发现。

## 2. 十项系数与面板的可辨识性

工作簿用 C~L 十列算出 N~W 八项面板加金币/K 点价格。反推时「面板能定住谁」决定工具能给什么、不能给什么：

| 系数 | 工作簿列 | 能否由面板定 | 依据与精度 |
|------|----------|--------------|------------|
| 阶段 C | C | **能**（不靠面板） | 首次出场关卡反查，见第 3 节 |
| 档次系数 D | D | **拟合的四个自由量之一，但只落在档次取值网格上** | 它是设计判断（样貌与招式），面板只能给「最贴这块面板的那一档」。搜索网格是 Excel 档次表的词表按同一粒度往两端接出来的（`tierFitCandidates`：**0.1~0.9 每 0.1、1~10 每 0.5、11 起每 1**），细扫只在粗格最优的邻域内挪（`TIER_REFINE_RADIUS`），所以不会写出 19.36 这种不在词表上的值。**参考区间 1~25 不是这个网格的边界**（2026-10-06 制作组口径：Excel 给的区间只是正常情况的范围）：解顶到初始网格上界 25 时按 25 个整数一档的块继续往上加长（硬上限 200），解要低于 1 时也照样往下探；两种越界只报警不夹紧，账见本节末。制作组点名的档次（配置 `humanTierFactors`）或人工权威里的 档次系数（HEAD 已提交、且不是标识来源台账登记的工具自写格）一律钉住、退出搜索；拟合出来的档次只在该模板从没被人工定过档时才写盘。**唯一的例外**是配置 `estimatedTierTemplates` 点名的行：制作组认定人工权威里那颗档次只是当时**预估**，于是只摘掉 `档次系数` 这一项放回搜索、重算值照写回，同一行其余人工权威标识（含 `阶段`）照旧钉住（2026-10-07 口径，现点名 `敌人-双喷少女`、`敌人-特警僵尸`）|
| 成长系数 E | E | **能，与 D、J、L 联立** | 六项面板（空手攻击力 min/max、hp min/max、基本防御力 min/max）一起进误差，目标是相对误差的均方根；四项自由量一次联立解，不逐通道各解一次再取均值（2026-10-05 试算：逐通道各解更差，空手MAX、HPmax 两条要靠 成长系数 上探到 8.9~13.5 才贴得住，而那已经是不可信的档次）。经验 min/max **不进误差**，只随结果给一份复算对照 —— 制作组口径是「经验可以随时按标识重算，也不需要考虑成长」 |
| 攻速系数 | F | **不能** | 攻速系数、攻击倍率、段数系数在空手攻击里只以乘积「攻击倍率 × √段数系数 × 1.2^(攻速系数-3) × 1.1^(速度系数-2)」出现，面板只能定住这个乘积。本表「工作簿列」那一列的字母只是 Excel 里的列号，不是这三个系数的别名。取值改由实测：**前摇为主、后摇按分量折进去**，比较值是 `前摇均值 + 后摇均值 × attackTempoTailFactor`（现 0.2），档位门槛同步放宽 `(1 + attackTempoTailFactor)` 倍，所以常量表仍是 `<9` 极快=5、`9~16` 快=4、`16~26` 中等=3、`26~41` 慢=2、`≥41` 极慢=1（上界不含，正好 16 帧起算中等），门槛写在 `attackTempoBands`。前摇 = 招式起始帧到第一个子弹实例，后摇 = 末子弹帧到该招 `_parent.动画完毕();` 所在帧（找不到就退到段尾并标疑点） |
| 攻击倍率 | G | **不能** | 同上，由 `monster-attack` 量每次命中的 `子弹威力` 表达式：物理=1、法伤/元素×2、真伤×3，固定值伤害按面板均值折算并标疑点 |
| 段数系数 | H | **不能** | 同上。段数 = 一次攻击里所有子弹实例的 `霰弹值` 之和（没写 `霰弹值` 的子弹按 1 段；一颗子弹里多次 `霰弹值 = n` 取均值，`+=` 才算追加，`最小霰弹值` 不计）。一次攻击的次数量的是**子弹跨度**（首子弹帧→末子弹帧）而不是整段动画长：跨度不满 `attackSegmentWindowFrames`（现 15 帧，2026-10-05 定案）算 1 次，满了按 `跨度 / 窗口` 取小数、不再 ceil 补成整数；该招段数 = 总段数 / 总次数，再对所有招式取均值。**加总的颗数只算打得中玩家的那部分**（`meleeSegmentRules`，只对近战类子弹生效，见下面的近战子弹有效颗数一节）；每颗子弹的 `霰弹值` 还要乘它自己的**穿刺倍数**（`pierceSegmentRules`：穿刺 ×2、次级穿刺 ×1.5，见下面单独一节）|
| 速度系数 I | I | **能，但只按定义取，不参与拟合** | I 的定义就是移动速度档次：工作簿 D15 的 10~40 慢=1、40~60 中=2、60~90 快=3，**取 `速度_min` 与 `速度_max` 的均值落在哪一档**，区间上限归本档（均值正好 60 读 2）。现存 9 例人工标注实测：均值读法 8/9、`速度_min` 6/9、`速度_max` 2/9。区间跨两档时另给两档中点候选（如 50~75 → 均值档 3、中点 2.5），体育老师这类实操标 2.5 的怪取中点。取值次序是**行内已有值 > 移动速度定义档 > 工作簿默认值**：面板不再反解速度系数去覆盖定义档，`solveSpeedFactorFromDefense` 这条校验通道已随四元联立一起去掉了。标识里的 2.5 与定义档 3 不合，现在由 全量表 的「误差值」现形（体育老师 5.1%），不再单设一条报警 |
| 高攻低血防系数 J | J | **拟合的四个自由量之一** | 主要由 基本防御力_min 支撑，与 D/E/L 同批联立；人工给过（人工权威里的格，或 `humanTierFactors` 点名）才钉住。面板与标识本来自同一套公式时六项能贴到 0.2%（`敌人-爆胖僵尸`），实测残差地板见本节末 |
| 霸体系数 K | K | **能，从元件观测** | 五档定性（长击退可击飞 1／短击退可击飞 2／长击退不可击飞 3／短击退不可击飞 4／不可击退不可击飞 5）由 `monster-attack` 从容器时间轴量出来，判据见第 10 节。它现在属于观测系数（`MONSTER_OBSERVED_COEFFICIENTS`）：**盘上有值就钉住，没有就按默认值参与拟合并进未定清单，反推通道不产出它**。HP 公式里的霸体乘子分支（`superArmorHpFactor`）是解释误差地板的关键，见本节末。韧性系数高于 20 时每 20 点加 0.1（上限 0.5），是人工小数位（1.1、2.3）的来源 |
| 高防低血系数 L | L | **拟合的四个自由量之一** | 主要由 基本防御力_max 支撑；它与 J 在防御两式里以乘积与比值出现，所以只给一项防御字段时 J、L 会互相补偿 |

**依赖链**：`C 由首次出场关卡反查或人工判定 → I 由移动速度按 D15 定档 → 攻速系数/攻击倍率/段数系数/霸体系数 由 monster-attack 观测 → D、E、J、L 由六项面板四元联立`。
链条前段钉得越死，后段四项的解才越有意义；观测项缺值时按工作簿默认值参与拟合，同时进 `unresolved`，写回侧据此**把这几格留空**（`敌人-雪女`、`敌人-异形蛋` 就是缺 攻速系数/攻击倍率/段数系数 的观测，全量表 那三列是白格）。
面板方程数少于自由量时不报错但要报警：结果里 `equations < freeCoefficients` 会顶出「方程数少于自由量，解不唯一，误差小不代表标识可信」，一行只剩空手两项时四元联立照样能给出一组零误差的系数，那不代表标识可信。
链条上任一环缺失，工具就退回「只登记缺什么」，不会伪造结论。
攻速系数/攻击倍率/段数系数/霸体系数/速度系数 走观测或定义通道，**反推通道一律不产出这五项**（`toolFlagProposal` 只写机械项与本次真正拟合出的自由量），缺观测的项由 `unresolved` 显式列出来。

**反推值超出参考区间时按实算登记，不夹紧（2026-10-05 口径变更，人工裁定）。**
区间（档次 1~25、成长 0.2~5、高攻低血防 0.5~2、高防低血 0.1~10、速度 1~3、霸体 1~5.5、攻速 1~5、攻击倍率 0.5~3、段数 1~10）是**判断算出来的值合不合理的参考区间，不是硬边界**：
拟合不做 clamp，越界项集中进结果的 `outOfRange`，由 `monster-flags-csv` 落成超范围表，人工决定放宽区间还是回改面板数值。
成长区间的下界 0.2 与上界 5 是制作组 2026-10-05 放的宽：工作簿推荐 0.5~2，但按面板实算要 0.2~5 才谈得上合，「其他系数也是，不必严格限定死范围」。
**2026-10-06 把这同一条口径落到 档次系数 的搜索空间上**：档次不再只在 Excel 档次表的 1~25 里找（见第 2 节那一行），
网格下到取值词表下界 0.1、上到按块加长的 200，越界只登记不夹紧。表上现量的档次越界就是这一放的开的账：**22 行低于 1**（最浅 0.3、最深 0.9，多为早期阶段的弱怪与异形幼虫），**6 行高于 25**（`武士铁血战士`/`唐装剑侠` 27、`dude` 29、`拼命之王` 30、`人修罗` 32、`EXUSIAI指挥官` 36）。
`<标识>` 不被运行时代码读取，所以越界值只影响工具结论、不影响游戏数值；反过来夹紧会把面板误差伪装成反推误差。
工具识别的 143 行里 **66 行有越界项**（逐系数计数与拆表前一致 —— 人工完整打标那 27 行没有一行越界，所以移出统计面不改动这一格）：高攻低血防系数 31 行（面板给的攻防差比 Excel 参考带宽得多）、档次系数 28 行、攻击倍率 13 行、段数系数 11 行（这两类越的是**这一格自己写的值**，如 `武士铁血战士` 段数 15.8、`方舟护士` 倍率 20.1；`铠甲勇士` 3.8 与 `拼命之王` 3.9 则是 §9 的人工折算值）、高防低血系数 1 行。
**成长系数 0 行**（上一批是 2 行、最高 12）：放开档次之后量级由档次自己承担，成长回到了区间内 —— 越界项之间会互相补偿，逐系数放宽看不出来。
超范围表数的是**写进标识的那个值**，所以连续解越界、归档到词表后不越界的行不进表（`敌人-终结者T800` 的高攻低血防连续解 0.496、归档成 0.5 就在区间内）——这不是漏行。
**误差的地板不在夹紧上**（这条归因在取消夹紧的那轮已被否掉，四元联立之后仍在）：贴不住的行最差项普遍落在 HP 与 空手攻击，
根因是工作簿的霸体乘子分支最多只能把 HP 挪到 0.89~2 倍（`superArmorHpFactor` 两个分支的极值），
而 `诺亚狙击兵`、`方舟爪豪` 在人工档次上需要 5.8~9.2 倍、在面板最优档次上需要 58~79 倍，HP 面板与该档次的公式不在同一量级——
这一类行的正确处置是回查面板 HP 或阶段/档次，而不是继续调系数。
制作组点名的 11 行档次按**表上口径**（归档取档后的标识复算，2026-10-07 现量）误差 4.9%~24.3%（`方舟兽王` 4.9% / `EXUSIAI指挥官` 7.4% / `方舟收割者` 7.6% / `诺亚地狱三头犬` 8.6% / `诺亚突击兵` 10% / `诺亚重装兵` 11.8% / `诺亚狙击兵` 15.3% / `拼命之王` 17% / `人修罗` 20.2% / `方舟爪豪` 21.2% / `A兵团改造人` 24.3%）。
这 11 行**不论过不过门槛都无条件进偏差大表**，就是为了不让门槛把人工判定挡住。
这一列此前写的是 11.3%~57.3%，那是 2026-10-05 档次还被 `humanTierFactors` 钉住时的解；放开档次之后没有整批重出过对照，本批才按现量刷新 —— 降幅里既有档次进搜索的贡献也有本批 4 行重算的贡献，不再拆分归因，只认现在这组数。

## 3. 阶段反查规则（已实现）

优先级从高到低：

1. 模板已标 `阶段` → 直接沿用，不再猜。
2. **主线关卡**：该关卡对应的主线 id 落在 `mainlineBands` 哪个区间，就是哪个阶段。主线序号严格递增，分界明确。
3. **支线关卡**：取该支线链上最近的**前置主线 id**（支线本身没要求主线 id 时，用它链上前一个任务的），按区间定档后 **+1**。
4. **没有对应支线的关卡**：按关卡 `UnlockCondition` 反查最近主线 id，**+1**。
5. 主线 id 超过 `mainlineCompletedUntil`（现为 77，诺亚前后与雪山尚未划分）→ 记 `deferred`，不给阶段。
6. 在纳入统计的关卡里查不到注册 → 记 `unresolved`。

关卡目录到章节的归属写在配置的 `chapters` / `stageChapterOverrides` 里；
`excludedStagePatterns` 只排魔神图，按制作组口径**现役魔神图只有 菲尼克斯 与 锡蒙利**（`挑战人修罗`/`挑战混沌王` 是普通支线挑战副本，2026-10-03 已从排除名单移出）；
`excludedSourceFiles` 排除 `魔神.xml`（魔神图的怪不需要标识）。
被排除后若某模板彻底查不到出场，会列进普查的「无出场记录」，供人工确认排除没有过头。

**人工判定通道：`data/monster-flag-table.csv`（全量表）。** 旧的 `data/monster-stage-backfill.csv` 与 `npm run monster-stage-backfill` 已于 2026-10-05 删除（制作组口径：「原来的那个 csv 可以删了，后面都是全量查验和修改」）；那张表已经填好的阶段值此前就写进了各模板的行内 `<阶段>`，所以删表不丢判定。
上面 5/6 两条给出 `deferred`/`unresolved` 的行现在直接在全量表上人工补：**空格 = 这一项不改，填了数 = 这一项按填的写**，改完跑 `npm run monster-flags-table-apply`（默认 dry-run，`--write` 才落盘）。
取值次序不变，`行内 <阶段>` 始终最权威：想让工具重算就把单元格留空，想覆盖就填数；填了数又正好等于盘上现值时写回不产生差异。
非法文本（`后期`、`3.5`、负数）在读回时按列报错顶回去，不静默当成没填。

判定「**这一行根本不需要标识**」（分身、投影、召唤物、boss 的子件一类不挂面板的模板）不再靠往 CSV 里填 0，改成写进 `data/monster-census.json` 的 `noFlagTemplates`：

**各张表的排序**（2026-10-06 制作组要求，为了让同类连片、一眼看出问题）：
- **全量表 / 人工表**：**阶段从低到高（缺阶段排最后）→ 同阶段内按 档次系数 从小到大（缺档次排最后）→ 同一数据文件聚在一起 → 文件内按模板名**（`localeCompare(…, "zh")`；制作组 2026-10-06 第二次改口：档次是这条链上的第二眼信息，同阶段里先按档次从轻到重扫一遍才知道哪批怪该往上抬）。
  同一条阶段链上的怪常常出自同一份 XML，文件和模板名仍是末两级，能直接看出「同阶段同档次的怪哪一项系数齐不齐」。
  数据文件 仍参与排序，但**不再占列**（制作组 2026-10-06：这一列没用人工看）；人工表是人工权威标识的台账、要按文件回看 XML 原文，所以这一列在人工表上留着（连同 标识行 行号）。
- **超范围表**：**档次系数 越界的行整块排在最前**（档次超出参考区间是「面板比档次表还宽/还窄」这一类账，要先看），
  块内与其后的行都按**最严重那一格的超出倍数**降序，同倍数再按阶段升序、再按模板名。
  同日一度把这张表也改成按阶段排，那是把指令读错了对象，已按原口径回退（比较器 `byTierFirstThenExceedance`）。
  超出倍数 = 上界外 `值/上限`、下界外 `下限/值`，所以 `1倍` 是贴线、`2倍` 是差一个量级的一半；
  光有「越界」两字分不出轻重（段数 10.4 与段数 22.1 都算越界）。为此表上多给 **最越界的系数**、**超出倍数** 两列，
  「超出的系数与参考区间」那格也改成按倍数从大到小列。倍数与误差都按**表上印出来的精度**分桶比较，
  浮点尾差（4.2/3 与 2.8/2 差 3e-17，屏幕上都写 `1.4倍`）不许把看着同倍数的两行拆到两处。
- **偏差大表**：误差值降序，同误差按模板名。

**全量表列序**：`模板, 别名, 主线进度, 档次描述, 阶段, 档次系数, 成长系数, 攻速系数, 攻击倍率, 段数系数, 速度系数, 高攻低血防系数, 霸体系数, 高防低血系数, 超出范围, 误差值`。
除名字外只有十项系数；主线进度 与 档次描述 放在系数之前（紧跟别名之后，让这两格不用横向拖就能看到），最后两列是 超出范围（简述哪个系数越界、参考区间是多少）与 误差值（六项面板复算的相对误差均方根，经验两项不计入）。
回写按**表头列名**定位系数列，所以派生列（以及以后再加的只读列）在读回时一律忽略，删列加列都不破坏兼容。
`主线进度` 与 `档次描述` 是配置 `stageLabels`/`tierLabels` 的投影，对应 Excel 的阶次表与档次表：

| 阶段 | 主线进度 | 档次系数 | 档次描述 |
|------|----------|----------|----------|
| 1 | 废城 | 1 | 小型小怪 |
| 2 | 盗贼 | 1.5 | 中型小怪 |
| 3 | 军阀 | 2 | 大型小怪 |
| 4 | 总堂前期 | 3~4 | 低级精英 |
| 5 | 总堂后期 | 5~6 | 中级精英 |
| 6 | 诺亚前期 | 8~9 | 高级精英 |
| 7 | 诺亚后期 | 9 | 低级boss |
| 8 | 雪山 | 13 | 中级boss |
| 9 | 主线完结 | 16 | 高级boss |
| 10~15 | 主线后 | 20~25 | 顶级boss |

**档次描述的写法（2026-10-06 制作组改口径）**：每档只取**下限当门槛**（`3~4` 按 3 起算、`8~9` 按 8 起算，这样 `9` 只属于 低级boss 而不再同时命中 高级精英，也不会再一行并列两档），
命中门槛就是该档本名；落在两档之间按**就近档**给后缀 —— 离已达标那档更近写「已达标档+」（`3.5 → 低级精英+`），离更上面那档更近写「上面那档−」（`4 → 中级精英-`、`2.5 → 低级精英-`），
正好取中间算更上面那档（四舍五入进档）。低于最小档写「最小档−」（`0.5 → 小型小怪-`）、高于最大档写「最大档+」（`28 → 顶级boss+`）。
不再写「低于 小型小怪」「高于 顶级boss」「中级精英～高级精英 之间」这类长句，也不再用「／」并列多档。
这两列与 超出范围/误差值 都是**派生列**，`monster-flags-table-apply` 读回时一律忽略；改完整张表要重跑 `monster-census` + `monster-flags-csv` 才会重算。

**偏差大表的入选规则**：误差 ≥ 门槛（`--high-error-threshold`，默认 20%）的行，加上 `humanTierFactors` 里制作组点名过档次的行 **无条件全部列入** ——
档次是人工按样貌与招式钉的，面板合不上只能说明面板或阶段有问题，不能被门槛挡掉。现量 34 行里 23 行走门槛、11 行走点名（这 11 行没有一行是人工完整打标，所以拆表之后一个不少），表内「档次来源」列区分 制作组点名 / 已提交标识 / 拟合 —— 其中「已提交标识」说的是人工权威里那颗已提交的档次（HEAD 过台账之后仍算人工的格）。被 `estimatedTierTemplates` 摘掉预估档次的那两行在这里读 **拟合** —— 这一列说的是「这一档是谁定的」，摘出去就不再是人工权威那份钉住的档。

# 普查 + 面板四元联立反推：写 reports/monster-flag-census.json，同时出人工复核用 markdown（reports/ 已 gitignore）
npm run monster-census -- --free-tier         # 现量账都是这条模式跑的（盘上档次是放开档次解出来的），见下面 §4 的 ⚠

- 反推在 `monster-census` 这一步就算，查验表只是它的投影；改完全量表要 `monster-flags-table-apply -- --write` 再重跑 `monster-census` + `monster-flags-csv`，派生列（主线进度/档次描述/超出范围/误差值）才会跟着新系数重算。

- 一次性让 档次系数 也回到搜索空间：`npm run monster-census -- --free-tier`。它只摘掉配置 `humanTierFactors` 点名的档次，人工权威里的 档次 照旧钉住，观测五项不受影响；默认不加就是人工档次优先。人工权威里那颗档次被 `estimatedTierTemplates` 点名预估的行是唯一的例外，两种模式都放回搜索。
  **⚠ 这台机器现在的现役模式是 `--free-tier`**：盘上 档次 已经是放开档次解出来又写回的值，所以 census 与 `monster-flags-csv` 都必须用同一模式跑，否则读到的是一张不自洽的表。2026-10-07 踩过一次：写回两行档次后用默认模式重跑 census，11 行点名档次被旧值钉住去解其余三项、盘上却留着新档次，表上误差当场从 max 38.9% 涨到 77.3%（`敌人-A兵团改造人`）、>40% 从 0 行变 3 行，换回 `--free-tier` 才复现基准账。
  **用完要清账**：`humanTierFactors` 不会因为写过一次 `--free-tier` 而自动更新，下一次不带开关的重算会拿旧点名档次去解其余三项、却不覆盖 档次，那一行就会写成「新档次 ＋ 按旧档次解出的其余系数」的不自洽组合。采纳重算结果就删掉或改写对应条目。
- 写回只动 `<标识>` 块：已有叶子改文本，缺字段合并成一次插入，缺整块则插到模板闭合标签前，中文注释与其余排版保持原样；**同值重写不碰文件**，所以全量重算不会把没变的行也弄脏。
- 仅改数据 XML 通常重启游戏即可，不据此重编 SWF。

## 5. 工作流程

日常循环是「**反推 → 四张表 → 在全量表上改 → 写回 → 复跑**」，可改的查验面只有全量表一张，改数不再绕 JSON：

1. `npm run monster-census` 反推全量，再 `npm run monster-flags-csv` 出四张表。
2. 先扫**超范围表**决定区间：区间是判断合理不合理的参考，越界不等于错，人工裁定要么放宽 `MONSTER_COEFFICIENT_RANGES`，要么回改面板。
3. 再看**偏差大表**的「最差项 / 面板值 / 复算值 / 该项偏差 / 经验偏差 / 偏差在哪」：它按现标识复算，说明这一行的哪一项面板与这组系数对不上。制作组点名档次的 11 行一定在表里，不用门槛筛。
4. 要改数值就改**全量表**：空格表示这项不动，填了数表示按填的写。改完 `npm run monster-flags-table-apply` 看差异（默认 dry-run，会把覆盖到人工权威标识上的项单独点名：那些格照改，但落盘后改算工具自写、下次普查能重算，不会因为这一步变成人工权威），确认无误再 `--write`。
   写回的不是全量表而是另一张同列名（模板 + 十项系数）的表时，用 `--csv 路径` 换读源；2026-10-07 第十四批就据此把人工批次对照表 `data/monster-flag-human-recheck.csv` 那 28 行的九项（五项实测/定义档 ＋ 四项重解）写回 XML，`阶段` 整列留空没动、仍是台账 `claims` 里人工点名的 8 格。
   **⚠ 顺序是硬约束**：`monster-flags-csv` 按盘上现值重生成统计表，会**原地覆盖**制作组还没被读回的全量表。所以「先 `monster-flags-table-apply` 读回并留一份表副本，才允许 `monster-flags-csv`」；反例是 2026-10-06 的一批，重生成把制作组 15:07 之后的 阶段 手改盖掉了（账见 [可行性文档 §6p](../../../docs/怪物标识普查与面板反推可行性-2026-10-01.md)）。人工表读的是人工权威那份值（HEAD 过台账、并上 `claims` 点名的人工批次），不是盘上现值 ∪ 候选，所以它是只读对照面：在这张表上改数会被下一次 `monster-flags-csv` 整个盖掉，直接编辑 XML 也不经它 —— 要落地就改全量表，由 `monster-flags-table-apply` 读回（这批格按工具自写登记，不算人工权威）；确实要把某格钉成人工权威，就手填 `data/monster-flag-ledger.json` 的 `claims`。
5. 重跑 `monster-census` + `monster-flags-csv`，派生列才会按新系数重算；`git diff data/enemy_properties` 复核，写回应当只动 `<标识>`。
6. 判定某行不需要标识 → 加进 `data/monster-census.json` 的 `noFlagTemplates`；人工钉档次 → 加进 `humanTierFactors`（这样档次就不再被拟合覆盖）；反过来认定人工权威里那颗档次只是当初的预估、要重算 → 加进 `estimatedTierTemplates`（只摘 `档次系数`，同行其余人工权威标识照旧钉住）。这三处都是配置，不进代码。
   判定某只怪**整行暂时下线/面板待重做** → 在全量表把 `阶段` 填 0，写回后该行的实测四项留在标识里、但不再反推、不再进任何一张查验表与任何统计（见 §3）。
7. 写回的格式合同：新字段按**兄弟行缩进**对齐（`天网.xml` 的 `<标识>` 用制表符而子节点用空格，不能跟着块缩进走），不产生只有空白的行，不碰注释；小批先行仍适用于**观测口径变更后**的批量重标（2026-10-02 的攻速/倍率/段数批次就是先 `--only` 十几行、从 `彩蛋支线.xml` 9 行扩到 10 个文件 157 条）。
8. 误差的判读基准（2026-10-07 把人工完整打标的 27 行移出统计面之后的账，工具识别的 143 行）。**报数先认口径**：统计表上的「误差值」按**归档取档后的标识**复算（能从 XML 行内重现），census 里的 `fit.fitError` 是**连续解**，两套都别混着报。

   连续解口径（同一批 143 行 —— 移出去的人工 27 行本次**一个自由量都没有**，本来就不在连续解统计里，两条判据在这份数据上完全重合，见 §3；档次进搜索的也是这 143 行 —— 原先钉在 git HEAD 的 `敌人-双喷少女`、`敌人-特警僵尸` 两行自 2026-10-07 起由 `estimatedTierTemplates` 按预估摘出，HEAD 那道钉不再挡它们）：中位 11.4%、p75 16.9%、p90 20.1%、最大 38.9%；>20% 17 行、>40% 0 行。

## 6. 取值词表

反推的连续解不能直接进数据，`snapMonsterCoefficient` 按 **整数 → 0.5 半档 → 0.1 十分档** 逐档放宽，容差 0.05：够得着整数就取整数，`2.014 → 2`；整数够不着才降半档，`2.5 → 2.5`；半档也够不着才降十分档，`1.840 → 1.8`。
**词表没有 0 档，下限是 0.1**（`SNAP_FLOOR`）：十项系数全都站在公式的分母或指数上（HP、防御除以 `高攻低血防系数 × √高防低血系数`，攻速与速度在指数上），写 0 会把面板算成无穷大。2026-10-05 全量批里 `敌人-雪女`、`敌人-异形蛋` 的高防低血系数连续解贴 0，落到 0 档会给出 `Infinity%` 误差，正是这条下限挡住并已进超范围表。
词表是按现网 25~29 例真值实测出来的，不是假定：

| 系数 | 在 0.5 网格 | 需要 0.1 或更细 |
|------|-------------|----------------|
| 速度系数 | 25/25（唯一非整数就是 2.5） | 无 |
| 攻速 / 攻击倍率 / 段数 | 人工标注全部在 0.5 网格 | 实测均值可细到 0.1（试点批次已写 `段数系数 6.7 / 4.3 / 3.9`） |
| 霸体系数 | 25/27 | 2 例（2.3、1.1，即韧性带出的 0.1 小数位） |
| 成长系数 | 21/27 | 6 例（0.8、0.9、1.2、1.3） |
| 高攻低血防 | 20/27 | 7 例（0.8、0.9、1.1、1.2） |
| 高防低血 | 19/27 | 8 例（含 1 例 1.25） |

**取值网格只管连续解，速度系数不走它**：`snapMonsterCoefficient` 归档的是档次系数、成长系数、高攻低血防系数、高防低血系数这四项由面板反推出的连续值；速度系数按 D15 直接定档，本来就是 1/2/3（跨档怪的手感半档由人工写），攻速系数/攻击倍率/段数系数/霸体系数 由实测归档，都不走拟合。体育老师是三方不合的样本：标识人工写 **2.5**、面板按 **2** 生成（取 2 时防御max 残差 0.00%、HPmax 0.42%、空手MAX 0.03%，取 2.5 三处都涨到 3.4%~7.8%）、移动速度 50~75 的均值档是 **3**。四元联立之后工具既不替它改值、也不再单设一条「定义 3 与人工 2.5 相差 0.5 档」的报警：2.5 作为已标注的观测系数被钉住，面板贴不上的部分全落进 全量表 的 **误差值**（该行现量 5.1%），最终是改面板还是改速度区间由人工定夺。

## 7. 标识与数值不合时的处置原则

`<data>` 里的面板数值是运行时权威，`<标识>` 是它的溯源标注。两边对不上时按**标识是否齐备**分岔，不看哪边改起来省事：

| 情形 | 处置 | 理由 |
|------|------|------|
| 十项标识齐备（速度系数由 `速度_min/max` 定义即算齐备），面板与之不合 | **改面板数值**：按标识正算、按该行既有的取整粒度回填 | 标识是设计输入，数值是它的输出；补一个与速度对不上的速度系数等于把错处从数值挪到标识 |
| 只有面板数值、没有标识 | **反推标识**：阶段与速度系数机械可取，攻速系数/攻击倍率/段数系数/霸体系数要翻 XFL/FLA 观测，档次系数/成长系数/高攻低血防系数/高防低血系数 由六项面板四元联立 | 数值是唯一真源，标识此时才待补 |
| 标识像占位（例如除速度系数外全 1） | 不算「齐备」，回原表核对后按第二行处理 | 占位标识不携带设计意图 |
| 人工权威标识与面板不合，但偏差集中在 HP 或空手攻击 | **改面板数值或阶段**，不回头拟合被钉住的观测系数；四元联立给出的四项只在全量表上供人工裁定 | 观测系数是动画事实，面板贴不上说明面板或阶段/档次错，不说明动画量错了 |
| 逐通道各说各话（例如经验通道要的成长与面板通道差一倍以上） | 不再逐通道各解一次取均值（2026-10-05 试算更差），按四元联立解一次，经验只作对照 | 空手MAX、HPmax 这类通道靠 成长系数 上探到 8.9~13.5 才贴得住，取均值会把可信通道拖下水 |

**取整粒度跟着该行自己的写法**，不是全局统一：25 行已标注实测，空手攻击与防御取整到 1，HP 取整到 100，经验取整到 100（早期行）或 1（`天网` 与 `僵尸新单位` 之后的行直接 `round(公式值)`）。半档数值（如 `325.5`）按 Excel 的 ROUND 远离零取 326。
已按此原则处置：`敌人-爆胖僵尸` 速度系数 2 → 1（定义档），数值由 105/323/8900/26000/315 重算为 115/351/10500/31100/326。回填后攻击/HP/防御六条通道最大偏差 0.43%，两条经验通道 1.5%~1.9%：经验公式里不含 速度系数，这一档偏差改前改后相同，属面板原有的粗填，不视为本次改动的残留。

## 8. 已知不可自动化的部分

- 档次系数 D：制作组按风格与招式定档，面板只能给「最贴这块面板的那一档」。四元联立会把从没被人工钉过的行的档次一并解出来并写盘（2026-10-05 授权），但它**不是判定**：
  人工钉过的（人工权威里的格，或 `humanTierFactors` 点名）一律不被覆盖，点名的 11 行不论误差大小都进偏差大表，就是为了让人复核「面板给的档次」与「按样貌该给的档次」是不是同一档。
  面板单独定档从来不可靠（老口径实测 top1 只有 7/29 且整体偏低），这条判读别丢。
- 攻速系数、攻击倍率、段数系数：由 `monster-attack` 翻 XFL/.fla 数子弹实例得到观测值，**任何一项都不从面板反推**；
  剩下的手工部分是把疑点行判干净（见第 9 节），以及给卡在 `<conflict>`/`<duplicate>` 的模板认现役源 —— 注册表是生成物、又被烘焙管线消费，工具不代填，只在 `data/monster-census.json` 的 `attackSourceOverrides` 里指定用哪份源（见第 9 节末）。
- 霸体系数 K 的档位：`monster-attack` 已经按第 10 节的判据从元件量出来，人工只复核 census 表里报警的分歧行（阈值压线、读法敏感、只靠内联写法撑起来的 21 行、被人工例外留在盘上的 `鳄嘴兽人`）。
- 主线 >77 的阶段划分：诺亚前后、雪山尚未收口，`deferred` 行的阶段等划分规则定了再补。

## 9. 攻击实测的口径与首轮结果（2026-10-02）

**量法。** 一次命中 = 时间轴上摆出去的子弹元件实例：脚本内联在实例上就算它，否则取该子弹元件自己的脚本，
两者都没有才退回帧级脚本。**归属由摆放树 + 状态硬门决定（现行口径见下面 2026-10-04 那条）**：招式所在元件必须在 `placementNodes()` 从容器（`敌人-xxx` 导出元件）沿 `libraryItemName` 走 ≤4 层能到的集合里，
容器 → 动画 → 动画再摆的子元件都算它自己的；子弹、特效、通用模板是动画再摆的，本身不算招式。
有效招式 = 容器脚本真正跳转到的标签；`状态改变("a" + 随机数)` 这类拼名跳转按同族前缀放行，
同文件同族的 `a0/a1/a2` 一起算有效，**被按名调度的文件里**没人跳转的孤立标签才判废弃动画。没有标签但被容器摆着的长动画（空手攻击一类）整段算一招。
**顺播放行（2026-10-03）**：容器摆着的动画如果整个文件没有一个攻击样标签被按名 goto（招式合集把跳转写成 `gotoAndPlay(招式名)`、`兵器动作类型 + "1连招"`，
静态搜不到字面量），那就是播放头顺播到底，每一段标签都算有效招式；宿主只 goto 到 受创/站立 一类状态标签不算"按名挑招式"。
退到整个作用域捞候选的 widened 行不放这条。
**同库多怪是常态**（184 个模板里 132 行与别的导出 `敌人-*` 元件同包），旧的 widened 兜底会塌到整包、只要包内某处字面 goto 过就放行，量出来的其实是兄弟怪的招式：
审计到 23 招在树外且全部能指出主人，摆放树硬门之后这 6 行退回量不到（`146 → 140`、挂起 `38 → 44`），**量到招式的 140 行归属全是 placed**。

**状态硬门 + 摆放树取源（2026-10-04，现行口径）。** 制作组口径是**只有空手与近战一类出手状态下的动作才算招式**，
所以招式归属由两件事一起定：
1. **取源换成摆放树**：`placementNodes()` 从容器沿 `libraryItemName` 走 ≤4 层，每层记录元件摆在哪一帧；不再按「容器所在目录」划作用域。
   老口径把库根容器（`敌人-xxx.xml` 直接躺在 LIBRARY 根）的子树整个丢掉，另一些包则把同目录别人的动画捞进来 —— 31 行「候选只剩特效/子弹元件自己的时间轴」正是这个原因。
2. **状态硬门**：容器时间轴上标签最多的那一层当状态机层（`stateSegmentsOf()`），按标签切成状态段；元件按摆放帧落在的状态段定性，
   更深一层继承父元件的状态段。状态段名要**含 `attackStateWords`、不含 `nonAttackStateWords`** 才算出手（词表写在 `data/monster-census.json`，改口径不改代码）。
   挂在 击倒/血腥死/被击/空手跳/躲闪 一类状态上的子弹不算招式 —— `敌人-飞刀小子` 那 15 招就是这么来的（死前投刀与受创反弹被当成了招式）。
   同一份动画既摆在 近战 又摆在 被击 时仍放行（按攻击样那一段算）。
   「没有标签整段算一招」与「标签没盖住的段落按顺播补一招」只在挂在攻击样状态上的元件里找，够长（≥4 帧）才算。
   容器直接摆的那层一个有效招式都没有时，才沿摆放链往里再找一层（widened），widened 仍要求字面跳转引用、不放顺播。

**现行结果（2026-10-04 状态硬门 + 摆放树取源，同日两轮定源之后）。** 184 个模板量到有效招式 **178**、未量到 **6**（此前 140 / 44，定源前 174 / 10，第一轮定源 176 / 8）；
量到的行**归属全部是 placed**，widened 一行都不剩。攻速档分布 60 极快、61 快、37 中等、18 慢、2 极慢。
按「候选数=可用数 + 无固定值折算 + 倍率 ≤3 + 段数 1~10」这把尺子（数的是每行原始均值，不是四舍五入后的写回值），完全干净 **68 → 74 → 76 → 77** 行（两种数法现在都是 77）；状态硬门否掉 52 个候选招式、涉及 25 行（挡住的状态：击倒 18、血腥死 14、空手跳 9、被击 3、躲闪 3，其余零散），另有 3 个候选在 `汽车炸弹`、`迷你黑洞`、`黑无常索命` 上被同一道门否掉、这三行因此一行招式都不剩（全量口径 55 个候选、28 行）。
已标注的三项一律不覆盖，所以 `apply` 需要 `--overwrite` 才能改写本批工具自己写过的行（见本节末「口径变更后要改写数据」）。

2. **联弹折 `霰弹值` 分量**（乘 `linkageFactor`，现 0.6），方向口径是制作组 2026-10-06 更正的（原写反了：那版是「纵向免 area 折、横向不折」）：

   方向词只在认到 `联弹` 之后才看（`横向`／`纵向` 也出现在非联弹的种类名里，那条口径与打折无关），所以 `横向机枪联弹`／`纵向机枪联弹` 这一族按前缀自动归入，不必逐个列名字 —— 这正好把 §9 末「`枪弹狂热` 里 32 处 `纵向机枪联弹` 算不算折」那笔口子关掉了：**算纵向，不折**。

1. **认发弹函数看函数体不看函数名**：体内给 `子弹威力` 赋值**并且**摆了子弹（该函数自己的段数 > 0）才算。文件内按名去重；函数体声明在容器那份文件里、本文件只有调用时，仍把颗数折进来，`concerns` 写明「X 的函数体在 Y 里声明，本文件只有调用」。
2. **触发次数按调用点的类型累计**：`onClipEvent (enterFrame)` 的锚点元件按它在台上活过的帧数逐帧进一次；写在帧脚本里的调用一个关键帧进一次（窗口按该招的有效帧夹）。**同一个摆放已经作为子弹实例计过颗数的不再当调用点计**（`consumed` 集），否则一颗子弹会被算两遍。
3. **闸门是「每 N 次触发发 1 弹」**：体内 `if((射击计数++ % 性能倍率) != 0) return;` 这类写法把 N 认出来，来源分四种记进 `throttleBasis` —— `无`（每次调用都发）／`字面`（写死的数）／`数值声明`（同文件里 `var 性能倍率 = 2;`）／`读不出`。读不出**按 1 处理并写疑点**，不猜。发弹帧号按 `Math.floor(第几次 / N)` 折，**奇偶不猜**（宁可在 concerns 里说不确定，也不给一个看着像真的时间轴）。
4. **倍率现在认乘积式**：`子弹威力 = 4 * 空手攻击力`、`0.5 * 性能倍率 * 空手攻击力` 这种**前置系数**由 `productCoefficient()` 认（只吃纯 `*`/`/` 链，链里的标识数从同文件的数值声明解析）；含 `+ - ( )` 的表达式仍只认 `空手攻击力 * 4` 那种尾数写法 —— 现网 2395 处尾数走原通道，不受这次改动影响。
5. **「声明」永远不能冒充「一颗子弹」**（两处同规则）：`bulletMarks` 的帧级兜底与 `carrierScripts` 都改成先看函数体**以外**的那段文本（`functionDeclsOf(text).outside`）。整帧只有一段发弹函数声明的代码帧不代表「这颗子弹自带威力」，那种子弹由上面这条函数式通道按真实调用次数计；混过去的后果是把动画摆出去一次就凭空多一颗。这一修正顺带清掉了 `圣诞白忍` 倍率 2.30→2.29、`拼命之王` 招式 30→29（后摇 22.1→5.8）两处幻影。

**可击飞** = `击倒` 与 `倒地` 两段**各自**都有一段**生效**的击飞代码，**并且那段确实摆了元件**（制作组 2026-10-05 二次定案）：

- 生效代码有两种写法：统一函数（实例脚本上的 `_parent.击飞浮空();` / `_parent.击飞倒地();`，词表 `airborneCallWords`）和内联浮空（`_parent.浮空 = true;` / `_parent.倒地 = true;`，词表 `inlineAirborneWords`）。实测统一函数 100% 挂在容器时间轴的实例脚本上，所在帧号就等于该状态标签的帧号。脚本匹配一律先去掉空白再比，所以 `浮空 = true` 与 `浮空=true` 同一写法，`浮空 = false` 不误命中。证据里 `via` 只有 `函数` / `内联` 两种。
- **两条明确不认**（这两条把首轮判据收紧了）：**只摆了名字叫 `击飞*` 的元件、一处脚本都没写不算** —— 那是美术摆放，不是击飞逻辑；**写在注释里的击飞代码不算** —— 匹配前先 `stripAs2Comments()` 剔掉行注释与块注释，再比词表。现网两种都真实存在：`拼命之王` 与 `鳄嘴兽人` 的 `_parent.浮空 = true` 整块包在 `/* onClipEvent(load){ … } */` 里；`闪流步兵` 的 击倒 段、`三头犬` 与 `诺亚重装兵` 的 击倒 段只摆了 `击飞` 元件、那段没有任何生效代码（`诺亚重装兵` 的 倒地 段有生效内联、`三头犬` 两段都没有，两段要求不齐就整体判不可击飞）。`airborneInstanceWords`（元件名词）因此退出证据通道，现在只用来把 concerns 的成因写准。
