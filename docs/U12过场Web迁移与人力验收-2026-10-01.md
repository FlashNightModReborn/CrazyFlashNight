## 2. 范围与交接合同

会话包 `session_d0dd7d76-9389-465f-932f-908cf802cc9d.zip` 的上游成果是 U8 教程及帮助合成表面。重新评估后，U12 收敛为游戏内过场投影：沿用作者 XFL 的 14 个背景标签及现有无损 Web 像素，复用独立合成表面设施。初估小 M / 2–4 有效工程日只用于排期，未作实测工时校准。

| 层 | 当前权威与职责 |
|---|---|
| AS2 | [SceneTransitionService](../scripts/类定义/org/flashNight/arki/ui/SceneTransitionService.as)选择背景、消费一次 `本次背景`、保留严格 Unlock 比较，生成 `tr:<seq>` 身份与 revision；原时间轴负责导航、清理、结算、dirty/save 和失败返回 |
| Main XFL | [淡出动画](../CRAZYFLASHER7MercenaryEmpire/LIBRARY/sprite/淡出动画.xml)保留脚本与透明跳转中标记，移除其可见图像/进度/按钮 placement；通过 asLoader 安装的根桥调用服务，避免 main 重复链接类闭包 |
| Host | [SceneTransitionTask](../launcher/src/Tasks/SceneTransitionTask.cs)核快照与回执身份；[SceneTransitionController](../launcher/src/Guardian/SceneTransitionController.cs)管理独立窗口、遮罩及目标捕获。[PanelHost 结算接线](../launcher/src/Guardian/PanelHostController.TransitionSettlement.cs)把现役 Loot owner 绑定到同一端点；加载期间不暂停，不做普通开窗背景截图，场景结束后才取得暂停 |
| Web | [固定页面](../launcher/web/scene-transition.html)在 1024×576 逻辑画布等比显示；[原 Loot Panel](../launcher/web/modules/loot/loot-panel.js)拥有唯一结算 View。预览时无业务权威，绑定后走原 Loot/整理模型和命令。固定源仅开放 exact 当前实例的既有 Loot/库存边界，不进入通用任务路由 |

AS2 快照 v1 的精确字段为 `version/requestId/revision/phase/imageId/tip/targetScene/actionPending`；phase 为 cover/loading/reveal/error/hide。Host 自行附加 transport generation、connected 和 revealAllowed。呈现回执与失败导航操作必须匹配当前身份、revision 和 generation；同一不可变 v2 报告的内部接通/关闭意图使用下述单独规则。未知字段、foreign 身份、未来或畸形 revision、错误图片 ID 及 hide 后身份复活均拒绝。

返回 token 与当前 run 精确一致且战报已经 durable 暂存时使用 v2，额外精确字段为 `report/reportVisible/reportHandoff`。report 复用 Loot 的闭合报告校验，须 `rewardStashed=true`，本次请求内内容不可变化，已关闭报告不能复活。Host 的 `rewardReady` 表示已遮盖且可申请原奖励会话；`reportReady` 表示目标世界已真实捕获且仍为当前场景，二者独立。页面不能自报世界或业务就绪。

`manageReport/closeReport` 指向本次不可变报告，加载阶段、提示与目标编号的显示 revision 前进不改变它的身份。Host 只在同一 request/transport generation、报告仍可用及既有操作锁下接受 `1 ≤ 意图 revision ≤ 当前显示 revision` 的整数；发往 AS2 时带当前 revision，AS2 再以同一请求、原返回 token/run 和关闭权威验证，允许传输中再次发生显示前进。已经接受的 covered 证明只在该请求内跨显示更新保留，新请求、hide 或断连清除；世界捕获回执仍按当前阶段/目标验证。自动接通仍只申请一次，未知结果不重放；Loot 库存、奖励、关闭的业务 revision/lease/terminal 合同不变。

普通 `淡出跳转帧` 在受理跳图的同步函数内先发布 cover，再跳到第 2 帧；地图导航的成功响应在此之后。第 2 帧复用同一身份和图片，不消耗第二次 `本次背景`；开门动画仍在其原共同帧进入过场。Host 在第一次 Web 消息尚未送达、图片尚未绘制时就安装原生不透明底板，暖端点也走此门；Web 同步置不透明背景，等待解码期间或同身份提示更新不会从透明重新淡入。当前 covered 回执到达后才撤掉原生底板，成功揭幕保留原有动效和 reduced-motion 结果。

遮罩显示且图片解码/回退背景绘制后，Web 回 covered；AS2 在原第 5 帧等待该回执，再执行原第 6 帧清理。原第 30 帧等新世界 `SceneReady` 的普通对象身份，该身份还须严格匹配当前世界的权威字段，拒绝同路径重绑定携带的旧事件；Host 还须确认目标光照已经提交且其后捕获帧已到达，才准许 Web 揭幕。revealed 回执只释放同一次过场，原时间轴继续至空白终帧。没有用根跳图同步返回或固定延时替代世界就绪。

原第 17 帧必须保留 `__returnFadeActive = false`，让副本首子关的生产 admission 按既有时机放行；dirty/save 守卫也保留在此帧。这个旧初始化标记不代表 Web 遮罩寿命，遮罩继续由独立 `__transitionProjectionIdentity` 和呈现/世界帧回执持有。把旧标记延长到揭幕后会阻止它正在等待的副本初始化。其他 run、返回、结算与战斗地图拒绝条件不变。

`StageRunSession.onReturnBaseStarted` 按原规则先完成奖励 durable 暂存，`onSceneReady` 仍确认 exact 到达。本轮没有改暂存区或结算业务语义，也没有重新制作 UI。原 Loot Panel/View 先挂载预览，零业务命令；Host 确认 covered 后，由既有 Loot 权威申请一次业务 owner，绑定同一 View，不 cleanup、重挂载、截图背景或切换窗口。原材料/整理/关闭操作即可与基地加载并行；入暂存区后的空奖励容器仍为空，不为了“提前领取”再造第二份奖励。

固定 Core/source 的消息入口只允许当前 `panelInstanceId` 对应的 `loot_request`、原 Loot 的库存命令及 exact 关闭，仍由现役 LootTask、InventoryTask、Coordinator 验 revision、lease、terminal 和 unknown。其他领域、foreign 实例和通用 task 拒绝；业务响应也只送回这个端点。每个 request/run 自动接通一次，不新增按钮。阅读状态留在同一 DOM；四项只读呈现消息仅作有界诊断，不再作为跨页恢复或撤幕门。

目标世界真实捕获后，Host 发 `prepared`，并核同一 Bound panel/chest/container/epoch/run 的两帧呈现回执；目标场景编号更新不清除奖励身份。成功排入 `handoff` 后仍保留原窗口；AS2 复核世界、跳到空白第 36 帧并 clear，Host 收到时间轴结束才暂停世界并更新原页面就绪状态。没有第二次 snapshot 或页面切换。原业务提前关闭完成后，同一次加载页继续遮盖，到达不重开报告；未知结果不能靠视觉关闭解除。失败重试保持已绑定会话及未知写锁，不再开窗或暂存一次。用户主动切走时等待回到游戏。

现场加载样本 `maxMs=556/1680` 曾仍为 `admitted=True`，并触发 `reason=panic` 降至 LOW。过场持有期间现保留世界捕获，但不把这些长帧纳入画质决策、不执行排队的分辨率调整；相同持有状态不再反复撤销指针 epoch。每个新结算会话清除上次 `sceneReady`，同次预览转业务绑定保留原页面、状态与未知写锁。AS2/main/asLoader 与奖励规则未变，已逐项核对既有来源哈希，复用前轮编译证据。

接续检查结果、候选身份与测量见[性能修正证据](evidence/u12-settlement-performance-2026-10-02.json)。浏览器增加同一文档连续三次结算；真实合成夹具增加不变尺寸零重复通知与下次会话恰好一次新 viewport。它们不代签实际游戏卡顿消失、保存重启或正式部署。
