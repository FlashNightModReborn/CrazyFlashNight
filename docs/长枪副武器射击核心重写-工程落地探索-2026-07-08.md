## 1. 结论摘要

当前长枪副武器运行时已经形成一套小型影子射击系统。它没有真正复用长枪主射击的标准生命周期，而是在 `LongGunSubWeaponCore` 内自行处理：

- K 发射冷却与待发锁。
- 姿态归一化和 `__stateTransitionJob`。
- `man` 重建后的延迟重试。
- 枪口取点、角度偏移、发射动画。
- 子弹属性构造和 `_root.子弹区域shoot传递()`。
- 弹仓状态、物品弹药扣除、UI 第二行刷新。
- F 快装 / R 联动换弹对 `ReloadManager` 的标记注入。

这解释了为什么边界补丁持续出现：它不是单个条件漏判，而是副武器在主射击生命周期外重建了一遍时序。

建议重写，但不要把副武器伪装成双枪副手，也不要直接复用 `ShootCore.secondaryParams`。正确方向是新增“长枪副武器射击 lane”，复用 `ShootCore` 的调度、动作键、后摇、任务清理，复用 `WeaponFireCore` / `FireEventComponent` 的发射提交、枪口更新、散射、自瞄边界和 `processShot` 标准入口。注意：复用 `processShot` 前必须先把现有非核心订阅者改成按 `weaponType` 过滤，不能只看 `攻击模式`。

第一阶段只迁移 K 发射路径。F/R 装填保持现状，等 K 发射 lane 稳定后再收敛。

## 3. 当前架构问题

### 3.1 绕过标准发射链

主长枪射击路径：

```text
状态机
  -> man.开始射击()
  -> ShootCore.startShooting()
  -> ShootCore.continuousShoot()
  -> dispatcher.publish("长枪射击")
  -> core.长枪射击(gunRef, bulletAttr)
  -> WeaponFireCore.executeShot()
  -> dispatcher.publish("processShot")
  -> FireEventComponent.processShot()
  -> _root.子弹区域shoot传递()
```

这条链提供：

- 射击任务清理。
- 半自动 / 全自动调度。
- 后摇控制。
- `长枪射击` 事件。
- `processShot` 事件。
- 枪口位置更新。
- 散射、自瞄。
- `发射间隔毫秒` 盖戳。
- `updateBullet` UI 事件。

副武器当前路径：

```text
状态机 / man.开始副武器射击()
  -> LongGunSubWeaponCore.fireInternal()
  -> 自己切状态 / 延迟 / 找 man / 找枪口
  -> LongGunSubWeaponCore.shoot()
  -> _root.子弹区域shoot传递()
```

因此副武器天然绕开 `processShot`、`FireEventComponent`、`WeaponFireCore.executeShot()` 的统一入口。

### 3.2 状态权威过多

当前至少存在这些状态：

- `unit.长枪副武器配置`
- `unit.长枪副武器状态.loaded`
- `unit.长枪副武器状态.capacity`
- `unit.subWeapon`
- `unit.当前弹夹副武器已发射数`
- `unit.长枪.value.subweaponShot`
- `unit.__subweaponPendingFireCdUntil`
- `unit.__subweaponManualReloadLock`
- `unit.man.subweaponReloadRequest`
- `unit.man.subweaponManualReload` / `unit.man.subweaponLinkedReload`（仅历史兼容清理，不再作为生产权威）
- `unit.__subweaponDeferredFireRetries`
- `unit.__subweaponDeferredReloadRetries`

其中 `loaded`、`当前弹夹副武器已发射数`、`subweaponShot` 是同一事实的不同表达。继续维护三份状态，边界 bug 会持续产生。

### 3.3 ReloadManager 被副武器语义侵入

`ReloadManager.startReload()` 现在不仅处理主武器换弹，还负责：

- 主武器满弹时把 R 解释为副武器候补快装。
- 主武器可换弹时设置 `subweaponReloadRequest.kind == "linked"`。
- 逐发换弹 / 枪械师免费换弹下决定是否联动副武器。

`initReloadBurden()` 又要把 `manualReloadBurden` 或 linked burden 加进主换弹负担。Phase 3 已先把散落布尔标记收敛为副武器 `reload request`；长期若要进一步统一，应拆成真正的 reload lane / reload policy，而不是让 ReloadManager 继续理解更多副武器细节。

### 3.4 UI 与输入语义已有补丁化迹象

7 月 5 日文档说 F 快装复用战技栏 / 控制器。当前代码又引入 `WeaponSkillInputService`，让副武器控制槽绕过普通战技共用冷却。

这层服务化是好方向，但也说明“副武器不是普通主动战技”这个事实正在外围补洞。后续应把输入语义固定为：

- K：副武器射击 lane。
- F：副武器 reload request，不发布 `WeaponSkill`。
- R：主换弹 request，可附带副武器 reload lane。

## 4. 目标架构

### 4.1 不直接复用双枪副手

不要把长枪副武器塞进 `ShootCore.secondaryParams`。该参数强绑定：

- `gunPath = "枪2.枪.装扮.枪口位置"`
- `taskName = "keepshooting2"`
- `playerBulletField = "子弹数_2"`
- `shootingStateName = "副手射击中"`
- `weaponType = 手枪2`

它是双枪副手，不是长枪下挂。复用它会把枪口、换弹、状态名、弹匣字段继续搞混。

### 4.2 新增第三条射击 lane

目标形态：

```text
ShootCore
  primaryParams       主手 / 长枪主射击
  secondaryParams     双枪副手
  subweaponParams     长枪副武器
```

`subweaponParams` 候选：

```actionscript
{
    weaponType: "长枪副武器",
    shootingStateName: "长枪副武器射击中",
    actionFlagName: "动作B",
    prefix: "",
    bulletAttrKeys: ["副武器子弹属性"],
    shootBulletAttrKey: "副武器子弹属性",
    bulletPropsProvider: "LongGunSubWeaponCore.getBulletProps",
    gunPath: "枪.枪.装扮.枪口位置",
    taskName: "keepshootingSubweapon",
    playerBulletField: "子弹数_2",
    eventName: "长枪副武器射击",
    intervalProvider: "LongGunSubWeaponCore.getFireInterval",
    emptyPolicy: "denyNoReload",
    reloadPolicy: "none",
    magazineRemainingProvider: "LongGunSubWeaponCore.getMagazineRemaining",
    updateBulletWeaponType: "长枪副武器"
}
```

`ShootCore.continuousShoot()` 当前已支持传入 `attackMode`，但 `startShooting()` 不只是固定用 `core.攻击模式`。它还硬绑定：

- `protagonist.射击速度` 作为间隔。
- `core[attackMode].value.shot >= core[attackMode + "弹匣容量"]` 作为空仓判定。
- 空仓时按 `protagonist.剩余弹匣数`、非控制目标、枪械师免费换弹条件触发 `protagonist.开始换弹()`。

副武器不能继承这些主武器策略。`config.cd` 是副武器独立冷却，资源也由 `LongGunSubWeaponCore` 管。需要新增或改造为 lane policy，而不是只多传一个 `weaponType`：

```text
ShootCore.startShootingAs(core, protagonist, params, lanePolicy)
```

旧入口保持：

```text
startShooting(core, protagonist, params)
  -> startShootingAs(core, protagonist, params, mainWeaponLanePolicy(core, protagonist, params))
```

`lanePolicy` 至少要覆盖：

```text
weaponType                当前 lane 对应的武器对象名，例如 长枪副武器
fireMethodName            实际射击方法名，不能继续由 core.攻击模式 推导
preFireEventName          尝试射击事件；副武器默认 none，避免成功前通知订阅者
postShotEventName         成功发射事件；若需要 长枪副武器射击，应在提交成功后发
intervalProvider          返回本次基础射击间隔；长枪副武器必须来自 config.cd，不读 protagonist.射击速度
emptyPolicy               空仓处理；长枪副武器空仓只拒绝 K 发射，不触发主武器开始换弹
reloadPolicy              是否允许射击入口触发 reload；长枪副武器为 none，F/R 另走现有 reload 路径
semiPolicy                半自动策略；副武器默认 disabled 或显式来自副武器 config
gunslingerPolicy          枪械师点按 / 按住链策略；副武器默认 disabled，不继承主武器枪械师
recoilPolicy              后摇策略；副武器不能无条件清 / 写主武器全局后摇
aimPolicy                 自瞄策略；显式声明继承长枪自瞄或禁用自瞄
bulletPropsProvider       返回本次 bulletProps；若继续用 shootBulletAttrKey，则它指向当前 man 上的字段
shotOwnerProvider         返回 value.shot 的权威对象，例如 unit.长枪副武器
magazineCapacityProvider  返回容量；不能从 长枪弹匣容量 推导
magazineRemainingProvider 返回 UI 剩余量；副武器按剩余触发次数算
updateBullet              updateBullet 载荷策略；至少写 playerBulletField，最好额外带 weaponType
pendingIntervalPolicy     __pendingFireInterval 写入 / 清理策略
```

`lanePolicy` 不能只在 `startShootingAs()` 生效。当前 `continuousShoot()` 内部仍通过 `attackMode` 推导 `shootMethodName`、`magazineCapName`、`attackMode + "射击"` 和 `updateBullet` 剩余弹；枪械师按住链又通过 `_gunslingerContinuousShoot()` 再次裸调 `continuousShoot()`。Phase 1 必须新增 `continuousShootAs(core, shootContext)` 或等价的 `shootContext` 缓存，把同一份 lane policy 传进：

- 首发 `startShootingAs()`。
- 持续射击任务 `params.taskName`。
- 枪械师链 / 释放轮询任务，如果该 lane 启用。
- `updateBullet` 发布和 `__pendingFireInterval` 消费。

副武器默认不启用主武器半自动 / 枪械师链。若未来确实要让某些副武器吃枪械师收益，必须由副武器 config 显式声明，并单独测试 `config.cd` 与 tap/hold multiplier 的交互。

子弹属性挂载位置必须明确。当前 `ShootCore.continuousShoot()` 从 `man[config.shootBulletAttrKey]` 取 `bulletAttr`，不是从 unit 取；主武器也是每次 `man` 初始化时写当前 `man.子弹属性`。因此 Phase 1 只能二选一：

- 保守方案：在 `ShootInitCore` / 长枪 man 初始化路径为当前 `man` 生成 `man.副武器子弹属性`，`shootBulletAttrKey="副武器子弹属性"` 明确指向当前 man。姿态切换后必须重新读取 `unit.man`，不能持有旧 man 的属性。
- 更干净方案：`continuousShootAs()` 不再直接索引 `man[shootBulletAttrKey]`，而是调用 `bulletPropsProvider(core, man, shootContext)` 返回本次 bulletProps。该 provider 内部可以缓存到当前 man，也可以每次生成，但不得读取 stale man。

只在 `LongGunSubWeaponCore.configureUnit()` 写 `unit.副武器子弹属性` 不够，除非 `continuousShootAs()` 已改为从 provider 读取。

### 4.3 虚拟武器对象

为了复用 `WeaponFireCore.executeShot()` 和 `FireEventComponent.processShot()`，需要让副武器在运行时拥有与主武器同构的最小字段：

```actionscript
unit.长枪副武器 = {
    name: config.name,
    value: {
        shot: firedCount
    }
};
unit.长枪副武器弹匣容量 = config.capacity;
unit.长枪副武器属性 = configAsWeaponData;
unit.长枪副武器射击 = function(muzzlePosition, bulletProps) { ... };
```

其中 `value.shot` 是权威运行时计数。`长枪.value.subweaponShot` 作为持久化镜像，统一由 sync 方法写入。

注意：AS2 没有接口，第一版可以用 duck typing。不要引入复杂继承。

### 4.4 副武器发射 wrapper

`unit.长枪副武器射击(muzzle, bulletProps)` 负责副武器专属资源：

1. 检查副武器容量、冷却和 `LongGunSubWeaponCore.canPayFireCosts()`。
2. 调用 `WeaponFireCore.executeShot(unit, "长枪副武器", muzzle, bulletProps, commitGuard)`，或在过渡方案里执行旧签名。
3. 如果成功，确认副武器资源已经提交；如果采用过渡后扣方案，则在这里提交并处理失败回滚。
4. 同步 `长枪.value.subweaponShot` 和 UI 第二行。

这里要处理一个原子性细节，事实模型必须写准：`WeaponFireCore.executeShot()` 自身不递增 `value.shot`。它只检查 `owner[weaponType].value.shot` 与 `owner[weaponType + "弹匣容量"]`，发布 `processShot`，盖戳 `发射间隔毫秒`，再调用 `_root.子弹区域shoot传递()`。真正递增的是 `FireEventComponent.processShot()` 这个订阅者：

```text
WeaponFireCore.executeShot()
  -> dispatcher.publish("processShot", owner, weaponType, muzzlePosition, bulletProps)
       -> FireEventComponent.processShot() 递增 target[weaponType].value.shot
       -> 其他 processShot 订阅者
       事件总线当前不能作为业务顺序保证；后注册订阅者可能先执行
  -> _root.子弹区域shoot传递(bulletProps)
```

这意味着 `canPayFireCosts()` -> `executeShot()` -> `payFireCosts()` 不是完全原子：`executeShot()` 返回 true 之前，`processShot` 已经让 `value.shot++`，其他订阅者也已经执行；如果后扣资源失败，只回滚虚拟 `shot` 还不够，其他订阅者的副作用无法自然撤销。并且不要假设 `FireEventComponent` 一定先于装备函数执行；`processShot` 订阅者必须接收 `weaponType` / `bulletProps` 自行判断，不得依赖“shot 已递增、枪口已更新”的事件顺序。

推荐两档方案：

- 干净方案：扩展 `WeaponFireCore.executeShot()` 接收可选 `commitGuard` / `preCommit`，在弹药上限检查通过后、`dispatcher.publish("processShot", ...)` 之前提交副武器资源。`commitGuard` 返回 false 时，`executeShot()` 直接返回 false，不发布 `processShot`，不发射子弹。这个位置必须在 `processShot` 之前，而不是在 `_root.子弹区域shoot传递()` 之前。
- 过渡方案：wrapper 发射前先检查容量和 `canPayFireCosts()`，`executeShot()` 成功后调用 `payFireCostsAssumeChecked()`；若后扣失败，记录硬错误、回滚 `unit.长枪副武器.value.shot` 并同步 UI。该方案只在 AS2 单线程下 `canPay` 后几乎不可能失败时可接受，而且必须先隔离非核心 `processShot` 订阅者。

`commitGuard` 失败路径还必须处理 `ShootCore` 已预置的 `core.__pendingFireInterval`。当前间隔是在调用射击方法前写入，`WeaponFireCore` 在 `processShot` 后才消费并清零；如果 guard 在 `processShot` 前返回 false，必须由失败出口清理 pending interval，或把 pending interval 的写入移动到 guard 成功之后。

### 4.5 子弹属性生成

当前 `ShootInitCore.generateBulletProps()` 已经接近通用，只依赖 `weaponData` 上的具名字段：

- `split`
- `diffusion`
- `sound`
- `muzzle`
- `bullet`
- `velocity`
- `bullethit`
- `power`
- `bulletsize`
- `impact`
- `targethit`

副武器 config 可以规范化为同构对象，再调用生成逻辑，或新增：

```text
ShootInitCore.generateSubweaponBulletProps(unit, config)
```

第一版推荐新增专用方法，内部尽量复用公共片段，避免把 `calculateWeaponPower()` 的主武器倍率误套到副武器上。

迁入 `WeaponFireCore` / `FireEventComponent` 后，副武器子弹属性必须满足标准射击链的字段契约。旧 `LongGunSubWeaponCore.shoot()` 只要能直接 `_root.子弹区域shoot传递()` 即可；新链路会被 `FireEventComponent.processShot()` 改写散射、自瞄和发射间隔，因此 Phase 1 至少要保证：

- `站立子弹散射度`、`移动子弹散射度` 存在；否则 `processShot` 会把 `子弹散射度` 覆盖成 `undefined`。
- `ammoCost` 有明确定义。副武器 UI 推荐按“剩余触发次数”显示，不能默认套用主武器纵向联弹的 `ammoCost = split`。
- `发射者`、`子弹速度`、`shootX/Y/Z` 所需字段、`Z轴攻击范围` 等 `_root.子弹区域shoot传递()` 必需字段齐全。
- `aimPolicy` 显式决定是否继承长枪自瞄。当前 `WeaponFireCore.applyAimingLogic()` 只有 `weaponType == "长枪"` 时走长枪自瞄；`weaponType="长枪副武器"` 默认会进入非长枪分支，清理 `速度X/Y/ZY比例`。

副武器 power 仍由 `LongGunSubWeaponCore.calculatePower()` 管，因为它有独立乘区：

```text
basePower
* subweaponPowerMultiplier
* hostSubweaponPowerMultiplier
* passiveSubweaponPowerMultiplier
```

### 4.6 事件语义

不要默认发布普通 `WeaponSkill`。

是否发布 `长枪射击` 要谨慎。当前大量装备生命周期脚本订阅 `长枪射击`，它们语义上多半指主武器开火。副武器若也发布该事件，会触发主武器特效、弹药、变形或过热逻辑污染。

推荐新增 / 区分：

```text
长枪副武器尝试射击    可选 pre-fire 事件，默认不发
长枪副武器射击        post-shot 成功事件，只能在资源提交和 executeShot 成功后发
processShot(weaponType = "长枪副武器")
updateBullet(..., playerBulletField = "子弹数_2")
```

这样需要响应副武器的装备函数可以显式订阅新事件。

注意当前 `ShootCore.continuousShoot()` 的 `dispatcher.publish(attackMode + "射击")` 发生在实际射击函数调用前。如果只把 `eventName` 塞到这个位置，`长枪副武器射击` 会变成 pre-fire 事件：`commitGuard` 失败、`processShot` 未发布、子弹未生成时订阅者已经执行。Phase 1 要么不发副武器 pre-fire 事件，要么把成功事件移动到 `executeShot()` 返回 true 之后；需要“实际成功发射”的逻辑优先使用 `processShot weaponType="长枪副武器"` 或 post-shot 事件。

但 `processShot` 不能被当成完全安全的扩展点。当前已知订阅者：

| 文件 | 当前过滤条件 | 副武器风险 | Phase 1 要求 |
|---|---|---|---|
| `FireEventComponent.as` | 无 | 这是标准 shot 递增、枪口、散射、自瞄入口，应继续执行 | 保持按 `weaponType` 访问 `target[weaponType]` |
| `GM6_LYNX.as` | `actor.攻击模式 != "长枪"` | 副武器发射时 `攻击模式` 仍是 `"长枪"`，会扰动 GM6 展开 / 射击状态机 | 订阅函数接收 `weaponType`，先判 `weaponType != "长枪"` return |
| `G1111.as` | `target.攻击模式 !== "长枪"` | 副武器发射时会进入磁轨弹自瞄处理，并读取 `target.man.子弹属性` | 订阅函数接收 `weaponType`，先判 `weaponType != "长枪"` return |

因此 Phase 1 不能只新增 `长枪副武器射击` 事件；还必须把现有非核心 `processShot` 订阅者改为 `weaponType` 感知。后续新增装备函数也应把 `processShot` 的第一层过滤写成 `weaponType`，`攻击模式` 只能作为次级条件。

`updateBullet` 也不是安全的纯 UI 事件。`ShootCore.continuousShoot()` 成功射击后会发布：

```text
updateBullet(core, shootStateName, magazineRemaining, playerBulletField)
```

通用 `ReloadEventComponent` 用它刷新 UI 和后摇状态，这是应保留的；但部分装备函数把它当“主长枪刚开火”信号，而且当前只看 `攻击模式 == "长枪"`。已知风险：

| 文件 | 当前行为 | 副武器风险 | Phase 1 要求 |
|---|---|---|---|
| `ReloadEventComponent.as` | 写 `playerBulletField`，并按 `magazineRemaining` 改 `target[shootStateName]` / `射击最大后摇中` | 它不是纯 UI；副武器剩余量或状态名错误会误清 / 残留后摇 | lane-aware：副武器用 `magazineRemainingProvider`，后摇用 `recoilPolicy` 聚合 |
| `G1111.as` | `updateBullet` 时置 `ref.fireRequest = true` | 副武器会驱动主武器动画 / 状态机 | 按 `weaponType == "长枪"` 或 `playerBulletField == "子弹数"` 过滤 |
| `RShG4Я.as` | 每次 `updateBullet` 视为射击请求 | 副武器会驱动主武器开火 / 装填动画 | 按 `weaponType == "长枪"` 或 `playerBulletField == "子弹数"` 过滤 |
| `XM214-CageFrame.as` | `updateBullet` 中改 `target.长枪.value.shot` 和 UI `子弹数` | 副武器发射可能污染主武器弹仓 | 必须排除 `playerBulletField != "子弹数"`，推荐同时接收 `weaponType` |

推荐把 `ShootCore` 的 `updateBullet` 发布扩展为末尾追加 `weaponType`，兼容旧订阅者：

```text
updateBullet(core, shootStateName, magazineRemaining, playerBulletField, weaponType)
```

AS2 旧回调忽略多余参数，通用 UI 逻辑可以不改；主武器特效订阅者要显式接收并过滤 `weaponType`。如果不改事件签名，最低限度也要按 `playerBulletField == "子弹数"` 过滤主武器订阅者，避免 `子弹数_2` 触发主枪逻辑。

后摇也必须 lane-aware。当前 `continuousShoot()` 会写全局 `core.射击最大后摇中`，`ReloadEventComponent.updateNpcBullet()` 又会按本次 `magazineRemaining` 重写同一个字段。副武器不能因为自己空仓、失败或结束后摇而提前清掉主武器后摇。第一版至少要保证 `ReloadEventComponent` 对副武器 `shootStateName` 的收束不破坏主武器状态；更稳的做法是用 `ShootCore.isAnyShooting(core)` / `recoilPolicy` 聚合所有 shooting lane 后再写全局后摇。

## 10. Compact Handoff

当前判断：

- 副武器问题是架构层问题，不是单纯边界漏判。
- 根因是 `LongGunSubWeaponCore` 从旧主动战技直发逻辑演化成影子射击核心，绕开 `ShootCore / WeaponFireCore / FireEventComponent`。
- 推荐重写方向是“新增长枪副武器 lane”，不是“复用双枪副手 lane”。
- Phase 1 只迁移 K 发射：新增 `ShootCore.startShootingAs()`、`subweaponParams`、虚拟 `unit.长枪副武器`、`unit.长枪副武器射击` wrapper。
- `startShootingAs()` 必须是 lane policy，不是只多传 `weaponType`：副武器 interval 用 `config.cd`，空仓只拒绝发射，不触发主武器 `开始换弹()`；半自动 / 枪械师默认不继承主武器。
- `lanePolicy` 必须贯穿 `continuousShootAs()`、轮任务、枪械师链、`updateBullet` 和 cleanup；不能只改首发入口。
- `单位函数_lsy_主角行走状态机.as` 的切姿态直发路径也必须迁到新 lane；只改 `ShootInitCore` 会漏掉关键旧入口。
- F/R 装填先保留现状，等 K 发射稳定后再抽 reload request。
- 副武器不默认发布 `WeaponSkill` 或普通 `长枪射击`；`长枪副武器射击` 若作为成功事件，只能在 `executeShot()` 成功后发布，不能复用当前 pre-fire publish 位置。
- 复用 `processShot` 前必须处理订阅者隔离：`GM6_LYNX`、`G1111` 当前只按 `攻击模式 == "长枪"` 过滤，会被副武器发射误触发，应改成优先按 `weaponType == "长枪"` 过滤。
- 不要依赖 `processShot` 订阅顺序；装备订阅者不得假设 `FireEventComponent` 已递增 shot 或已更新枪口。
- `updateBullet` 也必须隔离：`G1111`、`RShG4Я`、`XM214-CageFrame` 当前会把它当主长枪开火信号；推荐事件追加 `weaponType`，最低按 `playerBulletField == "子弹数"` 过滤。
- `ReloadEventComponent` 不是纯 UI；副武器需要 `magazineRemainingProvider` 和 `recoilPolicy`，避免显示被 `ammoCost/split` 污染或提前清主武器后摇。
- `ShootCore.cleanup()` 必须清理 `subweaponParams` 的任务、半自动锁、枪械师链、rate key、shooting state，不能只清 primary / secondary。
- `generateSubweaponBulletProps()` 必须输出标准射击链字段：站立 / 移动散射、ammoCost、发射者、必要坐标 / Z 轴字段；`副武器子弹属性` 必须来自当前 man 或 `bulletPropsProvider`，不能只写 unit 字段。
- Phase 1 默认 `aimPolicy=disabled` / 不继承长枪自瞄；若要继承长枪自瞄，必须改 `applyAimingLogic()` 消费 policy。
- `WeaponFireCore.executeShot()` 不直接递增 `value.shot`；递增发生在 `FireEventComponent.processShot()`。副武器资源提交最好通过 `commitGuard` 放在 `processShot` 发布前，过渡后扣方案必须有失败回滚和测试。
- `commitGuard` false 必须清理 `__pendingFireInterval`，或把 pending interval 写入移动到 guard 成功后。
- Phase 1 不新增 AI/NPC 长枪副武器自动使用；不改全局 K/B 键映射，只改长枪消费点。
- Phase 1 只要求 K 发射同步 `unit.长枪副武器.value.shot` 与旧 `loaded` 快照；真正移除 `loaded` 权威地位放到 Phase 2。
- 第一施工点：测试注册和 fixture，再事件隔离，再改 `ShootCore` context，再改 `LongGunSubWeaponCore.configureUnit()` 和入口绑定。

- `LongGunSubWeaponCore.executeShot()` 依赖 `FireEventComponent.processShot` 订阅来递增虚拟 shot；若未来某单位未初始化开火事件，会导致 shot / loaded 不同步。当前生产射击单位和测试夹具均已注册该事件，Phase 1 接受此依赖。
- `submitFireAfterPoseChange()` 沿用旧状态切换兜底：若某条生产状态切换异步创建新 man 但未消费 `__stateTransitionJob.callback`，兜底可能过早在旧 man 上发射。这是旧路径既有风险，Phase 1 未扩大处理。
- `GM6_LYNX.enemyKilled` 负 shot、`canPayFireCosts()` hp/mp 边界语义不一致属于既有设计问题，未纳入本轮。
