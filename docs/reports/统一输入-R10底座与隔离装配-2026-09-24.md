## 2. 输入底座

代码位于 `launcher/src/Guardian/InputOwnership/`。

- `RawDeviceLedger` 以设备和物理扫描位置聚合按住状态；左右修饰键及其通用别名分开处理。同一键盘的主 Enter/小键盘 Enter、两把键盘相同 VK、重复 Down、NumLock 改变后的 Up 不会直接混成一个 release。
- 冷启动快照中的按住键没有伪造设备归属；另一设备的孤立 Up 不能清掉它。已知设备仍按住时，聚合 OS 快照的 Up 不能覆盖该事实。
- `RawInputSource` 使用独立消息线程与 `INPUTSINK | DEVNOTIFY`，不依赖缺边沿的 LL 键盘流，不吞外部输入。注册被其他同进程组件替换时关闭来源，不抢回对方注册；退出也只移除自己仍持有的注册。
- 来源代次、数据队列溢出、拓扑变化、歧义包、普通快照竞争与前台/桌面查询资格分别处理。Raw 记录仍标 `Unmarked`，不将它当硬件证明。
- 控制命令走独立队列；实际 Windows 线程测试覆盖控制顺序、声明的来源失效和退休后拒绝执行。这个 API 尚未被真实 C1 handoff 使用。

`InputHandoffCoordinator` 实现 exact scope/incarnation 覆盖、session/coverage/epoch/ticket/geometry、取消回执、独立 READY/最终 grant、观察前缀复验和一次 OpenIntent。补出的重要反例是：意图被几何/前台变化取消后，不能仍把目标 owner 留为 Web；现在回退原域，且不重放动作。准备期间的 Down/Up 作废轮次，重新 neutral 后可准备；取消不清物理 held。

当前仍是候选底座，不能称完整键盘资格已完成。IME 不由 Raw VK 账本证明；Pause、无扫描码/多媒体键、布局差异和设备真实拔插仍须明确覆盖。`OnObserver` 的队列排空只描述本地观察线程，不替代下游端点已消费/撤销的回执。

注册所有权与无扫描码处理参考微软的 [RegisterRawInputDevices](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerrawinputdevices) 和 [RAWKEYBOARD](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawkeyboard) 合同；接口文档不提供本应用的连续性证明。

## 3. 实际链接闭包揭示的首帧漏口

最初只按 import 摘录审计不够。对实际 `C1Island.swf` 使用 FFDec 只读 `-dumpAS2`/脚本导出后，发现初版连入 **307 个类**，包括：

| 入口 | 隐含行为 |
|---|---|
| `KeyManager.keyMap = init()` | 静态初始化建立 `keyPollMC.onEnterFrame`，轮询实际按键 |
| `FrameTimer._instance = getInstance()` | 静态构造根影片剪辑和帧回调 |
| `VectorAfterimageRenderer.instance = new ...` | 构造 VFX 池，并间接取得增强时间轮/基础时间轮 |
| `CooldownWheel` 首次构造 | 建立 `_cdWheel.onEnterFrame` 驱动延后任务 |

因此在业务模块帧脚本里才设置“隔离”，会晚于 `DoInitAction`；此前四素材零业务脚本、真实 snapshot 成功都不能独立证明旧域从未准入。

修补采用 **bootstrap 先设置能力，再加载唯一白名单业务模块**：

1. `C1Bootstrap.swf` 为 726 字节，只有一个帧动作；实际 dump 没有类初始化、库元件或导入。
2. 它先固定不可写/不可删的 `_global` 隔离能力，再加载 `C1Island.swf`；加载目标设置 `_lockroot`，保持真实 service 所需的 root 上下文。
3. 新 `IsolatedInputPolicy` 在类首次初始化时固定判断。已执行普通域后才设置标志不会被认证为 C1；只能新 VM 冷启动。
4. 五个相关类只在该能力存在时禁止旧轮询、驱动或任务登记。实例方法只在隔离构造时替换，常规游戏热循环没有新增持续门禁分支。未知/畸形能力按关闭处理，不能默默回落旧输入。
5. 当前业务模块链接 **308 个类**；已知构造门和源 hash 记入 `tmp/c1-bootstrap-audit.json`。这份编译闭包索引不替代未来新加载内容的审计。

真实 VM 检查确认三个旧驱动均未创建；对排队、reset、销毁重建、私有轮询的动态绕路等共十次尝试全部拒绝，手动推进旧计时器也没有执行 callback。普通入口的 11 项回归确认按键标签/轮询、正常定时任务与取消保留，迟到标志不能改变已运行 VM 的模式。

C1 独立编译还暴露了 CS6 相对宏路径问题：之前未重编的类可能命中缓存，修改后才报 `../macros` 缺失。生成器现在按字节/BOM 从 `scripts/macros` 派生本夹具的宏目录并 `--check`，不修改 canonical 宏。失败编译即使产出了 SWF 也被拒收；一次误进入执行的失败编译目录已明确标 `INVALID-COMPILE.txt`，不能算通过证据。

普通驱动测试初版另有一项失败：TestLoader 第一帧立即查询既有 FrameTimer 根驱动，未见函数。最终测试改为显式销毁/重新构造该测试实例后验证缺省构造、登记及取消；未据此修复或归因普通游戏的早期生命周期。原始失败日志保留，这 11 项结果不能升级为标准游戏冷启动已复验。

## 4. 真实业务与呈现组件

隔离角色使用四个现役被动素材、真实 `DressupReferenceManager` 注册与 `LiveAppearanceUpdater.isReady`，没有用空 registry/no-op 保存服务伪造 readiness。原 `PlasticSurgeryPanelService` 生成真实 snapshot/session 和 `world_plastic_surgery` opener。C1-I 没有普通基地、门、NPC、存档服务；退出销毁专用 VM，不回到同 VM 的普通游戏。

付费边界有两层：`PlasticSurgeryTask(draftOnly:true)` 在投递前拒绝 commit；AS2 `installDraftOnly()` 在 token/cache/写入之前拒绝直接 commit，普通 install 和 session reset 都不能恢复写能力。只读快照不再要求安装根本不会使用的保存/扣费函数。普通 paid 路径仍由原有 service 执行；Host 同时识别 AS2 的确定性只读拒绝，避免错误制造未知写锁。

装配夹具复用实际整形页面及其模块、Host task、AS2 快照；没有使用页面开发 harness 的假后端。执行代码和 CSS 在启动时冻结，未知 Document/Script 请求在执行前拒绝；静态外观资源继续使用本地生产目录。SWF 复制到本轮证据目录后执行，身份记录实际路径与字节 hash。

新增 `ProbeStartVisual` 把 world swapchain 接入调用方提供的 visual；诊断 `C1Scene.dll` 建立 World→HUD→Web 的 DComp 树。PlayerInfo 使用真实资源投影、现役严格解析、SVG 分块缓存和 premultiplied GPU 上传；原资源注释组件也经过实际 Show/Reset。这里尚未验证 Native 的物理 hover/滚动交互。

Web 接入遵循 [RootVisualTarget](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2compositioncontroller.rootvisualtarget) 的视觉目标合同；并未据此认定键盘/IME 归属自动成立。

Web 组件验证了 gate 关闭时载入真实页面、取得编辑快照、生产 cleanup 回执，以及确切 controller 退休。输入挂起和页面退休已区分：挂起保留本地草稿，退休才 close。当前 Host 没有接入物理业务输入，页面持续 inert；它直接安排只读页面准备，所以不能把它与另一条 AS2 opener 协议测试拼成已通过的真实 opener→Web handoff。

## 5. 初轮环境阻塞、脚本补验与归因边界

初轮桌面观察一直见 Flash CS6 的 `TestLoader` 处于前台；对应编译任务为最高权限运行。C1 观察器持续报告 Default 桌面可打开、来源已注册，但前台 PID 不属于候选，故 `Eligible=false / Neutral=false`，没有授予输入。桌面工具未能激活候选后曾请用户手动切离；这个人工阻塞判断过早，没有先充分复用仓库脚本。

初轮世界内容的画面证据也未成立：WGC 计数非零、AVM 显示帧推进、角色尺寸有效，但截图出现白/黑块、菜单或其他窗口内容，没有确认到预期诊断色块。原 S/P/F、独立 projector 以及完全未改窗口的对照当时均未给出合格图像；独立 projector 记录为可见、未 cloak，不能宣称已找到 `SetParent`、遮挡、休眠、虚拟桌面或特定软件的根因。`rootBounds=null` 也保留为待核字段。

**09-24 06:33–06:36 脚本补验：** 用户确认已切换，并指出仓库具有切换基础设施。CS6 编译本来已有 `compile_test.ps1 -Target` 自动选择文档；候选前台是另一项，已有 `capture_screenshot.ps1` 的激活/截图实现可复用。本轮给该脚本补 exact PID/HWND、显式输出路径、截图前后前台核验及 `-NoActivate` 观察模式，不再默认选多个 Flash 中的第一个，也不接入正式游戏的焦点恢复。

新 Raw 候选 `tmp/c1-input-source/evidence-script-setup/` 得到 exact HWND 前台回执，9/9 通过；强化条件实际取得 `Healthy=true / Eligible=true / Reason=held / Neutral=false`，随后收到 Up 在同一来源代次恢复 neutral。没有改变通过门或重新采人工样本。

真实装配 `tmp/c1-island-host/evidence-script-setup/` 执行既有 `bin12`，14 项组件检查通过，前台核验成功；`scene.png` 确认真实整形页面，关闭页面后的 `world.png` 确认 navy 背景、诊断色块、被动角色素材、整形按钮与 Native HUD，来源观察为 `Eligible=true / Neutral=true`。这解除了本次 S/P/F 输出内容未确认的阻塞；角色只含四项被动素材，不能称完整纸娃娃或游戏表现验收。

两次未修改 projector 原始窗口对照仍未取得 exact foreground：一次非激活屏幕截图被其他前台应用遮挡，均留拒收记录；不能以该截图证明 Flash 渲染错误。原始独立窗口像素和长期移动/遮挡稳定性仍未验证。脚本成功也不证明此前激活失败的根因，更不证明物理业务 handoff 已接通。

`--independent-source` 只保留为明确的对照参数。默认入口继续 S/P/F；没有因自动激活失败就更改正式源窗口路线。

3. **跑双向自动矩阵**：合法意图先兑现、全覆盖取消、来源 neutral、准备/授予分开；覆盖准备冲突、注册/设备故障、队列溢出、迟到 callback、重绑/实例更换、关闭失败与确定退休。不能在这里重开 native 取消消息试探。
4. **明确支持输入语义**：尤其第一击、键盘激活时点、组合键和 IME。第一击问题此前未得到回复，不能静默改正式游戏；当前只读装配不宣称兼容。
