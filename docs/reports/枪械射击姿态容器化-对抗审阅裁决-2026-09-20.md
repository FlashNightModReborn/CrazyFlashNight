## 有效改稿结果

1. P1 在同一套双枪素材上分两步：先复用控制时间轴验证持久语义，再拆三组视觉件；保留完整目标，不预先制作另一套一次性手枪样板。
2. 将持久范围限定在兼容的持枪族状态内部，明确同状态重复调用、离开后清理/返回重建、输入仲裁换绑与实际换装直接跳帧入口。
3. 列入数值帧、标签、顺播与门禁的换弹合同，默认保持现役双手射击封锁、串行续换及库存提交规则；视觉拆件不强制重写换弹 API。
4. 补角色、holder、skinKey、规范引用写者和关闭通知的对应关系；区分主动关闭与短暂 detached/cache 回退。
5. 补入 LongGunSubWeaponCore 与铁枪的硬编码枪口路径、模式提交/初始化顺序，以及实际分支的缓存与退出责任。
6. P0 收敛为足以驱动样板的接口与基线方法；实际 holder 生灭和 attach 基线随 P1 首个候选验证，不前置独立的全面性能工程。

## 明确驳回的断言

- B 的证据缺口段声称 things1 `Symbol 127` 不走装扮配置。主控回读 `Symbol 127.xml:17-25`，其 load 明确调用 `_root.装备引用配置.配置装扮`，该推断不成立。
- “只改 manager 就必然零 XML 变更”不成立：三部件带来的层级变化发生在素材 load 读取装扮之前，manager 内 gate 不能独自解决该读取路径。
- “三部件必然要求重写换弹 API”缺少必然性；先用现有控制时间轴验证视觉映射是更小的候选。
- “增加 `_parent` 自验即可证明缓存仍属当前实例”不足：当前 AS2 约束记录了同路径重建后的 MovieClip 引用语义，仍须结合拥有者/代次。
- E 最后仍建议可增手枪拆件实验，本轮未采纳为固定工件；只有具体机制无法在双枪样板中隔离时才补临时夹具。
