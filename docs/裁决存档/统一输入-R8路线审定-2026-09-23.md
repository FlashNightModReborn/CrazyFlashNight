## 0. 裁决摘要

**推荐采用从启动即关闭 U 的专用真实 C1 入口（下称 C1-I），不以扩大普通基地场景迁移作为本轮默认前置工程。** 这里的“专用”是启动边界与能力范围专用，不是重写一套类似 surgery 的演示业务。必须保留现役 AS2 opener、实际 surgery 业务处理器与 Web 页面、一个现役 Native 交互目标和一块现役 PlayerInfo 缓存。原计划的姓名草稿、取消、返回世界链仍须跑通；付费应用不在本轮内。

**C1-I 可以成为真实纵切的实施路线，但 R8 现状尚不能进入 C1 人验。** C1-I 通过后也只证明该封闭入口，不证明普通基地、动态外部 SWF 或整个游戏具备生产隔离能力。启动路径和验证场景的范围变化须明确写入同一分阶段计划，不能只换名称而保留旧的“完整基地已安全”验收口径。

不接受以下捷径：把原游戏先启动再隐藏 U；只换整形/理发两个按钮；用 M 的逻辑 Begin/End 覆盖 raw 首击失败；以常闭、超时或未知状态永不恢复代替活性；把源字符串、窗口隐藏、发送 close 成功当取消证书；把五键合成 Down/Up 当生产 neutral 初始化。

native 单次候选机制保持否决，不继续扫描取消消息。现役 A0/C0、已经完成的窄域验收不因此推倒重来；B、性能封口、普通基地验收和发布另设门禁。

### raw 失败的实际含义

## 2. Q1：M 样本能贡献什么，不能证明什么

### 2.1 可用于生产设计的实证

R8 确实让主 SWF 与实际加载的子 SWF 运行了。样本不是只写协议或只用模拟对象：`CooperativeChild.as` 的两行代码调用 `_root.installDomain(this,"B")`，主程序实际 loadMovie；受控重载后子域 incarnation 也变化。（E04 L74–78、L119–120；E05；E19。）

可保留的设计结果是：在**所有入口、任务和视觉状态均受同一协作协议管理**的域内，可以把 raw 回调降为诊断，用明确的新 Begin/End 建立业务手势；通过 session、coverage、epoch、ticket、gesture、beginSeq 和目标 incarnation 拒绝旧身份；取消时撤销 activeToken 与延后任务，清视觉状态；Host 必须等齐预期 scope 的取消回执和 neutral，才重新发 READY。（E03 L39–73；E04 L30–59、L81–115、L133–139。）

已有实跑还支持若干窄结论：外部释放之后新逻辑点击可以工作；持键返回不准开门；右键叠加会取消当前左键手势；普通拖出不提交；取消能移除尚未到期的逻辑任务；旧 ACK、缺子 ACK 不足以开门；受控子 SWF 重载后旧 incarnation 失效。这些正负控值得保留，不能因其范围有限就说“没有价值”。（E03 L142–217；E19。）

### 2.2 必须反驳的过度外推

**两个 SWF 文件不等于两个已独立封闭的生产执行域。** 子文件只调用根的 installDomain；主根持有同一个 domains、jobs、activeToken，且根在 CANCEL 后遍历这两个对象发回执。它证明的是“同一个受控根能管理实际子 SWF 中受它登记的对象”，不是“任意子 SWF 的私有任务、监听器、root 依赖与加载入口都已受控”。这里的隔离是业务准入封闭，不是已经建立了不可信 SWF 的安全沙箱。（E04、E05。）

**缺子 ACK 是接收端聚合门禁负控，不是子程序不执行取消的实测。** `mDropChildCancelReceipt` 让 Host 丢弃 B 的取消回执；AS2 原日志 L792–793 实际同时有 A、B 的 CANCELLED。因此这组反例已证明“不能只凭主回执放行”，但没有证明“一个有独立任务的子程序拒绝取消时，系统如何终止它、如何不误提交，以及恢复后如何重新入域”。（E03 L192–196；E19 L792–800。）

**逻辑成功不是 raw 修复。** 原型 raw press/release/drag/key 均只计数、记录；甚至按钮禁用 Tab。逻辑命中使用自身 domains 逆序查找，不是现役复杂显示树的通用命中与遮挡规则。它没有承担生产原 onRelease、Key.isDown、全局回调的原有权限。（E04 L29–52、L123–125。）

**SendInput 加明确 Activate/FocusFlash 不是自然窗口返回体验。** 这对可重复刺激有用，却未覆盖任意系统前台恢复、首击激活策略、IME 候选窗口、Tab、隐藏/全几何变化。五键校准也只建立了这次实验已知基线。（E03 L132–160、L197–201。）

26/26 不涵盖 loadMovieNum、未知子 SWF、独立子域拒绝清理、传输与钩子失效、长时身份更新、全几何或键盘/IME。不能把“不支持但拒绝”的测试写成已支持该能力。

### 2.3 新增静态停止反例：尚未在 R8 实跑

#### S1：Host 数据队列故障，并不自动撤销 AS2 延后任务

源码链：`CooperativeHost.cs` L76 在队列满时只设 `mBroken=true,mOpen=false`；L60 又使 `CancelCooperative` 在 mBroken 时直接返回。与此同时，AS2 End 会排入 `frames+12` 的任务，任务到期仅检查 AS2 本地 token、gate 和身份；Host 的 mBroken 不在这些检查中。（E03 L58–76；E04 L110–114、L133–139。）

应注入的反例是：合法 End 已排队但尚未 mCommit → 令 Host 队列达到故障分支 → 连接仍存活 → 推进 AS2 帧。**现有源码不保证该任务被取消，因而允许 Host 停止准入后 AS2 仍提交。** 这是静态构造，不是宣称现有 26/26 日志已出现该失败。

修补要求不是许诺跨进程瞬时取消。必须把 `FaultBlocked/Revoking` 与 `Cancelled` 区分：数据队列坏掉不能同时封死撤销控制路径；未得到真实撤销或确定销毁证据前，不准把所有权交给新端点。若业务在撤销生效前已越过不可撤销提交点，应保留其操作状态并对账，不伪装为“未发生”；若仍是可撤销任务，取消合同必须覆盖其实际提交点。**最晚在取消证书成立及新 owner 获准之前，旧域必须已不可能产生未结算的延后输入业务。**

#### S2：READY 中途左键按下，可以让恢复永久等不到第二回执

构造顺序：A 的 READY 被接收；随后左键从松开变按下；再收到 B 的 READY；最后左键释放。`DrainCooperative` 对 awaitReady 期间的“第一个普通左键 Down”不触发取消，而 READY 接收条件因 held!=0 丢弃 B；释放后没有自动重发 READY，也没有重启准备轮次。（E03 L53–55、L67–72、L94–107。）

此时没有新 Begin，安全可能仍保持，但“最终松手即可恢复”没有成立。生产合同应在准备期间遇到冲突边沿时作废该轮回执，回到等待可信 neutral，然后幂等重试准备；禁止重放用户输入或 opener。测试必须同时证明不误提交与恢复后的独立新手势恰好成功一次。

#### S3：几何取消与 M 身份不贯通

M 队列保存屏幕坐标，drain 时却按当前 Surface 尺寸换算；M wire 不带 geometry 身份。现役 controller 的几何取消调用 Surface.CancelPointer，不能自动视为已经通知了另一个 M 协调状态机。（E03 L78、L102–109；E14 L326–338。）

应注入 Down 入队后窗口移动、缩放、重绑或目标换实例的情况。旧按钮边沿必须被拒绝/取消，不能用新几何把旧刺激改投新目标。普通 hover 是否可重投影可另定，但不能借其规则给 Down/End 重新授权。

#### S4：日志零丢弃不证明物理观测连续

Program 的 hookDropped 只计自身诊断队列溢出；它不探测操作系统静默移除钩子。微软文档明确说明低级鼠标钩子超时后可被静默移除，且没有直接移除通知。当前 UI 线程、业务队列和网络调度的健康，不能替代输入观测健康。（E06 L106–140、L267–275；外部依据 W1。）

生产需要观测代次、Unknown 和可验证恢复。单纯加心跳、再把计数置零，不构成修补。

## 3. Q2：启动即隔离 U 可行，但它是可执行依赖闭包，不是隐藏 UI

### 3.1 启动边界

推荐新建可明确识别的 C1-I 启动分支或最小入口构建，复用现役模块与业务实现。**在首个 frame/onLoad、监听器注册、任务排队和动态加载执行之前，U 就应没有业务准入。** 最容易审计的方式是不实例化这些 U 对象、不注册其命令和任务；必须保留的对象，则须证明其每条可达业务路径均经过门禁。

不能先运行普通基地，再设 `_visible=false` 或“取消一次”后宣称纯净。也不能在尚未证明 U 取消的同一个活跃 VM 中把专用入口随意切回普通游戏。本轮入口退出回 launcher 或受控重启；返回 C1-I 内的 M 世界不等于恢复 U。

### 3.3 最小真实岛的组成

1. **可信 bootstrap 与能力清单。** 本轮仅登记允许的 M 输入目标、真实 surgery 模块、一个现役 Native 目标及 PlayerInfo 缓存。允许的构建/模块、scope、incarnation 在执行前确定；缺项不开门。未知 SWF 的拒绝发生在 load/onLoad 之前，而不是运行后发现没 ACK 再拒绝登记。loadMovieNum 本轮可明确禁用，但不得标注“已兼容”。
2. **最小真实世界上下文。** 复用现役 opener 所需的角色、外观与只读快照链；移除普通基地的门、NPC/任务和玩家移动入口，或证明这些依赖已经受控。用可丢弃测试身份与隔离测试存储，不接真实玩家存档。若实际初始化依赖强迫 U 执行，扩大该闭包并再审；不能用伪造 readiness 的替身通过测试后称真实链已成立。
3. **现役 opener 与 surgery 草稿/取消。** 必须运行原业务处理器和实际页面，不复制一个简化页面。页面 Apply 隐藏不足以隔离写入：Host task 与 AS2 commit 入口均须由 C1-I 能力明确拒绝付费提交。快照生成编辑 session 是允许的临时状态，不应误报为“完全零状态变化”。
4. **真实 Native 交互和缓存。** 选一个现役、无持久写目标；PlayerInfo 使用实际分块缓存及 GPU 承载。截图贴图或新画一个按钮不能替代。具体目标与 Web lazy/runtime 代码须在施工前补读；本包没有足够内容让我替其签完闭包。

这四项之外，不迁基地玩法、理发/睡眠/商店、任务系统，不改原暂停协议，不顺便重构存档，不提前展开 B。安全边界做足，不等于本轮业务范围做大。

### 3.4 付费业务的特殊约束

`PlasticSurgeryPanelService` 原有 snapshot/commit/query 命令注册与 token 校验，不等于输入 owner 校验。commit 可 markDirty、改变姓名/外观、扣 5 货币并进入 save_pending，再调用 durable flush。（E10 L15–27、L58–91、L115–163。）

所以首轮无持久写须在调用边界阻止 commit 到达，不是依靠人类“不点”。与此同时，输入取消不能普遍撤销已越过提交点的业务，也不能把既有 save_pending/unknown 记录删掉作为清场。输入手势身份、编辑 session、业务操作身份三者分开；未来付费纵切仍需要原有恢复/对账合同和授权。

## 4. Q3：继续普通基地必须扩面到哪里，哪些变化需用户决定

### 4.1 扩面的计算方法

迁移对象应是**该场景下所有仍可达的业务副作用闭包**，而不是“两个可见按钮”或“两个 SWF 文件”。从每个 raw、按键轮询、帧回调、异步回调和 Host/gameCommand 入口向后追踪，直到实际副作用与可执行内容加载；将它们纳入同一准入/取消合同，或证明在 C1 存续期间根本不可达。隐藏、只读命名、主根有一个 gate 都不能替代该证明。

按现有证据，至少包括医务室整形原入口、门与场景切换、演员输入/按键状态、NPC 初始化及任务检测、菜单可见性与刷新、全局 UI 命令/加载、其派生帧任务和 Host 返回回调；一旦允许从这里回到普通基地，相应目的场景与再加载内容也进入可达范围。确实断开的纯显示区域不需要为凑“全游戏迁移”而扩进去。（E07–E09。）

### 4.2 不可静默决定的产品语义

| 议题 | M 原型或拟议收缩可能引入的变化 | 处理 |
|---|---|---|
| 提交时点 | 原 onPress/onRelease 等行为统一成 Begin/End 后提交 | 逐目标对照，不能把所有操作默认改成 release |
| 多键/混合输入 | 原型右键叠加会取消左键；实际游戏可能有组合操作 | 是仅 C1-I 限制，还是正式游戏规则，须用户决定 |
| 拖出、拖回、覆盖目标 | 原型简化命中顺序未必等于原显示树 | 固定正式规则与遮挡关系后验收 |
| 激活点击与首击 | 点击非活动窗口是只激活还是激活并操作 | 必须选定；不能把人为吞掉首击称 raw 修好 |
| 键盘与文本 | Tab/Enter/Space、自动重复、快捷键、IME Enter 与候选窗口 | 规定 owner 与组合键边界，不能永久禁键却称基地行为未变 |
| NPC、任务与暂停 | 任务检测相对开面板的时序、切出/模态时世界动作 | 复用已有规则；任何语义变化另列批准，不借输入工程重写暂停 |
| 动态内容 | 不在清单的外部 SWF 被禁用 | 是专用入口范围还是正式功能删减，要明确告诉用户 |

**推荐路线仍是 C1-I。** 它把工程集中在可验证的生产链与公共交接机制；普通基地的迁移另列闭包清单与语义差异表，待用户接受范围与规则后再展开。不能因为每发现一个 U 入口就无授权地扩大整场景，更不能为了避免扩面而把该入口改名为“背景”。

### 4.3 明确停止条件

出现以下任一情况，停在自动验证或路线审查，不进入 C1 人验：首帧之前不能证明 U 无准入；任何未知可执行加载先运行后登记；raw/polling/回调在门闭后仍能绕到业务；角色或页面初始化依赖未经审计的 U；真实 Native/Web 源未读而只能用 demo；取消回执不覆盖真实待执行任务；物理基线为 Unknown 却准备开门；READY 冲突后不恢复；旧几何/旧实例输入可提交；Web/Native 关闭未确认而 Flash 已重新获权；同一手势被两个后端消费；必须改变正式游戏语义但未得到用户决定。

这些停止条件不触发重新研究 native 取消消息；应修当前合同、缩小可执行闭包或回到用户做范围选择。

## 5. Q4：生产公共底座与交接顺序

### 5.1 先把物理账本从 owner 生命周期里拿出来

现役 controller 只在 active 且有 surface 时转发捕获输入；Surface 隐藏时直接返回；CancelPointer 清 `_physicalButtons`，Rebind/等待释放依赖物理状态查询。（E13 L72–147、L267–288；E14 L48–57、L246–268。）这可作为端点状态处理，却不能充当跨失焦、隐藏、外部释放的全局物理真相。

生产账本应独立于 M/Web/Native 的显示、焦点与存活，先观察再按 owner 路由。外部窗口的按下/释放可以观察用于账本，**不因此获得吞掉外部窗口输入的许可**。每个受支持的按钮及会影响目标的按键至少区分 Down、Up、Unknown；另有观测代次、输入序号、来源/注入标记和健康状态。owner epoch、geometry、业务手势与观测代次不是同一个计数。

取消、隐藏、重绑、销毁 endpoint，只撤销业务资格，不把真实 held 清零。输入观测有缺口、队列溢出、来源失效或查询资格不明时，降为 Unknown 并关门。记录连续和无本地丢弃只是必要观测之一，不是 OS 连续性证明。

**生产初始化不能照抄五键 Down/Up，也不能要求玩家先把五个按钮各按一次。** 可行候选必须在声明支持的桌面/权限环境下，证明状态快照有效，把连续边沿与有界的采样/排空前缀对齐；任何竞争或不一致都重试，不把默认零认成 neutral。GetAsyncKeyState 的零还可能表示查询失败，低位历史不能可靠补漏；重复读零若未解决有效性问题仍不成立。物理左右键与逻辑映射也须区分。（W2。）

本轮要求的是这个合同及其实际实现证据，不声称 R8 已提供该实现。自动刺激仍可使用 SendInput，但 neutral 初始化必须在不依赖五键合成校准的条件下成立，注入刺激与实际硬件的证明范围分开记录。自动门禁要覆盖“冷启动时全部松开即可正常开始”“启动前已持键，后来实际松开可恢复”，并同时覆盖外部窗口释放、隐藏、失效恢复；不能靠合成按键或无限等待换取通过。

### 5.2 取消的线性化边界与证书

建议最小状态为：`BootClosed → Revoking → WaitNeutral/Blocked → Prepared → Ready(owner) → Held(owner)`；故障可以退回 Blocked。是否存在多个准备子状态由实现决定，但以下事实不可合并：

- Host 停止接收新业务，不等于远端已撤销。
- 所有相关 scope 撤销完成，不等于物理键已经松开。
- endpoint 准备好，不等于已经获得输入权。
- 已发送 close、窗口隐藏或一次回调结束，不等于旧端点不再能产生业务。

取消先关闭新准入并作废当前手势/准备轮次，再把取消送到**实际拥有状态和任务的域**。每个确切 scope 关闭 gate、清 pressed/drag/hover 等受控状态、撤销未提交工作；回执绑定 session、coverage/构建清单、scope incarnation、owner epoch、cancel ticket，并说明当前待撤销义务已经完成。不能只复读收到的 ticket，不能由父节点替未审计的独立子节点空签。

ACK 集合必须等于预期覆盖集合，不能仅计数相等。超时、旧 ACK、未来 ACK、重复/伪造 scope、未知已运行子域都不放行；重试只重试幂等取消/准备协议，不重放用户动作。数据队列损坏不能使控制撤销静默消失；无法确认时停在撤销未确认，而非宣称“都取消了”。

已进入不可撤销业务阶段的操作保留操作 ID、结果与恢复状态。只要有未结算工作可能回写旧页面或世界，必须在交接合同中明确其隔离/对账归属；不能用粗暴清数组把业务事实抹掉。

### 5.3 AS2 opener 应怎样进入交接

现役 `_root.打开整形手术()` 最终调用 `PlasticSurgeryPanelService.openPanel()`，生成 `world_plastic_surgery` 请求；Host 对 surgery 分支检查 source 字符串后开面板。这个来源白名单不是输入令牌验证。`RequestOpenPanel` 总入口已有 openRequestId 参数，但 surgery 分支未将其变成手势/取消证书。（E09 L19–22；E10 L24–27；E11 L3204–3206、L3306–3311。）

最小修补是沿原链传递或在受控上下文中消费当前合法手势身份，Host 将它与实际登记的发送域核对，并且最多接受一次。不要新建一个绕过原 service 的“C1 开面板”假入口。编辑 session/token 仍做编辑事务校验；它不替代输入身份。

**时序关键：先把合法完成手势兑现为一次独立 OpenIntent/handoffId，再撤销旧 owner。** 之后冻结该意图等待屏障，不再调用旧手势、不补点击。若先升旧 epoch，再试图用已过期 token 开页面，会制造“必须重放才打得开”的伪需求。OpenIntent 只能消费一次，失败则结束/取消该意图，不能在超时重试中重开多个面板。

### 5.4 双向 handoff 的必要条件

| 步骤 | M → Web/Native | Web/Native → M |
|---|---|---|
| 1. 合法意图 | 受准入手势产生一次 opener；旧动作不再分发 | 当前 panel incarnation 产生一次关闭/切换意图；按产品规则结束或撤销编辑 |
| 2. 撤销旧域 | M 全部 scope、延后任务、加载回调与旁路入口关闭 | 旧 endpoint 的 capture、pressed、拖动、按键重复、文本组合、待处理事件/回调与自主 reopen/focus 路径撤销或被实例屏障隔离 |
| 3. 屏障 | 等全覆盖取消证书；保持全局观测，不清 held | 等确切实例撤销/确定退休证据；仅隐藏或 close-post 不够 |
| 4. 准备目标 | 目标 visual、实例、geometry、OS 焦点候选准备，但业务仍无权 | M 的新轮次、geometry 与合法前台归属准备，U 仍关闭 |
| 5. 最终授予 | 可信 neutral、观测前缀已排空、准备轮次未被边沿/几何/焦点变化打断，才 grant | 同左；不能由旧 RestoreFocus、自主 return-stack 或延后回调提前授予 |
| 6. 新输入 | 只接 grant 之后真实新输入；不转发 opener 的尾 Up | 只接完整的新 Begin/End；关闭页面的 Up 不得成为世界点击 |

授予至少满足：`U 已排除 ∧ 旧覆盖撤销完成 ∧ 无未隔离延后义务 ∧ 物理基线有效且 neutral ∧ 目标实例/几何/前台归属有效 ∧ 传输与观测健康 ∧ 新刺激晚于授予前缀`。

READY 收到不能让旧 raw 业务重新有权；原型提前打开 AS2 local gate 之所以可行，是因为所有 raw 仍无业务权且 Host 是唯一逻辑来源。生产不得复制其表面动作而遗漏这个前提。准备期间发生冲突边沿、实例/geometry 变化或前台变化，应作废这一轮，重新等待 neutral 并准备；修复的是恢复轮次，不是重放刺激。

Tab、Enter、Space、快捷键与 IME 不属于“五个鼠标按钮都松开”的推论。目标可能需要保留合法的 IME/下拉窗口焦点关系，必须精确登记而非放大成任意同进程窗口；输入业务授予前核对实际焦点。切到外部应用时不得被定时恢复强夺回来。针对 IME 的提交/取消策略须显式固定，不能把失焦时自动完成的字符插入送进新 owner。

### 5.5 现役 close/focus 链必须服从同一个协调器

`PanelHostController.DoClose` 会尝试通知 Web 关闭，发送失败会记录后继续后续流程；之后恢复 HUD、清 active panel、发布 closed 事件并调用恢复 Flash 焦点。（E12 L3180–3259。）这证明现有操作序列有多个绕过统一输入屏障的候选位置，**不证明当前实机已在这些位置出错**。

应让这些步骤变成协调器控制下的 visual/资源准备或通知，不让“发出 close/设成 null/恢复焦点”自行等价于输入授权。已有 exact panel-instance 关闭方法可以复用，但实例身份本身不证明页面无任务。若 Web 关闭通知未确认，须保持世界输入门闭；通过确切实例退休/重新建立端点来恢复时，也须防旧回调复活，并保留已提交业务的对账状态。旧 return-stack、自主重开、延后焦点恢复与 rebind 一并受 handoffId/实例屏障控制。

## 6. 最小施工顺序与自动验证出口

### 6.1 顺序

| 次序 | 实施边界 | 进入下一步所需证据 |
|---|---|---|
| 0 | 冻结 C1-I 可执行/业务清单、支持输入语义、无持久写能力，保留现役正常入口不被实验影响 | 确认首帧前 U 排除与真实依赖闭包；遗漏模块不能以猜测补齐 |
| 1 | 全局物理观测、Unknown/代次/健康与 neutral 恢复 | 冷启动、预持键、外部释放、隐藏及观测失效的自动正负控；不得用实验校准代替 |
| 2 | 统一准入协调器、CANCEL/覆盖 ACK/READY、任务及几何身份 | 补 S1–S4、部分 ACK、真实子域未清理和恢复活性；不把原型原封不动搬生产 |
| 3 | C1-I AS2 受控入口、真实 opener 身份、原 service 与 Host 路由 | 原 raw/命令/任务旁路全部被拒；一次有效输入仅一个 OpenIntent |
| 4 | 真实 surgery 草稿/取消、Native 样本及 PlayerInfo 缓存；两向交接和 close/focus 约束 | 两向互斥消费、第一份新输入、实际目标身份、零付费提交/零真实存档接入 |
| 5 | 自动矩阵冻结、复核反例和未测项 | 全部门禁通过后才形成 C1-I 人验候选；随后人验不代替缺失的自动安全项 |

bootstrap/清单的纯静态工作可以与物理账本准备并行；任何真实交互准入必须等待其依赖通过。不因 parallel lane 数量增加而让多个实现同时改公共输入权威。

### 6.2 自动门禁矩阵

| 门禁 | 必须存在的反例/刺激 | 通过条件 |
|---|---|---|
| A. 首帧与 U 闭包 | 直接打 raw 回调、Key/polling、帧任务、gameCommand、Host 回调、隐藏对象、NPC 检测和门切换路径 | 在真实门禁关闭/未入域条件下不产生 opener、任务/场景副作用、未知加载或写入；验证实际 sink，不仅扫描字符串 |
| B. 跨 SWF 生命周期 | 允许子域正常加载；未知/嵌套/晚到加载、同路径新实例、旧加载完成、被禁用 loadMovieNum | 未允许代码在执行前被阻止；受支持子域换 incarnation/coverage；旧回调失效。拒绝支持与实现支持分开记 |
| C. 物理连续性 | 无合成校准的冷启动、启动前持键、外部 Up、隐藏/最小化、observer 失效、输入队列丢失、多键与键盘修饰键 | Unknown 不准入；真实松开且健康恢复后，在预先规定的有界条件内可获得独立新输入；不以永久封锁判绿 |
| D. CANCEL/READY | S1 队列故障且 AS2 已排队；部分/陈旧/不匹配 ACK；真正有未清理任务的子域；S2 READY 两回执间按下；单向断链 | 取消未确认绝不交接；证书成立后旧域无未隔离提交；恢复后协议可幂等重新准备，旧输入不重放 |
| E. 唯一业务身份 | 重复 opener、旧 gesture、orphan End、返回窗口首击、关闭尾 Up、两端相同刺激、AS2 旁路直接调用 | 只有当前实例/owner 的有效新输入提交一次；不把仅 globalDown/Up 或计数递增当新 press 身份 |
| F. 几何与命中 | 持键窗口移动、大小/DPI 变化、隐藏/重绑、入队后换 geometry、重叠/遮罩/目标换实例 | 老按钮边沿不重投新目标；取消与几何轮次贯通；新目标恢复后首个合法新手势成功 |
| G. 真实三样本 | 原 surgery opener→真实页面姓名草稿→取消→M 世界；现役 Native 目标；实际 PlayerInfo 缓存 | 原处理器与真实 Runtime 身份可核对；两个后端不双消费；无 paid commit、无真实玩家存储接入；不能用新 demo 代替 |
| H. 键盘与 IME 协议 | 旧 KeyDown/重复/字符晚到、Tab/Enter/Esc、组合中关闭/切出/返回、IME 候选相关焦点 | 旧 owner 输入与组合尾事件不提交到新 owner；规定的 IME 提交/取消策略可自动观测；不以 Space 诊断计数代替 |
| I. 判定器与运行证据 | 有意放开一个旁路/接受旧 ACK/允许双消费的可丢弃负控；setup 失败；缺刺激、丢日志、超时 | 负控必须真失败；setup/缺覆盖标记为失败或未知，不能归通过；源码、构建、实际载入身份和完整刺激链可追溯 |

A/B/D 的故障注入只用可丢弃测试数据，不能向真实存档投毒。每项需同时给出预期事件、实际输入身份、业务/任务证据以及停止/恢复结果，不只屏幕截图或一个“PASS”。支持范围、超时/恢复阈值须测试前声明；长时和身份轮次更新另有有限可复现覆盖，不能用运行一次未故障推出无限期安全。

原 raw 失败矩阵永久保留为独立历史失败。即使 C1-I 在 M 协议下通过，其报告也应并列列出“U raw 未修复、生产入口隔离”；不能把 raw assert 换成 mCommit 后悄悄把原项改绿。

### 6.3 人验对象与最后权限边界

上述自动门禁全部闭合后，才把固定源码/构建/Runtime 身份的 **C1-I 候选**交给人类，集中验证真实中文 IME 的组合与候选窗口体验、Tab/文本焦点、约定的首击激活策略、自然 Alt-Tab、窗口移动/DPI/隐藏与恢复。自动协议测试不是这些体验已经好用；体验好也不能豁免自动安全失败。

不重复要求人类替 R6/R7 已明确接受的窄域问题背书；不把本轮人验扩写成整个游戏、所有 SWF、所有几何或长时场景已经通过。普通基地、B、付费/恢复业务纵切和发布仍按各自范围及用户授权推进。

## 7. 本轮未能核验的范围

本轮只做 ZIP 完整性检查、冻结源码阅读、原始日志复数及静态构造反例。未执行任何包内源码、补丁、构建脚本或原 Windows 进程；未运行 Flash/CS6/projector、WebView2、Native、人类 IME、真实硬件刺激或正式 runtime；没有访问玩家存档、凭据或发布环境。历史路径和 PID 只用于对照，不认定进程仍活着。

包内缺少可独立重算的运行二进制，故仅核对其记录身份，未认证构建可复现性。整个游戏输入入口、实际 Web lazy/runtime/页面、相关 Host task 的完整实现、真实 Native 样本/PlayerInfo 装配、角色初始化和任务/调度/存储依赖，没有全部随包，故不能在此宣称真实闭包已经封完。S1–S4 是静态缺口及拟定反例，不是新增实机结论。

**最终裁决：以 C1-I 启动即 U 关闭为推荐路线，先补物理观测与取消/READY/交接公共合同，再接真实 opener 和真实三样本；不授予普通基地的两按钮方案、不授予当前人验、不重开 native 消息搜索。**
