# 军阀 vNext 零背景首次游玩历史模板

> 当前不再单独触发 Slice 0/2 语义验收。本模板的有效观察项已并入[Slice 3 单一真人验收单](slice-3-human-acceptance.md)；保留本文仅供后续需要独立零背景复测时复用。

用途：验证当前 Slice 0 玩家文案与玩法帮助是否真的能被未参与开发、没有战棋经验的玩家理解。它只覆盖语义可读性，不验收 GameStage、AS2、正式入口、部署或大地图。

## 准备

- 使用真实 Launcher/WebView2，从“刘海 → 其他 → 测试 → 军阀演习测试”打开当前候选；保持默认九节点、默认难度和 `1024×576` 逻辑画布，不打开开发设置。
- 找一位未读过军阀设计文档、未参与开发且不熟悉战棋术语的体验者。
- 观察者只处理启动或崩溃，不能解释规则、指出按钮、翻译词语或示范操作。体验者可以自由打开“玩法帮助”。
- 一次观察控制在约 10～15 分钟；不录个人信息，不要求逐字填写长表。

## 三段观察

1. **看懂局面**：请体验者自行说明哪边是我方、现在轮到谁、眼前应该做什么，以及他理解的至少一个胜负条件。
2. **完成一轮动作**：体验者独立完成选兵、移动或进攻、查看反馈、结束我方行动。若自然遇到不可执行动作，观察他能否依据界面给出的原因与下一步自行修正；本轮没有遇到时只记“未观察”，不要人为讲解或制造答案。
3. **使用帮助后继续**：体验者自行找到玩法帮助，说明当前相关的“行动点”“驻军上限”或胜负规则，关闭帮助后继续原来的操作；同时观察状态和焦点是否让人迷失。

任何核心动作需要观察者解释，语义可读性即未通过。高级策略不会、走了次优路线或单纯输掉对局不构成失败。

## 最短记录

只需保留以下结论；无需生成 receipt、hash 或额外状态机：

~~~text
semantic_readability=passed | failed
技术异常：无 | <一句话>
首次停顿或误判：<位置 + 体验者当时的原话；没有则写“无”>
是否靠正文/帮助自行解决：正文 | 帮助 | 未解决
阻断修改项：无 | <最多三条>
~~~

若修改了规则、核心术语、帮助结构或首次入口，应换一位未看过旧版答案的体验者 fresh 复测；纯配色变化只需另做颜色独立检查。
