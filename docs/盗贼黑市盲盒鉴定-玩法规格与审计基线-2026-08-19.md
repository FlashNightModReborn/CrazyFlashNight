## 1. 产品结论

本玩法可行，且适合承担两项目前缺失的任务：

1. 提供一个操作较繁琐、需要观察和判断、但长期收益可计算且有保底的 K 点投送渠道。
2. 把“解密”从主要用于题材表达的被动技能扩展成有持续学习动机的经济/鉴定技能，并与既有“逆向”等经济能力形成不同分工。

核心不是普通抽卡，而是“有限货源下的成对估值”：玩家面对三个二选一货包组，通过轮廓、污泥遮挡、需求判断和解密等级找出更值得买的一件；买下后必须在“提取自用”和“当场回售”之间做一次不可逆选择。

本规格把经济闭环限制在黑市货包的来源与一次性结算令牌中，明确禁止普通库存、K 商城货物或合成产物回流成交易点。因此，K 商城已有的 `K → 物品 → 商人 → 金币` 路径不能逆向变成 `金币 → K`。

## 4. 术语与对象

### 4.1 未清洗货包（raw box）

战斗中由受控来源小概率掉落的黑市凭证物品。它不是一个已经预先生成具体内容的普通装备箱：上交时按货包等级/来源表给固定交易点，并增加黑市补货信用，避免通过兑换价反推隐藏内容。

未清洗货包必须具有明确的黑市来源标记或受控物品 ID；普通物品即使名称相似也不能调用上交路径。

### 4.2 柜台货包（counter offer）

黑市已经“初步清洗”、但仍被污泥遮挡的具体物品实例。购买前只能看到该解密等级允许的视觉信息；购买成功后立即揭晓。

货包的数量（堆叠）是实例属性；第 7.3 节的 `Q` 与经济不变量按整个实例（含数量）计算。

### 4.3 货包组（pair）

两个共享同一柜台标价、同类且视觉相似的柜台货包。组内只有一个购买名额。

### 4.4 柜台页（page）

三个货包组，即最多六个同时可见货包。生成、持久化和失效以整页为原子边界。

### 4.5 时间纪元（epoch）

由 UTC 时间和配置中的固定间隔计算的本地刷新周期。具体间隔是调参项。纪元只用于供给和刷新，不构成联网时间或反作弊证明。

### 4.6 交易点（trade point）

黑市域内的整数记账单位，报价面额与 1 金币单位等价，但不是金币，也不能由金币兑换得到。

为方便玩家查阅数量，交易点登记一个货币类展示条目（形状为 `type=消耗品`、`use=货币`、`price=0`，仅提供名称/图标/描述）：余额权威存于 `_saveExt.blackMarketV1.tradePoints`，经济面板与黑市界面投影显示。该条目永不上架、不可出售、不产生库存实例、不进入候选池、商店或合成路径；`price=0` 使其天然不满足第 7.2 节的正价格过滤。

### 4.7 提取与当场回售

- **提取**：把揭晓实例领取到玩家库存；此后只能自用或走普通商店金币出售路径。容量不足时按第 11.3 节强制转为当场回售。
- **当场回售**：实例尚未进入库存时，使用与普通商店相同的 AS2 售价计算和经济技能语义，把回售价结算为交易点。

### 4.8 页面草稿（page draft）

AS2 在创建新页时先持久化、但绝不投影给玩家的有界候选草稿。草稿包含 `draftId + revision + draftDigest`、6–`maxDraftCandidates` 个不重复的候选实例快照（身份、数量、插件、类别、经济报价输入）、生成摘要与过期策略；候选只是黑市域内的暂定实例，不进入库存、不产生货币或插件。Host 只能使用草稿中的不透明候选句柄、规范视觉与必要审计字段提出恰好三组的配对/左右建议，不能增删、改写或另造候选。

### 4.9 页面对象（page object）

AS2 对配对建议复验成功后原子提交的完整可见快照：恰好六个物品实例（身份、数量、插件）、组归属、左右位置、共同标价、生成摘要及来源 `draftDigest`。只有已提交页面对象可以投影给玩家；重开、崩溃恢复与“不重抽”承诺以该对象为唯一真源。随机种子只驱动污泥形状等视觉附加物，不再承担实例重建。

## 5. 玩家循环

```text
受控战斗来源
   │ 小概率 + 最大空窗保底；受纪元预算约束
   ▼
未清洗货包 ──上交──> 交易点 + 补货信用
                         │
                         ├──50:1 单向兑换──> K点
                         │
K点 ──直接支付──────────┤
                         ▼
                三组二选一柜台货包
                         │ 购买一件，同组另一件撤回
                         ▼
                    立即揭晓实例
                    ┌────┴────┐
                    ▼         ▼
                  提取       当场回售
                    │         │
             自用/商人卖金币  └──> 交易点
```

明确不存在以下边：

- `金币 → 交易点`
- `金币 → K点`
- `普通库存物品 → 交易点`
- `K 商城物品 → 交易点`
- `合成产物 → 交易点`
- `已提取黑市物品 → 交易点`

补充说明：直接 K 支付 → 购买赢家 → 当场回售 → 50:1 兑回构成的“纯 K 循环”是显式设计的满级奖励通道（BM-024），不是协议层兑换接口；其上界公式见第 7.6 节，投送节奏的主控仍是掉落概率与纪元预算。提取时容量不足按第 11.3 节强制当场回售，不允许托管区成为长期仓储。

## 6. 供给、刷新与“确实可获利”

### 6.1 掉落既要随机，也要有可计算上界

只写“小概率掉落”并不能形成硬上限：可重复战斗意味着长期总产出仍然无界，而且长时间不掉落会继续强化玩家对 K 点渠道不可靠的感受。因此必须同时存在：

1. `rawBoxDropChance`：合格来源的基础掉落概率。
2. `rawBoxPityEligibleCount`：连续多少次合格结算未掉落后，下一个合格来源必掉。
3. `maxRawBoxDropsPerEpoch`：每个纪元最多自然掉落多少个；达到后概率为 0。
4. `eligibleSourceRules`：哪些关卡、敌人、难度或结算算作合格来源。

空窗计数应持久化；普通刷新不能吞掉一个接近保底的进度。达到纪元掉落上限后暂停推进，在下一纪元继续。测试/作弊环境无需伪装成可信服务器，但正常玩法的计数必须幂等。

这使渠道同时具备：单次掉落的不确定性、最大劳动量的可预期性、每纪元投送量的硬上界。

### 6.2 基础柜台与玩家补货

- 每个新纪元提供 1 个基础柜台页。
- 上交未清洗货包会同时获得固定交易点和不可交易的 `supplyCredit`。
- 当前页未终局前，新增补货信用不得替换、插入或重抽任何可见货包。
- 当前页三个组全部购买或跳过后，若信用足够且未达到 `maxSupplementPagesPerEpoch`，玩家可以明确选择“整理下一批”。
- **全局 `pendingSettlementCount > 0` 时，基础页领取、基础页/补充页生成、“整理下一批”和任何新购买全部不可用（BM-023）**。该门跨页面、跨纪元和跨重启生效；打开面板必须先进入结算恢复视图，结清后才重新判断当前纪元页面资格。
- `pendingSettlementCount <= 3` 是存档加载、事务恢复与旧状态迁移都必须守住的防御性硬上限；正常 v1 交互在首个待结算实例产生后立即闭合新购买入口，因此通常最多为 1。发现大于 3 的存档视为损坏并 fail closed，不能截断后继续发页。
- 整理下一批按配置一次性消耗信用，原子生成一个新的六货包柜台页；生成失败不得扣信用。
- 不足一页的信用和超过本纪元补页上限的信用跨纪元保留，不到期、不折算货币。
- 回售已经揭晓的柜台物品不提供补货信用，避免同一批货既产生差价又无限复制库存。

`supplyCreditsPerRawBox`、`supplyCreditsPerPage` 与补页上限是调参项。结构上始终保持一页三组、一次最多六件。

### 6.3 纪元切换

- `epochId = floor(utcNow / refreshIntervalSeconds)`；夏令时和本地日期格式不能影响结果。
- 面板已经打开时跨过边界，当前页保持不变，对当前页的购买提交仍然有效；关闭后再打开才切换到新纪元。
- “整理下一批”按发起时刻的真实当前纪元计入 `maxSupplementPagesPerEpoch`；不允许为旧纪元页面追加生成补页。
- 关闭后重开时若存在待结算实例，先恢复结算且不得领取或生成新页；结清后，未购买的旧纪元货包作废，再按当前 UTC 纪元判断是否发放基础页。补充页计数与掉落计数按新纪元计算。
- 已经扣款形成的待结算实例永不过期，必须继续允许提取或回售。
- 时钟倒退不能让已记录的纪元号回退；时钟大幅前进只生成“当前纪元”，不逐个补发跳过的纪元。
- 游戏内一昼夜长度只作为 `refreshIntervalSeconds` 的节奏标定样本；无论其是否稳定、暂停或加速，都不能替换 UTC 纪元权威（BM-027）。
- 本规则用于避免重复发放和存档损坏，不承诺阻止玩家修改系统时间。项目内置修改能力，v1 不增加联网校时、签名时钟或封禁逻辑。

## 7. 三组二选一的经济生成规则

### 7.1 页面结构

页面创建状态机固定为：

```text
NO_PAGE
  └─ pagePrepare ──> PAGE_PREPARING（exact page draft 已持久化、玩家不可见）
                         ├─ pageCommit 成功 ──> PAGE_READY（exact page object 已持久化）
                         ├─ Host 超时/建议非法 ──> 保留同一 draft 重试或显式作废后重建
                         └─ commit 结果未知 ──> reconcilePage ──> PAGE_PREPARING / PAGE_READY
```

`pagePrepare` 先由 AS2 从资格真源创建并持久化 6–`maxDraftCandidates` 个候选实例的有界草稿；Host 对 exact `draftId + revision + draftDigest` 提交恰好 3 组、每组 2 件的视觉配对与左右建议。`pageCommit` 必须由 AS2 重新验证建议只引用草稿成员、六件唯一、组内同类、资格仍有效、报价摘要一致且第 7.3 节不变量成立，再派生共同标价并原子写入 exact page object。只有 `PAGE_READY` 可以对 Web 可见。

最终页面必须满足：

- 恰好 3 组；首次成功生成时恰好 6 个货包。
- 每组内类别相同；不同组类别可任意重复。
- 合法组合包括三组装备、两组消耗品加一组材料等。
- 页面以 AS2 提交并持久化的页面对象为唯一可见真源（BM-021）：六件实例、组归属与左右位置在 `pageCommit` 时冻结，任何重开只恢复、不重抽。
- Host 的视觉配对结果只是绑定 exact draft 的建议；AS2 可以拒绝并保留同一草稿重试，不能由 Host/Web 单方面决定页面内容。Web 从不接收 page draft。
- 同一页不得出现完全相同的物品实例，也不得让两组共享同一购买名额或结算令牌。
- 任一组购买成功后，兄弟货包立即进入 `WITHDRAWN`，之后任何重放都必须失败。

失败与幂等语义：生成/配对失败不消耗基础页资格或补货信用；关闭、崩溃或 Host 重启必须恢复同一草稿。若 `pageCommit` 已落盘但成功响应丢失，重试/对账必须返回同一个 `pageId + revision + pageDigest`，不得形成第二页。只有显式记录了作废原因、且没有已提交页面对象时，AS2 才能销毁草稿并重建；作废动作本身也必须幂等。

### 7.2 候选池硬过滤

所有候选必须先通过 authored eligibility 真源（BM-022），再进入相似度和经济配对：

- 全类别默认拒绝：仅经审计明确允许（`allow`）的物品可进入抽样；未审计或 `review` 状态一律不得进入生产候选池。该真源同时承担“任务唯一物、剧情钥匙、未揭示奖励、调试物品”的排除——现役物品 schema 没有这些标记字段，默认拒绝的 authored 清单是唯一可数据化验收的边界。
- 显式排除 `use=货币` 条目（金币/K点/经验值/技能点及任何同源新条目）与其他成长值对象：现役 `ItemUtil` 会把这些名称直接写入余额/成长字段而不生成库存实例，允许入池将打开交易点 → K点/技能点/经验值的直接转换，绕过本规格的闭环。
- 显式排除调试/测试物品与获取即触发余额、剧情或全局状态副作用的对象。
- 类别属于装备、材料或消耗品；有合法正价格、可生成数量、可回售规则和稳定物品身份。
- 不是情报或黑市未清洗货包。
- 装备具有可用纸娃娃资产且黑市视觉资格为允许（第 9.1 节）。
- 材料/消耗品具有可用图标且通过透明度、尺寸和空图检查；隐藏态不得使用携带品质/档位底色的背包帧，避免污泥之外的颜色侧信道。
- 随机插件池与候选池共用同一资格真源；当前版本无法安全持久化或回滚的实例类型必须排除。

### 7.3 同价、一赚一赔的不变量

本节不变量只约束**交易点差额**口径的“一赚一赔”；插件返还属于额外资产输出，口径与模拟见第 7.4 节。

定义：

- `P`：一组共享的柜台标价，单位为交易点。
- `C(P, e)`：在经济技能状态 `e` 下，AS2 权威购买路径实际扣除的交易点。
- `Q(i, e)`：物品实例 `i`（含数量堆叠）在相同状态下，AS2 普通商店回售价路径计算出的整数报价；黑市当场回售仅把该数值的结算货币改成交易点。
- `KCost(P, e) = ceil(C(P, e) / 50)`：直接用 K 支付时实际扣除的整数 K 点。
- `KEquivalentCost(P, e) = 50 × KCost(P, e)`：用于审计直接 K 支付的交易点等价值。
- `W`：高价值候选的最小盈利边际，必须至少为 50 交易点。
- `L`：低价值候选的最小亏损边际，必须大于 0。
- `E`：当前版本所有受支持经济技能的**可达（技能 × 等级 × 启用）组合**。现役为“口才”0–10 级 × 启用/停用（买价 `1-等级×0.03`、售倍率 `+等级×0.025`，买卖双向推高两件物品的边际）。最坏角点是确定的：赢家约束在口才 0 级最紧，输家约束在满级启用口才最紧。

组内低价值实例 `low`、高价值实例 `high` 和共同标价 `P` 必须同时满足：

```text
对所有 e ∈ E：
Q(low,  e) - C(P, e)                 <= -L
Q(high, e) - C(P, e)                 >=  W
Q(high, e) - KEquivalentCost(P, e)   >=  W
```

直接 K 支付向上取整且不找零，因此低价值实例在 K 支付下只会更亏，不需要额外放宽条件。若找不到满足区间的共同标价，该候选对必须被拒绝，不能靠 UI 文案掩盖。

推论：`KEquivalentCost(P, e) - C(P, e) ∈ [0, 49]`，标价越贴近 50 的整数倍，可行候选对越多。Slice 0 模拟必须按 `C mod 50` 分布报告可行对数量，不能只报告总价差分布。

结果是：无论玩家有没有启用当前受支持的经济技能，每组都稳定存在一个货币赢家和一个货币输家；经济技能扩大玩家收益或降低成本，但不能把两件都变成赢家。将来若“口才”或售价公式变化，必须更新 `economyDigest` 并重跑全候选模拟。

### 7.4 经济技能复用

- 黑市购买必须复用普通购买路径中已启用经济技能的语义，而不是在 Web 复制倍率。
- 当场回售必须复用 `_root.物品UI函数.计算售卖总价` 或其后续权威等价实现，包括基础 `0.25` 回售倍率、已启用“口才”、tier 与强化价值。
- 当前商店出售会返还装备上的插件材料；黑市当场回售保持同一规则。返还插件属于额外物品输出，不计入第 7.3 节的“交易点赚赔”符号；插件的身份、稀有度与估值分布必须单独进入第 16 节的模拟与调参报告。
- 若插件返还所需容量不足，交易保持在待结算状态，不能先发交易点再丢失插件。
- 购买、回售和插件返还的最终数值都由 AS2 在提交时重算；Web/Host 缓存只能展示预览。

### 7.5 K 点与取整

- 交易点余额和 K 点余额都是非负整数。
- 手动兑换使用 `kGain = floor(tradePointsSpent / 50)`；不足 50 的交易点保留，不到期。
- UI 只允许提交整 K 点兑换量，AS2 反算并扣除 `50 × kGain`，避免“提交任意交易点并丢掉余数”。
- 直接 K 支付显示 `ceil(C/50)` 的精确成本和“不找零”说明。
- 直接 K 支付后当场回售仍然得到交易点；它不创建一条通用 `K → 交易点` 兑换接口（其经济效果见 BM-024 与第 7.6 节上界）。

### 7.6 发行上限口径

为避免把交易点兑换、K 直接支付与跨期余额重复计算，先定义黑市流动价值：

```text
V = tradePoints + 50 × K

M_TP(pair, e) = Q(high, e) - C(P, e)
M_K(pair, e)  = Q(high, e) - KEquivalentCost(P, e)

maxPairLiquidGain = max(0, 所有可出现 pair、e 与支付方式上的 M_TP/M_K)
maxPairKMargin    = max(0, 所有可出现 pair、e 上的 M_K)
```

每个纪元由本机制新增的流动价值可按下式给出保守上界：

```text
rawPointCap = maxRawBoxDropsPerEpoch × maxRawBoxPointValue
pageCap     = 1 + maxSupplementPagesPerEpoch
pairCap     = pageCap × 3
offerLiquidGainCap       = pairCap × maxPairLiquidGain
kCycleValueCap           = pairCap × maxPairKMargin
kCycleKEquivalentCap     = ceil(kCycleValueCap / 50)
epochAttributableValueCap = rawPointCap + offerLiquidGainCap
```

对已经冻结的具体页面集合，可以用逐组最大边际求和替代 `pairCap × maxPairLiquidGain` 得到更紧上界；全局审计必须保留上述保守式。`kCycleValueCap` 是纯 K 循环（BM-024）的流动价值增量上界，`kCycleKEquivalentCap` 只是其 K 等价值表示，必须对总价值先求和再 `ceil`，不能逐组 `floor` 后相加。

`tradePoints → K` 只改变 `V` 的组成，不创造价值。由于交易点和 K 都可跨期，玩家可以在本纪元兑换此前累积的余额；因此“本纪元实际收到/支付了多少 K”的现金流没有独立于期初余额的硬上界，不能拿它冒充本纪元投送。正式调参必须分开报告：期初/期末 `V`、本纪元可归因价值增量、实际 TP/K 毛现金流、纯 K 循环分量，以及 P50/P90 K 等价值/小时和保底最慢速度。插件返还继续作为独立资产输出，不计入上述货币上界。

如果取消 `maxRawBoxDropsPerEpoch`，本机制只能称为“按游玩时间限速”，不能再宣称有硬投送上限。

## 8. 玩家需求权重与自用动机

玩家需求只改变抽样概率，不改变经济赢家/输家定义，也不构成预言式推荐。

允许读取：

- 玩家已经主动标注的合成方案及其尚缺材料。
- 已经接取的任务（`tasks_to_do`）所需材料。
- 当前装备/快捷栏中的药剂类型、现有数量和可配置的缺口阈值。
- 已经公开的装备槽位与库存事实。

禁止读取：

- 尚未接取或尚未揭示的任务需求。
- 隐藏任务阶段、未来剧情钥匙、未来奖励或情报内容。
- 用内部流派预测模型直接断言“这是玩家需要的装备”。

生成顺序应为：先用需求快照加权候选，再寻找视觉相似且满足经济不变量的同组对象。需求物品既可以是货币赢家，也可以是货币输家；后者形成“卖掉能止损、留下更有实际用途”的选择。

类别与组构成必须独立于需求快照抽样：需求权重只作用于类别内部的选品，不得让类别分布本身成为可识别的需求信号。需求命中不得在购买前通过标签、ARIA、排序、污泥多少或动画强弱泄露。揭晓后可以显示“用于已标注合成”或“补充当前药剂”等已知用途。

`maxDemandBiasedPairsPerPage` 和权重倍率是调参项，必须保留至少一个不受需求定向的惊喜空间。

## 9. 视觉配对与污泥生成

### 9.1 视觉资格

装备数据需要新增可审计的黑市视觉资格，概念字段如下；具体 XML 位置须在施工 ADR 中按现有物品 schema 冻结：

```xml
<blackMarketVisual eligibility="allow|deny" reason="..." revision="..." />
```

- `deny` 至少覆盖激光束、常驻发光/拖尾、脱离主体的大面积特效、空遮罩、错误锚点和明显破图。
- 未审计或 `review` 状态默认不能进入生产候选池。
- 装备视觉资格是 BM-022 全类别 authored eligibility 真源在装备维度的附加审计；材料/消耗品的资格由同一真源的非视觉维度承载（默认拒绝 + 人工/规则复核）。
- Luna 集群可以批量看图并生成建议清单，但模型结果不能在游玩时直接决定资格，也不能自动写入生产数据后跳过人工/规则验证。
- 游戏运行时仍执行廉价确定性检查，防止资产漂移后出现空图、极端面积、越界或缺失纸娃娃。

装备池容量不足时必须换类别、重采样或保留上一个有效页面；严禁把装备退化成普通图标。材料和消耗品本来就没有纸娃娃，可以使用其规范图标。

### 9.2 规范化渲染

同组装备必须在完全相同的规范环境渲染：

- 同一中性纸娃娃、姿态、性别/体型、朝向、视口和缩放策略。
- 按槽位使用同一锚点，不得为追求相似度任意拉伸真实外形。
- 去掉与物品身份无关的背景和 UI，只保留可控的 alpha 主体。
- 随机插件先生成并存入实例，但只有会实际改变外观且已通过资格检查的部分才能进入渲染。

材料/消耗品使用同一尺寸、留白和 alpha 规范化规则。现役图标烘焙契约中 `f1=背包图标、f2=掉落物`：黑市优先选择无品质底框的透明 `f2`，存在但不透明的 `f2` 必须 fail-closed。首版影子渠道为了维持全目录测试覆盖，可以把无 `f2` 的单帧 `f1` 在隐藏态归一为同一单色，揭晓后再恢复源色；该回退仍是 `review`，不能代替生产候选所需的透明/中性 authored 资产。

### 9.3 廉价相似度搜索

运行时不做全库两两比较。建议管线：

1. 按类别、子类、槽位、宽高比、alpha 面积和粗轮廓描述符分桶。
2. 从满足经济区间的候选中抽取有上限的小样本。
3. 对样本做锚点对齐后的 mask IoU、轮廓距离和差异面积比较。
4. 选择达到 `minVisualSimilarity` 且经济差异最大的合法组合。
5. 描述符和规范化 mask 按 `assetDigest + rendererRevision` 缓存。

生成必须有时间预算、尝试上限和拒绝原因；超时后走类别重采样或有效页保留，不得阻塞 Flash 主循环。

### 9.4 破局点与污泥

- 破局点不得按物品或物品组合维护人工标注表。每件规范化 Alpha 必须先独立计算 PCA 主轴、细化骨架端点、局部宽度/质量和分支持久度，以确定性评分自动选择锚点；结果按 `assetDigest + rendererRevision` 缓存，因此复杂度随物品数增长，不随配对组合数爆炸。
- 自动锚点优先选择可学但不直接泄露身份的稳定结构端；长枪示例中允许枪托胜出，且折叠托与固定托必须由同一算法处理。低置信度只能进入确定性算法 fallback、资格复核或拒绝，不能在游玩时请求人工补点。
- 对齐两个 mask 后仍可计算 XOR 差异区和信息量，用于验证破局点是否有区分价值；但它不能反向成为每个配对的人工作者标注入口。
- 污泥只允许存在于物品局部 Alpha/SDF 包络及有界轮廓外扩、连通滴落区，不得使用覆盖整个卡窗的矩形遮罩。锚点揭示区从自动锚点沿物品内部加权测地距离扩散，所有一眼可见的主要差异仍应被覆盖，只保留经过可见性阈值验证的破局区。
- 污泥的世界观真身是包裹物资进入休眠的军用纳米机器人。正常观察距离首先必须读成湿重污泥；蜂群单元接缝、静态团簇结节和冷金属微粒只在近看时提供机械暗示。休眠态不做持续脉冲或爬行动画，避免把动画强度变成价值侧信道。
- 额外污泥、高度场与滴落只能使用页面/offer 种子落在物品局部区域，保证关闭重开完全一致。高度外观可组合低频 fBm 宏观泥团、Worley 蜂群接缝、SDF 贴附厚度和法线明暗；这些只改变材质，不能改变信息预算。
- 两件按“污泥覆盖的物品有效 Alpha 像素 / 物品有效 Alpha 总像素”计算实际覆盖率；目标/实测差、边缘噪声和动画强度必须落在相同容差内，不能让遮挡量成为价值暗号。首个 Shadow Lab 阶梯为 Lv.0/3/5/10=`97%/84%/54%/18%`，只作调参初值，不冻结生产数值。
- 必须保留最低主体可见比例；不能把玩法退化成纯随机点击。
- 左右位置、泥块数量、色阶、抖动或音效不得与高低价值相关。

### 9.5 隐藏身份边界

购买前的 Web 快照只能包含：不透明 offer/visual handle、脱敏类别、允许的身份无关视觉栅格/mask、共同标价、当前解密层级和可公开状态。普通产品 init/snapshot/遥测/匿名导出均不得携带可重放 seed；实例与视觉随机性必须由不可公开的会话熵驱动。

真实物品 ID、物品名、显示名、icon key、原始文件名、资源 URL、插件名、精确回售价和任务身份不能提前出现在：

- DOM 属性或隐藏节点；
- ARIA label / description；
- CSS class、data attribute、日志或错误文本；
- 可枚举的前端缓存键；
- 网络/桥接响应中的未使用字段；
- 隐藏 `<img src>`、CSS URL、预取、缓存键或浏览器实际发出的请求 URL。

这不是反作弊安全边界，而是避免普通检查工具、资源面板和无障碍树意外破坏玩法。Host/私有视觉端口可以持有映射，Web 只能用不透明句柄请求不可逆的安全栅格/画布，不能收到真实 asset URI 或据此提交任意物品名。exact 目录/视觉/debug 只允许显式开发 Lab bootstrap + 专用 capability；普通 `mode=dev`、`shadowOnly` 或 `debug:true` 均不授予该能力。

## 10. “解密”0–10 级信息权限

当前 [skills.xml](../data/skills/skills.xml) 中“解密”为被动技能、`MaxLevel=5`。施工时把 `MaxLevel` 扩展为 10：升级 SP 已是数据驱动标量（`UpgradeSP`），存档中技能等级只是一个数字，旧档无需迁移；需同步更新说明文本以包含黑市鉴定用途。本规格不直接修改该数据。

**情报域副作用（产品决策：顺势开放）**：现役情报面板直接读取已启用解密等级；[information_dictionary.xml](../data/dictionaries/information_dictionary.xml) 已存在 4 页超过旧上限的加密情报（6 级两页、9 级一页、10 级一页）。扩展 `MaxLevel` 后这些页面按新等级可读。BM-DATA-01 必须包含这 4 页的叙事签收与 Intelligence 面板回归；后续情报域施工时一并处理其叙事前置与内容完整性的深化。

黑市读取面板打开时的**已启用等级快照**：技能未学习、未启用或数据非法均按 0 级；等级钳制在 0–10。提交时若技能快照摘要变化，旧预览令牌失效并要求刷新，而不是沿用 Web 自报等级。

| 已启用等级 | 购买前允许看到的信息 |
| --- | --- |
| 0 | 原始污泥视图；只有类别、共同标价和基础操作，无辅助 |
| 1 | 去除约 15% 的非关键随机污泥，略增强主体连续性；不新增语义信息 |
| 2 | 去除约 30% 的非关键随机污泥，强化粗轮廓；不标记破局点 |
| 3 | 甜点等级：所有设计保留的破局点清晰可见，但不自动圈选或解释 |
| 4 | 进一步降低非关键污泥，目标为约 60% 的基础轮廓可读性 |
| 5 | 显示基础物品全貌；仍不显示名称、属性表、精确回售价和随机插件 |
| 6 | 显示是否带随机插件及插件数量，不显示插件身份 |
| 7 | 显示随机插件的确切身份；不直接给出货币赚赔方向 |
| 8 | 显示当前支付方式下绝对差价属于“小”或“大”，不显示正负号 |
| 9 | 显示更窄的绝对差价档位，例如 `0–74 / 75–199 / ≥200`，仍不显示方向 |
| 10 | 显示“当场回售盈利 / 当场回售亏损”；按当前支付方式和经济技能快照计算 |

其中 3/5/7/10 是产品里程碑，1/2/4/6/8/9 是本规格为连续升级体验提出的审计默认值。百分比与差价档位可以调参，但必须满足信息单调性：高等级不能比低等级少看到已经解锁的信息。

三条结构性约束已冻结：

- **方向支持重叠**：8/9 级每个实际显示的绝对差价档位 `b`，在当前支付方式、经济技能快照与生产抽样权重下，都必须同时存在 `Δ > 0` 与 `Δ < 0` 的可达样本，并满足 `max(Pr(Δ>0 | b), Pr(Δ<0 | b)) <= maxPreLevel10DirectionPosterior`。该上限不得高于 `0.75`；若样本支撑不足或后验越界，必须合并相邻档位或退回更粗提示，不能显示一个事实上等同于赚赔方向的档位（BM-028）。
- **档位防撞只是必要非充分条件**：9 级档位边界仍不得与 `W` 或任何保证边际重合，但“边界不相等”本身不能证明不泄漏。赢家 `|Δ| ≥ W ≥ 50` 恒成立，例如 `W=100` 时显示 `0–74` 仍会确定性暴露输家；必须同时通过上述方向支持重叠检查。
- **“持平”不可达**：第 7.3 节不变量保证每件物品 `|Δ| ≥ L > 0` 或 `≥ W`，不存在零边际候选；10 级只显示盈利/亏损两态，UI 可保留防御性“无法判定”态用于数据异常，但它不是正常玩法状态。

补充说明：对能辨认装备外观的资深玩家，5 级“显示基础物品全貌”近似身份揭示，8–10 级对该群体的边际信息递减。调教门（第 19.2 节）的强度评估必须按玩家熟悉度分组，不能只用新手样本。

10 级直觉只判断**当场回售的交易点差额**，不评价流派适配、合成用途、插件的主观价值或未来价格。切换交易点/K 支付方式时，8–10 级提示必须基于所选支付方式重新计算。

禁用技能进入黑市是正式支持的 0 级玩法，可用于挑战、测试和玩家二创；不能被当成错误状态。

## 11. 购买、揭晓与一次性结算状态机

### 11.1 组状态

```text
AVAILABLE
  ├─ skip ───────────────> SKIPPED
  └─ purchase(member A/B)
          ├─ success ────> PURCHASED_PENDING_SETTLEMENT
          │                 sibling = WITHDRAWN
          │                 ├─ extract ──────────> EXTRACTED（持久终态）
          │                 └─ immediate_resell ─> RESELL_COMPLETED（持久终态）
          └─ failure ────> AVAILABLE 或 NEEDS_RECONCILE
NEEDS_RECONCILE ── reconcile ──> AVAILABLE / PURCHASED_PENDING_SETTLEMENT / 对应持久终态
```

组一旦进入 `SKIPPED`、`WITHDRAWN` 或购买成功状态，不能靠关闭面板、重开存档会话或重复 callId 回到 `AVAILABLE`。`EXTRACTED` 与 `RESELL_COMPLETED` 是持久终态，与页面对象一同落盘，重开后仍可用于对账。

### 11.2 购买提交

购买至少分预览和提交：

1. AS2 根据 `sessionId + epochId + pageId + pairId + offerId + revision` 创建短期预览令牌。
2. 令牌绑定支付方式、实际扣款、经济技能摘要、物品实例摘要和配置摘要。
3. 预览和提交都必须检查全局 `pendingSettlementCount == 0`；提交还要防御性检查计数是有限整数且 `< 3`。任一条件失败都只能恢复已有结算，不能继续购买。
4. 提交时 AS2 重新检查余额、页面状态、技能/价格摘要和令牌是否使用过。
5. 同一存档事务中完成扣款、兄弟撤回、实例进入结算托管和事务日志推进。
6. 扣款与存档持久化属于同一事务：只有 `flushNow()` 成功后才向 Web 返回成功揭晓；flush 失败时保留未完成事务、进入 `NEEDS_RECONCILE` 并在下一次 flush 重试。禁止返回“内存已扣、落盘未知”的成功回包（现役 `flushNow()` 可返回 false）。

客户端超时不能自动发起一个新购买；必须先按原 `callId` 对账。

### 11.3 待结算实例

购买成功后实例先进入黑市托管，不直接并入背包。玩家只能执行一次：

- `extract`：容量允许时移入库存，销毁黑市结算令牌；**容量不足时强制转为当场回售**（按权威报价结算交易点与插件返还），购买预览应在容量不足时提前警示。
- `immediate_resell`：调用权威回售价路径，结算交易点与插件返还，销毁实例和令牌。

对材料和消耗品也必须先选择，再与库存堆叠；否则无法证明它仍是“刚揭晓的那一件”，会迫使系统引入可被滥用的通用来源追踪。

关闭面板、Launcher 断开、Web 崩溃或游戏退出时，不得默认回售。待结算实例留在持久化托管区，下次进入优先恢复结算。仅当强制回售的插件返还本身极端失败（如材料收集上限）时，交易才保持待结算且不先发交易点。只要全局仍有待结算实例，新购买和任何新页领取/生成都被拒绝（BM-023）；结构上限 3 是存档与异常恢复硬门，不是提供给玩家的仓储额度。

### 11.4 幂等与未知结果

- 所有变更命令必须携带唯一 `callId`。
- 同一 `callId` 重放返回相同终态，不重复扣款或发奖。
- 完成回执（receipt）按存档持久化：保留最近 64 条已完成 receipt 与全部未完成事务；更老的 `callId` 重放按未知处理，强制走 `reconcileCall` 读取终态，不得靠无限增长的墓碑兑现幂等承诺。
- 相同业务意图使用新 `callId` 但目标已经终局时必须失败。
- Host/Web 不确定提交是否完成时进入 `NEEDS_RECONCILE`，先读 AS2 事务状态。
- 禁止以“UI 已经播放揭晓动画”作为交易成功证据。

## 12. 跨栈权威边界

### 12.1 Flash / AS2

Flash 负责：

- 堕落城商业街黑市摊位 NPC/入口（摊位基建为独立美术任务，接入前可用临时入口施工）；
- 发起版本化面板打开请求；
- Launcher/Web 不可用时显示可理解、可关闭的失败提示；
- 对余额、库存、技能、报价、掉落、交易、存档、page draft、page object、物品实例和最终结果保持唯一业务权威。

昂贵的 mask、相似度和污泥运算不得占用 Flash 帧循环。

### 12.2 Launcher Host

Host 负责：

- 面板准入、生命周期、单实例与会话绑定；
- 调度现代渲染/视觉工作进程、缓存和超时；
- 对 AS2 exact page draft 的不透明候选句柄做有界视觉配对建议；页面提交后基于 exact page object 做渲染投影，保存真实 offer 映射并向 Web 投影脱敏快照；
- 透传有界意图、事务令牌和对账请求；
- 在协议异常时 fail closed，并把错误变成可恢复状态。

Host 不能生成/替换物品实例、向草稿注入候选、自行增加余额、改变 AS2 报价或把模型分类结果当作生产物品资格真源。配对建议必须回显 exact `draftId + revision + draftDigest`，只引用草稿成员且恰好选出 6 个唯一句柄；迟到、foreign、重复或摘要不匹配的结果全部拒绝。Host 侧重计算与磁盘缓存没有单一现役设施，施工样板是 GomokuTask（子进程生命周期/串行/超时）与 DollBakeTask（校验后原子落盘缓存）的组合。

### 12.3 Web Panel

Web 负责：

- 三组货包的排版、污泥视觉、键盘/鼠标操作和揭晓动画；
- 显示 AS2/Host 已投影的余额、价格、技能层级和状态；
- 提交“选择哪个 offer、使用哪种支付方式、提取或回售”等意图。

Web 不负责生成最终随机物品、计算可支付性、决定赚赔、修改库存或结算任何货币。

### 12.4 建议协议域

施工时建议冻结 `black-market.v1`，概念命令如下，名称在实现 ADR 前仍可调整：

- `openSnapshot`
- `pagePrepare` / `pageRecommend` / `pageCommit` / `reconcilePage`（AS2 持久化不可见 page draft → Host 提交 exact-draft 配对建议 → AS2 原子提交 page object → 未知结果对账）
- `redeemRawBoxPreview` / `redeemRawBoxCommit`
- `purchasePreview` / `purchaseCommit`
- `settleRevealPreview` / `settleRevealCommit`
- `redeemKPreview` / `redeemKCommit`
- `reconcileCall`
- `closePanel`

每个请求必须带协议版本、会话、存档身份、页面 revision 和 `callId`；所有集合有数量上限，所有未知字段/枚举按协议规则拒绝或忽略，不能把自由文本物品名当作权威输入。

## 13. 存档模型与配置漂移

建议在 AS2 权威存档扩展中使用版本化对象（概念名 `_saveExt.blackMarketV1`），至少保存：

- `schemaVersion`
- `tradePoints`
- `supplyCredits`
- `lastAcceptedEpochId`
- 当前 `pageDraft`（若处于 `PAGE_PREPARING`）：`draftId/revision/draftDigest`、有界候选实例快照、生成摘要、重试/作废状态；不得保存成 Web 可见快照
- 当前页 exact page object：六个实例的完整快照（身份、数量、插件、组归属、左右位置、共同标价）与页面/组/offer 终态（含 `EXTRACTED` / `RESELL_COMPLETED`）和 revision
- 本纪元基础页是否领取、补充页计数、掉落计数和保底进度
- 未完成购买事务、最近 64 条已完成 receipt 与待结算实例（≤ 3）
- 生成时的 `configDigest`、`economyDigest`、`assetDigest`、`demandDigest`

约束：

- 所有余额和计数必须为有限非负整数，加载时拒绝 NaN、负数和越界值。
- 交易点、补货信用和待结算实例跨保存/重启保留，不因面板关闭丢失。
- `PAGE_PREPARING` 重开恢复同一 page draft 并继续建议/提交，`PAGE_READY` 重开恢复同一 page object；两者都不能因为进程重启重新抽样。随机种子只用于重建污泥等视觉附加物。
- 配置或资产摘要变化时，已经购买的实例保持原快照；未购买旧页因持久化的是完整实例快照，可以真实地保留到终局或在下个纪元统一作废，不能把同一 offer ID 静默映射成另一物品。digest 用于审计与视觉缓存失效，不再承担实例重建。
- 存档迁移必须有旧版本、缺字段、损坏字段和重复事务测试。

## 14. UI、可访问性与反馈

### 14.1 主界面

界面必须同时让玩家看到：

- 三个明确分隔的二选一组；
- 每组共享标价、当前选择和兄弟撤回后果；
- 交易点余额、K 点余额与 `50:1` 单向兑换率；
- 当前已启用解密等级及其本页快照状态；
- 本页剩余组数、纪元刷新时间和是否可整理补充页（含被待结算实例阻断的原因）；
- “跳过此组”而不是强迫购买。

### 14.2 揭晓结算

揭晓后两个主要动作必须使用结果导向文案：

- `提取物品`：进入库存；以后只能自用或卖商人换金币。容量不足时将强制转为当场回售，需在确认前明示。
- `当场回售`：按当前权威报价获得交易点；完成后不能反悔。

若存在插件返还、库存容量问题或未完成事务，必须在确认前列出。关闭含待结算实例的面板时给出说明，但不能用强制自动回售替玩家做决定。

### 14.3 无障碍与输入

- 三组使用可理解的 group/radiogroup 结构；同组两件可键盘切换，购买与跳过可独立触达。
- 焦点顺序与视觉顺序一致；兄弟撤回后焦点移动到本组结果或下一组。
- 颜色不是赚赔、选中、锁定或插件信息的唯一载体。
- 支持 reduced motion；揭晓动画可跳过且不改变提交时序。
- 隐藏状态只读作“未鉴定装备/材料/消耗品 A/B”，不能把真实名称塞进无障碍文本。
- 交易全流程（浏览三组、购买、跳过、提取、回售、兑换）必须键盘与屏幕阅读器完全可达，这是硬要求，不得降级。
- 0–6 级视觉鉴定线索（污泥、轮廓、破局点）应当提供不泄露身份的文字等价物（例如等级化的差异方位提示）；该等价物允许在小游戏阶段 Slice 2 降级为显式挂起的后续任务，挂起必须在验收记录中留痕，但不得带着挂起项进入上线阶段真实纵切或 `e2e_verified` 声明。
- 说明信息使用项目共享 tooltip/帮助模式，不依赖原生 `title`。
- 至少验证 1024×576、1366×768、1920×1080 三档视口和 Windows 常用缩放。

### 14.4 独立小游戏视觉合同

小游戏必须看起来是“堕落城里一座正在营业的非法检货台”，不是套了黑色背景的管理后台。视觉完成度属于玩法反馈的一部分：玩家要靠构图识别三组关系、靠材质与遮挡理解“污泥清洗”、靠揭晓动效感知一次性抉择。首轮 One-shot 可以使用仓库外一次性施工包中的视觉方向图和精选真实资产，但长期约束只以本节与[产出回收及接入交接](盗贼黑市盲盒鉴定-产出回收与游戏接入交接-2026-08-19.md)为准；运输包不入库，也不是可忽略本节的替代真源。一次性输入只携带夹具逐项引用的 18 个现役物品资产及其真实数据子集，不打包完整图标库、dressup 库或源 XML；生成式图片只作整机视觉方向参考，不得替代正式货物资产。

**构图与身份**：

- 以固定 `1024×576` 逻辑画布为设计基准，等比适配更大视口；主画面是一个略不对称的黑市摊台框架，而不是居中的 landing page。
- 顶部窄檐只承载游戏名、交易点/K 点、解密等级和纪元倒计时；中部必须是三个横向检货舱，每舱共享一个标价与操作轨，清楚表达“一组二选一”，不能把六件货拆成六张同权通用卡片。
- 每件物品的可辨主体是舱内第一视觉层；在基准视口中，装备/材料/消耗品主体有效包围盒长边不得小于 112px。底部固定结算轨承载提取、回售、兑换和持久错误；开发抽屉默认关闭，不得侵占产品画面。
- 选中、兄弟撤回、揭晓盈利/亏损、待结算、余额不足、页面准备和恢复对账都要有不同的构图/符号反馈，不能只换一行文字或颜色。

**美术语言**：

- 主材质是煤灰黑、旧漆钢板、油渍纸签、铆钉与磨损黄铜；商业/标价强调使用琥珀与旧金。纳米污泥以低饱和石墨灰、病绿色/蓝绿色和冷钢反光为主，不得用大面积发光电路直接揭示其机器本质；危险使用朱红。DLS 晶体青只允许用于 K 点或解密科技的局部信息，不得成为全屏默认霓虹描边。
- CSS 必须以 `--bm-*` 语义 token 组织；小游戏阶段使用本节冻结值，上线时映射到 DLS/项目真源，不能靠全局搜索重画界面。
- 标题可用本地衬线中文字体回退，正文使用清晰黑体回退，批号/价格使用等宽字体；中文正文不得低于 10px，常规正文/按钮目标为 12px 以上，不能用 6–9px 中文堆出“复杂感”。
- 纹理、污迹、纸签和光影必须受控，不遮挡焦点环、正文或物品破局点。生成素材可以辅助生产，但状态、文字、按钮和关键价值信息必须是可访问 DOM，不得烘进一张不可读大图。

**明确否决的默认审美**：

- 通用 SaaS/dashboard：等宽三列统计卡、满屏圆角矩形、胶囊标签、表单式侧栏、居中大标题加说明文；
- 默认“AI 科幻 UI”：满屏青紫渐变、任意霓虹辉光、过量玻璃拟态、每个边框都发光；
- 占位美术：emoji、通用图标字体、写着 `ITEM` 的盒子、随机几何渐变、未处理系统滚动条或原生表单控件；
- 把调试数据、seed、隐藏答案、事件日志或测试按钮常驻在主界面；
- 为了“更像游戏”加入持续抖动、扫描线噪声、无限粒子或影响阅读的环境动画。

**动效与交互质感**：

- 微反馈 90–120ms、标准状态切换 140–180ms、揭晓/结构转换 220–360ms；动效只解释状态，不等待动画后才提交交易。
- hover/focus 不移动卡位；键盘焦点必须使用稳定高对比轮廓。`prefers-reduced-motion` 下关闭位移、抖动、粒子与环境循环，保留即时状态切换。
- 可以有 900–1800ms 的低能量待机呼吸或灯丝变化，但同屏最多一个环境循环，且不得竞争物品主体和结算结果。

黑市摊位外景/Flash NPC 基建仍可在后续独立美术任务中生成和接入；这不构成延期面板美术的理由。小游戏阶段交付的面板 DOM、CSS、动画与素材插槽就是上线阶段基座，真实接入只允许替换宿主适配器、权威数据和经审计的最终物品资产，不允许整体重写前端美术（BM-026）。

## 15. 性能与降级

- page draft 候选实例与 page object 的创建/提交由 AS2 完成；昂贵的视觉配对和规范渲染运行在 Launcher/Host/Web 现代组件，不阻塞 Flash。
- 首开允许显示明确的“清洗货物中”状态；必须有超时和取消，不得无限空白。
- mask/SDF/自动锚点描述符、规范渲染和最终污泥栅格均按内容摘要缓存；当前可见六件的像素运算优先进入 `OffscreenCanvas` worker，worker/图片解码不可用时允许单件主线程 fallback，但必须暴露 backend、耗时和低置信分割证据。
- 生成尝试必须有 `maxCandidateSamples`、`maxPairAttempts` 和总耗时预算。
- 单个类别失败可以换类别；整页未凑齐三组时不得发布半页。
- 已有有效页时刷新失败继续显示旧页并标注刷新延迟；从未成功生成时显示“暂时无货”和可重试错误。
- 装备视觉失败不能降级为图标，也不能用未遮挡真实资源图临时顶替。
- Luna/网络不可用不影响已审核候选和本地生成；运行时不得等待外部模型服务。

- 生成耗时、缓存命中、超时、恢复和对账结果。

生产界面日志不能提前输出隐藏身份；开发模式如需明文，必须显式启用并与普通 UI 输出分离。

调参报告至少给出：

- 每纪元可归因流动价值增量的上界、P50、P90，并另以 K 等价值/小时表达（含纯 K 循环分量）；
- 触发保底时的最慢可得 K 等价值速度；
- 按解密等级分组的识别胜率、净收益和跳过率；
- 提取自用率、当场回售率、需求命中后的提取提升；
- 交易点余数与囤积分布；
- 页面售罄率、补页率和各类生成失败率；
- 左右选择偏差，确认不存在位置或泥量暗号。
- 8/9 级每个实际显示档位的正负样本支撑、按生产权重计算的方向后验，以及被合并/抑制的档位数量。

模拟必须使用固定种子、真实物品价格快照和 AS2 等价报价函数；只用手写六个示例不能作为经济闭环证据。

## 17. 验收矩阵

每条验收项标注可验证阶段：【小游戏阶段】项是调教门（第 19.2 节）的通过条件；【上线阶段】项只能在真实接入后验证。小节标题上的标注表示该小节全部条目同属一个阶段。

### 17.1 数据与静态门

- `BM-DATA-01`【上线阶段】：“解密”上限为 10，说明文本更新完整，旧存档兼容验证通过；既有 EncryptLevel>5 的 4 页情报完成叙事签收，Intelligence 面板回归通过。

- `BM-DATA-03`【小游戏阶段】：所有生产装备候选都有视觉资格 `allow`；deny/review/缺失不会进入抽样；材料/消耗品通过图标与资格检查，并且隐藏态只使用透明/中性 authored 资产，品质/档位底色不得进入公开投影。影子渠道的单帧统一去色回退不计为生产资格。

- `BM-DATA-05`【上线阶段】：50:1、掉落预算、保底、补页与边际参数来自一个版本化配置快照。
- `BM-DATA-06`【上线阶段】：交易点展示条目已按 `price=0`、不上架、不可出售登记，不进入候选池/商店/合成路径；经济面板可查阅交易点余额。

### 17.2 生成器（全部【小游戏阶段】）

- `BM-GEN-01`：每个成功页面恰好 3 组、6 件；类别可重复但组内同类。
- `BM-GEN-02`：同组同价，且对所有支持的经济技能状态（含口才等级轴）始终一赚一赔（交易点差额口径）。
- `BM-GEN-03`：赢家在交易点和直接 K 支付下都至少保留 50 交易点边际。
- `BM-GEN-04`：同种子、同摘要、同需求快照得到完全相同的页面和污泥；已持久化的页面对象在物品数据或资产变化后仍能原样恢复。
- `BM-GEN-05`：左右位置、泥量和价值无统计相关；固定大样本通过偏差阈值。
- `BM-GEN-06`：激光/常驻 VFX/空 mask 被拒；装备绝不回退为图标。
- `BM-GEN-07`：需求权重只使用已公开数据，不改变同组经济不变量，且不改变类别分布的可识别性。
- `BM-GEN-08`：超时、候选不足和缓存损坏均 fail closed，不发布半页。
- `BM-GEN-09`：page draft 有界、持久化且从不进入 Web；Host 建议只引用 exact draft 的 6 个唯一成员，AS2 拒绝 foreign/duplicate/stale/digest mismatch 并独立复验全部经济不变量。
- `BM-GEN-10`：page prepare/commit 任一步崩溃都恢复同一 draft 或同一 page object；commit 成功但回包丢失时对账返回同一 page digest，生成失败不消耗基础页资格或补货信用。

### 17.3 交易与经济闭环（全部【上线阶段】）

- `BM-TXN-01`：只有上交合法未清洗货包和待结算实例当场回售能增加交易点。
- `BM-TXN-02`：普通库存、K 商城、合成和任务物品调用交易点接口均失败。
- `BM-TXN-03`：组内购买一个后另一个不可购买；跳过后两者均不可恢复。
- `BM-TXN-04`：提取与回售互斥且各只能成功一次；堆叠前先结算选择。
- `BM-TXN-05`：回售复用权威售价与插件返还；提取容量不足强制转为当场回售；插件返还极端失败不丢物、不先发钱。
- `BM-TXN-06`：交易点按 50:1 单向兑换 K，余数保留；金币无逆向入口。
- `BM-TXN-07`：直接 K 支付使用向上取整成本、不找零，也不增加交易点余额。
- `BM-TXN-08`：余额不足、技能摘要变化、价格变化、页面过期和脏 revision 均拒绝旧令牌。
- `BM-TXN-09`：重复 callId、超时重试、Host/Web 崩溃和保存重启不重复扣款/发奖。
- `BM-TXN-10`：待结算实例在关闭/崩溃后恢复；不能被静默回售或吞掉。
- `BM-TXN-11`：全局存在待结算实例时，新购买、基础页领取/生成和“整理下一批”全部被拒绝；重新打开先恢复结算。flush 失败不返回成功且可通过重试/对账恢复。
- `BM-TXN-12`：交易账本每笔显式记录不同单位的 `deltaTp` 与 `deltaK`，并满足 `ΔV = deltaTp + 50 × deltaK`；K 支付后提取必须是 `deltaTp=0 / deltaK=-paidK`，K 支付后回售必须是 `deltaTp=+resellTp / deltaK=-paidK`，不得把 K 数量写进 TP 列。50:1 兑换的 `ΔV = 0`，每纪元可归因价值增量不超过第 7.6 节上界，实际跨期 K 毛现金流单独报告。

### 17.4 刷新与存档（全部【上线阶段】）

- `BM-SAVE-01`：同纪元关闭重开不重抽，跨纪元只在规定边界切页。
- `BM-SAVE-02`：时钟倒退不回滚纪元，大幅前进不补发跳过页面。
- `BM-SAVE-03`：掉落上限、保底、补货信用、页面对象、终态、receipt 墓碑和余额跨保存准确恢复。
- `BM-SAVE-04`：补充页只在当前页终局且无待结算实例后原子产生；失败不扣信用。
- `BM-SAVE-05`：配置/资产摘要变化不把旧 offer 静默映射为新物品。
- `BM-SAVE-06`：挂面板跨纪元时旧页购买仍有效，补页按真实当前纪元计数；关闭重开后旧纪元未购项作废。
- `BM-SAVE-07`：待结算实例跨纪元时不发新基础页，结清后只发真实当前 UTC 纪元的一页；游戏内昼夜暂停/快进不能改变 epochId。
- `BM-SAVE-08`：`pendingSettlementCount` 加载时为有限整数且不超过 3；越界存档 fail closed，不通过截断、丢弃实例或发新页自愈。

### 17.5 解密、视觉与 Web

- `BM-VIS-01`【小游戏阶段】：0–10 级信息严格单调，3/5/7/10 里程碑与本规格一致；9 级档位边界不与 W 或保证边际重合。
- `BM-VIS-02`【小游戏阶段】：禁用“解密”按 0 级工作且可以完成完整交易。
- `BM-VIS-03`【小游戏阶段】：购买前 snapshot/init/匿名导出、DOM/ARIA/错误文本、日志/遥测和资源请求不含真实 asset URI、item ID、icon key 或可重放 seed；自动门必须同时扫描字段、DOM 属性、请求 URL，并用私有熵注入负例证明公开输入不能离线重建精确物品身份。
- `BM-VIS-04`【小游戏阶段】：同组相似度、最低可见面积、破局点和泥量容差通过自动检查。
- `BM-VIS-05`【小游戏阶段】：1024×576、1366×768、1920×1080 三档视口、键盘、焦点、非颜色提示、reduced motion 与交易全流程 ARIA 可达通过人工/自动组合验证；视觉线索文字等价物若在小游戏阶段挂起必须有显式记录。
- `BM-VIS-06`【小游戏阶段】：8/9 级每个显示档位在生产抽样权重下同时有正负方向支撑，方向后验不高于 `maxPreLevel10DirectionPosterior <= 0.75`；固定样本证明不合格档位会合并或抑制。
- `BM-VIS-07`【上线阶段前置】：0–6 级视觉线索的非泄漏文字等价物全部完成；未关闭该挂起项不得进入第 17.7 节真实纵切，也不得声称该功能 `e2e_verified`。

### 17.6 独立小游戏完成度（全部【小游戏阶段】）

- `BM-DEMO-01`：从干净启动进入完整闭环不超过两次解释性交互；至少 6 名不熟悉玩法的测试者中，至少 5 名且总体不少于 80% 能在不看源码/规则全文的情况下于 90 秒内开始第一组判断，并在 5 分钟内完成一页三组及全部结算。
- `BM-DEMO-02`：至少 6 名新手与 4 名熟悉 CF7 装备的测试者参加冻结前试测；0/3/5/10 级各累计不少于 30 次成对判断。新手 0 级正确率目标为 52%–68%，3 级较 0 级至少提高 8 个百分点，5 级较 3 级至少提高 8 个百分点；10 级在数据正常时方向判断为 100%。未达到目标时先回到破局点/污泥调教，不以改答案、泄露身份或放宽经济不变量过门。
- `BM-DEMO-03`：至少 3 名未参与施工的观察者只看打乱顺序的真实运行截图，按“主题辨识度、构图层级、物品可读性、交互反馈、字体/间距、独立成品感”六维 1–5 分盲评，每维中位数均不低于 4；不得存在尚未关闭的“像管理后台、通用 AI/SaaS 模板、只有工程原型、需要整面重画”阻断意见。施工模型的同量表自评只用于交付前迭代，不能冒充独立盲评。

- `BM-DEMO-05`：视觉回归、键盘 E2E、axe 等价检查（或同等可审计工具）、构建和单测通过；关闭动画后同一操作仍得到完全相同的业务终态。

## 20. 明确不采用的方案

- **允许任意库存卖成交易点**：会把 K 商城、合成和金币经济接入 K 点回流，否决。
- **装备生成失败时显示普通图标**：视觉语法突变会直接暴露类别/身份，否决。
- **把所有污泥组合离线穷举成素材**：维护和资产体积成本过高，否决；只缓存可复算描述符和页面结果。
- **游玩时调用 Luna/云模型判定资格**：不可用性、漂移和权威不清，否决；只用于数据筛选建议。
- **只用低概率、不做保底**：无法支撑“确实可获利”的产品承诺，否决。
- **为系统时间建立反作弊基础设施**：与单机、内置修改能力和开发成本不匹配，v1 不做。
- **精确预测玩家流派并保证投送最优装备**：成本高且容易误判；改为公开需求的有限权重。
- **用情报做货包候选**：会泄露任务与叙事信息，否决。
- **允许待结算托管区无限囤积**：会形成零成本无限仓储与存档无界增长，否决；托管结构上限 3，提取容量不足强制当场回售。
- **把交易点做成可持有库存物品**：会打开库存回流与获取分流特判，否决；只登记 `price=0` 展示条目，余额为账本字段。
- **情报域对 6+ 级做领域级钳制**：评估后放弃；顺势开放既有 4 页并以叙事签收与面板回归兜底。
- **把 one-shot 当作一次性原型皮肤**：会让夹具验证结束后整面重写、丢失调教证据，否决；同一 UI/CSS/素材接口必须直接承接真实 Host 适配。
- **用通用后台卡片快速拼出可用 UI**：信息能跑通但无法验证玩法的视觉判断与成品感，否决；第 14.4 与 17.6 节是硬门。
