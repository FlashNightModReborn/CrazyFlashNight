# R8：取消机制判定与隔离 AS2 协作域

**文档角色**：本轮实验结果、证据边界与 C1 阻塞说明。2026-09-23；基于 `5c02a10360` 加工作区已有未提交施工。当前状态归[分阶段计划 §11/§13](../统一合成与输入归属-分阶段施工计划-2026-09-22.md)，本报告不授予发布或扩大迁移权限。

## 结论

1. **一次 virtual capture 撤销试验失败。** 观测到了真实虚拟 capture 归属，试验也执行了对称 CaptureChanged/中性查询；返回第一击仍只有旧 pressId 的 release，没有新 press。停止这个 native 假设，不继续扫消息或补 MouseUp。
2. **完整协作域方向取得有限实机正例。** disposable 主/子 SWF 的鼠标左键域 26/26：新的 LL 边沿直接驱动有身份的逻辑 Begin/End，旧 native 回调不能提交，取消与物理 neutral 分开证明。没有改名原生失败断言。
3. **尚未到真实游戏 C1 人验。** 游戏中的旧 U 类入口、全局输入和外部 SWF 尚未被隔离或迁移；M 夹具的 ACK 不授予这些入口重新准入。没有交付新的可玩候选，没有宣称焦点根治、C1/B 通过或正式部署。

本轮 production `InputBridge`、`Surface`、`Controller` 未因 R8 新增行为改动；实验代码在 `launcher/native/world-compositor/flash-hover-fixture/`，capture 变体在 `tmp`，可读补丁保留在夹具的 `experiments/`。原有 R6/R7 悬停、注释清理及其人验结论不变。

**回执接收后的口径修正：** 26/26 是 26 次断言、20 个不同名称；主/子 SWF 对象共用根协调状态，不是两个独立故障域。缺子 ACK 用例丢的是 Host 收到的回执，未模拟子 SWF 实际拒绝取消。新增静态缺口 S1–S4（队列故障仍有远端延后任务、READY 冲突恢复、几何身份、观测连续性）尚未实跑或修复。后续路线采纳 C1-I，详见[计划 §14](../统一合成与输入归属-分阶段施工计划-2026-09-22.md#14-r8-回执采纳c1-i-专用真实隔离入口)。本段为冻结包之后的补充，不重写原包及历史通过记录。

## 2. M 协作域的实际实现

代码与可执行命令归[夹具 README](../../launcher/native/world-compositor/flash-hover-fixture/README.md)。能力严格限定为单个左键手势的受控按钮域；右/中/X 键参与物理 neutral，额外按键会撤销手势，未提供它们的业务交互。键盘仅保留 raw 诊断，Tab/IME/键盘激活未迁移，不得称完整游戏统一输入。

- 主 SWF A、真正 `loadMovie` 的子 SWF B 各注册 scope/incarnation、protocol、contentBuild、coverage 和 capabilities。
- 身份包含字符串 session、coverage、ownerEpoch、gesture、button、beginSeq、普通对象目标 incarnation。AVM1 旧 MovieClip 路径引用不充当跨重载身份。
- Host 账本在取消期间继续观察全局实际 LL Down/Up；不清 held，不用一次 GetAsyncKeyState 零值解锁。实验初始关闭业务，注入五键各一次 Down/Up 建立基线；**该校准步骤不是产品设计**。
- hook 只写有界队列。入队保留 admission、epoch、QPC 和刺激 ID；业务资格撤销不把旧排队边沿转成 fresh Begin。网络发送在 UI drain；过载或通信断开关闭资格。
- 主/子两个 exact CANCELLED、无可提交旧任务、已知物理 neutral、两个 READY 同时成立才开门。缺子域 ACK、迟到旧 ticket/epoch/实例不能借父 ACK 放行。
- AS2 负责命中、遮挡顺序、悬停/按住显示与 End 内外判定。Begin/End 由新 LL 边缘协议驱动；raw onPress/onRelease/outside/drag/key 不提交、不排业务任务、不驱动关键视觉。
- 取消独立作废 active token 和帧延后任务；不转调 release/outside。已合法提交的计数不回滚。同路径重载 B 先关门，改 coverage 和 child incarnation，再完整注册、取消、准入。

26 项包括：A/B 新手势顺序及身份、无失焦取消、外部释放、返回原 A 与 B、pending job 作废、多键未全抬起、拖出、空白点击、raw 空格回调无提交、旧 ACK、缺子域 ACK、持键返回拒绝、旧 session/epoch/ticket/孤立 End 和子 SWF 同名重载。输入是明确标记的 **SendInput 注入**；返回用了显式 Activate/FocusFlash，不代签用户物理切换或手感。

本有限资产集合没有未知子 SWF；没有实现任意第三方/未注册 SWF 的覆盖发现器。没有验证 loadMovieNum、多显示器/IME/Tab、设备丢失、全窗口几何取消矩阵或长时稳定性。新域的成功绝不覆盖这些缺口。

## 4. C1 真实交接的具体阻塞与下一步

这次已经触发原约定的停止条件：**旧 F 域未取得安全撤销能力，也没有覆盖完整的可隔离业务门**。以下都是当前源码的直接路径，不把静态存在写成新现场复现：

| 实际消费者 | 当前路径与缺口 |
|---|---|
| 医务室整形入口 | `flashswf/levels/基地场景合集/LIBRARY/地图/医务室.xml` 的 `on(release)` 直接 `_root.打开整形手术()`，旁边 raw over/out 控制注释 |
| AS2 服务入口 | `scripts/展现/UI交互/UI交互_lsy_UI管理.as` → `PlasticSurgeryPanelService.openPanel()` → panel request；没有 M gesture/coverage 资格 |
| Host opener | `LauncherCommandRouter.RequestOpenPanel` 接受 `world_plastic_surgery` 来源字符串后开 surgery；来源白名单不是手势取消证书 |
| 其他场景/NPC 与外部 UI | 理发师 raw release 直接触发任务检测/NPC 菜单；`加载外部UI` 可以 loadMovie。不能只迁整形按钮而让这些 U 路径继续接 raw 边缘 |
| 生产物理账本 | `Surface.CancelPointer` 清 physicalButtons，Controller 在 inactive 时不转入 Surface；R8 的全局账本目前只在实验夹具，没有修补这两处生产路径 |

下一施工应落在**真实、完整、有限交互域**，并先决定如何保证 U 端点从始至终不接业务输入。建议顺序如下，不把它当已完成实施：

1. **生产级准入合同**：把全局物理观察与 active owner 分开；失活/隐藏仍记 Up；未知基线保持关闭。冻结 scope/coverage 和取消能力，U 永不以 native ACK 获证，G 只称 guard。实验的五键校准不得进入游戏产品。
2. **隔离方案先过反例**：比较“专用 C1 开发入口从启动即关闭 U，只加载/注册许可交互岛”与“直接在真实基地对旧输入入口逐项迁移”。前者需如实标记专用开发旅程；后者范围会覆盖场景、全局 Mouse/Key、NPC/任务及动态子 SWF。无完整 raw/轮询/延后任务封口证明，不能边迁一个按钮边放行整个游戏。
3. **真实 opener 与提交资格**：AS2 M 命中适配器调用原 `PlasticSurgeryPanelService.openPanel`，将手势关联带到 Host；不开第二条旁路，不手造页面假称生产 opener。来源字符串和新 panel session 均不能补造旧域撤销。
4. **双向 handoff**：old domain CANCELLED＋覆盖＋neutral 后 Web/Native 接管；退出 Web/Native 要撤销其捕获/键盘/延后任务，确认后等 fresh Begin 回 M。超时保持关闭，不重放开面板/提交，不借 UI 关窗解除未知写状态。
5. **C1 候选与人验**：实际 surgery 草稿/取消、不付费应用；Native 交互首样及 PlayerInfo 缓存样本。机器先验证故障、唯一消费、取消与身份，再合并安排一次中文 IME/Tab/首击/切出/移动缩放体验。此时才称“到下个人验节点”。

当前没有要求用户重复上一轮 R6/R7 验收。需要审定的是第 2 项真实隔离路线；原裁决所需的 native 反例和 M 可行性证据现已具体化，可以直接沿本报告审阅，不再讨论“补哪一种 Windows 消息”。C1、B0-05 性能、战斗 #119、正式发布保持原边界。

下一次路线审阅的一句话启动词：**“请依据 R8 冻结源码及实机负控，审定真实 C1 应采用启动即关闭 U 的专用隔离入口还是扩大真实场景迁移，反驳主/子 SWF M 样本对生产隔离能力的过度外推，给出最小实施范围、双向 handoff 必要条件和停止反例；不要重新枚举 native 取消消息。”**
