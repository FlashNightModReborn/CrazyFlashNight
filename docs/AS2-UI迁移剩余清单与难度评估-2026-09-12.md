# AS2 UI 迁移剩余清单与难度评估（2026-09-12，深化复核）

**文档角色**：剩余界面与相关债务的持续迁移台账，汇总范围、排期和调查交接；不替代各专项 ADR，不授权实现或退役。文件日期为建账日期，后续原位维护；[文档治理 §6](../agentsDoc/documentation-governance.md)规定记账归属和更新时机。

**最后核对代码基线**：commit `c1e51dd1e8dba6bf72452cfef3af8b6f09b36acf` 加本次读取的工作区。暂存物资共享收纳正在另项施工，不能将其未提交实现视为已发布。状态与估计均为本日快照。

**结论**：剩余工作不能再概括为“两项大迁移加一批疑死清场”。玩家 HUD、现场对话仍是最大专项；同时存在睡觉、训练、酒馆、书架、地铁、彩蛋选关和车库购车等真实入口。通用 UI 层仍有多个消费者，确认通用面板也仍承载购车事务，必须在消费者迁走后再讨论退役。原“约 75 已完成／25 待施工／27–45 人日”不再用于完成率或总预算。

**本轮方法与边界**：三路本机 Kimi K3 1M/max 分别核地图入口、主 XFL/独立 UI、旧台账与估算；主控复读关键消费者、实际 SWF，并由 Astra 审核易误判的范围和计数。检查包含 35 个现存地图 SWF 的脚本导出，28 个没有对应 XFL，合计 1,578 个导出脚本、导出均成功。源码、二进制片段、输入摘要与覆盖范围保存在[调查快照](evidence/as2-ui-migration-remaining-2026-09-12.json)。本轮未启动游戏、编译或发布；“静态可达”不等于真机旅程通过。

## 2. 计数与估算口径

旧对账主表的 **B21 + C19 = 40 行**可作为追踪基数，不能称 40 个独立产品。它混合了完整功能、容器、子控件、素材库、纯领域架构和新玩法。原 C 桶的四分类重复放了消息窗、漏放基建系统；原 S15/M11/L7/XL7 只描述旧表行，不表示当前工程量分布。

本版用 §4 的旧身份逐项登记去向，用 §5 补回旧 D 桶及扫描新增对象，用下列交付包估算。**同一个对象只有一个主要去向；共用宿主、图片容器、HUD 子组件不再叠加到包含它们的包价。** 旧 A 桶混入原型和基础设施，未重建精确分母前不再报“迁移完成百分比”。

S/M/L/XL 表示工程复杂度：S 为少量接线或已证残留核实；M 为一个边界明确的界面/域；L 为多条权威写、状态或转场耦合；XL 为高频完整 HUD 或呈现与大资产工程结合。它们不与某个天数阈值一一绑定。

以下人日均为**初步工程估计**：一名熟悉本项目的实现者约一天有效工程投入，包含领域/协议、界面素材、Flash 接线及定向验证和候选验收准备。不是用户工时、模型调用数或日历工期；不含排队等 CS6、人验反馈等待、双构建共识等待及发布调度。没有实测产能，不给模型加速倍数。估算低端假设沿用现有玩法和复用设施，高端容纳所列兼容与表现返工，不包括附加新玩法。
