# 物品数据与素材映射（加物品 / 加素材时必看）

本文件由 `MEMORY.md` 同名章节原样归并而来，主索引见 [../MEMORY.md](../MEMORY.md)。

- 物品定义在 `data/items/*.xml`，由 `data/items/list.xml` 的 `<items>` 逐个登记；`<item>` 无 `<id>`（ID 自动生成），查找走 `_root.getItemData(名称)` → `ItemUtil.getItemData`，**按名称取值，条目顺序无影响**
- 消耗品（含手雷）必须 `<use>手雷</use>` 才进手雷装备格；字段见 `消耗品_手雷.xml`：level/weight/dressup/capacity/split/diffusion/interval/velocity/bullet/sound/muzzle/bullethit/clipname/bulletsize/power/impact（+ 可选 damagetype/magictype）
- `icon` 只写裸名（运行时拼 `图标-`）；`dressup` = 手持/装备外观元件、`bullet` = 投掷物元件、`clipname` = 弹夹名（手雷用不到，随 bullet 写）
- 投掷物骨架参考 `flashswf/arts/new/公共素材位0/LIBRARY/其他武器/`：`砖.xml`（Labels 层第 3 帧标签 `消失` + Script 层 `stop()`/`removeMovieClip()` + 名为 `area` 的实例带重力落地 `gotoAndPlay("消失")` + 画层 `_rotation += 7`）、`手雷-砖.xml`（含 `枪口位置` 标记）、`图标-砖.xml`；图标也可照瓦巴杰克 `武器/刀剑/图标-舞.xml`（第 1 帧遮罩特写 + `图标阴影`，第 2 帧完整展示，Script 层 `stop()`）。**2026-09-14 的足球手雷已照这套骨架纯文本写进瓦巴杰克 XFL，可直接当模板**：`LIBRARY/武器/足球/{足球图,足球,手雷-足球,图标-足球}.xml`（CS6 保存后由用户从 `特效与子弹/` 移来，路径以磁盘为准）；`area` 宿主要用透明元件（如 `area40X40`），别拿图形元件顶替
- 元件放 `flashswf/arts/**` 的 XFL 里，新增后必须：publish 该 SWF → 重跑 `python tools/linkage_scanner/scan_linkage.py` 让 `data/items/asset_source_map.xml` 收录，否则运行时 `attachMovie` 找不到符号
- 没进 `data/shops/npcs/*.json`（商人货架）和掉落表的物品，游戏内拿不到

## 武器/拳套装扮（dressup）的挂装口径 —— 2026-09-15 实测

- 装扮池前缀：刀 `刀-*`、枪 `枪-{手枪,长枪}-*`、拳套/手套 `男变装-*`（`use=手部装备` 且 `punch>0`）；`双枪-*` 在 `asset_source_map.xml` 里 0 条
- 挂点元件在 `flashswf/arts/things0/LIBRARY/主角肢体素材/`：`刀.xml`(主手) / `刀-副手.xml` / `手枪.xml` / `长枪.xml` / `右手.xml`；每个都是「一层壳 + 一个 `sprite/Symbol NN` 实例（名为 `刀`/`枪`）+ `onClipEvent(load)` 里 `_root.装备引用配置.配置装扮(this, 装扮名, "装扮", "X_引用")`」
- **游戏本体挂装扮 = `attachMovie` 后不再做任何 transform**（`DressupReferenceManager.doConfig`）⇒ 装扮的"原尺寸/原朝向"就是游戏内的正确值
- **真实包围盒（px，挂点局部坐标）—— 刀竖画、枪横画，长边差 90°**：

  | 类型 | 元件链 | 包围盒 | 朝向（可由 `*位置` 空元件反推） |
  | --- | --- | --- | --- |
  | 刀 | `sprite/刀-新手刀（模型）`→`shape/Symbol 10` | 51.4 × 401.6 | 竖画，刀尖 **+y**（`刀口位置1/2/3` ty=34/136/262）|
  | 手枪 | `sprite/枪-手枪-m9（模型）`→`shape/Symbol 26` | 93.6 × 60.1 | 横画，枪口 **+x**（`枪口位置` tx=70）|
  | 长枪 | `sprite/枪-长枪-G36（模型）`→`shape/Symbol 4` | 273.9 × 106.7 | 横画，枪口 **+x**（`枪口位置` tx=143.1）|

  ⇒ **任何"自己摆武器"的特效**（如王之财宝的 `王财宝具`）都必须给枪单独加 90° 旋转，否则一定歪；
  ⇒ 也说明**同类物品尺寸差异很大**（手枪 93.6 / 长枪 273.9），做缩放只能用"一个全局倍率"，
    用"最长边归一"会把手枪放大 2 倍多
- 拳套类装扮是**手部素材**（本挂 `主角肢体素材/右手`），尺寸只有几十 px，跟刀枪不是一个量级




## XML `<data>` 字段 → 运行时属性映射

出处 `scripts/类定义/org/flashNight/arki/unit/UnitComponent/Initializer/DressupInitializer.as` L525-596（`updateProperty`）。
`weaponPrefixKeys[key]` 有前缀（按装备槽位，如 `兵器`/`手枪`/`长枪`）就写 `{前缀}X`，否则累加到 `基础X`。

| XML data 字段 | 含义 | 单位属性 |
| --- | --- | --- |
| `damagetype` | 伤害类型（物理/魔法/破击/真伤） | `{前缀}伤害类型`（缺省 "物理"） |
| `magictype` | 魔法伤害属性（热/冷/电/蚀/巨体/装甲/生化/能/冲/精英/电子体…） | `{前缀}魔法伤害属性`（缺省 null） |
| `poison` | 淬毒值 | `{前缀}毒` / `基础毒` |
| `rout` | 击溃（0.01~0.15） | `{前缀}击溃` / `基础击溃` |
| `slay` | 斩杀 | `{前缀}斩杀` / `基础斩杀` |
| `vampirism` | 吸血 | `{前缀}吸血` / `基础吸血` |
| `accuracy` | 命中加成 | `{前缀}命中加成` / `基础命中加成` |
| `criticalhit` | 暴击（数值 或 "满血暴击"） | `{前缀}暴击`（函数） |
| `knifepower`/`gunpower`/`punch`/`damage`/`toughness`/`evasion`/`force` | 刀锋/枪械/空手/伤害/韧性/闪避/内力加成 | `装备刀锋利度加成`/`装备枪械威力加成`/`空手攻击力`/`伤害加成`/`韧性加成`/`闪避加成`/`内力` |

**子弹属性对应字段**（往 `子弹属性` 上挂，必须在 `_root.子弹区域shoot传递(子弹属性)` **之前**）：
`伤害类型` / `魔法伤害属性` / `毒` / `血量上限击溃`（`inheritShooterAttributes` 合并成 `Obj.击溃`）/ `斩杀` / `吸血`。
原因：`Obj` 在 `attachMovie(..., Obj)` 之前已被 `prepareBulletData` 定型，之后改 `Obj` 或子弹 MC 都来不及。

**手部装备（拳套）拼后缀**：`DressupInitializer` L238-239 用 `dressup + "左手"` / `dressup + "右手"`
作为真实 linkage ⇒ `男变装-小型拳套` 必须拼成 `男变装-小型拳套右手` 才能 attachMovie。

## 三个「物品来源」的运行时结构

| 来源 | 运行时 | 结构 | 磁盘源 |
| --- | --- | --- | --- |
| 金币商店 | `_root.shops[店id]` | catalog 对象：键 `"0"/"1"…` → 物品名（字符串） | `data/shops/list.xml` + `data/shops/npcs/*.json` 的 `catalog` 段 |
| K点商城 | `_root.kshop_list` | `[{id,item,type,price}]` | `data/kshop/list.xml` + `*.json` |
| 合成 | `_root.改装清单[分类]` | `[{recipeId,title,name,price,kprice,materials[]}]`（`改装清单对象` = name→配方） | `data/crafting/list.xml` + `*.json` |

物品属性：`_root.物品属性列表[name]`（= `ItemUtil.itemDataDict`），由 `ItemDataLoader` 合并 `data/items/list.xml`
列出的 XML；字段路径 `item.use` / `item.data.dressup` / `item.data.power` / `item.data.punch` …

素材存在性校验：`data/items/asset_source_map.xml` 是自动生成的，**只扫 XFL**，会漏 SWF 里独有的 linkage。
要判"某 linkage 能否 attachMovie"就扫 SWF 二进制：`flashswf/**/*.swf`（CWS 用 zlib 解压后做 bytes 包含判断，
817 个文件全量约 10 秒）。
