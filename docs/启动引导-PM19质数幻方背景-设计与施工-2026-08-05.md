# 启动引导界面 PM19 质数幻方背景层 — 设计与施工（2026-08-05）

## 背景与目标

对 Launcher 启动引导界面（BootstrapPanel / welcome 视图）做体验升级：以 **19 阶完整质数幻方**作为电子战（θ-FLOOD / 黑铁网络 / 诺亚终端）氛围背景，把"行—列—双对角同步"的数学过程转化成有结构的视觉叙事，取代普通随机数字矩阵。

关键诉求：**叙事感来自真数学，不是演的**。同步阶段高亮的每一行/列/对角线，其和真的恒等于 `190000361`；敌对故障只污染视觉层，权威矩阵不被触碰。

## 交付物评估（两个外部 zip，2026-08-05）

| 包 | 角色 | 处置 |
|---|---|---|
| `prime-magic-19-delivery.zip` | 数学底座：8 张验真 seed + python 编译/验证链 + TS orbit runtime + 证明/审计报告 | 迁入 `tools/pm19-prime-magic/`（真源） |
| `prime-magic-visual-demo.zip` | 可视化参考：WebGL2 instanced 渲染器 + 七阶段电子战状态机 | 未入仓，仅作移植蓝本（评估副本 `tmp/prime-magic-eval/`） |

原始交付迁入复验（Windows / Python 3.13.7 / Node 24）：含生成目录的 `SHA256SUMS` 210 项全 OK；python 12 测试 + `verify_manifest` valid；TS 14/14 测试；百万次轨道压力测试无错误。入仓审阅收尾后，清单收敛为新鲜 clone 实际存在的 131 个交付文件，排除可由 TS 真源重建的 `runtime/dist` / `runtime/node_modules`，并由局部 `.gitattributes` 固定 LF。数学要点：单 seed 轨道精确 743,178,240 状态；8 seed 中心互异 → 8 条不相交轨道共 5,945,425,920 棋盘；运行时只做已证明保持幻性的置换，不判质数、不搜索。

## 架构决策

1. **真源 / vendoring 分离**：数学资产真源在 `tools/pm19-prime-magic/`（入仓交付文件受 `SHA256SUMS` 保护，复现命令见其 README 与 `CF7-INTEGRATION.md`）；Launcher 侧持字节级副本（`runtime/src/*.ts` 新鲜 build 后复制引擎 → `launcher/web/modules/bg-gl/pm19/`，种子 → `launcher/web/assets/pm19/`），因为 `bootstrap.local` 虚拟主机只映射 `launcher/web/`。视觉层（配色/相位叙事/事件绑定）是 launcher 私有，不回填 tools。
2. **web 侧首个 ESM 模块**：bootstrap 既有脚本全是经典 script + IIFE；bg-gl 用 `type="module"` 自包含加载，不引入打包器、不引第三方依赖。
3. **受限重放挂钩**：事件源复用 `BootstrapApp.onMessage` 注册表（`list_resp` / `state` / `flash_ready`）+ `#btn-confirm-start` DOM capture 监听 + `body.intro-video` MutationObserver。由于 ESM 的 fetch/SHA 初始化可能晚于宿主首包，主控只缓存这三类小型 latest-value 消息，PM19 以 `{replayLatest:true}` 补收；不缓存任意大 payload。
4. **渲染路线**：WebGL2 instanced 单 draw call（361 instances，数字 fragment shader 整数拆位）→ Canvas2D 回退 → 静默撤下 canvas。不引入 Worker/SharedArrayBuffer（COOP/COEP 在虚拟主机不好配，且 8–12Hz 换盘主线程成本约数十 µs/s）。DPR 上限 1.0。

## 叙事映射（事件 → 相位）

| 事件 | 相位 | 说明 |
|---|---|---|
| 页面加载 | SCRAMBLE 频谱扰动 | 环境底态，8–12Hz 换合法棋盘，低故障强度 |
| 首个 `list_resp` | ROW ACQUISITION → COLUMN COHERENCE → 环境态 | 与 launcher 宿主首次握手完成 = 行列捕获 |
| 环境态 | SCRAMBLE + 每 6–10s 插播行/列扫描（交替） | 闲置不死屏 |
| 点「确认」/ `Spawning`/`WaitingConnect`/`WaitingHandshake`/`Embedding` | DIAGONAL LOCK | 扫完保持 |
| `WaitingGameReady` | 对角锁定完成度拉满 | |
| `Ready` / `flash_ready` | MATRIX SYNCHRONIZED | 保持到 panel swap 自然隐藏 |
| `Error` | FAULT INJECTION | 故障拉满，仅视觉层 |
| 回到 `Idle` | ORBIT RESCRAMBLE → 环境态 | 取消/失败后复位 |

相位时序/故障强度常量集中在 `modules/bg-gl/main.mjs` 顶部常量区，调参只动一处。

## 性能契约（沿用交付方边界）

- 仅 SCRAMBLE / FAULT / RESCRAMBLE 相位换棋盘（8–12Hz，抖动间隔）；ROW / COLUMN / DIAGONAL / SYNCHRONIZED 冻结合法棋盘只动 uniform——避免逐格混合造成的短暂约束失效，也让数学结构可被看见。
- `visibilitychange` 与 `body.intro-video` 期间停 rAF；`#bg-gl` 已加入 welcome.css 的 intro-video 熄灯规则（片头播放时 GPU 让给视频解码）。
- CSS `opacity:.45` + shader 整体压暗约 35%，配色换血为 `--dls` 蓝（数字）/ `--bone` 骨白琥珀（行列高亮）/ `--rust` 锈红（故障）。

# 三期半：实机反馈修正 + iGPU 性能压制（2026-08-05，同日续作）

真实 Launcher 实机反馈驱动的一轮修正。

## 垫图位置修正（RECON 窗 → 中央卡片垫图）

三期的左栏 RECON 小窗误解了需求：用户意图是把垫图放到**中央卡片**这个"特写位"做衬底。本轮撤掉 `.art-feed`（HTML/CSS/JS 全移除），`loadRandomBackground()` 改为给 `.welcome-card` 喂图（`.has-art` class + inline `backgroundImage` = 82–88% 深色罩渐变 + 图片 url），图以质感形式从卡片透出，文字可读性由罩层保证。截图验证：人物立绘从卡片左侧透出，标题/存档栏/简报文字均可读。

## slots 卡片"存档名遮挡"诊断（非 CSS bug，是矩阵透印）

## slots 卡片"横线穿字"终局定性

三期半的 .95 alpha 修正后实机仍有横线。本轮取证链：1.35 字号档 headless 复现 → 描边定位元素无重叠 → **getBoundingClientRect 探针实测**：`.card-divider` top=241.2 / `.slot-id` top=250.2，布局完全正确。最终定性：横线是 PM19 矩阵高亮数字行的**透印**，且 `RENDER_SCALE=0.5` 低分辨率渲染 + 2× CSS 放大把数字行柔化成连续横带，在半透明卡片上读作"横线"。修复：卡片改**实底**（`#0c0e12→#05070a` 纯色渐变，空槽 .95/.97），透印物理消除。卡片间隙仍可见矩阵，氛围不受损。

## 对角锁定动画被真实事件截断

根因：预热链路上 `WaitingGameReady`（旧代码 `enterDiagonalLock(true)` 瞬间拉满）与 `Ready`（直接 SYNCHRONIZED）比 1.8s 扫描动画快得多，动画被截断到几乎不可见。修复：

- `WaitingGameReady` 并入普通推进组，只做 `enterDiagonalLock()`，不再拉满；
- `Ready`/`flash_ready` 改走 `requestSynchronized()`：扫描在播则置 `syncPending` 挂起，`onDiagonalSweepDone` 播完后再进 SYNCHRONIZED；不在对角相位则直接同步；
- Idle/Error 路径重置 `syncPending`。

效果：点确认后用户必见完整 1.8s 双对角扫描；加载慢则进入保持期行波+读数呼吸；加载快则扫完即同步。

## slots"横线穿字"终案

二轮修正（实底卡片）后实机依旧。CDP 实测：

- `cardBg = linear-gradient(rgb(12,14,18), rgb(5,7,10))` —— 新 CSS 已加载，排除缓存；实底下仍有"横线"，排除透印。
