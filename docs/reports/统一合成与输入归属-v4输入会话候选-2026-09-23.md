## 实现结果

输入会话改为 v4。epoch 普通域 1…0x7FFFFD，终止保留域和独立 sequence 上限均显式检查；共享状态通过真实映射上的 Interlocked 访问，issued/floor 单调。
正常续接先封发送者，由目标 UI 确认队列为空、原处理器/钩子无在途、鼠标状态结束，再终止、恢复并等待 broker 真退出；硬边界或失败明确取消。
等待超过正常交接预算时转显式取消；目标不执行、所有权冲突、恢复或卸钩未确认时保持 ClosedUnconfirmed，不安装后继、不杀玩家进程。

数据在 WH_GETMESSAGE 的 PM_REMOVE 内处理，返回给应用前改成 WM_NULL；PM_NOREMOVE 副本同样清空但不执行，直接 Send 到窗口过程的数据不准入。
控制消息独立携带会话身份；repaint/关闭采用对应 ticket。原处理器和 IAT 查询的在途范围参与退休；IAT 原函数调用不持状态锁，映射访问受存活锁保护。
微软 [GetMsgProc 合同](https://learn.microsoft.com/en-us/windows/win32/winmsg/getmsgproc)允许修改返回的 MSG；这里不假定一个哨兵消息就排空所有已取出副本。

broker 在目标进程实例级取得稳定命名锁，拒绝已存在的 v3/v4 属性；旧控制无法初始化或关闭新会话。异常退出/遗留安装采取保守拒绝策略，不覆盖未知所有者。
Controller 的输入续接保留 P/native；Surface 的排程回调绑定工作代次，新会话等待真实释放及 fresh Down，不重放旧 Down/Up。
恢复执行器新增 watchdog 资格回调，在实际主尝试、SetFocus 和 fallback 前复核，不能用策略层通过代签执行点。
