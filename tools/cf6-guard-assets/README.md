# CF6 光头保安：穿刺散弹与暴君变身

光头保安使用 R2 黑西服、红领带、墨镜身体，固定一把 SPAS12。普通型登记为 `468`（`敌人-CF6光头保安`），变身型为 `469`（`敌人-CF6变身光头保安`）；阶段 **6**、档次 **3** 来自制作组指定。目标是明显弱于无盾特种兵，但能造成至少 20% 的净生命损失。实战是否达到目标以本页后续实测段和绑定产物的证据为准。

## 源稿、装配与归属

- 冻结输入为 [CF6光头保安-R2](../../flashswf/arts/new/Codex素材源稿/CF6光头保安-R2/)。`archive-origin.json` 绑定原 ZIP 和 49 个保留文件；仅取原始根 `888` 的人形站立、行走、散弹、受击、被投、击飞倒地和三段死亡。撞车党 `612` 不在范围内。变身 `887` 的动作来自同一冻结时间轴，撕裂衣服的六个矢量分件另存于 [变身源稿](../../flashswf/arts/new/Codex素材源稿/CF6光头保安-变身-R2/)；其七个文件含一份仅供参考的原始位图枪稿。作者脚本作为审阅材料保留，未执行，也不承诺这份筛选档案独立重建整个作者包。
- 唯一原生编辑源为 [Codex光头保安素材](../../flashswf/arts/new/Codex光头保安素材/)。[build.py](build.py) 保留各帧深度、矩阵和颜色变化，生成 185 个库元件；[native-manifest.json](native-manifest.json) 记录所有输出及输入哈希。已有人工修改不符合 manifest 时拒绝覆盖。
- 身体为原生矢量，原稿中 `592` 的枪械是位图。运行版本明确改用现有 [CF7 SPAS12 矢量](../../flashswf/arts/things切割/LIBRARY/长枪/SPAS12/枪-长枪-SPAS12.xml) 的画稿副本，以原握点等比缩放 `0.6`；不修改原枪，也不接入装备属性。枪口取本地 `(302.8,-34.05)`，经过缩放与实际动作矩阵换算。原始枪械 SVG 仍保存在冻结档案中。
- 鞋底接地依据 `582` 的可见 alpha 轮廓，统一纵移 `-11.777058410644528`；死亡首姿按相同脚部注册点对齐。影子归本单位私有，在浮空、旋转和镜像时仍落在 Z 轴地面，跟随现有阴影开关。
- `things-new.fla` 第四帧挂载新库；首次挂载时两者均由真实 CS6 编译。本轮共享入口 URL 不变，只重编保安独立库；其停止在第一帧的入口用不可达第二帧收齐第二种导出单位的共享动作依赖，避免 CS6 生成单帧占位体。本轮私有帧脚本不要求重编 `asLoader.swf`，也不触发正式 runtime 发布。

## 行为和数值

[GuardAI.as](GuardAI.as) 让通用 AI 继续负责索敌，本单位负责实际移动与攻击时序。移动消费前逐帧重算方向，纵向采用 24/12 的开始与停止区间，横向在 380 以外靠近、340 内停止，最后一步限制到目标区间。冷却中不反复跨越目标纵坐标，手动控制仍调用标准行走。

散弹动作保留原第 **41** 帧开火、第 **74** 帧收招；原稿共 87 帧，尾部 13 帧不进入动作循环。每次动作只发射一次三颗穿刺子弹，单颗威力取 `空手攻击力`，使用已有 SPAS12 声音和霰弹枪枪火。实际出弹须满足当前身体、动作 token、状态、血量、暂停和开火帧条件；举枪至出弹期间暂时持有刚体与抗位移，出弹后立即归还；不提供减伤，强制换状态和死亡仍立即取消动作，并恢复进入动作前的外部状态。普通收招期保持正常受击、击飞和被投响应。攻击时间轴由私有时钟逐帧推进，暂停不积累时间。

没有护盾、减伤、额外暴击或装备伤害加成。受击仍为血迹，击飞与落地分别调用现有物理入口。普通型默认人形单命、变身型默认死亡后进入下述变身，两种均已登记到兵种目录。显式 `光头保安变身:true/false` 优先于兵种默认值，也接受 XML 的 `1/0` 和对应字符串；不识别的值输出配置错误并关闭变身。三种普通死亡各自只结束一次。

[balance.py](balance.py) 使用现有 `computeMonsterRow` 生成八项面板，记录见 [balance-inputs.json](balance-inputs.json)。观测参数为：速度均值 55 → 速度系数 2；前摇 40、后摇 33、后摇权重 0.2 → 攻速系数 2；物理倍率 1、单次三颗穿刺弹、现有 `pierceSegmentRules.pierceFactor=2` → 段数 6；受击恢复 8/7 帧，具有击飞和倒地 → 霸体系数 2。阶段与档次固定，其他基础成长、攻防偏置暂为 1。

## 二阶段合同

[GuardTransform.as](GuardTransform.as) 使用黑龙式“旧单位死亡、生成新单位”的边界。第 70 帧仅调用一次现有 `敌人-完全体克隆兽`（单位 460，暴君克隆兽），继承等级；HP、MP、技能、冷却、伤害与其他战斗属性全部由现有暴君模板重新初始化，不复制保安状态。后继名字统一使用现役单位 460 的“暴君克隆兽”，不继承保安的名字与称号；保留生成地点、阵营、方向和产生源，身高明确使用现役暴君的 230。姓名在调用单位工厂时传入，早于 `DisplayNameInitializer`，避免出现 `Lv.N undefined` 或继续显示保安身份。

变身共保留原稿 75 帧，在第 70 帧完成生成；71–75 的原始空白尾帧不参与播放。身体内驱动不被标准死亡事件清理，暂停时停止推进。本单位确认新单位身份、`__unitInitializedVersion`、等级、阵营与有效生命面板吻合后，主动显示后继单位并对旧身体执行 `死亡检测({noCount:true,noCorpse:true})`。与黑龙现行规则一致，第一阶段经验结算一次，关卡剩余怪数留给后继单位死亡时扣除；第一阶段不掉钱。新单位若已经完成初始化但紧接着被击杀，仍会完成旧身体回收，避免把正常死亡误当成生成失败。重复死亡或受击不重启变身；名称冲突、空返回、身份错位或初始化超时明确保留失败状态，不自动重刷或提前回收旧身体。

[transform.py](transform.py) 复制当前暴君的 13 个原生分件及其矢量依赖到保安私有命名空间，绑定实际源文件哈希。它不使用原包中的旧灰色克隆兽，也不覆盖现役暴君。抛枪沿用保安同一把 SPAS12 画稿和原稿飞出矩阵，仅为动画画面，不生成可拾取装备。

## 历史普通弹实测（不证明当前穿刺版本）

## 性能与双兵种修复（最终命名更正前）

[该轮证据](evidence/20261016-performance/summary.json) 绑定用户现场报告、修复前后 SWF、原生绘制、行为测试和真实候选游戏回执。该轮产物为 **189,309 字节**，SHA-256 `c90a6eb3209a8e295fb9af76bc7efb4cd5534c2d03086bf29ba1e9f574677c28`，仍是零位图。

| 目录名称 | 兵种 ID | 默认死亡路线 |
|---|---:|---|
| CF6光头保安·普通型 | 468 | 普通死亡 |
| CF6光头保安·变身型 | 469 | 原动作变身后生成现役暴君 |
